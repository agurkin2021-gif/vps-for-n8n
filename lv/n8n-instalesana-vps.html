DOCKER INSTALĒŠANA

n8n instalēšana VPS serverī

Instalējiet n8n VPS serverī, izmantojot Docker Compose un PostgreSQL. Produkcijas videi nepieciešama arī pastāvīga lietotnes un datubāzes datu glabāšana, nemainīga N8N_ENCRYPTION_KEY, publiski pieejams resursdatora nosaukums, HTTPS un pareiza tīmekļa aizķeru konfigurācija. Pirms produkcijas darbplūsmu aktivizēšanas pārbaudiet visus šos elementus.

PRIEKŠNOSACĪJUMI

Sagatavojiet VPS pirms n8n palaišanas

Linux VPS

Izmantojiet uzturētu Linux serveri ar pietiekamiem resursiem n8n, PostgreSQL, Docker un reversajam starpniekserverim.

DNS

Pirms TLS sertifikātu izsniegšanas un tīmekļa aizķeru URL publicēšanas norādiet domēnu vai apakšdomēnu uz VPS.

Docker Compose

Instalējiet Docker Engine un Compose spraudni no operētājsistēmai atbalstītajām pakotnēm.

Ugunsmūris

Atveriet tikai nepieciešamos administrēšanas un tīmekļa portus. PostgreSQL un iekšējiem lietotnes pakalpojumiem nedrīkst būt publiskas piekļuves.

Vai instalējat uz VPS, kurā jau darbojas tīmekļa vietnes? Varat pievienot n8n savam serverim, ja to ļauj procesora, RAM un diska resursi. Tomēr, ja Nginx, Apache, Caddy vai cits reversais starpniekserveris jau izmanto portus 80/443, nedrīkst bez izmaiņām palaist zemāk parādīto Caddy konteineru, jo porti konfliktēs. Tā vietā novirziet jaunu n8n apakšdomēnu caur esošo reverso starpniekserveri, nodrošinot atbilstošu privāto tīklu, vai izvēlieties tīru VPS precīzai Compose piemēra izmantošanai. Saglabājiet pārējo vietņu un to TLS konfigurāciju: piemērs paredz, ka porti 80/443 ir brīvi.

INSTALĒŠANAS PIEMĒRS PIELĀGOŠANAI

Instalējiet n8n savā VPS ar Docker Compose

Izmantojiet šo piemēru n8n izvietošanai uz pašu pārvaldīta Linux VPS. n8n instalēšana un uzturēšana ir jūsu atbildība; servera izvēle, izmantojot mūsu partnera saiti, neietver iepriekš instalētu n8n. Piemērā privātā Compose tīklā apvienoti n8n, PostgreSQL, ārējs uzdevumu izpildītājs un Caddy HTTPS. Šī ir konfigurācijas veidne, nevis apgalvojums par praksē pārbaudītu izvietojumu.

Vai vēlaties ātrāku sākotnējo instalēšanu? n8n piedāvā arī oficiālu vienas komandas Docker instalēšanu. Tās skriptu varat lejupielādēt un pārskatīt ar komandu curl -fsSL https://get.n8n.io -o get-n8n.sh pirms komandas sh get-n8n.shizpildes. Šī iespēja palaiž sākotnēju instanci ar SQLite lokālā adresē un ietver n8n Assistant izolētās vides pakalpojumus; tā nav tas pats kas šī VPS vide ar publisku HTTPS un PostgreSQL. Pilnai oficiālajai izolētajai videi nepieciešams vairāk RAM un procesora jaudas nekā vienkāršai n8n instalācijai (Compose ceļvedī norādīti vismaz 4 GB RAM / 2 vCPU). Publiski pieejamai produkcijas VPS videi turpiniet ar tālāk aprakstīto manuāli konfigurējamo risinājumu.

1. Sagatavojiet Docker, DNS un piekļuvi

Pieslēdzieties ar SSH un sudo tiesībām un norādiet DNS A ierakstu domēnam n8n.example.com uz sava VPS IPv4 adresi. Uz tikko uzstādīta Ubuntu 22.04, 24.04 vai 26.04 VPS tālāk norādītās komandas instalē Docker Engine un moderno docker compose spraudni no Docker oficiālā parakstītā apt repozitorija:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Šī ir produkcijas videi paredzēta instalēšanas metode no oficiālā Docker Ubuntu ceļveža. Nepārinstalējiet un neizdzēsiet Docker nepārdomāti uz VPS, kurā jau darbojas konteineri vai citas vietnes; vispirms pārbaudiet esošo instalāciju un iespējamos pakotņu konfliktus. Debian vai citai Linux distribūcijai izmantojiet attiecīgo oficiālo instrukciju, nevis Ubuntu komandas.

Tagad pārbaudiet pašu Docker, Compose spraudni, DNS un darba direktoriju:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Ja komanda getent hosts neatgriež adresi vai atgriež nepareizu, izlabojiet DNS pirms Caddy palaišanas; aizstājiet n8n.example.com visā ceļvedī ar savu īsto resursdatora nosaukumu. Docker parasti nepieciešamas root tiesības: ja SSH lietotājs nevar izpildīt turpmākās docker compose komandas tieši, pievienojiet tām prefiksu sudo. Lietotāja pievienošana grupai docker piešķir root līmeņa piekļuvi; koplietojamā serverī to nedrīkst darīt pavirši.

Pirms ugunsmūra ieslēgšanas pārliecinieties, ka SSH administrēšanas ports joprojām ir sasniedzams. Atļaujiet ienākošos HTTP (80) un HTTPS (443) savienojumus sertifikātu izsniegšanai un redaktoram. Docker publicētie konteineru porti var apiet dažus UFW noteikumus, tāpēc pārskatiet Docker ugunsmūra dokumentāciju un publicējiet tikai paredzētos Caddy portus. Šis Compose piemērs apzināti nepublicē PostgreSQL (5432), n8n (5678) vai uzdevumu izpildītāja ziņojumu brokera (5679) portus publiskajā internetā.

2. Izveidojiet vides vērtības un saglabājiet atslēgu

Projekta direktorijā ģenerējiet trīs atšķirīgas nejaušas heksadecimālas vērtības ar komandu:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Izveidojiet failu .env pēc tālāk sniegtās veidnes, katru REPLACE_WITH_RANDOM_HEX aizstājiet ar citu ģenerēto vērtību un mainiet resursdatora nosaukumu un laika joslu. Norādītais 2.42.5 tags atbilst stabilajai versijai, kas norādīta 2026. gada 8. oktobrī; tas ir datēts konfigurācijas piemērs, nevis garantija, ka izvietojums ir praksē pārbaudīts vai arī nākotnē paliks drošs. Pirms instalēšanas pārbaudiet aktuālās oficiālās n8n versijas un izmantojiet vienu un to pašu pārbaudīto versiju n8n un tā uzdevumu izpildītāja attēlam.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Nekad neievietojiet .env publiskā repozitorijā. Glabājiet šifrēšanas atslēgu un atjaunošanas instrukcijas droši ārpus VPS. Pēc konteineru atjaunošanas vai migrācijas atslēgai jāsaglabājas nemainīgai.

3. Izveidojiet compose.yaml jaunai instalācijai

Tajā pašā direktorijā izveidojiet compose.yaml. Piemērā izmantotas oficiālās n8n vides mainīgo konvencijas un PostgreSQL 18 datu ceļš PGDATA , kas dokumentēts n8n mitināšanas projektā:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Četriem pakalpojumiem ir atšķirīgas lomas: PostgreSQL saglabā datubāzes stāvokli, n8n izpilda darbplūsmas, n8n-runner izpilda uzdevumus kā ārējs izpildītājs, izmantojot saskaņotu versiju un kopīgu autentifikācijas marķieri, savukārt Caddy nodrošina publisku HTTPS. Ārējs uzdevumu izpildītājs nav Redis rindas režīms. Tikai Caddy publicē resursdatora portus. Šajā vienkāršotajā piemērā izmantota viena datubāzes loma; stingrākai PostgreSQL tiesību nodalīšanai skatiet oficiālo n8n izvietošanas piemēru ar PostgreSQL.

4. Izveidojiet HTTPS Caddyfile

Blakus failam Caddyfile izveidojiet failu compose.yaml(ar lielo C un bez paplašinājuma). Visur aizstājiet piemēra resursdatora nosaukumu ar savu DNS nosaukumu:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy pieprasa un atjauno publiskos TLS sertifikātus, ja domēns pareizi atrisinās un ārējā datplūsma sasniedz portus 80/443. Nenorādiet DNS uz localhost. Ja aizstājat Caddy ar citu reverso starpniekserveri, pārsūtiet sākotnējā resursdatora, protokola un klienta adreses galvenes un pielāgojiet N8N_PROXY_HOPS faktiskajam uzticamo starpniekserveru posmu skaitam.

5. Palaidiet konteinerus un pārbaudiet no ārpuses

Kad saglabāti faili .env, compose.yaml un Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Pēdējā komanda pārbauda publisko HTTPS veselības pārbaudes galapunktu. Ja sertifikāta izsniegšana vēl nav pabeigta, pārbaudiet Caddy žurnālus, DNS un portus, pirms secināt, ka n8n nedarbojas. Atveriet https://n8n.example.com, nekavējoties izveidojiet pirmo īpašnieka kontu un ieslēdziet atbilstošu pierakstīšanās aizsardzību. Pārliecinieties, ka instance tiešām izpilda darbplūsmu, nevis tikai ielādē redaktoru:

  1. Redaktorā izveidojiet darbplūsmu ar Webhook trigeri. Iestatiet HTTP Method uz GET, choose the Path vps-checkceļu Respond uz Immediately. Saglabājiet darbplūsmu.
  2. Noklikšķiniet uz Listen for Test Event, nokopējiet pilno Test URL adreses vērtību, kuru rāda n8n, un citā ierīcē palaidiet curl -i 'PASTE_TEST_URL_HERE' ar nokopēto URL. Sagaidiet veiksmīgu HTTP atbildi un ienākošo notikumu n8n redaktorā. Testa URL darbojas tikai laikā, kad n8n gaida šo notikumu.
  3. Publicējiet darbplūsmu, pārslēdziet mezglu uz Production URL, nokopējiet to un vēlreiz palaidiet curl -i 'PASTE_PRODUCTION_URL_HERE' . Pārbaudiet izpildi darbplūsmas cilnē Executions . Produkcijas tīmekļa aizķeru pieprasījumiem darbplūsmai jābūt publicētai; to saturs nav redzams redaktora testa skatā.

Šis ir apzināti vienkāršs, neautentificēts darbības tests: nekad nesūtiet uz to slepenus datus. Pēc pārbaudes atceliet publicēšanu vai izdzēsiet darbplūsmu, vai pirms publiskā galapunkta izmantošanas ar īstiem datiem konfigurējiet Webhook autentifikāciju un IP ierobežojumus. Skatiet oficiālo Webhook testa un produkcijas režīma dokumentāciju.

6. Pirms versiju maiņas izveidojiet rezerves kopiju

Saglabājiet atjaunojamu PostgreSQL datubāzes izdruku un pastāvīgo n8n datu sējumu, .env/šifrēšanas atslēgu un nepieciešamos ārējos failus glabātuvē ārpus šī servera. Pārbaudiet atjaunošanu, izmantojot dublēšanas un atjaunošanas ceļvedi pirms produkcijas vides atjaunināšanas. Komandu piemēri:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Mainiet piesaistīto N8N_VERSION tikai pēc versijas piezīmju izlasīšanas; n8n un izpildītāja attēlu versijas jāmaina kopā. Neizpildiet docker compose down -v ikdienas uzturēšanas laikā, jo tā dzēš nosauktos datu sējumus. PostgreSQL galvenās versijas maiņai vajadzīgs datubāzes jaunināšanas vai izdrukas un atjaunošanas plāns; Postgres 18 attēla aizstāšana ar citas galvenās versijas tagu nenozīmē automātisku migrāciju.

Galvenie avoti: n8n Docker Compose ceļvedis, n8n reversā starpniekservera un tīmekļa aizķeru konfigurācija, kā arī oficiālās PostgreSQL izvietošanas piezīmes. Netiek pieņemti nekādi infrastruktūras veiktspējas testi vai konkrēta pakalpojumu sniedzēja iepriekš instalētas iespējas.

KONFIGURĀCIJA

Šifrēšanas atslēga

Publiskais resursdatora nosaukums

Konfigurējiet īsto ārējo resursdatora nosaukumu un HTTPS izcelsmes adresi, nevis iekšējo konteinera adresi.

Tīmekļa aizķeres URL

Iestatiet N8N_WEBHOOK_URL uz publiski sasniedzamo HTTPS pamata URL un iestatiet N8N_PROXY_HOPS=1 ja ir viens uzticams reversais starpniekserveris. WEBHOOK_URL ir novecojis aizstājvārds n8n 2.35.0 un jaunākās versijās; nekopējiet to no vecākām pamācībām.

Vai n8n izmantošanai ar Docker ir vajadzīgs PostgreSQL?

Docker darbībai PostgreSQL nav obligāts, un nelielas instalācijas var izmantot SQLite. VPS produkcijas videi PostgreSQL nodrošina stabilāku datubāzes pamatu un atbalsta turpmāku mērogošanu ar rindas režīmu.

Kāpēc vajadzīgs pastāvīgs n8n sējums, ja dati glabājas PostgreSQL?

Pastāvīgais n8n direktorijs var saturēt svarīgus instances datus un konfigurāciju. Saglabājiet to atbilstoši izvietojuma arhitektūrai, nevis pieņemiet, ka datubāze ir vienīgais atjaunošanai vajadzīgais resurss.

Kāpēc manas tīmekļa aizķeres URL rāda localhost?

Iekšējā konteinera adrese atšķiras no publiskās adreses. Konfigurējiet ārējo resursdatora nosaukumu, protokolu un tīmekļa aizķeres URL un nodrošiniet, ka reversais starpniekserveris pārsūta vajadzīgās galvenes.

Vai portam 5678 jābūt publiski pieejamam?

Parastā produkcijas vidē aiz reversā starpniekservera atveriet HTTPS piekļuvi starpniekserverī, bet n8n lietotnes portu atstājiet iekšēju, ja vien nav īpaša ekspluatācijas iemesla rīkoties citādi.

Vai vajadzīgs Redis?

Parastai viena instances Docker instalācijai tas nav vajadzīgs. Redis kļūst aktuāls, ja apzināti pārejat uz rindas režīmu un izpildītājiem.

Vai ārējie n8n uzdevumu izpildītāji ir tas pats, kas rindas režīma darbinieki?

Nē. Ārējie uzdevumu izpildītāji izpilda atbalstīto uzdevumu kodu atsevišķi no galvenā n8n procesa un izmanto kopīgu autentifikācijas marķieri. Redis rindas režīms sadala darbplūsmu izpildes, un tam ir savas infrastruktūras prasības. Šajā piemērā izmantots ārējs uzdevumu izpildītājs, nevis Redis rindas režīms.
