INSTALARE COPIE-ȘI-ADAPTĂ

Instalați n8n pe VPS cu Docker Compose

Utilizați acest exemplu pentru a construi o implementare n8n pe un autogestionat Linux VPS. Instalați și întrețineți singur n8n; alegerea unui server prin partenerul nostru nu include o instanță n8n preinstalată. Exemplul combină n8n, PostgreSQL, un rulator de sarcini extern și Caddy HTTPS într-o rețea Compose privată. Este un șablon de configurare, nu este o revendicare a unei implementări testate în direct.

În schimb, doriți cea mai rapidă instalare proaspătă? n8n oferă, de asemenea, o configurare oficială pe o singură linie Docker. Puteți descărca și revizui scriptul acestuia cu curl -fsSL https://get.n8n.io -o get-n8n.sh înainte de a alerga sh get-n8n.sh. Această opțiune lansează o instanță inițială cu SQLite la o adresă URL locală și include servicii sandbox Asistent n8n; este nu la fel ca această implementare public-HTTPS, PostgreSQL susținută VPS. Stack-ul oficială completă sandbox are nevoie de mai multe RAM și CPU decât o instalare slabă n8n (ghidul său Compose specifică cel puțin 4 GB RAM / 2 vCPU-uri). Pentru o producție orientată spre internet VPS, continuați cu stack-ul configurată manual de mai jos.

1. Pregătiți Docker, DNS și accesul

Conectați-vă prin SSH cu acces sudo și indicați un DNS O înregistrare pentru n8n.example.com la adresa dvs. IPv4 VPS. Pe a proaspăt Ubuntu 22.04, 24.04 sau 26.04 VPS, următoarele comenzi instalează Docker Motor și modern docker compose plugin de la oficialul Docker semnat apt depozit:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Aceasta este metoda de depozitare orientată spre producție din ghidul oficial de instalare Docker Ubuntu. Do not blindly reinstall or remove Docker on a VPS already running containers or other websites; inspectați mai întâi instalarea existentă și posibilele conflicte ale pachetului. Pentru Debian sau altă distribuție, utilizați instrucțiunile oficiale corespunzătoare specifice sistemului de operare în loc de comenzile Ubuntu.

Acum verificați Docker însuși, pluginul Compose, DNS și directorul de lucru:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Dacă getent hosts nu returnează nicio adresă sau adresa greșită, corectează-ți DNS înainte de a începe Caddy; înlocuiți n8n.example.com în acest ghid cu numele dvs. de gazdă real. Docker necesită în mod normal privilegii root: dacă utilizatorul dvs. SSH nu poate rula mai târziu docker compose comenzile direct, prefixați-le cu sudo. Adăugarea unui utilizator la docker grupul acordă acces echivalent cu rădăcină și nu ar trebui să se facă întâmplător pe un server partajat.

Păstrați-vă portul de administrare actual SSH accesibil înainte de a activa un firewall. Permiteți intrarea HTTP (80) și HTTPS (443) pentru eliberarea certificatului și editorului. Porturile de containere publicate de Docker pot ocoli unele reguli UFW, deci consultați ghidul pentru firewall Docker și publicați numai porturile dorite Caddy. Acest exemplu Compose o face în mod deliberat nu publica PostgreSQL (5432), n8n (5678) sau task-runner broker (5679) pe internetul public.

2. Creați valori de mediu și păstrați cheia

Din directorul de proiect, generați trei diferite valori hexazecimale aleatoare cu:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Creați un fișier numit .env folosind șablonul de mai jos, înlocuiți fiecare REPLACE_WITH_RANDOM_HEX cu o valoare generată diferită și modificați numele gazdei și fusul orar. Cea arătată 2.42.5 eticheta este versiune stabilă listată la 8 octombrie 2026, folosit aici ca exemplu de configurare datat, nu este o garanție a unei implementări testate în direct sau a securității viitoare. Înainte de instalare, verificați versiunile oficiale n8n curente, apoi păstrați n8n și imaginea lui task-runner pe aceeași versiune verificată.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Nu te angajezi niciodată .env la un depozit public. Păstrați cheia de criptare și instrucțiunile de recuperare în siguranță în afara VPS. Cheia trebuie să rămână aceeași după recrearea sau migrarea containerului.

3. Scrieți compose.yaml pentru o instalare nouă

În același director, creați compose.yaml. Exemplul folosește convențiile oficiale n8n privind variabilele de mediu și PostgreSQL 18 PGDATA calea documentată de proiectul de găzduire n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Cele patru servicii au roluri distincte: PostgreSQL stochează starea bazei de date, n8n rulează fluxuri de lucru, n8n-runner execută sarcini de rulare cu o versiune care se potrivește și un token de autentificare partajat, iar Caddy se ocupă de public HTTPS. Un extern alergător de sarcini nu este Redis Queue Mode. Doar Caddy publică porturi gazdă. Această ilustrație slabă folosește un singur rol de bază de date pentru configurare; pentru o separare mai puternică a privilegiilor PostgreSQL, consultați exemplul oficial de implementare n8n PostgreSQL.

4. Creați Caddyfile-ul HTTPS

Creați fișierul Caddyfile (C majusculă, fără prelungire) alături compose.yaml. Înlocuiți exemplul de hostname peste tot cu propriul dvs. nume DNS:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy solicită și reînnoiește certificate publice TLS atunci când domeniul se rezolvă corect și traficul extern poate ajunge în porturile 80/443. Nu indicați DNS către localhost. Dacă înlocuiți Caddy cu un alt proxy invers, redirecționați anteturile originale de gazdă, protocol și adresă client și ajustați N8N_PROXY_HOPS pentru numărul real de hop-uri de proxy de încredere.

5. Porniți containerele și testați din exterior

Rulați aceste comenzi din directorul proiectului după salvare .env, compose.yaml şi Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Ultima comandă verifică public HTTPS endpoint de sănătate. Dacă eliberarea certificatului este încă în așteptare, inspectați jurnalele Caddy și DNS/porturile înainte de a încheia că n8n este rupt. Deschide https://n8n.example.com, creați imediat primul cont de proprietar și activați protecțiile de conectare adecvate. Confirmați că instanța execută de fapt un flux de lucru, nu doar că editorul încarcă:

  1. În editor, creați un flux de lucru cu a Webhook declanșatorul. Setați HTTP Metoda la GET, alegeți Path vps-check, și setați Răspunde la Imediat. Salvați fluxul de lucru.
  2. Faceți clic Ascultați evenimentul de testare, copiați integral Adresa URL de testare indicat de n8n, iar de pe alt dispozitiv rulați curl -i 'PASTE_TEST_URL_HERE' cu adresa URL copiată. Așteptați-vă ca un răspuns de succes HTTP și evenimentul de intrare să apară în editorul n8n. Adresele URL de testare funcționează numai în timp ce n8n ascultă evenimentul.
  3. Publicați fluxul de lucru, comutați nodul la acesta Adresa URL de producție, copiați-l și rulați curl -i 'PASTE_PRODUCTION_URL_HERE' din nou. Confirmați execuția sub fluxul de lucru Execuții fila. Solicitările de webhook de producție necesită ca fluxul de lucru să fie publicat și nu își arată sarcina utilă în vizualizarea de testare a editorului.

Acesta este un test de fum deliberat simplu, neautentificat: nu trimiteți niciodată secrete. Anulați publicarea/ștergeți-l după testare sau configurați restricțiile de autentificare/IP cu Webhook înainte de a utiliza un endpoint public pentru date reale. Consultați documentația oficială de testare/producție Webhook.

6. Faceți backup înainte de a schimba versiunile fixate

Salvați un dump recuperabil PostgreSQL şi volumul de date persistent n8n, .env/ cheie de criptare și fișiere externe necesare pentru stocarea în afara acestui server. Verificați o restaurare folosind ghid de backup și recuperare înainte de a actualiza producția. Exemple de comenzi:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Schimbați fixarea N8N_VERSION numai după citirea notelor de lansare; atât n8n cât și imaginile alergătorului trebuie să avanseze împreună. Nu alerga docker compose down -v în timpul întreținerii de rutină, deoarece aceasta șterge volumele de date denumite. PostgreSQL modificările majore ale versiunii necesită o actualizare a bazei de date sau un plan de descărcare/restaurare; înlocuirea imaginii Postgres 18 cu o altă etichetă majoră nu este o migrare automată.

Referințe autorizate: n8n Docker Ghid de redactare, n8n configurație reverse-proxy/webhook și note oficiale de implementare PostgreSQL. Nu se presupune nici un benchmark de infrastructură sau o funcție preinstalată specifică furnizorului.

VERIFICAREA POST-DEPLARE

Verificați funcționarea înainte de a conecta workflow-uri reale

Verificați starea containerului

Fugi docker compose ps și confirmați că aplicația și serviciile de bază de date rulează conform așteptărilor înainte de a trata implementarea ca sănătoasă.

Verificați endpoint-ul de health n8n

Cu exemplul Compose de mai sus, portul 5678 nu este publicat pe gazdă. Verificați endpoint-ul public cu curl -fsS https://n8n.example.com/healthz după schimbarea numelui de gazdă și folosiți docker compose ps plus jurnalele de service dacă HTTPS sau baza de date nu este pregătită.

Folosiți versiuni fixe ale aplicației

Do not treat an unreviewed floating image update as a maintenance strategy. Record the n8n version you run, read release notes and back up before changing it.

Nu actualizați direct versiunea majoră PostgreSQL pe datele existente

Schimbarea numai a etichetei de imagine majoră Postgres poate face incompatibil un director de date existent. Faceți backup și urmați procedura de actualizare a bazei de date în loc să presupuneți că recrearea containerului efectuează o migrare a versiunii majore.

Întrebări frecvente

Instalarea n8n cu Docker: întrebări frecvente

Does n8n need PostgreSQL when using Docker?

Docker does not require PostgreSQL, and small deployments can use SQLite. For a production-oriented VPS deployment, PostgreSQL provides a stronger database foundation and supports later queue-mode scaling.

De ce să păstrați un volum persistent n8n dacă PostgreSQL stochează date?

Directorul persistent n8n poate conține stare și configurație importante ale instanței. Păstrați-o conform designului de implementare, în loc să presupuneți că baza de date este singurul activ de recuperare.

De ce webhook-ul meu arată localhost?

Adresa containerului intern diferă de originea publică. Configurați numele de gazdă extern, protocolul și URL-ul webhook și asigurați-vă că proxy-ul invers trece anteturile necesare.

Portul 5678 ar trebui să fie public?

Pentru o implementare normală de producție în spatele unui proxy invers, expuneți HTTPS la proxy și păstrați portul aplicației n8n intern, cu excepția cazului în care există un motiv operațional specific pentru a nu face acest lucru.

Am nevoie de Redis?

Nu pentru o implementare standard cu o singură instanță Docker. Redis devine relevant atunci când treceți în mod deliberat la Queue Mode și workeri.

Sunt executanții externi de sarcini n8n la fel ca workerii în Queue Mode?

Nu. Rugătorii externi de sarcini execută codul de sarcină acceptat separat de procesul principal n8n și folosesc un simbol de autentificare partajat. Redis Queue Mode distribuie execuțiile fluxului de lucru și are propriile cerințe de infrastructură. Acest exemplu arată un rulator de sarcini extern, nu Queue Mode Redis. Potriviți versiunea imaginii alergătorului cu versiunea n8n.
