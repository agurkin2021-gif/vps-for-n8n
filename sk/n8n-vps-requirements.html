MINIMUM A PRAKTICKÁ KAPACITA

Má n8n jednu oficiálnu minimálnu konfiguráciu VPS?

Nie pre každú záťaž. Oficiálne príklady predpokladov n8n opisujú ilustračné nasadenie OEM a výslovne upozorňujú, že požiadavky sa líšia podľa záťaže. Táto dokumentácia nie je univerzálnou zárukou, že konkrétna konfigurácia CPU, RAM alebo disku zvládne produkčné automatizácie.

n8n upozorňuje, že nečinná inštancia môže využívať pomerne málo pamäte, ale uzol Code, veľký binárny obsah alebo súbežné vykonania môžu spotrebu pamäte prudko zvýšiť. Samostatne započítajte operačný systém, Docker, PostgreSQL aj nástroje na zálohovanie a monitorovanie.

Technické zdroje: ilustračné predpoklady n8n a oficiálny návod k pamäti. Štyri riadky vyššie predstavujú skutočné dostupné konfigurácie prostriedkov, nie predpísané oficiálne požiadavky n8n.

RAM A CPU

Čo skutočne spotrebúva prostriedky servera

Súbežné vykonania

Viaceré pracovné postupy spustené súčasne môžu zaťažovať server viac než celkový počet uložených pracovných postupov v n8n. Pri prekrývaní sledujte špičky pamäte a oneskorenie vykonávania.

Veľkosť údajov

Veľké objekty JSON, súbory a binárne dáta zvyšujú nároky na pamäť. Niekoľko dátovo náročných vykonaní môže potrebovať viac RAM než množstvo ľahkých automatizácií volajúcich API.

Uzly náročné na CPU

Kód, transformácie a ďalšie výpočtovo náročné kroky môžu dlhodobo zaťažovať CPU. Viac jadier pomáha, keď vykonania skutočne súťažia o výpočtový výkon.

Podporné služby

Operačný systém, PostgreSQL, reverzný proxy server, monitorovanie aj Docker tiež potrebujú prostriedky. Dimenzujte celý systém, nielen proces n8n.

PRED NAVÝŠENÍM PROSTRIEDKOV MERAJTE

Ako zistiť, či n8n potrebuje viac RAM, CPU alebo disku

Spustite najnáročnejší očakávaný pracovný postup a realistickú špičku súbežných vykonaní. Potom skontrolujte server a protokoly vykonaní n8n. Samotný počet pracovných postupov uložených v editore nie je užitočným meradlom kapacity.

Pamäť / nedostatok pamäte (OOM)

Skontrolujte výstup príkazov docker stats --no-stream a free -h. Ak je pamäť vyčerpaná, najskôr znížte objem údajov JSON alebo binárnych dát, veľké importy spracúvajte po dávkach a vyhýbajte sa pamäťovo náročným krokom Code. Chybu haldy JavaScriptu nemusí vyriešiť pridanie vCPU.

CPU / súbežnosť

Zmerajte, či CPU zostáva vyťažené pri transformáciách, alebo úlohy iba čakajú na odpovede externých API. V bežnom režime zvážte podporovaný limit súbežných produkčných vykonaní ešte pred prechodom na pracovníkov. Pridanie CPU nezrýchli externé API s obmedzenou rýchlosťou požiadaviek.

Úložisko / databáza

Skontrolujte df -h, veľkosť databázy a uchovávanú históriu vykonaní. Sledujte rast disku a pomalé databázové operácie. Pred zaplatením väčšieho disku cielene nastavte uchovávanie údajov; kópie potrebné na obnovu držte mimo servera.

Použite odporúčania n8n k súbežnosti a oficiálne vysvetlenie výkonnostných testov. Akýkoľvek sľubovaný počet súbežných pracovných postupov bez znalosti veľkosti dát a latencie API je iba odhadom.

DATABÁZA A ÚLOŽISKO

SQLite, PostgreSQL a trvalé údaje

SQLite

SQLite je vhodné pre malé nasadenia jednej inštancie a testovanie. S rastúcou produkčnou záťažou a súbežnosťou sa voľba databázy mení z detailu inštalácie na prevádzkové obmedzenie.

PostgreSQL

Pre produkčne orientovaný VPS poskytuje PostgreSQL robustnejší databázový základ. Vyhraďte RAM, CPU a disk aj samotnej databáze a sledujte jej rast.

Trvalé údaje .n8n

Nepovažujte PostgreSQL za jedinú súčasť, ktorú treba trvalo uchovať. Zachovajte dátový adresár n8n a chráňte šifrovací kľúč potrebný na obnovu šifrovaných prístupových údajov.

Rast obsadeného miesta na disku

História vykonaní, binárne dáta, databázové súbory a protokoly môžu časom narastať. Nastavenia uchovávania údajov a zálohy mimo servera priamo ovplyvňujú potrebnú kapacitu.

KAPACITA DISKU

Pred objednávkou odhadnite miesto pre históriu vykonaní n8n

Začnite vzorcom uložené vykonania za deň × priemerný počet uložených bajtov na vykonanie × počet dní uchovávania. Napríklad 500 uložených vykonaní denne × 200 KB na vykonanie × 14 dní = 1.4 GB ukážkových údajov o vykonaniach pred započítaním databázovej réžie. Predpoklad 200 KB je len ilustračný, nie výkonnostný test n8n.

Počítajte aj s miestom na operačný systém, vrstvy obrazov Docker, indexy databázy, binárne súbory, protokoly aplikácie, aktualizácie a dočasné súbory. Zálohy mimo servera potrebujú vlastnú kapacitu. Disk s 10 GB môže stačiť úspornému systému, ale má oveľa menej priestoru na uložené súbory než disk so 40 alebo 80 GB.

n8n dokumentuje predvolené odstraňovanie starých údajov o vykonaniach podľa veku (336 hodín / 14 dní) alebo počtu (10,000 vykonaní), s výnimkami. Pred zmenami skontrolujte skutočné nastavenia a overte, čo sa uchováva. SQLite môže uvoľnený priestor opätovne použiť bez automatického zmenšenia databázového súboru.

Zdroj: n8n, správa údajov o vykonaniach a odstraňovanie starých záznamov. Požiadavky na disk závisia od nameranej veľkosti ukladaných dát, nie iba od počtu uzlov.

Docker a Compose

Nasadenie v kontajneroch uľahčuje opakovateľnosť, ale neodstraňuje spotrebu prostriedkov. Údaje n8n a databázy uchovávajte mimo dočasných kontajnerov.

HTTPS a reverzný proxy server

Verejné webhooky potrebujú stabilný názov hostiteľa a správne nakonfigurované HTTPS. Reverzný proxy server a vrstvu TLS zahrňte do návrhu produkčného nasadenia.

SÚBEŽNÉ VYKONÁVANIE

Keď väčší VPS už nestačí ako jediné riešenie

Vertikálne škálovanie je vhodné, kým jedna inštancia spoľahlivo zvláda záťaž. Keď trvalý paralelný dopyt vedie k vzájomnému obmedzovaniu úloh, zvážte režim frontu a pracovníkov. Režim frontu zavádza Redis, PostgreSQL a jeden alebo viac procesov pracovníkov; RAM a CPU vyhraďte každému komponentu, nielen n8n. n8n dokumentuje aj obmedzenia súborového ukladania binárnych dát v režime frontu, preto pred prechodom overte kompatibilný návrh úložiska.

ZÁKLADNÁ TRIEDA A DISKOVÉ I/O

Ako používať základný VPS s 1 GB RAM

1 GB RAM

Ide o skutočnú funkčnú triedu VPS, nielen o produkt na testovanie. Môže byť vhodná pre malé nepretržité automatizácie a väčšinou sekvenčné volania API, keď pamäť, využitie disku a súbežné úlohy zostávajú v nameraných medziach. Ponúka málo rezervy pre PostgreSQL na tom istom serveri, veľké dáta alebo náročné paralelné vykonania.

2 GB RAM

Pri 2 GB RAM máte bezpečnejší základ pre ľahkú inštanciu, ak chcete väčšiu rezervu pre operačný systém, Docker a krátke špičky záťaže bez okamžitého prechodu na produkčne dimenzovaný systém.

SSD verzus NVMe

Bežné SSD postačuje na ľahkú automatizáciu. NVMe je užitočnejšie, ak PostgreSQL a história vykonaní spôsobujú časté čítanie a zápis alebo ak sa latencia disku prejavuje na nameranom výkone pracovných postupov.

Podľa CPU, pamäte, rastu dát na disku a trvania vykonaní pri maximálnom prekrývaní posúďte, či je obmedzením výpočtový výkon, pamäť alebo úložisko. Nepredpokladajte, že väčší VPS odstráni každé spomalenie.

ČASTÉ OTÁZKY

Požiadavky na VPS pre n8n: časté otázky

Koľko RAM potrebuje n8n?

Neexistuje univerzálna hodnota. Potreba RAM sa mení podľa súbežnosti, veľkosti dát, správania vykonávaných úloh a podporných služieb na VPS. Server so 4 GB RAM je praktickou východiskovou triedou pre menšiu produkciu, nie zaručenou požiadavkou pre každú záťaž.

Koľko jadier CPU mám použiť?

Ľahké záťaže môžu začať s malým prídelom CPU. Jadrá pridávajte, keď monitorovanie ukáže trvalé vyťaženie CPU alebo pomalšie vykonania pri súbežnosti, nie iba podľa počtu pracovných postupov.

Vyžaduje n8n PostgreSQL?

Malé nasadenia môžu používať SQLite, ale pri rastúcich prevádzkových požiadavkách a súbežnosti je PostgreSQL robustnejšou voľbou pre produkciu.

Kedy je potrebný Redis?

Redis súvisí s režimom frontu. Bežné nasadenie jednej inštancie ho nepotrebuje len preto, že beží na VPS.

Koľko miesta na disku mám rezervovať?

Potrebné miesto závisí od rastu PostgreSQL, uchovávanej histórie vykonaní, binárnych dát, protokolov, vrstiev kontajnerov a záloh. Sledujte rast a nechávajte rezervu namiesto spoliehania sa na pevné univerzálne číslo.

Môžem n8n nepretržite prevádzkovať na VPS s 1 GB RAM?

Áno, ak sa do dostupných prostriedkov zmestí skutočná záťaž. VPS s 1 GB RAM je reálne použiteľný server pre malé, prevažne sekvenčné automatizácie, ale rezerva pamäte je obmedzená. Nepredpokladajte, že sa doň zmestí PostgreSQL na tom istom serveri, úlohy s veľkými binárnymi dátami alebo viacero veľkých súbežných vykonaní. Sledujte spotrebu a zvyšujte prostriedky podľa nameraného zaťaženia.

Je pre produkčný VPS s n8n lepších 2 GB alebo 4 GB RAM?

Dva gigabajty ponúkajú viac priestoru než úsporná inštancia s 1 GB, zatiaľ čo 4 GB sú praktickou východiskovou triedou pre n8n spolu s PostgreSQL a HTTPS. Neexistuje univerzálne zaručené produkčné minimum: skutočné nároky určujú zložitosť záťaže, maximálne prekrývanie, konfigurácia kontajnerov a uchovávané údaje.

Potrebujú AI pracovné postupy n8n GPU?

Nie, ak n8n iba volá API externého modelu: inferenciu vykonáva poskytovateľ modelu, zatiaľ čo VPS zabezpečuje koordináciu úloh, dáta a súbežnosť. Lokálne spúšťanie inferenčných modelov je samostatným hardvérovým rozhodnutím, ktoré môže vyžadovať podstatne viac RAM a vhodný GPU.

Čo spôsobuje chyby nedostatku pamäte v n8n?

Bežnými príčinami sú veľké objekty JSON alebo binárne dáta, pamäťovo náročné operácie Code a súbežné vykonania. Skontrolujte protokoly behu a špičkovú spotrebu pamäte; potom znížte množstvo dát držaných počas jedného vykonania alebo pridajte RAM podľa nameraného problému.
