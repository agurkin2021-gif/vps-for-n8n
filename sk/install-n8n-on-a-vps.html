INŠTALÁCIA CEZ DOCKER

Inštalácia n8n na VPS

Nainštalujte n8n na VPS pomocou Docker Compose a PostgreSQL. Produkčné nasadenie potrebuje aj trvalé úložisko údajov aplikácie a databázy, nemenný N8N_ENCRYPTION_KEY, verejný názov hostiteľa, HTTPS a správnu konfiguráciu webhookov. Pred aktivovaním produkčných pracovných postupov všetko overte.

PREDPOKLADY

Pripravte VPS pred spustením n8n

VPS so systémom Linux

Použite udržiavaný linuxový server s dostatočnými prostriedkami pre n8n, PostgreSQL, Docker a reverzný proxy server.

DNS

Pred vydaním certifikátov TLS a zverejnením URL adries webhookov nasmerujte doménu alebo subdoménu na VPS.

Docker Compose

Nainštalujte Docker Engine a doplnok Compose z podporovaných balíkov pre daný operačný systém.

Firewall

Sprístupnite iba potrebné porty na správu a webovú prevádzku. PostgreSQL a interné služby aplikácie ponechajte neprístupné z verejného internetu.

Inštalujete na VPS, ktorý už hostuje webové stránky? n8n môžete pridať na server, ktorý spravujete, ak má dostatok CPU, RAM a úložiska. Ak však Nginx, Apache, Caddy alebo iný reverzný proxy server už používa porty 80/443, nespúšťajte nasledujúci ukážkový kontajner Caddy bez úprav: porty by sa dostali do konfliktu. Namiesto toho smerujte novú subdoménu n8n cez existujúci reverzný proxy server s vhodne nastavenou súkromnou sieťou alebo použite čistý VPS presne pre uvedený príklad Compose. Zachovajte ostatné weby aj ich nastavenia TLS; príklad predpokladá dostupné porty 80/443.

INŠTALÁCIA PODĽA VZORU S ÚPRAVAMI

Nainštalujte n8n na VPS pomocou Docker Compose

Tento príklad použite na vytvorenie nasadenia n8n na linuxovom VPS vo vlastnej správe. n8n inštalujete a udržiavate sami; výber servera cez nášho partnera nezahŕňa predinštalovanú inštanciu n8n. Príklad spája n8n, PostgreSQL, externý proces na vykonávanie úloh a HTTPS cez Caddy v súkromnej sieti Compose. Ide o konfiguračnú šablónu, nie o tvrdenie, že nasadenie bolo otestované v reálnej prevádzke.

Chcete namiesto toho čo najrýchlejšiu inštaláciu na čistý server? n8n ponúka aj oficiálnu inštaláciu Dockera pomocou jednoriadkového príkazu. Jej skript si môžete stiahnuť a skontrolovať príkazom curl -fsSL https://get.n8n.io -o get-n8n.sh pred spustením sh get-n8n.sh. Táto možnosť spustí úvodnú inštanciu so SQLite na lokálnej URL adrese a zahŕňa izolované služby asistenta n8n; nejde o rovnaké nasadenie ako toto nasadenie VPS s verejným HTTPS a PostgreSQL. Úplný oficiálny izolovaný balík vyžaduje viac RAM a CPU než úsporná inštalácia n8n (návod Compose uvádza najmenej 4 GB RAM / 2 vCPU). Pre produkčný VPS dostupný z internetu pokračujte manuálne konfigurovanými komponentmi nižšie.

1. Pripravte Docker, DNS a prístup

Pripojte sa cez SSH s oprávnením sudo a nasmerujte DNS záznam typu A pre n8n.example.com na IPv4 adresu vášho VPS. Na čistom VPS s Ubuntu 22.04, 24.04 alebo 26.04 nasledujúce príkazy nainštalujú Docker Engine a moderný doplnok docker compose z oficiálneho podpísaného repozitára Docker pre apt :

# Čistá inštalácia z oficiálnych balíkov pre Ubuntu 22.04 / 24.04 / 26.04
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Pridajte podpísaný repozitár apt pre Docker
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Ide o postup s produkčne orientovaným repozitárom podľa oficiálneho návodu na inštaláciu Dockera pre Ubuntu. Neinštalujte ani neodstraňujte Docker bez rozmyslu na VPS, na ktorom už bežia kontajnery alebo iné webové stránky; najskôr skontrolujte existujúcu inštaláciu a prípadné konflikty balíkov. Pre Debian alebo inú distribúciu použite zodpovedajúci oficiálny návod pre daný operačný systém namiesto príkazov pre Ubuntu.

Teraz overte samotný Docker, doplnok Compose, DNS a pracovný adresár:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Ak príkaz getent hosts nevráti žiadnu adresu alebo vráti nesprávnu adresu, pred spustením Caddy opravte DNS; n8n.example.com v celom návode nahraďte skutočným názvom hostiteľa. Docker spravidla vyžaduje oprávnenia správcu: ak váš používateľ SSH nemôže neskôr priamo spúšťať príkazy docker compose , pridajte pred ne sudo. Pridanie používateľa do skupiny docker poskytuje oprávnenia zodpovedajúce používateľovi root, preto ho na zdieľanom serveri nerobte bez zváženia.

Pred zapnutím firewallu zachovajte dostupnosť portu, ktorý skutočne používate na správu cez SSH. Povoľte prichádzajúce HTTP (80) a HTTPS (443) na vydanie certifikátu a prístup k editoru. Porty kontajnerov publikované Dockerom môžu obísť niektoré pravidlá UFW, preto skontrolujte dokumentáciu firewallu Dockera a zverejnite len zamýšľané porty Caddy. Tento príklad Compose zámerne nezverejňuje porty PostgreSQL (5432), n8n (5678) ani sprostredkovateľa úloh (5679) vo verejnom internete.

2. Vytvorte hodnoty prostredia a uchovajte kľúč

V adresári projektu vytvorte tri rôzne náhodné hexadecimálne hodnoty príkazom:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Vytvorte súbor s názvom .env podľa šablóny nižšie, každú hodnotu REPLACE_WITH_RANDOM_HEX nahraďte inou vygenerovanou hodnotou a zmeňte názov hostiteľa a časové pásmo. Uvedená značka verzie 2.42.5 je stabilné vydanie uvedené 8. októbra 2026, použité ako datovaný konfiguračný príklad, nie ako záruka otestovania nasadenia v reálnej prevádzke ani budúcej bezpečnosti. Pred inštaláciou skontrolujte aktuálne oficiálne vydania n8n a potom používajte rovnakú overenú verziu n8n aj jeho procesu na vykonávanie úloh.

# .env — nahraďte tri ukážkové tajné hodnoty
# Používajte udržiavanú verziu n8n; n8n a proces na vykonávanie úloh musia mať rovnakú verziu.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Nikdy neukladajte .env do verejného repozitára. Šifrovací kľúč a pokyny na obnovu bezpečne uchovávajte mimo VPS. Kľúč musí zostať rovnaký aj po opätovnom vytvorení kontajnera alebo migrácii.

3. Vytvorte compose.yaml na čistú inštaláciu

V tom istom adresári vytvorte súbor compose.yaml. Príklad používa oficiálne konvencie premenných prostredia n8n a cestu PGDATA pre PostgreSQL 18 zdokumentovanú v projekte hostingu n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Štyri služby majú odlišné úlohy: PostgreSQL uchováva stav databázy, n8n vykonáva pracovné postupy, n8n-runner vykonáva úlohy prostredníctvom zodpovedajúcej verzie a zdieľaného autentifikačného tokenu a Caddy zabezpečuje verejné HTTPS. Externý proces na vykonávanie úloh nie je režim frontu Redis. Hostiteľské porty publikuje iba Caddy. Táto úsporná ukážka používa na úvodné nastavenie jednu databázovú rolu; pre prísnejšie oddelenie oprávnení PostgreSQL si pozrite oficiálny príklad nasadenia n8n s PostgreSQL.

4. Vytvorte Caddyfile pre HTTPS

Vytvorte súbor Caddyfile (s veľkým C a bez prípony) vedľa súboru compose.yaml. V celom príklade nahraďte ukážkový názov hostiteľa vlastnou doménou DNS:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy automaticky žiada a obnovuje verejné certifikáty TLS, keď sa doména správne prekladá a externá prevádzka dosiahne porty 80/443. DNS nesmerujte na localhost. Ak Caddy nahradíte iným reverzným proxy serverom, preposielajte pôvodné hlavičky hostiteľa, protokolu a adresy klienta a upravte N8N_PROXY_HOPS podľa skutočného počtu dôveryhodných proxy serverov na ceste.

5. Spustite kontajnery a otestujte prístup zvonka

Nasledujúce príkazy spustite z adresára projektu po uložení súborov .env, compose.yaml a Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Posledný príkaz kontroluje koncový bod stavu cez verejné HTTPS . Ak sa certifikát ešte vydáva, pred záverom, že n8n nefunguje, skontrolujte protokoly Caddy, DNS a porty. Otvorte https://n8n.example.com, okamžite vytvorte prvý účet vlastníka a zapnite primeranú ochranu prihlasovania. Overte, že inštancia skutočne vykonáva pracovný postup, nielen načíta editor:

  1. V editore vytvorte pracovný postup so spúšťačom Webhook . Nastavte HTTP Method na GET, vyberte Path vps-checka položku Respond nastavte na Immediately. Pracovný postup uložte.
  2. Kliknite na Listen for Test Event, skopírujte úplnú Test URL zobrazenú v n8n a z iného zariadenia spustite curl -i 'PASTE_TEST_URL_HERE' so skopírovanou URL adresou. Očakávajte úspešnú odpoveď HTTP a zobrazenie prichádzajúcej udalosti v editore n8n. Testovacie URL adresy fungujú len vtedy, keď n8n počúva na danú udalosť.
  3. Publikujte pracovný postup, prepnite uzol na jeho Production URL, skopírujte ju a znova spustite curl -i 'PASTE_PRODUCTION_URL_HERE' . Potvrďte vykonanie na karte Executions . Produkčné požiadavky webhookov vyžadujú publikovaný pracovný postup a ich údaje sa nezobrazujú v testovacom náhľade editora.

Ide zámerne o jednoduchý test funkčnosti bez autentifikácie: nikdy doň neposielajte tajné údaje. Po testovaní postup zrušte z publikovania alebo odstráňte, prípadne pred použitím verejného koncového bodu na skutočné údaje nastavte autentifikáciu webhooku alebo obmedzenie IP adries. Pozrite si oficiálnu dokumentáciu k testovacím a produkčným webhookom.

6. Pred zmenou pevných verzií vytvorte zálohu

Uložte obnoviteľný výpis PostgreSQL a trvalý dátový zväzok n8n, súbor .envso šifrovacím kľúčom a potrebné externé súbory do úložiska mimo tohto servera. Pred aktualizáciou produkcie overte obnovu podľa návodu na zálohovanie a obnovu . Príklady príkazov:

# Pred zmenou pevne určených verzií zálohujte databázu, šifrovací kľúč, údaje inštancie
# aj súbory.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# Po zabezpečení zálohy mimo tohto VPS:
docker compose pull
docker compose up -d
docker compose ps

Pevne určenú verziu N8N_VERSION meňte až po prečítaní poznámok k vydaniu; obrazy n8n aj procesu na vykonávanie úloh musia byť aktualizované spoločne. Pri bežnej údržbe nespúšťajte docker compose down -v , pretože tento príkaz odstráni pomenované dátové zväzky. Zmeny hlavnej verzie PostgreSQL vyžadujú plán aktualizácie databázy alebo exportu a obnovy; nahradenie obrazu PostgreSQL 18 značkou inej hlavnej verzie nie je automatickou migráciou.

Autoritatívne zdroje: návod n8n na Docker Compose, konfigurácia reverzného proxy servera a webhookov n8n a oficiálne poznámky k nasadeniu PostgreSQL. Nepredpokladáme žiadny benchmark infraštruktúry ani predinštalovanú funkciu konkrétneho poskytovateľa.

KONFIGURÁCIA

Tajné údaje a verejné URL nastavujte zámerne

Šifrovací kľúč

Pred ukladaním produkčných prístupových údajov nastavte a uchovajte silný šifrovací kľúč n8n. Rovnaký kľúč bude potrebný aj po obnove.

Prihlasovacie údaje PostgreSQL

Používajte vyhradené prihlasovacie údaje k databáze a heslá neukladajte do verejného zdrojového kódu.

Verejný názov hostiteľa

Nastavte skutočný externý názov hostiteľa a pôvod HTTPS namiesto internej adresy kontajnera.

URL webhookov

Nastavte N8N_WEBHOOK_URL na verejne dostupnú základnú URL adresu HTTPS a pri jednom dôveryhodnom reverznom proxy serveri nastavte N8N_PROXY_HOPS=1 . Premenná WEBHOOK_URL je od n8n 2.35.0 zastaraný alias; nekopírujte ju zo starších návodov.

BEŽNÉ PROBLÉMY

Prečo inštalácia n8n v Dockeri funguje lokálne, ale zlyháva v produkcii

Nesprávna URL webhooku

Spätné volania smerujú na localhost, HTTP alebo interný názov hostiteľa namiesto verejnej adresy HTTPS.

Chýbajúce trvalé úložisko

Pri opätovnom vytvorení kontajnera sa stratia údaje aplikácie alebo databázy.

Stratený šifrovací kľúč

Verejný port databázy

PostgreSQL je zbytočne vystavený internetu, hoci k nemu potrebuje pristupovať iba n8n.

Skontrolujte stav kontajnerov

Spustite docker compose ps a pred vyhlásením nasadenia za funkčné overte, že služby aplikácie a databázy bežia podľa očakávania.

Skontrolujte koncový bod stavu n8n

V príklade Compose vyššie nie je port 5678 publikovaný na hostiteľovi. Po zmene názvu hostiteľa skontrolujte verejný koncový bod príkazom curl -fsS https://n8n.example.com/healthz a ak HTTPS alebo databáza ešte nie sú pripravené, použite docker compose ps spolu s protokolmi služieb.

Používajte pevné verzie aplikácie

Neoverenú automatickú aktualizáciu obrazu nepovažujte za stratégiu údržby. Zaznamenajte používanú verziu n8n, prečítajte si poznámky k vydaniu a pred zmenou vytvorte zálohu.

Nemeňte hlavné verzie PostgreSQL bez postupu aktualizácie

Samotná zmena značky obrazu na inú hlavnú verziu PostgreSQL môže spôsobiť nekompatibilitu existujúceho dátového adresára. Namiesto predpokladu, že opätovné vytvorenie kontajnera vykoná migráciu, najprv vytvorte zálohu a použite postup aktualizácie databázy.

ČASTÉ OTÁZKY

Inštalácia n8n cez Docker: časté otázky

Potrebuje n8n pri použití Dockera PostgreSQL?

Docker nevyžaduje PostgreSQL a malé nasadenia môžu používať SQLite. Pri produkčnom nasadení na VPS poskytuje PostgreSQL robustnejší databázový základ a umožňuje neskoršie škálovanie režimu frontu.

Prečo zachovať trvalý zväzok n8n, ak PostgreSQL ukladá údaje?

Trvalý adresár n8n môže obsahovať dôležitý stav a konfiguráciu inštancie. Uchovávajte ho podľa architektúry nasadenia a nepredpokladajte, že databáza je jedinou súčasťou potrebnou na obnovu.

Prečo môj webhook zobrazuje localhost?

Interná adresa kontajnera sa líši od verejnej adresy. Nastavte externý názov hostiteľa, protokol a URL webhooku a zabezpečte, aby reverzný proxy server preposielal požadované hlavičky.

Má byť port 5678 verejne dostupný?

Pri bežnom produkčnom nasadení za reverzným proxy serverom sprístupnite HTTPS na proxy serveri a port aplikácie n8n ponechajte interný, pokiaľ neexistuje konkrétny prevádzkový dôvod postupovať inak.

Potrebujem Redis?

Nie pri štandardnom nasadení Dockera s jednou inštanciou. Redis sa stáva relevantným pri zámernom prechode na režim frontu a pracovníkov.

Sú externé procesy n8n na vykonávanie úloh totožné s pracovníkmi režimu frontu?

Nie. Externé procesy na vykonávanie úloh spúšťajú podporovaný kód úloh oddelene od hlavného procesu n8n a používajú spoločný autentifikačný token. Režim frontu Redis rozdeľuje vykonávanie pracovných postupov a má vlastné požiadavky na infraštruktúru. Tento príklad ukazuje externý proces na vykonávanie úloh, nie režim frontu Redis. Verzia obrazu procesu musí zodpovedať verzii n8n.
