تثبيت n8n على VPS

قم بتثبيت n8n على VPS باستخدام Docker Compose و PostgreSQL. يحتاج نشر الإنتاج أيضًا إلى بيانات ثابتة للتطبيق وقاعدة بيانات مستقرة N8N_ENCRYPTION_KEYواسم مضيف عام و HTTPS وتكوين خطاف الويب الصحيح. تحقق من هذه القطع قبل تنشيط سير عمل الإنتاج.

تركيب النسخ والتكيف

قم بتثبيت n8n على VPS الخاص بك باستخدام Docker Compose

استخدم هذا المثال لإنشاء نشر n8n على ملف الإدارة الذاتية Linux VPS. تقوم بتثبيت وصيانة n8n بنفسك؛ لا يتضمن اختيار خادم من خلال شريكنا نسخة n8n مثبتة مسبقًا. يجمع المثال بين n8n و PostgreSQL ومشغل المهام الخارجي و Caddy HTTPS في شبكة Compose خاصة. إنه قالب التكوين، ليس ادعاءً بالنشر المباشر الذي تم اختباره.

هل تريد التثبيت الجديد الأسرع بدلاً من ذلك؟ يوفر n8n أيضًا إعدادًا رسميًا من سطر واحد Docker. يمكنك تنزيل ومراجعة البرنامج النصي الخاص به باستخدام curl -fsSL https://get.n8n.io -o get-n8n.sh قبل الجري sh get-n8n.sh. يقوم هذا الخيار بتشغيل مثيل أولي يحتوي على SQLite على عنوان URL محلي ويتضمن n8n خدمات وضع الحماية المساعدة؛ إنها ليس نفس الشيء مثل هذا النشر العام HTTPS، PostgreSQL المدعوم VPS. يحتاج مكدس Sandbox الكامل الرسمي إلى المزيد من RAM و CPU من تثبيت n8n البسيط (يحدد دليل الإنشاء الخاص به على الأقل 4 GB RAM / 2 vCPUs). بالنسبة للإنتاج الذي يواجه الإنترنت VPS، تابع مع المجموعة التي تم تكوينها يدويًا أدناه.

1. إعداد Docker، DNS والوصول

قم بالاتصال عبر SSH مع وصول sudo وأشر إلى DNS A سجل لـ n8n.example.com إلى عنوان VPS IPv4 الخاص بك. على أ جديدة Ubuntu 22.04، 24.04 أو 26.04 VPS، تثبيت الأوامر التالية Docker المحرك والحديث docker compose البرنامج المساعد من مسؤول Docker الموقع apt مستودع:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

هذه هي طريقة المستودع الموجهة نحو الإنتاج في دليل التثبيت الرسمي Docker Ubuntu. لا تقم بإعادة تثبيت أو إزالة Docker بشكل أعمى على VPS التي تعمل بالفعل على الحاويات أو مواقع الويب الأخرى; قم أولاً بفحص التثبيت الحالي وتعارضات الحزمة المحتملة. بالنسبة إلى توزيعة Debian أو أي توزيعة أخرى، استخدم التعليمات الرسمية الخاصة بنظام التشغيل بدلاً من أوامر Ubuntu.

الآن تحقق من Docker نفسه، والمكون الإضافي Compose، و DNS ودليل العمل:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

إذا getent hosts لا يُرجع أي عنوان أو عنوانًا خاطئًا، قم بتصحيح DNS قبل البدء Caddy؛ استبدال n8n.example.com في هذا الدليل مع اسم المضيف الحقيقي الخاص بك. Docker يتطلب عادةً امتيازات الجذر: إذا لم يتمكن مستخدم SSH الخاص بك من تشغيل الإصدار الأحدث docker compose الأوامر مباشرة، ابدأ بها sudo. إضافة مستخدم إلى docker تمنح المجموعة وصولاً مكافئًا للجذر ولا يجب إجراؤها بشكل عرضي على خادم مشترك.

اجعل منفذ إدارة SSH الفعلي الخاص بك قابلاً للوصول قبل تمكين جدار الحماية. السماح للوارد HTTP (80) و HTTPS (443) بإصدار الشهادة والمحرر. Docker-يمكن لمنافذ الحاويات المنشورة تجاوز بعض قواعد UFW، لذا راجع إرشادات جدار الحماية الخاصة بالفقرة Docker وانشر فقط منافذ Caddy المقصودة. هذا المثال الإنشاء يفعل عمدا لا نشر PostgreSQL (5432)، n8n (5678) أو وسيط إدارة المهام (5679) على الإنترنت العام.

2. إنشاء قيم البيئة والحفاظ على المفتاح

من دليل المشروع، قم بإنشاء ثلاثة مختلفة القيم السداسية العشرية العشوائية مع:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

قم بإنشاء ملف باسم .env باستخدام القالب أدناه، استبدل كل REPLACE_WITH_RANDOM_HEX بقيمة تم إنشاؤها مختلفة، وقم بتغيير اسم المضيف والمنطقة الزمنية. المبينة 2.42.5 العلامة هي الإصدار المستقر مدرج في 8 أكتوبر 2026، المستخدمة هنا كمثال تكوين مؤرخ، لا يضمن النشر المباشر أو الأمان المستقبلي. قبل التثبيت، تحقق من إصدارات n8n الرسمية الحالية، ثم احتفظ بـ n8n وصورة مشغل المهام الخاصة به على نفس الإصدار الذي تم التحقق منه.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

لا تلتزم أبدًا .env إلى المستودع العام. قم بتخزين مفتاح التشفير وتعليمات الاسترداد بشكل آمن خارج VPS. يجب أن يظل المفتاح كما هو بعد إعادة إنشاء الحاوية أو ترحيلها.

3. اكتب compose.yaml لتثبيت جديد

في نفس الدليل، قم بإنشاء compose.yaml. يستخدم المثال اتفاقيات البيئة المتغيرة n8n الرسمية و PostgreSQL 18 PGDATA المسار الموثق بواسطة مشروع استضافة n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

للخدمات الأربع أدوار مميزة: PostgreSQL يخزن حالة قاعدة البيانات، n8n يدير سير العمل، n8n-runner ينفذ مهام التشغيل باستخدام إصدار مطابق ورمز مصادقة مشترك، ويتعامل Caddy مع HTTPS العام. خارجي عداء المهمة ليس Redis وضع قائمة الانتظار. فقط Caddy ينشر المنافذ المضيفة. يستخدم هذا الرسم التوضيحي البسيط دورًا واحدًا لقاعدة البيانات للإعداد؛ للحصول على فصل أقوى لامتيازات PostgreSQL، راجع مثال نشر n8n PostgreSQL الرسمي.

4. قم بإنشاء HTTPS Caddyfile

قم بإنشاء الملف Caddyfile (الحرف الكبير C، بدون امتداد) جنبًا إلى جنب compose.yaml. استبدل اسم المضيف المثال في كل مكان باسم DNS الخاص بك:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy يطلب ويجدد شهادات TLS العامة عندما يتم حل المجال بشكل صحيح ويمكن أن تصل حركة المرور الخارجية إلى المنافذ 80/443. لا تشير إلى DNS localhost. إذا قمت باستبدال Caddy بوكيل عكسي آخر، فأعد توجيه المضيف الأصلي والبروتوكول ورؤوس عنوان العميل واضبطه N8N_PROXY_HOPS للحصول على العدد الفعلي لقفزات الوكيل الموثوقة.

5. ابدأ تشغيل الحاويات واختبرها من الخارج

قم بتشغيل هذه الأوامر من دليل المشروع بعد الحفظ .env, compose.yaml و Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

الأمر الأخير يتحقق من HTTPS العامة نقطة النهاية الصحية إذا كان إصدار الشهادة لا يزال معلقًا، فافحص سجلات Caddy و DNS/المنافذ قبل إنهاء n8n معطلة. مفتوح https://n8n.example.com، قم بإنشاء حساب المالك الأول على الفور وقم بتمكين الحماية المناسبة لتسجيل الدخول. تأكد من أن المثيل ينفذ بالفعل سير العمل، وليس مجرد تحميل المحرر:

  1. في المحرر، قم بإنشاء سير عمل باستخدام ملف خطاف ويب الزناد. تعيين HTTP الطريقة ل GET، اختر Path vps-check، وتعيين الرد ل على الفور. حفظ سير العمل.
  2. انقر استمع لحدث الاختبار، انسخ كاملا عنوان URL التجريبي يظهر بواسطة n8n، ومن تشغيل جهاز آخر curl -i 'PASTE_TEST_URL_HERE' مع عنوان URL المنسوخ. توقع استجابة نجاح HTTP وظهور الحدث الوارد في محرر n8n. تعمل عناوين URL التجريبية فقط أثناء استماع n8n للحدث.
  3. نشر سير العمل، قم بتبديل العقدة إلى عنوان URL للإنتاج، انسخه وقم بتشغيله curl -i 'PASTE_PRODUCTION_URL_HERE' مرة أخرى. قم بتأكيد التنفيذ ضمن سير العمل عمليات الإعدام فاتورة غير مدفوعة. تحتاج طلبات خطاف الويب الخاصة بالإنتاج إلى نشر سير العمل وعدم إظهار حمولتها في العرض الاختباري للمحرر.

هذا اختبار دخان بسيط وغير موثق بشكل متعمد: لا ترسل إليه أسرارًا أبدًا. قم بإلغاء النشر/الحذف بعد الاختبار، أو قم بتكوين قيود مصادقة Webhook/IP قبل استخدام نقطة نهاية عامة للبيانات الحقيقية. راجع وثائق اختبار/إنتاج Webhook الرسمية.

6. قم بالنسخ الاحتياطي قبل تغيير الإصدارات المثبتة

احفظ تفريغ PostgreSQL القابل للاسترداد و حجم البيانات n8n المستمر، .env/ مفتاح التشفير والملفات الخارجية المطلوبة للتخزين خارج هذا الخادم. التحقق من الاستعادة باستخدام دليل النسخ الاحتياطي والاسترداد قبل تحديث الإنتاج. أوامر المثال:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

تغيير المثبت N8N_VERSION فقط بعد قراءة ملاحظات الإصدار؛ يجب أن تتقدم كل من n8n وصور العداء معًا. لا تركض docker compose down -v أثناء الصيانة الروتينية لأن ذلك يؤدي إلى حذف وحدات تخزين البيانات المسماة. PostgreSQL تتطلب تغييرات الإصدار الرئيسي ترقية قاعدة البيانات أو خطة التفريغ/الاستعادة؛ إن استبدال صورة Postgres 18 بعلامة رئيسية مختلفة لا يعد ترحيلًا تلقائيًا.

المراجع الرسمية: n8n Docker دليل الإنشاء، n8n تكوين الوكيل العكسي/خطاف الويب، وملاحظات نشر PostgreSQL الرسمية. لا يُفترض وجود أي معيار للبنية التحتية أو ميزة مثبتة مسبقًا خاصة بالموفر.

قم بتعيين الأسرار وعناوين URL العامة بشكل متعمد

مفتاح التشفير

قم بتعيين مفتاح تشفير n8n قوي واحتفظ به قبل تخزين بيانات اعتماد الإنتاج. نفس المفتاح مطلوب بعد الاسترداد.

استخدم بيانات اعتماد قاعدة البيانات المخصصة واحتفظ بكلمات المرور خارج نطاق التحكم بالمصادر العامة.

اسم المضيف العام

قم بتكوين اسم المضيف الخارجي الحقيقي وأصل HTTPS بدلاً من عنوان الحاوية الداخلية.

عنوان URL للويب هوك

تعيين N8N_WEBHOOK_URL إلى عنوان URL الأساسي HTTPS الذي يمكن الوصول إليه بشكل عام وتعيينه N8N_PROXY_HOPS=1 عندما يكون هناك وكيل عكسي واحد موثوق به. WEBHOOK_URL هو اسم مستعار مهمل في n8n 2.35.0 وما بعده؛ تجنب نسخه من البرامج التعليمية القديمة.

هل يحتاج n8n إلى PostgreSQL عند استخدام Docker؟

Docker لا يتطلب PostgreSQL، ويمكن لعمليات النشر الصغيرة استخدام SQLite. بالنسبة لنشر VPS الموجه نحو الإنتاج، يوفر PostgreSQL أساسًا أقوى لقاعدة البيانات ويدعم تحجيم وضع قائمة الانتظار لاحقًا.

لماذا تحتفظ بحجم n8n ثابت إذا كان PostgreSQL يخزن البيانات؟

يمكن أن يحتوي الدليل n8n المستمر على حالة وتكوين مثيل مهم. احتفظ بها وفقًا لتصميم النشر بدلاً من افتراض أن قاعدة البيانات هي أصل الاسترداد الوحيد.

لماذا يُظهر خطاف الويب الخاص بي المضيف المحلي؟

يختلف عنوان الحاوية الداخلية عن الأصل العام. قم بتكوين اسم المضيف الخارجي والبروتوكول وعنوان URL لخطاف الويب، وتأكد من قيام الوكيل العكسي بتمرير الرؤوس المطلوبة.

هل يجب أن يكون المنفذ 5678 عامًا؟

بالنسبة لنشر الإنتاج العادي خلف وكيل عكسي، قم بكشف HTTPS في الوكيل واحتفظ بمنفذ تطبيق n8n داخليًا ما لم يكن هناك سبب تشغيلي محدد لعدم القيام بذلك.

هل أحتاج إلى Redis؟

ليس للنشر القياسي لمثيل واحد Docker. Redis تصبح ذات صلة عندما تنتقل عمدا إلى وضع قائمة الانتظار والعمال.

هل مشغلو المهام الخارجيون n8n هم نفس العاملين في وضع قائمة الانتظار؟

لا. يقوم مشغلو المهام الخارجية بتنفيذ رمز المهمة المدعوم بشكل منفصل عن العملية الرئيسية n8n واستخدام رمز المصادقة المشترك. Redis يقوم وضع قائمة الانتظار بتوزيع عمليات تنفيذ سير العمل وله متطلبات البنية التحتية الخاصة به. يوضح هذا المثال مشغل مهمة خارجي، وليس وضع قائمة الانتظار Redis. قم بمطابقة إصدار صورة العداء مع إصدار n8n.
