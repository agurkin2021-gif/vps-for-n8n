INSTALACIJA POMOĆU DOCKERA

Instalacija n8n-a na VPS

Instalirajte n8n na VPS pomoću Docker Composea i PostgreSQL-a. Produkcijska instalacija također zahtijeva trajnu pohranu podataka aplikacije i baze, stabilan N8N_ENCRYPTION_KEY, javni naziv hosta, HTTPS i ispravnu konfiguraciju webhookova. Provjerite sve te dijelove prije aktiviranja produkcijskih radnih tijekova.

Odaberite VPS za n8n

Partnerska poveznica: možemo ostvariti proviziju od kupnje.

PREDUVJETI

Pripremite VPS prije pokretanja n8n-a

Linux VPS

Koristite održavani Linux poslužitelj s dovoljno resursa za n8n, PostgreSQL, Docker i obrnuti proxy.

DNS

Usmjerite domenu ili poddomenu na VPS prije izdavanja TLS certifikata i objave webhook URL-ova.

Docker Compose

Instalirajte Docker Engine i dodatak Compose iz podržanih paketa za svoj operacijski sustav.

Vatrozid

Otvorite samo nužne administracijske i web-portove. PostgreSQL i interne aplikacijske usluge zadržite privatnima.

Instalirate na VPS-u koji već hosta web-stranice? Možete dodati n8n na poslužitelj kojim upravljate ako ima dovoljno procesorskih resursa, RAM-a i prostora za pohranu. Međutim, ako Nginx, Apache, Caddy ili drugi obrnuti proxy već koristi portove 80/443, nemojte pokrenuti niže prikazani Caddy kontejner bez izmjena jer će doći do sukoba portova. Umjesto toga usmjerite novu poddomenu n8n-a kroz postojeći obrnuti proxy uz odgovarajuće privatno umrežavanje ili koristite čisti VPS za točan primjer konfiguracije Compose. Sačuvajte ostale stranice i njihove TLS postavke; primjer pretpostavlja da su portovi 80/443 slobodni.

INSTALACIJA S PRILAGODBOM PRIMJERA

Instalirajte n8n na VPS pomoću Docker Composea

Koristite ovaj primjer za postavljanje n8n-a na Linux VPS-u kojim sami upravljate. Sami instalirate i održavate n8n; odabir poslužitelja preko našeg partnera ne uključuje unaprijed instaliran n8n. Primjer objedinjuje n8n, PostgreSQL, vanjski izvršitelj zadataka i Caddy HTTPS u privatnoj Compose mreži. To je predložak konfiguracije, a ne tvrdnja da je instalacija testirana uživo.

Želite najbržu novu instalaciju? n8n nudi i službeni postupak postavljanja Dockera jednom naredbom. Skriptu možete preuzeti i pregledati naredbom curl -fsSL https://get.n8n.io -o get-n8n.sh prije pokretanja sh get-n8n.sh. Ta opcija pokreće početnu instancu sa SQLiteom na lokalnom URL-u i uključuje sandbox usluge n8n Assistanta; to nije isto što i ova VPS instalacija s javnim HTTPS-om i PostgreSQL-om. Službeni puni sandbox sustav zahtijeva više RAM-a i CPU-a od jednostavne instalacije n8n-a (vodič za Compose navodi najmanje 4 GB RAM-a / 2 vCPU-a). Za produkcijski VPS dostupan putem interneta nastavite s ručno konfiguriranim sustavom u nastavku.

1. Pripremite Docker, DNS i pristup

Povežite se preko SSH-a s pravima sudo i usmjerite DNS A zapis za n8n.example.com na IPv4 adresu svojeg VPS-a. Na svježe instaliranom Ubuntu 22.04, 24.04 ili 26.04 sustavu na VPS-u sljedeće naredbe instaliraju Docker Engine i suvremeni dodatak docker compose iz Dockerova službenog potpisanog apt repozitorija:

# Nova službena instalacija Ubuntu 22.04 / 24.04 / 26.04
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Dodajte Dockerov potpisani apt repozitorij
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Ovo je postupak za produkcijsku instalaciju putem repozitorija iz službenog vodiča za instalaciju Dockera na Ubuntu. Nemojte naslijepo ponovno instalirati ili uklanjati Docker na VPS-u na kojem već rade kontejneri ili druge web-stranice; najprije pregledajte postojeću instalaciju i moguće sukobe paketa. Za Debian ili drugu distribuciju umjesto Ubuntu naredbi koristite odgovarajuće službene upute za taj operacijski sustav.

Sada provjerite Docker, dodatak Compose, DNS i radni direktorij:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Ako getent hosts ne vrati adresu ili vrati pogrešnu adresu, ispravite DNS prije pokretanja Caddyja; zamijenite n8n.example.com u cijelom vodiču stvarnim nazivom hosta. Docker obično zahtijeva root ovlasti: ako vaš SSH korisnik ne može izravno izvršavati kasnije docker compose naredbe, dodajte im prefiks sudo. Dodavanje korisnika u grupu docker daje mu ovlasti jednake root korisniku i to ne treba olako raditi na zajedničkom poslužitelju.

Prije uključivanja vatrozida osigurajte da stvarni administracijski SSH port ostane dostupan. Dopustite dolazni HTTP (80) i HTTPS (443) za izdavanje certifikata i uređivač. Portovi koje Docker objavljuje mogu zaobići neka UFW pravila, stoga pregledajte Dockerove smjernice za vatrozid i objavite samo predviđene Caddy portove. Ovaj primjer Compose namjerno nemojte ne izlaže PostgreSQL (5432), n8n (5678) ni posrednik izvršitelja zadataka (5679) javnom internetu.

2. Izradite vrijednosti okruženja i sačuvajte ključ

U direktoriju projekta generirajte tri različite nasumične heksadekadske vrijednosti pomoću:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Izradite datoteku .env prema predlošku u nastavku, svaku pojavu REPLACE_WITH_RANDOM_HEX zamijenite različitom generiranom vrijednošću te promijenite naziv hosta i vremensku zonu. Prikazana oznaka verzije 2.42.5 odnosi se na stabilno izdanje navedeno 8. listopada 2026., koje ovdje služi kao vremenski određen primjer konfiguracije, a ne kao jamstvo da je instalacija testirana uživo ili da će u budućnosti biti sigurna. Prije instalacije provjerite najnovija službena izdanja n8n-a, a sliku n8n-a i izvršitelja zadataka držite na istoj provjerenoj verziji.

# .env — zamijenite tri primjera tajnih vrijednosti
# Fiksirajte održavano izdanje n8n-a; n8n i izvršitelj moraju imati istu verziju.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Nikada ne spremajte .env u javni repozitorij. Ključ za šifriranje i upute za oporavak čuvajte na sigurnom mjestu izvan VPS-a. Ključ mora ostati isti nakon ponovnog stvaranja kontejnera ili migracije.

3. Napišite compose.yaml za novu instalaciju

U istom direktoriju izradite compose.yaml. Primjer koristi službene konvencije n8n-a za varijable okruženja i PostgreSQL 18 PGDATA putanju dokumentiranu u n8n projektu za hosting:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Četiri usluge imaju različite uloge: PostgreSQL pohranjuje stanje baze, n8n pokreće radne tijekove, n8n-runner izvršava zadatke pomoću odgovarajuće verzije i zajedničkog autentifikacijskog tokena, a Caddy obrađuje javni HTTPS. Vanjski izvršitelj zadataka nije isto što i način rada s Redis redom čekanja. Samo Caddy objavljuje portove na hostu. Ovaj jednostavni primjer koristi jednu ulogu baze podataka za postavljanje; za strože razdvajanje PostgreSQL ovlasti pogledajte službeni primjer n8n instalacije s PostgreSQL-om.

4. Izradite HTTPS Caddyfile

Izradite datoteku Caddyfile (veliko slovo C, bez nastavka) uz compose.yaml. Svugdje zamijenite primjer naziva hosta vlastitim DNS nazivom:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy traži i obnavlja javne TLS certifikate ako se domena ispravno razrješava i vanjski promet može dosegnuti portove 80/443. Nemojte usmjeravati DNS na localhost. Ako Caddy zamijenite drugim obrnutim proxyjem, proslijedite izvorna zaglavlja hosta, protokola i klijentske adrese te prilagodite N8N_PROXY_HOPS stvarnom broju pouzdanih proxy skokova.

5. Pokrenite kontejnere i testirajte izvana

Pokrenite ove naredbe iz direktorija projekta nakon spremanja .env, compose.yaml i Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Posljednja naredba provjerava javni HTTPS endpoint za provjeru zdravlja sustava. Ako izdavanje certifikata još traje, pregledajte Caddyjeve zapisnike i DNS/portove prije nego što zaključite da n8n ne radi. Otvorite https://n8n.example.com, odmah izradite prvi vlasnički račun i uključite primjerenu zaštitu prijave. Provjerite da instanca doista izvršava radni tijek, a ne samo da učitava uređivač:

  1. U uređivaču izradite radni tijek s okidačem Webhook . Postavite HTTP Method na GET, odaberite Path , a, a zatim postavite Respond na Immediately. Spremite radni tijek.
  2. Kliknite Listen for Test Event, kopirajte cijeli Test URL koji prikazuje n8n i s drugog uređaja pokrenite curl -i 'PASTE_TEST_URL_HERE' s kopiranim URL-om. Očekujte uspješan HTTP odgovor i prikaz dolaznog događaja u uređivaču n8n-a. Testni URL-ovi rade samo dok n8n osluškuje događaj.
  3. Objavite radni tijek, prebacite čvor na njegov Production URL, kopirajte ga i ponovno pokrenite curl -i 'PASTE_PRODUCTION_URL_HERE' . Potvrdite izvršavanje na kartici Executions . Produkcijski webhook zahtjevi zahtijevaju objavljen radni tijek i ne prikazuju svoj sadržaj u testnom prikazu uređivača.

Ovo je namjerno jednostavan test bez autentifikacije: nikada mu ne šaljite tajne podatke. Nakon testiranja povucite objavu ili izbrišite test, odnosno konfigurirajte webhook autentifikaciju ili ograničenje IP adresa prije upotrebe javnog endpointa za stvarne podatke. Pogledajte službenu dokumentaciju testnih i produkcijskih webhookova.

6. Napravite sigurnosnu kopiju prije promjene fiksiranih verzija

Spremite PostgreSQL sigurnosnu kopiju koja se može vratiti, i trajni podatkovni volumen n8n-a, .envključ za šifriranje i potrebne vanjske datoteke na pohranu izvan ovog poslužitelja. Provjerite vraćanje pomoću vodiča za sigurnosno kopiranje i oporavak prije ažuriranja produkcijskog okruženja. Primjer naredbi:

# Sigurnosno kopirajte bazu, ključ za šifriranje i podatke instance,
# kao i datoteke, prije promjene fiksiranih verzija.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# Nakon što zaštitite sigurnosnu kopiju izvan ovog VPS-a:
docker compose pull
docker compose up -d
docker compose ps

Promijenite fiksiranu N8N_VERSION tek nakon čitanja napomena o izdanju; slike n8n-a i izvršitelja zadataka moraju se ažurirati zajedno. Nemojte pokretati docker compose down -v tijekom redovitog održavanja jer to briše imenovane podatkovne volumene. Promjene glavne verzije PostgreSQL-a zahtijevaju plan nadogradnje baze ili izvoza i vraćanja; zamjena slike Postgresa 18 drugom glavnom verzijom ne obavlja automatsku migraciju.

Mjerodavni izvori: vodič n8n-a za Docker Compose, konfiguracija obrnutog proxyja i webhookova u n8n-u te službene upute za PostgreSQL. Ne pretpostavljaju se testovi performansi infrastrukture ni unaprijed instalirane značajke pojedinog pružatelja.

PROVJERA NAKON INSTALACIJE

Provjerite stanje prije povezivanja stvarnih radnih tijekova

Provjerite stanje kontejnera

Pokrenite docker compose ps i potvrdite da aplikacija i usluge baze rade očekivano prije nego što sustav smatrate ispravnim.

Provjerite endpoint za stanje n8n-a

U gornjem primjeru Compose port 5678 nije objavljen na hostu. Provjerite javni endpoint pomoću curl -fsS https://n8n.example.com/healthz nakon promjene naziva hosta, a ako HTTPS ili baza nisu spremni, koristite docker compose ps i zapisnike usluga.

Fiksirajte verzije aplikacije

ČESTA PITANJA

Instalacija n8n-a putem Dockera: česta pitanja

Treba li n8n-u PostgreSQL pri korištenju Dockera?

Docker ne zahtijeva PostgreSQL, a manje instalacije mogu koristiti SQLite. Za VPS instalaciju namijenjenu produkciji PostgreSQL pruža čvršću bazu i omogućuje kasnije skaliranje u načinu rada s redom čekanja.

Zašto čuvati trajni volumen n8n-a ako PostgreSQL pohranjuje podatke?

Trajni direktorij n8n-a može sadržavati važno stanje i konfiguraciju instance. Sačuvajte ga prema načinu postavljanja, umjesto da pretpostavite kako je baza jedina komponenta potrebna za oporavak.

Zašto moj webhook prikazuje localhost?

Interna adresa kontejnera razlikuje se od javnog ishodišta. Konfigurirajte vanjski naziv hosta, protokol i URL webhooka te osigurajte da obrnuti proxy prosljeđuje potrebna zaglavlja.

Treba li port 5678 biti javan?

Kod uobičajene produkcijske instalacije iza obrnutog proxyja izložite HTTPS na proxyju, a aplikacijski port n8n-a zadržite internim, osim ako postoji poseban operativni razlog za drukčije.

Trebam li Redis?

Ne za standardnu Docker instalaciju s jednom instancom. Redis postaje važan kada namjerno prijeđete na način rada s redom čekanja i radne procese.

Jesu li vanjski n8n izvršitelji zadataka isto što i radni procesi u načinu rada s redom čekanja?

Nisu. Vanjski izvršitelji zadataka izvršavaju podržani kod zadataka odvojeno od glavnog n8n procesa i koriste zajednički autentifikacijski token. Način rada s Redis redom čekanja raspoređuje izvršavanja radnih tijekova i ima vlastite infrastrukturne zahtjeve. Primjer prikazuje vanjski izvršitelj zadataka, a ne Redis red čekanja. Verzija slike izvršitelja mora odgovarati verziji n8n-a.
