DOCKER-INSTALLATION

Installer n8n på en VPS

Installer n8n på en VPS med Docker Compose og PostgreSQL. En produktionsinstallation kræver også vedvarende data til applikationen og databasen, en stabil N8N_ENCRYPTION_KEY, et offentligt værtsnavn, HTTPS og korrekt webhook-konfiguration. Kontrollér disse dele, før du aktiverer workflows i produktion.

FORUDSÆTNINGER

Klargør din VPS, før du starter n8n

Linux-VPS

Brug en vedligeholdt Linux-server med tilstrækkelige ressourcer til n8n, PostgreSQL, Docker og reverse proxyen.

DNS

Lad et domæne eller underdomæne pege på VPS'en, før du udsteder TLS-certifikater og offentliggør webhook-URL'er.

Docker Compose

Installer Docker Engine og Compose-pluginet fra understøttede pakker til operativsystemet.

Firewall

Åbn kun de nødvendige porte til administration og webtrafik. Hold PostgreSQL og interne applikationstjenester private.

Installerer du på en VPS, der allerede hoster websteder? Du kan tilføje n8n på en server, du selv administrerer, hvis CPU, RAM og lagerplads tillader det. Hvis Nginx, Apache, Caddy eller en anden reverse proxy allerede bruger port 80/443, må du ikke starte Caddy-containeren fra eksemplet nedenfor uden ændringer: Portene vil være i konflikt. Opret i stedet en rute til et nyt n8n-underdomæne via din eksisterende reverse proxy og et passende privat netværk, eller brug en ren VPS til præcis dette Compose-eksempel. Bevar de øvrige websteder og deres TLS-konfiguration; eksemplet forudsætter, at port 80/443 er ledige.

INSTALLATIONSEKSEMPEL, DER SKAL TILPASSES

Installer n8n på din VPS med Docker Compose

Brug dette eksempel til at opbygge en n8n-installation på en selvadministreret Linux-VPS. Du installerer og vedligeholder selv n8n; valg af en server gennem vores partner omfatter ikke en forudinstalleret n8n-instans. Eksemplet kombinerer n8n, PostgreSQL, en ekstern task runner og Caddy HTTPS i et privat Compose-netværk. Det er en konfigurationsskabelon, ikke en påstand om, at installationen er afprøvet i drift.

Vil du i stedet have den hurtigste nye installation? n8n tilbyder også en officiel Docker-installation med én kommando. Du kan hente og gennemgå scriptet med curl -fsSL https://get.n8n.io -o get-n8n.sh før du kører sh get-n8n.sh. Denne mulighed starter en indledende instans med SQLite på en lokal URL og omfatter sandkassetjenester til n8n Assistant; det er ikke det samme som denne VPS-installation med offentlig HTTPS og PostgreSQL. Den officielle komplette sandkasse kræver mere RAM og CPU end en enkel n8n-installation (dens Compose-guide angiver mindst 4 GB RAM / 2 vCPU'er). Fortsæt med det manuelt konfigurerede miljø nedenfor, hvis VPS'en skal være offentlig tilgængelig i produktion.

1. Klargør Docker, DNS og adgang

Opret forbindelse via SSH med sudo-adgang, og lad en DNS A-record for n8n.example.com pege på VPS'ens IPv4-adresse. På en ny Ubuntu 22.04-, 24.04- eller 26.04-installation installerer følgende kommandoer Docker Engine og det moderne docker compose plugin fra Dockers officielle signerede apt pakkearkiv:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Dette er metoden med pakkearkiv til produktionsbrug i Dockers officielle installationsguide til Ubuntu. Geninstaller eller fjern ikke Docker ukritisk på en VPS, der allerede kører containere eller andre websteder; undersøg først den eksisterende installation og mulige pakkekonflikter. Brug de tilsvarende officielle vejledninger til det konkrete operativsystem i stedet for Ubuntu-kommandoerne, hvis du bruger Debian eller en anden distribution.

Kontrollér nu Docker, Compose-pluginet, DNS og arbejdsmappen:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Hvis getent hosts ikke returnerer en adresse eller returnerer en forkert adresse, skal du rette DNS, før du starter Caddy; erstat n8n.example.com overalt i denne guide med dit rigtige værtsnavn. Docker kræver normalt root-rettigheder: Hvis din SSH-bruger ikke kan udføre de senere docker compose kommandoer direkte, skal du sætte sudoforan. At tilføje en bruger til docker gruppen giver rettigheder svarende til root og bør ikke gøres uden omtanke på en delt server.

Sørg for, at din faktiske SSH-administrationsport fortsat er tilgængelig, før du aktiverer en firewall. Tillad indgående HTTP (80) og HTTPS (443) til certifikatudstedelse og editoren. Offentliggjorte Docker-containerporte kan omgå visse UFW-regler, så gennemgå Dockers firewallvejledning, og offentliggør kun de tilsigtede Caddy-porte. Dette Compose-eksempel offentliggør bevidst ikke PostgreSQL (5432), n8n (5678) eller task runner-brokeren (5679) på det offentlige internet.

2. Opret miljøværdier, og bevar nøglen

Generér fra projektmappen tre forskellige tilfældige hexadecimale værdier med:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Opret en fil med navnet .env ud fra skabelonen nedenfor, erstat hver REPLACE_WITH_RANDOM_HEX med en forskellig genereret værdi, og ændr værtsnavn og tidszone. Den viste 2.42.5 version er den stabile udgivelse opført den 8. oktober 2026og bruges her som et dateret konfigurationseksempel, ikke som garanti for en afprøvet installation eller fremtidig sikkerhed. Kontrollér de aktuelle officielle n8n-udgivelser før installationen, og hold n8n og det tilhørende task runner-image på samme verificerede version.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Læg aldrig .env i et offentligt repository. Gem krypteringsnøglen og gendannelsesvejledningen sikkert uden for VPS'en. Nøglen skal forblive den samme efter genskabelse eller migrering af containere.

3. Skriv compose.yaml til en ny installation

Opret i samme mappe compose.yaml. Eksemplet bruger de officielle konventioner for n8n-miljøvariabler og PostgreSQL 18- PGDATA stien, som er beskrevet i n8n-hostingprojektet:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

De fire tjenester har hver sin rolle: PostgreSQL gemmer databasedata, n8n kører workflows, n8n-runner udfører runner-opgaver med en tilsvarende version og et fælles godkendelsestoken, og Caddy håndterer offentlig HTTPS. En ekstern task runner er ikke Redis-køtilstand. Kun Caddy offentliggør værtsporte. Dette enkle eksempel bruger én databaserolle til opsætningen; se det officielle n8n-eksempel til PostgreSQL-installation for bedre adskillelse af databaseprivilegier.

4. Opret Caddyfile til HTTPS

Opret filen Caddyfile (stort C, ingen filendelse) ved siden af compose.yaml. Erstat eksempelværtsnavnet med dit eget DNS-navn overalt:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy anmoder om og fornyer offentlige TLS-certifikater, når domænet peger korrekt, og ekstern trafik kan nå port 80/443. Lad ikke DNS pege på localhost. Hvis du erstatter Caddy med en anden reverse proxy, skal du videresende de oprindelige headere for vært, protokol og klientadresse og tilpasse N8N_PROXY_HOPS til det faktiske antal betroede proxyhop.

5. Start containerne, og test udefra

Kør disse kommandoer fra projektmappen, når du har gemt .env, compose.yaml og Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Den sidste kommando kontrollerer health-endpointet over offentlig HTTPS . Hvis certifikatudstedelsen stadig afventer, skal du undersøge Caddy-logfiler og DNS/porte, før du konkluderer, at n8n er defekt. Åbn https://n8n.example.com, opret straks den første ejerkonto, og aktiver passende beskyttelse af login. Kontrollér, at instansen faktisk kan køre et workflow, og ikke blot at editoren indlæses:

  1. Opret i editoren et workflow med en Webhook trigger. Indstil HTTP Method til GET, vælg den angivne Path vps-check, og indstil Respond til Immediately. Gem workflowet.
  2. Klik på Listen for Test Event, kopiér den fulde Test URL , som n8n viser, og kør fra en anden enhed curl -i 'PASTE_TEST_URL_HERE' med den kopierede URL. Forvent et vellykket HTTP-svar, og kontrollér, at den indgående hændelse vises i n8n-editoren. Test-URL'er virker kun, mens n8n lytter efter hændelsen.
  3. Publicér workflowet, skift noden til dens Production URL, kopiér den, og kør curl -i 'PASTE_PRODUCTION_URL_HERE' igen. Kontrollér kørslen under workflowets fane Executions . Produktionswebhooks kræver, at workflowet er publiceret, og viser ikke deres payload i editorens testvisning.

Dette er en bevidst enkel, ikke-godkendt grundtest: Send aldrig hemmeligheder til endpointet. Ophæv publiceringen eller slet det efter testen, eller konfigurér webhook-godkendelse/IP-begrænsninger, før du bruger et offentligt endpoint til rigtige data. Se den officielle dokumentation om test- og produktionswebhooks.

6. Tag backup, før du ændrer fastlåste versioner

Gem et genskabeligt PostgreSQL-dump og den vedvarende n8n-datadiskenhed, .env/krypteringsnøglen og de nødvendige eksterne filer i lagerplads uden for denne server. Kontrollér en gendannelse med guiden til sikkerhedskopiering og gendannelse før du opdaterer produktionen. Eksempelkommandoer:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Ændr kun den fastlåste N8N_VERSION efter at have læst udgivelsesnoterne; både n8n- og runner-images skal opgraderes sammen. Kør ikke docker compose down -v ved almindelig vedligeholdelse, da det sletter navngivne datadiskenheder. Store versionsskift i PostgreSQL kræver en databaseopgradering eller en plan for dump og gendannelse; en ændring fra Postgres 18-imaget til en anden hovedversion er ikke en automatisk migrering.

Autoritative kilder: n8n's Docker Compose-guide, n8n's konfiguration af reverse proxy/webhooks og de officielle PostgreSQL-noter om installation. Der forudsættes ingen infrastrukturbenchmarks eller udbyderspecifikke forudinstallerede funktioner.

ALMINDELIGE FEJL

Hvorfor en n8n-Docker-installation virker lokalt, men fejler i produktion

Forkert webhook-URL

Callbacks peger på localhost, HTTP eller et internt værtsnavn i stedet for den offentlige HTTPS-adresse.

Manglende vedvarende lagring

Applikations- eller databasedata forsvinder, når en container genskabes.

Mistet krypteringsnøgle

Gemte legitimationsoplysninger kan ikke længere bruges efter genopbygning, fordi den nye instans bruger en anden nøgle.

Offentlig databaseport

KONTROL EFTER INSTALLATION

Kontrollér systemets tilstand, før du forbinder rigtige workflows

Kontrollér containertilstand

Kør docker compose ps , og kontrollér, at applikations- og databasetjenesterne kører som forventet, før du betragter installationen som velfungerende.

Kontrollér n8n's health-endpoint

Med Compose-eksemplet ovenfor er port 5678 ikke offentliggjort på værten. Kontrollér det offentlige endpoint med curl -fsS https://n8n.example.com/healthz efter at have ændret værtsnavnet, og brug docker compose ps samt tjenesternes logfiler, hvis HTTPS eller databasen endnu ikke er klar.

Lås applikationsversioner fast

Betragt ikke en uigennemgået opdatering af et flydende image som en vedligeholdelsesstrategi. Registrér den n8n-version, du kører, læs udgivelsesnoter, og tag backup, før du ændrer den.

Opgrader ikke PostgreSQL's hovedversion direkte

Hvis du kun ændrer Postgres-imagets hovedversion, kan en eksisterende datamappe blive inkompatibel. Tag backup, og følg databasens opgraderingsprocedure i stedet for at antage, at genskabelse af containeren udfører versionsmigreringen.

FAQ

Installation af n8n med Docker: Ofte stillede spørgsmål

Kræver n8n PostgreSQL, når man bruger Docker?

Docker kræver ikke PostgreSQL, og små installationer kan bruge SQLite. Til en produktionsorienteret VPS-installation giver PostgreSQL et mere robust databasegrundlag og understøtter senere skalering med køtilstand.

Hvorfor bevare en vedvarende n8n-diskenhed, hvis PostgreSQL gemmer data?

Den vedvarende n8n-mappe kan indeholde vigtige instansdata og konfiguration. Bevar den i overensstemmelse med installationens opbygning i stedet for at antage, at databasen er den eneste nødvendige del til gendannelse.

Hvorfor viser min webhook localhost?

Den interne containeradresse er anderledes end den offentlige adresse. Konfigurér det eksterne værtsnavn, protokollen og webhook-URL'en, og sørg for, at reverse proxyen videresender de nødvendige headere.

Skal port 5678 være offentlig?

Ved en normal produktionsinstallation bag en reverse proxy skal HTTPS være offentlig på proxyen, mens n8n's applikationsport forbliver intern, medmindre der findes en særlig driftsmæssig grund til andet.

Har jeg brug for Redis?

Ikke til en almindelig Docker-installation med én instans. Redis bliver relevant, når du bevidst går over til køtilstand og arbejdere.

Er eksterne n8n-task runners det samme som arbejdere i køtilstand?

Nej. Eksterne task runners kører understøttet opgavekode adskilt fra n8n's hovedproces og bruger et fælles godkendelsestoken. Redis-køtilstand fordeler workflowkørsler og har sine egne infrastrukturkrav. Eksemplet viser en ekstern task runner, ikke Redis-køtilstand. Sørg for, at task runner-imagets version passer til n8n-versionen.
