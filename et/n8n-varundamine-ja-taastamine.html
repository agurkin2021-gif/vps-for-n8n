VARUNDAMINE JA TAASTAMINE

n8n-i varundamine ja taastamine

Ise majutatava n8n-i varundamiseks ja taastamiseks säilitage SQLite'i andmebaas või terviklik PostgreSQL-i varukoopia, püsiv .n8n kaust ja algne krüptimisvõti, juurutuse konfiguratsioon ning kõik välised binaarandmed ja ühendatud failidest sõltuvused. Hoidke krüptitud varukoopiat väljaspool VPS-i ja katsetage taastamist eraldi eksemplaris. Töövoogude ja juurdepääsuandmete CLI-eksport sobib valikuliseks taastamiseks; üksnes JSON-eksport ei ole serveri täielik varukoopia.

LÜHIKE KONTROLLNIMEKIRI

Mida peab n8n-i varukoopia kaitsma?

Andmebaas

Varundage PostgreSQL-i andmebaas või eksemplari kasutatav SQLite'i andmebaasifail. Andmebaas sisaldab n8n-i põhiandmeid, sealhulgas töövooge, juurdepääsuandmeid ja täitmisandmeid.

Krüptimisvõti

Hoidke täpset n8n-i krüptimisvõtit eraldi ja turvaliselt. Taastatud krüptitud juurdepääsuandmed vajavad sama võtit.

Püsifailid

Kaasake n8n-i püsiv andmekataloog ning kõik ühendatud failid, binaarandmete hoidlad ja töövoogude failid, millest juurutus sõltub.

Juurutuse konfiguratsioon

Säilitage Compose'i ja konfiguratsioonifailid ning muud mittesalajased seaded, mida vajate süsteemi taastamiseks. Kaitske saladusi asjakohaste juurdepääsupiirangutega.

KAKS VARUNDUSTASET

Loogiline eksport või täielik taastamine pärast tõrget

Töövoogude ja juurdepääsuandmete eksport

n8n-i CLI-eksport sobib migratsiooniks, versioonitud töövoogude koopiate tegemiseks ja valikuliseks taastamiseks. Juurdepääsuandmeid saab eksportida krüptitult ja seejärel sama krüptimisvõtmega importida. Ühe töövoo taastamiseks valige töövooredaktori kolme punktiga menüüst selle JSON-i allalaadimine (Download) ja importige see valikuga Import from File eraldi kontrollimiseks mõeldud töövoogu või isoleeritud eksemplari. Enne aktiivse töövoo asendamist kontrollige juurdepääsuandmeid, töövoo ID-sid ja sõlmede parameetreid: töövoo JSON-i taastamine ei taasta kogu serverit.

Andmebaasiüksuste eksport

CLI saab eksportida andmebaasiüksusi andmete teisaldamiseks toetatud andmebaasitüüpide vahel. Täitmisajaloo tabelid on valikulised, sest need võivad olla väga suured.

Kogu eksemplari taastamine

Kui server ei tööta, on vaja kaitsta tegelikku andmebaasi, krüptimisvõtit, püsifaile ja juurutuse sõltuvusi. Ärge eeldage, et töövoo JSON-eksport taastab kogu eksemplari.

Teenusepakkuja hetktõmmis

VPS-i hetktõmmis on kasulik täiendav taastamisvõimalus, kuid see ei tohiks olla ainus koopia ega asendada eraldi kontrollitud rakenduse ja andmebaasi varukoopiat.

ANDMEBAAS

Tehke andmebaasist terviklik varukoopia

PostgreSQL

Kasutage PostgreSQL-i jaoks järjepideva olekuga varundusmeetodit ja hoidke valminud varukoopiat VPS-ist eraldi. Samal rikkis kettal olev andmebaasikoopia ei ole piisav tõrketaaste.

SQLite

Kui juurutus kasutab SQLite'i, kaitske n8n-i püsivast andmekataloogist pärinevat andmebaasifaili. Ärge kopeerige aktiivselt muudetavat andmebaasi ebaturvalises olekus.

Täitmisajalugu

Otsustage, kas ajaloolised täitmisandmed kuuluvad taastamise eesmärgi hulka. Need võivad varukoopiat oluliselt suurendada, mistõttu lähtuge säilitamise ja nõuete täitmise vajadustest.

Andmebaasi versioon

Märkige üles lähtejuurutuse andmebaasimootor ja versioon, et taastamiskeskkond oleks sellega ühilduv.

PostgreSQL Docker Compose'iga VPS-is. Kui PostgreSQL-i teenuse nimi on postgres ning andmebaasi ja kasutaja nimi on mõlemal n8n, loob järgmine käsk hosti arvutisse PostgreSQL-i kohandatud vormingus tervikliku varukoopia. Enne käsu käivitamist kontrollige tegelikku Compose'i faili ning vajaduse korral muutke andmebaasi juurdepääsuandmeid ja teenusenimesid. pg_dump võib teha loogiliselt tervikliku koopia ka töötava PostgreSQL-i korral; see ei varunda eraldi .n8n kasutajakausta ega väliseid binaarandmeid.

# In the Docker Compose project; adapt service, DB and user names
docker compose exec -T postgres pg_dump -U n8n -d n8n -Fc > n8n-postgres.dump
test -s n8n-postgres.dump
# Check that the archive has a readable object list
docker compose exec -T postgres pg_restore --list < n8n-postgres.dump

Arhiivisisu kontroll leiab ilmsed vorminguprobleemid, kuid ei tõesta, et andmeid saab taastada. Hoidke krüptitud koopiat väljaspool serverit ja harjutage taastamist. Andmebaasispetsiifilisi võimalusi selgitab PostgreSQL-i ametlik pg_dump dokumentatsioon.

SQLite Dockeris. Vaikimisi SQLite'i juurutuses asuvad database.sqlite ja genereeritud krüptimisvõtme konfiguratsioon püsivas .n8n kaustas (tavaliselt ühendatud aadressile /home/node/.n8n). Ärge pidage SQLite'i lihtsat jooksvalt tehtud koopiat terviklikuks. Enne kausta kopeerimist peatage n8n ja teised andmebaasi kirjutajad või kasutage SQLite'i toetatud veebivarundusmehhanismi, kui katkestamine pole võimalik:

# Only for SQLite and the default /home/node/.n8n mount
# Stop n8n (and any other writers) before copying an SQLite database
docker compose stop n8n
docker compose cp n8n:/home/node/.n8n ./n8n-user-folder-backup
docker compose start n8n

Need on näidiskäsud toodud teenuse ja failitee jaoks, mitte universaalne andmeköidete paigutus. Kopeeritud kaust on alguses endiselt samas VPS-is; teisaldage see serverist välja ja kaitske seda. Kui kasutate järjekorrarežiimi täitmisprotsesse või muid kirjutajaid, peatage ka need ja järgige oma juurutuse tegelikku arhitektuuri. n8n-i praegune täieliku varunduse juhend kirjeldab SQLite'i terviklikkuse nõuet.

SQLite'i vaikekausta taastamine puhtal sihtserveril: esmalt peatage n8n ja kõik andmebaasi kirjutavad protsessid. Kui ühilduv n8n-i teenusekonteiner ja sihtandmeköide on olemas, kopeerige varundatud .n8n sisu tagasi samasse püsikataloogi. See kirjutab sihtfailid üle, seega ärge tehke seda eksemplaris, mille andmeid peate säilitama:

# Run only on the intended CLEAN recovery instance
docker compose stop n8n
docker compose cp ./n8n-user-folder-backup/. n8n:/home/node/.n8n/
# Verify ownership and permissions for the n8n container user BEFORE the next command
# Start only after restored files are readable/writable by n8n
docker compose start n8n
# Check logs, restored credentials and workflow triggers

Docker suudab kopeerida faile ka peatatud konteinerisse, kuid sihtfailide omanik võib algsest erineda; enne käivitamist veenduge, et n8n-i protsess saaks taastatud konfiguratsiooni ja andmebaasifaili lugeda ning kirjutada. Kui teie Compose'i konfiguratsioon kasutab teist teed või ühendatud hostikataloogi, kohandage kopeerimist. Docker Compose'i kopeerimisjuhend. Ainult n8n-i kausta taastamisest ei piisa, kui juurutus kasutab eraldi PostgreSQL-i andmebaasi.

KRIITILINE SALADUS

Krüptimisvõti on taastamise osa

n8n krüptib salvestatud juurdepääsuandmed eksemplari krüptimisvõtmega. Andmebaasi või krüptitud juurdepääsuandmete eksport ilma õige võtmeta võib jätta taastatud töövood ilma toimivate salvestatud juurdepääsuandmeteta.

Kui seadistasite N8N_ENCRYPTION_KEY, taastage täpselt sama salajane väärtus. Muidu asub genereeritud võti püsivas failis .n8n/config: säilitage see varundamisel või süsteemi uuesti ehitamisel. Hoidke taastamisvõtmeid turvaliselt väljaspool VPS-i. Järjekorrarežiimis peavad kõik põhi- ja täitmisprotsessid kasutama sama võtit.

FAILID JA BINAARANDMED

Andmebaasi varukoopia ei pruugi sisaldada kõiki töövoo sõltuvusi

Püsivad .n8n andmed

Leidke ja säilitage tegelik .n8n kasutajakaust, mitte ainult konteineritõmmis. Tüüpilises Dockeri juurutuses on see ühendatud teele /home/node/.n8n; ilma Dockerita on vaikimisi tee ~/.n8n. Kui N8N_USER_FOLDER on seadistatud, loob n8n .n8n kausta määratud ülemkataloogi sisse. Kaasake konfiguratsioonivõti ning kõik kohalikud SQLite'i, binaar- või failisüsteemi täitmisandmed, mida teie paigaldus kasutab.

Töövoogude ühendatud failid

Kui töövood loevad või kirjutavad hostist ühendatud katalooge, varundage need kataloogid eraldi. Ilma nendeta võib taastatud n8n-i korral osa muidu korrektseid töövooge lakata töötamast.

Binaarandmed

Tehke kindlaks salvestusrežiim ja taastage kõik välised sõltuvused. Failisüsteemi binaar- või täitmisandmed võivad asuda .n8n kaustas või kohandatud kataloogis; S3/Azure Blob või muu väline salvestus nõuab eraldi taastatavat koopiat ja ligipääsuseadeid. Andmebaasi varukoopia ei asenda neid faile.

Kogukonna sõlmed

Märkige üles kogukonnapakettide versioonid ja varundage täiendavad kohandatud sõlmekataloogid, mis on määratud muutujaga N8N_CUSTOM_EXTENSIONS. Need võivad asuda väljaspool .n8n kausta; pelgalt andmebaasi ja kasutajakausta taastamine ei pruugi kohandatud sõlmedega töövooge tööle saada.

SERVERIVÄLINE STRATEEGIA

Samas VPS-is olev varukoopia on ainult kohalik koopia

Kohalik koopiaSobib kiireks tagasipöördumiseks, kuid võib serveri kadumise, kettarikke või pöördumatu vea korral hävida.
Serveriväline koopiaHoidke vähemalt üks varukoopia tootmiskeskkonna VPS-ist sõltumatus salvestuskohas.
Versioonitud varukoopiadHoidke mitut taastamispunkti, et andmete rikkumine või halb muudatus ei kirjutaks ainsat kasutatavat koopiat üle.
LigipääsupiirangudVarukoopiad võivad sisaldada juurdepääsuandmeid, töövoogude loogikat ja tundlikke äriandmeid. Krüptige need ning piirake ligipääsu.
SeireAndke märku, kui ajastatud varundamine ebaõnnestub või ei loo enam uusi taastamispunkte.

Muutke varundusgraafik mõõdetavaks. Salvestage iga eduka varunduse ajatempel, ülekande lõppemine, faili suurus, lähteandmebaasi versioon, krüptimisvõtme taastamise asukoht ja viimase õnnestunud taastamistesti aeg. Teavitage puuduvatest, nurjunud või ootamatult tühjadest failidest. Krüptige varukoopiate arhiivid enne VPS-ist välja saatmist ja piirake ligipääsu taastamise saladustele. Mitu kuupäevaga taastamispunkti kaitsevad olukorra eest, kus rikutud uusim koopia on viimase töökorras koopia juba üle kirjutanud.

Näiteks kui suudate taluda kõige rohkem kuue tunni muudatuste kadumist, on iga kuue tunni järel toimuv edukas varundamine alguspunkt, mitte garantii: ebaõnnestunud tööd ja viibiv serveriväline kopeerimine võivad tegelikku andmekadu suurendada. Valige säilitusaeg ja taastamisharjutuste sagedus oma RPO/RTO ning andmenõuete järgi, mitte universaalse 7 või 30 päeva reegli põhjal.

TAASTAMISE JÄRJEKORD

Taastage süsteem kontrollitud järjestuses

1 · Valmistage etteLooge ühilduv server, andmebaas ja konteinerite või käituskeskkonna seadistus.
2 · Taastage saladusedSeadistage algne n8n-i krüptimisvõti ja vajalikud juurutussaladused turvaliselt.
3 · Taastage andmebaasTaastage PostgreSQL või SQLite ning kontrollige, et n8n ühendub õige andmestikuga.
4 · Taastage failidTaastage püsikataloogid, binaarandmed ja töövoogude ühendatud failid.
5 · Käivitage n8nKäivitage rakendus õige hostinime, andmebaasi ja keskkonnaseadetega.
6 · KontrolligeVeenduge, et kasutajad, töövood ja juurdepääsuandmed laaditakse, seejärel käivitage tüüpilised töövood ja veebikonksud.

PostgreSQL-i tõrketaaste näide: kasutage eraldi puhast taastamiskeskkonda , kus on juba õigete õigustega andmebaasiroll ja tühi n8n andmebaas, ning käivitage ainult PostgreSQL. Enne importimist oodake, kuni see on töökorras: docker compose up -d võib lõpetada ajal, kui PostgreSQL veel käivitub, mistõttu järgnev pg_restore võib ebaõnnestuda. Näites kasutatakse --wait tänapäevases Compose'i paigalduses ja kontrollitakse eraldi pg_isready. Usaldusväärseks ootamiseks seadistage sobiv PostgreSQL-i tervisekontroll või kinnitage valmisolek enne jätkamist. Ärge käivitage seda käsku juba andmeid sisaldavas tootmisandmebaasis ega käivitage n8n-i enne andmebaasi ning sellega sobiva .n8n võtme ja andmete taastamist.

# RESTORE ONLY TO A FRESH, EMPTY TARGET DATABASE
# Adapt Postgres Compose service, database and user names
docker compose up -d --wait postgres
docker compose exec -T postgres pg_isready -U n8n -d n8n
docker compose exec -T postgres pg_restore --exit-on-error --no-owner --no-acl -U n8n -d n8n < n8n-postgres.dump

Sihtkeskkonnas peab olema ühilduv PostgreSQL-i versioon, rolliõigused, laiendused ja algne n8n-i konfiguratsioon. Taastage .n8n õigesse püsiköitesse või ühendatud kataloogi oma varundusmeetodiga, säilitades omaniku ja õigused. Taastage välised binaarfailid, kohandatud laiendused, Compose'i ja saladuste konfiguratsioon, seejärel käivitage n8n ühilduva versiooniga ning kontrollige logisid. Andmebaasi taastamine üksi ei taasta võtit: PostgreSQL-i juurutus hoiab võtit failis .n8n/config , kui te pole selgesõnaliselt seadistanud muutujat N8N_ENCRYPTION_KEY. pg_restore'i juhend · n8n-i täieliku taastamise järjekord.

CLI VARUKOOPIATE PIIRANGUD

Mida töövoogude ja juurdepääsuandmete eksport ei taasta?

CLI-eksport ei ole kogu eksemplari varukoopia

Töövoogude ja juurdepääsuandmete eksport ei sisalda kasutajaid ega rolle, täitmisajalugu ega logisid, muutujaid või eksemplari seadeid, näiteks krüptimisvõtit.

Uue eksemplari taastamiseks on vaja omanikku

Puhtas eksemplaris lõpetage omaniku esmane seadistamine enne juurdepääsuandmete importimist. Mitme kasutaja või projekti taastamisel võib vaja minna ka õigeid kasutaja- või projektiseoseid.

Imporditud ID-d võivad olemasolevad kirjed üle kirjutada

Töövoogude ja juurdepääsuandmete eksport säilitab algsed ID-d. Kui impordite andmed eksemplari, kus on juba samad ID-d, võidakse olemasolevad kirjed asendada.

Avaldage imporditud töövood teadlikult

CLI-import jätab töövood tavaliselt passiivseks. n8n 2.x puhul kontrollige iga imporditud töövoo avaldatud olekut ja avaldage vaid need, mida soovite käivitada; ise majutatava Server CLI toetab ka käsku n8n publish:workflow --id=YOUR_WORKFLOW_ID. Kui n8n töötab, jõustuvad Server CLI avaldamis- või avaldamise tühistamise muudatused alles pärast n8n-i taaskäivitamist. Enne ajastatud käivituste ja tootmisveebikonksude kontrollimist või liikluse ümberlülitamist tehke taaskäivitus.

Hulgiekspordi näide Docker Compose'i jaoks: kui n8n-i teenuse nimi on n8n, võite kasutada allolevaid ametlikke CLI varunduskäske. Väljunditee on tahtlikult paigutatud ühendatud püsivasse .n8n kataloogi, sest suvalised kataloogid konteineris võivad selle uuesti loomisel kaduda. Veenduge, et n8n-i konteineri kasutajal on kataloogi kirjutamisõigus. Hoidke töövoogude ja juurdepääsuandmete JSON-failid eraldi kataloogides— n8n dokumenteerib impordiprobleemi, kui mõlemad failitüübid asuvad samas kataloogis.

n8n 2.x mustandite ja avaldatud töövoogude varundamine: tavaline --backup töövoo eksport salvestab praegused mustandid, mis võivad erineda tootmiskeskkonnas avaldatud versioonidest. Konkreetse töövoo tegeliku avaldatud versiooni säilitamiseks eksportige see eraldi, kasutades käsku docker compose exec -T n8n n8n export:workflow --id=WORKFLOW_ID --published --output=/home/node/.n8n/backups/published-workflow.json, olles eelnevalt loonud kirjutatava väljundkausta. CLI saab ajaloolise versiooni eksportida ka käsuga --version=VERSION_ID. Hoidke need koopiad koos täieliku varukoopiaga väljaspool serverit; ärge eeldage, et mustandi JSON kajastab avaldatud töövoogu.

# Execute from your Docker Compose project; the n8n service must exist
# Keep workflow and credential backups in DIFFERENT folders
docker compose exec -T n8n n8n export:workflow --backup --output=/home/node/.n8n/backups/workflows/
docker compose exec -T n8n n8n export:credentials --backup --output=/home/node/.n8n/backups/credentials/
# Copy the saved export directories OUT of the container to the host
mkdir -p ~/n8n-recovery
docker compose cp n8n:/home/node/.n8n/backups ~/n8n-recovery/cli

Kopeeritud ~/n8n-recovery/cli kataloog asub endiselt VPS-is, kuni teisaldate selle kaitstud sõltumatusse varukoopia asukohta. Juurdepääsuandmete eksport on vaikimisi krüptitud ja importimiseks vajab sama krüptimisvõtit. Ärge kasutage võimalust --decrypted välja arvatud rangelt kontrollitud migratsioonil: see kirjutab saladused lihttekstina. Ärge kunagi lisage tundlikke töövooge või juurdepääsuandmeid sisaldavaid ekspordifaile avalikku GitHubi repositooriumi. Mõned kolmandate osapoolte GitHubi varundusmallid ekspordivadki dekrüptitud saladusi; privaatne repositoorium piirab juurdepääsu, kuid ei krüpti andmeid. Kontrollige mallide ekspordiseadeid ja salvestusõigusi, krüptige saladused enne serverivälist edastamist ning vahetage tahtmatult avalikustatud juurdepääsuandmed välja.

Hulgiimpordi näide: puhtas sihtkeskkonnas lõpetage omaniku seadistamine, lisage algne krüptimisvõti ja tagage varukoopiafailide kättesaadavus taastamis-VPS-is. Järgmine näide loob sihtkataloogi ning kopeerib hostist n8n-i konteinerisse alamkaustad workflows/ ja credentials/ ; kohandage teid, kui Dockeri andmeköidete paigutus erineb:

# Run only on the intended CLEAN recovery instance
docker compose exec -T n8n mkdir -p /home/node/.n8n/backups
docker compose cp ~/n8n-recovery/cli/. n8n:/home/node/.n8n/backups/

Kontrollige n8n-i konteineri kasutaja failide omandi- ja ligipääsuõigusi. Ärge importige täidetud tootmiseksemplari ilma kontrollitud tagasipöördumisvõimaluseta: töövoogude ja juurdepääsuandmete ID-d võivad olemasolevad kirjed üle kirjutada. Seejärel käivitage:

# After fresh-instance owner setup AND providing the correct key
# Copy saved cli/ contents back under the target n8n service's .n8n/backups/
docker compose exec -T n8n n8n import:workflow --separate --input=/home/node/.n8n/backups/workflows/
docker compose exec -T n8n n8n import:credentials --separate --input=/home/node/.n8n/backups/credentials/

Imporditud ID-d võivad asendada olemasolevaid töövooge või juurdepääsuandmeid; katsetage esmalt eraldi eksemplaris ning kontrollige pärast importimist juurdepääsuandmeid ja aktiveerimise või avaldamise olekut. n8n 2.x puhul ei tõesta mustandi JSON-i taastamine iseenesest, et töövoog on avaldatud ja ajastatud käivitajad töötavad. Impordi ohutus: ilma multi-main-režiimita n8n-i eksemplaris võivad varem aktiivsed ajastatud käivitajad pärast CLI-importi jätkata töötamist, kuni eksemplar taaskäivitatakse. Peatage või isoleerige tootmiskeskkonna käivitajad ja taaskäivitage n8n enne taastatud tööde lubamist; veenduge, et topelttäitmisi pole. CLI-eksport ei sisalda algseid kasutajaid, täitmisloge, eksemplari muutujaid ega krüptimisvõtit. --backup määrab --all --pretty --separate, mitte kogu eksemplari. Allikad: n8n-i praegune ametlik varundamise ja taastamise juhend ning n8n-i CLI käsujuhend.

Hulgitaastamine GitHubi või Google Drive'i mallide abil: see on alternatiiv ainult töövoogude JSON-i jaoks, mitte eksemplari andmebaasi, kasutajate, krüptitud juurdepääsuandmete väärtuste ega krüptimisvõtme jaoks. Enne API-põhise malli kasutamist kontrollige selle n8n-i API ja salvestusõigusi, valitud varukoopia versiooni ja sihteksemplari, kas see uuendab kattuvaid ID-sid ja loob kustutatud töövood uuesti ning kuidas käsitleb avaldamist. Kõik mallid ei taasta sihtkohas puuduvaid ID-sid; katsetage seda eraldi, enne kui toetute automaatsele taastamisele.

KKK

n8n-i varundamine ja taastamine: korduma kippuvad küsimused

Kas töövoogude eksportimisest piisab n8n-i varundamiseks?

Ei. Töövooeksport on kasulik loogiline koopia, kuid täielik taastamine võib vajada ka juurdepääsuandmeid, nendega sobivat krüptimisvõtit, andmebaasi olekut, püsifaile ja binaarandmete salvestust.

Kas vajan n8n-i krüptimisvõtit, kui mul on andmebaas?

Jah, kui soovite selles andmebaasis olevate krüptitud juurdepääsuandmete kasutatavust säilitada. Hoidke algne võti turvaliselt alles.

Kas varundada PostgreSQL või eksportida töövood ja juurdepääsuandmed?

Tõrketaaste jaoks kaitske andmebaasi ja krüptimisvõtit. Loogilised ekspordid on kasulikud lisaks migratsiooniks ja valikuliseks taastamiseks, mitte kogu eksemplari asenduseks.

Kas VPS-i hetktõmmis võib olla ainus varukoopia?

Parem on käsitleda seda ühe taastamiskihina. Hoidke sõltumatut serverivälist varukoopiat, et teenusepakkuja, konto, serveri või hetktõmmise rike ei hävitaks korraga kõiki taastamispunkte.

Kuidas teada, et varukoopia töötab?

Taastage see puhtasse testkeskkonda, veenduge juurdepääsuandmete dekrüptimises ja käivitage tüüpilised töövood. Ainuüksi edukas varundustöö ei tõenda taastatavust.

Kas GitHubi või Google Drive'i töövoogude varukoopiad sisaldavad salvestatud salasõnu?

Ainult töövoo JSON-i varukoopiad ei sisalda n8n-i juurdepääsuandmete hoidlas hallatavaid salajasi väärtusi ega eksemplari krüptimisvõtit. Siiski võib eksporditud JSON paljastada juurdepääsuandmete nimed ja ID-d ning sõlme parameetritesse otse sisestatud saladused, näiteks autentimise päised. Enne eksportfailide üleslaadimist või jagamist vaadake need üle ja kaitske neid. Täielikuks taastamiseks varundage andmebaas ja algne võti või kasutage toetatud krüptitud CLI-eksporti koos kontrollitud taastamisega. Ainult töövoogude GitHubi või Google Drive'i mall pole täielik tõrketaaste.

TAASTAMISE EESMÄRGID

Määrake enne tõrget RPO ja RTO

RPO tähendab suurimat lubatud hiljutiste muudatuste kadu. Mõõtke seda uusimast kasutatavast, eraldi salvestatud taastamispunktist; iga kuue tunni tagant ajastatud töö ei tõesta kuue tunni RPO-d, kui varundamine või edastamine ebaõnnestus. RTO tähendab suurimat lubatud seisakut. Mõõtke seda puhta taastamise käigus, arvestades saladuste kättesaamist, väliste failide taastamist, juurdepääsuandmete kontrolli ja taastatud töövoogude avaldamist, mitte ainult konteineri käivitamist.

TAASTAMISVÕTI

Leidke algne krüptimisvõti enne süsteemi uuesti ehitamist

Kui tootmiskeskkonnas seadistati N8N_ENCRYPTION_KEY, säilitage täpselt see keskkonna salajane väärtus. Kui seda ei seadistatud, säilitage algne genereeritud võti püsivas .n8n/config failis. Enne krüptitud juurdepääsuandmete importi kontrollige, millist võtit taastatud eksemplar tegelikult kasutab; uus genereeritud võti ei saa vana andmebaasi juurdepääsuandmeid dekrüptida.
