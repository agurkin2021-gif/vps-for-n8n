n8n-i paigaldamine VPS-i

Paigaldage n8n VPS-i Docker Compose'i ja PostgreSQL-i abil. Tootmiskeskkonnas on lisaks vaja rakenduse ja andmebaasi andmete püsivat salvestamist, püsivat N8N_ENCRYPTION_KEY, avalikku hostinime, HTTPS-i ja korrektset veebikonksude seadistust. Kontrollige neid osi enne tootmistöövoogude käivitamist.

Valmistage VPS enne n8n-i käivitamist ette

Linuxi VPS

Docker Compose

Paigaldage Docker Engine ja Compose'i pistikprogramm operatsioonisüsteemile toetatud pakettidest.

Tulemüür

Avage ainult vajalikud haldus- ja veebipordid. Hoidke PostgreSQL ja rakenduse siseteenused privaatsena.

Kas paigaldate n8n-i VPS-i, kus juba töötavad veebilehed? Võite lisada n8n-i oma serverisse, kui CPU, RAM ja salvestusruum seda võimaldavad. Kui aga Nginx, Apache, Caddy või muu pöördpuhverserver kasutab juba porte 80/443, ärge käivitage alltoodud Caddy konteinerit muutmata kujul: pordid lähevad konflikti. Suunake uus n8n-i alamdomeen olemasoleva pöördpuhverserveri kaudu sobiva privaatvõrguga või kasutage täpselt selle Compose'i näite jaoks puhast VPS-i. Säilitage teiste veebilehtede ja nende TLS-i konfiguratsioon; näide eeldab, et pordid 80/443 on vabad.

KOPEERIGE JA KOHANDAGE

Paigaldage n8n oma VPS-i Docker Compose'iga

Selle näite abil saate n8n-i juurutada ise hallatavasse Linuxi VPS-i. n8n-i paigaldamine ja hooldamine on teie vastutusel; meie partnerilt serveri valimine ei tähenda, et n8n oleks eelpaigaldatud. Näide ühendab privaatses Compose'i võrgus n8n-i, PostgreSQL-i, välise ülesandetäituri ja Caddy HTTPS-i. Tegemist on konfiguratsioonimalliga, mitte väitega, et juurutust on tegelikus kasutuses katsetatud.

Kas soovite alustada veel kiiremini? n8n pakub ka ametlikku ühe käsuga Dockeri paigaldust. Saate selle skripti alla laadida ja üle vaadata käsuga curl -fsSL https://get.n8n.io -o get-n8n.sh enne järgmise käsu käivitamist: sh get-n8n.sh. See võimalus käivitab algse eksemplari SQLite'iga kohalikul aadressil ja sisaldab n8n Assistanti isoleeritud testkeskkonna teenuseid; see ei ole sama mis siin kirjeldatud avaliku HTTPS-i ja PostgreSQL-iga VPS-i juurutus. Ametlik täielik testkeskkond vajab lihtsast n8n-i paigaldusest rohkem RAM-i ja CPU-d (Compose'i juhendis on märgitud vähemalt 4 GB RAM-i / 2 vCPU-d). Internetist ligipääsetava tootmis-VPS-i jaoks jätkake allpool käsitsi seadistatava lahendusega.

1. Valmistage ette Docker, DNS ja ligipääs

Looge sudo-õigustega SSH-ühendus ja suunake DNS-i A-kirje nimele n8n.example.com oma VPS-i IPv4-aadressile. Värskes Ubuntu 22.04, 24.04 või 26.04 paigalduses installivad järgmised käsud Docker Engine'i ja tänapäevase docker compose pistikprogrammi Dockeri ametlikust allkirjastatud apt paketihoidlast:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

See on Dockeri ametlikus Ubuntu juhendis kirjeldatud tootmiskeskkonna paigaldusmeetod. Ärge paigaldage Dockerit pimesi uuesti ega eemaldage seda VPS-ist, kus juba töötavad konteinerid või veebilehed; kontrollige esmalt olemasolevat paigaldust ja võimalikke paketikonflikte. Debiani või muu distributsiooni puhul kasutage Ubuntu käskude asemel selle operatsioonisüsteemi ametlikke juhiseid.

Seejärel kontrollige Dockerit, Compose'i pistikprogrammi, DNS-i ja töökataloogi:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Kui getent hosts ei tagasta aadressi või tagastab vale aadressi, parandage enne Caddy käivitamist DNS; asendage n8n.example.com kogu juhendis oma tegeliku hostinimega. Docker nõuab tavaliselt root-õigusi. Kui SSH-kasutaja ei saa järgmisi docker compose käske otse täita, lisage neile ette sudo. Kasutaja lisamine docker gruppi annab root-taseme ligipääsu ja seda ei tohi jagatud serveris kergekäeliselt teha.

Enne tulemüüri lubamist veenduge, et tegelik SSH-haldusport jääb kättesaadavaks. Lubage sertifikaatide väljastamiseks ja redaktori kasutamiseks sisenevad HTTP (80) ning HTTPS (443) ühendused. Dockeri avaldatud konteineripordid võivad mõnest UFW reeglist mööda minna; seega lugege Dockeri tulemüürijuhendit ja avaldage ainult vajalikud Caddy pordid. See Compose'i näide teadlikult ei avalda PostgreSQL-i (5432), n8n-i (5678) ega ülesandetäituri sõnumivahendaja (5679) porte avalikku internetti.

2. Looge keskkonnaväärtused ja säilitage võti

Genereerige projektikataloogis kolm erinevat juhuslikku kuueteistkümnendväärtust käsuga:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Looge fail .env alloleva malli järgi, asendage iga REPLACE_WITH_RANDOM_HEX eri genereeritud väärtusega ning muutke hostinime ja ajavööndit. Näites kasutatud 2.42.5 versioonitähis on 8. oktoobril 2026 avaldatud stabiilne versioon; seda kasutatakse kuupäevaga konfiguratsiooninäitena, mitte tõendina juurutuse tegeliku testimise ega tulevase turvalisuse kohta. Enne paigaldamist kontrollige n8n-i ametlikke värskeimaid väljalaskeid ning hoidke n8n-i ja selle ülesandetäituri tõmmise versioonid samad.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Ärge kunagi lisage .env avalikku repositooriumi. Säilitage krüptimisvõti ja taastamisjuhised turvaliselt väljaspool VPS-i. Võti peab jääma samaks ka pärast konteinerite uuesti loomist või migratsiooni.

3. Koostage uue paigalduse jaoks compose.yaml

Looge samas kataloogis compose.yaml. Näites kasutatakse n8n-i ametlikke keskkonnamuutujaid ja PostgreSQL 18 andmete asukohta PGDATA , mis on kirjeldatud n8n-i majutusprojekti juhendis:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Neljal teenusel on eri ülesanded: PostgreSQL salvestab andmebaasi oleku, n8n käitab töövooge, n8n-runner täidab ülesandeid sama versiooni ja jagatud autentimistokeniga, Caddy aga pakub avalikku HTTPS-i. Väline ülesandetäitur ei ole Redise järjekorrarežiim. Ainult Caddy avaldab hosti pordid. Lihtsustatud näites kasutatakse seadistamiseks üht andmebaasirolli; PostgreSQL-i õiguste paremaks eraldamiseks vaadake n8n-i ametlikku PostgreSQL-iga juurutusnäidet.

4. Looge HTTPS-i Caddyfile

Looge fail Caddyfile (suure C-tähega ja ilma laiendita) faili compose.yamlkõrvale. Asendage näidishostinimi kõikjal oma DNS-nimega:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy taotleb ja uuendab avalikke TLS-sertifikaate, kui domeeni DNS-lahendus on õige ning välisliiklus jõuab portideni 80/443. Ärge suunake DNS-i aadressile localhost. Kui asendate Caddy muu pöördpuhverserveriga, edastage algne hosti-, protokolli- ja kliendiaadressi päis ning kohandage N8N_PROXY_HOPS tegeliku usaldatud puhverserveriahela pikkusega.

5. Käivitage konteinerid ja katsetage väljastpoolt

Pärast failide .env, compose.yaml ja Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

salvestamist käivitage projektikataloogis alltoodud käsud. Viimane neist kontrollib avalikku HTTPS-i tervisekontrolli aadressi. Kui sertifikaadi väljastamine veel kestab, kontrollige enne n8n-i rikkis oleku järeldamist Caddy logisid, DNS-i ja porte. Avage https://n8n.example.com, looge kohe esimene omaniku konto ja lubage asjakohane sisselogimise kaitse. Veenduge, et eksemplar päriselt täidab töövoogu, mitte ainult ei ava redaktorit:

  1. Looge redaktoris töövoog, millel on Webhook käivitaja. Seadke väljal HTTP Method väärtuseks GET, valige Path vps-checkja määrake Respond väärtuseks Immediately. Salvestage töövoog.
  2. Klõpsake nuppu Listen for Test Event, kopeerige täielik Test URL , mida n8n näitab, ja käivitage teisest seadmest curl -i 'PASTE_TEST_URL_HERE' kopeeritud URL-iga. Oodake edukat HTTP-vastust ja veenduge, et saabuv sündmus ilmub n8n-i redaktoris. Test-URL-id töötavad ainult ajal, mil n8n kuulab vastavat sündmust.
  3. Avaldage töövoog, lülitage sõlm ümber Production URLaadressile, kopeerige see ja käivitage curl -i 'PASTE_PRODUCTION_URL_HERE' uuesti. Kontrollige täitmist töövoo vahekaardil Executions . Tootmiskeskkonna veebikonksupäringud eeldavad avaldatud töövoogu ning nende sisu ei ilmu redaktori testvaatesse.

See on teadlikult lihtne, autentimata toimivustest: ärge kunagi saatke sellesse saladusi. Pärast katsetamist tühistage avaldamine või kustutage töövoog või seadistage enne pärisandmete kasutamist Webhooki autentimine ja IP-piirangud. Vaadake ametlikku Webhooki testi- ja tootmisrežiimi dokumentatsiooni.

6. Tehke enne versioonide muutmist varukoopia

Säilitage taastatav PostgreSQL-i andmebaasi tõmmis ja n8n-i püsiv andmeköide, .env/krüptimisvõti ning vajalikud välised failid serverist eraldi salvestuskohas. Kontrollige taastamist varundamise ja taastamise juhendi järgi enne tootmiskeskkonna uuendamist. Näidiskäsud:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Muutke fikseeritud N8N_VERSION versiooni alles pärast väljalaskemärkmete lugemist; n8n-i ja täituri tõmmiseid tuleb uuendada üheskoos. Ärge käivitage docker compose down -v tavalise hoolduse käigus, sest see kustutab nimega andmeköited. PostgreSQL-i põhiversiooni muutmiseks on vaja andmebaasi uuendamise või varundamise ja taastamise plaani; Postgres 18 tõmmise vahetamine muu põhiversiooni vastu ei tee automaatselt migratsiooni.

Peamised allikad: n8n-i Docker Compose'i juhend, pöördpuhverserveri ja veebikonksude seadistamine ning ametlik PostgreSQL-i juurutusdokumentatsioon. Siin ei eeldata taristu jõudlusteste ega teenusepakkuja eelpaigaldatud funktsioone.

n8n-i paigaldamine Dockeriga: korduma kippuvad küsimused

Kas n8n-i käitamiseks Dockeris on vaja PostgreSQL-i?

Docker ei nõua PostgreSQL-i ning väikesed juurutused võivad kasutada SQLite'i. Tootmiskeskkonna VPS-is annab PostgreSQL tugevama andmebaasipõhja ja toetab hilisemat järjekorrarežiimi skaleerimist.

Miks säilitada n8n-i püsiandmeköide, kui andmed on PostgreSQL-is?

n8n-i püsikataloog võib sisaldada olulist eksemplari olekut ja konfiguratsiooni. Säilitage see oma juurutusarhitektuuri järgi ega eeldage, et andmebaas on ainus taastamiseks vajalik vara.

Miks näitab veebikonks localhost'i?

Sisemine konteineriaadress erineb avalikust aadressist. Seadistage väline hostinimi, protokoll ja veebikonksu URL ning tagage, et pöördpuhverserver edastab vajalikud päised.

Kas port 5678 peab olema avalik?

Tavapärases pöördpuhverserveri taga töötavas tootmiskeskkonnas avage HTTPS puhverserveris ja hoidke n8n-i rakenduse port sisemisena, kui puudub konkreetne põhjus teisiti toimida.

Kas vajan Redist?

Tavalise ühe eksemplariga Dockeri juurutuse jaoks mitte. Redis muutub oluliseks siis, kui lähete teadlikult üle järjekorrarežiimile ja täitmisprotsessidele.

Kas n8n-i välised ülesandetäiturid on sama mis järjekorrarežiimi tööprotsessid?

Ei. Välised ülesandetäiturid käitavad toetatud ülesandekoodi n8n-i põhiprotsessist eraldi ja kasutavad ühist autentimistokenit. Redise järjekorrarežiim jaotab töövoogude täitmisi ning vajab eraldi taristut. Selles näites on väline ülesandetäitur, mitte Redise järjekorrarežiim. Täituri tõmmise versioon peab vastama n8n-i versioonile.
