INSTALLATIE KOPIËREN EN AANPASSEN

Installeer n8n op uw VPS met Docker Compose

Gebruik dit voorbeeld om een n8n-implementatie te bouwen op een zelfbeheerd Linux VPS. Je installeert en onderhoudt n8n zelf; het kiezen van een server via onze partner omvat geen vooraf geïnstalleerde n8n-instantie. In het voorbeeld worden n8n, PostgreSQL, een externe taskrunner en Caddy HTTPS gecombineerd in een particulier Compose-netwerk. Het is een configuratiesjabloon, geen claim van een live geteste implementatie.

Wilt u in plaats daarvan de snelste nieuwe installatie? n8n biedt ook een officiële éénregelige Docker-opstelling. U kunt het script downloaden en bekijken met curl -fsSL https://get.n8n.io -o get-n8n.sh voordat u gaat rennen sh get-n8n.sh. Die optie start een eerste exemplaar met SQLite op een lokale URL en omvat n8n Assistant-sandboxservices; het is niet hetzelfde zoals deze door het publiek HTTPS, PostgreSQL gesteunde VPS-implementatie. De officiële volledige sandbox-stack heeft meer RAM en CPU nodig dan een gestroomlijnde n8n-installatie (de Compose-gids specificeert ten minste 4 GB RAM / 2 vCPU's). Voor een internetgerichte productie VPS gaat u verder met de handmatig geconfigureerde stapel hieronder.

1. Docker, DNS voorbereiden en openen

Maak verbinding via SSH met sudo-toegang en wijs een DNS A-record aan n8n.example.com naar uw VPS IPv4-adres. Op een vers Ubuntu 22.04, 24.04 of 26.04 VPS, de volgende opdrachten installeren Docker Engine en de moderne docker compose plug-in van Docker's officiële ondertekende apt opslagplaats:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Dit is de productiegerichte repositorymethode in de officiële Docker Ubuntu installatiehandleiding. Installeer of verwijder Docker niet blindelings op een VPS waarop al containers of andere websites draaien; inspecteer eerst de bestaande installatie en mogelijke pakketconflicten. Gebruik voor Debian of een andere distributie de overeenkomstige officiële OS-specifieke instructies in plaats van Ubuntu-opdrachten.

Controleer nu Docker zelf, de Compose-plug-in, DNS en de werkmap:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Als getent hosts retourneert geen adres of het verkeerde adres, corrigeer uw DNS voordat u met Caddy begint; vervangen n8n.example.com in deze handleiding met uw echte hostnaam. Voor Docker zijn normaal gesproken root-rechten vereist: als uw SSH-gebruiker de laatste niet kan uitvoeren docker compose commando's rechtstreeks, laat ze voorafgaan door sudo. Een gebruiker toevoegen aan de docker group verleent root-equivalente toegang en mag niet terloops op een gedeelde server worden gedaan.

Houd uw feitelijke SSH-beheerpoort bereikbaar voordat u een firewall inschakelt. Sta inkomende HTTP (80) en HTTPS (443) toe voor certificaatuitgifte en de editor. In Docker gepubliceerde containerpoorten kunnen sommige UFW-regels omzeilen, dus bekijk de firewallrichtlijnen van Docker en publiceer alleen de beoogde Caddy-poorten. Dit Compose-voorbeeld doet dat bewust niet publiceer PostgreSQL (5432), n8n (5678) of task-runner broker (5679) op het openbare internet.

2. Creëer omgevingswaarden en behoud de sleutel

Genereer er drie vanuit de projectmap anders willekeurige hexadecimale waarden met:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Maak een bestand met de naam .env gebruik het onderstaande sjabloon en vervang elke REPLACE_WITH_RANDOM_HEX met een andere gegenereerde waarde en wijzig de hostnaam en tijdzone. De getoonde 2.42.5 label is de stabiele release vermeld op 8 oktober 2026, hier gebruikt als een gedateerd configuratievoorbeeld, geen garantie voor een live geteste implementatie of voor toekomstige veiligheid. Controleer vóór de installatie de huidige officiële n8n-releases en bewaar n8n en de taakrunner-image op dezelfde geverifieerde versie.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Nooit plegen .env naar een openbare opslagplaats. Bewaar de coderingssleutel en herstelinstructies veilig buiten de VPS. De sleutel moet hetzelfde blijven na recreatie of migratie van containers.

3. Schrijf compose.yaml voor een nieuwe installatie

Maak in dezelfde map een compose.yaml. In het voorbeeld worden de officiële n8n-conventies voor omgevingsvariabelen en de PostgreSQL 18 gebruikt PGDATA pad gedocumenteerd door het n8n hostingproject:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

De vier services hebben verschillende rollen: PostgreSQL slaat de databasestatus op, n8n voert workflows uit, n8n-runner voert runner-taken uit met een overeenkomende versie en gedeeld authenticatietoken, en Caddy handelt openbare HTTPS af. Een externe taak loper is geen Redis wachtrijmodus. Alleen Caddy publiceert hostpoorten. Deze slanke illustratie gebruikt één databaserol voor installatie; voor een sterkere scheiding van PostgreSQL-privileges raadpleegt u het officiële n8n PostgreSQL-implementatievoorbeeld.

4. Maak het HTTPS Caddybestand aan

Maak het bestand Caddyfile (hoofdletter C, geen extensie) ernaast compose.yaml. Vervang de voorbeeldhostnaam overal door uw eigen DNS-naam:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy vraagt openbare TLS-certificaten aan en vernieuwt deze wanneer het domein correct wordt opgelost en extern verkeer de poorten 80/443 kan bereiken. Wijs DNS niet aan localhost. Als u Caddy vervangt door een andere reverse proxy, stuurt u de oorspronkelijke host-, protocol- en clientadresheaders door en past u deze aan N8N_PROXY_HOPS voor het werkelijke aantal vertrouwde proxy-hops.

5. Start de containers en test van buitenaf

Voer deze opdrachten uit vanuit de projectmap nadat u deze hebt opgeslagen .env, compose.yaml en Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Het laatste commando controleert de openbaar HTTPS eindpunt voor de gezondheid. Als de certificaatuitgifte nog steeds in behandeling is, inspecteer dan de Caddy-logboeken en DNS/poorten voordat u concludeert dat n8n kapot is. Openen https://n8n.example.com, maak onmiddellijk het account van de eerste eigenaar en schakel de juiste inlogbeveiligingen in. Bevestig dat de instantie daadwerkelijk een workflow uitvoert, en niet alleen dat de editor laadt:

  1. Maak in de editor een workflow met a Webhook triggeren. Instellen HTTP Method naar GET, kies de Path vps-check, en instellen Reageer naar Onmiddellijk. Sla de werkstroom op.
  2. Klik Luister naar testgebeurtenis, kopieer het volledige Test-URL weergegeven door n8n, en vanaf een ander apparaat uitgevoerd curl -i 'PASTE_TEST_URL_HERE' met de gekopieerde URL. Verwacht een succesreactie van HTTP en de binnenkomende gebeurtenis verschijnt in de n8n-editor. Test-URL's werken alleen terwijl n8n naar de gebeurtenis luistert.
  3. Publiceren de workflow, schakel het knooppunt naar zijn Productie-URL, kopieer het en voer het uit curl -i 'PASTE_PRODUCTION_URL_HERE' opnieuw. Bevestig de uitvoering onder de workflow's Executies tabblad. Voor productiewebhookverzoeken moet de workflow worden gepubliceerd en wordt de payload niet weergegeven in de testweergave van de editor.

Dit is een opzettelijk eenvoudige, niet-geverifieerde rooktest: stuur er nooit geheimen naar. Maak de publicatie/verwijdering ongedaan na het testen, of configureer Webhook-verificatie/IP-beperkingen voordat u een openbaar eindpunt voor echte gegevens gebruikt. Zie de officiële Webhook-test-/productiedocumentatie.

6. Maak een back-up voordat u vastgezette versies wijzigt

Sla een herstelbare PostgreSQL-dump op en het aanhoudende n8n datavolume, .env/encryptiesleutel en vereiste externe bestanden naar opslag buiten deze server. Controleer een herstel met behulp van de back-up- en herstelgids voordat de productie wordt bijgewerkt. Voorbeeldopdrachten:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Wijzig de vastgezette N8N_VERSION alleen na het lezen van de release-opmerkingen; zowel n8n- als runner-afbeeldingen moeten samen vooruitgaan. Niet rennen docker compose down -v tijdens routineonderhoud, omdat daardoor benoemde datavolumes worden verwijderd. PostgreSQL wijzigingen in de grote versie vereisen een database-upgrade of een dump/herstelplan; het vervangen van de Postgres 18-afbeelding door een andere hoofdtag is geen automatische migratie.

Gezaghebbende referenties: n8n Docker Handleiding opstellen, n8n reverse-proxy/webhook-configuratie en officiële PostgreSQL implementatie-aantekeningen. Er wordt niet uitgegaan van een infrastructuurbenchmark of providerspecifieke vooraf geïnstalleerde functie.

Huidige officiële Docker Componeergids

Veelgestelde vragen

n8n installeren met Docker: veelgestelde vragen

Heeft n8n PostgreSQL nodig bij gebruik van Docker?

Voor Docker is PostgreSQL niet vereist, en kleine implementaties kunnen SQLite gebruiken. Voor een productiegerichte VPS-implementatie biedt PostgreSQL een sterkere databasebasis en ondersteunt latere schaling in de wachtrijmodus.

Waarom een aanhoudend n8n-volume behouden als PostgreSQL gegevens opslaat?

De persistente n8n-directory kan belangrijke instantiestatus en -configuratie bevatten. Bewaar deze volgens het implementatieontwerp in plaats van ervan uit te gaan dat de database het enige herstelmiddel is.

Waarom toont mijn webhook localhost?

Het interne containeradres verschilt van de openbare oorsprong. Configureer de externe hostnaam, het protocol en de webhook-URL en zorg ervoor dat de reverse proxy de vereiste headers doorgeeft.

Moet poort 5678 openbaar zijn?

Voor een normale productie-implementatie achter een omgekeerde proxy stelt u HTTPS bloot aan de proxy en houdt u de n8n-toepassingspoort intern, tenzij er een specifieke operationele reden is om dit niet te doen.

Heb ik Redis nodig?

Niet voor een standaard Docker-implementatie met één exemplaar. Redis wordt relevant wanneer u opzettelijk overschakelt naar wachtrijmodus en werknemers.

Zijn externe n8n taaklopers hetzelfde als wachtrijmoduswerkers?

Nee. Externe taaklopers voeren de ondersteunde taakcode afzonderlijk van het n8n-hoofdproces uit en gebruiken een gedeeld authenticatietoken. De wachtrijmodus Redis verdeelt de workflow-uitvoeringen en heeft zijn eigen infrastructuurvereisten. Dit voorbeeld toont een externe taakrunner, niet de wachtrijmodus Redis. Zorg ervoor dat de afbeeldingsversie van de hardloper overeenkomt met de n8n-versie.
