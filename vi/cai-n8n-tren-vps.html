Cài xong container chưa có nghĩa production-ready

1 · Linux + DockerDùng Linux được hỗ trợ, Docker Engine và Docker Compose plugin hiện hành.
2 · Persistent datan8n và PostgreSQL phải có persistent volumes; không expose PostgreSQL ra Internet.
3 · Encryption keyGiữ N8N_ENCRYPTION_KEY ổn định, lưu riêng khỏi repository/compose public.
4 · HTTPSReverse proxy/TLS, public hostname và WEBHOOK_URL phải khớp endpoint thật.
5 · VerifyKiểm tra docker compose ps, logs, health endpoint, editor và webhook từ bên ngoài.
6 · Update pathPin/kiểm soát version, backup trước update và có rollback; không blind-upgrade PostgreSQL major version.

Acceptance checks mà tutorial thường bỏ qua

Restart test

Reboot/container recreate xong workflows và credentials vẫn còn.

Webhook test

Gửi request từ ngoài VPS để xác nhận DNS/TLS/proxy/webhook path thực sự đúng.

Credential test

Sau restart vẫn decrypt được credentials bằng encryption key cũ.

Database privacy

PostgreSQL chỉ reachable nội bộ; port public bị đóng.

Backup test

Có recovery set trước lần update đầu tiên.

Rollback

Biết cách quay về image/config cũ khi release mới gây lỗi.

FAQ cài n8n trên VPS

Docker Compose có đủ không?

Đủ cho deployment phổ biến, nhưng production còn cần persistence, HTTPS, backup, verification và update policy.

Có nên mở port 5678 trực tiếp?

Nếu dùng reverse proxy HTTPS, public exposure nên đi qua proxy thay vì mở trực tiếp không cần thiết.

N8N_ENCRYPTION_KEY quan trọng thế nào?

Mất key có thể làm credentials đã lưu không dùng được khi migrate/restore.

Có thể dùng latest image không?

Production nên kiểm soát version và rollback thay vì cập nhật không kiểm soát.
