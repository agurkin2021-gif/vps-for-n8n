n8n را روی VPS نصب کنید

با استفاده از Docker Compose و PostgreSQL n8n را روی VPS نصب کنید. یک استقرار تولید همچنین به داده‌های کاربردی و پایگاه‌داده پایدار نیاز دارد N8N_ENCRYPTION_KEY، یک نام میزبان عمومی، HTTPS و پیکربندی صحیح وب‌هوک. قبل از فعال کردن گردش‌کار تولید، این قطعات را بررسی کنید.

قبل از صدور گواهینامه TLS و انتشار نشانی های وب‌هوک، یک دامنه یا زیر دامنه را در VPS قرار دهید.

Docker Engine و افزونه Compose را با استفاده از بسته های پشتیبانی شده برای سیستم عامل نصب کنید.

فایروال

فقط مدیریت مورد نیاز و پورت های وب را در معرض دید قرار دهید. PostgreSQL و خدمات برنامه داخلی را خصوصی نگه دارید.

نصب روی VPS که قبلاً وب سایت ها را میزبانی می‌کند؟ زمانی که CPU، RAM و فضای ذخیره‌سازی اجازه می‌دهد، می‌توانید n8n را به سروری که کنترل می کنید اضافه کنید. با این حال، اگر Nginx، Apache، Caddy یا یک Reverse Proxy دیگر از قبل دارای پورت های 80/443 هستند، این کار را انجام دهید. نه نمونه Caddy ظرف را بدون تغییر شروع کنید: پورت ها در تضاد خواهند بود. در عوض، یک زیردامنه n8n جدید را از طریق پراکسی معکوس موجود خود با شبکه خصوصی مناسب مسیریابی کنید، یا از یک VPS تمیز برای مثال Compose استفاده کنید. سایت های دیگر و پیکربندی TLS آن‌ها را حفظ کنید. مثال فرض می‌کند که پورت های 80/443 در دسترس هستند.

نصب را کپی و تطبیق دهید

n8n را با Docker Compose روی VPS نصب کنید

از این مثال برای ایجاد یک استقرار n8n بر روی a استفاده کنید مدیریت‌شده توسط خودتان Linux VPS. شما خودتان n8n را نصب و نگهداری می کنید. انتخاب سرور از طریق شریک ما شامل نمونه n8n از پیش نصب شده نیست. این مثال n8n، PostgreSQL، یک اجراکننده وظیفه خارجی و Caddy HTTPS را در یک شبکه Compose خصوصی ترکیب می‌کند. این یک قالب پیکربندی است، ادعای استقرار آزمایش شده زنده نیست.

در عوض سریعترین نصب تازه را می‌خواهید؟ n8n همچنین یک راه‌اندازی رسمی Docker یک خطی را فراهم می‌کند. می‌توانید اسکریپت آن را دانلود و بررسی کنید curl -fsSL https://get.n8n.io -o get-n8n.sh قبل از دویدن sh get-n8n.sh. آن گزینه یک نمونه اولیه را با SQLite در یک URL محلی راه‌اندازی می‌کند و شامل n8n خدمات جعبه ایمنی دستیار است. آن است یکسان نیست به عنوان این استقرار عمومی-HTTPS، PostgreSQL-پشتیبانی VPS. پشته کامل سندباکس رسمی به RAM و CPU بیشتر از نصب n8n ناب نیاز دارد (راهنمای Compose آن حداقل 4 GB RAM / 2 vCPU ها را مشخص می‌کند). برای تولید اینترنت VPS، با پشته پیکربندی دستی زیر ادامه دهید.

1. Docker، DNS را آماده کرده و دسترسی داشته باشید

با دسترسی sudo روی SSH وصل شوید و یک رکورد DNS را برای آن علامت بزنید n8n.example.com به آدرس VPS IPv4 شما. در یک تازه Ubuntu 22.04، 24.04 یا 26.04 VPS، دستورات زیر Docker Engine و مدرن را نصب می کنند docker compose افزونه از طرف رسمی Docker امضا شده است apt مخزن:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

این روش مخزن تولید محور در راهنمای نصب رسمی Docker Ubuntu است. کورکورانه Docker را در کانتینرهای VPS از قبل در حال اجرا یا سایر وب سایت ها نصب یا حذف نکنید; ابتدا نصب موجود و تضادهای بسته احتمالی را بررسی کنید. برای دبیان یا توزیع دیگری، به جای دستورات Ubuntu از دستورالعمل های رسمی مربوط به سیستم عامل استفاده کنید.

اکنون خود Docker، افزونه Compose، DNS و دایرکتوری کاری را تأیید کنید:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

اگر getent hosts هیچ آدرسی یا آدرس اشتباهی برمی‌گرداند، قبل از شروع Caddy DNS خود را تصحیح کنید. جایگزین کنید n8n.example.com در سراسر این راهنما با نام میزبان واقعی شما. Docker معمولاً به حقوق ریشه نیاز دارد: اگر کاربر SSH شما نتواند نسخه بعدی را اجرا کند docker compose دستورات را مستقیماً، آن‌ها را با پیشوند اضافه کنید sudo. اضافه کردن کاربر به docker گروه دسترسی معادل ریشه را اعطا می‌کند و نباید به‌طور معمولی روی یک سرور مشترک انجام شود.

قبل از فعال کردن فایروال، پورت مدیریت SSH واقعی خود را در دسترس نگه دارید. به HTTP (80) و HTTPS (443) برای صدور گواهی و ویرایشگر اجازه دهید. پورت‌های کانتینری منتشرشده در Docker می‌توانند برخی از قوانین UFW را دور بزنند، بنابراین راهنمای فایروال Docker را بررسی کنید و فقط پورت‌های Caddy مورد نظر را منتشر کنید. این مثال Compose عمدا انجام می‌دهد نه PostgreSQL (5432)، n8n (5678) یا کارگزار وظیفه (5679) را در اینترنت عمومی منتشر کنید.

2. ارزش های محیطی را ایجاد کنید و کلید را حفظ کنید

از دایرکتوری پروژه، سه تولید کنید متفاوت است مقادیر هگزادسیمال تصادفی با:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

یک فایل به نام ایجاد کنید .env با استفاده از الگوی زیر، هر کدام را جایگزین کنید REPLACE_WITH_RANDOM_HEX با مقدار تولید شده متفاوت، و نام میزبان و منطقه زمانی را تغییر دهید. نشان داده شده 2.42.5 برچسب است نسخه پایدار فهرست شده در 8 اکتبر 2026، در اینجا به عنوان مثال پیکربندی تاریخ استفاده می‌شود، تضمینی برای استقرار آزمایش شده زنده یا امنیت آینده نیست. قبل از نصب، نسخه های رسمی n8n فعلی را بررسی کنید، سپس n8n و تصویر اجرای وظیفه آن را در همان نسخه تایید شده نگه دارید.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

هرگز متعهد نشوید .env به یک مخزن عمومی کلید رمزگذاری و دستورالعمل های بازیابی را به‌طور ایمن از VPS ذخیره کنید. پس از تفریح ​​یا مهاجرت، کلید باید ثابت بماند.

3. برای نصب جدید compose.yaml بنویسید

در همان دایرکتوری ایجاد کنید compose.yaml. این مثال از قراردادهای رسمی متغیر محیطی n8n و PostgreSQL 18 استفاده می‌کند. PGDATA مسیر مستند شده توسط پروژه میزبانی n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

این چهار سرویس دارای نقش های متمایز هستند: PostgreSQL وضعیت پایگاه‌داده را ذخیره می‌کند، n8n گردش‌کار را اجرا می‌کند. n8n-runner وظایف دونده را با یک نسخه منطبق و نشانه احراز هویت مشترک اجرا می‌کند و Caddy HTTPS عمومی را مدیریت می‌کند. یک خارجی دونده وظیفه حالت صف Redis نیست. فقط Caddy پورت های میزبان را منتشر می‌کند. این تصویر ناب از یک نقش پایگاه‌داده واحد برای راه‌اندازی استفاده می‌کند. برای تفکیک قوی تر از امتیازات PostgreSQL، به مثال رسمی استقرار n8n PostgreSQL مراجعه کنید.

4. HTTPS Caddyfile را ایجاد کنید

فایل را ایجاد کنید Caddyfile (با بزرگ C، بدون پسوند) در کنار compose.yaml. نام میزبان نمونه را در همه جا با نام DNS خود جایگزین کنید:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy زمانی که دامنه به درستی حل شود و ترافیک خارجی به پورت های 80/443 برسد، گواهی های TLS عمومی را درخواست و تمدید می‌کند. به DNS اشاره نکنید localhost. اگر Caddy را با پراکسی معکوس دیگری جایگزین کنید، سربرگ میزبان اصلی، پروتکل و آدرس کلاینت را فوروارد کرده و تنظیم کنید. N8N_PROXY_HOPS برای تعداد واقعی پرش های پراکسی قابل اعتماد.

5. ظروف را شروع کنید و از بیرون تست کنید

این دستورات را پس از ذخیره از دایرکتوری پروژه اجرا کنید .env, compose.yaml و Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

آخرین فرمان را بررسی می‌کند عمومی HTTPS نقطه پایان سلامت اگر صدور گواهی هنوز در حال تعلیق است، قبل از اینکه نتیجه گیری کنید که n8n خراب است، گزارش های Caddy و DNS/پورت ها را بررسی کنید. باز کنید https://n8n.example.com، بلافاصله اولین حساب مالک را ایجاد کنید و حفاظت های مناسب ورود به سیستم را فعال کنید. تأیید کنید که نمونه در واقع یک گردش‌کار را اجرا می‌کند، نه اینکه صرفاً ویرایشگر بارگیری کند:

  1. در ویرایشگر، یک گردش‌کار با a ایجاد کنید وب‌هوک ماشه تنظیم کنید HTTP روش به GET، انتخاب کنید Path vps-check، و تنظیم کنید پاسخ دهید به بلافاصله. گردش‌کار را ذخیره کنید.
  2. کلیک کنید به رویداد تست گوش دهید، کامل را کپی کنید تست URL نشان داده شده توسط n8n، و از دستگاه دیگری اجرا شود curl -i 'PASTE_TEST_URL_HERE' با URL کپی شده انتظار داشته باشید که پاسخ موفقیت آمیز HTTP و رویداد دریافتی در ویرایشگر n8n ظاهر شود. URLهای آزمایشی فقط زمانی کار می کنند که n8n در حال گوش دادن به رویداد است.
  3. منتشر کنید گردش‌کار، گره را به آن تغییر دهید URL تولید، آن را کپی کرده و اجرا کنید curl -i 'PASTE_PRODUCTION_URL_HERE' دوباره اجرا را تحت گردش‌کار تایید کنید اعدام ها برگه درخواست‌های وب‌هوک تولیدی نیاز به انتشار گردش‌کار دارند و بار خود را در نمای آزمایشی ویرایشگر نشان نمی‌دهند.

این یک تست دود عمدا ساده و غیرقابل تایید است: هرگز اسرار را برای آن نفرستید. پس از آزمایش آن را لغو/حذف کنید یا قبل از استفاده از یک نقطه پایانی عمومی برای داده‌های واقعی، محدودیت های احراز هویت/IP Webhook را پیکربندی کنید. مستندات رسمی آزمایش/تولید Webhook را ببینید.

6. قبل از تغییر نسخه های پین شده، پشتیبان بگیرید

یک روگرفت PostgreSQL قابل بازیابی را ذخیره کنید و حجم داده n8n پایدار، .envکلید رمزگذاری / و فایل های خارجی مورد نیاز برای ذخیره‌سازی خارج از این سرور. بازیابی را با استفاده از راهنمای تهیه نسخه پشتیبان و بازیابی قبل از به‌روزرسانی تولید دستورات مثال:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

پین شده را تغییر دهید N8N_VERSION فقط پس از خواندن یادداشت های انتشار؛ هر دو تصویر n8n و دونده باید با هم جلو بروند. اجرا نکنید docker compose down -v در طول تعمیر و نگهداری معمول، زیرا حجم داده‌های نامگذاری شده را حذف می‌کند. PostgreSQL تغییرات نسخه اصلی نیازمند ارتقاء پایگاه‌داده یا طرح تخلیه/بازیابی است. جایگزین کردن تصویر 18 Postgres با یک تگ اصلی متفاوت، یک انتقال خودکار نیست.

مراجع معتبر: n8n Docker راهنمای نگارش، n8n پیکربندی معکوس پروکسی/وبقلاب، و یادداشت های رسمی استقرار PostgreSQL. هیچ معیار زیرساخت یا ویژگی از پیش نصب شده خاص ارائه‌دهنده فرض نمی‌شود.

نصب n8n با Docker: سؤالات متداول

آیا n8n هنگام استفاده از Docker به PostgreSQL نیاز دارد؟

Docker به PostgreSQL نیاز ندارد، و استقرارهای کوچک می توانند از SQLite استفاده کنند. برای استقرار VPS تولید محور، PostgreSQL پایه پایگاه‌داده قوی تری را فراهم می‌کند و از مقیاس‌پذیری حالت صف بعدی پشتیبانی می‌کند.

اگر PostgreSQL داده‌ها را ذخیره می‌کند، چرا یک حجم n8n ثابت نگه دارید؟

دایرکتوری n8n پایدار می‌تواند شامل وضعیت و پیکربندی نمونه مهم باشد. به جای اینکه فرض کنید پایگاه‌داده تنها دارایی بازیابی است، آن را طبق طراحی استقرار حفظ کنید.

چرا وب‌هوک من لوکال هاست را نشان می‌دهد؟

آدرس کانتینر داخلی با مبدا عمومی متفاوت است. نام میزبان خارجی، پروتکل و آدرس وب‌هوک را پیکربندی کنید و اطمینان حاصل کنید که Reverse Proxy هدرهای مورد نیاز را ارسال می‌کند.

آیا پورت 5678 باید عمومی باشد؟

برای استقرار تولید معمولی در پشت یک پراکسی معکوس، HTTPS را در پراکسی در معرض دید قرار دهید و پورت برنامه n8n را درون خود نگه دارید، مگر اینکه دلیل عملیاتی خاصی وجود داشته باشد.

آیا به Redis نیاز دارم؟

نه برای استقرار Docker تک نمونه ای استاندارد. Redis زمانی مرتبط می‌شود که شما عمداً به حالت صف و Workerها بروید.

آیا اجرای وظایف n8n خارجی مانند Workerها حالت صف هستند؟

خیر. اجراکننده های وظیفه خارجی کد وظیفه پشتیبانی شده را جدا از فرآیند اصلی n8n اجرا می کنند و از یک نشانه احراز هویت مشترک استفاده می کنند. Redis حالت صف اجراهای گردش‌کار را توزیع می‌کند و زیرساخت مورد نیاز خود را دارد. این مثال یک کار اجرا کننده خارجی، نه حالت صف Redis را نشان می‌دهد. نسخه تصویر دونده را با نسخه n8n مطابقت دهید.
