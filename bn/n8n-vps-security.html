QUICK CHECKLIST

Public exposure-এর আগে minimum security baseline

Reachable port, HTTPS, verified administrative access, MFA এবং saved credential protection দিয়ে শুরু করুন। Sensitive কাজ trigger করার আগে প্রতিটি incoming webhook authenticate করুন। Access control বদলানোর পর intended editor ও external integration এখনও কাজ করছে verify করুন, তারপর n8n security audit চালান।

শুধু HTTPS

n8n-কে correctly configured TLS reverse proxy-এর পিছনে রাখুন এবং editor ও webhook-এর জন্য consistently public HTTPS URL ব্যবহার করুন।

Minimum open port

Public traffic-এর জন্য দরকারি port-ই শুধু expose করুন। PostgreSQL, Redis ও internal application port public internet থেকে দূরে রাখুন।

SSH harden করুন

Key-based administration ব্যবহার করুন, কে login করতে পারে restrict করুন এবং operating system patched রাখুন।

Credential সুরক্ষিত করুন

n8n encryption key stable ও secret রাখুন। Environment file, database access ও backup copy-কে sensitive asset হিসেবে বিবেচনা করুন।

NETWORK EDGE

Reverse proxy, HTTPS ও trusted header

TLS termination

HTTPS terminate করতে Nginx, Caddy বা Traefik-এর মতো reverse proxy ব্যবহার করুন। Plain HTTP redirect করুন এবং proxy intended entry point হলে n8n application port সরাসরি expose করবেন না।

Proxy configuration

n8n reverse proxy-এর পিছনে চললে proxy hop count সঠিকভাবে configure করুন এবং original client request reconstruct করতে n8n-এর দরকারি forwarded header pass করুন।

Secure cookie

Editor HTTPS দিয়ে serve করুন যাতে authentication cookie secure থাকে। Broken TLS setup এড়াতে cookie security দুর্বল করবেন না।

Webhook URL

Public webhook URL externally reachable HTTPS hostname-এ set করুন যাতে generated webhook endpoint internal container বা HTTP address-এ point না করে।

Webhook না ভেঙে editor private রাখুন। Practical হলে VPN, trusted-IP policy বা authenticated proxy দিয়ে management access restrict করুন। Public webhook receiver ও OAuth callback route reachable থাকতে পারে; proxy rule enforce করার আগে trusted editor sign-in এবং real external callback দুটোই test করুন। Client-address header শুধু trusted proxy থেকে forward করুন, arbitrary request header থেকে নয়।

Webhook caller authenticate করুন: Sender support করলে Webhook node-এ None-এর বদলে Basic, Header বা JWT authentication বেছে নিন। ব্যবহার করুন IP(s) Allowlist যেখানে appropriate, এবং integration signed request support করলে provider signature verify করুন। Difficult-to-guess URL যথেষ্ট authentication নয়। Appropriate হলে proxy-তে rate limit apply করুন এবং valid burst block হচ্ছে না confirm করুন। Official Webhook authentication option।

VPS HARDENING

Server attack surface কমান

Firewall

Unsolicited inbound traffic default-deny করুন এবং শুধু reachable থাকা দরকারি service permit করুন। Database ও Redis port সাধারণত private/local network-এ থাকা উচিত।

SSH

Password-এর বদলে SSH key prefer করুন, unnecessary login path disable করুন এবং administrative access সীমিত করুন। Root-equivalent access কঠোরভাবে control করা উচিত।

OS update

Linux host ও container runtime patch করুন। Exposed বা obsolete operating system-এর ঘাটতি application hardening পূরণ করতে পারে না।

Container exposure

Host access দরকার এমন port-ই শুধু publish করুন। Internal service public interface-এর বদলে private Docker network দিয়ে communicate করবে।

Firewall বা SSH setting বদলানোর আগে inspect করুন: Listening port check করুন sudo ss -lntp, Docker publishing docker compose ps project directory থেকে, এবং host firewall policy sudo ufw status verbose UFW ব্যবহার করলে। Password access disable করার আগে actual SSH port ও separate session-এ successful key login verify করুন। Published Docker port UFW rule bypass করতে পারে; firewall status page একা port 5678 private প্রমাণ করে না। Real external reachability check করুন। Docker/UFW caveat।

Automatic Ubuntu security update কাজ করে ধরে না নিয়ে check করুন: Inspect করুন apt-config dump APT::Periodic::Unattended-Upgrade এবং log /var/log/unattended-upgrades/unattended-upgrades.log. Unattended security upgrade disabled হলে, sudo dpkg-reconfigure unattended-upgrades supported configuration dialog দেয়। Working VPS-এ enable করার আগে reboot ও service-restart behavior review করুন। Ubuntu APT update না n8n Docker image বা প্রতিটি third-party software repository automatically update করে না। Ubuntu automatic-update documentation।

Optional SSH brute-force monitoring: Fail2Ban repeated failed SSH login detect করতে পারে। Installed ও SSH-এর জন্য configured হলে jail verify করুন sudo fail2ban-client status sshd এবং confirm করুন actual SSH authentication log/journal read করে ও configured port match করে। এটি SSH key ও network restriction complement করে; replace করে না। Existing access check না করে fixed SSH port বা ban rule copy করবেন না। Ubuntu SSH hardening guidance।

DATABASE & REDIS

Backend service private রাখুন

Typical Docker Compose setup-এ PostgreSQL ও queue-mode Redis relevant container থেকে private networking দিয়ে reachable হবে, host-published port দিয়ে নয়। Verify করুন docker compose ps যে 5432 ও 6379 publicly published নয়; আলাদাভাবে VPS/cloud firewall exposure review করুন। Network policy least-privilege database credential-এর substitute নয়।

PostgreSQLRemote access explicitly required ও independently secured না হলে private interface বা container network-এ bind করুন।
RedisQueue-mode Redis infrastructure, public endpoint নয়। যেসব n8n component-এর দরকার তাদের মধ্যে network access restrict করুন।
CredentialApplication-এর দরকারি permission-সহ dedicated database credential ব্যবহার করুন এবং source control-এর বাইরে protect করুন।
TransportDatabase traffic untrusted network cross করলে শুধু application-level credential encryption-এর উপর নির্ভর না করে appropriate encrypted transport ব্যবহার করুন।

N8N SECRET

Encryption key ও credential boundary protect করুন

Encryption key

n8n encryption key দিয়ে stored credential encrypt করে। Restart ও worker জুড়ে একই key preserve করুন এবং ordinary application content থেকে আলাদাভাবে protect করুন।

Environment secret

Password, token বা encryption key public repository-তে commit করবেন না। Environment file ও deployment secret-এর access restrict করুন।

User access

শুধু trusted user-কে editor access দিন। Workflow sensitive system-এ connect করতে পারে এবং secret process বা powerful node execute করতে পারে।

Credential scope

সম্ভব হলে narrowly scoped service account ও API token ব্যবহার করুন। Compromised workflow unrelated system-এ broad access automatically inherit করা উচিত নয়।

Review করার n8n configuration: N8N_BLOCK_ENV_ACCESS_IN_NODE=true Code-node ও expression-এর environment value access prevent করে; N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true settings file-এ owner-only permission request করে। রাখুন N8N_ENCRYPTION_KEY persistent ও securely backed up: first startup-এ n8n random key তৈরি করতে পারে, কিন্তু key হারালে existing encrypted credential unusable হতে পারে। Production encryption key casually replace করবেন না; officially supported rotation procedure ব্যবহার করুন। Environment access block করলে existing integration ভাঙতে পারে, তাই production change-এর আগে test করুন। n8n security variable definition।

WORKFLOW RISK

Node security boundary বাড়াতে পারে

Self-hosting workflow-কে substantial power দেয়। Code execution, shell access, arbitrary HTTP request ও third-party community node risk বাড়াতে পারে। দরকার নেই এমন functionality disable করুন এবং untrusted workflow import run করার আগে review করুন।

Exact supported control ব্যবহার করুন: Configure করুন NODES_EXCLUDE disable করার node-এর JSON array দিয়ে, যেমন n8n-nodes-base.executeCommand এবং n8n-nodes-base.readWriteFile, unused হলে। Newer version-এ কিছু high-risk node default-এ blocked; বদলানোর আগে actual list review করুন। Official node exclusion।

n8n 2.12.0, N8N_SSRF_PROTECTION_ENABLED=true থেকে internal, loopback ও metadata-address range-এ outbound HTTP request check enable হয়। Legitimate internal API workflow কাজ বন্ধ করতে পারে; দরকার হলে শুধু নিজের control-এর destination narrowly allowlist করুন। Network segmentation primary defense রাখুন। Code-node isolation-এর জন্য external task runner review করুন। SSRF protection · Task-runner isolation।

Community nodeশুধু trusted package install করুন; এগুলো n8n environment-এর মধ্যে execute হয়।
Risky nodeDeployment-এর দরকার নেই এবং capability intended workflow boundary ছাড়িয়ে গেলে node exclude করুন।
SSRFযেখানে workflow internal বা metadata endpoint-এ পৌঁছানো উচিত নয় সেখানে n8n SSRF protection ও network control ব্যবহার করুন।
Workflow importActivation-এর আগে imported workflow, credential, expression ও executable step review করুন।

AUDIT & UPDATE

Security একটি operating process

n8n security audit চালান

Official CLI command হলো n8n audit. If your Docker Compose service is named n8n, run করুন docker compose exec -T n8n n8n audit সেই deployment directory-তে। পাঁচ category review করুন: unused credential, risky SQL-query pattern, file-system access, risky/community node এবং unprotected webhook ও outdated release-সহ instance risk। Relevant finding fix করে rerun করুন। এটি penetration test নয়। Official audit guide।

সচেতনভাবে update করুন

Security fix পাওয়ার মতো n8n current রাখুন। Internet-facing instance permanently stale না রেখে release note review করুন ও important upgrade test করুন।

Authentication monitor করুন

Unexpected access pattern, workflow change ও failure দেখুন। Operating model broad public reachability না চাইলে editor UI আরও restrict করুন।

Rollback ও recovery প্রস্তুত করুন

Significant upgrade-এর আগে recoverable backup নিন। Detailed backup scope ও restoration আলাদা recovery guide-এর বিষয়।

Sensitive execution history কমান: Successful run customer data ও token persist করতে পারে। Appropriate হলে set করুন EXECUTIONS_DATA_SAVE_ON_SUCCESS=none, রাখুন EXECUTIONS_DATA_PRUNE=true, এবং বেছে নিন EXECUTIONS_DATA_MAX_AGE ঘণ্টায়, যেমন 168 (সাত দিন)। এগুলো configurable example, legal retention rule নয়। কম history মানে কম debugging ও forensic data; running, waiting বা annotated execution একইভাবে prune নাও হতে পারে। Official execution retention।

Compromise সন্দেহ হলে: Evidence নষ্ট না করে malicious access restrict করুন, proxy, host ও n8n activity এবং changed workflow inspect করুন, possibly exposed upstream credential revoke/rotate করুন, কারণ patch করুন এবং দরকার হলে শুধু tested recoverable backup থেকে restore করুন। Affected webhook URL, editor account ও connected service review করুন; HTTPS, snapshot বা VPS purchase incident-response service দেয় ধরে নেবেন না।

ACCOUNT & PLATFORM CONTROL

VPS-এর পাশাপাশি editor-ও protect করুন

Stronger login protection ব্যবহার করুন

Editor account-এর জন্য two-factor authentication enable করুন এবং edition centralized policy enforcement support করলে n8n security policy দিয়ে MFA enforce করুন।

কারা workflow edit করতে পারে সীমিত করুন

Editor access privileged access: workflow credential read, internal system call এবং powerful node execute করতে পারে। User access narrow রাখুন এবং আর দরকার নেই এমন account remove করুন।

ব্যবহার করেন না এমন capability disable করুন

Public API অপ্রয়োজনীয় হলে disable করে এবং operating model-এর দরকার নেই এমন high-risk node বা feature block করে application attack surface কমান।

SSRF ও secret control সচেতনভাবে ব্যবহার করুন

Arbitrary HTTP request করতে পারে এমন workflow-এর জন্য n8n SSRF protection evaluate করুন এবং workflow code, public repository ও broadly readable environment file থেকে secret দূরে রাখুন।

Unused management endpoint restrict করুন: N8N_PUBLIC_API_DISABLED=true n8n public REST API disable করে, এবং N8N_PUBLIC_API_SWAGGERUI_DISABLED=true API playground আলাদাভাবে disable করে। Integration-এর এই feature দরকার না হলেই করুন। REST API disable করা workflow webhook URL authenticate করে না। Editor user-এর জন্য MFA ব্যবহার করুন এবং centralized policy শুধু edition support করলে ব্যবহার করুন।

FAQ

n8n VPS security: সাধারণ প্রশ্ন

n8n port কি সরাসরি expose করা উচিত?

Reverse proxy public entry point হলে proxy expose করুন এবং unnecessary service broadly publish না করে application port তার পিছনে রাখুন।

PostgreSQL বা Redis public হওয়া উচিত?

সাধারণত না। শুধু যেসব system-এর দরকার তাদের থেকেই reachable হওয়া উচিত। Public exposure normal n8n operation-এ সাহায্য না করে attack surface বাড়ায়।

n8n encryption key গুরুত্বপূর্ণ কেন?

এটি n8n stored credential protect করে এবং deployment জুড়ে consistent থাকতে হবে। হারালে recovered data থেকে usable encrypted credential নাও পাওয়া যেতে পারে।

Community node কি safe?

এগুলো third-party code দিয়ে n8n extend করে, তাই নিজস্ব supply-chain ও privilege risk-সহ software dependency হিসেবে বিবেচনা করুন। শুধু trusted ও দরকারি জিনিস install করুন।

HTTPS কি self-hosted n8n instance secure করে?

না। HTTPS transport protect করে। Production security-তে host hardening, access control, private backend service, secret protection, safe workflow capability, monitoring ও update-ও দরকার।

Production webhook চলার সময় n8n editor private রাখা যায়?

হ্যাঁ। Trusted reverse proxy বা VPN public production webhook ও OAuth callback path থেকে আলাদা করে editor/admin access restrict করতে পারে। Integration accidentally block না করতে প্রতিটি access-rule change-এর পর trusted sign-in ও external webhook delivery test করুন।

Incoming n8n webhook কীভাবে authenticate করব?

Sender support করলে Webhook node-এ Basic, Header বা JWT authentication configure করুন। IP(s) Allowlist ব্যবহার করতে পারেন এবং available হলে provider signature check করুন। শুধু secret-looking path-এর উপর নির্ভর করবেন না এবং sensitive API action trigger করার আগে request validate করুন।
