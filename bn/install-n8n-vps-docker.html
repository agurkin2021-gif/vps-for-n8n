নিজের VPS-এ Docker Compose দিয়ে n8n install করুন

এই example ব্যবহার করে n8n deployment তৈরি করুন একটি self-managed Linux VPS. n8n আপনি নিজেই install ও maintain করেন; আমাদের partner-এর মাধ্যমে server বেছে নিলে preinstalled n8n instance included নয়। Example private Compose network-এ n8n, PostgreSQL, external task runner ও Caddy HTTPS combine করে। এটি configuration template, live-tested deployment-এর claim নয়.

এর বদলে সবচেয়ে দ্রুত fresh installation চান? n8n official one-line Docker setup-ও দেয়। Script download ও review করতে পারেন curl -fsSL https://get.n8n.io -o get-n8n.sh run করার আগে sh get-n8n.sh. এই option local URL-এ SQLite-সহ initial instance launch করে এবং n8n Assistant sandbox service অন্তর্ভুক্ত করে; এটি একই নয় এই public-HTTPS, PostgreSQL-backed VPS deployment-এর সঙ্গে। Official full sandbox stack lean n8n installation-এর চেয়ে বেশি RAM ও CPU চায় (Compose guide অন্তত 4 GB RAM / 2 vCPUs বলে)। Internet-facing production VPS-এর জন্য নিচের manually configured stack ব্যবহার করুন।

1. Docker, DNS ও access প্রস্তুত করুন

sudo access-সহ SSH connect করুন এবং DNS A record point করুন n8n.example.com নিজের VPS IPv4 address-এ। একটি fresh Ubuntu 22.04, 24.04 বা 26.04 VPS-এ নিচের command Docker Engine ও modern docker compose plugin Docker-এর official signed apt repository থেকে install করে:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

এটি official Docker Ubuntu installation guide-এর production-oriented repository method। যে VPS-এ container বা website আগে থেকেই চলছে সেখানে blindly Docker reinstall/remove করবেন না; আগে existing installation ও possible package conflict inspect করুন। Debian বা অন্য distribution-এ Ubuntu command-এর বদলে corresponding official OS-specific instruction ব্যবহার করুন।

এখন Docker, Compose plugin, DNS ও working directory verify করুন:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

যদি getent hosts কোনো address বা ভুল address return করে, Caddy start করার আগে DNS ঠিক করুন; replace করুন n8n.example.com পুরো guide-এ নিজের real hostname দিয়ে। Docker সাধারণত root privilege চায়: SSH user পরে docker compose command সরাসরি চালাতে না পারলে সামনে দিন sudo। User-কে docker group-এ যোগ করলে root-equivalent access হয়; shared server-এ এটি casually করবেন না।

Firewall enable করার আগে actual SSH administration port reachable রাখুন। Certificate issuance ও editor-এর জন্য inbound HTTP (80) ও HTTPS (443) allow করুন। Docker-published container port কিছু UFW rule bypass করতে পারে, তাই Docker firewall guidance review করুন এবং শুধু intended Caddy port publish করুন। এই Compose example ইচ্ছাকৃতভাবে না PostgreSQL (5432), n8n (5678) বা task-runner broker (5679) public internet-এ publish করে না।

2. Environment value তৈরি করুন এবং key সংরক্ষণ করুন

Project directory থেকে তিনটি আলাদা random hexadecimal value তৈরি করুন:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

নামে file তৈরি করুন .env নিচের template ব্যবহার করে প্রতিটি REPLACE_WITH_RANDOM_HEX কে আলাদা generated value দিয়ে replace করুন এবং hostname/timezone বদলান। দেখানো 2.42.5 tag হলো 8 অক্টোবর 2026-এ listed stable release, এখানে dated configuration example হিসেবে ব্যবহার করা হয়েছে, live-tested deployment বা future security-এর guarantee নয়. Install করার আগে current official n8n release check করুন, তারপর n8n ও task-runner image একই verified version-এ রাখুন।

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

কখনো commit করবেন না .env public repository-তে। Encryption key ও recovery instruction VPS-এর বাইরে নিরাপদে রাখুন। Container recreation বা migration-এর পর key একই থাকতে হবে।

3. Fresh installation-এর জন্য compose.yaml লিখুন

একই directory-তে তৈরি করুন compose.yaml। Example official n8n environment-variable convention ও PostgreSQL 18 PGDATA path ব্যবহার করে, যা n8n hosting project document করে:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

চার service-এর আলাদা role: PostgreSQL database state store করে, n8n workflow চালায়, n8n-runner matching version ও shared authentication token-সহ runner task execute করে, আর Caddy public HTTPS handle করে। External task runner Redis queue mode নয়। শুধু Caddy host port publish করে। এই lean example setup-এর জন্য single database role ব্যবহার করে; PostgreSQL privilege আরও আলাদা করতে official n8n PostgreSQL deployment example দেখুন।

4. HTTPS Caddyfile তৈরি করুন

File তৈরি করুন Caddyfile (capital C, কোনো extension নয়) পাশে compose.yaml. Example hostname সব জায়গায় নিজের DNS name দিয়ে replace করুন:

n8n.example.com {
    reverse_proxy n8n:5678
}

Domain সঠিক resolve হলে এবং external traffic ports 80/443-এ পৌঁছালে Caddy public TLS certificate request/renew করে। DNS point করবেন না localhost. Caddy অন্য reverse proxy দিয়ে replace করলে original host, protocol ও client-address header forward করুন এবং adjust করুন N8N_PROXY_HOPS trusted proxy hop-এর actual সংখ্যা অনুযায়ী।

5. Container start করুন এবং বাইরে থেকে test করুন

Project directory থেকে command চালান, save করার পর .env, compose.yaml এবং Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

শেষ command check করে public HTTPS health endpoint। Certificate issuance pending থাকলে n8n broken ধরে নেওয়ার আগে Caddy log ও DNS/port inspect করুন। Open করুন https://n8n.example.com, সঙ্গে সঙ্গে first owner account তৈরি করুন এবং উপযুক্ত sign-in protection enable করুন। Confirm করুন instance আসলেই workflow execute করে, শুধু editor load হয় না:

  1. Editor-এ workflow তৈরি করুন একটি Webhook trigger দিয়ে। Set করুন HTTP Method এ GET, বেছে নিন Path vps-check, এবং set করুন Respond এ Immediately. Workflow save করুন।
  2. Click করুন Listen for Test Event, full Test URL যা n8n দেখায় copy করুন, তারপর অন্য device থেকে run করুন curl -i 'PASTE_TEST_URL_HERE' Copied URL দিয়ে। HTTP success response এবং incoming event n8n editor-এ দেখা উচিত। Test URL শুধু তখনই কাজ করে যখন n8n event-এর জন্য listening থাকে।
  3. Publish করুন workflow, node-কে তার Production URL, copy করে run করুন curl -i 'PASTE_PRODUCTION_URL_HERE' আবার। Workflow-এর Executions tab-এ execution confirm করুন। Production webhook request-এর জন্য workflow published থাকা দরকার এবং payload editor test view-এ দেখায় না।

এটি ইচ্ছাকৃতভাবে simple unauthenticated smoke test: এতে secret পাঠাবেন না। Test-এর পর unpublish/delete করুন, অথবা real data-র public endpoint ব্যবহারের আগে Webhook authentication/IP restriction configure করুন। Official Webhook test/production documentation দেখুন।

6. Pinned version বদলানোর আগে backup নিন

Recoverable PostgreSQL dump save করুন এবং persistent n8n data volume, .env/encryption key ও required external file এই server-এর বাইরে storage-এ রাখুন। Restore verify করুন backup ও recovery guide production update-এর আগে। Example command:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Pinned N8N_VERSION release note পড়ার পরই বদলান; n8n ও runner image একসঙ্গে advance করতে হবে। চালাবেন না docker compose down -v routine maintenance-এর সময়, কারণ এটি named data volume delete করে। PostgreSQL major-version change-এর জন্য database upgrade বা dump/restore plan দরকার; Postgres 18 image অন্য major tag দিয়ে replace করা automatic migration নয়।

Authoritative reference: n8n Docker Compose guide, n8n reverse-proxy/webhook configuration এবং official PostgreSQL deployment note। কোনো infrastructure benchmark বা provider-specific preinstalled feature assume করা হয়নি।

FAQ

Docker দিয়ে n8n install: সাধারণ প্রশ্ন

Docker ব্যবহার করলে n8n-এর PostgreSQL দরকার?

Docker-এর জন্য PostgreSQL বাধ্যতামূলক নয় এবং ছোট deployment SQLite ব্যবহার করতে পারে। Production-oriented VPS deployment-এ PostgreSQL শক্ত database foundation দেয় এবং পরে queue-mode scaling support করে।

PostgreSQL data store করলে persistent n8n volume কেন রাখব?

Persistent n8n directory-তে গুরুত্বপূর্ণ instance state ও configuration থাকতে পারে। Database-ই একমাত্র recovery asset ধরে না নিয়ে deployment design অনুযায়ী এটি preserve করুন।

আমার webhook localhost দেখায় কেন?

Internal container address public origin থেকে আলাদা। External hostname, protocol ও webhook URL configure করুন এবং নিশ্চিত করুন reverse proxy required header pass করে।

Port 5678 public হওয়া উচিত?

Normal production deployment-এ reverse proxy-তে HTTPS expose করুন এবং specific operational reason না থাকলে n8n application port internal রাখুন।

Redis দরকার?

Standard single-instance Docker deployment-এর জন্য নয়। Queue mode ও worker-এ গেলে Redis relevant হয়।

External n8n task runner ও queue-mode worker কি একই?

না। External task runner supported task code n8n main process থেকে আলাদা execute করে এবং shared authentication token ব্যবহার করে। Redis queue mode workflow execution distribute করে এবং তার নিজস্ব infrastructure requirement আছে। এই example external task runner দেখায়, Redis queue mode নয়। Runner image version n8n version-এর সঙ্গে match করুন।
