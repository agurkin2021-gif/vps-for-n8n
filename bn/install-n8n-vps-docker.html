Production responsibility

Ubuntu/Debian → Docker/Compose → PostgreSQL → persistent volumes → domain/DNS → HTTPS/reverse proxy → webhook test → backup.

Production intent

Self-hosted-এ OS, networking, performance, updates ও recovery server owner/team-এর দায়িত্ব; default ports অপ্রয়োজনীয়ভাবে public রাখবেন না।

n8n-এর জন্য VPS বাছাইয়ে CPU, RAM, NVMe, Docker, PostgreSQL, HTTPS এবং workload একসঙ্গে বিবেচনা করুন। · n8n-এর best VPS workload, concurrency, storage, latency এবং scaling-এর উপর নির্ভর করে। · n8n VPS requirements executions, payload, PostgreSQL, retention এবং binary data-এর উপর নির্ভর করে। · n8n Cloud এবং self-hosted VPS-কে cost, maintenance, data control ও scaling দিয়ে তুলনা করুন। · n8n queue mode Redis ও workers দিয়ে execution workload scale করে। · Self-hosted n8n-এর জন্য HTTPS, firewall, SSH hardening, updates এবং data protection জরুরি। · n8n backup-এ database, persistent data এবং encryption key একসঙ্গে সুরক্ষিত রাখতে হবে। · VPS-এ Docker, PostgreSQL, domain, HTTPS ও reverse proxy দিয়ে n8n production deploy করুন। · n8n Hosting Bangladesh

মূল technical decision

Production-এর আগে deployment যাচাই

1

Docker Compose-এ n8n ও PostgreSQL persistent volume ব্যবহার করবে এবং PostgreSQL public internet-এ expose করা যাবে না।

2

N8N_ENCRYPTION_KEY স্থির রাখুন এবং container-এর বাইরে সুরক্ষিত করুন।

3

Start-এর পর docker compose ps, logs এবং /healthz যাচাই করে তারপর production webhook চালু করুন।

4

n8n version pin করুন; একই volume-এ PostgreSQL major version blind upgrade করবেন না।

1 GB কি বাস্তব VPS?
