KOPYALA VE UYARLA KURULUM

n8n'i VPS'inize Docker Compose ile yükleyin

Bir n8n dağıtımı oluşturmak için bu örneği kullanın. kendi kendini yöneten Linux VPS. n8n'i kendiniz kurar ve bakımını yaparsınız; ortağımız aracılığıyla bir sunucu seçmek, önceden yüklenmiş bir n8n örneğini içermez. Örnek, harici bir görev çalıştırıcısı olan n8n, PostgreSQL ve özel bir Compose ağında Caddy HTTPS'i birleştirir. Bu bir yapılandırma şablonudur, canlı olarak test edilmiş bir dağıtım iddiası değildir.

Bunun yerine en hızlı yeni kurulumu mu istiyorsunuz? n8n ayrıca resmi bir tek satırlık Docker kurulumu sağlar. Komut dosyasını indirip inceleyebilirsiniz. curl -fsSL https://get.n8n.io -o get-n8n.sh koşmadan önce sh get-n8n.sh. Bu seçenek, yerel bir URL'de SQLite ile bir başlangıç ​​örneği başlatır ve n8n Yardımcı sanal alan hizmetlerini içerir; öyle aynı değil bu genel HTTPS, PostgreSQL destekli VPS konuşlandırması gibi. Resmi tam sanal alan yığını, yalın bir n8n kurulumundan daha fazla RAM ve CPU'e ihtiyaç duyar (Oluşturma kılavuzu en az 4 GB RAM / 2 vCPU'ları belirtir). İnternete yönelik bir üretim VPS için aşağıdaki manuel olarak yapılandırılan yığınla devam edin.

1. Docker, DNS ve erişimi hazırlayın

Sudo erişimiyle SSH üzerinden bağlanın ve bir DNS A kaydını işaret edin. n8n.example.com VPS IPv4 adresinize. bir taze Ubuntu 22.04, 24.04 veya 26.04 VPS, aşağıdaki komutlar Docker Motoru ve moderni yükler docker compose Docker'ın resmi imzalı eklentisi apt depo:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Bu, resmi Docker Ubuntu kurulum kılavuzundaki üretim odaklı depolama yöntemidir. Halihazırda çalışan bir VPS kapsayıcısında veya diğer web sitelerinde Docker öğesini körü körüne yeniden yüklemeyin veya kaldırmayın; öncelikle mevcut kurulumu ve olası paket çakışmalarını inceleyin. Debian veya başka bir dağıtım için, Ubuntu komutları yerine ilgili resmi işletim sistemine özgü talimatları kullanın.

Şimdi Docker'ın kendisini, Compose eklentisini, DNS'i ve çalışma dizinini doğrulayın:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Eğer getent hosts adres yok veya yanlış adres veriyorsa, Caddy'e başlamadan önce DNS'ınızı düzeltin; değiştir n8n.example.com Bu kılavuz boyunca gerçek ana makine adınızı girin. Docker normalde root ayrıcalıkları gerektirir: eğer SSH kullanıcınız daha sonra çalıştıramazsa docker compose komutları doğrudan kullanın, bunların önüne şunu ekleyin sudo. Bir kullanıcıyı eklemek docker grup kök eşdeğeri erişim sağlar ve paylaşılan bir sunucuda gelişigüzel yapılmamalıdır.

Güvenlik duvarını etkinleştirmeden önce gerçek SSH yönetim bağlantı noktanızı erişilebilir tutun. Sertifika verilmesi ve editör için gelen HTTP (80) ve HTTPS (443) öğelerine izin verin. Docker-yayınlanan konteyner bağlantı noktaları bazı UFW kurallarını atlayabilir, bu nedenle Docker'ın güvenlik duvarı kılavuzunu inceleyin ve yalnızca amaçlanan Caddy bağlantı noktalarını yayınlayın. Bu Compose örneği kasıtlı olarak değil PostgreSQL (5432), n8n (5678) veya görev yürütücü komisyoncuyu (5679) halka açık internette yayınlayın.

2. Ortam değerleri oluşturun ve anahtarı koruyun

Proje dizininden üç tane oluşturun farklı aşağıdakilerle rastgele onaltılık değerler:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Adlı bir dosya oluşturun .env aşağıdaki şablonu kullanarak her birini değiştirin REPLACE_WITH_RANDOM_HEX farklı bir oluşturulmuş değerle ana bilgisayar adını ve saat dilimini değiştirin. Gösterilen 2.42.5 etiket şu 8 Ekim 2026'de listelenen kararlı sürüm, burada tarihli bir yapılandırma örneği olarak kullanılmıştır, canlı olarak test edilmiş bir dağıtımın veya gelecekteki güvenliğin garantisi değildir. Yüklemeden önce mevcut resmi n8n sürümlerini kontrol edin, ardından n8n ve görev çalıştırıcı görüntüsünü aynı doğrulanmış sürümde tutun.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Asla taahhütte bulunma .env halka açık bir depoya. Şifreleme anahtarını ve kurtarma talimatlarını VPS'ın dışında güvenli bir şekilde saklayın. Anahtar, konteynerin yeniden oluşturulmasından veya taşınmasından sonra aynı kalmalıdır.

3. Yeni bir kurulum için compose.yaml yazın

Aynı dizinde oluşturun compose.yaml. Örnekte resmi n8n ortam değişkeni kuralları ve PostgreSQL 18 kuralları kullanılmaktadır. PGDATA n8n barındırma projesi tarafından belgelenen yol:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Dört hizmetin farklı rolleri vardır: PostgreSQL verisisitabanı durumunu saklar, n8n iş akışlarını çalıştırır, n8n-runner koşucu görevlerini eşleşen bir sürüm ve paylaşılan kimlik doğrulama jetonuyla yürütür ve Caddy genel HTTPS'i yönetir. Harici bir görev çalıştırıcısı Redis Queue Mode değildir. Yalnızca Caddy ana bilgisayar bağlantı noktalarını yayınlar. Bu yalın örnekte kurulum için tek bir veritabanı rolü kullanılıyor; PostgreSQL ayrıcalıklarının daha güçlü bir şekilde ayrılması için resmi n8n PostgreSQL dağıtım örneğine bakın.

4. HTTPS Caddy dosyasını oluşturun

Dosyayı oluştur Caddyfile (büyük C, uzatma yok) yanında compose.yaml. Örnek ana bilgisayar adını her yerde kendi DNS adınızla değiştirin:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy, alan adı doğru şekilde çözümlendiğinde ve harici trafik 80/443 bağlantı noktalarına ulaşabildiğinde genel TLS sertifikalarını talep eder ve yeniler. DNS'ü şuna işaret etmeyin: localhost. Caddy'ı başka bir reverse proxy ile değiştirirseniz, orijinal ana bilgisayar, protokol ve istemci adresi başlıklarını iletin ve ayarlayın N8N_PROXY_HOPS güvenilir proxy atlamalarının gerçek sayısı için.

5. Container'ları başlatın ve dışarıdan test edin

Bu komutları kaydettikten sonra proje dizininden çalıştırın .env, compose.yaml ve Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Son komut şunları kontrol eder: genel HTTPS sağlık son noktası. Sertifikanın verilmesi hâlâ beklemedeyse, n8n'nin bozuk olduğu sonucuna varmadan önce Caddy günlüklerini ve DNS/bağlantı noktalarını inceleyin. Açık https://n8n.example.com, hemen ilk sahip hesabını oluşturun ve uygun oturum açma korumalarını etkinleştirin. Örneğin yalnızca düzenleyicinin yüklemediğini değil, gerçekten bir iş akışı yürüttüğünü doğrulayın:

  1. Düzenleyicide bir iş akışı oluşturun. Webhook tetikleyin. Ayarla HTTP Yöntem için GET, şunu seç Path vps-checkve ayarlayın Yanıtla için Hemen. İş akışını kaydedin.
  2. Tıklayın Test Etkinliğini Dinle, tamamını kopyala URL'yi test edin n8n ile gösterilir ve başka bir cihaz çalıştırmasından curl -i 'PASTE_TEST_URL_HERE' kopyalanan URL ile. HTTP başarılı yanıtının ve gelen etkinliğin n8n düzenleyicisinde görünmesini bekleyin. Test URL'leri yalnızca n8n olayı dinlerken çalışır.
  3. Yayınla iş akışında düğümü kendi Üretim URL'si, kopyalayın ve çalıştırın curl -i 'PASTE_PRODUCTION_URL_HERE' tekrar. İş akışı altında yürütmeyi onaylayın İnfazlar sekmesi. Üretim webhook isteklerinin yayınlanması için iş akışı gerekir ve bunların yükü, editörün test görünümünde gösterilmez.

Bu kasıtlı olarak basit, doğrulanmamış bir duman testidir: ona asla sır göndermeyin. Test ettikten sonra yayından kaldırın/silin veya gerçek veriler için genel bir uç nokta kullanmadan önce Webhook kimlik doğrulaması/IP kısıtlamalarını yapılandırın. Resmi Webhook testi/üretim belgelerine bakın.

6. Pinlenmiş sürümleri değiştirmeden önce yedek alın

Kurtarılabilir bir PostgreSQL dökümünü kaydet ve kalıcı n8n verisisi hacmi, .env/encryption anahtarını ve gerekli harici dosyaları bu sunucunun dışında depolamak için. kullanarak bir geri yüklemeyi doğrulayın. yedekleme ve kurtarma kılavuzu Üretimi güncellemeden önce. Örnek komutlar:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Sabitleneni değiştir N8N_VERSION yalnızca sürüm notlarını okuduktan sonra; hem n8n hem de koşucu görselleri birlikte ilerlemelidir. Koşma docker compose down -v rutin bakım sırasında adlandırılmış veri birimleri silinir. PostgreSQL Büyük sürüm değişiklikleri, veritabanı yükseltme veya boşaltma/geri yükleme planı gerektirir; Postgres 18 görüntüsünü farklı bir ana etiketle değiştirmek otomatik bir geçiş değildir.

n8n'i Docker ile kurmak: sık sorulan sorular

Docker kullanılırken n8n'in PostgreSQL'e ihtiyacı var mı?

Docker, PostgreSQL'i gerektirmez ve küçük dağıtımlar SQLite'i kullanabilir. Üretim odaklı VPS dağıtımı için PostgreSQL daha güçlü bir veritabanı temeli sağlar ve daha sonraki Queue Mode ölçeklendirmesini destekler.

Eğer PostgreSQL verisisileri saklıyorsa neden kalıcı bir n8n birimini tutmalısınız?

Kalıcı n8n dizini önemli örnek durumunu ve yapılandırmasını içerebilir. Veritabanının tek kurtarma varlığı olduğunu varsaymak yerine dağıtım tasarımına göre koruyun.

Web kancam neden localhost'u gösteriyor?

Dahili kapsayıcı adresi genel kaynaktan farklıdır. Harici ana bilgisayar adını, protokolü ve webhook URL'sini yapılandırın ve reverse proxy'nin gerekli başlıkları aktardığından emin olun.

5678 numaralı bağlantı noktası herkese açık olmalı mı?

Reverse proxy arkasında normal bir üretim dağıtımı için, proxy'de HTTPS'ı gösterin ve özel bir operasyonel neden olmadığı sürece n8n uygulama bağlantı noktasını dahili tutun.

Redis'a ihtiyacım var mı?

Standart tek örnekli Docker dağıtımı için değil. Redis kasıtlı olarak Queue Modena ve işçilere geçtiğinizde geçerli hale gelir.

Harici n8n görev çalıştırıcıları Queue Mode çalışanlarıyla aynı mıdır?

Hayır. Harici görev çalıştırıcıları, desteklenen görev kodunu n8n ana işleminden ayrı olarak yürütür ve paylaşılan bir kimlik doğrulama belirteci kullanır. Redis Queue Mode iş akışı yürütmelerini dağıtır ve kendi altyapı gereksinimlerine sahiptir. Bu örnekte Redis Queue Modenu değil, harici bir görev çalıştırıcısı gösterilmektedir.
