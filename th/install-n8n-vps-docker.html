ติดตั้ง n8n บน VPS ของคุณด้วย Docker Compose

ใช้ตัวอย่างนี้เพื่อสร้างdeployment n8n บน จัดการตนเอง Linux VPS. คุณติดตั้งและบำรุงรักษา n8n ด้วยตัวคุณเอง การเลือกเซิร์ฟเวอร์ผ่านพันธมิตรของเราไม่รวมอินสแตนซ์ n8n ที่ติดตั้งไว้ล่วงหน้า ตัวอย่างนี้รวม n8n, PostgreSQL, ตัวดำเนินการงานภายนอกและ Caddy HTTPS ในเครือข่ายการเขียนส่วนตัว เป็นเทมเพลตการกำหนดค่า ไม่ใช่การอ้างสิทธิ์การใช้งานที่ทดสอบแล้ว.

ต้องการการติดตั้งใหม่ที่เร็วที่สุดแทนหรือไม่ n8n ยังมีการตั้งค่า Docker บรรทัดเดียวอย่างเป็นทางการอีกด้วย คุณสามารถดาวน์โหลดและตรวจสอบสคริปต์ได้ด้วย curl -fsSL https://get.n8n.io -o get-n8n.sh ก่อนที่จะวิ่ง sh get-n8n.sh. ตัวเลือกนั้นจะเปิดตัวอินสแตนซ์เริ่มต้นด้วย SQLite ที่ URL ในเครื่อง และรวมถึงบริการแซนด์บ็อกซ์ของผู้ช่วย n8n มันคือ ไม่เหมือนกัน เนื่องจากdeployment public-HTTPS, PostgreSQL-backed VPS สแต็กแซนด์บ็อกซ์แบบเต็มอย่างเป็นทางการต้องการ RAM และ CPU มากกว่าการติดตั้งแบบ Lean n8n (คู่มือการเขียนระบุ vCPU อย่างน้อย 4 GB RAM / 2) สำหรับการผลิตผ่านอินเทอร์เน็ต VPS ให้ดำเนินการต่อด้วยสแต็กที่กำหนดค่าด้วยตนเองด้านล่าง

1 เตรียม Docker, DNS และการเข้าถึง

เชื่อมต่อผ่าน SSH ด้วยการเข้าถึง sudo และชี้ DNS บันทึกสำหรับ n8n.example.com ไปยังที่อยู่ VPS IPv4 ของคุณ บน สด Ubuntu 22.04, 24.04 หรือ 26.04 VPS คำสั่งต่อไปนี้จะติดตั้ง Docker เครื่องยนต์และความทันสมัย docker compose ปลั๊กอินจาก Docker ลงนามอย่างเป็นทางการ apt พื้นที่เก็บข้อมูล:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

นี่เป็นวิธีการเก็บข้อมูลเชิงการผลิตในคู่มือการติดตั้ง Docker Ubuntu อย่างเป็นทางการ อย่าติดตั้งซ้ำหรือลบ Docker ใน VPS ที่ใช้งานคอนเทนเนอร์หรือเว็บไซต์อื่นๆ อยู่แล้วโดยสุ่มสี่สุ่มห้า; ขั้นแรกให้ตรวจสอบการติดตั้งที่มีอยู่และข้อขัดแย้งของแพ็คเกจที่เป็นไปได้ สำหรับ Debian หรือการแจกจ่ายอื่น ให้ใช้คำแนะนำเฉพาะระบบปฏิบัติการอย่างเป็นทางการที่เกี่ยวข้องแทนคำสั่ง Ubuntu

ตอนนี้ให้ตรวจสอบ Docker ปลั๊กอินเขียน DNS และไดเร็กทอรีการทำงาน:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

ถ้า getent hosts ไม่ส่งคืนที่อยู่หรือที่อยู่ผิด แก้ไข DNS ของคุณก่อนเริ่ม Caddy; แทนที่ n8n.example.com ตลอดทั้งคู่มือนี้พร้อมด้วยชื่อโฮสต์จริงของคุณ โดยปกติ Docker ต้องการสิทธิ์รูท: หากผู้ใช้ SSH ของคุณไม่สามารถเรียกใช้ในภายหลัง docker compose คำสั่งโดยตรง นำหน้าด้วย sudo. การเพิ่มผู้ใช้ให้กับ docker group ให้สิทธิ์การเข้าถึงเทียบเท่า root และไม่ควรทำโดยไม่ตั้งใจบนเซิร์ฟเวอร์ที่ใช้ร่วมกัน

รักษาพอร์ตการดูแลระบบ SSH ที่แท้จริงของคุณให้สามารถเข้าถึงได้ก่อนเปิดใช้งานไฟร์วอลล์ อนุญาตให้ขาเข้า HTTP (80) และ HTTPS (443) สำหรับการออกใบรับรองและบรรณาธิการ พอร์ตคอนเทนเนอร์ที่เผยแพร่ Docker สามารถข้ามกฎ UFW บางอย่างได้ ดังนั้น โปรดตรวจสอบคำแนะนำไฟร์วอลล์ของ Docker และเผยแพร่เฉพาะพอร์ต Caddy ที่ต้องการเท่านั้น ตัวอย่างการเขียนนี้จงใจทำ ไม่ เผยแพร่ PostgreSQL (5432), n8n (5678) หรือนายหน้าผู้ดำเนินการงาน (5679) ไปยังอินเทอร์เน็ตสาธารณะ

2 สร้างค่าสภาพแวดล้อมและรักษาคีย์ไว้

จากไดเร็กทอรีโครงการ ให้สร้างสามรายการ แตกต่าง ค่าเลขฐานสิบหกแบบสุ่มด้วย:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

สร้างไฟล์ชื่อ .env โดยใช้เทมเพลตด้านล่าง แทนที่ทุกรายการ REPLACE_WITH_RANDOM_HEX ด้วยค่าที่สร้างขึ้นที่แตกต่างกัน และเปลี่ยนชื่อโฮสต์และเขตเวลา ที่แสดง 2.42.5 แท็กคือ การเผยแพร่ที่เสถียรซึ่งแสดงอยู่ใน 8 ตุลาคม 2026ใช้ที่นี่เป็นตัวอย่างการกำหนดค่าวันที่ ไม่ใช่การรับประกันการใช้งานจริงที่ทดสอบแล้วหรือความปลอดภัยในอนาคต. ก่อนการติดตั้ง ให้ตรวจสอบรุ่น n8n อย่างเป็นทางการในปัจจุบัน จากนั้นเก็บ n8n และอิมเมจตัวดำเนินการงานไว้ในเวอร์ชันที่ได้รับการยืนยันเดียวกัน

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

ไม่เคยกระทำ .env ไปยังพื้นที่เก็บข้อมูลสาธารณะ เก็บคีย์เข้ารหัสและคำแนะนำในการกู้คืนไว้อย่างปลอดภัยนอก VPS คีย์จะต้องคงเดิมหลังจากการสร้างคอนเทนเนอร์ใหม่หรือการย้ายข้อมูล

3 เขียน compose.yaml สำหรับการติดตั้งใหม่

ในไดเร็กทอรีเดียวกัน ให้สร้าง compose.yaml. ตัวอย่างใช้แบบแผน n8n ตัวแปรสภาพแวดล้อมอย่างเป็นทางการและ PostgreSQL 18 PGDATA เส้นทางที่จัดทำโดยโครงการโฮสติ้ง n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

บริการทั้งสี่มีบทบาทที่แตกต่างกัน: PostgreSQL เก็บสถานะฐานข้อมูล n8n ดำเนินการเวิร์กโฟลว์ n8n-runner ดำเนินการงานรองชนะเลิศด้วยเวอร์ชันที่ตรงกันและโทเค็นการรับรองความถูกต้องที่ใช้ร่วมกัน และ Caddy จัดการสาธารณะ HTTPS ภายนอก นักวิ่งงาน ไม่ใช่Queue Mode Redis เฉพาะ Caddy เท่านั้นที่เผยแพร่พอร์ตโฮสต์ ภาพประกอบแบบลีนนี้ใช้บทบาทฐานข้อมูลเดียวสำหรับการตั้งค่า เพื่อการแยกสิทธิ์ของ PostgreSQL ที่แข็งแกร่งยิ่งขึ้น โปรดดูตัวอย่างการใช้งาน n8n PostgreSQL อย่างเป็นทางการ

4 สร้าง HTTPS แคดดี้ไฟล์

สร้างไฟล์ Caddyfile (ตัวพิมพ์ใหญ่ C ไม่มีการขยาย) ควบคู่ไปกับ compose.yaml. แทนที่ชื่อโฮสต์ตัวอย่างทุกที่ด้วยชื่อ DNS ของคุณเอง:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy ร้องขอและต่ออายุใบรับรอง TLS สาธารณะ เมื่อโดเมนแก้ไขได้อย่างถูกต้องและการรับส่งข้อมูลภายนอกสามารถเข้าถึงพอร์ต 80/443 อย่าชี้DNS ไปที่ localhost. หากคุณแทนที่ Caddy ด้วยreverse proxyอื่น ให้ส่งต่อโฮสต์ โปรโตคอล และส่วนหัวที่อยู่ไคลเอ็นต์ดั้งเดิม แล้วปรับเปลี่ยน N8N_PROXY_HOPS สำหรับจำนวนฮอพพร็อกซีที่เชื่อถือได้จริง

5 เริ่มคอนเทนเนอร์และทดสอบจากภายนอก

รันคำสั่งเหล่านี้จากไดเร็กทอรีโปรเจ็กต์หลังจากบันทึก .env, compose.yaml และ Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

คำสั่งสุดท้ายจะตรวจสอบไฟล์ สาธารณะ HTTPS endpointด้านสุขภาพ หากการออกใบรับรองยังอยู่ในระหว่างดำเนินการ ให้ตรวจสอบบันทึก Caddy และ DNS/พอร์ต ก่อนที่จะสรุป n8n ว่าใช้งานไม่ได้ เปิด https://n8n.example.comสร้างบัญชีเจ้าของคนแรกทันทีและเปิดใช้งานการป้องกันการลงชื่อเข้าใช้ที่เหมาะสม ยืนยันว่าอินสแตนซ์ดำเนินการเวิร์กโฟลว์จริง ไม่ใช่แค่ตัวแก้ไขโหลด:

  1. ในตัวแก้ไข ให้สร้างเวิร์กโฟลว์ด้วย webhook ทริกเกอร์ ชุด HTTP วิธีการ ถึง GET, เลือก Path vps-checkและตั้งค่า ตอบกลับ ถึง ทันที. บันทึกขั้นตอนการทำงาน
  2. คลิก ฟังกิจกรรมทดสอบ, คัดลอกเต็ม ทดสอบ URL แสดงโดย n8n และเรียกใช้จากอุปกรณ์อื่น curl -i 'PASTE_TEST_URL_HERE' ด้วย URL ที่คัดลอก คาดว่าจะได้รับคำตอบที่ประสบความสำเร็จ HTTP และเหตุการณ์ที่กำลังจะเกิดขึ้นจะปรากฏในตัวแก้ไข n8n URL ทดสอบจะทำงานเฉพาะในขณะที่ n8n กำลังฟังกิจกรรมอยู่เท่านั้น
  3. เผยแพร่ เวิร์กโฟลว์ ให้สลับโหนดไปที่มัน URL การผลิตคัดลอกและเรียกใช้ curl -i 'PASTE_PRODUCTION_URL_HERE' อีกครั้ง ยืนยันการดำเนินการภายใต้เวิร์กโฟลว์ การประหารชีวิต แท็บ คำขอwebhookที่ใช้งานจริงจำเป็นต้องเผยแพร่เวิร์กโฟลว์ และไม่แสดงเพย์โหลดในมุมมองทดสอบของตัวแก้ไข

นี่เป็นการทดสอบควันที่ง่ายดายโดยเจตนาและไม่ผ่านการรับรองความถูกต้อง: ห้ามส่งsecretไปให้เด็ดขาด ยกเลิกการเผยแพร่/ลบออกหลังการทดสอบ หรือกำหนดค่าการตรวจสอบสิทธิ์/ข้อจำกัด IP ของ Webhook ก่อนที่จะใช้endpointสาธารณะสำหรับข้อมูลจริง ดูเอกสารการทดสอบ/การผลิตอย่างเป็นทางการของ Webhook

6 สำรองข้อมูลก่อนที่จะเปลี่ยนเวอร์ชันที่ปักหมุดไว้

บันทึกดัมพ์ PostgreSQL ที่กู้คืนได้ และ ปริมาณข้อมูล n8n แบบถาวร .env/คีย์การเข้ารหัสและไฟล์ภายนอกที่จำเป็นสำหรับการจัดเก็บนอกเซิร์ฟเวอร์นี้ ตรวจสอบการคืนค่าโดยใช้ คู่มือการสำรองและกู้คืน ก่อนอัพเดตการผลิต คำสั่งตัวอย่าง:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

เปลี่ยนที่ปักหมุดไว้ N8N_VERSION หลังจากอ่านบันทึกประจำรุ่นแล้วเท่านั้น ทั้ง n8n และรูปนักวิ่งจะต้องก้าวหน้าไปพร้อมๆ กัน อย่าวิ่ง docker compose down -v ในระหว่างการบำรุงรักษาตามปกติเนื่องจากจะลบวอลุ่มข้อมูลที่มีชื่อ PostgreSQL การเปลี่ยนแปลงเวอร์ชันหลักจำเป็นต้องมีการอัพเกรดฐานข้อมูลหรือแผนการดัมพ์/กู้คืน การแทนที่รูปภาพ Postgres 18 ด้วยแท็กหลักอื่นไม่ใช่การย้ายข้อมูลอัตโนมัติ

ข้อมูลอ้างอิงที่เชื่อถือได้: n8n Docker คู่มือการเขียน n8n การกำหนดค่าreverse proxy/webhook และบันทึกการใช้งาน PostgreSQL อย่างเป็นทางการ ไม่มีการวัดประสิทธิภาพโครงสร้างพื้นฐานหรือคุณสมบัติเฉพาะของผู้ให้บริการที่ติดตั้งไว้ล่วงหน้า

คำถามที่พบบ่อย

การติดตั้ง n8n ด้วย Docker: คำถามทั่วไป

n8n จำเป็นต้องมี PostgreSQL เมื่อใช้ Docker หรือไม่

Docker ไม่ต้องการ PostgreSQL และdeploymentขนาดเล็กสามารถใช้ SQLite ได้ สำหรับdeployment VPS ที่มุ่งเน้นการผลิต PostgreSQL มอบรากฐานฐานข้อมูลที่แข็งแกร่งยิ่งขึ้น และรองรับการปรับขนาดQueue Modeในภายหลัง

เหตุใดจึงต้องคงปริมาณ n8n ไว้อย่างต่อเนื่อง หาก PostgreSQL เก็บข้อมูล

ไดเร็กทอรี n8n แบบถาวรสามารถมีสถานะอินสแตนซ์และการกำหนดค่าที่สำคัญได้ เก็บรักษาไว้ตามการออกแบบdeployment แทนที่จะถือว่าฐานข้อมูลเป็นเพียงสินทรัพย์การกู้คืนเท่านั้น

เหตุใด webhook ของฉันจึงแสดง localhost

ที่อยู่คอนเทนเนอร์ภายในแตกต่างจากแหล่งที่มาสาธารณะ กำหนดค่าชื่อโฮสต์ภายนอก โปรโตคอล และ URL ของwebhook และตรวจสอบว่าreverse proxyผ่านส่วนหัวที่จำเป็น

พอร์ต 5678 ควรเป็นแบบสาธารณะหรือไม่

สำหรับdeploymentที่ใช้งานจริงตามปกติหลังreverse proxy ให้เปิดเผย HTTPS ที่พร็อกซีและเก็บพอร์ตแอปพลิเคชัน n8n ไว้ภายใน เว้นแต่จะมีเหตุผลในการปฏิบัติงานเฉพาะที่ไม่ทำเช่นนั้น

ไม่ใช่สำหรับdeployment Docker อินสแตนซ์เดียวแบบมาตรฐาน Redis มีความเกี่ยวข้องเมื่อคุณจงใจย้ายไปที่Queue Modeและพนักงาน

ตัวดำเนินการงาน n8n ภายนอกเหมือนกับworkerในQueue Modeหรือไม่

ไม่ ผู้ดำเนินการงานภายนอกรันโค้ดงานที่ได้รับการสนับสนุนแยกจากกระบวนการหลัก n8n และใช้โทเค็นการรับรองความถูกต้องที่ใช้ร่วมกัน Redis Queue Modeจะกระจายการดำเนินการเวิร์กโฟลว์และมีข้อกำหนดด้านโครงสร้างพื้นฐานของตัวเอง ตัวอย่างนี้แสดงตัวดำเนินการงานภายนอก ไม่ใช่Queue Mode Redis จับคู่เวอร์ชันรูปภาพนักวิ่งกับเวอร์ชัน n8n

ดูตัวเลือก VPS

ข้อกำหนด VPS · ความปลอดภัยในการผลิต · สำรองและกู้คืน · Queue Modeและworker · คู่มือหลัก n8n VPS

เปรียบเทียบผู้ให้บริการ?

สำหรับตัวเลือกของผู้ให้บริการ การตั้งค่าเพียงคลิกเดียว ขอบเขตการสนับสนุน backup การโยกย้าย ภูมิภาค และการปรับขนาด ให้ใช้ ดีที่สุด VPS สำหรับการเปรียบเทียบ n8n. สำหรับการกำหนดขนาดทรัพยากร ให้กลับไปที่ หลัก VPS สำหรับคำแนะนำ n8n.
