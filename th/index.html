ที่เก็บของใช้ที่เก็บข้อมูล SSD หรือ NVMe และเลือกความจุสำหรับข้อมูลที่คุณเก็บไว้จริง วางสำเนาการกู้คืนนอกเซิร์ฟเวอร์เพื่อให้รอดพ้นจากการสูญเสีย VPS
สิ่งแวดล้อมเลือก Linux พร้อมสิทธิ์การเข้าถึงระดับผู้ดูแลระบบและการสนับสนุน Docker ใช้ชื่อโฮสต์สาธารณะ HTTPS สำหรับ webhooks และเครือข่ายส่วนตัวระหว่างบริการแอปพลิเคชัน
เครือข่ายและภูมิภาคหากผู้ให้บริการของคุณให้บริการหลายภูมิภาค ให้วาง VPS ใกล้กับฐานข้อมูล, API หรือผู้ใช้ที่ควบคุมการเดินทางไปกลับ เวิร์กโฟลว์ที่มีไฟล์จำนวนมากยังทำให้แบนด์วิธและนโยบายการถ่ายโอนเป็นส่วนหนึ่งของการตัดสินใจด้านทรัพยากร ภูมิภาคอาจมีความสำคัญต่อถิ่นที่อยู่ของข้อมูล
ขอบเขตการสนับสนุนก่อนชำระเงิน ให้ตรวจสอบสิ่งที่ผู้ให้บริการรองรับ ด้วย VPS ที่self-managed วางแผนที่จะเป็นเจ้าของการอัปเดต n8n การกำหนดค่า และการกู้คืน เว้นแต่จะรวมการจัดการระดับแอปพลิเคชันไว้อย่างชัดเจน

เส้นทางการเติบโตที่ชัดเจน

เริ่มต้นด้วยตัวอย่างเดียว เพิ่มworkerเมื่อจำเป็น

สาธารณะ HTTPS→reverse proxy→n8n↔PostgreSQL

อินสแตนซ์ n8n เดี่ยวช่วยให้deploymentขนาดเล็กตรงไปตรงมา เมื่องานสะสมเนื่องจากความสามารถในการดำเนินการเป็นข้อจำกัด Queue Modeจะแยกทริกเกอร์ขาเข้าออกจากกระบวนการของworkerที่รันเวิร์กโฟลว์

วางแผนทรัพยากรสำหรับกระบวนการหลัก PostgreSQL, Redis และworkerแต่ละคน พนักงานแชร์การเข้าถึงฐานข้อมูลและคีย์การเข้ารหัส สำหรับคิวที่มีไฟล์จำนวนมาก ให้เลือกพื้นที่เก็บข้อมูลไบนารีที่ใช้ร่วมกันที่รองรับ วางแผนQueue Modeและworker · สถาปัตยกรรมคิวอย่างเป็นทางการ

ดำเนินdeploymentของคุณให้เสร็จสิ้น

เตรียมการตั้งค่า n8n ของคุณให้พร้อมสำหรับการทำงานในแต่ละวัน

01

รักษาข้อมูลของคุณให้คงอยู่

ให้n8n และวอลุ่มถาวรของฐานข้อมูล ตรวจสอบว่าเวิร์กโฟลว์และข้อมูลรับรองยังคงใช้งานได้หลังจากรีสตาร์ทคอนเทนเนอร์แล้ว

02

เชื่อมต่ออุปกรณ์ปลายทางที่ปลอดภัย

ตั้งค่า HTTPS และการรับรองความถูกต้อง กำหนดค่า URL webhookสาธารณะ และรักษาพอร์ตฐานข้อมูลภายในให้เป็นส่วนตัว รายการตรวจสอบความปลอดภัย.

03

รักษาการกู้คืนอย่างตรงไปตรงมา

สำรองฐานข้อมูล การกำหนดค่า คีย์การเข้ารหัส และไฟล์ที่จำเป็นไปยังตำแหน่งอื่น ตรวจสอบกระบวนการคืนค่า สำรองและกู้คืน.

04

กำหนดการบำรุงรักษา

เลือกเวลาที่จะอัปเดตแอปพลิเคชัน ตรวจสอบการเปลี่ยนแปลงรุ่น และตรวจสอบขั้นตอนการทำงานที่สำคัญหลังการอัพเกรด ตรวจสอบความล้มเหลวในการดำเนินการ การใช้ทรัพยากร และการต่ออายุใบรับรอง

วางงบประมาณของคุณไว้ในที่ที่จะช่วยได้

มี RAM เพิ่มเติม CPU เพิ่มเติม หรือเวิร์กโฟลว์มีการเปลี่ยนแปลงหรือไม่

01 · หน่วยความจำ

สำหรับชุดข้อมูลการทำงานขนาดใหญ่

ตรวจสอบการใช้หน่วยความจำในขณะที่งานที่ใหญ่ที่สุดของคุณทับซ้อนกัน ประมวลผลการนำเข้าเป็นชุดเล็กๆ และส่งคืนเฉพาะข้อมูลที่จำเป็นสำหรับขั้นตอนถัดไปเท่านั้น

ซื้อเพิ่มเติม RAM เมื่อเวิร์กโหลดยังคงเต็มหน่วยความจำหลังจากการเปลี่ยนแปลงเหล่านั้น

02 · กำลังประมวลผล

สำหรับการเปลี่ยนแปลงที่ช้า

เปรียบเทียบเวลาประมวลผลภายในกับเวลาที่ใช้ในการรอบริการภายนอก โหลด CPU อย่างต่อเนื่องในระหว่างจุดทำงานในพื้นที่เพื่อการประมวลผลที่มากขึ้น

รักษาระดับ CPU ปัจจุบันไว้ เมื่อการตอบสนอง API หรือขีดจำกัดอัตราเป็นจุดคอขวด

03 · การจัดเก็บ

สำหรับประวัติการดำเนินการที่เพิ่มขึ้น

เลือกผลการดำเนินการที่จะบันทึกและระยะเวลา รวมไฟล์เวิร์กโฟลว์และการเติบโตของฐานข้อมูลไว้ในงบประมาณพื้นที่จัดเก็บข้อมูลของคุณ

เลือกดิสก์ที่ใหญ่กว่า เมื่อประวัติที่คุณต้องการรักษามีมากกว่าพื้นที่ว่าง

04 · งานคู่ขนาน

สำหรับการระเบิดที่ทับซ้อนกัน

ซวนเซกำหนดเวลาการนำเข้าก่อน เพิ่มworkerเมื่องานที่ค้างอยู่แสดงถึงขีดจำกัดความสามารถในการดำเนินการ และฐานข้อมูลและทรัพยากรของworkerสามารถรองรับการทำงานแบบขนานได้มากขึ้น

ปรับขนาดพนักงานและทรัพยากรของพวกเขาเข้าด้วยกัน

สำหรับการตั้งค่า Docker แผงเว็บโฮสติ้งแบบชำระเงินเป็นทางเลือก สำหรับการโทร AI API ที่โฮสต์ ไม่จำเป็นต้องใช้ฮาร์ดแวร์ GPU ในเครื่อง เก็บงบประมาณสำหรับ RAM การประมวลผล การจัดเก็บ และการกู้คืนความต้องการขั้นตอนการทำงานจริงของคุณ

ใช้ docker stats, การใช้งานดิสก์ของโฮสต์และบันทึกการดำเนินการเพื่อเปรียบเทียบช่วงเวลาที่ยุ่งที่สุดก่อนและหลังการเปลี่ยนแปลง การวัดประสิทธิภาพ n8n · การควบคุมการทำงานพร้อมกัน

งบประมาณที่คุณสามารถติดตามได้

สิ่งที่คุณจ่ายเมื่อคุณself-hosted n8n

ต้นทุนการกำหนดค่า Standard สำหรับธุรกิจขนาดเล็ก $0.67 ต่อวันที่เรียกเก็บเงิน: $20.10 สำหรับ 30 วัน หรือ $20.77 สำหรับ 31 วันในการใช้งานเซิร์ฟเวอร์ นี่คืออัตราเซิร์ฟเวอร์รายวัน ไม่ใช่อัตราเฉลี่ยรายเดือนหลายปี

สร้างงบประมาณของคุณจาก การใช้เซิร์ฟเวอร์ + โครงสร้างพื้นฐานพิเศษที่เลือก + การใช้งาน API ภายนอก + คุณสมบัติ n8n แบบชำระเงินใดๆ. แยกเวลาการบริหารออกจากค่าธรรมเนียมเงินสด

เซิร์ฟเวอร์เลือกชุดทรัพยากรที่ตรงกัน และตรวจสอบการชำระเงินที่จำเป็นเพื่อเติมเงินในบัญชีของคุณ ยอดรวมขึ้นอยู่กับวันที่เรียกเก็บเงินและตัวเลือกที่เลือก
การกู้คืนรวมพื้นที่เก็บข้อมูลและการเก็บรักษาสำหรับbackupนอกเซิร์ฟเวอร์ของคุณ ใช้โดเมนหรือโดเมนย่อยที่มีอยู่ตามความเหมาะสม แทนที่จะซื้อโดเมนอื่นสำหรับทุกขั้นตอนการทำงาน
การใช้งานn8n ฉบับชุมชนเปิดให้self-hostedได้ฟรี งบประมาณแยกต่างหากสำหรับการใช้งานรุ่น API และบริการแบบชำระเงินอื่นๆ ที่เวิร์กโฟลว์ของคุณเรียกใช้ ตรวจสอบคุณสมบัติฉบับ
การดำเนินงานให้เวลาสำหรับการอัปเดต การตรวจสอบ และการกู้คืนการตรวจสอบ เลือกการโฮสต์แอปพลิเคชันที่ได้รับการจัดการเมื่อคุณต้องการชำระค่าจัดการงานเหล่านั้น

สร้างงบประมาณรายเดือนที่แท้จริงของคุณ

ประมาณราคาตามจริงของเดือน n8n VPS ของคุณ

สร้างตัวเลขรายเดือนจากค่าบริการเซิร์ฟเวอร์บวกเฉพาะส่วนเสริมที่คุณใช้จริง เครื่องคิดเลขเริ่มต้นด้วยอัตรารายวัน Standard ปัจจุบันที่แสดงในหน้านี้ ต้นทุนเสริมจะอยู่ที่ศูนย์จนกว่าคุณจะป้อนจำนวนเงินของคุณเอง

ป้อนเฉพาะค่าใช้จ่ายที่เกิดซ้ำตามที่คุณคาดหวัง เช่น backupนอกเซิร์ฟเวอร์หรือ API ภายนอก การประมาณการจะแบ่งจำนวนเงินรายเดือนของคุณตามจำนวนวันที่เรียกเก็บเงินที่เลือกโดยใช้เดือน 30 วัน การเรียกเก็บเงินบุคคลที่สามที่เกิดขึ้นจริงอาจแตกต่างกัน ป้อนศูนย์หากไม่มีการใช้

ค่าบริการเซิร์ฟเวอร์โดยประมาณ$20.10ค่าใช้จ่ายเพิ่มเติมตามสัดส่วน$0.00ยอดรวมโดยประมาณสำหรับวันที่เลือก$20.10

เมื่อเวิร์กโฟลว์ของคุณเก็บไฟล์หรือชุดข้อมูลขนาดใหญ่ไว้ในหน่วยความจำ ทำการแปลงที่หนักกว่า หรือรันงานที่มีความต้องการสูงหลายๆ งานร่วมกัน จำนวนการดำเนินการต่อเดือนที่สูงเพียงอย่างเดียวไม่ใช่เหตุผลที่จะเพิ่ม RAM เป็นสองเท่า ตรวจสอบข้อมูลการทำงานและการทับซ้อนของจุดสูงสุด

การเรียกโมเดลที่โฮสต์ API จะใช้ฮาร์ดแวร์การอนุมานของผู้ให้บริการโมเดล เลือก n8n VPS ของคุณสำหรับการเรียบเรียง เพย์โหลด และการทำงานพร้อมกัน การเรียกใช้โมเดลเฉพาะที่หรือบริการอนุมานแยกต่างหากเป็นการซื้อที่แตกต่างกันโดยมี RAM เฉพาะรุ่นและความต้องการด้านฮาร์ดแวร์

จะเกิดอะไรขึ้นหลังจากที่ฉันเลือก VPS

เลือกการกำหนดค่าเซิร์ฟเวอร์ Standard และระบบปฏิบัติการ Linux ในแค็ตตาล็อกโฮสติ้ง ปรับใช้ n8n ด้วย Docker เชื่อมต่อ HTTPS จากนั้นเพิ่มข้อมูลรับรองเวิร์กโฟลว์ของคุณ เส้นทางdeploymentบนหน้านี้ได้รับการself-managed เปิดรายการตรวจสอบการตั้งค่า.

ฉันสามารถย้ายเวิร์กโฟลว์ที่มีอยู่ไปยังการตั้งค่านี้ได้หรือไม่

ส่งออกและนำเข้าเวิร์กโฟลว์ เชื่อมต่อข้อมูลรับรองอีกครั้งเมื่อจำเป็น และสลับ webhooks และทริกเกอร์ที่กำหนดเวลาไว้อย่างจงใจ สำหรับการย้ายแบบเต็มอินสแตนซ์ ให้เก็บฐานข้อมูลและคีย์การเข้ารหัสดั้งเดิมไว้ เพื่อให้ข้อมูลประจำตัวที่บันทึกไว้ยังคงใช้งานได้ การเตรียมการย้ายถิ่นและการกู้คืน.

ฉันจำเป็นต้องมี Redis หรือแผงควบคุมแบบชำระเงินหรือไม่

การใช้งาน Docker อินสแตนซ์เดียวปกติสามารถทำงานได้โดยไม่ต้องมี Redis หรือแผงควบคุมโฮสติ้งแบบชำระเงิน เพิ่ม Redis ด้วยQueue Mode เมื่อคุณต้องการการดำเนินการตามworker เลือกแผงควบคุมเมื่อคุณสมบัติการจัดการมีประโยชน์สำหรับคุณเท่านั้น

ฉันจะทำให้ n8n VPS มีราคาต่ำโดยไม่ลดขนาดเซิร์ฟเวอร์ได้อย่างไร

เริ่มต้นด้วยการกำหนดค่าที่เล็กที่สุดที่เหมาะกับเพย์โหลดจริงและการทับซ้อนสูงสุด จากนั้นลดความต้องการที่หลีกเลี่ยงได้ก่อนอัปเกรด ตัดประวัติการดำเนินการที่คุณไม่ต้องการ การนำเข้าจำนวนมากเป็นชุด กำหนดการที่หนักหน่วง และใช้ AI API ที่โฮสต์เมื่อไม่จำเป็นต้องมีการอนุมานเฉพาะที่ วัดหน่วยความจำ CPU และดิสก์ในช่วงเวลาที่ยุ่งที่สุด เลื่อนระดับขึ้นเมื่อปริมาณงานที่ปรับให้เหมาะสมยังคงถึงขีดจำกัดที่ยั่งยืน
