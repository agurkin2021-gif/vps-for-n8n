INSTALACE POMOCÍ DOCKERU

Jak nainstalovat n8n na VPS

Nainstalujte n8n na VPS pomocí Docker Compose a PostgreSQL. Produkční nasazení zároveň vyžaduje trvalé uložení dat aplikace i databáze, stabilní hodnotu N8N_ENCRYPTION_KEY, veřejný název hostitele, HTTPS a správné nastavení webhooků. Před aktivací produkčních workflow všechny tyto součásti ověřte.

Partnerský odkaz: můžeme získat provizi z nákupů.

PŘEDPOKLADY

Připravte VPS před spuštěním n8n

Linux VPS

Použijte udržovanou distribuci Linuxu na serveru s dostatkem CPU, RAM a úložiště pro n8n, PostgreSQL, Docker a reverzní proxy.

DNS

Ještě před vystavením certifikátů TLS a zveřejněním URL webhooků nasměrujte doménu nebo subdoménu na VPS.

Docker Compose

Nainstalujte Docker Engine a plugin Compose pomocí balíčků podporovaných daným operačním systémem.

Firewall

Zpřístupněte jen nezbytné administrační a webové porty. PostgreSQL a interní aplikační služby ponechte neveřejné.

Instalujete na VPS, kde už běží jiné weby? n8n můžete přidat na server pod vlastní správou, pokud máte dostatek CPU, RAM a úložiště. Jestliže porty 80/443 již využívá Nginx, Apache, Caddy nebo jiná reverzní proxy, níže uvedený kontejner Caddy nespouštějte v nezměněné podobě: porty by byly v konfliktu. Novou subdoménu n8n raději nasměrujte přes stávající reverzní proxy a vhodnou privátní síť, nebo pro přesný příklad Compose použijte čisté VPS. Zachovejte ostatní weby i jejich nastavení TLS; příklad předpokládá volné porty 80/443.

PŘÍKLAD INSTALACE K ÚPRAVĚ

Instalace n8n na VPS pomocí Docker Compose

Podle tohoto příkladu můžete nasadit n8n na samostatně spravované VPS s Linuxem. n8n si instalujete a spravujete sami; server objednaný přes partnerský odkaz neobsahuje předinstalované n8n. Příklad kombinuje n8n, PostgreSQL, externí spouštěč úloh a Caddy pro HTTPS v privátní síti Docker Compose. Jde o konfigurační šablonu, nikoli potvrzení, že přesně toto nasazení bylo otestováno v živém provozu.

Chcete raději co nejrychlejší novou instalaci? n8n nabízí také oficiální instalaci Dockeru pomocí jediného příkazu. Před spuštěním si můžete instalační skript stáhnout a zkontrolovat příkazem curl -fsSL https://get.n8n.io -o get-n8n.sh a poté jej spustit příkazem sh get-n8n.sh. Tato varianta spustí první instanci se SQLite na lokální URL a zahrnuje služby sandboxu n8n Assistant. Jde o řešení, které není totožné s popsaným nasazením VPS s veřejným HTTPS a PostgreSQL. Kompletní oficiální sandboxová sestava potřebuje více RAM a CPU než úsporná instalace n8n (návod Compose uvádí alespoň 4 GB RAM / 2 vCPU). Pro produkční VPS dostupné z internetu pokračujte níže uvedenou ručně konfigurovanou sestavou.

1. Připravte Docker, DNS a přístup

Připojte se přes SSH s oprávněním sudo a nastavte DNS záznam typu A pro n8n.example.com na IPv4 adresu VPS. Na novém VPS s Ubuntu 22.04, 24.04 nebo 26.04 následující příkazy nainstalují Docker Engine a moderní plugin docker compose z oficiálního podepsaného apt repozitáře Dockeru:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Tento způsob instalace z repozitáře je doporučen pro produkční provoz v oficiálním návodu Dockeru pro Ubuntu. Na VPS, kde už běží jiné kontejnery nebo weby, Docker bez prověření konfigurace nepřeinstalovávejte ani neodstraňujte; nejprve zkontrolujte stávající instalaci a případné konflikty balíčků. Pro Debian nebo jinou distribuci použijte příslušný oficiální návod místo příkazů pro Ubuntu.

Nyní ověřte Docker, plugin Compose, DNS a pracovní adresář:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Pokud getent hosts nevrátí žádnou adresu nebo vrátí nesprávnou, opravte DNS před spuštěním Caddy. Ukázkový název n8n.example.com ve všech pokynech nahraďte skutečným názvem hostitele. Docker obvykle vyžaduje oprávnění root; pokud váš uživatel SSH nemůže následující příkazy docker compose spouštět přímo, přidejte před ně sudo. Přidání uživatele do skupiny docker mu uděluje oprávnění srovnatelná s rootem; na sdíleném serveru to nedělejte bez rozmyslu.

Před zapnutím firewallu ověřte, že zůstane dostupný skutečný administrační port SSH. Pro vystavení certifikátů a přístup k editoru povolte příchozí HTTP (80) a HTTPS (443). Porty kontejnerů zveřejněné Dockerem mohou obcházet některá pravidla UFW; proto zkontrolujte pokyny Dockeru k firewallu a zveřejněte pouze potřebné porty Caddy. Tento příklad Compose záměrně nezveřejňuje porty PostgreSQL (5432), n8n (5678) ani zprostředkovatele úloh (5679) do veřejného internetu.

2. Vytvořte proměnné prostředí a uchovejte klíč

V adresáři projektu vygenerujte tři různé náhodné hexadecimální hodnoty pomocí:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Vytvořte soubor s názvem .env podle následující šablony; každý výskyt řetězce REPLACE_WITH_RANDOM_HEX nahraďte jinou vygenerovanou hodnotou a upravte název hostitele i časové pásmo. Uvedená verze 2.42.5 byla ke dni 8. října 2026 uvedena jako stabilní vydánía slouží zde jako příklad konfigurace s uvedeným datem, nikoli jako záruka, že popsané nasazení bylo otestováno v živém provozu nebo že verze zůstane bezpečná i v budoucnu. Před instalací ověřte aktuální oficiální verze n8n a udržujte obraz n8n i obraz externího spouštěče úloh na téže ověřené verzi.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Nikdy neukládejte soubor .env do veřejného repozitáře. Šifrovací klíč a pokyny k obnově uchovávejte bezpečně mimo VPS. Po opětovném vytvoření kontejneru nebo migraci musí klíč zůstat stejný.

3. Vytvořte soubor compose.yaml pro novou instalaci

Ve stejném adresáři vytvořte compose.yaml. Příklad používá oficiální konvence proměnných prostředí n8n a cestu PostgreSQL 18 PGDATA zdokumentovanou v projektu n8n pro hosting:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Čtyři služby mají odlišné úlohy: PostgreSQL uchovává databázová data, n8n provádí workflow, n8n-runner provádí úlohy pomocí odpovídající verze a sdíleného autentizačního tokenu a Caddy zajišťuje veřejné HTTPS. Externí spouštěč úloh není totéž co režim fronty Redis. Hostitelské porty zveřejňuje pouze Caddy. Tato úsporná ukázka používá jedinou databázovou roli; pro důslednější oddělení oprávnění PostgreSQL prostudujte oficiální příklad nasazení n8n s PostgreSQL.

4. Vytvořte soubor Caddyfile pro HTTPS

Vytvořte soubor Caddyfile (s velkým C, bez přípony) vedle souboru compose.yaml. Všude nahraďte ukázkový název hostitele vlastní doménou:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy vystavuje a obnovuje veřejné certifikáty TLS, pokud se doména správně překládá a externí provoz dosáhne na porty 80/443. Nesměrujte DNS na localhost. Pokud Caddy nahradíte jinou reverzní proxy, předávejte původní hlavičky hostitele, protokolu a adresy klienta a upravte N8N_PROXY_HOPS podle skutečného počtu důvěryhodných proxy serverů na cestě.

5. Spusťte kontejnery a vyzkoušejte přístup zvenčí

V adresáři projektu spusťte následující příkazy po uložení souborů .env, compose.yaml a Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Poslední příkaz zkontroluje veřejný HTTPS koncový bod pro kontrolu stavu. Pokud se certifikát dosud vystavuje, zkontrolujte logy Caddy, DNS a porty, než dojdete k závěru, že n8n nefunguje. Otevřete https://n8n.example.com, okamžitě vytvořte první účet vlastníka a zapněte vhodnou ochranu přihlašování. Ověřte také skutečné provedení workflow, nejen načtení editoru:

  1. V editoru vytvořte workflow se spouštěčem Webhook a nastavte možnost HTTP Method na GETzvolte pole Path vps-checka nastavte možnost Respond na Immediately. Workflow uložte.
  2. Klikněte na Listen for Test Event, zkopírujte úplnou Test URL zobrazenou v n8n a na jiném zařízení spusťte curl -i 'PASTE_TEST_URL_HERE' se zkopírovanou URL. Očekávejte úspěšnou odpověď HTTP a příchozí událost v editoru n8n. Testovací URL funguje pouze po dobu, kdy n8n naslouchá testovací události.
  3. Publikujte workflow, přepněte uzel na jeho Production URL, zkopírujte ji a spusťte curl -i 'PASTE_PRODUCTION_URL_HERE' znovu. Provedení workflow ověřte na kartě Executions . Produkční požadavky webhooků vyžadují publikované workflow a jejich data se nezobrazují v testovacím zobrazení editoru.

Jde o záměrně jednoduchý test bez autentizace: nikdy do něj neposílejte tajné údaje. Po dokončení testu workflow zrušte publikování nebo je smažte. Před použitím veřejného endpointu se skutečnými daty nastavte autentizaci webhooku či omezení přístupu podle IP. Viz oficiální dokumentace pro testovací a produkční webhooky.

6. Před změnou pevně nastavených verzí vytvořte zálohu

Uložte obnovitelnou zálohu PostgreSQL a a trvalý datový svazek n8n spolu se souborem .env, šifrovacím klíčem a potřebnými externími soubory do úložiště mimo tento server. Obnovu ověřte podle průvodce zálohováním a obnovou před aktualizací produkční instance. Příklad příkazů:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Pevně nastavenou verzi N8N_VERSION měňte až po přečtení poznámek k vydání; obrazy n8n i spouštěče úloh musíte aktualizovat společně. Během běžné údržby nespouštějte docker compose down -v protože tento příkaz odstraní pojmenované datové svazky. Přechod na jinou hlavní verzi PostgreSQL vyžaduje upgrade databáze nebo plán zálohování a obnovy; pouhá výměna obrazu Postgres 18 za jinou hlavní verzi nepředstavuje automatickou migraci.

Oficiální zdroje: návod k Docker Compose pro n8n, konfigurace reverzní proxy a webhooků n8n a dokumentace nasazení PostgreSQL. Nepředpokládají se žádné výkonnostní benchmarky infrastruktury ani předinstalované funkce konkrétního poskytovatele.

KONFIGURACE

Pečlivě nastavte tajné údaje a veřejné adresy URL

Šifrovací klíč

Před uložením produkčních přihlašovacích údajů nastavte silný šifrovací klíč n8n a bezpečně jej uchovávejte. Stejný klíč budete potřebovat při obnově.

Přihlašovací údaje k PostgreSQL

Používejte vyhrazené databázové přihlašovací údaje a hesla neukládejte do veřejných repozitářů.

Veřejný název hostitele

Nastavte skutečný veřejný název hostitele a základní HTTPS adresu místo interní adresy kontejneru.

Adresa URL webhooku

Nastavte N8N_WEBHOOK_URL na veřejně dostupnou základní HTTPS adresu a nastavte N8N_PROXY_HOPS=1 pokud používáte jednu důvěryhodnou reverzní proxy. WEBHOOK_URL je od verze n8n 2.35.0 zastaralý alias; nepřebírejte jej ze starších návodů.

HTTPS A REVERZNÍ PROXY

Zpřístupněte veřejnou adresu n8n přes HTTPS

Reverzní proxy

Nginx, Caddy nebo Traefik použijte jako veřejný vstupní bod a požadavky přeposílejte interní službě n8n.

TLS

Pro veřejný název hostitele vystavte platný certifikát a přesměrujte HTTP na HTTPS.

Přeposlané hlavičky

Reverzní proxy musí předávat název hostitele, protokol a údaje o klientovi, které n8n potřebuje, a musí být nastaven správný počet důvěryhodných proxy serverů.

Ověření webhooku

Vyvolejte webhook zvenčí VPS a ověřte, že n8n vytváří veřejně dostupnou HTTPS adresu.

Návod na zálohování a obnovu

ČASTÉ PROBLÉMY

Proč instalace n8n přes Docker funguje lokálně, ale selhává v produkci

Nesprávná adresa webhooku

URL pro zpětná volání míří na localhost, HTTP nebo interní název hostitele místo veřejné HTTPS adresy.

Chybějící trvalé úložiště

Po opětovném vytvoření kontejneru zmizí stav aplikace nebo databáze.

Ztracený šifrovací klíč

Po novém nasazení jsou uložené přihlašovací údaje nepoužitelné, protože instance používá jiný klíč.

Veřejně zpřístupněný databázový port

PostgreSQL je zbytečně vystavené internetu, přestože k němu potřebuje přistupovat pouze n8n.

Ověřte koncový bod n8n pro kontrolu stavu

Ve výše uvedené konfiguraci Compose se port 5678 na hostiteli nezveřejňuje. Veřejný endpoint zkontrolujte příkazem curl -fsS https://n8n.example.com/healthz po nahrazení ukázkového názvu hostitele. Pokud HTTPS nebo databáze nejsou připravené, použijte také docker compose ps a logy jednotlivých služeb.

Používejte pevně určené verze aplikace

Nepovažujte automatické přebírání nejnovějších obrazů bez kontroly za strategii údržby. Poznamenejte si používanou verzi n8n, čtěte poznámky k vydání a před změnou verze vytvářejte zálohu.

Neměňte hlavní verzi PostgreSQL prostou výměnou obrazu

Pouhá změna hlavní verze v označení obrazu PostgreSQL může způsobit nekompatibilitu existujícího datového adresáře. Místo předpokladu, že vytvoření nového kontejneru provede migraci, vytvořte zálohu a postupujte podle příslušného postupu upgradu databáze.

Instalace n8n pomocí Dockeru: časté dotazy

Vyžaduje n8n při použití Dockeru PostgreSQL?

Ne. Docker nevyžaduje PostgreSQL a malá nasazení mohou používat SQLite. Pro produkční VPS však PostgreSQL poskytuje robustnější databázový základ a umožňuje pozdější škálování pomocí režimu fronty.

Proč uchovávat trvalý svazek n8n, když jsou data v PostgreSQL?

Trvalý adresář n8n může obsahovat důležitý stav a konfiguraci instance. Uchovávejte jej podle architektury nasazení; nepředpokládejte, že samotná databáze postačuje k obnově.

Proč můj webhook zobrazuje localhost?

Interní adresa kontejneru se liší od veřejné adresy. Nastavte externí název hostitele, protokol a URL webhooku a zajistěte, že reverzní proxy předává potřebné hlavičky.

Měl by být port 5678 veřejný?

Při běžném produkčním nasazení přes reverzní proxy zpřístupněte HTTPS na proxy a aplikační port n8n ponechte interní, pokud nemáte konkrétní provozní důvod k jinému řešení.

Potřebuji Redis?

Ne při standardním nasazení Dockeru s jedinou instancí. Redis potřebujete až při vědomém přechodu na režim fronty a workery.

Jsou externí spouštěče úloh n8n totéž co workery režimu fronty?

Ne. Externí spouštěče úloh provádějí podporovaný kód úloh odděleně od hlavního procesu n8n a používají sdílený autentizační token. Režim fronty Redis rozděluje spouštění workflow a má vlastní infrastrukturní požadavky. Tento příklad používá externí spouštěč úloh, nikoli režim fronty Redis. Verze obrazu spouštěče musí odpovídat verzi n8n.
