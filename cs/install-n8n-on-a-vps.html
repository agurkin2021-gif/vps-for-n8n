INSTALACE DOCKERU

Jak nainstalovat n8n na VPS

Nainstalujte n8n na VPS pomocí Docker Skládání a PostgreSQL. Produkční nasazení také potřebuje trvalá data aplikací a databází, stabilní N8N_ENCRYPTION_KEY, veřejný název hostitele, HTTPS a správnou konfiguraci webhooku. Před aktivací produkčních pracovních postupů tyto kusy ověřte.

PŘEDPOKLADY

Připravte si VPS před zahájením n8n

Linux VPS

Použijte udržovaný server Linux o velikosti pro n8n, PostgreSQL, Docker a reverzní proxy.

DNS

Před vydáním certifikátů TLS a publikováním adres URL webhooku nasměrujte doménu nebo subdoménu na VPS.

Docker Compose

Nainstalujte Docker Engine a zásuvný modul Compose pomocí podporovaných balíčků pro operační systém.

Firewall

Vystavte pouze požadované administrační a webové porty. Udržujte PostgreSQL a interní aplikační služby soukromé.

Instalace na VPS, který již hostuje webové stránky? Můžete přidat n8n na server, který ovládáte, pokud to CPU, RAM a úložiště umožňují. Pokud však Nginx, Apache, Caddy nebo jiný reverzní proxy již vlastní porty 80/443, ne spusťte níže uvedený příklad Caddy kontejner beze změny: porty budou v konfliktu. Místo toho nasměrujte novou subdoménu n8n přes svůj stávající reverzní proxy s vhodnou privátní sítí nebo použijte čistý VPS pro přesný příklad Compose. Zachovat ostatní stránky a jejich TLS konfiguraci; příklad předpokládá, že jsou dostupné porty 80/443.

INSTALACE KOPÍROVÁNÍ A PŘIZPŮSOBENÍ

Nainstalujte n8n na svůj VPS pomocí Docker Vytvořit

Použijte tento příklad k vytvoření nasazení n8n na a samostatně spravovaný Linux VPS. n8n si instalujete a udržujete sami; výběr serveru prostřednictvím našeho partnera nezahrnuje předinstalovanou instanci n8n. Příklad kombinuje n8n, PostgreSQL, externího spouštěče úloh a Caddy HTTPS v soukromé síti pro vytváření zpráv. Jedná se o konfigurační šablonu, nejde o tvrzení o nasazení v reálném čase.

Chcete místo toho nejrychlejší novou instalaci? n8n také poskytuje oficiální jednořádkové nastavení Docker. Jeho skript si můžete stáhnout a zkontrolovat pomocí curl -fsSL https://get.n8n.io -o get-n8n.sh před běháním sh get-n8n.sh. Tato možnost spustí úvodní instanci s SQLite na místní adrese URL a zahrnuje n8n služby Asistent sandbox; to je ne stejný jako toto veřejné-HTTPS, PostgreSQL-podporované VPS nasazení. Oficiální úplný sandboxový zásobník potřebuje více RAM a CPU než štíhlá instalace n8n (jeho průvodce Compose specifikuje alespoň 4 GB RAM / 2 vCPU). Pro produkci s internetem VPS pokračujte ručně nakonfigurovaným zásobníkem níže.

1. Připravte Docker, DNS a získejte přístup

Připojte se přes SSH s přístupem sudo a přejděte na DNS Záznam pro n8n.example.com na vaši VPS IPv4 adresu. Na a čerstvé Ubuntu 22.04, 24.04 nebo 26.04 VPS, následující příkazy nainstalujte Docker Engine and the modern docker compose plugin od Docker podepsaný úředníkem apt úložiště:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Toto je produkčně orientovaná metoda úložiště v oficiální instalační příručce Docker Ubuntu. Neinstalujte naslepo ani neodstraňujte Docker na již běžících kontejnerech nebo jiných webových stránkách VPS; nejprve zkontrolujte existující instalaci a možné konflikty balíčků. Pro Debian nebo jinou distribuci použijte namísto příkazů Ubuntu odpovídající oficiální pokyny specifické pro OS.

Nyní ověřte samotný Docker, plugin Compose, DNS a pracovní adresář:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Pokud getent hosts nevrací žádnou nebo špatnou adresu, opravte svůj DNS před zahájením Caddy; nahradit n8n.example.com v této příručce s vaším skutečným názvem hostitele. Docker normálně vyžaduje oprávnění root: pokud váš uživatel SSH nemůže spustit novější docker compose příkazy přímo, předpona jim sudo. Přidání uživatele do docker group uděluje root-ekvivalentní přístup a nemělo by být prováděno náhodně na sdíleném serveru.

Před aktivací brány firewall udržujte svůj skutečný administrační port SSH dostupný. Povolit příchozí HTTP (80) a HTTPS (443) pro vydávání certifikátů a editor. Kontejnerové porty publikované Docker mohou obejít některá pravidla UFW, proto si přečtěte pokyny k firewallu Docker a publikujte pouze zamýšlené porty Caddy. Tento příklad Compose to záměrně dělá ne publikovat PostgreSQL (5432), n8n (5678) nebo task-runner broker (5679) na veřejný internet.

2. Vytvořte hodnoty prostředí a uchovejte klíč

Z adresáře projektu vygenerujte tři jiný náhodné hexadecimální hodnoty s:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Vytvořte soubor s názvem .env pomocí níže uvedené šablony vyměňte všechny REPLACE_WITH_RANDOM_HEX s jinou vygenerovanou hodnotou a změňte název hostitele a časové pásmo. Zobrazené 2.42.5 tag je stabilní vydání uvedené na 8 říjen 2026, zde použitý jako příklad datované konfigurace, není zárukou otestovaného nasazení nebo budoucí bezpečnosti. Před instalací zkontrolujte aktuální oficiální vydání n8n a poté ponechejte n8n a jeho image-runner na stejné ověřené verzi.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Nikdy se nezavazujte .env do veřejného úložiště. Uložte šifrovací klíč a pokyny k obnově bezpečně mimo VPS. Klíč musí zůstat stejný po rekreaci nebo migraci kontejneru.

3. Pro novou instalaci napište compose.yaml

Ve stejném adresáři vytvořte compose.yaml. Příklad používá oficiální konvence n8n proměnných prostředí a PostgreSQL 18 PGDATA cesta dokumentovaná hostovacím projektem n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Tyto čtyři služby mají odlišné role: PostgreSQL ukládá stav databáze, n8n spouští pracovní postupy, n8n-runner provádí běžné úlohy s odpovídající verzí a sdíleným ověřovacím tokenem a Caddy zpracovává veřejné HTTPS. Externí běžec úkolu není režim fronty Redis. Pouze Caddy zveřejňuje hostitelské porty. Tato štíhlá ilustrace používá pro nastavení jedinou databázovou roli; pro silnější oddělení práv PostgreSQL se podívejte na oficiální příklad nasazení n8n PostgreSQL.

4. Vytvořte HTTPS Caddyfile

Vytvořte soubor Caddyfile (velké C, bez přípony) vedle compose.yaml. Nahraďte vzorový název hostitele všude svým vlastním DNS názvem:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy požaduje a obnovuje veřejné certifikáty TLS, když se doména vyřeší správně a externí provoz může dosáhnout portů 80/443. Neukazujte na DNS localhost. Pokud nahradíte Caddy jiným reverzním proxy, přepošlete původní hlavičky hostitele, protokolu a adresy klienta a upravte N8N_PROXY_HOPS pro skutečný počet důvěryhodných proxy skoků.

5. Spusťte nádoby a otestujte je zvenčí

Po uložení spusťte tyto příkazy z adresáře projektu .env, compose.yaml a Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Poslední příkaz zkontroluje veřejný HTTPS zdravotní koncový bod. Pokud stále čeká na vydání certifikátu, prohlédněte si protokoly Caddy a DNS/porty, než dojde k závěru, že n8n je porušen. Otevřít https://n8n.example.com, okamžitě vytvořte účet prvního vlastníka a povolte vhodnou ochranu přihlášení. Potvrďte, že instance skutečně provádí pracovní postup, nejen že editor načte:

  1. V editoru vytvořte pracovní postup s a Webhook spoušť. Set HTTP Metoda do GET, vyberte Path vps-checka nastavte Odpovězte do Okamžitě. Uložte pracovní postup.
  2. Klikněte Poslouchejte testovací událost, zkopírujte celý Testovací URL zobrazeno v n8n a spustit z jiného zařízení curl -i 'PASTE_TEST_URL_HERE' se zkopírovanou adresou URL. Očekávejte úspěšnou odpověď HTTP a příchozí událost se objeví v editoru n8n. Testovací adresy URL fungují pouze tehdy, když n8n naslouchá události.
  3. Publikovat workflow, přepněte uzel na jeho Produkční URL, zkopírujte a spusťte curl -i 'PASTE_PRODUCTION_URL_HERE' znovu. Potvrďte provedení v rámci pracovního postupu Popravy tab. Požadavky produkčního webhooku vyžadují zveřejnění pracovního postupu a nezobrazují se v testovacím zobrazení editoru.

Toto je záměrně jednoduchý, neověřený kouřový test: nikdy do něj neposílejte tajemství. Před použitím veřejného koncového bodu pro skutečná data zrušte publikování/smažte jej po testování nebo nakonfigurujte omezení ověřování Webhooku/IP. Podívejte se na oficiální testovací/produkční dokumentaci Webhooku.

6. Před změnou připnutých verzí zálohujte

Uložte obnovitelný výpis PostgreSQL a trvalý objem dat n8n, .env/šifrovací klíč a požadované externí soubory k ukládání mimo tento server. Ověřte obnovení pomocí průvodce zálohováním a obnovou před aktualizací výroby. Příklad příkazů:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Změňte připnuté N8N_VERSION pouze po přečtení poznámek k vydání; jak n8n, tak obrázky běžce musí postupovat společně. Neutíkej docker compose down -v během běžné údržby, protože se tím odstraní pojmenované datové svazky. PostgreSQL změny hlavní verze vyžadují upgrade databáze nebo plán výpisu/obnovy; nahrazení obrázku Postgres 18 jiným hlavním tagem není automatická migrace.

Autoritativní odkazy: n8n Docker Průvodce sestavováním, n8n konfigurace reverzního proxy/webhooku a oficiální PostgreSQL poznámky k nasazení. Nepředpokládá se žádný benchmark infrastruktury nebo předinstalovaná funkce specifická pro poskytovatele.

KONFIGURACE

Záměrně nastavujte tajná tajemství a veřejné adresy URL

Šifrovací klíč

Před uložením produkčních pověření nastavte a uchovejte silný šifrovací klíč n8n. Po obnovení je vyžadován stejný klíč.

Přihlašovací údaje k PostgreSQL

Používejte vyhrazené přihlašovací údaje k databázi a udržujte hesla mimo kontrolu veřejných zdrojů.

Veřejný název hostitele

Nakonfigurujte skutečný externí název hostitele a původ HTTPS spíše než adresu interního kontejneru.

Adresa URL webhooku

Set N8N_WEBHOOK_URL na veřejně dostupnou HTTPS základní URL a nastavte N8N_PROXY_HOPS=1 když existuje jeden důvěryhodný reverzní proxy. WEBHOOK_URL je zastaralý alias v n8n 2.35.0 a pozdějších; vyvarujte se kopírování ze starších výukových programů.

n8n a PostgreSQL trvejte samostatně

n8n údaje

Připojte trvalé úložiště pro datový adresář n8n, aby stav kritické instance přežil obnovení kontejneru.

PostgreSQL údaje

Oprávnění k souboru

Zajistěte, aby připojené cesty mohl zapisovat zamýšlený uživatel kontejneru, aniž by bylo úložiště hostitele zbytečně tolerantní.

Soubory pracovního postupu

Zachovejte všechny připojené soubory nebo úložiště binárních dat, na kterých závisí produkční pracovní postupy.

BĚŽNÉ PORUCHY

Proč instalace n8n Docker funguje lokálně, ale selže ve výrobě

Nesprávná adresa URL webhooku

Zpětná volání ukazují na localhost, HTTP nebo interní název hostitele namísto veřejného původu HTTPS.

Chybí vytrvalost

Stav aplikace nebo databáze zmizí, když je kontejner znovu vytvořen.

Ztracený šifrovací klíč

Uložená pověření se po opětovném sestavení stanou nepoužitelnými, protože nová instance používá jiný klíč.

Port veřejné databáze

PostgreSQL je zbytečně vystaven, i když k němu potřebuje dosáhnout pouze n8n.

OVĚŘENÍ PO NASTAVENÍ

Před připojením skutečných pracovních postupů ověřte stav

Zkontrolujte stav kontejneru

Spustit docker compose ps a ujistěte se, že aplikace a databázové služby běží podle očekávání, než budete nasazení považovat za zdravé.

Zkontrolujte koncový bod zdraví n8n

Ve výše uvedeném příkladu Compose není port 5678 publikován na hostiteli. Zkontrolujte veřejný koncový bod pomocí curl -fsS https://n8n.example.com/healthz po změně názvu hostitele a použijte docker compose ps plus servisní protokoly, pokud HTTPS nebo databáze není připravena.

Připnout verze aplikace

Instalace n8n s Docker: běžné otázky

Potřebuje n8n PostgreSQL při použití Docker?

Docker nevyžaduje PostgreSQL a malá nasazení mohou použít SQLite. Pro produkčně orientované nasazení VPS poskytuje PostgreSQL silnější databázový základ a podporuje pozdější škálování v režimu fronty.

Proč udržovat trvalý objem n8n, když PostgreSQL ukládá data?

Trvalý adresář n8n může obsahovat důležitý stav instance a konfiguraci. Zachovejte ji podle návrhu nasazení namísto toho, abyste předpokládali, že databáze je jediným aktivem obnovy.

Proč můj webhook zobrazuje localhost?

Adresa interního kontejneru se liší od veřejného původu. Nakonfigurujte externí název hostitele, protokol a adresu URL webhooku a zajistěte, aby reverzní proxy předal požadované hlavičky.

Měl by být port 5678 veřejný?

Pro normální produkční nasazení za reverzní proxy vystavte HTTPS na proxy a ponechte aplikační port n8n interní, pokud neexistuje konkrétní provozní důvod, proč tomu tak není.

Potřebuji Redis?

Ne pro standardní jednoinstanční Docker nasazení. Redis se stane relevantním, když záměrně přejdete do režimu fronty a pracovníků.

Jsou externí spouštěči úloh n8n stejní jako pracovníci v režimu fronty?

Ne. Externí spouštěči úloh spouštějí podporovaný kód úlohy odděleně od hlavního procesu n8n a používají sdílený ověřovací token. Redis režim fronty distribuuje provádění pracovních postupů a má své vlastní požadavky na infrastrukturu. Tento příklad ukazuje externího spouštěče úloh, nikoli režim fronty Redis.
