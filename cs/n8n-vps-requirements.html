Požadavky n8n na VPS

Při výběru VPS pro n8n vycházejte z náročnosti workflow, nikoli z jediné univerzální minimální konfigurace. Pečlivě dimenzované VPS s 1 vCPU / 1 GB RAM zvládne jednoduché nepřetržitě běžící automatizace, zatímco 2 vCPU / 4 GB RAM představují praktický výchozí bod pro n8n s PostgreSQL a HTTPS. Rozsáhlá data, souběžná spuštění a lokální zpracování vyžadují větší výkonovou rezervu. Před výběrem změřte skutečnou spotřebu prostředků.

MINIMUM VERSUS PRAKTICKÁ KAPACITA

Existuje jedna oficiální minimální konfigurace VPS pro n8n?

Ne pro všechny typy zátěže. Oficiální příklady předpokladů n8n popisují ilustrativní nasazení OEM a výslovně upozorňují, že požadavky se liší podle zátěže. Nezaručují, že libovolná konkrétní kombinace CPU, RAM a disku bude stačit pro produkční automatizace.

n8n uvádí, že nečinná instance může spotřebovávat poměrně málo paměti. Uzel Code, velký binární soubor nebo souběžná spuštění však mohou spotřebu RAM prudce zvýšit. Samostatně započítejte operační systém, Docker, PostgreSQL a nástroje pro zálohování a monitoring.

Technické zdroje: ilustrativní předpoklady n8n a oficiální návod ke spotřebě paměti. Čtyři výše uvedené varianty jsou skutečně dostupné konfigurace serveru, nikoli předepsané oficiální požadavky n8n.

RAM a CPU

Co ve skutečnosti spotřebovává zdroje serveru

Souběžná spuštění

Několik současně běžících workflow může být náročnějších než velký počet workflow pouze uložených v n8n. Sledujte špičkovou spotřebu paměti a prodlevu při souběhu.

Velikost zpracovávaných dat

Rozsáhlé objekty JSON, soubory a binární data zvyšují nároky na paměť. I několik datově náročných spuštění může vyžadovat více RAM než mnoho jednoduchých automatizací přes API.

Uzly náročné na CPU

Uzel Code, transformace a další výpočetně náročné kroky mohou dlouhodobě zatěžovat CPU. Více jader pomůže, když několik skutečně prováděných úloh současně potřebuje výpočetní výkon.

Související služby

Operační systém, PostgreSQL, reverzní proxy, monitoring a Docker také spotřebovávají prostředky. Dimenzujte celou sestavu, nikoli jen proces n8n.

MĚŘTE DŘÍVE, NEŽ NAVÝŠÍTE VÝKON

Jak poznat, zda n8n potřebuje více RAM, CPU nebo místa na disku

Spusťte největší očekávané workflow a realistickou špičku se souběžnými úlohami. Poté zkontrolujte stav serveru a logy spuštění v n8n. Samotný počet workflow uložených v editoru není spolehlivým měřítkem potřebné kapacity.

Paměť / OOM

Zkontrolujte docker stats --no-stream a free -h. Pokud paměť nestačí, nejprve omezte objem objektů JSON či binárních dat, rozdělte velké importy do dávek a vyhněte se krokům Code s vysokou spotřebou RAM. Chybu nedostatku paměti v JavaScriptu nemusí vyřešit přidání dalších vCPU.

CPU / souběžnost spuštění

Změřte, zda CPU zůstává dlouhodobě vytížené transformacemi, nebo zda úlohy pouze čekají na odpovědi externích API. V běžném režimu před přechodem na workery zvažte podporované nastavení limitu souběžných produkčních spuštění. Vyšší výkon CPU nezrychlí externí API s limitem počtu požadavků.

Úložiště / databáze

Zkontrolujte df -h, velikost databáze a uchovávanou historii spuštění. Sledujte růst využití disku a pomalé databázové operace. Než koupíte větší disk, vědomě nastavte dobu uchovávání historie. Zálohy pro obnovu udržujte mimo server.

Řiďte se oficiálním návodem n8n k souběžnosti a vysvětlením benchmarků. Jakýkoli údaj o počtu současně běžících workflow je bez znalosti objemu dat a latence API pouze odhadem.

DATABÁZE A ÚLOŽIŠTĚ

SQLite, PostgreSQL a trvalé ukládání dat

SQLite

SQLite se hodí pro malé instalace s jednou instancí a pro testování. S růstem produkční zátěže a souběžnosti se volba databáze stává důležitým provozním rozhodnutím, nikoli jen detailem instalace.

PostgreSQL

Pro produkční VPS je PostgreSQL robustnějším základem databáze. Vyhraďte mu odpovídající RAM, CPU i disk a sledujte růst dat.

Trvalá data .n8n

PostgreSQL není jediná složka, kterou je nutné trvale uchovávat. Zálohujte také datový adresář n8n a chraňte šifrovací klíč nezbytný k obnovení šifrovaných přihlašovacích údajů.

Růst využití disku

Historie spuštění, binární data, databázové soubory a logy mohou postupně růst. Nastavení doby uchovávání i zálohování mimo server přímo ovlivňují potřebnou kapacitu.

DISKOVÁ KAPACITA

Před objednáním odhadněte místo pro historii spuštění n8n

Začněte s počet uložených spuštění za den × průměrný počet uložených bajtů na jedno spuštění × počet dní uchování. Například 500 uložených spuštění denně × 200 KB na spuštění × 14 dní = 1.4 GB dat historie spuštění bez režie databáze. Hodnota 200 KB je pouze ilustrativní předpoklad, nikoli benchmark n8n.

Vyhraďte místo také pro operační systém, vrstvy obrazů Dockeru, databázové indexy, binární soubory, logy aplikace, aktualizace a dočasné soubory. Zálohy mimo server potřebují vlastní kapacitu. Disk s 10 GB může pro úspornou sestavu stačit, ale pro uchovávané soubory poskytuje mnohem méně místa než disk s 40 nebo 80 GB.

n8n popisuje výchozí promazávání historie spuštění podle stáří (336 hodin / 14 dní) nebo počtu (10,000 spuštění), s určitými výjimkami. Před změnou zkontrolujte skutečné nastavení a ověřte, která data se uchovávají. SQLite může uvolněné místo opětovně využít, aniž by se velikost databázového souboru automaticky zmenšila.

Zdroj: dokumentace n8n ke správě a promazávání dat spuštění. Potřebná kapacita disku se odvíjí od skutečné velikosti ukládaných dat, nikoli pouze od počtu uzlů.

Docker a režie produkčního provozu

Linux VPS

Používejte udržovanou distribuci Linuxu a kromě aplikací počítejte také s prostředky pro operační systém a bezpečnostní aktualizace.

Docker a Compose

Nasazení v kontejnerech usnadňuje opakované vytváření prostředí, ale neodstraňuje jejich vlastní nároky na prostředky. Data n8n a databáze uchovávejte mimo dočasné kontejnery.

HTTPS a reverzní proxy

Veřejné webhooky vyžadují stabilní název hostitele a správně nastavené HTTPS. Do produkční architektury zahrňte reverzní proxy a vrstvu TLS.

Monitoring a zálohy

Sledujte RAM, CPU, využití disku a růst databáze. Obnovitelné zálohy uchovávejte mimo VPS a obnovu pravidelně testujte; samotný snapshot nemusí stačit.

SOUBĚŽNOST

Kdy už nestačí jen větší VPS

Navýšení výkonu jednoho serveru je vhodné, dokud jedna instance zvládá zátěž bez problémů. Pokud trvalá souběžná zátěž začíná způsobovat konflikty o prostředky, zvažte režim fronty a workery. Režim fronty vyžaduje Redis, PostgreSQL a jeden nebo více procesů workerů. Naplánujte RAM a CPU pro každou součást, nejen pro n8n. n8n také dokumentuje omezení souborového úložiště binárních dat v režimu fronty; před přechodem ověřte kompatibilní způsob ukládání dat.

ZÁKLADNÍ TARIF A VÝKON DISKU

Jak využít základní VPS s 1 GB RAM

1 GB RAM

Jde o skutečný plnohodnotný tarif VPS, nikoli o produkt určený jen k testování. Může se hodit pro jednoduché nepřetržité automatizace a převážně postupná volání API, pokud spotřeba paměti, disku a souběh úloh zůstávají v naměřených mezích. Poskytuje však jen malou rezervu pro PostgreSQL na stejném serveru, velké objemy dat či náročné paralelní úlohy.

2 GB RAM

Konfigurace s 2 GB RAM je bezpečnějším výchozím bodem pro nenáročnou instanci, pokud chcete více místa pro operační systém, Docker a krátké špičky, ale nepotřebujete hned větší produkční sestavu.

SSD versus NVMe

Běžné SSD stačí pro jednoduché automatizace. NVMe je užitečnější, pokud PostgreSQL a historie spuštění často čtou a zapisují data nebo pokud naměřené prodlevy disku ovlivňují výkon workflow.

Před navýšením výkonu měřte

Sledujte CPU, RAM, růst obsazení disku a délku spuštění při nejvyšším souběhu. Podle toho určete, zda je úzkým hrdlem výkon CPU, paměť nebo úložiště, místo abyste předpokládali, že větší VPS vyřeší každé zpomalení.

Časté dotazy

Požadavky n8n na VPS: časté dotazy

Kolik RAM potřebuje n8n?

Jedna univerzální hodnota neexistuje. Potřeba RAM závisí na souběžnosti, objemu dat, průběhu spuštění a doplňkových službách na VPS. Server se 4 GB RAM představuje praktický výchozí bod pro menší produkční provoz, nikoli zaručený požadavek pro každé workflow.

Kolik jader CPU bych měl použít?

Nenáročná workflow mohou začít s menší kapacitou CPU. Více jader přidejte, pokud monitorování ukazuje trvale vysoké vytížení CPU nebo zpomalování při souběžných spuštěních; nevybírejte výkon pouze podle počtu workflow.

Vyžaduje n8n PostgreSQL?

Malé instalace mohou používat SQLite, ale s rostoucími provozními nároky a souběžností bývá pro produkci vhodnější PostgreSQL.

Kdy je vyžadován Redis?

Redis souvisí s režimem fronty. Běžná instalace s jedinou instancí jej nepotřebuje jen proto, že běží na VPS.

Kolik místa na disku mám vyhradit?

Potřebná kapacita disku závisí na růstu PostgreSQL, uchovávané historii spuštění, binárních datech, logách, vrstvách kontejnerů a zálohách. Sledujte růst a ponechte si rezervu; neřiďte se jednou univerzální hodnotou.

Mohu spouštět n8n nepřetržitě na 1 GB VPS?

Ano, pokud to skutečná zátěž umožňuje. VPS s 1 GB RAM je plnohodnotný server pro jednoduché, převážně postupné automatizace, ale rezerva paměti je omezená. Nepředpokládejte, že se na něj nutně vejdou PostgreSQL na stejném serveru, úlohy s velkými binárními soubory nebo několik rozsáhlých souběžných spuštění. Sledujte využití prostředků a podle naměřené zátěže případně navyšte konfiguraci.

Je pro produkční n8n vhodnější 2 GB, nebo 4 GB RAM?

Dva gigabajty poskytují větší rezervu než úsporná instance s 1 GB. Konfigurace se 4 GB představuje praktický výchozí bod pro n8n spolu s PostgreSQL a HTTPS. Neexistuje univerzální zaručené minimum pro produkci: skutečné nároky určují složitost workflow, souběh ve špičce, nastavení kontejnerů a objem uchovávaných dat.

Potřebují AI workflow v n8n GPU?

Ne, pokud n8n pouze volá API externího modelu: inferenci zajišťuje poskytovatel modelu, zatímco VPS zpracovává workflow, data a souběžné požadavky. Provozování inferenčních modelů lokálně je samostatné hardwarové rozhodnutí a může vyžadovat výrazně více RAM i odpovídající GPU.

Co způsobuje chyby nedostatku paměti v n8n?

Častými příčinami jsou velké objekty JSON nebo binární data, paměťově náročné operace v uzlech Code a souběžná spuštění. Prověřte logy a maximální využití paměti. Poté omezte množství dat uchovávaných během jednoho spuštění nebo přidejte RAM podle naměřené příčiny.
