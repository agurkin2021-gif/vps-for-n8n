Požadavky n8n na VPS

U požadavků n8n VPS začněte se svou pracovní zátěží spíše než s univerzálním minimem hardwaru. Pečlivě dimenzovaný 1 vCPU / 1 GB VPS může provozovat malé stále zapnuté automatizace, zatímco 2 vCPU / 4 GB RAM je praktická počáteční třída pro n8n s PostgreSQL a HTTPS. Velké užitečné zatížení, simultánní běhy a místní zpracování dat vyžadují větší prostor; před výběrem změřte skutečné použití.

MINIMÁLNÍ VS PRAKTICKÁ KAPACITA

Má n8n jednu oficiální minimální velikost VPS?

Ne pro každou pracovní zátěž. Oficiální příklady nezbytných požadavků n8n popisují ilustrativní nasazení OEM a výslovně upozorňují, že požadavky se liší podle pracovní zátěže. Tato dokumentace není univerzální zárukou, že jakýkoli konkrétní CPU, RAM nebo alokace disku bude podporovat automatizaci výroby.

n8n poznamenává, že nečinná instance může používat relativně málo paměti, ale uzel kódu, velké binární užitečné zatížení nebo současné provádění mohou požadavky na paměť prudce zvýšit. Rozpočet zvlášť pro operační systém, Docker, PostgreSQL a nástroje pro zálohování/monitorování.

Technické zdroje: ilustrativní předpoklady n8n a oficiální průvodce pamětí. Čtyři řádky výše jsou skutečné balíčky zdrojů, které lze zakoupit, nikoli předepsané oficiální požadavky n8n.

RAM a CPU

Co ve skutečnosti spotřebovává zdroje serveru

Souběžné popravy

Několik současně spuštěných pracovních postupů může mít větší význam než celkový počet pracovních postupů uložených v n8n. Sledujte špičky paměti a latenci provádění během překrývání.

Velikost užitečného zatížení

Velké objekty JSON, soubory a binární data zvyšují tlak na paměť. Několik málo datově náročných provedení může vyžadovat více RAM než mnoho lehkých API automatizací.

CPU-těžké uzly

Kód, transformace a další výpočetně náročné kroky mohou vytvořit trvalý tlak CPU. Více jader pomáhá, když skutečná provedení soutěží o výpočet.

Podpůrné služby

Operační systém, PostgreSQL, reverzní proxy, monitorování a Docker také potřebují zdroje. Velikost celého zásobníku, nejen proces n8n.

PŘED AKTUALIZACÍ MĚŘTE

Jak zjistit, zda n8n potřebuje více RAM, CPU nebo disk

Spusťte svůj největší očekávaný pracovní postup a realistický překrývající se shluk, poté prohlédněte server a n8n protokoly provádění. Počet pracovních postupů uložených v editoru není sám o sobě užitečným měřítkem kapacity.

Paměť / OOM

Zkontrolujte docker stats --no-stream a free -h. Pokud je paměť vyčerpána, nejprve snižte JSON nebo binární užitečné zatížení, dávkovejte velké importy a vyhněte se krokům s kódem zatěžujícím paměť. Chyba haldy JavaScriptu není nutně opravena přidáním vCPU.

CPU / souběžnost

Změřte, zda CPU zůstává během transformací zaneprázdněn nebo zda úlohy čekají pouze na externí API. V běžném režimu zvažte podporovaný limit souběžnosti výroby, než se škáluje na pracovníky. Zvýšení CPU nezrychlí externí API s omezenou sazbou.

Úložiště / databáze

Zkontrolujte df -h, velikost databáze a uchovávaná historie provádění. Sledujte růst disku a pomalé operace databáze. Před zaplacením většího disku schválně nastavte retenci; uchovávat obnovovací kopie mimo server.

Použijte návod k souběžnosti n8n a oficiální vysvětlení srovnávání. Jakýkoli počet souběžných pracovních postupů inzerovaných bez znalosti jejich užitečného zatížení a latence API je pouze odhad.

DATABÁZE A ULOŽENÍ

SQLite, PostgreSQL a trvalá data

SQLite

SQLite se vejde do malých jednoinstančních nasazení a testování. S rostoucím využitím a souběžností výroby se výběr databáze stává spíše provozním omezením než detailem instalace.

PostgreSQL

Pro produkčně orientovaný zásobník VPS poskytuje PostgreSQL silnější základ databáze. Rozpočtěte RAM, CPU a disk pro samotnou databázi a sledujte její růst.

Trvalá data .n8n

Nepovažujte PostgreSQL za jediné trvalé aktivum. Zachovejte datový adresář n8n a chraňte šifrovací klíč potřebný k obnovení zašifrovaných přihlašovacích údajů.

Růst disku

Historie provádění, binární data, databázové soubory a protokoly se mohou časem rozšiřovat. Nastavení uchovávání a zálohování mimo server přímo ovlivňují požadovanou kapacitu.

KAPACITA DISKU

Před objednáním odhadněte uložení historie provedení n8n

Začněte s uložená provedení za den × průměr uložených bajtů na provedení × dny uchování. Například 500 uložené exekuce za den × 200 KB každý × 14 dny = 1.4 GB příkladů provedení dat před režií databáze. Tento předpoklad 200 KB je ilustrativní, nikoli benchmark n8n.

Také alokujte disk pro OS, Docker obrazové vrstvy, databázové indexy, binární soubory, aplikační protokoly, upgrady a dočasné soubory. Zálohy mimo server potřebují vlastní kapacitu. Disk 10 GB může fungovat pro štíhlý zásobník, ale má mnohem méně místa pro uložené soubory než disk 40 nebo 80 GB.

n8n dokumentuje výchozí ořezávání provedení podle věku (336 hodin / 14 dnů) nebo počtu (10,000 provedení), s výjimkami. Zkontrolujte své skutečné nastavení a ověřte, co zůstalo zachováno, než je změníte. SQLite může znovu použít uvolněný prostor místo automatického zmenšování souboru.

Zdroj: n8n: správa dat provádění a prořezávání. Požadavky na disk závisí na pozorované velikosti uloženého užitečného zatížení, nikoli pouze na počtu uzlů.

SOUHLAS

Když větší VPS přestane být celou odpovědí

Vertikální škálování je vhodné, zatímco jedna instance zvládne pracovní zátěž čistě. Když trvalá paralelní poptávka vyvolává spory, vyhodnoťte režim fronty a pracovníky. Režim fronty zavádí Redis, PostgreSQL a jeden nebo více pracovních procesů; rozpočet RAM a CPU pro každou složku, nejen n8n. n8n také dokumentuje omezení ukládání binárních dat souborového systému v režimu fronty, takže před přepnutím ověřte kompatibilní návrh úložiště dat.

VSTUPNÍ ÚROVEŇ A SKLADOVÁNÍ I/O

Jak používat položku 1 GB VPS

1 GB RAM

Toto je skutečně funkční vrstva VPS, nikoli produkt určený pouze k testování. Může být vhodný pro malé automatizace a většinou sekvenční API práci, kdy udržujete paměť, využití disku a souběžné úlohy v naměřených mezích. Nabízí malý prostor pro PostgreSQL na stejném serveru, velké užitečné zatížení nebo náročné paralelní provádění.

2 GB RAM

Použijte 2 GB jako bezpečnější základ pro světelnou instanci, když chcete více místa pro operační systém, Docker a malé dávky bez okamžitého přechodu na zásobník produkční velikosti.

SSD vs. NVMe

Standard SSD je dostačující pro lehkou automatizaci. NVMe se stává užitečnějším, když PostgreSQL a historie provádění vytvářejí časté čtení a zápisy nebo když se v měřeném výkonu pracovního postupu projeví latence disku.

Před upgradem změřte

Použijte CPU, paměť, růst disku a dobu provádění pod vrcholovým překrytím, abyste se rozhodli, zda je úzkým místem výpočet, paměť nebo úložiště, spíše než předpokládat, že větší VPS opraví každé zpomalení.

Časté dotazy

n8n VPS požadavky: běžné otázky

Kolik RAM potřebuje n8n?

Univerzální postava neexistuje. RAM vyžaduje změny se souběžností, velikostí užitečného zatížení, chováním provádění a podpůrnými službami na VPS. Server 4 GB je praktickou maloprodukční počáteční třídou, která není zaručeným požadavkem pro každou zátěž.

Kolik jader CPU bych měl použít?

Nízká pracovní zátěž může začít malým přidělením CPU. Přidejte jádra, když monitorování ukazuje trvalý tlak CPU nebo pomalejší provádění při souběžném zpracování, spíše než dimenzování podle počtu pracovních postupů.

Vyžaduje n8n PostgreSQL?

Malá nasazení mohou používat SQLite, ale PostgreSQL je silnější volbou orientovanou na produkci, protože se zvyšují provozní požadavky a souběžnost.

Kdy je vyžadován Redis?

Redis je spojen s režimem fronty. Normální jednoinstanční nasazení nepotřebuje Redis jednoduše proto, že běží na VPS.

Kolik místa na disku mám vyhradit?

Požadavky na disk závisí na růstu PostgreSQL, uchovávané historii provádění, binárních datech, protokolech, vrstvách kontejnerů a zálohách. Sledujte růst a ponechte si rezervu místo spoléhání se na pevné univerzální číslo.

Mohu spouštět n8n nepřetržitě na 1 GB VPS?

Ano, když tomu odpovídá skutečné pracovní vytížení. A 1 GB VPS je skutečně fungující server a může podporovat malé, většinou sekvenční automatizace, ale kapacita paměti je omezená. Nepředpokládejte, že se vejde zásobník PostgreSQL stejného serveru, binárně náročné úlohy nebo více velkých souběžných spouštění. Monitorujte spotřebu a upgradujte na základě pozorovaného tlaku na zdroje.

Je pro produkci lepší 2 GB nebo 4 GB RAM n8n VPS?

Dva gigabajty poskytují více místa než štíhlá instance 1 GB, zatímco 4 GB je praktická počáteční třída pro posouzení n8n spolu s PostgreSQL a HTTPS. Neexistuje žádné univerzální garantované produkční minimum: skutečnou poptávku určují složitost pracovní zátěže, překrytí špiček, konfigurace kontejneru a uchovávaná data.

Vyžaduje n8n AI pracovní postupy GPU?

Ne, když n8n pouze volá externí model API: poskytovatel modelu se stará o odvození, zatímco VPS se stará o orchestraci, užitečné zatížení a souběžnost. Lokální spouštění odvozených modelů je samostatné hardwarové rozhodnutí, které může vyžadovat mnohem více RAM a vhodných GPU zdrojů.

Co způsobuje chyby v n8n nedostatku paměti?

Častými příčinami jsou velké JSON nebo binární užitečné zatížení, operace kódu náročné na paměť a překrývající se provádění. Zkontrolujte protokoly běhu a maximální využití paměti, poté snižte data uchovávaná v jednom provedení nebo přidělte více RAM na základě naměřeného problému.
