Modo cola de n8n: Redis, workers y escalado

El modo cola separa la recepción y coordinación de las ejecuciones del trabajo que realizan los workers. Añádelo cuando la concurrencia real lo justifique, no por defecto.

Cuándo tiene sentido el modo cola

Quédate en modo normal

Si una instancia mantiene latencia y recursos estables.

Considera modo cola

Cuando ejecuciones simultáneas generan backlog sostenido, aumenta la latencia de inicio y una sola instancia deja de absorber los picos aun después de optimizar recursos.

Escala vertical primero

Si el cuello es RAM o CPU de una única carga pesada.

WEBHOOKS Y LATENCIA

Escalar ejecuciones no elimina todos los cuellos de botella

Webhook processors

En despliegues de mayor escala puedes separar la recepción de webhooks del proceso principal para distribuir tráfico.

Latencia de cola

Mide el tiempo entre la entrada de una ejecución y el inicio real en un worker; una cola creciente indica capacidad insuficiente.

Concurrencia por worker

Un valor mayor aumenta paralelismo, pero también RAM, CPU y presión sobre PostgreSQL.

Health checks

Supervisa main, Redis, PostgreSQL y workers; un proceso vivo no garantiza que la cola esté avanzando.

DATOS COMPARTIDOS

Los workers necesitan una estrategia coherente para archivos y estado

PostgreSQLTodos los procesos comparten el mismo estado persistente.
RedisDebe ser privado y accesible solo por los componentes de la cola.
BinariosSi los workflows dependen de archivos, usa un almacenamiento compatible con múltiples workers; no asumas que el disco local de un worker existe en otro.
Escalado horizontalAñade workers cuando exista backlog sostenido y la base/Redis tengan margen; no multipliques workers si el cuello está en PostgreSQL o una API externa.

Decisiones técnicas restantes

Diseñar Queue Mode completo

1

Queue Mode usa PostgreSQL, Redis, procesos main/webhook y workers; todos necesitan el mismo N8N_ENCRYPTION_KEY.

2

Main, webhook processors y workers deben ejecutar la misma versión de n8n.

3

Mide concurrency, queue depth y latencia; añadir workers no corrige una base de datos o API externa lenta.

4

Los webhook processors son otra capa de escalado; multi-main/HA no es lo mismo que Queue Mode normal.

FAQ

Diseñar Queue Mode completo: FAQ

¿1 GB es un VPS real?

Sí. Es un VPS de entrada real para cargas ligeras; la limitación es el margen de recursos.

¿Por qué 2 GB como base ligera?

Da más margen a Docker, sistema operativo y pequeños picos.

¿Por qué medir antes de escalar?

CPU, RAM, disco y latencia muestran el cuello real.
