Qué consume recursos

Concurrencia

Varias ejecuciones pesadas elevan RAM y CPU. Si memoria o CPU permanecen cerca del límite, aparecen reinicios, swapping o latencia sostenida, aumenta recursos antes de añadir complejidad arquitectónica.

Payload

JSON y binarios grandes multiplican memoria.

Servicios

PostgreSQL, proxy y Redis consumen recursos.

Retención

El historial prolongado hace crecer base y disco.

SQLite, PostgreSQL y persistencia

SQLite puede servir para pequeño uso; PostgreSQL es más sólido para producción y futuros workers.

PostgreSQLPrivado, persistente y respaldado.
.n8nConserva datos y clave de cifrado.
RedisSolo para modo cola.

ALMACENAMIENTO Y MARGEN

Dimensiona el servidor completo, no solo el proceso n8n

40–80 GB NVMeRango práctico inicial cuando el mismo VPS aloja Docker, PostgreSQL, logs e historial; ajusta según retención y binarios.
PostgreSQLReserva memoria e I/O para la base: n8n no es el único proceso que compite por recursos.
IA / CodeLos nodos intensivos y payloads grandes pueden exigir 8 GB o más aunque el número de workflows sea pequeño.
ConcurrenciaSi 4 GB llegan a presión sostenida después de optimizar, aumenta RAM; si el problema es paralelismo sostenido, evalúa modo cola.

Decisiones técnicas restantes

Completar el dimensionamiento

1

1 GB es un VPS de entrada real para cargas muy ligeras; 2 GB deja más margen para Docker y picos pequeños.

2

Dimensiona por ejecuciones simultáneas, tamaño del payload, duración y nodos intensivos en CPU, no por número de workflows guardados.

3

PostgreSQL, proxy inverso, monitorización, logs y sistema operativo consumen recursos del mismo VPS.

4

SSD basta para cargas ligeras; NVMe aporta valor cuando la E/S de PostgreSQL o del historial ya es un cuello medido.

FAQ

Completar el dimensionamiento: FAQ

¿1 GB es un VPS real?

Sí. Es un VPS de entrada real para cargas ligeras; la limitación es el margen de recursos.

¿Por qué 2 GB como base ligera?

Da más margen a Docker, sistema operativo y pequeños picos.

¿Por qué medir antes de escalar?

CPU, RAM, disco y latencia muestran el cuello real.
