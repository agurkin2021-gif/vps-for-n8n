API de modelo alojado: usa la configuración económica, ligera o de pequeña empresa según el tamaño de los payloads y el solapamiento. El proveedor del modelo realiza la inferencia, por lo que tu VPS se ocupa principalmente de la orquestación y los datos.

Por qué el número de workflows por sí solo no sirve para elegir un plan

Llamadas API frecuentes y cortas: un servidor modesto puede manejar muchas ejecuciones si procesan registros pequeños y terminan antes de que llegue el siguiente lote.

Importaciones grandes o ráfagas: incluso pocos workflows pueden mantener muchos datos en memoria cuando procesan archivos grandes o se ejecutan a la vez. Observa el periodo de mayor carga, no solo el total mensual.

Llamadas a API de IA: el modelo se ejecuta en el proveedor de la API; tu VPS gestiona el workflow, sus datos y las solicitudes simultáneas. Los modelos locales y las bases de datos adicionales añaden otro tipo de carga. Factores de memoria de n8n · Requisitos detallados.

COMPRA LOS RECURSOS QUE USAN TUS WORKFLOWS

Qué buscar en un VPS para n8n

Prioriza RAM para los datos de trabajo, CPU para el procesamiento local y almacenamiento para el historial y los archivos que conservas. Incluye la base de datos y cualquier otra aplicación que comparta el VPS.

Estima el almacenamiento del historial de ejecuciones

Usa ejecuciones guardadas por día × tamaño medio almacenado × días de retención. Por ejemplo: 1,000 ejecuciones guardadas × 200 KB × 14 días son aproximadamente 2.8 GB de datos de ejecución almacenados, usando unidades decimales.

Añade espacio para índices y logs de la base de datos, el sistema operativo, los contenedores y los archivos de workflow. Usa en el cálculo el tamaño almacenado que hayas observado realmente. La retención puede reducir la demanda de almacenamiento sin cambiar CPU ni RAM. Configuración de datos de ejecución.

MemoriaDeja margen para n8n, la base de datos y los datos mantenidos por ejecuciones solapadas. Los archivos grandes y las transformaciones influyen más en el requisito que el número de workflows guardados.
CPUCompra más capacidad de procesamiento para cómputo local sostenido. Compara la asignación de CPU además del número de núcleos; las ofertas compartidas y dedicadas son diferentes.
AlmacenamientoUsa almacenamiento SSD o NVMe y elige capacidad según los datos que realmente conservas. Guarda las copias de recuperación fuera del servidor para que sobrevivan a la pérdida del VPS.
EntornoElige Linux con acceso administrativo y soporte para Docker. Usa un hostname HTTPS público para los webhooks y red privada entre los servicios de la aplicación.
Red y regiónSi tu proveedor ofrece varias regiones, coloca el VPS cerca de las bases de datos, APIs o usuarios que concentran los viajes de ida y vuelta. Los workflows con muchos archivos hacen que el ancho de banda y la política de transferencia también formen parte de la decisión; la región puede importar para la residencia de datos.
Límite del soporteAntes de pagar, verifica qué cubre el proveedor. Con un VPS autogestionado, asume la responsabilidad de las actualizaciones, configuración y recuperación de n8n salvo que se incluya explícitamente gestión a nivel de aplicación.

UNA RUTA CLARA DE CRECIMIENTO

Empieza con una instancia. Añade workers cuando haga falta.

HTTPS público→Reverse proxy→n8n↔PostgreSQL

Una sola instancia de n8n mantiene sencillo un despliegue pequeño. Cuando las tareas se acumulan porque la capacidad de ejecución es el límite, el modo cola separa los triggers entrantes de los procesos worker que ejecutan los workflows.

Planifica recursos para el proceso principal, PostgreSQL, Redis y cada worker. Los workers comparten acceso a la base de datos y a la clave de cifrado. Para colas con muchos archivos, usa almacenamiento binario compartido compatible. Planificar modo cola y workers · Arquitectura oficial de cola.

DESTINA EL PRESUPUESTO DONDE AYUDA

¿Más RAM, más CPU o cambiar el workflow?

01 · MEMORIA

Para conjuntos de datos de trabajo grandes

Comprueba el uso de memoria mientras se solapan tus tareas más grandes. Procesa las importaciones en lotes más pequeños y devuelve solo los datos que necesita el siguiente paso.

Compra más RAM cuando la carga siga llenando la memoria después de esos cambios.

02 · PROCESAMIENTO

Para transformaciones lentas

Compara el tiempo de procesamiento local con el tiempo de espera de servicios externos. Una carga sostenida de CPU durante el trabajo local apunta a la necesidad de más cómputo.

Mantén el nivel actual de CPU cuando el cuello de botella sea la respuesta de una API o su límite de peticiones.

03 · ALMACENAMIENTO

Para un historial de ejecuciones creciente

Decide qué resultados de ejecución guardar y durante cuánto tiempo. Incluye los archivos de workflow y el crecimiento de la base de datos en tu presupuesto de almacenamiento.

Elige un disco mayor cuando el historial que necesitas conservar supere el espacio disponible.

04 · TAREAS PARALELAS

Para ráfagas solapadas

Primero escalona las importaciones programadas. Añade workers cuando las tareas pendientes indiquen un límite de capacidad de ejecución y la base de datos y los recursos de los workers puedan soportar más trabajo paralelo.

Escala los workers y sus recursos conjuntamente.

Para una instalación Docker, un panel de hosting de pago es opcional. Para llamadas a APIs de IA alojadas, no hace falta GPU local. Reserva el presupuesto para la RAM, procesamiento, almacenamiento y recuperación que realmente necesite tu workflow.

Usa docker stats, el uso del disco del host y los logs de ejecución para comparar el periodo de mayor carga antes y después de un cambio. Medición del rendimiento de n8n · Controles de concurrencia.

RESPUESTAS A PREGUNTAS DE COMPRA

VPS para n8n: preguntas frecuentes

¿Qué configuración debería elegir para una pequeña empresa?

Elige la configuración Standard de 2 vCPU, 4 GB RAM y 80 GB para un stack moderado de n8n y PostgreSQL que gestione actualizaciones de CRM, leads e integraciones pequeñas basadas en JSON. Usa la opción mayor para trabajos intensivos en datos y mucho solapamiento; usa la opción ligera para una instancia sencilla con tareas pequeñas y principalmente secuenciales.

¿Cuándo es mejor elegir 8 GB de RAM que 4 GB?

Cuando tus workflows mantienen archivos o conjuntos de datos grandes en memoria, realizan transformaciones más pesadas o ejecutan varias tareas exigentes a la vez. Un número mensual elevado de ejecuciones por sí solo no justifica duplicar la RAM; analiza los datos de trabajo y el solapamiento máximo.

¿Los workflows de IA necesitan un VPS con GPU?

Llamar a una API de modelo alojado usa el hardware de inferencia del proveedor del modelo. Elige tu VPS para n8n según la orquestación, los payloads y la concurrencia. Ejecutar un modelo local o un servicio de inferencia independiente es otra compra, con necesidades de RAM y hardware específicas del modelo.

¿Qué ocurre después de elegir un VPS?

Selecciona la configuración de servidor Standard y el sistema operativo Linux en el catálogo de hosting. Despliega n8n con Docker, configura HTTPS y después añade las credenciales de tus workflows. La ruta de despliegue de esta página es autogestionada. Abrir la lista de instalación.

¿Puedo mover mis workflows actuales a esta configuración?

Exporta e importa workflows, vuelve a conectar las credenciales donde sea necesario y cambia deliberadamente los webhooks y triggers programados. Para mover una instancia completa, conserva la base de datos y la clave de cifrado original para que las credenciales guardadas sigan siendo utilizables. Preparación de migración y recuperación.

¿Necesitaré Redis o un panel de control de pago?

Un despliegue Docker normal de una sola instancia puede funcionar sin Redis ni un panel de hosting de pago. Añade Redis con modo cola cuando necesites ejecución mediante workers; elige un panel solo si sus funciones de gestión te resultan útiles.

¿Cómo mantener bajo el coste del VPS para n8n sin elegir un servidor demasiado pequeño?

Empieza con la configuración más pequeña que se ajuste a tus payloads reales y al solapamiento máximo, y reduce primero la demanda evitable antes de ampliar. Elimina historial de ejecuciones que no necesites, divide importaciones grandes en lotes, escalona programaciones pesadas y usa APIs de IA alojadas cuando no haga falta inferencia local. Mide memoria, CPU y disco durante el periodo de mayor carga; sube de nivel cuando la carga optimizada siga alcanzando límites sostenidos.
