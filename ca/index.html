DE L'AUTOMATITZACIÓ AL SERVIDOR

Quin VPS s'adapta a la vostra càrrega de treball de n8n?

Trieu segons les dades que processa cada execució i quantes execucions coincideixen en el temps. Una sincronització de contactes petita, una importació de documents voluminosos i una ràfega de webhooks exigeixen recursos diferents.

Quatre configuracions reals de VPS Standard autogestionats, a partir de $0.07/dia. Cada targeta obre VDSina mitjançant el nostre enllaç d'afiliació. Al catàleg del proveïdor, trieu el pla Standard amb la CPU, la RAM i l'emmagatzematge indicats aquí. El servidor no inclou n8n preinstal·lat.

00 · VPS ECONÒMIC

Automatitzacions petites i fluxos de treball continus

1 vCPU · 1 GB RAM

10 GB d'emmagatzematge · 1 TB de trànsit

Executeu automatitzacions lleugeres i contínues de n8n, com ara actualitzacions programades mitjançant API, notificacions i webhooks senzills. Un VPS d'1 GB pot ser una opció pràctica per al dia a dia si l'ús de memòria i les execucions simultànies es mantenen dins dels seus límits.

Valoreu ampliar la RAM si: PostgreSQL comparteix el servidor, els fluxos de treball processen dades més voluminoses, creix l'historial d'execucions o coincideixen tasques exigents. Comproveu el consum real de memòria abans d'ampliar-lo.

Trieu més RAM si: augmenteu la mida de les dades processades, executeu diverses tasques alhora o afegiu més serveis al mateix servidor.

$0.50/dia $15.00 durant 30 dies

Per què aquest nivell: espai per a l'aplicació i la base de dades al mateix servidor, i més emmagatzematge per a l'historial dels fluxos de treball.

$0.67/dia $20.10 durant 30 dies

Importacions, documents i tasques més exigents

Trieu aquesta configuració si necessiteu més marge per a conjunts de dades grans, transformacions locals i fluxos de treball que processen moltes dades alhora. Feu les importacions per lots per aprofitar la memòria.

Per què aquest nivell: més memòria de treball i capacitat de càlcul per processar dades, en lloc de limitar-se a esperar la resposta d'una API.

$1.34/dia $40.20 durant 30 dies

Fluxos de treball d'IA: trieu segons on s'executa el model

API d'un model allotjat: trieu la configuració econòmica, lleugera o per a una petita empresa segons el volum de dades i el nombre d'execucions simultànies. El proveïdor del model s'encarrega de la inferència; el VPS gestiona principalment l'orquestració i les dades.

Processament o model local: l'anàlisi de documents, els embeddings o la inferència local requereixen recursos propis de CPU i RAM i, potser, de GPU. Quan afegir treballadors.

Aquestes combinacions de CPU, RAM i emmagatzematge corresponen a la gamma Standard de servidors del proveïdor. Tarifes comprovades el 6 d'octubre de 2026; els imports de 30 dies corresponen al servidor, sense els extres seleccionats ni els impostos aplicables. Vegeu exactament què heu de triar.

Per què el nombre de fluxos de treball, per si sol, no serveix per triar un pla

Crides freqüents i breus a API: un servidor modest pot gestionar moltes execucions si processen registres petits i acaben abans que arribi el lot següent.

Importacions grans o ràfegues: fins i tot pocs fluxos de treball poden ocupar molta memòria quan processen fitxers grans o s'executen alhora. Vigileu les hores de màxima activitat, no només el total mensual.

Crides a API d'IA: el model s'executa a la infraestructura del proveïdor de l'API; el VPS gestiona el flux de treball, les dades i les peticions simultànies. Els models locals i les bases de dades addicionals generen necessitats diferents. Factors que influeixen en la memòria de n8n · Requisits detallats.

CONTRACTEU ELS RECURSOS QUE NECESSITEN ELS VOSTRES FLUXOS DE TREBALL

Què cal tenir en compte en triar un VPS per a n8n

Prioritzeu la RAM per a les dades en ús, la CPU per al processament local i l'emmagatzematge per a l'historial i els fitxers que conserveu. Incloeu-hi la base de dades i les altres aplicacions que comparteixen el VPS.

Calculeu l'espai de l'historial d'execucions

Utilitzeu nombre d'execucions desades al dia × mida mitjana de cada execució × dies de retenció. Per exemple: 1,000 execucions desades × 200 KB × 14 dies representen aproximadament 2.8 GB de dades d'execució emmagatzemades, utilitzant unitats decimals.

Afegiu espai per als índexs i els registres de la base de dades, el sistema operatiu, els contenidors i els fitxers dels fluxos de treball. Feu servir la mida mitjana observada a la vostra instal·lació. Reduir el període de retenció pot disminuir l'espai necessari sense canviar la CPU ni la RAM. Configuració de les dades d'execució.

MemòriaReserveu memòria per a n8n, la base de dades i les dades mantingudes per les execucions simultànies. La mida dels fitxers i la complexitat de les transformacions pesen més que el nombre de fluxos de treball desats.
CPUContracteu més capacitat de processament si feu càlculs locals de manera sostinguda. Compareu tant l'assignació de CPU com el nombre de nuclis; els recursos compartits i els dedicats no són equivalents.
EmmagatzematgeTrieu emmagatzematge SSD o NVMe amb capacitat suficient per a les dades que conserveu. Deseu les còpies de recuperació fora del servidor perquè continuïn disponibles si perdeu el VPS.
EntornTrieu Linux amb accés d'administració i compatibilitat amb Docker. Feu servir un nom de domini públic amb HTTPS per als webhooks i connexions privades entre els serveis de l'aplicació.
Regió de xarxaSi el proveïdor ofereix diverses regions, situeu el VPS a prop de les bases de dades, les API o els usuaris que generen més comunicacions de xarxa. Si processeu molts fitxers, tingueu en compte també l'amplada de banda i les condicions de transferència; la regió pot afectar la residència de les dades.
Abast del suport tècnicAbans de pagar, comproveu què cobreix el suport del proveïdor. En un VPS autogestionat, les actualitzacions de n8n, la configuració i la recuperació són responsabilitat vostra, llevat que el contracte inclogui explícitament la gestió de l'aplicació.

01 · MEMÒRIA

Per a grans conjunts de dades de treball

Amplieu la RAM si la càrrega de treball continua esgotant la memòria després d'aquests canvis.

02 · PROCESSAMENT

Per a transformacions lentes

Compareu el temps de processament local amb el temps d'espera dels serveis externs. Si la CPU es manté molt ocupada durant el processament local, pot ser necessari disposar de més capacitat de càlcul.

Manteniu la capacitat de CPU actual si el coll d'ampolla és el temps de resposta d'una API o el seu límit de peticions.

03 · EMMAGATZEMATGE

Per a un historial d'execucions creixent

Decidiu quins resultats d'execució voleu desar i durant quant de temps. Incloeu els fitxers dels fluxos de treball i el creixement de la base de dades en el càlcul de l'emmagatzematge.

Trieu un disc més gran quan l'historial que heu de conservar superi l'espai disponible.

04 · TREBALLS PARAL·LELS

Per a ràfegues superposades

Escaleu primer les importacions programades perquè no coincideixin. Afegiu workers quan la cua de tasques pendents indiqui que falta capacitat d'execució i la base de dades i els workers puguin assumir més treball en paral·lel.

Amplieu conjuntament el nombre de workers i els recursos que tenen disponibles.

Per a una instal·lació amb Docker, el tauler de control d'allotjament de pagament és opcional. Si utilitzeu API de models d'IA allotjats, no necessiteu cap GPU local. Destineu el pressupost a la RAM, el processament, l'emmagatzematge i la recuperació que requereixen els vostres fluxos de treball.

Feu servir docker stats, l'ús del disc del servidor i els registres d'execució per comparar els períodes de màxima activitat abans i després dels canvis. Mesurament del rendiment de n8n · Controls de concurrència.

RESPOSTES A PREGUNTES ABANS DE CONTRACTAR

VPS per a n8n: preguntes freqüents

Quina configuració he de triar per a una petita empresa?

Trieu la configuració Standard de 2 vCPU, 4 GB RAM i 80 GB per a una instal·lació moderada de n8n amb PostgreSQL que gestioni actualitzacions de CRM, contactes comercials i petites integracions JSON. Trieu una opció més potent per a tasques amb moltes dades o nombroses execucions simultànies; opteu per una de més lleugera si la instància fa sobretot tasques petites i seqüencials.

Quan convé més disposar de 8 GB de RAM que de 4 GB?

Quan els fluxos de treball mantenen fitxers o conjunts de dades grans en memòria, fan transformacions exigents o executen diverses tasques pesades alhora. Un nombre elevat d'execucions mensuals no justifica per si sol duplicar la RAM: comproveu les dades en ús i les execucions simultànies màximes.

Els fluxos de treball d'IA necessiten un VPS amb GPU?

Quan n8n crida l'API d'un model allotjat, la inferència s'executa al maquinari del proveïdor del model. Trieu el VPS segons les necessitats d'orquestració, les dades processades i la concurrència. Executar un model local o un servei d'inferència independent exigeix una altra configuració, amb requisits de RAM i maquinari específics del model.

Què passa després de triar un VPS?

Seleccioneu la configuració del servidor Standard i un sistema operatiu Linux al catàleg d'allotjament. Desplegueu n8n amb Docker, configureu HTTPS i afegiu-hi les credencials dels fluxos de treball. El procediment descrit en aquesta pàgina és autogestionat. Obriu la llista de comprovació de la instal·lació.

Puc moure els meus fluxos de treball existents a aquesta configuració?

Exporteu i importeu els fluxos de treball, torneu a connectar les credencials quan calgui i migreu amb cura els webhooks i els activadors programats. Si traslladeu tota la instància, preserveu la base de dades i la clau de xifratge original perquè les credencials desades continuïn funcionant. Preparació per a la migració i la recuperació.

Necessitaré Redis o un tauler de control de pagament?

Una instal·lació ordinària amb Docker i una sola instància pot funcionar sense Redis ni un tauler d'allotjament de pagament. Afegiu Redis i el mode de cua quan necessiteu executar fluxos de treball mitjançant workers; contracteu un tauler només si les seves funcions de gestió us resulten útils.

Com puc mantenir baixos els costos de n8n VPS sense reduir la mida del servidor?

Comenceu amb la configuració més petita que pugui gestionar les dades reals i el màxim d'execucions simultànies. Abans d'ampliar-la, elimineu l'historial d'execucions innecessari, dividiu les importacions grans en lots, distribuïu els horaris de les tasques pesades i utilitzeu API d'IA allotjades quan no calgui fer inferència local. Mesureu la RAM, la CPU i l'espai de disc durant les hores de màxima càrrega; passeu a un pla superior si, tot i aquestes optimitzacions, continueu arribant als límits de manera sostinguda.
