INSTAL·LACIÓ AMB DOCKER

Com instal·lar n8n en un VPS

Instal·leu n8n en un VPS amb Docker Compose i PostgreSQL. Per a un desplegament de producció també necessiteu emmagatzematge persistent per a l'aplicació i la base de dades, i una clau estable N8N_ENCRYPTION_KEY, un nom d'amfitrió públic, HTTPS i una configuració correcta dels webhooks. Comproveu tots aquests elements abans d'activar els fluxos de treball de producció.

REQUISITS PREVIS

Prepareu el VPS abans d'iniciar n8n

Linux VPS

Utilitzeu un servidor Linux amb actualitzacions de manteniment i recursos suficients per a n8n, PostgreSQL, Docker i el proxy invers.

DNS

Feu que un domini o subdomini apunti al VPS abans d'emetre els certificats TLS i publicar els URL dels webhooks.

Docker Compose

Instal·leu Docker Engine i el complement Compose amb els paquets compatibles amb el vostre sistema operatiu.

Tallafoc

Exposeu només els ports d'administració i web necessaris. Manteniu PostgreSQL i els serveis interns de l'aplicació fora de l'accés públic.

Voleu instal·lar n8n en un VPS que ja allotja llocs web? Podeu afegir n8n a un servidor que controleu si la CPU, la RAM i l'emmagatzematge ho permeten. Però si Nginx, Apache, Caddy o un altre proxy invers ja utilitza els ports 80/443, no inicieu el contenidor Caddy de l'exemple següent sense adaptar-lo: els ports entrarien en conflicte. Feu passar el nou subdomini de n8n pel proxy invers existent amb la xarxa privada adequada, o utilitzeu un VPS net per reproduir exactament l'exemple de Compose. Conserveu els altres llocs web i la seva configuració TLS; l'exemple pressuposa que els ports 80/443 estan disponibles.

INSTAL·LACIÓ PER COPIAR I ADAPTAR

Instal·leu n8n al vostre VPS amb Docker Compose

Utilitzeu aquest exemple per desplegar n8n en un VPS Linux autogestionat. La instal·lació i el manteniment de n8n són responsabilitat vostra; contractar un servidor mitjançant el nostre soci no inclou n8n preinstal·lat. L'exemple combina n8n, PostgreSQL, un executor de tasques extern i Caddy per a HTTPS en una xarxa privada de Compose. És una plantilla de configuració, no una garantia que el desplegament s'hagi provat en un servidor real.

Preferiu una instal·lació nova més ràpida? n8n també ofereix un procediment oficial d'instal·lació de Docker amb una sola ordre. Podeu descarregar-ne l'script i revisar-lo executant curl -fsSL https://get.n8n.io -o get-n8n.sh abans d'executar sh get-n8n.sh. Aquesta opció inicia una instància amb SQLite en un URL local i inclou els serveis de l'entorn de proves de n8n Assistant; no és equivalent al desplegament de VPS amb PostgreSQL i HTTPS públic descrit aquí. L'entorn de proves oficial complet necessita més RAM i CPU que una instal·lació senzilla de n8n (la guia de Compose indica com a mínim 4 GB RAM / 2 vCPU). Per a un VPS de producció accessible des d'Internet, continueu amb els serveis configurats manualment a continuació.

1. Prepareu Docker, el DNS i l'accés

Connecteu-vos per SSH amb accés sudo i configureu un registre A de DNS perquè n8n.example.com apunti a l'adreça IPv4 del VPS. En un VPS nou amb Ubuntu 22.04, 24.04 o 26.04 les ordres següents instal·len Docker Engine i el complement modern docker compose des del repositori oficial de Docker per a apt, signat digitalment:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

És el mètode d'instal·lació des del repositori recomanat per a producció a la guia oficial de Docker per a Ubuntu. No reinstal·leu ni elimineu Docker sense comprovar abans la configuració d'un VPS que ja executa contenidors o allotja altres llocs web; reviseu primer la instal·lació existent i els possibles conflictes entre paquets. Per a Debian o una altra distribució, seguiu les instruccions oficials corresponents al sistema operatiu en lloc de les ordres d'Ubuntu.

Comproveu ara Docker, el complement Compose, el DNS i el directori de treball:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Si getent hosts no retorna cap adreça o en retorna una d'incorrecta, corregiu el DNS abans d'iniciar Caddy. Substituïu n8n.example.com a tota la guia pel nom d'amfitrió real. Docker acostuma a requerir privilegis de root: si l'usuari SSH no pot executar directament les ordres docker compose , poseu-hi davant sudo. Afegir un usuari al grup docker li concedeix permisos equivalents als de root; no ho feu sense valorar-ne els riscos en un servidor compartit.

Abans d'activar el tallafoc, comproveu que el port SSH d'administració continua accessible. Permeteu l'entrada HTTP (80) i HTTPS (443) per emetre certificats i accedir a l'editor. Els ports publicats per Docker poden esquivar algunes regles d'UFW: consulteu les recomanacions de Docker sobre tallafocs i publiqueu només els ports de Caddy previstos. Aquest exemple de Compose expressament no exposa PostgreSQL (5432), n8n (5678) ni el servei intermediari de l'executor de tasques (5679) a Internet pública.

2. Creeu les variables d'entorn i preserveu la clau

Al directori del projecte, genereu tres valors hexadecimals aleatoris diferents amb aquesta ordre:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Creeu un fitxer anomenat .env amb la plantilla següent; substituïu cada valor REPLACE_WITH_RANDOM_HEX per un valor aleatori diferent i canvieu el nom d'amfitrió i la zona horària. La versió indicada 2.42.5 correspon a la versió estable publicada el 8 d'octubre de 2026, inclosa aquí com a exemple de configuració datat, no com a garantia que el desplegament s'hagi provat en un entorn real ni que continuï sent segur en el futur. Abans d'instal·lar n8n, consulteu les versions oficials actuals i manteniu n8n i la imatge de l'executor de tasques a la mateixa versió verificada.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

No pugeu mai el fitxer .env a un repositori públic. Deseu la clau de xifratge i les instruccions de recuperació fora del VPS de manera segura. La clau ha de continuar sent la mateixa quan es recreï el contenidor o es migri la instal·lació.

3. Escriviu compose.yaml per a una instal·lació nova

Al mateix directori, creeu el fitxer compose.yaml. L'exemple segueix les convencions oficials de les variables d'entorn de n8n i utilitza la ruta PGDATA de PostgreSQL 18 documentada pel projecte d'allotjament de n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Els quatre serveis tenen funcions diferents: PostgreSQL desa l'estat de la base de dades; n8n executa els fluxos de treball; n8n-runner executa tasques amb una versió coincident i un testimoni d'autenticació compartit, i Caddy gestiona el trànsit HTTPS públic. Un executor de tasques extern no és el mateix que el mode de cua amb Redis. Només Caddy publica ports de l'amfitrió. Aquest exemple senzill utilitza un sol rol de base de dades per configurar el sistema; per separar millor els privilegis de PostgreSQL, consulteu l'exemple oficial de desplegament de n8n amb PostgreSQL.

4. Creeu el fitxer Caddyfile per a HTTPS

Creeu el fitxer Caddyfile (amb C majúscula i sense extensió) al costat de compose.yaml. Substituïu arreu el nom d'amfitrió d'exemple pel vostre domini DNS:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy sol·licita i renova els certificats TLS públics quan el domini es resol correctament i el trànsit extern pot arribar als ports 80/443. No configureu el DNS perquè apunti a localhost. Si substituïu Caddy per un altre proxy invers, reenvieu les capçaleres que indiquen el nom de l'amfitrió original, el protocol i l'adreça del client, i adapteu N8N_PROXY_HOPS al nombre real de salts de proxy de confiança.

5. Inicieu els contenidors i feu la prova des de fora

Executeu aquestes ordres des del directori del projecte després de desar .env, compose.yaml i Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

L'última ordre comprova l'endpoint de salut HTTPS públic . Si encara s'està emetent el certificat, reviseu els registres de Caddy, el DNS i els ports abans de concloure que n8n no funciona. Obriu https://n8n.example.com, creeu immediatament el primer compte de propietari i activeu les proteccions d'inici de sessió adequades. Comproveu que la instància executa realment un flux de treball, no només que l'editor es carrega:

  1. A l'editor, creeu un flux de treball amb un activador Webhook . Establiu el camp Mètode HTTP com a GET, trieu el camp Ruta vps-check, i establiu l'opció Resposta com a Immediatament. Deseu el flux de treball.
  2. Feu clic a Escolta l'esdeveniment de prova, copieu l' URL de prova complet que mostra n8n i executeu des d'un altre dispositiu curl -i 'PASTE_TEST_URL_HERE' amb l'URL copiat. Hauríeu d'obtenir una resposta HTTP satisfactòria i veure l'esdeveniment entrant a l'editor de n8n. Els URL de prova només funcionen mentre n8n està esperant l'esdeveniment.
  3. Publiqueu el flux de treball, canvieu el node perquè utilitzi l' URL de producció, copieu-lo i torneu a executar curl -i 'PASTE_PRODUCTION_URL_HERE' . Comproveu l'execució a la pestanya Execucions del flux de treball. Les peticions dels webhooks de producció requereixen que el flux de treball estigui publicat i no mostren les dades rebudes a la vista de prova de l'editor.

És una prova funcional bàsica, deliberadament senzilla i sense autenticació: no hi envieu mai secrets. Quan hàgiu acabat, retireu el flux de treball de la publicació o suprimiu-lo, o configureu l'autenticació del Webhook i restriccions d'IP abans d'utilitzar un endpoint públic amb dades reals. Consulteu la documentació oficial de webhooks de prova i producció.

6. Feu una còpia de seguretat abans de canviar les versions fixades

Deseu un bolcat recuperable de PostgreSQL i el volum de dades persistent n8n, .envi la clau de xifratge, a més dels fitxers externs necessaris, en un emmagatzematge fora d'aquest servidor. Comproveu que es poden restaurar seguint la guia de còpies de seguretat i recuperació abans d'actualitzar el sistema de producció. Exemples d'ordres:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Canvieu la versió fixada N8N_VERSION només després de llegir les notes de la versió; les imatges de n8n i de l'executor de tasques s'han d'actualitzar conjuntament. No executeu docker compose down -v durant el manteniment habitual, perquè elimina els volums de dades amb nom. Els canvis de versió principal de PostgreSQL requereixen una actualització planificada de la base de dades o un procediment de bolcat i restauració; canviar la imatge de Postgres 18 per una d'una altra versió principal no migra automàticament les dades.

Referències oficials: guia de Docker Compose de n8n, configuració de proxy invers i webhooks de n8n, i documentació oficial del desplegament de PostgreSQL. No s'hi pressuposen resultats de rendiment mesurats ni funcions preinstal·lades específiques de cap proveïdor.

ERRORS HABITUALS

Per què una instal·lació de n8n amb Docker funciona localment però falla en producció

URL del webhook incorrecte

Els URL de retorn apunten a localhost, HTTP o un nom d'amfitrió intern en lloc de l'origen HTTPS públic.

No hi ha dades persistents

L'estat de l'aplicació o de la base de dades desapareix quan es recrea un contenidor.

Pèrdua de la clau de xifratge

Les credencials desades deixen de funcionar després de reconstruir el servidor perquè la nova instància utilitza una clau diferent.

Port públic de la base de dades

PostgreSQL queda exposat innecessàriament, tot i que només n8n hi ha de tenir accés.

Preguntes freqüents

Instal·lació de n8n amb Docker: preguntes freqüents

Necessito PostgreSQL per executar n8n amb Docker?

Docker no exigeix utilitzar PostgreSQL i les instal·lacions petites poden funcionar amb SQLite. En un VPS orientat a producció, PostgreSQL proporciona una base de dades més robusta i facilita una ampliació posterior amb el mode de cua.

Per què he de conservar el volum persistent de n8n si utilitzo PostgreSQL?

El directori persistent de n8n pot contenir dades i configuracions importants de la instància. Conserveu-lo segons el disseny del desplegament i no suposeu que la base de dades és l'únic element necessari per recuperar el sistema.

Per què el meu webhook mostra localhost?

L'adreça interna del contenidor és diferent de l'adreça pública. Configureu el nom d'amfitrió extern, el protocol i l'URL del webhook, i assegureu-vos que el proxy invers reenvia les capçaleres necessàries.

El port 5678 ha de ser públic?

En un desplegament de producció habitual darrere d'un proxy invers, publiqueu HTTPS al proxy i manteniu el port de l'aplicació n8n a la xarxa interna, tret que hi hagi una necessitat operativa concreta de fer-ho d'una altra manera.

Necessito Redis?

No per a un desplegament estàndard de Docker amb una sola instància. Redis és necessari quan decidiu utilitzar el mode de cua amb workers.

Els executors de tasques externs de n8n són el mateix que els workers del mode de cua?

No. Els executors de tasques externs executen el codi de les tasques compatibles en processos separats del procés principal de n8n i comparteixen un testimoni d'autenticació. El mode de cua amb Redis distribueix les execucions dels fluxos de treball i requereix una infraestructura pròpia. Aquest exemple mostra un executor de tasques extern, no el mode de cua amb Redis. La versió de la imatge de l'executor ha de coincidir amb la versió de n8n.
