INSTAL·LACIÓ DOCKER

Instal·leu n8n en un VPS

Instal·leu n8n en un VPS mitjançant Docker Compose i PostgreSQL. Un desplegament de producció també necessita dades d'aplicacions i bases de dades persistents, estables N8N_ENCRYPTION_KEY, un nom d'amfitrió públic, HTTPS i una configuració correcta del webhook. Verifiqueu aquestes peces abans d'activar els fluxos de treball de producció.

PREREQUISITS

Prepareu el VPS abans de començar el n8n

Linux VPS

Utilitzeu un servidor mantingut Linux de la mida de n8n, PostgreSQL, Docker i el proxy invers.

DNS

Apunteu un domini o subdomini al VPS abans d'emetre certificats TLS i publicar URL de webhook.

Docker Composar

Instal·leu Docker Engine i el connector Compose mitjançant paquets compatibles amb el sistema operatiu.

Tallafoc

Exposa només els ports web i d'administració necessaris. Mantingueu privats els serveis de PostgreSQL i d'aplicacions internes.

Instal·lar en un VPS que ja allotja llocs web? Podeu afegir n8n a un servidor que controleu quan CPU, RAM i l'emmagatzematge ho permeten. Tanmateix, si Nginx, Apache, Caddy o un altre servidor intermediari invers ja posseeix ports 80/443, feu-ho no inicieu el contenidor d'exemple Caddy a continuació sense canvis: els ports entraran en conflicte. En comptes d'això, encamineu un nou subdomini n8n a través del vostre servidor intermediari invers existent amb una xarxa privada adequada o utilitzeu un VPS net per a l'exemple de Compose exacte. Preservar els altres llocs i la seva configuració TLS; l'exemple suposa que els ports 80/443 estan disponibles.

INSTAL·LACIÓ PER COPIAR I ADAPTAR

Instal·leu n8n al vostre VPS amb Docker Compose

Utilitzeu aquest exemple per crear un desplegament n8n en a autogestionat Linux VPS. Tu mateix instal·leu i manteniu n8n; escollir un servidor a través del nostre soci no inclou una instància n8n preinstal·lada. L'exemple combina n8n, PostgreSQL, un executador de tasques extern i Caddy HTTPS en una xarxa de Compose privada. És una plantilla de configuració, no és una reclamació d'un desplegament provat en directe.

Voleu la instal·lació nova més ràpida? n8n també proporciona una configuració oficial d'una línia Docker. Podeu descarregar i revisar el seu script amb curl -fsSL https://get.n8n.io -o get-n8n.sh abans de córrer sh get-n8n.sh. Aquesta opció llança una instància inicial amb SQLite a una URL local i inclou els serveis de sandbox de n8n Assistant; ho és no és el mateix com aquest desplegament públic HTTPS, PostgreSQL recolzat per VPS. La pila oficial de sandbox completa necessita més RAM i CPU que una instal·lació senzilla n8n (la seva guia Compose especifica almenys vCPU 4 GB RAM / 2). Per a una producció orientada a Internet VPS, continueu amb la pila configurada manualment a continuació.

1. Prepara Docker, DNS i accedeix

Connecta't a través de SSH amb accés sudo i apunta un registre DNS A per n8n.example.com a la vostra adreça IPv4 VPS. En a fresc Ubuntu 22.04, 24.04 o 26.04 VPS, les ordres següents instal·len Docker Engine i el modern docker compose connector de l'oficial de Docker signat apt repositori:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Aquest és el mètode de repositori orientat a la producció de la guia d'instal·lació oficial Docker Ubuntu. No torneu a instal·lar ni suprimiu a cegues Docker en un VPS que ja s'executa contenidors o altres llocs web; primer inspeccioneu la instal·lació existent i els possibles conflictes de paquets. Per a Debian o una altra distribució, utilitzeu les instruccions oficials específiques del sistema operatiu corresponents en lloc de les ordres Ubuntu.

Ara verifiqueu Docker mateix, el connector Compose, DNS i el directori de treball:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Si getent hosts no retorna cap adreça o l'adreça incorrecta, corregiu el vostre DNS abans de començar el Caddy; substituir n8n.example.com al llarg d'aquesta guia amb el vostre nom d'amfitrió real. Docker normalment requereix privilegis de root: si el vostre usuari de SSH no pot executar el més tard docker compose ordres directament, prefixeu-les amb sudo. Afegint un usuari al docker El grup concedeix accés equivalent a l'arrel i no s'ha de fer casualment en un servidor compartit.

Manteniu el vostre port d'administració actual SSH accessible abans d'habilitar un tallafoc. Permet l'entrada HTTP (80) i HTTPS (443) per a l'emissió de certificats i l'editor. Els ports de contenidors publicats al Docker poden obviar algunes regles UFW, així que reviseu les instruccions del tallafocs del Docker i publiqueu només els ports previstos al Caddy. Aquest exemple de Compose ho fa deliberadament no publicar PostgreSQL (5432), n8n (5678) o el corredor de tasques (5679) a Internet pública.

2. Crea valors ambientals i preserva la clau

Des del directori del projecte, genereu-ne tres diferents valors hexadecimals aleatoris amb:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Creeu un fitxer anomenat .env utilitzant la plantilla següent, substituïu-ne tots REPLACE_WITH_RANDOM_HEX amb un valor generat diferent i canvieu el nom d'amfitrió i la zona horària. El mostrat 2.42.5 l'etiqueta és versió estable llistada el 8 d'octubre 2026, utilitzat aquí com a exemple de configuració datat, no és una garantia d'un desplegament provat en directe o de seguretat futura. Abans d'instal·lar, comproveu les versions oficials actuals de n8n i, a continuació, mantingueu n8n i la seva imatge d'executor de tasques a la mateixa versió verificada.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

No et comprometis mai .env a un repositori públic. Emmagatzemeu la clau de xifratge i les instruccions de recuperació de manera segura fora del VPS. La clau ha de romandre igual després de la recreació o la migració del contenidor.

3. Escriu compose.yaml per a una nova instal·lació

Al mateix directori, crea compose.yaml. L'exemple utilitza les convencions oficials de variables d'entorn n8n i la PostgreSQL 18 PGDATA camí documentat pel projecte d'allotjament n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Els quatre serveis tenen funcions diferents: PostgreSQL emmagatzema l'estat de la base de dades, n8n executa fluxos de treball, n8n-runner executa tasques de corredor amb una versió coincident i un testimoni d'autenticació compartit, i Caddy gestiona HTTPS públic. Un extern corredor de tasques no és el mode de cua Redis. Només Caddy publica ports d'amfitrió. Aquesta il·lustració lleugera utilitza una única funció de base de dades per a la configuració; per a una separació més forta dels privilegis PostgreSQL, consulteu l'exemple de desplegament oficial n8n PostgreSQL.

4. Creeu el HTTPS Caddyfile

Creeu el fitxer Caddyfile (C majúscula, sense extensió) al costat compose.yaml. Substituïu el nom d'amfitrió d'exemple a tot arreu pel vostre propi nom DNS:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy demana i renova els certificats públics TLS quan el domini es resol correctament i el trànsit extern pot arribar als ports 80/443. No assenyaleu DNS a localhost. Si substituïu Caddy per un altre proxy invers, reenvieu les capçaleres originals de l'amfitrió, el protocol i l'adreça del client i ajusteu-les. N8N_PROXY_HOPS per al nombre real de salts de proxy de confiança.

5. Engegueu els contenidors i proveu des de fora

Executeu aquestes ordres des del directori del projecte després de desar .env, compose.yaml i Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

L'última ordre comprova el públic HTTPS punt final de salut. Si l'emissió del certificat encara està pendent, inspeccioneu els registres Caddy i els DNS/ports abans de concloure que el n8n està trencat. Obert https://n8n.example.com, creeu el primer compte de propietari immediatament i activeu les proteccions d'inici de sessió adequades. Confirmeu que la instància executa realment un flux de treball, no només que l'editor carregui:

  1. A l'editor, creeu un flux de treball amb a Webhook disparador. Set HTTP Mètode a GET, tria el Path vps-check, i posat Respon a Immediatament. Deseu el flux de treball.
  2. Feu clic Escolteu l'esdeveniment de prova, copieu el complet URL de prova mostrat per n8n i executar des d'un altre dispositiu curl -i 'PASTE_TEST_URL_HERE' amb l'URL copiat. Espereu una resposta d'èxit HTTP i que l'esdeveniment entrant aparegui a l'editor n8n. Els URL de prova només funcionen mentre n8n escolta l'esdeveniment.
  3. Publicar el flux de treball, canvieu el node al seu URL de producció, copieu-lo i executeu-lo curl -i 'PASTE_PRODUCTION_URL_HERE' de nou. Confirmeu l'execució sota el flux de treball Execucions pestanya. Les sol·licituds de webhook de producció necessiten que el flux de treball es publiqui i no mostren la seva càrrega útil a la vista de prova de l'editor.

Aquesta és una prova de fum deliberadament senzilla i no autenticada: no hi envieu mai secrets. Anul·leu la publicació/suprimiu-lo després de la prova o configureu les restriccions d'autenticació/IP de Webhook abans d'utilitzar un punt final públic per a dades reals. Consulteu la documentació oficial de prova/producció de Webhook.

6. Fes una còpia de seguretat abans de canviar les versions fixades

Desa un abocador de PostgreSQL recuperable i el volum de dades persistent n8n, .env/clau de xifratge i fitxers externs necessaris per a l'emmagatzematge fora d'aquest servidor. Verifiqueu una restauració amb el guia de còpia de seguretat i recuperació abans d'actualitzar la producció. Exemples d'ordres:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Canvia el fixat N8N_VERSION només després de llegir les notes de llançament; tant n8n com les imatges del corredor han d'avançar juntes. No córrer docker compose down -v durant el manteniment rutinari perquè això elimina els volums de dades amb nom. PostgreSQL els canvis a la versió principal requereixen una actualització de la base de dades o un pla de bolcada/restauració; substituir la imatge de Postgres 18 per una etiqueta principal diferent no és una migració automàtica.

Referències autoritzades: n8n Docker Guia de redacció, n8n configuració de proxy invers/webhook i notes oficials de desplegament PostgreSQL. No s'assumeix cap referència d'infraestructura ni funció preinstal·lada específica del proveïdor.

FALLAS COMUNS

Per què una instal·lació n8n Docker funciona localment però falla en la producció

URL del webhook incorrecte

Les devolucions de trucada apunten a localhost, HTTP o un nom d'amfitrió intern en lloc de l'origen públic HTTPS.

Falta persistència

L'estat de l'aplicació o de la base de dades desapareix quan es recrea un contenidor.

S'ha perdut la clau de xifratge

Les credencials desades es tornen inutilitzables després de la reconstrucció perquè la nova instància utilitza una clau diferent.

Port de base de dades pública

PostgreSQL s'exposa innecessàriament tot i que només el n8n necessita arribar-hi.

Preguntes freqüents

Instal·lació de n8n amb Docker: preguntes habituals

n8n necessita PostgreSQL quan s'utilitza Docker?

Docker no requereix PostgreSQL, i els desplegaments petits poden utilitzar SQLite. Per a un desplegament de VPS orientat a la producció, PostgreSQL proporciona una base de dades més sòlida i admet l'escalat posterior en mode de cua.

Per què mantenir un volum n8n persistent si PostgreSQL emmagatzema dades?

El directori persistent n8n pot contenir un estat i una configuració de la instància importants. Preserveu-lo segons el disseny de desplegament en lloc d'assumir que la base de dades és l'únic actiu de recuperació.

Per què el meu webhook mostra localhost?

L'adreça interna del contenidor és diferent de l'origen públic. Configureu el nom d'amfitrió extern, el protocol i l'URL del webhook i assegureu-vos que el servidor intermediari invers passa les capçaleres necessàries.

El port 5678 hauria de ser públic?

Per a un desplegament de producció normal darrere d'un servidor intermediari invers, exposa HTTPS al servidor intermediari i mantén el port d'aplicació n8n intern tret que hi hagi una raó operativa específica per no fer-ho.

Necessito Redis?

No per a un desplegament estàndard d'una sola instància Docker. Redis esdevé rellevant quan passeu deliberadament al mode de cua i als treballadors.

Els executadors de tasques n8n externs són els mateixos que els treballadors en mode de cua?

No. Els executants de tasques externs executen el codi de tasca compatible per separat del procés principal n8n i utilitzen un testimoni d'autenticació compartit. Redis El mode de cua distribueix les execucions del flux de treball i té els seus propis requisits d'infraestructura. Aquest exemple mostra un executador de tasques extern, no el mode de cua Redis. Relaciona la versió de la imatge del corredor amb la versió n8n.
