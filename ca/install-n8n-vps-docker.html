INSTAL·LACIÓ AMB DOCKER

Com instal·lar n8n en un VPS

Instal·leu n8n en un VPS amb Docker Compose i PostgreSQL. Un desplegament de producció també requereix dades persistents de l'aplicació i de la base de dades, una clau de xifratge estable configurada a N8N_ENCRYPTION_KEY, un nom d'amfitrió públic, HTTPS i una configuració correcta dels webhooks. Comproveu tots aquests elements abans d'activar els fluxos de treball de producció.

REQUISITS PREVIS

Prepareu el VPS abans d'engegar n8n

VPS amb Linux

Feu servir un servidor Linux amb manteniment actiu i recursos suficients per a n8n, PostgreSQL, Docker i el proxy invers.

DNS

Feu que un domini o subdomini apunti al VPS abans d'emetre els certificats TLS i publicar els URL dels webhooks.

Docker Compose

Instal·leu Docker Engine i el complement de Compose amb paquets compatibles amb el sistema operatiu.

Tallafoc

Obriu només els ports web i d'administració necessaris. Manteniu privats PostgreSQL i els serveis interns de l'aplicació.

Voleu instal·lar n8n en un VPS que ja allotja llocs web? Podeu afegir n8n a un servidor que administreu si disposa de CPU, RAM i emmagatzematge suficients. Ara bé, si Nginx, Apache, Caddy o un altre proxy invers ja fa servir els ports 80/443, no inicieu el contenidor Caddy de l'exemple següent sense modificar-lo: els ports entrarien en conflicte. En lloc d'això, dirigiu un subdomini nou d'n8n a través del proxy invers existent, amb una xarxa privada adequada, o utilitzeu un VPS nou per seguir exactament l'exemple de Compose. Conserveu els altres llocs web i la seva configuració TLS; l'exemple pressuposa que els ports 80/443 estan lliures.

INSTAL·LACIÓ PER COPIAR I ADAPTAR

Instal·leu n8n al vostre VPS amb Docker Compose

Utilitzeu aquest exemple per desplegar n8n en un VPS Linux autogestionat. Haureu d'instal·lar i mantenir n8n pel vostre compte; contractar un servidor a través del nostre soci no inclou una instància d'n8n preinstal·lada. L'exemple combina n8n, PostgreSQL, un executor de tasques extern i Caddy amb HTTPS dins d'una xarxa privada de Compose. És una plantilla de configuració, no una afirmació que el desplegament s'hagi provat en un entorn real.

Preferiu una instal·lació nova més ràpida? n8n també ofereix una instal·lació oficial de Docker amb una sola ordre. Podeu descarregar-ne l'script i revisar-lo amb curl -fsSL https://get.n8n.io -o get-n8n.sh abans d'executar sh get-n8n.sh. Aquesta opció inicia una instància amb SQLite en un URL local i inclou serveis de l'entorn aïllat de n8n Assistant; no és equivalent a aquest desplegament en un VPS amb HTTPS públic i PostgreSQL. L'entorn aïllat oficial complet necessita més RAM i CPU que una instal·lació bàsica d'n8n (la seva guia de Compose especifica almenys 4 GB de RAM i 2 vCPU). Per a un VPS de producció accessible des d'Internet, continueu amb la configuració manual que s'explica a continuació.

1. Prepareu Docker, DNS i l'accés

Connecteu-vos per SSH amb permisos de sudo i feu que el registre A de DNS de n8n.example.com apunti a l'adreça IPv4 del VPS. En un VPS nou amb Ubuntu 22.04, 24.04 o 26.04 , les ordres següents instal·len Docker Engine i el complement modern docker compose des del repositori oficial signat de Docker per a apt:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Aquest és el mètode d'instal·lació amb repositori orientat a producció que descriu la guia oficial de Docker per a Ubuntu. No reinstal·leu ni desinstal·leu Docker a cegues en un VPS que ja executa contenidors o allotja altres llocs web; comproveu primer la instal·lació existent i els possibles conflictes entre paquets. Per a Debian o qualsevol altra distribució, seguiu les instruccions oficials del sistema operatiu corresponent en lloc de les ordres per a Ubuntu.

Ara comproveu Docker, el complement de Compose, el DNS i el directori de treball:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Si getent hosts no retorna cap adreça o en retorna una d'incorrecta, corregiu la configuració DNS abans d'engegar Caddy; substituïu n8n.example.com pel vostre nom d'amfitrió real a tota la guia. Docker normalment requereix permisos de root: si el vostre usuari SSH no pot executar directament les ordres docker compose, anteposeu-hi sudo. Afegir un usuari al grup docker li concedeix permisos equivalents als de root; no ho feu a la lleugera en un servidor compartit.

Manteniu accessible el port SSH d'administració que feu servir abans d'activar el tallafoc. Permeteu les connexions HTTP (80) i HTTPS (443) entrants per a l'emissió de certificats i l'accés a l'editor. Els ports publicats per Docker poden esquivar algunes regles d'UFW; reviseu la documentació de Docker sobre tallafocs i publiqueu només els ports previstos de Caddy. Aquest exemple de Compose expressament no exposa PostgreSQL (5432), n8n (5678) ni el bròquer d'executors de tasques (5679) a Internet.

2. Creeu les variables d'entorn i conserveu la clau

Des del directori del projecte, genereu tres valors hexadecimals aleatoris diferents amb aquesta ordre:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Creeu un fitxer anomenat .env a partir de la plantilla següent. Substituïu cada REPLACE_WITH_RANDOM_HEX per un valor generat diferent i adapteu el nom d'amfitrió i la zona horària. L'etiqueta 2.42.5 correspon a la versió estable publicada el 8 d'octubre de 2026, que aquí s'utilitza com a exemple de configuració datat, no com a garantia que el desplegament s'hagi provat en un entorn real ni que sigui segur en el futur. Abans d'instal·lar, consulteu les versions oficials actuals d'n8n i feu servir la mateixa versió verificada per a les imatges d'n8n i de l'executor de tasques.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

No pugeu mai el fitxer .env a cap repositori públic. Deseu la clau de xifratge i les instruccions de recuperació de manera segura fora del VPS. La clau ha de continuar sent la mateixa després de recrear els contenidors o de migrar el servei.

3. Escriviu compose.yaml per a una instal·lació nova

Al mateix directori, creeu compose.yaml. L'exemple segueix les convencions oficials de variables d'entorn d'n8n i utilitza la ruta PGDATA de PostgreSQL 18 documentada pel projecte d'allotjament d'n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Els quatre serveis tenen funcions diferents: PostgreSQL emmagatzema l'estat de la base de dades, n8n executa els fluxos de treball, n8n-runner executa tasques amb una versió coincident i un testimoni d'autenticació compartit, i Caddy gestiona les connexions HTTPS públiques. Un executor de tasques extern no és el mateix que el mode de cua amb Redis. Només Caddy publica ports de l'amfitrió. Aquest exemple bàsic utilitza un únic rol de base de dades per simplificar la configuració; per separar millor els privilegis de PostgreSQL, consulteu l'exemple oficial de desplegament d'n8n amb PostgreSQL.

4. Creeu el Caddyfile per a HTTPS

Creeu el fitxer Caddyfile (amb C majúscula i sense extensió) al costat de compose.yaml. Substituïu el nom d'amfitrió de l'exemple pel vostre nom DNS a tot arreu:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy sol·licita i renova certificats TLS públics quan el domini es resol correctament i el trànsit extern pot arribar als ports 80/443. No configureu el DNS perquè apunti a localhost. Si substituïu Caddy per un altre proxy invers, reenvieu les capçaleres originals del nom d'amfitrió, el protocol i l'adreça del client, i ajusteu N8N_PROXY_HOPS al nombre real de salts de proxy de confiança.

5. Inicieu els contenidors i feu una prova des de fora

Executeu aquestes ordres des del directori del projecte després de desar .env, compose.yaml i Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

L'última ordre comprova l'endpoint de salut públic amb HTTPS . Si l'emissió del certificat encara està pendent, reviseu els registres de Caddy, el DNS i els ports abans de concloure que n8n no funciona. Obriu https://n8n.example.com, creeu immediatament el primer compte de propietari i activeu les proteccions d'inici de sessió adequades. Comproveu que la instància executa realment un flux de treball, no només que es carrega l'editor:

  1. A l'editor, creeu un flux de treball amb un node activador Webhook . Configureu HTTP Method com a GET; escriviu al camp Path: vps-check i configureu Respond com a Immediately. Deseu el flux de treball.
  2. Feu clic a Listen for Test Event, copieu l'Test URL complet que mostra n8n i, des d'un altre dispositiu, executeu curl -i 'PASTE_TEST_URL_HERE' amb l'URL copiat. Espereu una resposta HTTP correcta i comproveu que l'esdeveniment entrant apareix a l'editor d'n8n. Els URL de prova només funcionen mentre n8n espera l'esdeveniment.
  3. Publiqueu el flux de treball, passeu el node a la seva Production URL, copieu-la i torneu a executar curl -i 'PASTE_PRODUCTION_URL_HERE' . Comproveu-ne l'execució a la pestanya Executions . Les sol·licituds als webhooks de producció requereixen que el flux de treball estigui publicat i no mostren les dades rebudes a la vista de proves de l'editor.

És una prova bàsica deliberadament senzilla i sense autenticació: no hi envieu mai secrets. Despubliqueu o suprimiu el flux de prova després de verificar-lo, o configureu l'autenticació del webhook i les restriccions per IP abans d'utilitzar un endpoint públic amb dades reals. Consulteu la documentació oficial sobre webhooks de prova i de producció.

6. Feu una còpia de seguretat abans de canviar les versions fixades

Deseu un bolcat recuperable de PostgreSQL i el volum persistent de dades d'n8n, el fitxer .env i la clau de xifratge, així com els fitxers externs necessaris, en un emmagatzematge fora d'aquest servidor. Comproveu que podeu restaurar les dades seguint la guia de còpies de seguretat i recuperació abans d'actualitzar el sistema en producció. Exemples d'ordres:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Canvieu el valor fixat de N8N_VERSION només després de llegir les notes de la versió; les imatges d'n8n i de l'executor de tasques s'han d'actualitzar conjuntament. No executeu docker compose down -v durant el manteniment habitual, perquè aquesta ordre elimina els volums de dades amb nom. Els canvis de versió principal de PostgreSQL requereixen una actualització de la base de dades o un pla de bolcat i restauració; substituir la imatge de Postgres 18 per una altra versió principal no migra les dades automàticament.

Fonts de referència: la guia oficial de Docker Compose d'n8n, la configuració d'n8n per a proxies inversos i webhooks i la documentació oficial de desplegament de PostgreSQL. No s'hi pressuposa cap prova de rendiment d'infraestructura ni cap funció preinstal·lada específica del proveïdor.

ERRORS HABITUALS

Per què una instal·lació d'n8n amb Docker funciona en local però falla en producció

URL del webhook incorrecte

Les crides de retorn apunten a localhost, HTTP o un nom d'amfitrió intern en lloc de l'origen HTTPS públic.

Manca de persistència

L'estat de l'aplicació o de la base de dades desapareix quan es recrea un contenidor.

Pèrdua de la clau de xifratge

Les credencials desades deixen de funcionar després de reconstruir la instància perquè la clau de xifratge ha canviat.

Port públic de la base de dades

PostgreSQL queda exposat innecessàriament tot i que només n8n necessita accedir-hi.

PREGUNTES FREQÜENTS

Preguntes habituals sobre la instal·lació d'n8n amb Docker

Cal PostgreSQL per executar n8n amb Docker?

Docker no exigeix PostgreSQL i els desplegaments petits poden utilitzar SQLite. Per a un VPS orientat a producció, PostgreSQL ofereix una base de dades més sòlida i permet escalar posteriorment amb el mode de cua.

Per què cal conservar un volum persistent d'n8n si PostgreSQL emmagatzema les dades?

El directori persistent d'n8n pot contenir dades d'estat i configuracions importants de la instància. Conserveu-lo segons el disseny del desplegament en lloc de suposar que la base de dades és l'únic element necessari per a la recuperació.

Per què el meu webhook mostra localhost?

L'adreça interna del contenidor és diferent de l'origen públic. Configureu el nom d'amfitrió extern, el protocol i l'URL del webhook, i assegureu-vos que el proxy invers reenvia les capçaleres necessàries.

Cal exposar públicament el port 5678?

En un desplegament de producció habitual darrere d'un proxy invers, exposeu HTTPS al proxy i manteniu intern el port de l'aplicació n8n, llevat que hi hagi un motiu operatiu concret per fer-ho d'una altra manera.

Necessito Redis?

No en un desplegament estàndard de Docker amb una sola instància. Redis només és necessari quan passeu expressament al mode de cua amb treballadors.

Els executors de tasques externs d'n8n són el mateix que els treballadors del mode de cua?

No. Els executors de tasques externs executen codi de tasques compatibles fora del procés principal d'n8n i fan servir un testimoni d'autenticació compartit. El mode de cua amb Redis distribueix les execucions dels fluxos de treball i requereix una infraestructura pròpia. Aquest exemple mostra un executor de tasques extern, no el mode de cua de Redis. La versió de la imatge de l'executor ha de coincidir amb la d'n8n.
