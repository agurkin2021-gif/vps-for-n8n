DECISIÓ SOBRE L'ALLOTJAMENT

n8n Cloud vs. n8n autoallotjat

Trieu n8n Cloud si voleu allotjament gestionat, sense haver de mantenir el servidor, i un nombre d'execucions incloses al pla clarament definit. Trieu n8n autoallotjat en un VPS si necessiteu accés root, xarxes privades o una arquitectura d'escalat pròpia i podeu administrar el servidor. Totes dues opcions permeten executar fluxos de treball en producció; cal comparar-ne el cost total, les funcions de cada edició i qui assumeix la seguretat, les còpies de seguretat i la recuperació.

FREQÜÈNCIA D'EXECUCIÓ DELS FLUXOS

Com una programació senzilla pot consumir les execucions incloses a Cloud

Penseu en un flux de treball programat cada cinc minuts durant un mes de 30 dies. Si cada activació programada acaba correctament i compta com una execució, el resultat és 12 execucions per hora × 24 hores × 30 dies = 8,640 execucions. Això supera les 2,500 execucions incloses al pla Starter, tot i tractar-se d'un únic flux de treball. A Cloud, comproveu la quota vigent del pla i la manera com n8n comptabilitza les execucions; en un VPS, examineu la càrrega real del servidor i el consum de recursos, en lloc d'equiparar el nombre d'execucions amb la capacitat.

És un càlcul il·lustratiu, no una prova de rendiment ni una predicció d'ús. Pot sortir més econòmic activar el flux amb un webhook en lloc de fer consultes periòdiques (polling), però trieu els activadors segons els requisits reals de les integracions. Comproveu les execucions incloses als plans oficials de n8n Cloud.

UN TERCER MODEL DE FUNCIONAMENT

Un VPS amb instal·lació d'n8n en un clic no sempre és un servei gestionat

A banda de n8n Cloud oficial i de gestionar un VPS propi, algunes empreses ofereixen allotjament d'n8n preinstal·lat o gestionat. Són ofertes comercials diferents, amb responsabilitats de suport, còpies de seguretat i actualitzacions de programari també diferents. Instal·lar amb un clic simplifica la posada en marxa, però no implica que el proveïdor administri l'aplicació n8n. Quan compareu una oferta de tercers, reviseu el contracte del servei, la retenció de còpies de seguretat, els límits d'execució i la llicència. No és automàticament equivalent a n8n Cloud oficial.

MODEL DE COST REAL

Exemple: quant costa realment un mes d'n8n autoallotjat?

Com a exemple, un VPS Standard autogestionat amb un preu de $0.07 per dia costa $2.10 per 30 dies facturats abans dels serveis addicionals. Una opció més gran, de $0.67 per dia costa $20.10 per 30 dies facturats. Aquests imports només cobreixen el servidor, no el cost total de l'aplicació. Trieu la mida del servidor segons la càrrega de treball real, no segons aquest exemple.

Cost total mensual de l'autoallotjament (TCO) = preu del VPS + còpies de seguretat, emmagatzematge i supervisió de pagament + serveis externs + temps d'administració.

Exemple il·lustratiu: $20.10 de VPS + $5 de despeses recurrents addicionals seleccionades + dues hores d'administració valorades en $20/hora = $65.10 aquell mes.

Alternativa: $2.10 de VPS + cap servei addicional de pagament + cap hora d'administració imputada separadament = $2.10 de cost directe del servidor, però això no elimina les responsabilitats de manteniment ni de recuperació.

Els $5 addicionals, les dues hores i els $20/hora són valors hipotètics, no pressupostos del proveïdor ni estimacions de la vostra càrrega real. A $20/hora, cada hora addicional d'administració incrementa el cost total de l'autoallotjament en $20. El temps de treball no és gratuït pel fet que no aparegui a la factura del proveïdor. Per calcular el llindar de rendibilitat, compareu el pla Cloud que cobreixi les vostres execucions completades, la concurrència i les funcions necessàries amb el VPS, els serveis addicionals i el temps valorat a les vostres tarifes. Consulteu la facturació vigent de Cloud. Les edicions de pagament d'n8n autoallotjat requereixen una llicència independent.

COST TOTAL DE PROPIETAT

Autoallotjar n8n implica més despeses que la factura del VPS

Infraestructura

Incloeu-hi la capacitat de càlcul, l'emmagatzematge, les còpies de seguretat i qualsevol servei extern de base de dades o supervisió que decidiu utilitzar.

Operacions

Les actualitzacions, els pedaços de seguretat, TLS, la supervisió, la resposta a incidents i les proves de restauració requereixen temps. Cal incloure aquesta feina a la comparació.

Volum d'execució

n8n Cloud factura segons el pla i les execucions mensuals completades de fluxos de treball, no segons els passos individuals d'un flux. La Community Edition autoallotjada no té la mateixa quota d'execucions del pla Cloud, però el rendiment efectiu depèn dels recursos de càlcul, la memòria, la base de dades i qualsevol llicència d'n8n contractada per separat.

Cost d'una fallada

Un VPS econòmic deixa de ser-ho si una còpia de seguretat no verificada o una mala actualització provoca una interrupció llarga del servei. Garantir la fiabilitat també forma part de l'autoallotjament.

CONTROL I DADES

On l'autoallotjament canvia l'arquitectura

Sistemes privats

Un desplegament autoallotjat es pot ubicar en una infraestructura amb accés directe a bases de dades privades, API internes i xarxes restringides.

Residència de dades

L'autoallotjament us permet triar una regió de servidor disponible i decidir on funciona la base de dades de l'aplicació. Això no garanteix que totes les dades dels fluxos de treball romanguin a la mateixa regió: les API externes, els proveïdors de models, els registres i les còpies de seguretat poden tractar dades en altres ubicacions. Si teniu obligacions normatives, reviseu tot el flux de dades.

Configuració personalitzada del servidor

Controleu les regles del proxy invers, el tallafoc, l'emmagatzematge, la base de dades, les variables d'entorn i els serveis auxiliars.

Responsabilitat de seguretat

El control implica responsabilitat. En un VPS heu de protegir SSH, TLS, les regles del tallafoc, les credencials, l'accés a la base de dades, les còpies de seguretat i les actualitzacions.

ESCALAT

Comoditat de Cloud vs. control de l'escalat amb autoallotjament

Núvol

El servei gestionat evita que hàgiu de prendre la majoria de decisions sobre l'escalat de la infraestructura. Heu de treballar dins de les capacitats i els límits comercials del pla escollit.

Un únic VPS

Comenceu amb un servidor dimensionat segons les execucions simultànies reals i la mida de les dades. Ampliar els recursos del mateix servidor sol ser la primera resposta més senzilla si la CPU o la RAM estan saturades de manera sostinguda.

Mode de cua

Si la demanda d'execucions paral·leles justifica una arquitectura distribuïda, podeu afegir Redis i workers a l'autoallotjament. Això incrementa la capacitat, però també la complexitat operativa.

Base de dades i emmagatzematge

Escalar n8n també requereix planificar PostgreSQL, la retenció de l'historial d'execucions, les dades binàries i el creixement de les còpies de seguretat, no només la CPU de l'aplicació.

CRITERIS DE DECISIÓ

Quin model de desplegament us convé?

Comenceu amb Cloud

Si preferiu evitar les tasques d'infraestructura abans que tenir control total del servidor, Cloud és l'opció més senzilla.

Utilitzeu un VPS

Si sabeu administrar Linux i Docker i necessiteu controlar la infraestructura, configurar xarxes pròpies o gestionar l'escalat, un VPS s'adapta millor a les vostres necessitats.

No autoallotgeu n8n només per estalviar diners

La factura del servidor pot ser baixa mentre que els costos operatius siguin alts. Autoallotgeu n8n quan el control i els costos de la vostra càrrega de treball justifiquin assumir-ne l'administració.

No trieu Cloud només perquè és més senzill

Si l'accés a xarxes privades, la ubicació de les dades o la personalització de la infraestructura són requisits imprescindibles, la comoditat de Cloud no els resol per si sola.

DIFERÈNCIES ENTRE EDICIONS I LLICÈNCIES

El model d'allotjament i l'edició d'n8n són decisions diferents

n8n Cloud

Els plans de Cloud combinen allotjament gestionat amb límits concrets d'execucions, concurrència, retenció de dades i funcions de col·laboració. L'exemple oficial del pla Starter amb facturació anual inclou 2,500 execucions al mes i 5 execucions simultànies. El pla Pro indica 10,000 execucions mensuals, més concurrència i funcions de gestió de projectes. El pla i el període de contractació importen: trieu-ne un que cobreixi tant els pics d'execucions simultànies com les execucions completades durant el mes. Comproveu la taula oficial de plans Cloud.

Community Edition autoallotjada

Executar n8n al vostre VPS no desbloqueja totes les funcions de pagament. Community Edition ofereix les funcions principals d'automatització, però no inclou automàticament les opcions de col·laboració, governança, assistència, control de versions o funcions empresarials de pagament. Consulteu la taula oficial de funcions de cada edició abans de triar-ne una per a un equip.

Business / Enterprise autoallotjades

Una clau de llicència desbloqueja funcions de pagament en les edicions autoallotjades. Encara que pagueu pel programari, continueu sent responsables d'administrar la infraestructura.

Allotjar n8n per a altres usuaris

Si persones alienes a la vostra organització poden crear o configurar fluxos de treball en una instància d'n8n que els oferiu, no doneu per fet que la llicència gratuïta d'autoallotjament cobreix aquest model de servei. Preguntes freqüents

n8n Cloud vs. n8n autoallotjat: preguntes freqüents

És millor n8n Cloud que autoallotjar n8n?

No sempre. Cloud és preferible quan el que més importa és tenir una infraestructura gestionada amb poca feina d'administració. L'autoallotjament és preferible quan el control de la infraestructura i la personalització del desplegament justifiquen administrar vosaltres mateixos tot el sistema.

És més econòmic autoallotjar n8n?

El preu del VPS pot ser molt inferior al de la subscripció Cloud, però això no garanteix un cost total més baix. Afegiu-hi les còpies de seguretat, la supervisió, el manteniment, el temps d'administració i les funcions de qualsevol edició de pagament. Compareu-ho amb les execucions incloses i els límits dels plans vigents de Cloud. L'exemple anterior mostra el càlcul explícit.

Es pot utilitzar n8n autoallotjat en producció?

Sí. Que el desplegament sigui adequat per a producció depèn de la base de dades, les dades persistents, HTTPS, la seguretat, la supervisió, les còpies de seguretat i els procediments de recuperació.

Cal Redis per autoallotjar n8n?

No. Redis s'utilitza amb el mode de cua i els workers distribuïts. Un VPS amb una sola instància d'n8n no necessita Redis per defecte.

Quan he de triar un VPS?

Trieu un VPS quan el control del servidor, les xarxes privades, la ubicació de les dades o l'escalat autogestionat siguin prou importants per assumir les actualitzacions, la seguretat, la supervisió i la recuperació. El preu del VPS, tot sol, no determina si autoallotjar n8n és més barat.

Què comptabilitza n8n Cloud com una execució?

La facturació d'n8n Cloud es basa en les execucions completades de fluxos de treball, no en els nodes ni en els passos individuals d'una execució. Compareu les execucions mensuals incloses i els límits de concurrència publicats per al pla Cloud que necessiteu.

Puc migrar de n8n Cloud a un servidor autoallotjat?

Planifiqueu l'exportació dels fluxos de treball i com es transferiran les credencials, les claus de xifratge, l'historial d'execucions, els usuaris, els URL dels webhooks i els horaris dels activadors. Exportar fluxos de treball no equival a restaurar tota la base de dades. Proveu la importació i el canvi d'entorn abans de retirar el servei anterior; consulteu la guia de còpies de seguretat i recuperació.

OPERACIONS A LLARG TERMINI

Pot aquest desplegament continuar sent fiable durant anys?

Ni n8n Cloud oficial ni un VPS autoallotjat poden garantir que un flux de treball concret funcioni ininterrompudament durant una dècada. Per a automatitzacions crítiques, esbrineu quines condicions de servei i compromisos de suport s'apliquen, com es detecten les incidències, qui restaura la instància i què passa si falla el desplegament o alguna API externa.

Per a n8n Cloud oficial

Comproveu les condicions de suport publicades del pla, les opcions d'exportació de dades i els procediments davant d'incidències. La infraestructura gestionada redueix l'administració del servidor, però no elimina la necessitat de supervisar els resultats del negoci i els errors de les integracions.

Per a un VPS autoallotjat

Assigneu una persona responsable dels pedaços de seguretat, la supervisió i les actualitzacions. Manteniu còpies de seguretat independents i proveu la restauració en un servidor nou. Planifiqueu com recuperar el servei si falla el VPS, un disc, una regió o una integració de tercers; un preu mensual baix no garanteix fiabilitat.

Els objectius de disponibilitat, assistència i recuperació han de basar-se en condicions de servei documentades i procediments que hàgiu provat, no en promeses de disponibilitat no verificades.

DECISIÓ SOBRE LA MIGRACIÓ

Què canvia quan migreu de n8n Cloud al vostre propi VPS?

Exportar un flux de treball no equival a completar una migració. Prepareu i comproveu el nou entorn abans de desactivar la instància Cloud.

Feu un inventari del desplegament

Enumereu els fluxos de treball actius i programats, les credencials, les variables d'entorn, els secrets de les integracions, els webhooks i els magatzems de dades. Identifiqueu quines funcions depenen del pla Cloud i no de Community Edition.

Prepareu i proveu el nou entorn

Desplegueu una versió d'n8n amb manteniment vigent, emmagatzematge persistent, HTTPS i una base de dades adequada. Proveu cada integració externa i cada credencial per separat: exportar un flux de treball en JSON no garanteix que les credencials siguin transferibles.

Planifiqueu el canvi d'entorn

Actualitzeu de manera planificada els URL de retorn i els webhooks externs. Eviteu executar en paral·lel les còpies dels fluxos activats per horari si les execucions duplicades poden provocar efectes no desitjats. Reserveu temps per comprovar les còpies de seguretat i poder revertir el canvi.

Comproveu què no es transferirà

No doneu per fet que els usuaris de Cloud, els permisos dels projectes, l'historial d'execucions, la configuració de la instància o les funcions de pagament es transferiran automàticament. Verifiqueu si cada conjunt de dades necessari es pot exportar o migrar amb un mètode compatible abans de cancel·lar Cloud.
