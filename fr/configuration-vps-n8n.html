DIMENSIONNEMENT N8N · 2026

Configuration VPS n8n : RAM, CPU et stockage

Il n’existe pas un “minimum officiel” universel pour tous les n8n self-hosted. Dimensionnez selon les données manipulées, les exécutions simultanées, PostgreSQL, les fichiers et les services qui partagent le VPS. Les chiffres 1/2/4/8 Go ci-dessous sont des points de départ pratiques, pas des garanties.

SERP · CONTRADICTIONS

Pourquoi les concurrents annoncent 2, 4 ou 8 Go comme “minimum”

FlowKit

Explique correctement que la RAM est souvent le facteur limitant et que la concurrence/payload comptent davantage que le nombre de workflows.

N8N France

Recommande 4 à 8 Go autour de Coolify, mais le chiffre inclut une couche d’orchestration supplémentaire : ce n’est pas un minimum universel n8n.

HostMyServers

Positionne 2 Go pour usage personnel/petite équipe et 4 Go pour charges plus lourdes.

NVHCloud

Propose 2 Go pour tests, 4 Go pour n8n + PostgreSQL, 8 Go pour production plus lourde, puis davantage pour Queue Mode ou LLM local.

Hostiliate

Affiche 4 Go / 2 vCPU comme minimum, mais ce chiffre est une recommandation de son guide, pas une règle officielle universelle n8n.

iTechGuides

Souligne l’absence de minimum RAM/CPU universel et recommande de mesurer des workflows représentatifs.

Selfhost.dev

Refuse les déploiements PostgreSQL sous 4 Go sur son propre service : c’est une contrainte produit, pas une exigence n8n.

Documentation n8n

Les chiffres publiés dans les prérequis sont illustratifs et basés sur un contexte Cloud/OEM ; la documentation dit explicitement que vos besoins peuvent varier.

RÉPONSE DIRECTE

Repères pratiques pour choisir la taille du VPS

1 Go RAM · 1 vCPU

Apprentissage, très petite automatisation, webhooks légers, faible concurrence. Peu de marge pour PostgreSQL et services annexes.

2 Go RAM · 1 vCPU

Petites APIs, notifications et tâches planifiées. Peut convenir si les payloads restent petits et le chevauchement faible.

4 Go RAM · 2 vCPU

Point de départ pratique pour petite production n8n + PostgreSQL + HTTPS sur un même VPS.

8 Go RAM · 4 vCPU

Plus de marge pour fichiers, gros JSON, Code nodes, transformations locales et pics de concurrence.

Ces repères servent à choisir une première taille. Validez ensuite avec des workflows réels et augmentez seulement si CPU, RAM, I/O ou latence le justifient.

GAP · RAM

La mémoire dépend du volume de données en vol

Une exécution n8n conserve des données pendant le traitement. Les nodes qui copient, transforment ou manipulent des données binaires peuvent faire monter la consommation mémoire rapidement.

Payload JSONLa taille de chaque item et le nombre d’items comptent plus que le nombre de nodes.
Code nodeLes copies de données avant/après traitement peuvent augmenter la mémoire utilisée.
Fichiers binairesPDF, images, audio et archives peuvent saturer la mémoire plus vite que des appels API simples.
ConcurrenceDeux workflows légers exécutés 20 fois en parallèle peuvent consommer plus qu’un gros workflow exécuté seul.

GAP · CPU

Le CPU n’est pas toujours le premier facteur limitant

Workflows I/O

Les appels HTTP et attentes d’API consomment souvent moins de CPU local que des transformations lourdes.

Transformations

Code, parsing, compression, chiffrement et grosses boucles peuvent rendre le CPU dominant.

Concurrence

Plus d’exécutions simultanées signifie davantage de travail en parallèle et de pression sur l’event loop.

Mesure

Regardez le pic CPU pendant vos exécutions représentatives plutôt que la moyenne quotidienne.

POSTGRESQL OU SQLITE

La base change le budget RAM, CPU et disque

SQLite

C’est la base par défaut en self-hosted. Elle réduit le nombre de services à administrer et peut convenir aux petites installations.

PostgreSQL

Ajoute son propre besoin de mémoire, CPU, disque et backup. Pour une petite production structurée, prévoyez-le dans le dimensionnement dès le départ.

Base séparée

Quand la charge augmente, séparer PostgreSQL du VPS n8n peut réduire la compétition sur les ressources et faciliter l’administration.

Queue Mode

Une architecture distribuée utilise PostgreSQL partagé ; SQLite n’est pas adapté à ce modèle.

GAP · DISQUE

Le stockage se dimensionne par croissance, pas par taille initiale de Docker

BaseWorkflows, credentials et exécutions passées occupent progressivement le disque.
RétentionPlus vous gardez longtemps les exécutions détaillées, plus PostgreSQL/SQLite grandit.
Binary dataFichiers et pièces jointes peuvent dominer le stockage total.
LogsReverse proxy, système et monitoring ajoutent aussi du volume.
BackupUne copie locale supplémentaire peut doubler temporairement l’espace nécessaire.
MargeNe dimensionnez pas à 95 % de remplissage : gardez assez d’espace pour maintenance, migrations et croissance.

FORMULE SIMPLE

Comment estimer la charge avant d’acheter

1. ReprésentatifChoisissez vos 3 à 5 workflows les plus lourds.
2. PicEstimez combien peuvent se chevaucher pendant la période la plus chargée.
3. PayloadNotez taille JSON, fichiers et transformations locales.
4. ServicesAjoutez PostgreSQL, reverse proxy, monitoring et autres conteneurs présents sur le même VPS.
5. MesureLancez une charge représentative et observez RAM, CPU, I/O et latence.
6. MargeGardez de la capacité pour pics, maintenance et croissance.

AI / LLM

Un workflow IA n’impose pas automatiquement un gros VPS

API externe

Si le modèle tourne chez OpenAI, Anthropic, Mistral ou un autre fournisseur, votre VPS orchestre surtout les appels et données.

Documents

Parsing, embeddings locaux et gros fichiers peuvent malgré tout augmenter fortement RAM et CPU.

LLM local

Faire tourner Ollama ou un autre modèle local change complètement le dimensionnement et peut exiger beaucoup plus de RAM ou un GPU.

Ne mélangez pas

“n8n avec node IA” et “serveur qui exécute le modèle IA” sont deux charges différentes.

FAQ

Questions fréquentes sur la configuration VPS n8n

Combien de RAM faut-il pour n8n ?

Il n’existe pas de minimum universel. 1/2/4/8 Go sont des repères à valider avec vos workflows et votre concurrence réelle.

2 vCPU suffisent-ils ?

Souvent oui pour une petite production, mais les transformations lourdes et la forte concurrence peuvent demander plus. Mesurez le pic CPU.

PostgreSQL est-il obligatoire ?

Non. SQLite est la base par défaut ; PostgreSQL est optionnel mais pertinent pour beaucoup de déploiements de production et nécessaire dans certaines architectures distribuées.

Pourquoi certains guides recommandent-ils 8 Go ?

Ils incluent parfois Coolify, PostgreSQL ou plusieurs services sur le même VPS. Ce n’est pas un minimum officiel universel n8n.
