INSTALLATION N8N · 2026

Installer n8n sur un VPS avec Docker Compose

Le chemin production n’est pas “docker compose up” puis terminé. Une installation exploitable doit couvrir persistance, domaine, HTTPS, URL publique des webhooks, clé de chiffrement, base de données, vérification et procédure de mise à jour. Docker Compose est aujourd’hui la voie recommandée par la documentation n8n pour un déploiement que vous contrôlez.

GAP · DOC OFFICIELLE 2026

Le “4 Go / 2 vCPU” du nouveau guide Compose ne concerne pas tous les n8n

Le guide Docker Compose actuel de n8n construit aussi le sandbox utilisé par n8n Assistant. Ce sandbox utilise Docker-in-Docker et demande plus de marge. Les 4 Go de RAM / 2 vCPU indiqués dans ce guide sont donc liés à ce stack complet, pas à un minimum universel pour une instance n8n classique.

Production Assistant

La documentation actuelle recommande un sandbox provider adapté à la production plutôt que le sandbox local par défaut.

Conclusion

Ne copiez pas un chiffre de prérequis sans vérifier quel stack il décrit.

PROCÉDURE

Le chemin propre pour installer n8n sur un VPS

1. VPSLinux récent, accès SSH/sudo, ressources adaptées à la charge.
2. DNSCréez un sous-domaine comme n8n.example.com pointant vers le VPS.
3. DockerInstallez Docker Engine et Docker Compose v2, puis vérifiez avec docker compose version.
4. ProjetCréez un dossier dédié et séparez compose, secrets et données persistantes.
5. n8n + DBDémarrez avec SQLite ou ajoutez PostgreSQL selon votre modèle de production.
6. Reverse proxyExposez uniquement HTTPS via Caddy, Traefik, Nginx ou équivalent.
7. VérificationValidez compose, démarrage, logs, HTTPS et endpoint de santé.
8. BackupAvant le premier upgrade, documentez déjà comment restaurer DB, volume et clé.

VARIABLES IMPORTANTES

Configuration minimale à vérifier derrière un reverse proxy

N8N_ENCRYPTION_KEY=<secret-long-et-aléatoire>
N8N_HOST=n8n.example.com
N8N_PROTOCOL=https
N8N_WEBHOOK_URL=https://n8n.example.com/
N8N_PROXY_HOPS=1
GENERIC_TIMEZONE=Europe/Paris
N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true

Important : les documentations/tutoriels qui utilisent encore WEBHOOK_URL sont désormais en retard. La documentation n8n actuelle indique N8N_WEBHOOK_URL et précise que WEBHOOK_URL est dépréciée depuis n8n 2.35.0.

GAP · PERSISTANCE

Le conteneur n’est pas votre sauvegarde

Volume .n8n

Conservez /home/node/.n8n dans un volume persistant. Même avec PostgreSQL, cette zone contient encore des données importantes.

Encryption key

Définissez et sauvegardez une clé stable ; sans elle, les credentials chiffrés restaurés peuvent devenir illisibles.

PostgreSQL

Si vous l’utilisez, son volume et sa stratégie de dump/restore sont séparés du volume n8n.

Compose file

Versionnez la configuration sans y committer les secrets.

POSTGRESQL

SQLite fonctionne ; PostgreSQL est un choix d’architecture

SQLite

Base par défaut, simple pour démarrer et petites installations. Persistez toujours le volume n8n.

PostgreSQL

Recommandé pour beaucoup de productions plus structurées et nécessaire pour certaines architectures distribuées.

Migration

Ajouter PostgreSQL à un nouveau Compose ne migre pas automatiquement les anciennes données SQLite. Traitez cela comme une vraie migration.

Upgrade PostgreSQL

Ne changez pas aveuglément de version majeure de l’image : faites d’abord un dump et suivez la procédure d’upgrade PostgreSQL.

HTTPS & WEBHOOKS

Le reverse proxy doit connaître l’URL publique réelle

n8n écoute généralement en interne sur le port 5678 tandis que votre proxy expose HTTPS sur 443. Sans URL publique explicite, les webhooks enregistrés auprès des services externes peuvent être incorrects.

N8N_WEBHOOK_URLURL HTTPS publique complète.
N8N_PROXY_HOPS=1À utiliser quand un reverse proxy se trouve directement devant n8n.
HeadersLe proxy doit transmettre X-Forwarded-For, X-Forwarded-Host et X-Forwarded-Proto.
TLSLa documentation n8n recommande un reverse proxy pour gérer SSL/TLS et le renouvellement des certificats.

COPY / VERIFY

Commandes de contrôle après déploiement

docker compose version
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n
curl -fsS https://n8n.example.com/healthz

Le but est de vérifier que le fichier Compose est valide, que les services sont réellement démarrés et que l’instance répond derrière HTTPS — pas simplement que la commande s’est terminée sans erreur.

FAQ

Questions fréquentes sur l’installation n8n sur VPS

Docker Compose est-il recommandé ?

Oui. La documentation n8n actuelle oriente vers Docker Compose pour les installations contrôlables et reproductibles.

Faut-il 4 Go / 2 vCPU ?

Pas universellement. Ce chiffre apparaît dans le nouveau guide Compose qui inclut le sandbox n8n Assistant. Un n8n classique doit être dimensionné selon sa propre charge.

WEBHOOK_URL ou N8N_WEBHOOK_URL ?

Utilisez N8N_WEBHOOK_URL. L’ancienne variable WEBHOOK_URL est dépréciée dans les versions actuelles.

PostgreSQL est-il obligatoire ?

Non. SQLite est la base par défaut ; PostgreSQL est un choix fréquent pour la production et certaines architectures distribuées.

Dois-je sauvegarder .n8n même avec PostgreSQL ?

Oui. La documentation recommande de conserver ce volume car il contient encore des données importantes telles que la clé de chiffrement et d’autres éléments d’instance.
