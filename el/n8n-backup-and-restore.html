BACKUP & RECOVERY

Αντίγραφα ασφαλείας και επαναφορά του n8n

Για να δημιουργήσετε αντίγραφα ασφαλείας και να επαναφέρετε τις αυτο-φιλοξενούμενες n8n, προστατέψτε τη βάση δεδομένων SQLite ή μια σταθερή ένδειξη PostgreSQL, τον μόνιμο φάκελο .n8n και το αρχικό κλειδί κρυπτογράφησης, τη διαμόρφωση ανάπτυξης και κάθε εξάρτηση εξωτερικού δυαδικού ή προσαρτημένου αρχείου. Διατηρήστε ένα κρυπτογραφημένο αντίγραφο εκτός VPS και δοκιμάστε την ανάκτηση σε ξεχωριστή παρουσία. Χρησιμοποιήστε την CLI ροή εργασιών και εξαγωγές διαπιστευτηρίων για επιλεκτική ανάκτηση. Οι εξαγωγές JSON από μόνες τους δεν αποτελούν πλήρες αντίγραφο ασφαλείας διακομιστή.

ΓΡΗΓΟΡΟΣ ΕΛΕΓΧΟΣ

Τι πρέπει να προστατεύει ένα αντίγραφο ασφαλείας του n8n

Βάση δεδομένων

Δημιουργήστε αντίγραφα ασφαλείας της βάσης δεδομένων PostgreSQL ή του αρχείου βάσης δεδομένων SQLite που χρησιμοποιείται από την παρουσία. Η βάση δεδομένων περιέχει την κατάσταση του πυρήνα n8n, όπως ροές εργασίας, διαπιστευτήρια και δεδομένα εκτέλεσης.

Κλειδί κρυπτογράφησης

Διατηρήστε το ακριβές κλειδί κρυπτογράφησης n8n ξεχωριστά και με ασφάλεια. Τα αποκατεστημένα κρυπτογραφημένα διαπιστευτήρια εξαρτώνται από το ίδιο κλειδί.

Μόνιμα αρχεία

Συμπεριλάβετε τον μόνιμο κατάλογο δεδομένων n8n και τυχόν προσαρτημένα αρχεία, δυαδική αποθήκευση δεδομένων ή στοιχεία ροής εργασίας στα οποία βασίζεται η ανάπτυξή σας.

Διαμόρφωση ανάπτυξης

Διατηρήστε τα αρχεία Σύνταξης/διαμόρφωσης και τη μη απόρρητη διαμόρφωση που απαιτείται για την εκ νέου κατασκευή της στοίβας. Προστατέψτε τα μυστικά με κατάλληλους ελέγχους πρόσβασης.

ΔΥΟ ΕΦΕΔΡΙΚΑ ΕΠΙΠΕΔΑ

Εξαγωγή δεδομένων έναντι πλήρους ανάκαμψης από καταστροφή

Ροή εργασιών και εξαγωγή διαπιστευτηρίων

Οι εξαγωγές n8n CLI είναι χρήσιμες για τη μετεγκατάσταση, την έκδοση αντιγράφων ροής εργασιών και την επιλεκτική επαναφορά. Τα διαπιστευτήρια μπορούν να εξαχθούν σε κρυπτογραφημένη μορφή και να εισαχθούν αργότερα με το αντίστοιχο κλειδί κρυπτογράφησης. Για να ανακτήσετε μόνο μία ροή εργασίας, χρησιμοποιήστε το μενού με τις τρεις κουκκίδες του προγράμματος επεξεργασίας ροής εργασιών για Λήψη της JSON και, στη συνέχεια, Εισαγωγή από αρχείο σε νέα ροή εργασιών αναθεώρησης ή μεμονωμένη παρουσία. Ελέγξτε τα διαπιστευτήρια, τα αναγνωριστικά ροής εργασίας και τις παραμέτρους κόμβων πριν αντικαταστήσετε μια ζωντανή ροή εργασίας: η επαναφορά της ροής εργασίας JSON δεν επαναφέρει ολόκληρο τον διακομιστή.

Εξαγωγή οντότητας

Η CLI μπορεί να εξάγει οντότητες βάσης δεδομένων για μετακίνηση δεδομένων μεταξύ υποστηριζόμενων τύπων βάσεων δεδομένων. Οι πίνακες ιστορικού εκτέλεσης είναι προαιρετικοί επειδή μπορεί να είναι πολύ μεγάλοι.

Πλήρης ανάκτηση περιστατικών

Για ένα σενάριο νεκρού διακομιστή, προστατέψτε την πραγματική βάση δεδομένων, το κλειδί κρυπτογράφησης, τα μόνιμα δεδομένα και τις εξαρτήσεις ανάπτυξης. Μην υποθέσετε ότι μια ροή εργασίας JSON εξαγωγής ανακατασκευάζει ολόκληρη την παρουσία.

Στιγμιότυπο παρόχου

Ένα στιγμιότυπο VPS είναι χρήσιμο ως πρόσθετο επίπεδο ανάκτησης, αλλά δεν θα πρέπει να είναι το μόνο αντίγραφο και δεν πρέπει να αντικαθιστά ένα ανεξάρτητο επαληθευμένο αντίγραφο ασφαλείας εφαρμογής/βάσης δεδομένων.

ΒΑΣΗ ΔΕΔΟΜΕΝΩΝ

Δημιουργήστε συνεπή αντίγραφα της βάσης δεδομένων

PostgreSQL

Χρησιμοποιήστε μια συνεπή μέθοδο δημιουργίας αντιγράφων ασφαλείας PostgreSQL και αποθηκεύστε το αντίγραφο ασφαλείας που προκύπτει μακριά από το VPS. Ένα αντίγραφο βάσης δεδομένων στον ίδιο αποτυχημένο δίσκο δεν είναι ανάκτηση καταστροφής.

SQLite

Εάν η ανάπτυξη χρησιμοποιεί SQLite, προστατέψτε το αρχείο της βάσης δεδομένων από τον μόνιμο κατάλογο δεδομένων n8n. Αποφύγετε την αντιγραφή μιας βάσης δεδομένων σε μη ασφαλή κατάσταση ενώ αυτή τροποποιείται ενεργά.

Ιστορικό εκτέλεσης

Αποφασίστε εάν τα δεδομένα εκτέλεσης ιστορικού αποτελούν μέρος του στόχου ανάκτησής σας. Μπορεί να κάνει τα αντίγραφα ασφαλείας σημαντικά μεγαλύτερα, επομένως οι απαιτήσεις διατήρησης και συμμόρφωσης θα πρέπει να οδηγήσουν στην επιλογή.

Έκδοση βάσης δεδομένων

Καταγράψτε τη μηχανή βάσης δεδομένων και την έκδοση που χρησιμοποιείται από την ανάπτυξη της πηγής, ώστε να μπορεί να προετοιμαστεί συμβατό ένα περιβάλλον ανάκτησης.

PostgreSQL σε μια Docker Σύνθεστο VPS. Εάν ονομαστεί η υπηρεσία PostgreSQL postgres και η βάση δεδομένων/χρήστης του είναι και τα δύο n8n, η ακόλουθη εντολή δημιουργεί μια συνεπή ένδειξη προσαρμοσμένης μορφής PostgreSQL στον κεντρικό υπολογιστή. Ελέγξτε το πραγματικό σας αρχείο Compose πριν το εκτελέσετε και προσαρμόστε τα διαπιστευτήρια βάσης δεδομένων και τα ονόματα υπηρεσιών. pg_dump μπορεί να παράγει ένα λογικά συνεπές στιγμιότυπο ενώ εκτελείται η PostgreSQL. το κάνει όχι δημιουργήστε αντίγραφα ασφαλείας του ξεχωριστού .n8n φάκελο χρήστη ή εξωτερικά δυαδικά δεδομένα.

# In the Docker Compose project; adapt service, DB and user names
docker compose exec -T postgres pg_dump -U n8n -d n8n -Fc > n8n-postgres.dump
test -s n8n-postgres.dump
# Check that the archive has a readable object list
docker compose exec -T postgres pg_restore --list < n8n-postgres.dump

Ο έλεγχος της λίστας αρχειοθέτησης εντοπίζει προφανή προβλήματα μορφής, αλλά δεν αποδεικνύει ότι τα δεδομένα μπορούν να αποκατασταθούν. Αποθηκεύστε ένα κρυπτογραφημένο αντίγραφο εκτός διακομιστή και κάντε πρόβα επαναφοράς. Χρησιμοποιήστε την επίσημη τεκμηρίωση PostgreSQL pg_dump για επιλογές για συγκεκριμένες βάσεις δεδομένων.

SQLite στην Docker. Για την προεπιλεγμένη ανάπτυξη SQLite, database.sqlite και η παραγόμενη διαμόρφωση κλειδιού κρυπτογράφησης ζωντανά μέσα στο μόνιμο .n8n φάκελο (συνήθως τοποθετείται στο /home/node/.n8n). Ποτέ μην αντιμετωπίζετε ένα απλό ζωντανό αντίγραφο της SQLite ως συνεπές. Σταματήστε το n8n και άλλα προγράμματα εγγραφής βάσης δεδομένων πριν αντιγράψετε το φάκελο ή χρησιμοποιήστε τον υποστηριζόμενο ηλεκτρονικό μηχανισμό δημιουργίας αντιγράφων ασφαλείας της SQLite όταν η διακοπή είναι αδύνατη:

# Only for SQLite and the default /home/node/.n8n mount
# Stop n8n (and any other writers) before copying an SQLite database
docker compose stop n8n
docker compose cp n8n:/home/node/.n8n ./n8n-user-folder-backup
docker compose start n8n

Αυτές είναι επεξηγηματικές εντολές για την υπηρεσία και τη διαδρομή που εμφανίζεται, όχι μια γενική διάταξη τόμου. Ο αντιγραμμένος φάκελος βρίσκεται αρχικά στην ίδια VPS. μεταφορά και προστασία του εκτός διακομιστή. Όταν υπάρχουν workers στην ουρά ή άλλοι συγγραφείς, σταματήστε και αυτούς και ακολουθήστε τον πραγματικό σχεδιασμό ανάπτυξης τους. Η τρέχουσα καθοδήγηση πλήρους αντιγράφου ασφαλείας του n8n τεκμηριώνει την απαίτηση συνοχής SQLite.

Επαναφορά του προεπιλεγμένου φακέλου SQLite σε καθαρό στόχο: πρώτα σταματήστε την υπηρεσία n8n και όλα τα προγράμματα εγγραφής βάσεων δεδομένων. Μόλις υπάρξει ένα συμβατό κοντέινερ υπηρεσίας n8n και ο τόμος προορισμού του, αντιγράψτε το αντίγραφο ασφαλείας .n8n περιεχόμενα πίσω στον ίδιο μόνιμο κατάλογο. Αυτό αντικαθιστά τα αρχεία προορισμού, επομένως μην το εκτελείτε σε μια παρουσία με δεδομένα που πρέπει να διατηρήσετε:

# Run only on the intended CLEAN recovery instance
docker compose stop n8n
docker compose cp ./n8n-user-folder-backup/. n8n:/home/node/.n8n/
# Verify ownership and permissions for the n8n container user BEFORE the next command
# Start only after restored files are readable/writable by n8n
docker compose start n8n
# Check logs, restored credentials and workflow triggers

Η Docker μπορεί να αντιγράψει σε σταματημένα κοντέινερ, αλλά η ιδιοκτησία προορισμού μπορεί να διαφέρει από την αρχική. βεβαιωθείτε ότι η αποκατασταθείσα διαμόρφωση και το αρχείο βάσης δεδομένων είναι αναγνώσιμα και εγγράψιμα με τη διαδικασία n8n πριν την εκκίνηση. Εάν η πραγματική σας διαμόρφωση Compose χρησιμοποιεί διαφορετική βάση διαδρομής ή σύνδεσης, προσαρμόστε το αντίγραφο ανάλογα. Docker Σύνταξη αναφοράς αντιγράφου. Η επαναφορά ενός φακέλου n8n από μόνη της δεν αρκεί για αναπτύξεις που χρησιμοποιούν ξεχωριστή βάση δεδομένων PostgreSQL.

ΚΡΙΣΙΜΟ ΜΥΣΤΙΚΟ

Το κλειδί κρυπτογράφησης είναι απαραίτητο για την επαναφορά

Το n8n κρυπτογραφεί τα αποθηκευμένα διαπιστευτήρια με ένα στιγμιότυπο κλειδί κρυπτογράφησης. Μια βάση δεδομένων ή μια κρυπτογραφημένη εξαγωγή διαπιστευτηρίων χωρίς το αντίστοιχο κλειδί μπορεί να αφήσει τις ροές εργασίας που έχουν αποκατασταθεί να μην μπορούν να χρησιμοποιήσουν τα αποθηκευμένα διαπιστευτήριά τους.

Εάν ορίσετε N8N_ENCRYPTION_KEY, επαναφέρετε αυτό ακριβώς το μυστικό. Διαφορετικά, το κλειδί που δημιουργείται αποθηκεύεται στο μόνιμο αρχείο .n8n/config: προστατεύστε αυτήν τη διαμόρφωση κατά τη δημιουργία αντιγράφων ασφαλείας ή την εκ νέου δημιουργία. Αποθηκεύστε τα κλειδιά ανάκτησης με ασφάλεια έξω από το VPS. Στη λειτουργία ουράς, όλες οι διεργασίες κύριας και εργασίας πρέπει να χρησιμοποιούν το ίδιο κλειδί.

ΚάνετεΚρατήστε ένα προστατευμένο αντίγραφο του ακριβούς κλειδιού που χρησιμοποιείται από την παραγωγή.
ΚάνετεΕπαληθεύστε ότι το περιβάλλον ανάκτησης χρησιμοποιεί αυτό το κλειδί πριν δοκιμάσετε τα διαπιστευτήρια.
ΌχιΒασιστείτε σε ένα κλειδί που δημιουργήθηκε πρόσφατα μετά την εκ νέου κατασκευή του διακομιστή.
ΌχιΔεσμεύστε το κλειδί σε ένα δημόσιο αποθετήριο ή αποθηκεύστε το δίπλα σε ένα μη προστατευμένο αντίγραφο ασφαλείας.

ΑΡΧΕΙΑ & ΔΥΔΙΚΑ ΔΕΔΟΜΕΝΑ

Το αντίγραφο της βάσης δεν καλύπτει πάντα όλες τις εξαρτήσεις

Επίμονα .n8n δεδομένα

Εντοπίστε και διατηρήστε τον πραγματικό φάκελο χρήστη .n8n, όχι μόνο την εικόνα του κοντέινερ. Σε μια τυπική ανάπτυξη Docker προσαρτάται στο /home/node/.n8n; εκτός Docker η προεπιλογή είναι ~/.n8n. Εάν έχει διαμορφωθεί η N8N_USER_FOLDER, το n8n δημιουργεί .n8n μέσα σε αυτόν τον καθορισμένο γονικό κατάλογο. Συμπεριλάβετε το κλειδί διαμόρφωσης και τυχόν τοπικά SQLite, δυαδικά δεδομένα ή δεδομένα εκτέλεσης συστήματος αρχείων που χρησιμοποιεί η εγκατάστασή σας.

Προσαρτημένα αρχεία ροής εργασίας

Εάν οι ροές εργασίας διαβάζουν ή γράφουν καταλόγους που είναι τοποθετημένοι στον κεντρικό υπολογιστή, δημιουργήστε αντίγραφα ασφαλείας αυτών των καταλόγων ξεχωριστά. Η επαναφορά του n8n χωρίς αυτές μπορεί να αφήσει διακοπεί τις έγκυρες ροές εργασίας.

Δυαδικά δεδομένα

Προσδιορίστε τη λειτουργία αποθήκευσης και επαναφέρετε κάθε εξωτερική εξάρτηση. Τα δυαδικά δεδομένα ή τα δεδομένα εκτέλεσης που βασίζονται σε σύστημα αρχείων ενδέχεται να βρίσκονται σε .n8n ή σε έναν προσαρμοσμένο κατάλογο. Το S3/Azure Blob ή άλλος διαμορφωμένος εξωτερικός χώρος αποθήκευσης χρειάζεται τις δικές του ανακτήσιμες ρυθμίσεις αντιγραφής και πρόσβασης. Μια απόρριψη βάσης δεδομένων από μόνη της δεν μπορεί να αντικαταστήσει αυτά τα αρχεία.

Κοινοτικοί κόμβοι

Καταγράψτε πακέτα και εκδόσεις κοινότητας και δημιουργήστε αντίγραφα ασφαλείας τυχόν πρόσθετων προσαρμοσμένων καταλόγων κόμβων που έχουν διαμορφωθεί μέσω της N8N_CUSTOM_EXTENSIONS. Αυτοί οι κατάλογοι μπορούν να βρίσκονται έξω από .n8n; Μόνο μια επαναφορά βάσης δεδομένων και φακέλου χρήστη μπορεί να αφήσει αδύνατες τις ροές εργασίας προσαρμοσμένου κόμβου.

ΣΤΡΑΤΗΓΙΚΗ OFF-SERVER

Ένα αντίγραφο στο ίδιο VPS παραμένει τοπικό αντίγραφο

Τοπικό αντίγραφοΧρήσιμο για γρήγορη επαναφορά, αλλά ευάλωτο σε απώλεια διακομιστή, αποτυχία δίσκου και καταστροφικά λάθη.
Αντίγραφο εκτός διακομιστήΔιατηρήστε τουλάχιστον ένα αντίγραφο ασφαλείας στην αποθήκευση ανεξάρτητα από την παραγωγή VPS.
Αντίγραφα με έκδοσηΔιατηρήστε πολλά σημεία ανάκτησης, ώστε η καταστροφή ή μια κακή αλλαγή να μην αντικαταστήσει το μοναδικό αντίγραφο ασφαλείας που μπορεί να χρησιμοποιηθεί.
Έλεγχος πρόσβασηςΤα αντίγραφα ασφαλείας μπορούν να περιέχουν διαπιστευτήρια, λογική ροής εργασιών και ευαίσθητα επιχειρηματικά δεδομένα. Κρυπτογραφήστε και περιορίστε τα κατάλληλα.
ΠαρακολούθησηΕιδοποίηση όταν τα προγραμματισμένα αντίγραφα ασφαλείας αποτυγχάνουν ή διακόπτουν την παραγωγή νέων σημείων ανάκτησης.

Κάντε το χρονοδιάγραμμα μετρήσιμο. Καταγράψτε τη χρονική σήμανση κάθε επιτυχούς δημιουργίας αντιγράφων ασφαλείας, ολοκλήρωσης μεταφοράς, μέγεθος αρχείου, έκδοση βάσης δεδομένων πηγής, θέση ανάκτησης κλειδιού κρυπτογράφησης και την τελευταία επιτυχημένη δοκιμή επαναφοράς. Ειδοποίηση για αρχεία που λείπουν, απέτυχαν ή απροσδόκητα άδεια. Κρυπτογραφήστε τα αρχεία αντιγράφων ασφαλείας πριν τα στείλετε στο VPS και περιορίστε την πρόσβαση στα μυστικά ανάκτησης. Τα πολλαπλά χρονολογημένα σημεία ανάκτησης προστατεύουν από την ανακάλυψη διαφθοράς μόνο αφού το νεότερο αντίγραφο αντικαταστήσει το τελευταίο υγιές.

Για παράδειγμα, εάν μπορείτε να ανεχτείτε το πολύ έξι ώρες χαμένων αλλαγών, ένα επιτυχημένο πρόγραμμα δημιουργίας αντιγράφων ασφαλείας έξι ωρών αποτελεί σημείο εκκίνησης και όχι εγγύηση: οι αποτυχημένες εργασίες και η καθυστερημένη αναπαραγωγή εκτός διακομιστή μπορούν να αυξήσουν την πραγματική απώλεια. Ρυθμίστε τη διατήρηση και επαναφέρετε τον ρυθμό στις δικές σας απαιτήσεις RPO/RTO και δεδομένων, αντί να υποθέσετε μια καθολική πολιτική 7-ημέρα ή 30 ημερών.

ΑΠΟΚΑΤΑΣΤΑΣΗ ΠΑΡΑΓΓΕΛΙΑΣ

Επαναφέρετε την εγκατάσταση με ελεγχόμενη σειρά βημάτων

1 · ΠροετοιμαστείτεΠαρέχετε έναν συμβατό διακομιστή, βάση δεδομένων και περιβάλλον κοντέινερ/χρόνου εκτέλεσης.
2 · Αποκατάσταση μυστικώνΔιαμορφώστε με ασφάλεια το αρχικό κλειδί κρυπτογράφησης n8n και τα απαιτούμενα μυστικά ανάπτυξης.
3 · Επαναφορά βάσης δεδομένωνΑνακτήστε τις PostgreSQL ή SQLite και βεβαιωθείτε ότι το n8n μπορεί να συνδεθεί στα αναμενόμενα δεδομένα.
4 · Επαναφορά αρχείωνΑνακτήστε μόνιμους καταλόγους, δυαδικά δεδομένα και προσαρτημένα στοιχεία ροής εργασίας.
5 · Έναρξτο n8nΑνεβάστε την εφαρμογή με το αναμενόμενο όνομα κεντρικού υπολογιστή, τη βάση δεδομένων και τη διαμόρφωση περιβάλλοντος.
6 · ΕπικύρωσηΕπιβεβαιώστε τη φόρτωση των χρηστών, των ροών εργασιών και των διαπιστευτηρίων και, στη συνέχεια, εκτελέστε αντιπροσωπευτικές ροές εργασίας και διαδρομές webhook.

PostgreSQL Παράδειγμα αποκατάστασης καταστροφών: σε α ξεχωριστό, καθαρό στόχο επαναφοράς που έχει ήδη τον σωστό ρόλο βάσης δεδομένων και ένα κενό n8n βάση δεδομένων, έναρξη μόνο PostgreSQL. Περιμένετε μέχρι να είναι υγιές πριν την εισαγωγή: docker compose up -d μόνο μπορεί να επιστρέψει ενώ η PostgreSQL είναι ακόμα αρχικοποίηση, άρα ακολουθεί pg_restore μπορεί να αποτύχει. Το παράδειγμα χρησιμοποιεί --wait σε μια σύγχρονη εγκατάσταση Compose και ελέγχει ανεξάρτητα pg_isready. Διαμορφώστε έναν κατάλληλο έλεγχο υγείας PostgreSQL για αξιόπιστη αναμονή ή επιβεβαιώστε ρητά την ετοιμότητα πριν προχωρήσετε. Μην κατευθύνετε αυτήν την εντολή σε μια συμπληρωμένη βάση δεδομένων παραγωγής και μην ξεκινήσετε το n8n πριν από τη βάση δεδομένων και την αντιστοίχιση της .n8n κλειδί/δεδομένα αποκαθίστανται.

# RESTORE ONLY TO A FRESH, EMPTY TARGET DATABASE
# Adapt Postgres Compose service, database and user names
docker compose up -d --wait postgres
docker compose exec -T postgres pg_isready -U n8n -d n8n
docker compose exec -T postgres pg_restore --exit-on-error --no-owner --no-acl -U n8n -d n8n < n8n-postgres.dump

Ο προορισμός πρέπει να έχει συμβατή έκδοση PostgreSQL, δικαιώματα ρόλου, επεκτάσεις και αρχική διαμόρφωστο n8n. Επαναφορά .n8n στη σωστή μόνιμο τόμο ή στη βάση σύνδεσης χρησιμοποιώντας τον μηχανισμό δημιουργίας αντιγράφων ασφαλείας, διατηρώντας την ιδιοκτησία και τα δικαιώματα. Επαναφέρετε εξωτερικά δυαδικά αρχεία, προσαρμοσμένες επεκτάσεις, Σύνταξη και διαμόρφωση μυστικών και, στη συνέχεια, ξεκινήστε το n8n σε μια συμβατή έκδοση και ελέγξτε τα αρχεία καταγραφής της. PostgreSQL: ΠΕΡΑΣΜΑΕισήγαγε την ίδια δοκιμαστική ροή εργασίας, δημιούργησε και επιθεώρησε μια προσαρμοσμένη μορφή pg_dump, το αποκατέστησε χρησιμοποιώντας pg_restore σε μια νέα κενή βάση δεδομένων PostgreSQL, επαναφέρατε το ξεχωριστό .n8n φάκελο, στη συνέχεια επανεξήχθη και εκτελέστηκε η ανακτημένη ροή εργασίας.
Τι θεσπίζει το PASSΟι δοκιμασμένες εφεδρικές διαδρομές διατήρησαν αυτή τη ροή εργασίας, τους δύο κόμβους και τις συνδέσεις τους και επέτρεψαν την εκτέλεση μετά την ανάκτηση. Αυτά είναι αναπαραγώγιμα λειτουργικά τεστ καπνού, όχι δείκτες αναφοράς φόρτου εργασίας.
Αυτό που δεν δοκιμάστηκεΑποκρυπτογράφηση και έλεγχος ταυτότητας πραγματικών διαπιστευτηρίων, webhooks παραγωγής, workers σε λειτουργία ουράς και Redis, δυαδικής αποθήκευσης S3/Azure, προσαρμοσμένων κόμβων, πρόσβασης χρήστη/έργου ή ανάκτηση μιας ζωντανής παρουσίας παραγωγής. Επιβεβαιώστε την ηλικία δημιουργίας αντιγράφων ασφαλείας, τον μετρημένο χρόνο διακοπής λειτουργίας και την προσβασιμότητα εκτός διακομιστή. Παράδειγμα μαζικής εξαγωγής για την Docker Σύνθεση: εάν η υπηρεσία n8n έχει όνομα n8n, μπορείτε να εκτελέσετε τα επίσημα αντίγραφα ασφαλείας CLI παρακάτω. Η διαδρομή εξόδου είναι εσκεμμένα μέσα στο τοποθετημένο μόνιμο .n8n κατάλογο, επειδή οι αυθαίρετοι κατάλογοι μέσα σε ένα κοντέινερ μπορεί να εξαφανιστούν όταν αναδημιουργηθεί. Επιβεβαιώστε ότι ο κατάλογος είναι εγγράψιμος από τον χρήστη του κοντέινερ n8n. Διατηρήστε τη ροή εργασιών και τα διαπιστευτήρια JSON ξεχωριστούς καταλόγους—n8n τεκμηριώνει ένα πρόβλημα εισαγωγής όταν και τα δύο είδη μοιράζονται έναν κατάλογο.

n8n 2.x πρόχειρο έναντι δημοσιευμένου αντιγράφου ασφαλείας: ένα κανονικό --backup Η εξαγωγή ροής εργασιών καταγράφει τα τρέχοντα πρόχειρα. Αυτές μπορεί να διαφέρουν από τις εκδόσεις που δημοσιεύονται στην παραγωγή. Για να διατηρήσετε την πραγματική δημοσιευμένη έκδοση μιας συγκεκριμένης ροής εργασίας, εξαγάγετε τη χωριστά χρησιμοποιώντας docker compose exec -T n8n n8n export:workflow --id=WORKFLOW_ID --published --output=/home/node/.n8n/backups/published-workflow.json, αφού βεβαιωθείτε ότι ο φάκελος εξόδου υπάρχει και είναι εγγράψιμος. Η CLI μπορεί επίσης να εξάγει μια ιστορική έκδοση χρησιμοποιώντας --version=VERSION_ID. Διατηρήστε αυτές τις λήψεις εκτός διακομιστή μαζί με το πλήρες αντίγραφο ασφαλείας. μην υποθέσετε ότι το σχέδιο JSON καταγράφει τη ζωντανή δημοσιευμένη κατάσταση.

# Execute from your Docker Compose project; the n8n service must exist
# Keep workflow and credential backups in DIFFERENT folders
docker compose exec -T n8n n8n export:workflow --backup --output=/home/node/.n8n/backups/workflows/
docker compose exec -T n8n n8n export:credentials --backup --output=/home/node/.n8n/backups/credentials/
# Copy the saved export directories OUT of the container to the host
mkdir -p ~/n8n-recovery
docker compose cp n8n:/home/node/.n8n/backups ~/n8n-recovery/cli

Το αντιγραμμένο ~/n8n-recovery/cli Ο κατάλογος βρίσκεται ακόμα στο VPS μέχρι να τον μετακινήσετε σε μια ασφαλή, ανεξάρτητη θέση δημιουργίας αντιγράφων ασφαλείας. Η εξαγωγή διαπιστευτηρίων είναι κρυπτογραφημένη από προεπιλογή και χρειάζεται το αντίστοιχο κλειδί κρυπτογράφησης κατά την εισαγωγή. Αποφύγετε τη χρήση --decrypted εκτός από μια αυστηρά ελεγχόμενη μετανάστευση: γράφει μυστικά σε απλό κείμενο. Ποτέ μην δεσμεύετε εξαγωγές που περιέχουν ευαίσθητη λογική ροής εργασίας ή διαπιστευτήρια σε δημόσιο χώρο αποθήκευσης GitHub. Ορισμένα GitHub πρότυπα αντιγράφων ασφαλείας διαπιστευτηρίων τρίτων εξάγουν σκόπιμα αποκρυπτογραφημένα μυστικά. ένα ιδιωτικό αποθετήριο είναι περιορισμός πρόσβασης, όχι κρυπτογράφηση. Επιθεωρήστε τις πραγματικές ρυθμίσεις εξαγωγής και τα δικαιώματα αποθήκευσης κάθε προτύπου, κρυπτογραφήστε μυστικά πριν από τη μεταφορά εκτός διακομιστή και περιστρέψτε τυχόν διαπιστευτήρια που εκτίθενται μέσω μιας ακούσιας μεταφόρτωσης απλού κειμένου.

Παράδειγμα μαζικής εισαγωγής: σε έναν καθαρό στόχο, ολοκληρώστε τη ρύθμιση του κατόχου, παρέχετε το αρχικό κλειδί κρυπτογράφησης και βεβαιωθείτε ότι τα αποθηκευμένα αρχεία αντιγράφων ασφαλείας είναι διαθέσιμα σε αυτήν την ανάκτηστο VPS. Το παρακάτω δημιουργεί τον φάκελο προορισμού και τον αντιγράφει workflows/ και credentials/ υποφακέλους από τον κεντρικό υπολογιστή στο κοντέινερ n8n. προσαρμόστε τις διαδρομές εάν η διάταξη της έντασης Docker διαφέρει:

# Run only on the intended CLEAN recovery instance
docker compose exec -T n8n mkdir -p /home/node/.n8n/backups
docker compose cp ~/n8n-recovery/cli/. n8n:/home/node/.n8n/backups/

Ελέγξτε την ιδιοκτησία και την πρόσβαση του αρχείου για τον χρήστη κοντέινερ n8n. Μην κάνετε εισαγωγή σε μια συμπληρωμένη παρουσία παραγωγής χωρίς επαληθευμένη επαναφορά: η ροή εργασίας και τα αναγνωριστικά διαπιστευτηρίων μπορούν να αντικαταστήσουν τις υπάρχουσες καταχωρίσεις. Στη συνέχεια, τρέξτε:

# After fresh-instance owner setup AND providing the correct key
# Copy saved cli/ contents back under the target n8n service's .n8n/backups/
docker compose exec -T n8n n8n import:workflow --separate --input=/home/node/.n8n/backups/workflows/
docker compose exec -T n8n n8n import:credentials --separate --input=/home/node/.n8n/backups/credentials/

Τα εισαγόμενα αναγνωριστικά μπορούν να αντικαταστήσουν υπάρχουσες ροές εργασίας ή διαπιστευτήρια. χρησιμοποιήστε ένα μεμονωμένο δείγμα δοκιμής για ξηρές εκτελέσεις και ελέγξτε τα διαπιστευτήρια και τις καταστάσεις ενεργοποίησης/δημοσίευσης στη συνέχεια. Στο n8n 2.x, η επαναφορά του προχείρου της JSON δεν αποδεικνύει από μόνη της ότι έχει δημοσιευθεί μια ροή εργασίας και μπορεί να εκτελέσει προγραμματισμένες ενεργοποιήσεις. Ασφάλεια εισαγωγής: σε μια παρουσία n8n που δεν είναι πολλαπλών βασικών, οι ενεργοποιητές cron που ήταν ενεργοί στο παρελθόν μπορούν να συνεχίσουν να εκτελούνται μετά την εισαγωγή της CLI έως ότου επανεκκινηθεί η παρουσία. Διακόψτε ή απομονώστε τους ενεργοποιητές παραγωγής και επανεκκινήστε το n8n πριν ενεργοποιήσετε τις εργασίες που έχουν αποκατασταθεί. βεβαιωθείτε ότι δεν υπάρχει διπλότυπη εκτέλεση. CLI οι εξαγωγές κάνουν όχι περιέχει αρχικούς χρήστες, αρχεία καταγραφής εκτέλεσης, μεταβλητές παρουσίας ή το κλειδί κρυπτογράφησης. --backup σετ --all --pretty --separate, όχι «πλήρης εμφάνιση». Πηγές: τρέχων επίσημος οδηγός δημιουργίας αντιγράφων ασφαλείας/επαναφοράς n8n και αναφορά εντολής n8n CLI.

Πρέπει να δημιουργήσω αντίγραφα ασφαλείας PostgreSQL ή να εξαγάγω ροές εργασίας και διαπιστευτήρια;

Για αποκατάσταση από καταστροφή, προστατέψτε τη βάση δεδομένων και το κλειδί κρυπτογράφησης. Οι λογικές εξαγωγές είναι πολύτιμες ως πρόσθετο επίπεδο μετανάστευσης και επιλεκτικής ανάκτησης παρά ως υποκατάστατο για κάθε μέρος του στιγμιότυπου.

Μπορεί ένα στιγμιότυπο VPS να είναι το μοναδικό μου αντίγραφο ασφαλείας;

Αντιμετωπίζεται καλύτερα ως ένα στρώμα ανάκτησης. Διατηρήστε ένα ανεξάρτητο αντίγραφο ασφαλείας εκτός διακομιστή, ώστε μια αποτυχία παρόχου, λογαριασμού, διακομιστή ή στιγμιότυπου να μην καταργεί κάθε σημείο ανάκτησης ταυτόχρονα.

Πώς μπορώ να ξέρω ότι το αντίγραφο ασφαλείας μου λειτουργεί;

Επαναφέρετέ το σε ένα καθαρό περιβάλλον δοκιμής, επαληθεύστε τα διαπιστευτήρια αποκρυπτογράφησης και εκτελέστε αντιπροσωπευτικές ροές εργασίας. Μια επιτυχημένη εργασία δημιουργίας αντιγράφων ασφαλείας από μόνη της δεν αποδεικνύει δυνατότητα ανάκτησης.

Περιλαμβάνουν αποθηκευμένα μυστικά διαπιστευτηρίων τα GitHub ή τα αντίγραφα ασφαλείας της ροής εργασίας του Google Drive;

Τα αντίγραφα ασφαλείας JSON μόνο στη ροή εργασίας δεν περιλαμβάνουν τις μυστικές τιμές που διαχειρίζεται ο χώρος αποθήκευσης διαπιστευτηρίων του n8n ή το κλειδί κρυπτογράφησης παρουσίας. Ωστόσο, η εξαγόμενη JSON μπορεί να εκθέσει ονόματα διαπιστευτηρίων και αναγνωριστικά και μυστικά πληκτρολογημένα απευθείας σε παραμέτρους κόμβων, όπως κεφαλίδες ελέγχου ταυτότητας. Επιθεωρήστε και προστατέψτε την εξαγόμενη JSON πριν τη ανεβάσετε ή την κοινοποιήσετε. Για πλήρη ανάκτηση, δημιουργήστε αντίγραφα ασφαλείας της βάσης δεδομένων και του αρχικού κλειδιού ή χρησιμοποιήστε υποστηριζόμενες εξαγωγές κρυπτογραφημένων διαπιστευτηρίων CLI με δοκιμασμένη επαναφορά. Ένα πρότυπο GitHub μόνο για ροή εργασιών ή Google Drive δεν είναι πλήρης ανάκτηση από καταστροφή.

ΣΤΟΧΟΙ ΑΝΑΚΤΗΣΗΣ

Ορίστε RPO και RTO πριν προκύψει συμβάν

RPO είναι η μέγιστη ανεκτή απώλεια πρόσφατων αλλαγών. Μετρήστε το από το νεότερο χρησιμοποιήσιμο, ανεξάρτητα αποθηκευμένο σημείο ανάκτησης. μια προγραμματισμένη εργασία έξι ωρών δεν καθιερώνει εξάωρη RPO εάν οι εξαγωγές ή οι μεταφορές αποτύχουν. RTO είναι η μέγιστη ανεκτή διακοπή λειτουργίας. Μετρήστε το σε ένα καθαρό τρυπάνι επαναφοράς, συμπεριλαμβανομένης της ανάκτησης μυστικών, της επαναφοράς εξωτερικών αρχείων, του επανέλεγχου των διαπιστευτηρίων και της δημοσίευσης ανακτημένων ροών εργασίας—όχι απλώς εκκίνησης ενός κοντέινερ.

ΚΛΕΙΔΙ ΑΝΑΚΤΗΣΗΣ

Εντοπίστε το αρχικό κλειδί κρυπτογράφησης πριν την επανεγκατάσταση

Εάν έχει οριστεί η παραγωγή N8N_ENCRYPTION_KEY, διατηρήστε αυτό ακριβώς το μυστικό του περιβάλλοντος. Εάν δεν το έκανε, διατηρήστε το κλειδί που δημιουργήθηκε στο αρχικό μόνιμο .n8n/config. Ελέγξτε ποια πηγή χρησιμοποιεί πραγματικά το ανακτημένο στιγμιότυπο πριν εισαγάγετε κρυπτογραφημένα διαπιστευτήρια. ένα νέο κλειδί που δημιουργήθηκε δεν μπορεί να αποκρυπτογραφήσει τα διαπιστευτήρια από την παλιά βάση δεδομένων.
