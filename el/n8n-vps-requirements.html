Μια προσεκτικά μεγέθους 1 vCPU / 1 GB VPS μπορεί να τρέξει μικρούς αυτοματισμούς πάντα ενεργούς, ενώ το 2 vCPU / 4 GB RAM είναι μια πρακτική αρχική τάξη για το n8n με PostgreSQL και HTTPS. Τα μεγάλα ωφέλιμα φορτία, οι ταυτόχρονες εκτελέσεις και η τοπική επεξεργασία δεδομένων απαιτούν περισσότερο χώρο. μετρήστε την πραγματική χρήση πριν επιλέξετε.

Μνήμη / OOM

Έλεγχος docker stats --no-stream και free -h. Εάν η μνήμη έχει εξαντληθεί, πρώτα μειώστε τα JSON ή τα δυαδικά ωφέλιμα φορτία, ομαδοποιήστε μεγάλες εισαγωγές και αποφύγετε τα βήματα Κώδικα που είναι βαριά για μνήμη. Ένα σφάλμα σωρού JavaScript δεν διορθώνεται απαραίτητα με την προσθήκη vCPU.

CPU / συγχρονισμός

Μετρήστε εάν η CPU παραμένει απασχολημένη κατά τη διάρκεια των μετασχηματισμών ή οι εργασίες περιμένουν μόνο εξωτερικά API. Σε κανονική λειτουργία, εξετάστε ένα υποστηριζόμενο όριο παραγωγής-συγχρονισμού πριν από την κλιμάκωση στους workers. Η αύξηση της CPU δεν επιταχύνει μια API περιορισμένης τιμής εξωτερικού.

Αποθήκευση / βάση δεδομένων

Έλεγχος df -h, μέγεθος βάσης δεδομένων και διατηρημένο ιστορικό εκτέλεσης. Παρακολουθήστε την ανάπτυξη του δίσκου και τις αργές λειτουργίες της βάσης δεδομένων. Ρυθμίστε τη διατήρηση σκόπιμα πριν πληρώσετε για μεγαλύτερο δίσκο. κρατήστε τα αντίγραφα ανάκτησης εκτός διακομιστή.

Χρησιμοποιήστε την καθοδήγηση συγχρονισμού του n8n και την επίσημη εξήγηση συγκριτικής αξιολόγησης. Οποιοσδήποτε αριθμός ταυτόχρονων ροών εργασίας διαφημίζεται χωρίς να γνωρίζουμε το ωφέλιμο φορτίο και την καθυστέρηση API είναι απλώς μια εκτίμηση.

SQLite, PostgreSQL και μόνιμη αποθήκευση δεδομένων

SQLite

Το SQLite μπορεί να χωρέσει μικρές αναπτύξεις και δοκιμές μίας παρουσίας. Καθώς η χρήση παραγωγής και η ταυτόχρονη ανάπτυξη αυξάνονται, η επιλογή της βάσης δεδομένων γίνεται λειτουργικός περιορισμός παρά λεπτομέρεια εγκατάστασης.

PostgreSQL

Για μια στοίβα VPS προσανατολισμένη στην παραγωγή, η PostgreSQL παρέχει μια ισχυρότερη βάση δεδομένων. Προϋπολογισμός RAM, CPU και δίσκος για την ίδια τη βάση δεδομένων και παρακολουθήστε την ανάπτυξή της.

Επίμονα .n8n δεδομένα

Μην αντιμετωπίζετε την PostgreSQL ως το μόνο μόνιμο περιουσιακό στοιχείο. Διατηρήστε τον κατάλογο δεδομένων n8n και προστατέψτε το κλειδί κρυπτογράφησης που απαιτείται για την ανάκτηση κρυπτογραφημένων διαπιστευτηρίων.

Ανάπτυξη δίσκου

Το ιστορικό εκτέλεσης, τα δυαδικά δεδομένα, τα αρχεία βάσης δεδομένων και τα αρχεία καταγραφής μπορούν να επεκταθούν με την πάροδο του χρόνου. Οι ρυθμίσεις διατήρησης και τα αντίγραφα ασφαλείας εκτός διακομιστή επηρεάζουν άμεσα την απαιτούμενη χωρητικότητα.

ΧΩΡΗΤΙΚΟΤΗΤΑ ΔΙΣΚΟΥ

Υπολογίστε τον χώρο για το ιστορικό εκτελέσεων πριν παραγγείλετε

Ξεκινήστε με αποθηκευμένες εκτελέσεις ανά ημέρα × μέσος όρος αποθηκευμένων byte ανά εκτέλεση × ημέρες διατήρησης. Για παράδειγμα, 500 αποθηκευμένες εκτελέσεις ανά ημέρα × 200 KB κάθε × 14 ημέρες = 1.4 GB παραδείγματος δεδομένων εκτέλεσης πριν από την επιβάρυνση της βάσης δεδομένων. Αυτή η υπόθεση 200 KB είναι ενδεικτική, όχι ένα σημείο αναφοράς n8n.

Εκχωρήστε επίσης δίσκο για το λειτουργικό σύστημα, επίπεδα εικόνας Docker, ευρετήρια βάσης δεδομένων, δυαδικά αρχεία, αρχεία καταγραφής εφαρμογών, αναβαθμίσεις και προσωρινά αρχεία. Τα αντίγραφα ασφαλείας εκτός διακομιστή χρειάζονται τη δική τους χωρητικότητα. Ένας δίσκος 10 GB μπορεί να λειτουργήσει για μια λιτή στοίβα, αλλά έχει πολύ λιγότερο χώρο για αρχεία που διατηρούνται από έναν δίσκο 40 ή 80 GB.

Το n8n τεκμηριώνει το κλάδεμα προεπιλεγμένης εκτέλεσης κατά ηλικία (336 ώρες / 14 ημέρες) ή πλήθος (10,000 εκτελέσεις), με εξαιρέσεις. Ελέγξτε τις πραγματικές ρυθμίσεις σας και επαληθεύστε τι διατηρείται πριν τις αλλάξετε. Η SQLite μπορεί να επαναχρησιμοποιήσει τον ελεύθερο χώρο αντί να συρρικνώσει αυτόματα το αρχείο του.

Πηγή: n8n: διαχείριση δεδομένων εκτέλεσης και κλαδέματος. Οι απαιτήσεις του δίσκου εξαρτώνται από τα παρατηρούμενα μεγέθη αποθηκευμένου ωφέλιμου φορτίου, όχι μόνο από τον αριθμό των κόμβων.

Το n8n τεκμηριώνει επίσης περιορισμούς για την αποθήκευση δυαδικών δεδομένων του συστήματος αρχείων σε λειτουργία ουράς, επομένως επικυρώστε μια συμβατή σχεδίαση αποθήκευσης δεδομένων πριν από την εναλλαγή.
