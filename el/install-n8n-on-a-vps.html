Εγκατάσταση του n8n σε VPS

Εγκαταστήστε το n8n σε ένα VPS χρησιμοποιώντας Docker Σύνθεση και PostgreSQL. Μια ανάπτυξη παραγωγής χρειάζεται επίσης μόνιμα δεδομένα εφαρμογής και βάσης δεδομένων, ένα σταθερό N8N_ENCRYPTION_KEY, ένα δημόσιο όνομα κεντρικού υπολογιστή, HTTPS και σωστή διαμόρφωση webhook. Επαληθεύστε αυτά τα κομμάτια πριν ενεργοποιήσετε τις ροές εργασιών παραγωγής.

Τείχος προστασίας

Εκθέστε μόνο τις απαιτούμενες θύρες διαχείρισης και ιστού. Διατηρήστε ιδιωτικές την PostgreSQL και τις εσωτερικές υπηρεσίες εφαρμογών.

Εγκατάσταση σε VPS που φιλοξενεί ήδη ιστότοπους; Μπορείτε να προσθέσετε n8n σε έναν διακομιστή που ελέγχετε όταν το επιτρέπουν οι CPU, RAM και ο χώρος αποθήκευσης. Ωστόσο, εάν οι Nginx, Apache, Caddy ή άλλος αντίστροφος διακομιστής μεσολάβησης έχουν ήδη τις θύρες 80/443, κάντε όχι ξεκινήστε το κοντέινερ του παραδείγματος Caddy παρακάτω αμετάβλητο: οι θύρες θα έρθουν σε διένεξη. Αντ 'αυτού, δρομολογήστε έναν νέο υποτομέα n8n μέσω του υπάρχοντος αντίστροφου διακομιστή μεσολάβησης με κατάλληλη ιδιωτική δικτύωση ή χρησιμοποιήστε μια καθαρή VPS για το ακριβές παράδειγμα Σύνταξης. Διατηρήστε τις άλλες τοποθεσίες και τη διαμόρφωσή τους TLS. Το παράδειγμα προϋποθέτει ότι οι θύρες 80/443 είναι διαθέσιμες.

Εγκαταστήστε το n8n στο VPS με Docker Compose

Χρησιμοποιήστε αυτό το παράδειγμα για να δημιουργήσετε μια ανάπτυξτο n8n σε ένα αυτοδιαχειριζόμενος Linux VPS. Εγκαθιστάτε και συντηρείτε το n8n μόνοι σας. Η επιλογή διακομιστή μέσω του συνεργάτη μας δεν περιλαμβάνει προεγκατεστημένη παρουσία n8n. Το παράδειγμα συνδυάζει n8n, PostgreSQL, μια εξωτερική εκτέλεση εργασιών και Caddy HTTPS σε ένα ιδιωτικό δίκτυο Σύνταξης. Είναι ένα πρότυπο διαμόρφωσης, δεν είναι ισχυρισμός για μια ζωντανά δοκιμασμένη ανάπτυξη.

Θέλετε την ταχύτερη νέα εγκατάσταση; Το n8n παρέχει επίσης μια επίσημη ρύθμιση Docker μιας γραμμής. Μπορείτε να κατεβάσετε και να ελέγξετε το σενάριό του με curl -fsSL https://get.n8n.io -o get-n8n.sh πριν τρέξετε sh get-n8n.sh. Αυτή η επιλογή εκκινεί μια αρχική παρουσία με SQLite σε μια τοπική διεύθυνση URL και περιλαμβάνει n8n υπηρεσίες sandbox Βοηθού. είναι όχι το ίδιο όπως αυτή η δημόσια ανάπτυξη HTTPS, PostgreSQL VPS. Η επίσημη στοίβα πλήρους sandbox χρειάζεται περισσότερες RAM και CPU από μια απλή εγκατάσταστο n8n (ο οδηγός Σύνθεσης καθορίζει τουλάχιστον 4 GB RAM / 2 vCPU). Για μια παραγωγή που έχει πρόσβαση στο Διαδίκτυο VPS, συνεχίστε με τη χειροκίνητη διαμορφωμένη στοίβα παρακάτω.

1. Προετοιμάστε τα Docker, DNS και αποκτήστε πρόσβαση

Συνδέστε μέσω SSH με πρόσβαση sudo και υποδείξτε a DNS Μια εγγραφή για n8n.example.com στη διεύθυνσή σας VPS IPv4. Σε ένα φρέσκο Ubuntu 22.04, 24.04 ή 26.04 VPS, οι ακόλουθες εντολές εγκαθιστούν Docker Engine και το σύγχρονο docker compose plugin από την επίσημη υπογραφή της Docker apt αποθετήριο:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Αυτή είναι η μέθοδος αποθήκευσης προσανατολισμένη στην παραγωγή στον επίσημο οδηγό εγκατάστασης Docker Ubuntu. Μην επανεγκαθιστάτε ή αφαιρείτε τυφλά την Docker σε κοντέινερ VPS που ήδη εκτελούνται ή άλλους ιστότοπους; πρώτα επιθεωρήστε την υπάρχουσα εγκατάσταση και πιθανές διενέξεις πακέτων. Για το Debian ή άλλη διανομή, χρησιμοποιήστε τις αντίστοιχες επίσημες οδηγίες για το λειτουργικό σύστημα αντί για τις εντολές Ubuntu.

Τώρα επαληθεύστε την ίδια την Docker, την προσθήκη Compose, την DNS και τον κατάλογο εργασίας:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Αν getent hosts δεν επιστρέφει διεύθυνση ή λάθος διεύθυνση, διορθώστε την DNS πριν ξεκινήσετε την Caddy. αντικαταστήστε n8n.example.com σε αυτόν τον οδηγό με το πραγματικό σας όνομα κεντρικού υπολογιστή. Η Docker απαιτεί κανονικά δικαιώματα root: εάν ο χρήστης SSH δεν μπορεί να εκτελέσει το τελευταίο docker compose εντολές απευθείας, προσαρτήστε τες με sudo. Προσθήκη χρήστη στο docker Η ομάδα χορηγεί πρόσβαση ισοδύναμη με τη ρίζα και δεν πρέπει να γίνεται τυχαία σε κοινόχρηστο διακομιστή.

Διατηρήστε προσβάσιμη την πραγματική θύρα διαχείρισης SSH πριν ενεργοποιήσετε ένα τείχος προστασίας. Επιτρέψτε τις εισερχόμενες HTTP (80) και HTTPS (443) για την έκδοση πιστοποιητικού και τον επεξεργαστή. Οι θύρες κοντέινερ που δημοσιεύονται στην Docker μπορούν να παρακάμψουν ορισμένους κανόνες UFW, επομένως ανατρέξτε στις οδηγίες του τείχους προστασίας της Docker και δημοσιεύστε μόνο τις προβλεπόμενες θύρες Caddy. Αυτό το παράδειγμα Σύνθεσης το κάνει σκόπιμα όχι δημοσιεύστε τις PostgreSQL (5432), n8n (5678) ή τον μεσίτη (5679) στο δημόσιο Διαδίκτυο.

2. Δημιουργήστε αξίες περιβάλλοντος και διατηρήστε το κλειδί

Από τον κατάλογο του έργου, δημιουργήστε τρία διαφορετικά τυχαίες δεκαεξαδικές τιμές με:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Δημιουργήστε ένα αρχείο με όνομα .env χρησιμοποιώντας το παρακάτω πρότυπο, αντικαταστήστε κάθε REPLACE_WITH_RANDOM_HEX με διαφορετική παραγόμενη τιμή και αλλάξτε το όνομα κεντρικού υπολογιστή και τη ζώνη ώρας. Το εμφανιζόμενο 2.42.5 η ετικέτα είναι το σταθερή έκδοση που αναφέρεται στην 8 Οκτώβριος 2026, που χρησιμοποιείται εδώ ως χρονολογημένο παράδειγμα διαμόρφωσης, δεν αποτελεί εγγύηση για μια ζωντανά δοκιμασμένη ανάπτυξη ή για μελλοντική ασφάλεια. Πριν την εγκατάσταση, ελέγξτε τις τρέχουσες επίσημες εκδόσεις n8n και, στη συνέχεια, διατηρήστε το n8n και την εικόνα του προγράμματος εκτέλεσης εργασιών στην ίδια επαληθευμένη έκδοση.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Μην δεσμευτείτε ποτέ .env σε δημόσιο αποθετήριο. Αποθηκεύστε το κλειδί κρυπτογράφησης και τις οδηγίες ανάκτησης με ασφάλεια εκτός του VPS. Το κλειδί πρέπει να παραμένει το ίδιο μετά την αναψυχή ή τη μετανάστευση κοντέινερ.

3. Γράψτε compose.yaml για νέα εγκατάσταση

Στον ίδιο κατάλογο, δημιουργήστε compose.yaml. Το παράδειγμα χρησιμοποιεί τις επίσημες συμβάσεις περιβαλλοντικής μεταβλητής n8n και την PostgreSQL 18 PGDATA διαδρομή που τεκμηριώνεται από το έργο φιλοξενίας n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Οι τέσσερις υπηρεσίες έχουν διακριτούς ρόλους: η PostgreSQL αποθηκεύει την κατάσταση της βάσης δεδομένων, το n8n εκτελεί ροές εργασίας, n8n-runner εκτελεί εργασίες εκτέλεσης με αντίστοιχη έκδοση και κοινόχρηστο διακριτικό ελέγχου ταυτότητας και η Caddy χειρίζεται τη δημόσια HTTPS. Ένα εξωτερικό δρομέας εργασιών δεν είναι Redis λειτουργία ουράς. Μόνο η Caddy δημοσιεύει θύρες κεντρικού υπολογιστή. Αυτή η λιτή απεικόνιση χρησιμοποιεί έναν ενιαίο ρόλο βάσης δεδομένων για εγκατάσταση. για ισχυρότερο διαχωρισμό των προνομίων PostgreSQL, συμβουλευτείτε το επίσημο παράδειγμα ανάπτυξης n8n PostgreSQL.

4. Δημιουργήστε το HTTPS Caddyfile

Δημιουργήστε το αρχείο Caddyfile (κεφαλαίο Γ, χωρίς επέκταση) παράλληλα compose.yaml. Αντικαταστήστε το παράδειγμα ονόματος κεντρικού υπολογιστή παντού με το δικό σας όνομα DNS:

n8n.example.com {
    reverse_proxy n8n:5678
}

Η Caddy ζητά και ανανεώνει δημόσια πιστοποιητικά TLS όταν ο τομέας επιλύεται σωστά και η εξωτερική κίνηση μπορεί να φτάσει στις θύρες 80/443. Μην υποδείξετε την DNS προς localhost. Εάν αντικαταστήσετε την Caddy με άλλο αντίστροφο διακομιστή μεσολάβησης, προωθήστε τον αρχικό κεντρικό υπολογιστή, το πρωτόκολλο και τις κεφαλίδες διεύθυνσης-πελάτη και προσαρμόστε N8N_PROXY_HOPS για τον πραγματικό αριθμό των αξιόπιστων διακομιδών μεσολάβησης.

5. Ξεκινήστε τα δοχεία και δοκιμάστε από έξω

Εκτελέστε αυτές τις εντολές από τον κατάλογο του έργου μετά την αποθήκευση .env, compose.yaml και Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Η τελευταία εντολή ελέγχει το δημόσιο HTTPS καταληκτικό σημείο της υγείας. Εάν η έκδοση πιστοποιητικού εξακολουθεί να εκκρεμεί, επιθεωρήστε τα αρχεία καταγραφής Caddy και τις DNS/θύρες προτού συμπεράνετε ότι το n8n είναι κατεστραμμένη. Ανοίξτε https://n8n.example.com, δημιουργήστε αμέσως τον πρώτο λογαριασμό κατόχου και ενεργοποιήστε τις κατάλληλες προστασίες σύνδεσης. Επιβεβαιώστε ότι το στιγμιότυπο εκτελεί πραγματικά μια ροή εργασίας, όχι απλώς ότι το πρόγραμμα επεξεργασίας φορτώνει:

  1. Στο πρόγραμμα επεξεργασίας, δημιουργήστε μια ροή εργασίας με a Webhook έναυσμα. Σετ HTTP Μέθοδος να GET, επιλέξτε το Path vps-check, και ορίστε Απαντήστε να Αμέσως. Αποθηκεύστε τη ροή εργασίας.
  2. Κάντε κλικ Ακούστε το Test Event, αντιγράψτε το πλήρες Δοκιμαστική διεύθυνση URL εμφανίζεται από το n8n και από άλλη συσκευή εκτελείται curl -i 'PASTE_TEST_URL_HERE' με την αντιγραμμένη διεύθυνση URL. Αναμένετε μια απάντηση επιτυχίας HTTP και το εισερχόμενο συμβάν να εμφανιστεί στο πρόγραμμα επεξεργασίας n8n. Οι δοκιμαστικές διευθύνσεις URL λειτουργούν μόνο όταν το n8n ακούει το συμβάν.
  3. Δημοσίευση τη ροή εργασίας, αλλάξτε τον κόμβο σε αυτόν URL παραγωγής, αντιγράψτε το και εκτελέστε το curl -i 'PASTE_PRODUCTION_URL_HERE' πάλι. Επιβεβαιώστε την εκτέλεση κάτω από τη ροή εργασιών Εκτελέσεις καρτέλα. Τα αιτήματα webhook παραγωγής χρειάζονται τη δημοσίευση της ροής εργασίας και δεν εμφανίζουν το ωφέλιμο φορτίο τους στη δοκιμαστική προβολή του συντάκτη.

Αυτό είναι ένα σκόπιμα απλό, μη πιστοποιημένο τεστ καπνού: μην του στέλνετε ποτέ μυστικά. Καταργήστε τη δημοσίευσή του/διαγράψτε το μετά τη δοκιμή ή διαμορφώστε τους περιορισμούς ελέγχου ταυτότητας/IP του Webhook πριν χρησιμοποιήσετε ένα δημόσιο τελικό σημείο για πραγματικά δεδομένα. Δείτε την επίσημη τεκμηρίωση δοκιμής/παραγωγής Webhook.

6. Δημιουργήστε αντίγραφα ασφαλείας πριν αλλάξετε τις καρφιτσωμένες εκδόσεις

Αποθηκεύστε μια ανακτήσιμη ένδειξη PostgreSQL και ο μόνιμος όγκος δεδομένων n8n, .env/κλειδί κρυπτογράφησης και απαιτούμενα εξωτερικά αρχεία για αποθήκευση εκτός αυτού του διακομιστή. Επαληθεύστε μια επαναφορά χρησιμοποιώντας το οδηγός δημιουργίας αντιγράφων ασφαλείας και ανάκτησης πριν από την ενημέρωση της παραγωγής. Παραδείγματα εντολών:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Αλλάξτε το καρφιτσωμένο N8N_VERSION μόνο μετά την ανάγνωση των σημειώσεων έκδοσης. Και οι δύο εικόνες n8n και δρομείς πρέπει να προωθηθούν μαζί. Μην τρέχετε docker compose down -v κατά τη διάρκεια της τακτικής συντήρησης, επειδή αυτό διαγράφει ονομασμένους τόμους δεδομένων. PostgreSQL οι αλλαγές σε μεγάλες εκδόσεις απαιτούν αναβάθμιση βάσης δεδομένων ή σχέδιο απόθεσης/επαναφοράς. Η αντικατάσταση της εικόνας Postgres 18 με διαφορετική κύρια ετικέτα δεν αποτελεί αυτόματη μετεγκατάσταση.

Συχνές ερωτήσεις

Εγκατάσταση n8n με Docker: συχνές ερωτήσεις

Χρειάζεται το n8n PostgreSQL όταν χρησιμοποιείται η Docker;

Η Docker δεν απαιτεί PostgreSQL και μικρές αναπτύξεις μπορούν να χρησιμοποιήσουν την SQLite. Για μια ανάπτυξτο VPS προσανατολισμένη στην παραγωγή, η PostgreSQL παρέχει μια ισχυρότερη βάση δεδομένων και υποστηρίζει μεταγενέστερη κλιμάκωση σε λειτουργία ουράς.

Γιατί να διατηρήσετε έναν μόνιμο τόμο n8n εάν το PostgreSQL αποθηκεύει δεδομένα;

Ο μόνιμος κατάλογος n8n μπορεί να περιέχει σημαντική κατάσταση και διαμόρφωση παρουσίας. Διατηρήστε το σύμφωνα με το σχέδιο ανάπτυξης αντί να υποθέσετε ότι η βάση δεδομένων είναι το μόνο στοιχείο ανάκτησης.

Γιατί το webhook μου εμφανίζει localhost;

Η εσωτερική διεύθυνση του κοντέινερ διαφέρει από τη δημόσια προέλευση. Διαμορφώστε το όνομα εξωτερικού κεντρικού υπολογιστή, το πρωτόκολλο και τη διεύθυνση URL του webhook και βεβαιωθείτε ότι ο αντίστροφος διακομιστής μεσολάβησης περνά τις απαιτούμενες κεφαλίδες.

Πρέπει η θύρα 5678 να είναι δημόσια;

Για μια κανονική ανάπτυξη παραγωγής πίσω από έναν αντίστροφο διακομιστή μεσολάβησης, εκθέστε την HTTPS στο διακομιστή μεσολάβησης και διατηρήστε τη θύρα εφαρμογής n8n εσωτερική, εκτός εάν υπάρχει συγκεκριμένος επιχειρησιακός λόγος να μην το κάνετε.

Χρειάζομαι Redis;

Όχι για μια τυπική ανάπτυξη Docker μιας παρουσίας. Η Redis γίνεται σχετική όταν μετακινείστε σκόπιμα σε λειτουργία ουράς και workers.

Είναι οι εξωτερικοί δρομείς εργασιών n8n ίδιοι με τους workers της λειτουργίας ουράς;

Όχι. Οι εξωτερικοί δρομείς εργασιών εκτελούν τον υποστηριζόμενο κώδικα εργασίας ξεχωριστά από την κύρια διαδικασία n8n και χρησιμοποιούν ένα κοινόχρηστο διακριτικό ελέγχου ταυτότητας. Η Redis λειτουργία ουράς διανέμει τις εκτελέσεις ροής εργασιών και έχει τις δικές της απαιτήσεις υποδομής. Αυτό το παράδειγμα δείχνει μια εξωτερική λειτουργία εκτέλεσης εργασιών, όχι Redis λειτουργία ουράς. Αντιστοιχίστε την έκδοση εικόνας δρομέα με την έκδοστο n8n.
