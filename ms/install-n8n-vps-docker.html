PEMASANGAN DOCKER

Pasang n8n pada VPS

Pasang n8n pada VPS menggunakan Docker Compose dan PostgreSQL. Pelaksanaan produksi juga memerlukan data aplikasi dan pangkalan data persisten, N8N_ENCRYPTION_KEY yang kekal, nama hos awam, HTTPS dan konfigurasi webhook yang betul. Sahkan semua komponen ini sebelum mengaktifkan aliran kerja produksi.

PRASYARAT

Sediakan VPS sebelum memulakan n8n

VPS Linux

Gunakan pelayan Linux yang masih diselenggara dan mempunyai sumber yang sesuai untuk n8n, PostgreSQL, Docker dan reverse proxy.

DNS

Arahkan domain atau subdomain ke VPS sebelum menerbitkan sijil TLS dan menerbitkan URL webhook.

Docker Compose

Pasang Docker Engine dan plugin Compose menggunakan pakej yang disokong untuk sistem operasi anda.

Firewall

Dedahkan hanya port pentadbiran dan web yang diperlukan. Kekalkan PostgreSQL dan perkhidmatan aplikasi dalaman sebagai persendirian.

Memasang pada VPS yang sudah mengehos laman web? Anda boleh menambah n8n pada pelayan yang anda kawal jika CPU, RAM dan storan mencukupi. Namun, jika Nginx, Apache, Caddy atau reverse proxy lain sudah menggunakan port 80/443, jangan jalankan kontena Caddy contoh di bawah tanpa perubahan kerana port akan bertembung. Sebaliknya, halakan subdomain n8n baharu melalui reverse proxy sedia ada menggunakan rangkaian persendirian yang sesuai, atau gunakan VPS bersih untuk mengikuti contoh Compose ini. Kekalkan laman web lain dan konfigurasi TLS mereka; contoh ini menganggap port 80/443 tersedia.

PEMASANGAN SALIN-DAN-SESUAIKAN

Pasang n8n pada VPS anda dengan Docker Compose

Gunakan contoh ini untuk membina pelaksanaan n8n pada VPS Linux yang diurus sendiri. Anda memasang dan menyelenggara n8n sendiri; memilih pelayan melalui rakan niaga kami tidak termasuk instans n8n yang diprapasang. Contoh ini menggabungkan n8n, PostgreSQL, task runner luaran dan Caddy HTTPS dalam rangkaian Compose persendirian. Ini ialah templat konfigurasi, bukan dakwaan bahawa pelaksanaan ini telah diuji secara langsung.

Mahukan pemasangan baharu yang paling pantas? n8n turut menyediakan persediaan Docker satu baris rasmi. Anda boleh memuat turun dan menyemak skripnya dengan curl -fsSL https://get.n8n.io -o get-n8n.sh sebelum menjalankan sh get-n8n.sh. Pilihan itu melancarkan instans awal menggunakan SQLite pada URL setempat dan menyertakan perkhidmatan sandbox n8n Assistant; ia tidak sama dengan pelaksanaan VPS HTTPS awam berasaskan PostgreSQL dalam panduan ini. Tindanan sandbox rasmi penuh memerlukan lebih banyak RAM dan CPU berbanding pemasangan n8n yang ringan (panduan Compose menetapkan sekurang-kurangnya 4 GB RAM / 2 vCPU). Untuk VPS produksi yang terdedah kepada internet, teruskan dengan tindanan yang dikonfigurasi secara manual di bawah.

1. Sediakan Docker, DNS dan akses

Sambung melalui SSH dengan akses sudo dan arahkan rekod DNS A bagi n8n.example.com kepada alamat IPv4 VPS anda. Pada VPS Ubuntu 22.04, 24.04 atau 26.04 yang baharu, arahan berikut memasang Docker Engine dan plugin docker compose moden daripada repositori apt rasmi Docker yang ditandatangani:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Ini ialah kaedah repositori berorientasikan produksi dalam panduan pemasangan rasmi Docker untuk Ubuntu. Jangan pasang semula atau buang Docker secara sembarangan pada VPS yang sudah menjalankan kontena atau laman web lain; semak dahulu pemasangan sedia ada dan kemungkinan konflik pakej. Untuk Debian atau distribusi lain, gunakan arahan rasmi khusus sistem operasi yang sepadan, bukan arahan Ubuntu.

Sekarang sahkan Docker itu sendiri, plugin Compose, DNS dan direktori kerja:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Jika getent hosts tidak mengembalikan alamat atau memberikan alamat yang salah, betulkan DNS sebelum memulakan Caddy; gantikan n8n.example.com di seluruh panduan ini dengan nama hos sebenar anda. Docker biasanya memerlukan keistimewaan root: jika pengguna SSH anda tidak boleh menjalankan arahan docker compose seterusnya secara langsung, awali dengan sudo. Menambah pengguna ke kumpulan docker memberikan akses setara root dan tidak patut dilakukan sewenang-wenangnya pada pelayan yang dikongsi.

Pastikan port pentadbiran SSH sebenar kekal boleh dicapai sebelum mengaktifkan firewall. Benarkan HTTP masuk (80) dan HTTPS (443) untuk pengeluaran sijil serta akses editor. Port kontena yang diterbitkan oleh Docker boleh memintas sesetengah peraturan UFW, jadi semak panduan firewall Docker dan terbitkan hanya port Caddy yang diperlukan. Contoh Compose ini sengaja tidak menerbitkan PostgreSQL (5432), n8n (5678) atau broker task runner (5679) ke internet awam.

2. Cipta nilai persekitaran dan simpan kunci

Daripada direktori projek, jana tiga nilai heksadesimal rawak yang berbeza dengan:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Cipta fail bernama .env menggunakan templat di bawah, gantikan setiap REPLACE_WITH_RANDOM_HEX dengan nilai berbeza yang dijana, kemudian ubah nama hos dan zon masa. Tag 2.42.5 yang ditunjukkan ialah keluaran stabil yang disenaraikan pada 8 Oktober 2026 dan digunakan sebagai contoh konfigurasi bertarikh, bukan jaminan bahawa pelaksanaan ini telah diuji secara langsung atau akan kekal selamat pada masa hadapan. Sebelum memasang, semak keluaran rasmi n8n semasa, kemudian kekalkan n8n dan imej task runner pada versi disahkan yang sama.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Jangan sekali-kali commit .env ke repositori awam. Simpan kunci penyulitan dan arahan pemulihan dengan selamat di luar VPS. Kunci mesti kekal sama selepas kontena dicipta semula atau selepas migrasi.

3. Cipta compose.yaml untuk pemasangan baharu

Dalam direktori yang sama, cipta compose.yaml. Contoh ini menggunakan konvensyen pemboleh ubah persekitaran rasmi n8n dan laluan PGDATA PostgreSQL 18 yang didokumenkan oleh projek pengehosan n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Keempat-empat perkhidmatan mempunyai peranan berbeza: PostgreSQL menyimpan keadaan pangkalan data, n8n menjalankan aliran kerja, n8n-runner menjalankan tugas runner menggunakan versi yang sepadan dan token pengesahan bersama, manakala Caddy mengendalikan HTTPS awam. Task runner luaran bukan Redis Queue Mode. Hanya Caddy menerbitkan port hos. Contoh ringkas ini menggunakan satu peranan pangkalan data untuk persediaan; untuk pemisahan keistimewaan PostgreSQL yang lebih ketat, rujuk contoh pelaksanaan PostgreSQL rasmi n8n.

4. Cipta Caddyfile HTTPS

Cipta fail Caddyfile (huruf C besar, tanpa extension) di sebelah compose.yaml. Gantikan nama hos contoh di semua tempat dengan nama DNS anda sendiri:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy meminta dan memperbaharui sijil TLS awam apabila domain resolve dengan betul dan trafik luaran boleh mencapai port 80/443. Jangan arahkan DNS ke localhost. Jika anda menggantikan Caddy dengan reverse proxy lain, teruskan header hos asal, protokol dan alamat klien, kemudian laraskan N8N_PROXY_HOPS mengikut bilangan hop proxy dipercayai yang sebenar.

5. Mulakan kontena dan uji dari luar

Jalankan arahan ini dari direktori projek selepas menyimpan .env, compose.yaml dan Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Arahan terakhir memeriksa health endpoint HTTPS awam. Jika pengeluaran sijil masih belum selesai, semak log Caddy serta DNS/port sebelum menyimpulkan bahawa n8n rosak. Buka https://n8n.example.com, cipta akaun pemilik pertama dengan segera dan aktifkan perlindungan log masuk yang sesuai. Sahkan bahawa instans benar-benar menjalankan aliran kerja, bukan sekadar memuatkan editor:

  1. Dalam editor, cipta aliran kerja dengan pencetus Webhook. Tetapkan HTTP Method kepada GET, pilih Path vps-check dan tetapkan Respond kepada Immediately. Simpan aliran kerja.
  2. Klik Listen for Test Event, salin Test URL penuh yang ditunjukkan oleh n8n, kemudian dari peranti lain jalankan curl -i 'PASTE_TEST_URL_HERE' menggunakan URL tersebut. Jangkakan respons HTTP berjaya dan acara masuk muncul dalam editor n8n. Test URL hanya berfungsi ketika n8n sedang mendengar acara ujian.
  3. Publish aliran kerja, tukar node kepada Production URL, salin URL itu dan jalankan curl -i 'PASTE_PRODUCTION_URL_HERE' sekali lagi. Sahkan pelaksanaan pada tab Executions aliran kerja. Permintaan webhook produksi memerlukan aliran kerja diterbitkan dan payload tidak dipaparkan dalam paparan ujian editor.

Ini ialah ujian asas yang sengaja dibuat ringkas dan tanpa pengesahan: jangan hantar rahsia melaluinya. Nyahterbit atau padam selepas ujian, atau konfigurasikan pengesahan Webhook/sekatan IP sebelum menggunakan endpoint awam untuk data sebenar. Rujuk dokumentasi rasmi Webhook untuk ujian dan produksi.

6. Buat sandaran sebelum menukar versi yang dipinkan

Simpan dump PostgreSQL yang boleh dipulihkan serta volum data n8n persisten, .env/kunci penyulitan dan fail luaran yang diperlukan dalam storan di luar pelayan ini. Sahkan pemulihan menggunakan panduan sandaran dan pemulihan sebelum mengemas kini produksi. Contoh arahan:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Tukar N8N_VERSION yang dipinkan hanya selepas membaca nota keluaran; imej n8n dan imej runner mesti dinaik taraf bersama. Jangan jalankan docker compose down -v semasa penyelenggaraan rutin kerana arahan itu memadam volum data bernama. Perubahan versi major PostgreSQL memerlukan naik taraf pangkalan data atau pelan dump/pemulihan; menggantikan imej Postgres 18 dengan tag major lain bukan migrasi automatik.

Rujukan rasmi: panduan n8n Docker Compose, konfigurasi reverse proxy/webhook n8n dan nota pelaksanaan PostgreSQL rasmi. Tiada penanda aras infrastruktur atau ciri prapasang khusus penyedia yang diandaikan.

PENGESAHAN SELEPAS PELAKSANAAN

Sahkan keadaan sistem sebelum menyambungkan aliran kerja sebenar

Semak keadaan kontena

Semak health endpoint n8n

Dengan contoh Compose di atas, port 5678 tidak diterbitkan pada hos. Selepas menukar nama hos, semak endpoint awam menggunakan curl -fsS https://n8n.example.com/healthz, dan gunakan docker compose ps bersama log perkhidmatan jika HTTPS atau pangkalan data belum sedia.

Jangan anggap kemas kini imej terapung yang belum disemak sebagai strategi penyelenggaraan. Catat versi n8n yang anda jalankan, baca nota keluaran dan buat sandaran sebelum menukarnya.

Menukar hanya tag imej major Postgres boleh menjadikan direktori data sedia ada tidak serasi. Buat sandaran dan ikut prosedur naik taraf pangkalan data, bukannya menganggap penciptaan semula kontena melakukan migrasi versi major.

FAQ

Memasang n8n dengan Docker: soalan lazim

Adakah n8n memerlukan PostgreSQL apabila menggunakan Docker?

Docker tidak memerlukan PostgreSQL dan pelaksanaan kecil boleh menggunakan SQLite. Untuk pelaksanaan VPS berorientasikan produksi, PostgreSQL menyediakan asas pangkalan data yang lebih kukuh dan menyokong penskalaan Queue Mode pada masa hadapan.

Mengapa perlu mengekalkan volum n8n persisten jika PostgreSQL menyimpan data?

Direktori n8n persisten boleh mengandungi keadaan dan konfigurasi instans penting. Kekalkannya mengikut reka bentuk pelaksanaan dan jangan anggap pangkalan data ialah satu-satunya aset pemulihan.

Mengapa webhook saya memaparkan localhost?

Alamat kontena dalaman berbeza daripada origin awam. Konfigurasikan nama hos luaran, protokol dan URL webhook, serta pastikan reverse proxy meneruskan header yang diperlukan.

Patutkah port 5678 didedahkan kepada awam?

Untuk pelaksanaan produksi biasa di belakang reverse proxy, dedahkan HTTPS pada proxy dan kekalkan port aplikasi n8n sebagai dalaman kecuali terdapat sebab operasi khusus untuk sebaliknya.

Adakah saya memerlukan Redis?

Tidak untuk pelaksanaan Docker satu instans standard. Redis menjadi relevan apabila anda sengaja beralih ke Queue Mode dan worker.

Adakah task runner luaran n8n sama dengan worker Queue Mode?

Tidak. Task runner luaran menjalankan kod tugas yang disokong secara berasingan daripada proses utama n8n dan menggunakan token pengesahan bersama. Redis Queue Mode mengagihkan pelaksanaan aliran kerja dan mempunyai keperluan infrastrukturnya sendiri. Contoh ini menunjukkan task runner luaran, bukan Redis Queue Mode. Padankan versi imej runner dengan versi n8n.
