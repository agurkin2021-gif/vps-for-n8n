PEMASANGAN DOCKER

Instal n8n di VPS

Instal n8n di VPS menggunakan Docker Compose dan PostgreSQL. Deployment produksi juga memerlukan aplikasi persisten dan data pangkalan data yang stabil N8N_ENCRYPTION_KEY, hostname awam, HTTPS dan konfigurasi webhook yang benar. sahkan bagian-bagian ini sebelum mengaktifkan aliran kerja produksi.

PRASYARAT

Siapkan VPS sebelum menginstal n8n

VPS Linux

Gunakan pelayan Linux yang dikelola dengan saiz untuk n8n, PostgreSQL, Docker dan reverse proxy.

DNS

Arahkan domain atau subdomain ke VPS sebelum menerbitkan sijil TLS dan menerbitkan URL webhook.

Pasang Docker Engine dan plugin Compose menggunakan pakej yang disokong untuk sistem operasi anda.

Firewall

Ekspos hanya administrasi dan port web yang diperlukan. Jaga kerahasiaan PostgreSQL dan perkhidmatan aplikasi internal.

Menginstal pada VPS yang sudah menghosting situs web? anda boleh menambahkan n8n ke pelayan yang anda kontrol apabila CPU, RAM dan storan mengizinkannya. Namun, jika Nginx, Apache, Caddy atau reverse proxy lainnya sudah memiliki port 80/443, lakukan tidak mulai contoh kontena Caddy di bawah ini tanpa perubahan: port akan konflik. Sebagai gantinya, rutekan subdomain n8n baru melalui reverse proxy yang ada dengan rangkaian pribadi yang sesuai, atau gunakan VPS yang bersih untuk contoh Compose yang tepat. Pertahankan situs lain dan konfigurasi TLS; contoh ini mengasumsikan bahwa port 80/443 tersedia.

INSTALASI SALINAN DAN ADAPTASI

Instal n8n di VPS anda dengan Docker Compose

Gunakan contoh ini untuk membangun deployment n8n di a dikelola sendiri VPS Linux. anda menginstal dan memelihara n8n sendiri; memilih pelayan melalui mitra kami tidak menyertakan instance n8n yang sudah diinstal sebelumnya. Contoh ini menggabungkan n8n, PostgreSQL, task runner luaran dan Caddy HTTPS di rangkaian Compose pribadi. Ini adalah templat konfigurasi, bukan klaim deployment yang diuji langsung.

Mahukan pemasangan baharu yang paling pantas? n8n juga menyediakan persediaan satu baris Docker resmi. anda boleh mengunduh dan menyemak skripnya dengan curl -fsSL https://get.n8n.io -o get-n8n.sh sebelum berlari sh get-n8n.sh. Opsi tersebut meluncurkan instance awal dengan SQLite di URL setempat dan mencakup n8n perkhidmatan sandbox Asisten; dia tidak sama seperti deployment VPS dengan HTTPS awam dan PostgreSQL ini. Stack sandbox resmi lengkap memerlukan lebih banyak RAM dan CPU daripada instalasi n8n ringan (panduan Compose menetapkan setidaknya 4 GB RAM / 2 vCPUs). Untuk VPS produksi yang terhubung ke internet, lanjutkan dengan stack yang dikonfigurasi secara manual di bawah.

1. Siapkan Docker, DNS dan akses

Hubungkan melalui SSH dengan akses sudo dan arahkan a DNS Catatan untuk n8n.example.com ke alamat VPS IPv4 anda. Pada a segar Ubuntu 22.04, 24.04 atau 26.04 VPS, arahan berikut menginstal Docker Engine dan modern docker compose plugin dari resmi Docker ditandatangani apt repositori:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Ini adalah kaedah repositori berorientasikan produksi dalam panduan instalasi resmi Docker Ubuntu. Jangan menginstal ulang atau menghapus Docker secara membabi buta pada VPS kontena atau situs web lain yang sudah berjalan; pertama-tama semak instalasi yang ada dan kemungkinan konflik pakej. Untuk Debian atau distribusi lainnya, gunakan instruksi resmi khusus OS yang sesuai, bukan arahan Ubuntu.

Sekarang sahkan Docker itu sendiri, plugin Compose, DNS dan direktori kerja:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Jika getent hosts tidak mengembalikan alamat atau alamat yang salah, perbaiki DNS anda sebelum memulakan Caddy; ganti n8n.example.com sepanjang panduan ini dengan hostname asli anda. Docker biasanya memerlukan hak akses root: jika pengguna SSH anda tidak boleh menjalankannya nanti docker compose arahan secara langsung, awali dengan sudo. Menambahkan pengguna ke docker grup memberikan akses yang setara dengan root dan tidak boleh dilakukan dengan santai di pelayan bersama.

Jaga agar port administrasi SSH anda yang sebenar boleh dicapai sebelum mengaktifkan firewall. Izinkan masuk HTTP (80) dan HTTPS (443) untuk pengeluaran sijil dan editor. Port kontena yang diterbitkan Docker boleh melewati beberapa aturan UFW, jadi tinjau panduan firewall Docker dan publikasikan hanya port Caddy yang diperlukan. Contoh Compose ini sengaja melakukannya tidak mempublikasikan PostgreSQL (5432), n8n (5678) atau broker pelaksana tugas (5679) ke internet awam.

2. Buat nilai environment dan simpan kuncinya

Dari direktori projek, hasilkan tiga berbeza nilai heksadesimal acak dengan:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Buat fail bernama .env menggunakan templat di bawah ini, ganti setiap REPLACE_WITH_RANDOM_HEX dengan nilai yang dihasilkan berbeza, dan ubah hostname dan zona waktu. Yang ditampilkan 2.42.5 tag adalah rilis stabil disenaraikan pada 8 Oktober 2026, digunakan di sini sebagai contoh konfigurasi bertanggal, bukan jaminan deployment yang teruji langsung atau keselamatan di masa depan. Sebelum menginstal, semak rilis resmi n8n saat ini, lalu pertahankan n8n dan imej task-runner-nya pada versi disahkan yang sama.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Jangan pernah berkomitmen .env ke repositori awam. Simpan kunci penyulitan dan instruksi pemulihan dengan aman di luar VPS. Kuncinya perlu tetap sama selepas pembuatan ulang atau migrasi kontena.

3. Buat compose.yaml untuk instalasi baru

Di direktori yang sama, buat compose.yaml. Contoh ini menggunakan konvensi variabel lingkungan resmi n8n dan PostgreSQL 18 PGDATA jalur yang didokumentasikan oleh projek hosting n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Keempat perkhidmatan tersebut memiliki peran yang berbeza: PostgreSQL menyimpan keadaan pangkalan data, n8n menjalankan aliran kerja, n8n-runner mengeksekusi tugas pelari dengan versi yang cocok dan token pengesahan bersama, dan Caddy menangani HTTPS awam. luaran pelari tugas bukan Queue Mode Redis. Hanya Caddy yang menerbitkan port hos. Ilustrasi lean ini menggunakan peran pangkalan data tunggal untuk persediaan; untuk pemisahan hak istimewa PostgreSQL yang lebih kuat, lihat contoh deployment resmi n8n PostgreSQL.

4. Cipta Caddyfile HTTPS

Buat filenya Caddyfile (huruf kapital C, tidak ada perpanjangan) di samping compose.yaml. Ganti contoh hostname di mana pun dengan nama DNS anda sendiri:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy meminta dan memperbarui sijil TLS awam apabila domain diselesaikan dengan benar dan trafik luaran boleh mencapai port 80/443. Jangan arahkan DNS ke localhost. Jika anda menggantikan Caddy dengan reverse proxy lainnya, teruskan hos asli, protokol, dan header alamat klien, lalu sesuaikan N8N_PROXY_HOPS untuk jumlah sebenar dari lompatan proxy tepercaya.

5. Jalankan kontena dan uji dari luar

Jalankan arahan ini dari direktori projek selepas menyimpan .env, compose.yaml dan Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

arahan terakhir memeriksa awam HTTPS endpoint kesehatan. Jika pengeluaran sijil masih tertunda, semak Caddy log dan DNS/ports sebelum menyimpulkan n8n rusak. Buka https://n8n.example.com, segera buat akun pemilik pertama dan aktifkan perlindungan masuk yang sesuai. sahkan bahwa instance benar-benar menjalankan aliran kerja, bukan hanya editor yang memuat:

  1. Di editor, buat aliran kerja dengan a webhook pencetus. Tetapkan HTTP kaedah untuk GET, pilih Path vps-check, dan atur Tanggapi untuk Segera. Simpan aliran kerja.
  2. Klik Dengarkan Acara ujian, salin selengkapnya URL ujian ditunjukkan oleh n8n, dan dijalankan dari peranti lain curl -i 'PASTE_TEST_URL_HERE' dengan URL yang disalin. Harapkan respons sukses HTTP dan acara masuk muncul di editor n8n. URL ujian hanya berfungsi saat n8n mendengarkan acara tersebut.
  3. Publikasikan aliran kerja, alihkan node ke workflownya URL Produksi, salin dan jalankan curl -i 'PASTE_PRODUCTION_URL_HERE' lagi. sahkan eksekusi berdasarkan aliran kerja Eksekusi tab. Permintaan webhook produksi memerlukan aliran kerja untuk dipublikasikan dan tidak menampilkan muatannya dalam tampilan ujian editor.

Ini ialah ujian asas yang sengaja dibuat ringkas dan tanpa pengesahan: jangan hantar rahsia melaluinya. Nyahterbit atau padam selepas ujian, atau konfigurasikan pengesahan Webhook/sekatan IP sebelum menggunakan endpoint awam untuk data sebenar. Rujuk dokumentasi rasmi Webhook untuk ujian dan produksi.

6. Buat sandaran sebelum menukar versi yang dipinkan

Simpan dump PostgreSQL yang boleh dipulihkan dan volume data n8n yang persisten, .env/ kunci penyulitan dan fail luaran yang diperlukan untuk disimpan di luar pelayan ini. sahkan pemulihan menggunakan panduan backup dan pemulihan sebelum memperbarui produksi. Contoh arahan:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Ubah yang disematkan N8N_VERSION hanya selepas membaca nota keluaran; baik imej n8n maupun imej pelari perlu maju bersama-sama. Jangan lari docker compose down -v selama pemeliharaan rutin kerana itu menghapus volume data bernama. PostgreSQL perubahan versi besar memerlukan upgrade pangkalan data atau rencana pembuangan/pemulihan; menggantikan imej Postgres 18 dengan tag mayor yang berbeza bukanlah migrasi otomatis.

Rujukan rasmi: panduan n8n Docker Compose, konfigurasi reverse proxy/webhook n8n dan nota pelaksanaan PostgreSQL rasmi. Tiada penanda aras infrastruktur atau ciri prapasang khusus penyedia yang diandaikan.

FAQ

Memasang n8n dengan Docker: soalan lazim

Adakah n8n memerlukan PostgreSQL apabila menggunakan Docker?

Docker tidak memerlukan PostgreSQL dan pelaksanaan kecil boleh menggunakan SQLite. Untuk pelaksanaan VPS berorientasikan produksi, PostgreSQL menyediakan asas pangkalan data yang lebih kukuh dan menyokong penskalaan Queue Mode pada masa hadapan.

Mengapa perlu mengekalkan volum n8n persisten jika PostgreSQL menyimpan data?

Direktori n8n persisten boleh mengandungi keadaan dan konfigurasi instans penting. Kekalkannya mengikut reka bentuk pelaksanaan dan jangan anggap pangkalan data ialah satu-satunya aset pemulihan.

Mengapa webhook saya memaparkan localhost?

Alamat kontena dalaman berbeza daripada origin awam. Konfigurasikan nama hos luaran, protokol dan URL webhook, serta pastikan reverse proxy meneruskan header yang diperlukan.

Patutkah port 5678 didedahkan kepada awam?

Untuk pelaksanaan produksi biasa di belakang reverse proxy, dedahkan HTTPS pada proxy dan kekalkan port aplikasi n8n sebagai dalaman kecuali terdapat sebab operasi khusus untuk sebaliknya.

Adakah saya memerlukan Redis?

Tidak untuk pelaksanaan Docker satu instans standard. Redis menjadi relevan apabila anda sengaja beralih ke Queue Mode dan worker.

Adakah task runner luaran n8n sama dengan worker Queue Mode?

Tidak. Task runner luaran menjalankan kod tugas yang disokong secara berasingan daripada proses utama n8n dan menggunakan token pengesahan bersama. Redis Queue Mode mengagihkan pelaksanaan aliran kerja dan mempunyai keperluan infrastrukturnya sendiri. Contoh ini menunjukkan task runner luaran, bukan Redis Queue Mode. Padankan versi imej runner dengan versi n8n.
