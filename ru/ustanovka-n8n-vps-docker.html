Установка n8n на VPS

Установите n8n на VPS с помощью Docker Compose и PostgreSQL. Для рабочего развёртывания также нужны постоянное хранение данных приложения и базы, неизменный N8N_ENCRYPTION_KEY, публичное доменное имя, HTTPS и корректная настройка вебхуков. Проверьте всё это до активации рабочих процессов.

DNS

Направьте домен или поддомен на VPS до выпуска TLS-сертификатов и публикации URL вебхуков.

Docker Compose

Установите Docker Engine и плагин Compose из поддерживаемых пакетов для вашей операционной системы.

Межсетевой экран

Откройте только необходимые порты администрирования и веб-доступа. PostgreSQL и внутренние сервисы приложения оставьте в закрытой сети.

Устанавливаете на VPS, где уже работают сайты? Можно добавить n8n на подконтрольный вам сервер, если хватает CPU, RAM и диска. Но если Nginx, Apache, Caddy или другой обратный прокси уже занимает порты 80/443, не запускайте приведённый ниже контейнер Caddy без изменений: возникнет конфликт портов. Вместо этого направьте новый поддомен n8n через существующий прокси с подходящим подключением к закрытой сети либо используйте чистый VPS для точного повторения примера Compose. Сохраните остальные сайты и их настройки TLS; пример предполагает, что порты 80/443 свободны.

УСТАНОВКА ПО ПРИМЕРУ С АДАПТАЦИЕЙ

Установите n8n на VPS через Docker Compose

Этот пример поможет развернуть n8n на Linux VPS с самостоятельным администрированием. Установкой и обслуживанием n8n занимаетесь вы; выбор сервера через нашего партнёра не включает предустановленный экземпляр n8n. Пример объединяет n8n, PostgreSQL, внешний исполнитель задач и Caddy с HTTPS в закрытой сети Compose. Это шаблон конфигурации, а не утверждение о проверке развёртывания на действующем сервере.

Нужна максимально быстрая установка с нуля? n8n также предоставляет официальную установку Docker одной строкой. Можно скачать и изучить скрипт командой curl -fsSL https://get.n8n.io -o get-n8n.sh перед запуском sh get-n8n.sh. Этот вариант запускает первоначальный экземпляр с SQLite по локальному URL и включает сервисы изолированного окружения n8n Assistant; это не то же самое , что описанное здесь VPS-развёртывание с публичным HTTPS и PostgreSQL. Полный официальный стек изолированного окружения требует больше RAM и CPU, чем минимальная установка n8n: руководство Compose указывает минимум 4 GB RAM / 2 vCPUs. Для рабочего VPS с доступом из интернета продолжайте с ручной настройкой стека ниже.

1. Подготовьте Docker, DNS и доступ

Подключитесь по SSH с правами sudo и направьте DNS-запись A для n8n.example.com на IPv4-адрес вашего VPS. На VPS с чистой Ubuntu 22.04, 24.04 или 26.04 следующие команды устанавливают Docker Engine и современный плагин docker compose из официального подписанного репозитория Docker для apt :

# Чистая официальная установка Ubuntu 22.04 / 24.04 / 26.04
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Подключите подписанный apt-репозиторий Docker
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Это способ через репозиторий, рекомендованный для рабочей эксплуатации в официальной инструкции Docker для Ubuntu. Не переустанавливайте и не удаляйте Docker вслепую на VPS с уже работающими контейнерами или сайтами; сначала изучите существующую установку и возможные конфликты пакетов. Для Debian и других дистрибутивов используйте соответствующие официальные инструкции, а не команды для Ubuntu.

Теперь проверьте Docker, плагин Compose, DNS и рабочий каталог:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Если getent hosts не возвращает адрес или возвращает неправильный, исправьте DNS до запуска Caddy; замените n8n.example.com во всём руководстве своим доменным именем. Docker обычно требует прав root: если ваш SSH-пользователь не может выполнять приведённые далее команды docker compose напрямую, добавляйте перед ними sudo. Добавление пользователя в группу docker даёт права, эквивалентные root, поэтому на общем сервере это требует осознанного решения.

Перед включением межсетевого экрана сохраните доступность фактического порта SSH. Разрешите входящие HTTP (80) и HTTPS (443) для выпуска сертификатов и редактора. Порты контейнеров, опубликованные Docker, могут обходить некоторые правила UFW: изучите рекомендации Docker по межсетевому экрану и публикуйте только нужные порты Caddy. Этот пример Compose намеренно не публикует PostgreSQL (5432), n8n (5678) и брокер исполнителей задач (5679) в открытый интернет.

2. Создайте значения окружения и сохраните ключ

В каталоге проекта сгенерируйте три разных случайных шестнадцатеричных значения командой:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Создайте файл с именем .env по шаблону ниже, замените каждый REPLACE_WITH_RANDOM_HEX отдельным сгенерированным значением и измените доменное имя и часовой пояс. Указанный тег 2.42.5 соответствует стабильному выпуску по состоянию на 8 октября 2026и используется здесь как пример конфигурации на эту дату, а не как гарантия проверки на действующем сервере или безопасности в будущем. Перед установкой проверьте актуальные официальные выпуски n8n, затем используйте одну и ту же проверенную версию n8n и образа исполнителя задач.

# .env — замените три секрета из примера
# Закрепите поддерживаемый выпуск; версии n8n и исполнителя должны совпадать.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Никогда не добавляйте .env в публичный репозиторий. Храните ключ шифрования и инструкции восстановления в защищённом месте вне VPS. Ключ должен оставаться прежним после пересоздания контейнера или переноса.

3. Создайте compose.yaml для новой установки

В том же каталоге создайте compose.yaml. Пример использует официальные соглашения n8n для переменных окружения и путь PostgreSQL 18 PGDATA , описанный в проекте хостинга n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

У четырёх сервисов разные роли: PostgreSQL хранит состояние базы, n8n выполняет процессы, n8n-runner выполняет задачи с соответствующей версией и общим токеном аутентификации, а Caddy обслуживает публичный HTTPS. Внешний исполнитель задач не является режимом очереди Redis. Порты хоста публикует только Caddy. Для простоты в этом примере используется одна роль базы данных; для более строгого разделения прав PostgreSQL обратитесь к официальному примеру развёртывания n8n с PostgreSQL.

4. Создайте Caddyfile для HTTPS

Создайте файл Caddyfile (с заглавной C, без расширения) рядом с compose.yaml. Во всех местах замените доменное имя примера своим DNS-именем:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy запрашивает и продлевает публичные TLS-сертификаты, когда домен разрешается правильно, а внешние запросы достигают портов 80/443. Не направляйте DNS на localhost. При замене Caddy другим обратным прокси передавайте исходные заголовки хоста, протокола и адреса клиента и настройте N8N_PROXY_HOPS по фактическому числу доверенных прокси в цепочке.

5. Запустите контейнеры и проверьте доступ извне

Выполните эти команды из каталога проекта после сохранения .env, compose.yaml и Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Последняя команда проверяет публичный HTTPS на маршруте проверки состояния. Если сертификат ещё выпускается, проверьте журналы Caddy, DNS и порты, прежде чем считать n8n неисправным. Откройте https://n8n.example.com, сразу создайте первого владельца и включите необходимые средства защиты входа. Убедитесь, что экземпляр действительно выполняет процесс, а не просто открывает редактор:

  1. В редакторе создайте процесс с триггером Вебхук . Для параметра «Метод HTTP» задайте GET, выберите путь vps-checkи для параметра ответа задайте немедленный ответ. Сохраните процесс.
  2. Нажмите «Ожидать тестовое событие», скопируйте полный тестовый URL , показанный n8n, и с другого устройства выполните curl -i 'PASTE_TEST_URL_HERE' с этим URL. Должен прийти успешный HTTP-ответ, а входящее событие — появиться в редакторе n8n. Тестовые URL работают только пока n8n ожидает событие.
  3. Опубликуйте процесс, переключите узел на его рабочий URL, скопируйте его и снова выполните curl -i 'PASTE_PRODUCTION_URL_HERE' . Проверьте выполнение на вкладке «Выполнения» этого процесса. Запросы к рабочему вебхуку требуют опубликованного процесса и не показывают данные в тестовом представлении редактора.

Это намеренно простая базовая проверка без аутентификации: не отправляйте туда секреты. После проверки снимите процесс с публикации или удалите его либо настройте аутентификацию вебхука и ограничения по IP до использования публичного адреса с реальными данными. См. официальную документацию о тестовых и рабочих вебхуках.

6. Сделайте копию перед изменением закреплённых версий

Сохраните пригодный для восстановления дамп PostgreSQL и постоянный том данных n8n, .env/ключ шифрования и необходимые внешние файлы в хранилище вне этого сервера. Проверьте восстановление по руководству по резервному копированию и восстановлению до обновления рабочего окружения. Примеры команд:

# Сохраните базу, ключ шифрования, данные экземпляра
# и файлы до изменения закреплённых версий.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# После сохранения защищённой копии вне этого VPS:
docker compose pull
docker compose up -d
docker compose ps

Изменяйте закреплённую переменную N8N_VERSION только после изучения примечаний к выпуску; образы n8n и исполнителя задач нужно обновлять вместе. Не выполняйте docker compose down -v при обычном обслуживании: команда удаляет именованные тома данных. Смена основной версии PostgreSQL требует плана обновления базы либо дампа и восстановления; замена образа Postgres 18 тегом другой основной версии не выполняет автоматический перенос.

Авторитетные источники: руководство n8n по Docker Compose, настройка обратного прокси и вебхуков n8n, официальные примечания по развёртыванию PostgreSQL. Здесь не предполагаются ни результаты тестов инфраструктуры, ни предустановленные функции конкретного провайдера.

КОНФИГУРАЦИЯ

Осознанно задавайте секреты и публичные URL

Ключ шифрования

Задайте и сохраните надёжный ключ шифрования n8n до записи рабочих учётных данных. После восстановления понадобится тот же ключ.

Учётные данные PostgreSQL

Используйте отдельные учётные данные базы и не храните пароли в публичной системе контроля версий.

Публичное доменное имя

Укажите реальное внешнее доменное имя и HTTPS-адрес, а не внутренний адрес контейнера.

URL вебхуков

Задайте N8N_WEBHOOK_URL как доступный извне базовый HTTPS-адрес и установите N8N_PROXY_HOPS=1 при одном доверенном обратном прокси. WEBHOOK_URL — устаревший псевдоним в n8n 2.35.0 и новее; не копируйте его из старых руководств.

ПОСТОЯННОЕ ХРАНЕНИЕ

Храните данные n8n и PostgreSQL отдельно

Данные n8n

Подключите постоянное хранилище для каталога данных n8n, чтобы важное состояние экземпляра сохранялось при пересоздании контейнера.

Данные PostgreSQL

Храните каталог базы независимо от контейнера PostgreSQL.

Права на файлы

Разрешите запись в подключённые пути нужному пользователю контейнера, не расширяя без необходимости права на хранилище хоста.

Файлы процессов

Обеспечьте постоянное хранение подключённых файлов и бинарных данных, от которых зависят рабочие процессы.

POSTGRESQL

Подключите n8n к закрытому сервису базы данных

Тип базы данныхНастройте n8n на PostgreSQL, чтобы он случайно не начал использовать SQLite.
ХостИспользуйте имя сервиса PostgreSQL в закрытой сети Docker.
Учётные данныеУкажите нужную базу, пользователя приложения и пароль.
ГотовностьДождитесь готовности PostgreSQL перед успешной инициализацией n8n.
СетьДля доступа к базе между контейнерами не нужен публичный порт PostgreSQL.

HTTPS И ПРОКСИ

Обеспечьте HTTPS для публичного URL n8n

Обратный прокси

Используйте Nginx, Caddy или Traefik как публичную точку входа и направляйте трафик к закрытому сервису n8n.

TLS

Выпустите действительный сертификат для публичного доменного имени и перенаправляйте HTTP-трафик на HTTPS.

Передаваемые заголовки

Передавайте нужные n8n сведения о хосте, протоколе и клиенте и настройте ожидаемое число прокси в цепочке.

Проверка вебхуков

Вызовите вебхук извне VPS и убедитесь, что n8n формирует доступный извне HTTPS-адрес.

Почему n8n в Docker работает локально, но не в рабочем окружении

Неверный URL вебхуков

Обратные вызовы направлены на localhost, HTTP или внутреннее имя вместо публичного HTTPS-адреса.

Нет постоянного хранилища

Состояние приложения или базы исчезает при пересоздании контейнера.

Утрачен ключ шифрования

Сохранённые учётные данные перестают работать после повторного развёртывания, потому что новый экземпляр использует другой ключ.

Публичный порт базы

PostgreSQL без необходимости открыт извне, хотя доступ к нему нужен только n8n.

Проверьте состояние контейнеров

Выполните docker compose ps и убедитесь, что сервисы приложения и базы работают как ожидается, прежде чем считать развёртывание исправным.

Проверьте маршрут состояния n8n

В приведённом выше примере Compose порт 5678 не опубликован на хосте. Проверьте публичный адрес командой curl -fsS https://n8n.example.com/healthz после замены доменного имени и используйте docker compose ps вместе с журналами сервисов, если HTTPS или база ещё не готовы.

Закрепляйте версии приложения

Непроверенное обновление образа с плавающим тегом — не стратегия обслуживания. Фиксируйте используемую версию n8n, читайте примечания к выпускам и создавайте копию перед её сменой.

Не меняйте основную версию PostgreSQL простой заменой тега

Смена только тега основной версии Postgres может сделать существующий каталог данных несовместимым. Создайте копию и следуйте процедуре обновления базы вместо предположения, что пересоздание контейнера выполнит перенос между основными версиями.

Вопросы и ответы

Установка n8n через Docker: частые вопросы

Нужен ли PostgreSQL для n8n в Docker?

Docker не требует PostgreSQL, и небольшие развёртывания могут использовать SQLite. Для VPS в рабочей эксплуатации PostgreSQL даёт более основательную базу данных и поддерживает последующее масштабирование через режим очереди.

Зачем постоянный том n8n, если данные хранит PostgreSQL?

Постоянный каталог n8n может содержать важное состояние и настройки экземпляра. Сохраняйте его в соответствии с устройством развёртывания, не считая базу единственным ресурсом для восстановления.

Почему вебхук показывает localhost?

Внутренний адрес контейнера отличается от публичного. Настройте внешнее доменное имя, протокол и URL вебхуков и убедитесь, что обратный прокси передаёт необходимые заголовки.

Должен ли порт 5678 быть публичным?

При обычном рабочем развёртывании за обратным прокси публикуйте HTTPS на прокси, а порт приложения n8n оставляйте внутренним, если нет конкретной эксплуатационной причины поступить иначе.

Нужен ли Redis?

Для обычного одиночного экземпляра в Docker — нет. Redis нужен при осознанном переходе на режим очереди и воркеры.

Внешние исполнители задач n8n и воркеры режима очереди — одно и то же?

Нет. Внешние исполнители выполняют поддерживаемый код задач отдельно от основного процесса n8n и используют общий токен аутентификации. Режим очереди Redis распределяет выполнения процессов и имеет собственные требования к инфраструктуре. В примере показан внешний исполнитель задач, а не режим очереди Redis. Версия его образа должна совпадать с версией n8n.
