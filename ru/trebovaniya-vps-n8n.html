Требования к VPS для n8n

Подбирая VPS для n8n, отталкивайтесь от своей нагрузки, а не универсального минимума оборудования. VPS с 1 vCPU / 1 GB при грамотном подборе нагрузки способен постоянно выполнять небольшие задачи, а 2 vCPU / 4 GB RAM — практичный начальный класс для n8n с PostgreSQL и HTTPS. Объёмные данные, одновременные запуски и локальная обработка требуют большего запаса: измерьте фактическое потребление до выбора.

МИНИМУМ И ПРАКТИЧЕСКАЯ МОЩНОСТЬ

Есть ли у n8n единый официальный минимальный размер VPS?

Не для всех нагрузок. Примеры официальных предварительных требований n8n описывают условное OEM-развёртывание и прямо предупреждают, что требования зависят от нагрузки. Эта документация не гарантирует, что любая конкретная конфигурация CPU, RAM и диска обеспечит работу автоматизации в рабочем окружении.

n8n отмечает, что простаивающий экземпляр может потреблять мало памяти, но узел Code, крупные бинарные данные и одновременное выполнение способны резко повысить её расход. Отдельно учитывайте ОС, Docker, PostgreSQL и средства копирования и мониторинга.

Технические источники: пример предварительных требований n8n и официальное руководство по памяти. Четыре строки выше — реальные конфигурации, которые можно купить, а не предписанные официальные требования n8n.

RAM И CPU

Что на самом деле расходует ресурсы сервера

Параллельные выполнения

Несколько одновременно работающих процессов могут быть важнее общего числа процессов, сохранённых в n8n. Следите за пиками памяти и временем выполнения при одновременных запусках.

Объём данных

Крупные JSON-объекты, файлы и бинарные данные увеличивают нагрузку на память. Несколько выполнений с большими данными могут требовать больше RAM, чем множество лёгких API-интеграций.

Узлы с высокой нагрузкой на CPU

Code, преобразования и другие вычислительно сложные шаги могут надолго загружать CPU. Дополнительные ядра помогают, когда реальные выполнения конкурируют за вычислительные ресурсы.

Вспомогательные сервисы

ОС, PostgreSQL, обратный прокси, мониторинг и Docker тоже требуют ресурсов. Рассчитывайте весь стек, а не только процесс n8n.

ИЗМЕРЬТЕ ПЕРЕД УВЕЛИЧЕНИЕМ РЕСУРСОВ

Как понять, чего не хватает n8n: RAM, CPU или диска

Запустите самый крупный ожидаемый процесс и реалистичную серию одновременных заданий, затем изучите состояние сервера и журналы выполнений n8n. Само по себе число процессов в редакторе не является полезным показателем мощности.

Память / OOM

Проверьте docker stats --no-stream и free -h. При нехватке памяти сначала сократите JSON или бинарные данные, разбейте большие импорты на пакеты и избегайте шагов Code с высоким потреблением памяти. Добавление vCPU не обязательно исправит ошибку кучи JavaScript.

CPU / параллелизм

Определите, загружен ли CPU преобразованиями или задания лишь ожидают внешние API. В обычном режиме перед переходом к воркерам рассмотрите поддерживаемое ограничение параллельных рабочих выполнений. Увеличение CPU не ускоряет внешний API с ограничением частоты запросов.

Диск / база данных

Проверьте df -h, размер базы и сохранённую историю выполнений. Следите за ростом диска и медленными операциями базы. Осознанно настройте срок хранения перед оплатой большего диска; держите копии восстановления вне сервера.

Используйте рекомендации n8n по параллелизму и официальное объяснение тестирования производительности. Любое заявленное число одновременных процессов без учёта их данных и задержек API — лишь оценка.

БАЗА ДАННЫХ И ХРАНИЛИЩЕ

SQLite, PostgreSQL и постоянные данные

SQLite

SQLite может подойти для небольших одиночных развёртываний и тестирования. С ростом рабочей нагрузки и параллелизма выбор базы становится эксплуатационным ограничением, а не деталью установки.

PostgreSQL

Для рабочего стека VPS PostgreSQL даёт более основательную базу данных. Выделите RAM, CPU и диск самой базе и следите за её ростом.

Постоянные данные .n8n

Не считайте PostgreSQL единственным постоянным ресурсом. Сохраняйте каталог данных n8n и защищайте ключ шифрования, необходимый для восстановления зашифрованных учётных данных.

Рост диска

История выполнений, бинарные данные, файлы базы и журналы со временем растут. Настройки хранения и внешние копии напрямую влияют на необходимый объём.

ОБЪЁМ ДИСКА

Оцените место для истории выполнений n8n до заказа

Начните с формулы сохранённые выполнения в день × средний размер одного сохранённого выполнения в байтах × срок хранения в днях. Например, 500 сохранённых выполнений в день × 200 KB каждое × 14 дней = 1.4 GB данных выполнений в этом примере без накладных расходов базы. Значение 200 KB условное, а не результат теста n8n.

Также выделите место для ОС, слоёв образов Docker, индексов базы, бинарных файлов, журналов приложения, обновлений и временных файлов. Для внешних копий нужен свой объём. Диск 10 GB может подойти минимальному стеку, но оставляет гораздо меньше места для файлов, чем диск 40 или 80 GB.

n8n описывает удаление данных выполнений по умолчанию по возрасту (336 часов / 14 дней) или количеству (10,000 выполнений), с исключениями. Перед изменением проверьте фактические настройки и то, что сохраняется. SQLite может повторно использовать освобождённое место, не уменьшая файл автоматически.

Источник: n8n — управление данными выполнений и их очисткой. Требования к диску зависят от измеренного размера сохраняемых данных, а не только числа узлов.

СИСТЕМНЫЕ ТРЕБОВАНИЯ

Docker и накладные расходы рабочей эксплуатации

Linux VPS

Используйте поддерживаемый дистрибутив Linux с ресурсами для ОС и обновлений безопасности в дополнение к стеку приложения.

Docker и Compose

Контейнеры упрощают повторяемость развёртывания, но не устраняют накладные расходы ресурсов. Храните данные n8n и базы вне заменяемых контейнеров.

HTTPS и обратный прокси

Публичным вебхукам нужны стабильное доменное имя и правильно настроенный HTTPS. Включите обратный прокси и TLS в проект рабочего развёртывания.

Мониторинг и резервные копии

Следите за RAM, CPU, диском и ростом базы. Храните пригодные для восстановления копии вне VPS и проверяйте восстановление, не предполагая, что снимка достаточно.

ПАРАЛЛЕЛЬНЫЕ ВЫПОЛНЕНИЯ

Когда одного увеличения VPS уже недостаточно

Вертикальное масштабирование подходит, пока один экземпляр уверенно справляется с нагрузкой. Если постоянная параллельная нагрузка вызывает конкуренцию за ресурсы, оцените режим очереди и воркеры. Он добавляет Redis, PostgreSQL и один или несколько процессов-воркеров; выделяйте RAM и CPU каждому компоненту, а не только n8n. n8n также описывает ограничения хранения бинарных данных в файловой системе при режиме очереди, поэтому до перехода проверьте совместимость схемы хранения.

Прочитать руководство по режиму очереди и воркерам

Оставайтесь на одном экземпляреЕсли CPU, RAM и время выполнения остаются в комфортных пределах при пиковом числе одновременных задач.
Увеличивайте ресурсы сервераЕсли ограничение — длительная нехватка CPU или памяти, а архитектура остаётся простой.
Рассмотрите режим очередиЕсли измеренная параллельная нагрузка оправдывает Redis и отдельные воркеры.
Пересмотрите хранилищеЕсли главным ограничением становится история выполнений, бинарные данные или рост PostgreSQL.

НАЧАЛЬНЫЙ ТАРИФ И ДИСКОВЫЙ ВВОД-ВЫВОД

Как использовать начальный VPS с 1 GB

1 GB RAM

Это полноценный рабочий тариф VPS, а не продукт только для тестирования. Он может подойти для небольших постоянных автоматизаций и преимущественно последовательной работы с API, если память, диск и параллельные задания остаются в измеренных пределах. Запаса для PostgreSQL на том же сервере, объёмных данных и тяжёлых параллельных выполнений немного.

2 GB RAM

Используйте 2 GB как более надёжную основу лёгкого экземпляра, если нужен запас для ОС, Docker и небольших всплесков без немедленного перехода к полноценному рабочему стеку.

SSD или NVMe

Обычного SSD достаточно для лёгкой автоматизации. NVMe полезнее, когда PostgreSQL и история выполнений вызывают частые чтения и записи либо измерения показывают влияние задержки диска на процессы.

Измеряйте перед увеличением ресурсов

По CPU, памяти, росту диска и времени выполнения при пиковой одновременной нагрузке определите, что ограничивает работу: вычисления, память или хранилище. Не считайте, что более мощный VPS устранит любое замедление.

Вопросы и ответы

Требования к VPS для n8n: частые вопросы

Сколько RAM нужно n8n?

Единой цифры нет. Потребность в RAM зависит от параллелизма, объёма данных, характера выполнения и других сервисов на VPS. Сервер с 4 GB — практичный начальный класс для небольшой рабочей системы, а не гарантированное требование для любой нагрузки.

Сколько ядер CPU использовать?

Для лёгких задач можно начать с небольшого объёма CPU. Добавляйте ядра, когда мониторинг показывает длительную загрузку CPU или замедление при одновременных выполнениях, а не по одному лишь числу процессов.

Требует ли n8n PostgreSQL?

Небольшие развёртывания могут использовать SQLite, но с ростом эксплуатационных требований и параллелизма PostgreSQL становится более основательным выбором для рабочей системы.

Когда нужен Redis?

Redis связан с режимом очереди. Обычному одиночному экземпляру он не нужен только потому, что тот работает на VPS.

Сколько места на диске выделить?

Потребность в диске зависит от роста PostgreSQL, сохранённой истории, бинарных данных, журналов, слоёв контейнеров и копий. Следите за ростом и оставляйте запас вместо опоры на универсальную цифру.

Можно ли постоянно запускать n8n на VPS с 1 GB?

Да, если реальная нагрузка укладывается в возможности. VPS с 1 GB — полноценный рабочий сервер для небольших, преимущественно последовательных автоматизаций, но запас памяти ограничен. Не предполагайте, что на нём поместятся PostgreSQL на том же сервере, задачи с большими бинарными данными или несколько крупных параллельных выполнений. Следите за расходом и увеличивайте ресурсы по наблюдаемой нехватке.

Для рабочего VPS с n8n лучше 2 GB или 4 GB RAM?

Два гигабайта дают больше запаса, чем минимальный экземпляр с 1 GB, а 4 GB — практичная отправная точка для оценки n8n вместе с PostgreSQL и HTTPS. Единого гарантированного минимума для рабочей эксплуатации нет: реальную потребность определяют сложность процессов, пиковые одновременные запуски, настройки контейнеров и сохраняемые данные.

Нужен ли GPU процессам n8n с ИИ?

Нет, если n8n только вызывает внешний API модели: вычисления выполняет провайдер модели, а VPS управляет процессами, данными и параллелизмом. Локальный запуск моделей — отдельная аппаратная задача, для которой может понадобиться гораздо больше RAM и подходящий GPU.

Что вызывает ошибки нехватки памяти n8n?

Частые причины — крупные JSON или бинарные данные, ресурсоёмкие операции Code и одновременные выполнения. Проверьте журналы и пиковый расход памяти, затем сократите объём данных одного выполнения или добавьте RAM по результатам измерений.
