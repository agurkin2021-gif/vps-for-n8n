ਇੰਕ੍ਰਿਪਸ਼ਨ ਕੁੰਜੀ

ਸਹੀ n8n ਐਨਕ੍ਰਿਪਸ਼ਨ ਕੁੰਜੀ ਨੂੰ ਵੱਖਰੇ ਅਤੇ ਸੁਰੱਖਿਅਤ ਢੰਗ ਨਾਲ ਸੁਰੱਖਿਅਤ ਰੱਖੋ। ਮੁਡ਼ ਸਥਾਪਿਤ ਐਨਕ੍ਰਿਪਟਡ ਪ੍ਰਮਾਣ ਪੱਤਰ ਉਸੇ ਕੁੰਜੀ ਉੱਤੇ ਨਿਰਭਰ ਕਰਦੇ ਹਨ।

ਲਗਾਤਾਰ ਫਾਇਲਾਂ

ਲਗਾਤਾਰ n8n ਡਾਟਾ ਡਾਇਰੈਕਟਰੀ ਅਤੇ ਕੋਈ ਵੀ ਮਾਊਂਟ ਕੀਤੀਆਂ ਫਾਈਲਾਂ, ਬਾਈਨਰੀ-ਡੇਟਾ ਸਟੋਰੇਜ ਜਾਂ ਵਰਕਫਲੋ ਸੰਪਤੀਆਂ ਸ਼ਾਮਲ ਕਰੋ ਜਿਸ ਉੱਤੇ ਤੁਹਾਡੀ ਤਾਇਨਾਤੀ ਨਿਰਭਰ ਕਰਦੀ ਹੈ।

ਤਾਇਨਾਤੀ ਸੰਰਚਨਾ

ਸੰਰਚਨਾ/ਸੰਰਚਨਾ ਫਾਇਲਾਂ ਅਤੇ ਸਟੈਕ ਨੂੰ ਦੁਬਾਰਾ ਬਣਾਉਣ ਲਈ ਲੋਡ਼ੀਂਦੀ ਗੈਰ-ਗੁਪਤ ਸੰਰਚਨਾ ਰੱਖੋ। ਢੁਕਵੇਂ ਪਹੁੰਚ ਨਿਯੰਤਰਣ ਨਾਲ ਗੁਪਤ ਸੁਰੱਖਿਅਤ ਕਰੋ।

ਬੈਕਅੱਪ ਦੇ ਦੋ ਪੱਧਰ

ਲਾਜ਼ੀਕਲ ਨਿਰਯਾਤ ਬਨਾਮ ਸੰਪੂਰਨ ਆਫ਼ਤ ਰਿਕਵਰੀ

ਵਰਕਫਲੋ ਅਤੇ ਪ੍ਰਮਾਣ ਪੱਤਰ ਨਿਰਯਾਤ

n8n CLI ਨਿਰਯਾਤ ਮਾਈਗ੍ਰੇਸ਼ਨ, ਵਰਜਨਡ ਵਰਕਫਲੋ ਕਾਪੀਆਂ ਅਤੇ ਚੋਣਵੀਂ ਬਹਾਲੀ ਲਈ ਲਾਭਦਾਇਕ ਹਨ। ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ ਨੂੰ ਐਨਕ੍ਰਿਪਟਡ ਰੂਪ ਵਿੱਚ ਨਿਰਯਾਤ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ ਅਤੇ ਬਾਅਦ ਵਿੱਚ ਮੇਲ ਖਾਂਦੀ ਐਨਕ੍ਰਿਪਸ਼ਨ ਕੁੰਜੀ ਨਾਲ ਆਯਾਤ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ। ਸਿਰਫ ਇੱਕ ਵਰਕਫਲੋ ਨੂੰ ਮੁਡ਼ ਪ੍ਰਾਪਤ ਕਰਨ ਲਈ, ਵਰਕਫਲੋ ਸੰਪਾਦਕ ਦੇ ਤਿੰਨ-ਬਿੰਦੂ ਮੇਨੂ ਦੀ ਵਰਤੋਂ ਇਸ ਦੇ JSON ਨੂੰ ਡਾਊਨਲੋਡ ਕਰਨ ਲਈ ਕਰੋ, ਫਿਰ ਫਾਈਲ ਤੋਂ ਇੱਕ ਨਵੀਂ ਸਮੀਖਿਆ ਵਰਕਫਲੋ ਜਾਂ ਅਲੱਗ-ਥਲੱਗ ਉਦਾਹਰਣ ਵਿੱਚ ਆਯਾਤ ਕਰੋ। ਲਾਈਵ ਵਰਕਫਲੋ ਨੂੰ ਬਦਲਣ ਤੋਂ ਪਹਿਲਾਂ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ, ਵਰਕਫਲੋ ਆਈਡੀ ਅਤੇ ਨੋਡ ਮਾਪਦੰਡਾਂ ਦੀ ਜਾਂਚ ਕਰੋ। JSON ਪੂਰੇ ਸਰਵਰ ਨੂੰ ਬਹਾਲ ਨਹੀਂ ਕਰਦਾ।

ਇਕਾਈ ਨਿਰਯਾਤ

CLI ਸਹਿਯੋਗੀ ਡਾਟਾਬੇਸ ਕਿਸਮਾਂ ਦੇ ਵਿਚਕਾਰ ਡੇਟਾ ਨੂੰ ਲਿਜਾਣ ਲਈ ਡਾਟਾਬੇਸ ਇਕਾਈਆਂ ਨੂੰ ਨਿਰਯਾਤ ਕਰ ਸਕਦਾ ਹੈ। ਐਗਜ਼ੀਕਿਊਸ਼ਨ-ਹਿਸਟਰੀ ਟੇਬਲ ਵਿਕਲਪਿਕ ਹਨ ਕਿਉਂਕਿ ਉਹ ਬਹੁਤ ਵੱਡੇ ਹੋ ਸਕਦੇ ਹਨ।

ਮੁਕੰਮਲ ਉਦਾਹਰਣ ਰਿਕਵਰੀ

ਇੱਕ ਡੈੱਡ-ਸਰਵਰ ਦ੍ਰਿਸ਼ ਲਈ, ਅਸਲ ਡਾਟਾਬੇਸ, ਐਨਕ੍ਰਿਪਸ਼ਨ ਕੁੰਜੀ, ਨਿਰੰਤਰ ਡੇਟਾ ਅਤੇ ਤਾਇਨਾਤੀ ਨਿਰਭਰਤਾਵਾਂ ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖੋ। ਇਹ ਨਾ ਮੰਨੋ ਕਿ ਇੱਕ ਵਰਕਫਲੋ JSON ਐਕਸਪੋਰਟ ਪੂਰੇ ਉਦਾਹਰਣ ਨੂੰ ਦੁਬਾਰਾ ਬਣਾਉਂਦਾ ਹੈ।

ਸਨੈਪਸ਼ਾਟ ਪ੍ਰਦਾਨ ਕਰੋ

ਇੱਕ VPS ਸਨੈਪਸ਼ਾਟ ਇੱਕ ਵਾਧੂ ਰਿਕਵਰੀ ਲੇਅਰ ਦੇ ਰੂਪ ਵਿੱਚ ਲਾਭਦਾਇਕ ਹੈ, ਪਰ ਇਹ ਇਕੋ ਕਾਪੀ ਨਹੀਂ ਹੋਣੀ ਚਾਹੀਦੀ ਅਤੇ ਇੱਕ ਸੁਤੰਤਰ ਤੌਰ'ਤੇ ਤਸਦੀਕ ਕੀਤੀ ਐਪਲੀਕੇਸ਼ਨ/ਡਾਟਾਬੇਸ ਬੈਕਅੱਪ ਨੂੰ ਨਹੀਂ ਬਦਲਣਾ ਚਾਹੀਦਾ।

ਡਾਟਾਬੇਸ

ਡਾਟਾਬੇਸ ਦਾ ਲਗਾਤਾਰ ਬੈਕਅੱਪ ਰੱਖੋ

PostgreSQL

ਇੱਕ ਨਿਰੰਤਰ PostgreSQL ਬੈਕਅੱਪ ਵਿਧੀ ਦੀ ਵਰਤੋਂ ਕਰੋ ਅਤੇ ਨਤੀਜੇ ਵਜੋਂ ਬੈਕਅੱਪ ਨੂੰ VPS ਤੋਂ ਦੂਰ ਸਟੋਰ ਕਰੋ। ਉਸੇ ਅਸਫਲ ਡਿਸਕ ਉੱਤੇ ਇੱਕ ਡਾਟਾਬੇਸ ਕਾਪੀ ਆਫ਼ਤ ਰਿਕਵਰੀ ਨਹੀਂ ਹੈ।

SQLite

ਜੇ ਤਾਇਨਾਤੀ SQLite ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ, ਤਾਂ ਡਾਟਾਬੇਸ ਫਾਈਲ ਨੂੰ ਲਗਾਤਾਰ n8n ਡਾਟਾ ਡਾਇਰੈਕਟਰੀ ਤੋਂ ਸੁਰੱਖਿਅਤ ਰੱਖੋ। ਇੱਕ ਅਸੁਰੱਖਿਅਤ ਸਥਿਤੀ ਵਿੱਚ ਡਾਟਾਬੇਸ ਦੀ ਨਕਲ ਕਰਨ ਤੋਂ ਪਰਹੇਜ਼ ਕਰੋ ਜਦੋਂ ਕਿ ਇਸ ਨੂੰ ਸਰਗਰਮੀ ਨਾਲ ਸੋਧਿਆ ਜਾ ਰਿਹਾ ਹੈ।

ਫਾਂਸੀ ਦਾ ਇਤਿਹਾਸ

ਫੈਸਲਾ ਕਰੋ ਕਿ ਕੀ ਇਤਿਹਾਸਕ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਡੇਟਾ ਤੁਹਾਡੇ ਰਿਕਵਰੀ ਉਦੇਸ਼ ਦਾ ਹਿੱਸਾ ਹੈ। ਇਹ ਬੈਕਅੱਪ ਨੂੰ ਕਾਫ਼ੀ ਵੱਡਾ ਬਣਾ ਸਕਦਾ ਹੈ, ਇਸ ਲਈ ਰੱਖਣ ਅਤੇ ਪਾਲਣਾ ਦੀਆਂ ਜ਼ਰੂਰਤਾਂ ਨੂੰ ਚੋਣ ਨੂੰ ਚਲਾਉਣਾ ਚਾਹੀਦਾ ਹੈ।

ਡਾਟਾਬੇਸ ਵਰਜ਼ਨ

ਡਾਟਾਬੇਸ ਇੰਜਣ ਅਤੇ ਸਰੋਤ ਤਾਇਨਾਤੀ ਦੁਆਰਾ ਵਰਤੇ ਗਏ ਸੰਸਕਰਣ ਨੂੰ ਰਿਕਾਰਡ ਕਰੋ ਤਾਂ ਜੋ ਇੱਕ ਰਿਕਵਰੀ ਵਾਤਾਵਰਣ ਨੂੰ ਅਨੁਕੂਲਤਾ ਨਾਲ ਤਿਆਰ ਕੀਤਾ ਜਾ ਸਕੇ।

PostgreSQL ਏ Docker ਉੱਤੇ VPS ਦੀ ਰਚਨਾ ਕਰੋ। ਜੇਕਰ PostgreSQL ਸੇਵਾ ਦਾ ਨਾਮ ਰੱਖਿਆ ਗਿਆ ਹੈ postgres ਅਤੇ ਇਸ ਦਾ ਡਾਟਾਬੇਸ/ਉਪਭੋਗਤਾ ਦੋਵੇਂ ਹਨ n8nਹੇਠ ਦਿੱਤੀ ਕਮਾਂਡ ਹੋਸਟ ਉੱਤੇ ਇੱਕ ਨਿਰੰਤਰ PostgreSQL ਕਸਟਮ-ਫਾਰਮੈਟ ਡੰਪ ਬਣਾਉਂਦੀ ਹੈ। ਇਸ ਨੂੰ ਚਲਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਆਪਣੀ ਅਸਲ ਕੰਪੋਜ਼ ਫਾਈਲ ਦੀ ਜਾਂਚ ਕਰੋ, ਅਤੇ ਡਾਟਾਬੇਸ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ ਅਤੇ ਸੇਵਾ ਨਾਮਾਂ ਨੂੰ ਐਡਜਸਟ ਕਰੋ। pg_dump ਜਦੋਂ PostgreSQL ਚੱਲ ਰਿਹਾ ਹੋਵੇ ਤਾਂ ਇੱਕ ਲਾਜ਼ੀਕਲ ਤੌਰ'ਤੇ ਇਕਸਾਰ ਸਨੈਪਸ਼ਾਟ ਤਿਆਰ ਕਰ ਸਕਦਾ ਹੈ; ਇਹ ਕਰਦਾ ਹੈ ਨਹੀਂ। ਵੱਖਰੇ ਦਾ ਬੈਕਅੱਪ ਲਓ .n8n ਉਪਭੋਗਤਾ ਫੋਲਡਰ ਜਾਂ ਬਾਹਰੀ ਬਾਈਨਰੀ ਡਾਟਾ।

# In the Docker Compose project; adapt service, DB and user names
docker compose exec -T postgres pg_dump -U n8n -d n8n -Fc > n8n-postgres.dump
test -s n8n-postgres.dump
# Check that the archive has a readable object list
docker compose exec -T postgres pg_restore --list < n8n-postgres.dump

ਅਕਾਇਵ-ਲਿਸਟ ਚੈੱਕ ਸਪੱਸ਼ਟ ਫਾਰਮੈਟ ਸਮੱਸਿਆਵਾਂ ਨੂੰ ਫਡ਼ਦੀ ਹੈ ਪਰ ਇਹ ਸਾਬਤ ਨਹੀਂ ਕਰਦੀ ਕਿ ਡੇਟਾ ਨੂੰ ਬਹਾਲ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ। ਇੱਕ ਐਨਕ੍ਰਿਪਟਡ ਕਾਪੀ ਆਫ-ਸਰਵਰ ਸਟੋਰ ਕਰੋ ਅਤੇ ਇੱਕ ਰੀਸਟੋਰ ਦਾ ਅਭਿਆਸ ਕਰੋ। ਡਾਟਾਬੇਸ-ਵਿਸ਼ੇਸ਼ ਵਿਕਲਪਾਂ ਲਈ ਅਧਿਕਾਰਤ PostgreSQL pg _ dump ਦਸਤਾਵੇਜ਼ ਦੀ ਵਰਤੋਂ ਕਰੋ।

Docker ਉੱਤੇ SQLite। ਡਿਫਾਲਟ SQLite ਤਾਇਨਾਤੀ ਲਈ, database.sqlite ਅਤੇ ਤਿਆਰ ਕੀਤੀ ਗਈ ਐਨਕ੍ਰਿਪਸ਼ਨ-ਕੁੰਜੀ ਸੰਰਚਨਾ ਲਗਾਤਾਰ ਦੇ ਅੰਦਰ ਰਹਿੰਦੀ ਹੈ .n8n ਫੋਲਡਰ (ਆਮ ਤੌਰ ਉੱਤੇ ਮਾਊਂਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ /home/node/.n8n). SQLite ਦੀ ਇੱਕ ਸਧਾਰਨ ਲਾਈਵ ਕਾਪੀ ਨੂੰ ਕਦੇ ਵੀ ਇਕਸਾਰ ਨਾ ਮੰਨੋ। ਫੋਲਡਰ ਦੀ ਨਕਲ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ n8n ਅਤੇ ਹੋਰ ਡਾਟਾਬੇਸ ਲੇਖਕਾਂ ਨੂੰ ਬੰਦ ਕਰੋ, ਜਾਂ ਜਦੋਂ ਰੁਕਾਵਟ ਅਸੰਭਵ ਹੋਵੇ ਤਾਂ SQLite ਦੇ ਸਹਿਯੋਗੀ ਔਨਲਾਈਨ ਬੈਕਅੱਪ ਵਿਧੀ ਦੀ ਵਰਤੋਂ ਕਰੋ।

ਕਿਹਡ਼ੀ ਚੀਜ਼ ਦੀ ਜਾਂਚ ਨਹੀਂ ਕੀਤੀ ਗਈ ਸੀਅਸਲੀ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ, ਉਤਪਾਦਨ ਵੈੱਬਹੂਕਸ, ਕਤਾਰ-ਮੋਡ ਕਰਮਚਾਰੀਆਂ ਅਤੇ Redis, S3/ਅਜ਼ੂਰ ਬਾਈਨਰੀ ਸਟੋਰੇਜ, ਕਸਟਮ ਨੋਡਸ, ਉਪਭੋਗਤਾ/ਪ੍ਰੋਜੈਕਟ ਪਹੁੰਚ ਜਾਂ ਇੱਕ ਲਾਈਵ ਉਤਪਾਦਨ ਉਦਾਹਰਣ ਦੀ ਰਿਕਵਰੀ ਦੀ ਡੀਕ੍ਰਿਪਸ਼ਨ ਅਤੇ ਪ੍ਰਮਾਣਿਕਤਾ। ਹਰੇਕ ਨਿਰਭਰਤਾ ਲਈ ਇੱਕ ਵੱਖਰੀ ਡ੍ਰਿਲ ਚਲਾਓ ਜੋ ਤੁਸੀਂ ਅਸਲ ਵਿੱਚ ਵਰਤਦੇ ਹੋ।

ਦੁਬਾਰਾ ਕਿਵੇਂ ਪੈਦਾ ਕਰਨਾ ਹੈਃ ਇੱਕ ਡਿਸਪੋਸੇਜਲ n8n ਇੰਸਟਾਲੇਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰੋ, ਇੱਕ ਹਾਨਿਰਹਿਤ ਦੋ-ਨੋਡ ਵਰਕਫਲੋ ਬਣਾਓ, ਲਾਗੂ ਡੇਟਾਬੇਸ ਅਤੇ ਲਗਾਤਾਰ-ਫੋਲਡਰ ਬੈਕਅੱਪ ਕਰੋ, ਇੱਕ ਸਾਫ਼ ਵਾਲੀਅਮ ਜਾਂ ਡੇਟਾਬੇਸ ਵਿੱਚ ਬਹਾਲ ਕਰੋ, ਫਿਰ ਬਹਾਲ ਕੀਤੇ ਵਰਕਫਲੋ ਦੇ ਨੋਡਾਂ, ਕੁਨੈਕਸ਼ਨਾਂ ਅਤੇ ਅਸਲ ਐਗਜ਼ੀਕਿਊਸ਼ਨ ਦੀ ਤਸਦੀਕ ਕਰੋ। ਉਤਪਾਦਨ ਪ੍ਰਣਾਲੀ ਉੱਤੇ ਆਫ਼ਤ ਰਿਕਵਰੀ ਸਾਬਤ ਹੋਣ ਦਾ ਐਲਾਨ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਐਨਕ੍ਰਿਪਟਡ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ, ਵੈਬਹੂਕਸ ਅਤੇ ਬਾਹਰੀ ਫਾਈਲਾਂ ਦੀ ਵੀ ਜਾਂਚ ਕਰੋ।

ਡ੍ਰਿਲ ਸਵੀਕਾਰਤਾ ਚੈੱਕਲਿਸਟ ਨੂੰ ਰੀਸਟੋਰ ਕਰੋ ਇੱਕ ਅਲੱਗ ਡੋਮੇਨ/ਵਾਤਾਵਰਣ ਦੀ ਵਰਤੋਂ ਕਰੋ; ਜਾਂਚ ਕਰੋ ਕਿ ਉਪਭੋਗਤਾ ਅਤੇ ਵਰਕਫਲੋ ਮੌਜੂਦ ਹਨ, ਇੱਕ ਮੌਜੂਦਾ ਐਨਕ੍ਰਿਪਟਡ ਪ੍ਰਮਾਣ ਪੱਤਰ ਬਿਨਾਂ ਰੀ-ਐਂਟਰੀ ਦੇ ਪ੍ਰਮਾਣਿਤ ਹੁੰਦਾ ਹੈ, ਇੱਕ ਉਤਪਾਦਨ ਵੈਬਹੁੱਕ ਉਦੇਸ਼ਿਤ ਬਹਾਲ ਵਰਕਫਲੋ ਨੂੰ ਸੱਦਾ ਦਿੰਦਾ ਹੈ, ਮਾਊਂਟ ਕੀਤੀਆਂ ਫਾਈਲਾਂ ਅਤੇ ਬਾਈਨਰੀ ਅਟੈਚਮੈਂਟ ਪਡ਼੍ਹਨ ਯੋਗ ਰਹਿੰਦੀਆਂ ਹਨ, ਅਤੇ ਲੋਡ਼ੀਂਦੇ ਕਮਿਊਨਿਟੀ ਨੋਡਸ ਲੋਡ ਨਾਲ ਏਕੀਕਰਨ। ਬੈਕਅੱਪ ਦੀ ਉਮਰ, ਮਾਪੀ ਗਈ ਡਾਊਨਟਾਈਮ ਅਤੇ ਆਫ-ਸਰਵਰ ਪਹੁੰਚਯੋਗਤਾ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ। ਜੇ ਕੋਈ ਜ਼ਰੂਰੀ ਚੈੱਕ ਅਸਫਲ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਉਸ ਰਿਕਵਰੀ ਬਿੰਦੂ ਨੂੰ ਨਿਸ਼ਾਨਬੱਧ ਕਰੋ ਤਸਦੀਕ ਨਾ ਕੀਤਾ ਗਿਆ ਬੈਕਅੱਪ ਨੂੰ ਸੰਪੂਰਨ ਦੱਸਣ ਦੀ ਬਜਾਏ।

ਵਰਕਫਲੋ ਅਤੇ ਪ੍ਰਮਾਣ ਪੱਤਰ ਨਿਰਯਾਤ ਉਹਨਾਂ ਦੇ ਮੂਲ ਆਈ. ਡੀ. ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਦੇ ਹਨ। ਇੱਕ ਉਦਾਹਰਣ ਵਿੱਚ ਇੰਪੋਰਟ ਕਰਨਾ ਜਿਸ ਵਿੱਚ ਪਹਿਲਾਂ ਤੋਂ ਹੀ ਉਹੀ ਆਈ. ਡੀ. ਹਨ, ਉਹਨਾਂ ਮੌਜੂਦਾ ਆਈਟਮਾਂ ਨੂੰ ਬਦਲ ਸਕਦਾ ਹੈ।

ਦਰਾਮਦ ਕੀਤੇ ਵਰਕਫਲੋ ਜਾਣਬੁੱਝ ਕੇ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰੋ

CLI ਦਰਾਮਦਾਂ ਆਮ ਤੌਰ ਉੱਤੇ ਵਰਕਫਲੋ ਨੂੰ ਸਰਗਰਮ ਛੱਡ ਦਿੰਦੀਆਂ ਹਨ। n8n 2. x ਉੱਤੇ, ਹਰੇਕ ਦਰਾਮਦ ਕੀਤੇ ਵਰਕਫਲੋ ਦੀ ਪ੍ਰਕਾਸ਼ਿਤ ਸਥਿਤੀ ਦੀ ਜਾਂਚ ਕਰੋ ਅਤੇ ਸਿਰਫ ਉਹਨਾਂ ਵਰਕਫਲੋ ਨੂੰ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰੋ ਜਿਨ੍ਹਾਂ ਨੂੰ ਤੁਸੀਂ ਚਲਾਉਣਾ ਚਾਹੁੰਦੇ ਹੋ; ਸਵੈ-ਮੇਜ਼ਬਾਨੀ ਸਰਵਰ CLI ਵੀ n8n ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈਃ ਵਰਕਫਲੋ-- ਆਈਡੀ = ਤੁਹਾਡਾ _ ਵਰਕਫਲੋ _ ਆਈਡੀ। ਜਦੋਂ n8n ਚੱਲ ਰਿਹਾ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਸਰਵਰ CLI ਪ੍ਰਕਾਸ਼ਿਤ/ਪ੍ਰਕਾਸ਼ਤ ਸਥਿਤੀ ਵਿੱਚ ਤਬਦੀਲੀਆਂ n8n ਨੂੰ ਮੁਡ਼ ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਬਾਅਦ ਹੀ ਪ੍ਰਭਾਵੀ ਹੁੰਦੀਆਂ ਹਨ। ਨਿਰਧਾਰਤ ਟਰਿੱਗਰਾਂ ਅਤੇ ਉਤਪਾਦਨ ਵੈਬਹੁੱਕਾਂ ਦੀ ਤਸਦੀਕ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਮੁਡ਼ ਸ਼ੁਰੂ ਕਰੋ ਜਾਂ ਟ੍ਰੈਫਿਕ ਨੂੰ ਬਦਲਣਾ।

Docker ਲਈ ਬਲਕ ਐਕਸਪੋਰਟ ਉਦਾਹਰਨ ਕੰਪੋਜ਼ਃ ਜੇ ਤੁਹਾਡੀ n8n ਸੇਵਾ ਦਾ ਨਾਮ ਹੈ n8nਤੁਸੀਂ ਹੇਠਾਂ ਅਧਿਕਾਰਤ CLI ਬੈਕਅੱਪ ਚਲਾ ਸਕਦੇ ਹੋ। ਆਉਟਪੁੱਟ ਮਾਰਗ ਜਾਣਬੁੱਝ ਕੇ ਇਸ ਦੇ ਮਾਊਂਟ ਕੀਤੇ ਸਥਾਈ ਦੇ ਅੰਦਰ ਹੈ। .n8n ਡਾਇਰੈਕਟਰੀ, ਕਿਉਂਕਿ ਇੱਕ ਡੱਬੇ ਦੇ ਅੰਦਰ ਮਨਮਰਜ਼ੀ ਵਾਲੀਆਂ ਡਾਇਰੈਕਟਰੀਆਂ ਅਲੋਪ ਹੋ ਸਕਦੀਆਂ ਹਨ ਜਦੋਂ ਇਸ ਨੂੰ ਦੁਬਾਰਾ ਬਣਾਇਆ ਜਾਂਦਾ ਹੈ। ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਡੈਕਟਰੀ n8n ਡੱਬੇ ਦੇ ਉਪਭੋਗਤਾ ਦੁਆਰਾ ਲਿਖਣ ਯੋਗ ਹੈ। ਵਰਕਫਲੋ ਅਤੇ ਪ੍ਰਮਾਣ ਪੱਤਰ JSON ਵਿੱਚ ਰੱਖੋ। ਵੱਖਰੀਆਂ ਡਾਇਰੈਕਟਰੀਆਂ- n8n ਇੱਕ ਦਰਾਮਦ ਸਮੱਸਿਆ ਦਾ ਦਸਤਾਵੇਜ਼ ਦਿੰਦਾ ਹੈ ਜਦੋਂ ਦੋਵੇਂ ਕਿਸਮਾਂ ਇੱਕ ਡਾਇਰੈਕਟਰੀ ਸਾਂਝੀਆਂ ਕਰਦੀਆਂ ਹਨ।

n8n 2. x ਡਰਾਫਟ ਬਨਾਮ ਪ੍ਰਕਾਸ਼ਿਤ ਬੈਕਅੱਪਃ ਇੱਕ ਆਮ --backup ਵਰਕਫਲੋ ਐਕਸਪੋਰਟ ਮੌਜੂਦਾ ਡਰਾਫਟ ਨੂੰ ਕੈਪਚਰ ਕਰਦਾ ਹੈ; ਇਹ ਉਤਪਾਦਨ ਵਿੱਚ ਪ੍ਰਕਾਸ਼ਿਤ ਸੰਸਕਰਣਾਂ ਤੋਂ ਵੱਖਰੇ ਹੋ ਸਕਦੇ ਹਨ। ਕਿਸੇ ਵਿਸ਼ੇਸ਼ ਵਰਕਫਲੋ ਦੇ ਅਸਲ ਪ੍ਰਕਾਸ਼ਿਤ ਸੰਸਕਰਣ ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਣ ਲਈ, ਇਸ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਇਸ ਨੂੰ ਵੱਖਰੇ ਤੌਰ'ਤੇ ਐਕਸਪੋਰਟ ਕਰੋ। docker compose exec -T n8n n8n export:workflow --id=WORKFLOW_ID --published --output=/home/node/.n8n/backups/published-workflow.jsonਇਹ ਸੁਨਿਸ਼ਚਿਤ ਕਰਨ ਤੋਂ ਬਾਅਦ ਕਿ ਆਉਟਪੁੱਟ ਫੋਲਡਰ ਮੌਜੂਦ ਹੈ ਅਤੇ ਲਿਖਣ ਯੋਗ ਹੈ। CLI ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਇੱਕ ਇਤਿਹਾਸਕ ਸੰਸਕਰਣ ਵੀ ਨਿਰਯਾਤ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ। --version=VERSION_IDਇਹਨਾਂ ਕੈਪਚਰਾਂ ਨੂੰ ਪੂਰੇ ਬੈਕਅੱਪ ਦੇ ਨਾਲ ਆਫ-ਸਰਵਰ ਰੱਖੋ; ਇਹ ਨਾ ਮੰਨੋ ਕਿ ਡਰਾਫਟ JSON ਲਾਈਵ ਪ੍ਰਕਾਸ਼ਿਤ ਸਥਿਤੀ ਨੂੰ ਰਿਕਾਰਡ ਕਰਦਾ ਹੈ।
