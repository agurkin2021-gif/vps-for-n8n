НУСХАБАРДОРӢ ВА БАРҚАРОРСОЗӢ

Нусхаи эҳтиётӣ ва барқарорсозии n8n

Барои нусхабардорӣ ва барқарор кардани n8n бо хостинги мустақил, пойгоҳи додаҳои SQLite ё нусхаи мутобиқи PostgreSQL, ҷузвдони доимии .n8n ва калиди аслии рамзгузорӣ, танзимоти ҷойгиркунӣ ва тамоми вобастагиҳои файлҳои бинарии беруна ё ҷузвдонҳои васлшударо ҳифз кунед. Нусхаи рамзгузоришударо берун аз VPS нигоҳ доред ва барқарорсозиро дар нусхаи алоҳида санҷед. Барои барқарорсозии интихобӣ аз содироти ҷараёнҳо ва маълумоти дастрасӣ тавассути CLI истифода баред; танҳо содироти JSON нусхаи пурраи сервер нест.

Барои n8n VPS интихоб кунед

Пайванди шарикӣ: мо метавонем аз харидҳо комиссия гирем.

РӮЙХАТИ САНҶИШИ ЗУД

Нусхаи эҳтиётии n8n бояд чиро ҳифз кунад

Пойгоҳи додаҳо

Пойгоҳи додаҳои PostgreSQL ё файли пойгоҳи додаҳои SQLite-и истифодашавандаи нусхаи n8n-ро нусхабардорӣ кунед. Пойгоҳи додаҳо ҳолати асосии n8n, аз ҷумла ҷараёнҳои корӣ, маълумоти дастрасӣ ва маълумоти иҷроишҳоро нигоҳ медорад.

Калиди рамзгузорӣ

Калиди айнан ҳамон рамзгузории n8n-ро алоҳида ва боэътимод нигоҳ доред. Маълумоти дастрасии рамзгузоришуда баъди барқарорсозӣ ба ҳамон калид вобаста аст.

Файлҳои доимӣ

Ҷузвдони додаҳои доимии n8n ва ҳар гуна файлҳои васлшуда, захираи додаҳои бинарӣ ё файлҳои ҷараёнҳои кориро, ки ҷойгиркунии шумо истифода мебарад, дохил кунед.

Танзимоти ҷойгиркунӣ

Файлҳои Compose/танзимот ва танзимоти ғайримахфиеро, ки барои аз нав сохтани муҳит лозиманд, нигоҳ доред. Маълумоти махфиро бо назорати мувофиқи дастрасӣ ҳифз намоед.

ДУ САТҲИ НУСХАБАРДОРӢ

Содироти мантиқӣ ё барқарорсозии пурра пас аз садама

Содироти ҷараёнҳо ва маълумоти дастрасӣ

Содироти CLI-и n8n барои интиқол, нигоҳдории версияҳои ҷараёнҳо ва барқарорсозии интихобӣ муфид аст. Маълумоти дастрасиро метавон дар шакли рамзгузоришуда содир кард ва баъд бо калиди мувофиқи рамзгузорӣ ворид намуд. Барои барқарор кардани танҳо як ҷараён дар муҳаррири он менюи се нуқтаро кушода, JSON-ро бо Download боргирӣ кунед ва сипас бо Import from File ба ҷараёни нави санҷишӣ ё нусхаи ҷудогона ворид созед. Пеш аз иваз кардани ҷараёни фаъол маълумоти дастрасӣ, ID-и ҷараён ва параметрҳои гиреҳҳоро санҷед: барқарор кардани JSON-и ҷараён тамоми серверро барқарор намекунад.

Содироти объектҳо

CLI метавонад объектҳои пойгоҳи додаҳоро барои интиқол байни навъҳои дастгиришавандаи пойгоҳи додаҳо содир кунад. Ҷадвалҳои таърихи иҷроишҳо ихтиёрианд, зеро хеле калон шуда метавонанд.

Барқарорсозии пурраи нусхаи барнома

Барои ҳолати аз кор баромадани сервер, худи пойгоҳи додаҳо, калиди рамзгузорӣ, додаҳои доимӣ ва вобастагиҳои ҷойгиркуниро ҳифз кунед. Гумон накунед, ки содироти JSON-и ҷараён тамоми нусхаро аз нав месозад.

Снапшоти провайдер

Снапшоти VPS ҳамчун қабати иловагии барқарорсозӣ муфид аст, аммо набояд ягона нусха бошад ё нусхаи мустақилона санҷидашудаи барнома ва пойгоҳи додаҳоро иваз кунад.

ПОЙГОҲИ ДОДАҲО

Пойгоҳи додаҳоро дар ҳолати мутобиқ нусхабардорӣ кунед

PostgreSQL

Барои PostgreSQL усули нусхабардории мутобиқро истифода баред ва нусхаро берун аз VPS нигоҳ доред. Нусхаи пойгоҳи додаҳо дар ҳамон диски азкорбаромада барқарорсозӣ пас аз садама ҳисоб намешавад.

SQLite

Агар ҷойгиркунии шумо SQLite-ро истифода барад, файли пойгоҳи додаҳоро аз ҷузвдони доимии n8n ҳифз кунед. Ҳангоми тағйирёбии фаъоли пойгоҳи додаҳо аз нусхабардории он дар ҳолати номувофиқ худдорӣ намоед.

Таърихи иҷроишҳо

Муайян кунед, ки оё таърихи иҷроишҳо ба ҳадафи барқарорсозии шумо дохил мешавад. Он метавонад нусхаҳоро хеле калон кунад, бинобар ин муҳлати нигоҳдорӣ ва талаботи мутобиқат бояд ба қарор асос бошанд.

Версияи пойгоҳи додаҳо

Навъ ва версияи муҳаррики пойгоҳи додаҳои муҳити ибтидоиро сабт кунед, то муҳити барқарорсозӣ бо он мувофиқ омода шавад.

PostgreSQL дар VPS бо Docker Compose. Агар хидмати PostgreSQL postgres ном дошта бошад ва пойгоҳи додаҳо ва корбараш ҳар ду n8n бошанд, фармони зерин нусхаи мутобиқи PostgreSQL-ро дар формати махсус дар хост эҷод мекунад. Пеш аз иҷро файли воқеии Compose-и худро санҷед ва номи хидмат ва маълумоти дастрасии пойгоҳи додаҳоро мувофиқ кунед. pg_dump метавонад ҳангоми кори PostgreSQL нусхаи мантиқан мутобиқ эҷод кунад; аммо он на ҷузвдони алоҳидаи .n8n -ро ва на додаҳои бинарии берунаро нусхабардорӣ намекунад.

# In the Docker Compose project; adapt service, DB and user names
docker compose exec -T postgres pg_dump -U n8n -d n8n -Fc > n8n-postgres.dump
test -s n8n-postgres.dump
# Check that the archive has a readable object list
docker compose exec -T postgres pg_restore --list < n8n-postgres.dump

Санҷиши рӯйхати объектҳои бойгонӣ камбудиҳои ошкори форматро нишон медиҳад, вале исбот намекунад, ки додаҳо барқарор мешаванд. Нусхаи рамзгузоришударо берун аз сервер нигоҳ доред ва барқарорсозиро амалан санҷед. Барои имконоти хоси пойгоҳи додаҳо ба ҳуҷҷатҳои расмии PostgreSQL оид ба pg_dump муроҷиат кунед.

SQLite дар Docker. Барои ҷойгиркунии пешфарзи SQLite, database.sqlite ва танзимоти калиди рамзгузории тавлидшуда дар ҷузвдони доимии .n8n ҷойгиранд (одатан дар /home/node/.n8n васл мешавад). Нусхаи одии SQLite-ро ҳангоми кори фаъол ҳатман мутобиқ ҳисоб накунед. Пеш аз нусхабардории ҷузвдон n8n ва дигар равандҳои нависанда ба пойгоҳи додаҳоро боздоред, ё агар қатъ кардани кор ғайриимкон бошад, аз механизми дастгиришавандаи нусхабардории онлайнии SQLite истифода кунед:

# Only for SQLite and the default /home/node/.n8n mount
# Stop n8n (and any other writers) before copying an SQLite database
docker compose stop n8n
docker compose cp n8n:/home/node/.n8n ./n8n-user-folder-backup
docker compose start n8n

Инҳо фармонҳои намунавӣ барои хидмат ва роҳи нишондодашудаанд, на сохтори умумии ҳамаи volume-ҳо. Ҷузвдони нусхабардоришуда ҳоло ҳам дар ҳамон VPS аст; онро берун аз сервер интиқол дода, ҳифз намоед. Агар коргарҳои навбат ё равандҳои дигари нависанда мавҷуд бошанд, онҳоро низ ба ҳолати ором гузаронед ва ба меъмории воқеии ҷойгиркунии худ пайравӣ кунед. Дастури ҷории n8n оид ба нусхабардории пурра талаботи мутобиқати SQLite-ро шарҳ медиҳад.

Барқарор кардани ҷузвдони пешфарзи SQLite дар муҳити тоза: аввал хидмати n8n ва ҳамаи равандҳои нависанда ба пойгоҳи додаҳоро боздоред. Вақте контейнер бо версияи мувофиқи n8n ва volume-и таъинотӣ омода аст, муҳтавои ҷузвдони нусхабардоришудаи .n8n ро дубора ба ҳамон ҷузвдони доимӣ нусхабардорӣ кунед. Ин амал файлҳои ҳадафро рӯйнавис мекунад; онро дар нусхае, ки маълумоти арзишманд дорад, иҷро накунед:

# Run only on the intended CLEAN recovery instance
docker compose stop n8n
docker compose cp ./n8n-user-folder-backup/. n8n:/home/node/.n8n/
# Verify ownership and permissions for the n8n container user BEFORE the next command
# Start only after restored files are readable/writable by n8n
docker compose start n8n
# Check logs, restored credentials and workflow triggers

Docker метавонад ба контейнерҳои боздошташуда файл нусхабардорӣ кунад, аммо соҳиби файлҳои ҳадаф метавонад аз ҳолати аввал фарқ кунад; пеш аз оғоз мутмаин шавед, ки раванди n8n метавонад файли танзимот ва пойгоҳи додаҳои барқароршударо хонад ва тағйир диҳад. Агар Compose-и воқеии шумо роҳ ё bind mount-и дигар дошта бошад, фармони нусхабардориро мутобиқ кунед. Маълумотномаи нусхабардории Docker Compose. Танҳо барқарор кардани ҷузвдони n8n барои муҳитҳое, ки пойгоҳи додаҳои алоҳидаи PostgreSQL доранд, кофӣ нест.

МАЪЛУМОТИ МАХФИИ МУҲИМ

Калиди рамзгузорӣ ҷузъи барқарорсозӣ аст

n8n маълумоти дастрасии захирашударо бо калиди рамзгузории ҳамон нусха ҳифз мекунад. Пойгоҳи додаҳо ё содироти рамзгузоришудаи маълумоти дастрасӣ бе калиди мувофиқ метавонад боис шавад, ки ҷараёнҳои барқароршуда маълумоти дастрасии захиракардаашонро истифода бурда натавонанд.

Агар N8N_ENCRYPTION_KEY таъин шуда бошад, айнан ҳамон арзиши махфиро барқарор кунед. Дар акси ҳол калиди тавлидшуда дар файли доимии .n8n/config нигоҳ дошта мешавад: ҳангоми нусхабардорӣ ё аз нав сохтани муҳит онро ҳифз намоед. Калидҳои барқарорсозиро боэътимод берун аз VPS нигоҳ доред. Дар режими навбат ҳамаи равандҳои асосӣ ва коргар бояд як калидро истифода баранд.

ҲатманНусхаи муҳофизатшудаи калиди аслии муҳити истеҳсолиро нигоҳ доред.
ҲатманПеш аз санҷиши маълумоти дастрасӣ мутмаин шавед, ки муҳити барқарорсозӣ ҳамон калидро истифода мебарад.
НакунедПас аз аз нав сохтани сервер ба калиди навтаҳияшуда такя накунед.
НакунедКалидро ба репозитории оммавӣ нафиристед ва дар паҳлуи нусхаи эҳтиётии муҳофизатнашуда нигоҳ надоред.

ФАЙЛҲО ВА ДОДАҲОИ БИНАРӢ

Нусхаи пойгоҳи додаҳо шояд ҳамаи вобастагиҳои ҷараёнҳоро дар бар нагирад

Додаҳои доимии .n8n

Ҷузвдони воқеии корбарии .n8n-ро пайдо ва ҳифз кунед, на танҳо образи контейнерро. Дар насби маъмулии Docker он ба /home/node/.n8n васл мешавад; берун аз Docker роҳи пешфарз ~/.n8n аст. Агар N8N_USER_FOLDER таъин шуда бошад, n8n ҷузвдони .n8n-ро дар дохили роҳи падари муайяншуда эҷод мекунад. Танзимоти дорои калид ва ҳар гуна додаҳои маҳаллии SQLite, бинарӣ ё иҷроишҳоро, ки насби шумо истифода мебарад, дохил кунед.

Файлҳои ҷараёнҳои васлшуда

Агар ҷараёнҳо аз ҷузвдонҳои васлшудаи хост бихонанд ё ба онҳо нависанд, онҳоро алоҳида нусхабардорӣ кунед. Бе онҳо ҳатто ҷараёнҳои дуруст барқароршуда метавонанд кор накунанд.

Додаҳои бинарӣ

Режими нигоҳдориро муайян намуда, ҳамаи вобастагиҳои берунаро барқарор кунед. Додаҳои бинарӣ ё иҷроишҳое, ки дар системаи файлӣ нигоҳ дошта мешаванд, метавонанд дар .n8n ё ҷузвдони фармоишӣ бошанд; барои S3/Azure Blob ё дигар захираи беруна нусхаи барқароршавандаи алоҳида ва танзимоти дастрасӣ лозиманд. Танҳо нусхаи пойгоҳи додаҳо ин файлҳоро иваз карда наметавонад.

Гиреҳҳои иловагии ҷомеа

Бастаҳо ва версияҳои ҷомеаро сабт кунед ва ҷузвдонҳои иловагии гиреҳҳои фармоиширо, ки тавассути N8N_CUSTOM_EXTENSIONS танзим шудаанд, нусхабардорӣ намоед. Ин ҷузвдонҳо метавонанд берун аз .n8n бошанд; танҳо барқарор кардани пойгоҳи додаҳо ва ҷузвдони корбар метавонад ҷараёнҳои дорои гиреҳҳои фармоиширо ҳанӯз ҳам ғайриқобили истифода гузорад.

СТРАТЕГИЯИ НИГОҲДОРӢ БЕРУН АЗ СЕРВЕР

Нусхаи эҳтиётӣ дар ҳамон VPS танҳо нусхаи маҳаллӣ аст

Нусхаи маҳаллӣБарои бозгашти зуд ба ҳолати қаблӣ муфид, аммо дар баробари аз даст рафтани сервер, вайроншавии диск ва хатоҳои харобкунанда осебпазир аст.
Нусхаи берун аз серверҲадди ақал як нусхаро дар захираи мустақил аз VPS-и истеҳсолӣ нигоҳ доред.
Нусхаҳои версиядорЯкчанд нуқтаи барқарорсозиро нигоҳ доред, то вайроншавии додаҳо ё тағйироти нодуруст ягона нусхаи қобили истифодаро аз байн набарад.
Назорати дастрасӣНусхаҳо метавонанд маълумоти дастрасӣ, мантиқи ҷараёнҳо ва додаҳои махфии тиҷоратиро дар бар гиранд. Онҳоро рамзгузорӣ кунед ва дастрасиро маҳдуд намоед.
МониторингАгар нусхабардории нақшавӣ ноком шавад ё нуқтаҳои нави барқарорсозӣ дигар эҷод нашаванд, огоҳӣ диҳед.

Ҷадвалро ченшаванда созед. Замони ҳар нусхабардории муваффақ, анҷоми интиқол, ҳаҷми файл, версияи пойгоҳи додаҳои ибтидоӣ, маҳалли нигоҳдории калиди барқарорсозӣ ва охирин санҷиши муваффақи барқарорсозиро сабт кунед. Барои файлҳои нопадидшуда, номуваффақ ё ғайричашмдошт холӣ огоҳӣ танзим намоед. Пеш аз интиқол аз VPS бойгониҳои нусхабардориро рамзгузорӣ кунед ва дастрасӣ ба маълумоти махфии барқарорсозиро маҳдуд созед. Якчанд нуқтаи барқарорсозии санаҳояшон гуногун аз ҳолате муҳофизат мекунанд, ки вайроншавӣ танҳо баъди рӯйнавис шудани охирин нусхаи солим бо нусхаи нав ошкор мешавад.

Масалан, агар шумо аз даст рафтани тағйироти ҳадди аксар шашсоатаро таҳаммул карда тавонед, нусхабардории муваффақ ҳар шаш соат нуқтаи оғоз аст, на кафолат: вазифаҳои номуваффақ ва таъхири интиқол ба захираи берунӣ талафоти воқеиро зиёд мекунанд. Муҳлати нигоҳдорӣ ва басомади санҷиши барқарорсозиро мувофиқи RPO/RTO ва талаботи додаҳои худ танзим кунед, на аз рӯйи сиёсати умумии тахминии 7 ё 30 рӯз.

ТАРТИБИ БАРҚАРОРСОЗӢ

Бо пайдарпайии назоратшаванда барқарор кунед

1 · ОмодагӣСервер, пойгоҳи додаҳо ва муҳити контейнер ё иҷроиши мувофиқро омода кунед.
2 · Барқарор кардани маълумоти махфӣКалиди аслии рамзгузории n8n ва дигар маълумоти махфии зарурии ҷойгиркуниро боэътимод танзим намоед.
3 · Барқарор кардани пойгоҳи додаҳоPostgreSQL ё SQLite-ро барқарор карда, пайвасти n8n-ро ба додаҳои пешбинишуда санҷед.
4 · Барқарор кардани файлҳоҶузвдонҳои доимӣ, додаҳои бинарӣ ва файлҳои васлшудаи ҷараёнҳоро барқарор намоед.
5 · Оғози n8nБарномаро бо номи хости пешбинишуда, пойгоҳи додаҳо ва танзимоти муҳит ба кор дароред.
6 · Санҷиши дурустӣБор шудани корбарон, ҷараёнҳо ва маълумоти дастрасиро тасдиқ карда, ҷараёнҳои намунавӣ ва роҳҳои вебҳукро иҷро кунед.

Мисоли барқарорсозии PostgreSQL баъд аз садама: дар муҳити алоҳида ва тозаи барқарорсозӣ, ки аллакай нақши дурусти пойгоҳи додаҳо ва пойгоҳи холии n8n дорад, дар аввал танҳо PostgreSQL-ро ба кор дароред. Пеш аз воридсозӣ то омода шудани он мунтазир шавед: docker compose up -d метавонад пеш аз анҷоми оғозёбии PostgreSQL баргардад; аз ин рӯ, фармони баъдии pg_restore ноком мешавад. Намуна аз --wait дар версияи муосири Compose истифода мебарад ва омодагиро ҳамчунин бо pg_isready алоҳида месанҷад. Барои интизории боэътимод санҷиши саломатии PostgreSQL-ро танзим кунед ё пеш аз идома омодагиро возеҳ тасдиқ намоед. Ин фармонро ба пойгоҳи додаҳои истеҳсолии пуршуда равона накунед ва пеш аз барқарор шудани пойгоҳи додаҳо ва калид/додаҳои мувофиқи .n8n n8n-ро оғоз накунед.

# RESTORE ONLY TO A FRESH, EMPTY TARGET DATABASE
# Adapt Postgres Compose service, database and user names
docker compose up -d --wait postgres
docker compose exec -T postgres pg_isready -U n8n -d n8n
docker compose exec -T postgres pg_restore --exit-on-error --no-owner --no-acl -U n8n -d n8n < n8n-postgres.dump

Муҳити ҳадаф бояд версияи мувофиқи PostgreSQL, ҳуқуқҳои нақш, васеъшавиҳо ва танзимоти аслии n8n дошта бошад. Ҷузвдони .n8n ро бо усули нусхабардории худ ба volume ё bind mount-и дурусти доимӣ барқарор намуда, соҳиби файлҳо ва ҳуқуқҳои дастрасиро нигоҳ доред. Файлҳои бинарии беруна, васеъшавиҳои фармоишӣ, Compose ва маълумоти махфиро барқарор кунед; сипас n8n-ро бо версияи мувофиқ оғоз намуда, логҳоро санҷед. Танҳо пойгоҳи додаҳоро барқарор кардан калидро барнамегардонад: дар ҷойгиркунии PostgreSQL калид дар .n8n/config нигоҳ дошта мешавад, магар он ки шумо N8N_ENCRYPTION_KEY ро возеҳ танзим карда бошед. САНҶИШИ БАРҚАРОРСОЗӢ

То барқарорсозӣ муваффақ нашавад, нусхаи эҳтиётӣ исботшуда нест

Дар муҳити тоза санҷед

Санҷиши воқеӣ бояд собит кунад, ки нусха бе такя ба файлҳои эълоннашудаи дар сервери истеҳсолӣ боқимонда метавонад муҳитро аз нав созад.

Маълумоти дастрасиро санҷед

Танҳо кушода шудани ҷараён кофӣ нест. Тасдиқ кунед, ки маълумоти дастрасии рамзгузоришуда пас аз барқарорсозӣ воқеан кушода мешавад ва санҷиши ҳувият бомуваффақият мегузарад.

Ҷараёнҳои намунавиро иҷро кунед

Ба ҷойи санҷидани танҳо як автоматикунонии сода, ҷараёнҳои вобаста ба вебҳукҳо, API-ҳои беруна, файлҳои васлшуда ва гиреҳҳои ҷомеаро санҷед.

Вақти барқарорсозиро чен кунед

Сабт кунед, ки барқарорсозӣ чӣ қадар давом кард ва кадом қадамҳои дастӣ боқӣ монданд. Ҳамин тавр нусхаи эҳтиётии тахминӣ ба дастури амалии барқарорсозӣ табдил меёбад.

Санҷиши тасдиқшудаи барқарорсозӣ: SQLite ва PostgreSQL

Муҳити санҷиш: n8n 2.42.5 дар контейнерҳои ҷудогонаи Docker дар муҳити муваққатии GitHub Actions, бо ҷараёни санҷишии сохта аз ду гиреҳ. Ин санҷишҳо 8 октябри 2026анҷом дода шуданд, на дар сервери муштарӣ ё сервери истеҳсолии n8n.

SQLite: PASSҶараёни санҷиширо ворид ва содир кардем, ҳамаи равандҳои нависандаро боздоштем, ҷузвдони доимии SQLite-и .n8n ва калиди тавлидшудаи рамзгузории онро бойгонӣ кардем, ба volume-и тоза барқарор намудем, n8n-ро оғоз кардем ва ҷараёни барқароршударо дубора содир ва иҷро намудем.
PostgreSQL: PASSҲамон ҷараёни санҷиширо ворид карда, бо формати махсус pg_dump эҷод ва санҷидем, онро тавассути pg_restore ба пойгоҳи нави холии PostgreSQL барқарор кардем, ҷузвдони алоҳидаи .n8n ро низ барқарор карда, баъд ҷараёнро дубора содир ва иҷро намудем.
PASS чиро тасдиқ мекунадРоҳҳои санҷидашудаи нусхабардорӣ ин ҷараён, ду гиреҳ ва пайвастҳои онҳоро нигоҳ доштанд ва пас аз барқарорсозӣ иҷрои ҷараёнро имконпазир карданд. Инҳо санҷишҳои такроршавандаи асосии коршоямӣ мебошанд, на озмоишҳои сарборӣ ё суръат.
Чӣ санҷида нашудКушодани рамз ва санҷиши ҳувияти маълумоти дастрасии воқеӣ, вебҳукҳои истеҳсолӣ, коргарҳои режими навбат ва Redis, захираи бинарии S3/Azure, гиреҳҳои фармоишӣ, дастрасии корбарон ва лоиҳаҳо ё барқарор кардани нусхаи истеҳсолии фаъол. Барои ҳар вобастагии истифодашаванда санҷиши алоҳида гузаронед.

Тарзи такрори санҷиш: насби муваққатии n8n-ро истифода баред, ҷараёни безарари дугиреҳӣ эҷод кунед, аз пойгоҳи додаҳо ва ҷузвдони доимӣ нусхаи мувофиқ гиред, онро ба volume ё пойгоҳи додаҳои тоза барқарор кунед ва гиреҳҳо, пайвастҳо ва иҷрои воқеии ҷараёни барқароршударо санҷед. Дар муҳити истеҳсолӣ пеш аз тасдиқи барқарорсозии баъди садама инчунин маълумоти дастрасии рамзгузоришуда, вебҳукҳо ва файлҳои берунаро санҷед.

Рӯйхати қабули санҷиши барқарорсозӣ: домен ё муҳити ҷудогона истифода баред; мавҷуд будани корбарон ва ҷараёнҳоро санҷед, боварӣ ҳосил намоед, ки як маълумоти дастрасии рамзгузоришудаи мавҷуда бе воридсозии дубора кор мекунад, вебҳуки истеҳсолӣ ҷараёни барқароршудаи дурустро оғоз мекунад, файлҳои васлшуда ва замимаҳои бинарӣ хонда мешаванд ва ҳамгироиҳои вобаста ба гиреҳҳои ҷомеа бор мешаванд. Синни нусха, вақти воқеии қатъи кор ва дастрасии нусха аз берунро тасдиқ кунед. Агар ягон санҷиши муҳим ноком шавад, он нуқтаи барқарорсозиро тасдиқнашуда ҳисоб кунед, на нусхаи эҳтиётии пурра.

МАҲДУДИЯТҲОИ НУСХАБАРДОРИИ CLI

Дақиқ фаҳмед, ки содироти ҷараёнҳо ва маълумоти дастрасӣ чиро барқарор намекунад

Содироти CLI нусхаи пурраи муҳит нест

Содироти эҳтиётии ҷараёнҳо ва маълумоти дастрасӣ корбарон ва нақшҳо, таърихи иҷроишҳо ва логҳо, тағйирёбандаҳо ё танзимоти нусха, аз ҷумла калиди рамзгузориро дар бар намегирад.

Барои барқарорсозӣ дар муҳити нав соҳиби ҳисоб лозим аст

Дар муҳити тоза пеш аз ворид кардани маълумоти дастрасӣ танзими соҳиби ҳисобро анҷом диҳед. Барқарорсозии чандкорбарӣ ё лоиҳаҳо метавонад таъини дурусти корбар ё лоиҳаро талаб кунад.

ID-ҳои воридшуда метавонанд маълумоти мавҷударо рӯйнавис кунанд

Содироти ҷараёнҳо ва маълумоти дастрасӣ ID-ҳои аслиро нигоҳ медорад. Воридсозӣ ба муҳите, ки аллакай ҳамон ID-ҳоро дорад, метавонад объектҳои мавҷударо иваз кунад.

Ҷараёнҳои воридшударо боэҳтиёт нашр кунед

Воридсозии CLI одатан ҷараёнҳоро ғайрифаъол мегузорад. Дар n8n 2.x ҳолати нашршудаи ҳар ҷараёни воридшударо санҷед ва танҳо ҷараёнҳои лозимро нашр намоед; CLI-и сервери худидорашаванда низ фармони n8n publish:workflow --id=YOUR_WORKFLOW_ID-ро дастгирӣ мекунад. Ҳангоми фаъол будани n8n тағйироти ҳолати нашр/бекор кардани нашр тавассути CLI танҳо баъди бозоғозии n8n амал мекунанд. Пеш аз санҷиши триггерҳои нақшавӣ ва вебҳукҳои истеҳсолӣ ё иваз кардани трафик серверро бозоғозӣ намоед.

Мисоли содироти гурӯҳӣ барои Docker Compose: агар номи хидмати n8n-и шумо n8n бошад, метавонед аз фармонҳои расмии CLI-и поён истифода баред. Роҳи барориши файл қасдан дар ҷузвдони доимии .n8n гузошта шудааст, зеро ҷузвдонҳои дилхоҳи дохили контейнер ҳангоми аз нав сохтани он метавонанд нопадид шаванд. Тасдиқ кунед, ки корбари контейнери n8n ҳуқуқи навиштан дар ин ҷузвдонро дорад. Файлҳои JSON-и ҷараёнҳо ва маълумоти дастрасиро дар ҷузвдонҳои алоҳида нигоҳ доред — n8n мушкили воридсозиро ҳангоми якҷо гузоштани ин ду навъ дар як ҷузвдон ҳуҷҷатгузорӣ кардааст.

Нусхаи эҳтиётии лоиҳа (draft) ва версияи нашршуда дар n8n 2.x: содироти муқаррарӣ бо --backup лоиҳаҳои ҷориро нигоҳ медорад; онҳо метавонанд аз версияҳои дар муҳити истеҳсолӣ нашршуда фарқ кунанд. Барои ҳифзи версияи воқеан нашршудаи ҷараёни муайян, онро алоҳида бо фармони docker compose exec -T n8n n8n export:workflow --id=WORKFLOW_ID --published --output=/home/node/.n8n/backups/published-workflow.json пас аз боварӣ ҳосил кардан аз мавҷуд будани ҷузвдони таъинотӣ ва ҳуқуқи навиштан содир кунед. CLI инчунин метавонад версияи таърихиро бо --version=VERSION_ID содир намояд. Ин нусхаҳоро дар баробари нусхаи пурра берун аз сервер нигоҳ доред; гумон накунед, ки JSON-и лоиҳа ҳолати нашршудаи фаъолро сабт мекунад.

# Execute from your Docker Compose project; the n8n service must exist
# Keep workflow and credential backups in DIFFERENT folders
docker compose exec -T n8n n8n export:workflow --backup --output=/home/node/.n8n/backups/workflows/
docker compose exec -T n8n n8n export:credentials --backup --output=/home/node/.n8n/backups/credentials/
# Copy the saved export directories OUT of the container to the host
mkdir -p ~/n8n-recovery
docker compose cp n8n:/home/node/.n8n/backups ~/n8n-recovery/cli

Ҷузвдони нусхабардоришудаи ~/n8n-recovery/cli ҳанӯз дар VPS мемонад, то вақте ки онро ба ҷойи мустақили муҳофизатшуда интиқол надиҳед. Содироти маълумоти дастрасӣ ба таври пешфарз рамзгузоришуда аст ва ҳангоми воридсозӣ калиди мувофиқро талаб мекунад. Аз истифодаи --decrypted ғайр аз ҳолатҳои интиқоли таҳти назорати қатъӣ худдорӣ намоед: ин интихоб маълумоти махфиро ҳамчун матни одӣ менависад. Содироте, ки мантиқи ҳассоси ҷараён ё маълумоти дастрасиро дорад, ҳеҷ гоҳ ба репозитории оммавии GitHub нафиристед. Баъзе қолабҳои нусхабардории маълумоти дастрасӣ ба GitHub дидаву дониста сирҳоро бе рамзгузорӣ содир мекунанд; репозитории хусусӣ танҳо маҳдудияти дастрасӣ аст, на рамзгузорӣ. Танзимоти воқеии содирот ва ҳуқуқҳои нигоҳдории ҳар қолабро санҷед, пеш аз интиқол ба ҷойи беруна сирҳоро рамзгузорӣ намоед ва маълумоти дастрасии бо фиристодани нохостаи матни одӣ фошшударо иваз кунед.

Мисоли воридсозии гурӯҳӣ: дар муҳити тоза танзими соҳиби ҳисобро анҷом диҳед, калиди аслии рамзгузориро таъин кунед ва дастрас будани файлҳои нусхаи эҳтиётиро дар VPS-и барқарорсозӣ таъмин намоед. Фармонҳои зерин ҷузвдони таъинотӣ месозанд ва зерҷузвдонҳои workflows/ ва credentials/ ро аз хост ба контейнери n8n нусхабардорӣ мекунанд; агар сохтори volume-ҳои Docker-и шумо дигар бошад, роҳҳоро мутобиқ кунед:

# Run only on the intended CLEAN recovery instance
docker compose exec -T n8n mkdir -p /home/node/.n8n/backups
docker compose cp ~/n8n-recovery/cli/. n8n:/home/node/.n8n/backups/

Соҳиби файлҳо ва ҳуқуқи дастрасии корбари контейнери n8n-ро санҷед. Бидуни роҳи санҷидашудаи бозгашт бар рӯйи муҳити пуршудаи истеҳсолӣ воридсозӣ накунед: ID-ҳои ҷараёнҳо ва маълумоти дастрасӣ метавонанд сабтҳои мавҷударо иваз кунанд. Сипас иҷро кунед:

# After fresh-instance owner setup AND providing the correct key
# Copy saved cli/ contents back under the target n8n service's .n8n/backups/
docker compose exec -T n8n n8n import:workflow --separate --input=/home/node/.n8n/backups/workflows/
docker compose exec -T n8n n8n import:credentials --separate --input=/home/node/.n8n/backups/credentials/

ID-ҳои воридшуда метавонанд ҷараёнҳо ё маълумоти дастрасии мавҷударо иваз кунанд; барои санҷиши пешакӣ муҳити ҷудогона истифода баред ва баъд маълумоти дастрасӣ ва ҳолати фаъолкунӣ/нашрро санҷед. Дар n8n 2.x барқарор кардани лоиҳаи JSON худ ба худ исбот намекунад, ки ҷараён нашр шудааст ва триггерҳои нақшавиро иҷро карда метавонад. Бехатарии воридсозӣ: дар n8n бе режими multi-main триггерҳои cron-и қаблан фаъол метавонанд баъди воридсозӣ тавассути CLI то бозоғозии муҳит кор кунанд. Пеш аз фаъол кардани вазифаҳои барқароршуда триггерҳои истеҳсолиро боздоред ё ҷудо кунед ва n8n-ро бозоғозӣ намоед; набудани иҷроиши такрориро санҷед. Содироти CLI дар бар намегирад: корбарони аслӣ, логҳои иҷроиш, тағйирёбандаҳои муҳит ё калиди рамзгузорӣ. --backup имконоти --all --pretty --separate ро фаъол мекунад, на «нусхаи пурраи муҳит»-ро. Манбаъҳо: дастури расмии ҷории n8n оид ба нусхабардорӣ ва барқарорсозӣ ва маълумотномаи фармонҳои CLI.

Барқарорсозии гурӯҳӣ аз қолабҳои GitHub ё Google Drive: ин роҳи алтернативӣ танҳо барои JSON-и ҷараёнҳои корӣ аст, на барои пойгоҳи додаҳои нусха, корбарон, арзишҳои махфии маълумоти дастрасии рамзгузоришуда ё калиди рамзгузорӣ. Пеш аз истифодаи қолаби ба API такякунанда, ҳуқуқҳои API ва захираи n8n, версияи нусха ва муҳити ҳадафи интихобшуда, тарзи навсозии ID-ҳои мувофиқ ва барқарорсозии ҷараёнҳои ҳазфшуда ва рафтори нашрро санҷед. На ҳамаи қолабҳо ID-и дар муҳити ҳадаф мавҷуднабударо аз нав месозанд; ин ҳолатро алоҳида санҷед, пеш аз он ки ба барқарорсозии худкор такя кунед.

САВОЛҲОИ МАЪМУЛ

Нусхабардорӣ ва барқарорсозии n8n: саволҳои маъмул

Оё содироти ҷараёнҳои корӣ барои нусхабардории n8n кофӣ аст?

Не. Содироти ҷараёнҳо нусхаҳои мантиқии муфиданд, аммо барқарорсозии пурра метавонад маълумоти дастрасӣ, калиди мувофиқи рамзгузорӣ, ҳолати пойгоҳи додаҳо, файлҳои доимӣ ва захираи додаҳои бинариро низ талаб кунад.

Агар пойгоҳи додаҳо дошта бошам, оё калиди рамзгузории n8n ҳам лозим аст?

Бале, агар мехоҳед маълумоти дастрасии рамзгузоришудаи дар пойгоҳи додаҳо нигоҳдошташуда баъди барқарорсозӣ кор кунад. Калиди аслиро боэътимод ҳифз кунед.

Оё PostgreSQL-ро нусхабардорӣ кунам ё ҷараёнҳо ва маълумоти дастрасиро содир намоям?

Барои барқарорсозӣ пас аз садама пойгоҳи додаҳо ва калиди рамзгузориро ҳифз кунед. Содироти мантиқӣ ҳамчун қабати иловагӣ барои интиқол ва барқарорсозии интихобӣ арзишманд аст, на ҷойгузини ҳамаи қисмҳои муҳит.

Оё танҳо снапшоти VPS метавонад нусхаи эҳтиётии ман бошад?

Беҳтар аст онро яке аз қабатҳои барқарорсозӣ ҳисоб кунед. Нусхаи мустақили берун аз сервер нигоҳ доред, то нокомии провайдер, ҳисоб, сервер ё снапшот ҳамаи нуқтаҳои барқарорсозиро якбора аз байн набарад.

Чӣ тавр донам, ки нусхаи эҳтиётӣ кор мекунад?

Онро дар муҳити тозаи санҷишӣ барқарор кунед, кушода шудани маълумоти дастрасии рамзгузоришударо тасдиқ намоед ва ҷараёнҳои намунавиро иҷро кунед. Танҳо анҷоми муваффақи вазифаи нусхабардорӣ имкони барқарорсозиро исбот намекунад.

Оё нусхаҳои ҷараёнҳои корӣ дар GitHub ё Google Drive сирҳои маълумоти дастрасии захирашударо дар бар мегиранд?

Нусхаҳои JSON-и танҳо ҷараёнҳои корӣ арзишҳои махфии захираи маълумоти дастрасии n8n ё калиди рамзгузории нусхаро дар бар намегиранд. Бо вуҷуди ин, JSON-и содиршуда метавонад номҳо ва ID-ҳои маълумоти дастрасӣ ва сирҳои бевосита дар параметрҳои гиреҳҳо навишташуда, ба мисли сарлавҳаҳои санҷиши ҳувиятро ошкор кунад. Пеш аз боргузорӣ ё мубодила JSON-и содиршударо санҷед ва ҳифз намоед. Барои барқарорсозии пурра пойгоҳи додаҳо ва калиди аслиро нусхабардорӣ кунед ё аз содироти дастгиришавандаи рамзгузоришудаи CLI бо санҷиши барқарорсозӣ истифода баред. Қолаби танҳо ҷараёнҳои GitHub ё Google Drive нусхаи пурраи барқарорсозӣ пас аз садама нест.

ҲАДАФҲОИ БАРҚАРОРСОЗӢ

Пеш аз садама RPO ва RTO-ро муайян кунед

RPO ҳадди аксари талафоти таҳаммулпазири тағйироти охирин мебошад. Онро аз навтарин нуқтаи барқарорсозии қобили истифода, ки мустақилона нигоҳ дошта шудааст, ҳисоб кунед; кори нақшавии ҳар шаш соат RPO-и шашсоатаро исбот намекунад, агар содирот ё интиқол ноком шуда бошад. RTO ҳадди аксари қатъи кори таҳаммулпазир аст. Онро дар санҷиши барқарорсозии тоза, аз ҷумла гирифтани маълумоти махфӣ, барқарор кардани файлҳои беруна, дубора санҷидани маълумоти дастрасӣ ва нашри ҷараёнҳои барқароршуда чен кунед — на танҳо то оғози контейнер.

КАЛИДИ БАРҚАРОРСОЗӢ

Пеш аз аз нав сохтани муҳит калиди аслии рамзгузориро пайдо кунед

Агар дар муҳити истеҳсолӣ N8N_ENCRYPTION_KEY таъин шуда бошад, айнан ҳамон арзиши махфии муҳитро нигоҳ доред. Дар акси ҳол калиди тавлидшударо дар файли аслии доимии .n8n/config ҳифз кунед. Пеш аз ворид кардани маълумоти дастрасии рамзгузоришуда санҷед, ки нусхаи барқароршуда воқеан аз кадом манбаи калид истифода мебарад; калиди навтаҳияшуда маълумоти дастрасии пойгоҳи додаҳои кӯҳнаро кушода наметавонад.

Провайдерҳоро муқоиса мекунед?

Барои интихоби провайдер, насби яккликӣ, ҳудуди дастгирӣ, нусхаҳои эҳтиётӣ, интиқол, минтақа ва миқёспазирӣ аз муқоисаи беҳтарин VPS барои n8n истифода баред. Барои интихоби захираҳои сервер ба дастури асосии VPS барои n8n баргардед.
