НАСБ БО DOCKER

Насби n8n дар VPS

n8n-ро дар VPS бо истифода аз Docker Compose ва PostgreSQL насб кунед. Барои муҳити истеҳсолӣ инчунин нигоҳдории доимии додаҳои барнома ва пойгоҳи додаҳо, калиди устувори N8N_ENCRYPTION_KEY, номи хости оммавӣ, HTTPS ва танзими дурусти вебҳукҳо лозиманд. Пеш аз фаъол кардани ҷараёнҳои кории истеҳсолӣ ҳамаи ин қисмҳоро санҷед.

ШАРТҲОИ ПЕШАКӢ

Пеш аз оғози n8n сервери VPS-ро омода кунед

VPS бо Linux

Аз сервери Linux истифода баред, ки навсозиҳои он дастгирӣ мешаванд ва барои n8n, PostgreSQL, Docker ва проксии баръакс захираҳои кофӣ дорад.

DNS

Пеш аз гирифтани сертификатҳои TLS ва нашри URL-ҳои вебҳук домен ё зердоменро ба VPS равона кунед.

Docker Compose

Docker Engine ва плагини Compose-ро бо бастаҳои барои системаи амалиётӣ дастгиришаванда насб кунед.

Файрвол

Танҳо портҳои зарурии идоракунӣ ва вебро боз кунед. PostgreSQL ва хидматҳои дохилии барномаро дар шабакаи хусусӣ нигоҳ доред.

n8n-ро дар VPS-е насб мекунед, ки аллакай сайтҳо дорад? Шумо метавонед n8n-ро ба сервери таҳти идораи худ илова кунед, агар CPU, RAM ва фазои диск кофӣ бошанд. Аммо агар Nginx, Apache, Caddy ё проксии баръакси дигар аллакай портҳои 80/443-ро ишғол карда бошад, набояд контейнери намунавии Caddy-и поёнро бе тағйир оғоз кунед: портҳо ба ҳам бармехӯранд. Ба ҷойи ин зердомени нави n8n-ро тавассути проксии баръакси мавҷуда ва шабакаи хусусии мувофиқ равона кунед ё барои ҳамин намунаи Compose аз VPS-и тоза истифода баред. Сайтҳои дигар ва танзимоти TLS-и онҳоро нигоҳ доред; намуна озод будани портҳои 80/443-ро пешбинӣ мекунад.

НАСБИ НАМУНАВӢ БО МУТОБИҚСОЗӢ

n8n-ро дар VPS-и худ бо Docker Compose насб кунед

Бо ин намуна n8n-ро дар VPS-и Linux бо идоракунии мустақил ҷойгир кунед. n8n-ро худатон насб ва нигоҳдорӣ мекунед; интихоби сервер тавассути шарики мо маънои онро надорад, ки n8n пешакӣ насб шудааст. Намуна n8n, PostgreSQL, иҷрокунандаи вазифаҳои берунӣ ва HTTPS-и Caddy-ро дар шабакаи хусусии Compose муттаҳид мекунад. Ин қолаби танзимот аст, на иддао дар бораи ҷойгиркунии амалан санҷидашуда.

Ба насби нави ҳарчи зудтар ниёз доред? n8n инчунин насби расмии яксатрӣ бо Docker дорад. Метавонед скрипти онро бо фармони curl -fsSL https://get.n8n.io -o get-n8n.sh боргирӣ ва пеш аз иҷрои sh get-n8n.sh дида бароед. Он як нусхаи ибтидоиро бо SQLite дар URL-и маҳаллӣ ва хидматҳои муҳити ҷудогонаи n8n Assistant оғоз мекунад; ин ҳамон роҳ нест, ки дар ин ҷо бо HTTPS-и оммавӣ ва PostgreSQL барои VPS тавсиф шудааст. Маҷмӯи пурраи муҳити ҷудогонаи расмӣ нисбат ба насби сабуки n8n RAM ва CPU-и бештар талаб мекунад (дар дастури Compose ҳадди ақал 4 GB RAM / 2 vCPUs нишон дода шудааст). Барои VPS-и истеҳсолии ба интернет пайваст танзими дастии поёнро идома диҳед.

1. Docker, DNS ва дастрасиро омода кунед

Тавассути SSH бо ҳуқуқи sudo пайваст шавед ва сабти DNS-и навъи A-ро барои n8n.example.com ба суроғаи IPv4-и VPS-и худ равона кунед. Дар VPS-и тоза бо Ubuntu 22.04, 24.04 ё 26.04 фармонҳои зерин Docker Engine ва плагини муосири docker compose ро аз репозитории расмии имзошудаи apt Docker насб мекунанд:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Ин усули насб аз репозитории расмӣ барои муҳити истеҳсолӣ дар дастури расмии Docker барои Ubuntu оварда шудааст. Дар VPS-е, ки аллакай контейнерҳо ё сайтҳои дигар дорад, Docker-ро бе санҷиш аз нав насб ё ҳазф накунед; аввал насби мавҷуда ва эҳтимоли ихтилофи бастаҳоро санҷед. Барои Debian ё дистрибутиви дигар ба ҷойи фармонҳои Ubuntu аз дастурҳои расмии махсуси ҳамон система истифода баред.

Акнун худи Docker, плагини Compose, DNS ва ҷузвдони кориро санҷед:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Агар getent hosts суроға наёбад ё суроғаи нодуруст баргардонад, пеш аз оғози Caddy DNS-ро ислоҳ кунед; дар тамоми дастур n8n.example.com ро бо номи воқеии хости худ иваз намоед. Docker одатан ҳуқуқи root талаб мекунад: агар корбари SSH-и шумо фармонҳои баъдии docker compose ро бевосита иҷро карда натавонад, пеш аз онҳо sudo гузоред. Илова кардани корбар ба гурӯҳи docker ба ӯ дастрасии баробар ба root медиҳад; ин корро дар сервери муштарак беандеша анҷом надиҳед.

Пеш аз фаъол кардани файрвол дастрасӣ ба порти воқеии идоракунии SSH-ро нигоҳ доред. Барои гирифтани сертификат ва кори муҳаррир HTTP (80) ва HTTPS (443)-и воридшавандаро иҷозат диҳед. Портҳои нашркардаи контейнерҳои Docker метавонанд баъзе қоидаҳои UFW-ро давр зананд, бинобар ин дастури файрволи Docker-ро санҷед ва танҳо портҳои пешбинишудаи Caddy-ро нашр кунед. Ин намунаи Compose қасдан портҳои зеринро ба интернети оммавӣ намекушояд: PostgreSQL (5432), n8n (5678) ва брокери иҷрокунандаи вазифаҳо (5679).

2. Арзишҳои муҳитро эҷод ва калидро ҳифз кунед

Аз ҷузвдони лоиҳа се арзиши шонздаҳии тасодуфии гуногунро бо фармони зерин созед:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Файле бо номи .env бо истифода аз қолаби поён эҷод кунед, ҳар REPLACE_WITH_RANDOM_HEX-ро бо арзиши тасодуфии алоҳидаи тавлидшуда иваз намоед ва номи хост ва минтақаи вақтро тағйир диҳед. Барчаспи 2.42.5 версияи устуворест, ки 8 октябри 2026 нишон дода шуда буд ва дар ин ҷо танҳо ҳамчун намунаи санаи муайян оварда мешавад, на кафолати он ки ҷойгиркунӣ амалан санҷида шудааст ё дар оянда бехатар мемонад. Пеш аз насб нашрҳои ҷории расмии n8n-ро санҷед ва тасвирҳои n8n ва иҷрокунандаи вазифаҳоро дар як версияи тасдиқшуда нигоҳ доред.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Ҳеҷ гоҳ файли .env-ро ба репозитории оммавӣ нафиристед. Калиди рамзгузорӣ ва дастури барқарорсозиро берун аз VPS боэътимод нигоҳ доред. Пас аз аз нав сохтани контейнер ё интиқоли он калид бояд бетағйир монад.

3. Барои насби тоза файли compose.yaml-ро нависед

Дар ҳамон ҷузвдон файли compose.yaml эҷод кунед. Намуна аз қоидаҳои расмии тағйирёбандаҳои муҳити n8n ва роҳи нигоҳдории PostgreSQL 18 бо номи PGDATA, ки дар лоиҳаи хостинги n8n ҳуҷҷатгузорӣ шудааст, истифода мебарад:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Ин чор хидмат вазифаҳои гуногун доранд: PostgreSQL ҳолати пойгоҳи додаҳоро нигоҳ медорад, n8n ҷараёнҳои кориро иҷро мекунад, n8n-runner вазифаҳои иҷрокунандаро бо версияи мувофиқ ва токени муштараки тасдиқи ҳувият иҷро мекунад, Caddy бошад HTTPS-и оммавиро таъмин мекунад. Иҷрокунандаи берунии вазифаҳо режими навбати Redis нест. Танҳо Caddy портҳоро дар хост нашр мекунад. Дар ин намунаи сабук барои соддагии насб аз як нақши пойгоҳи додаҳо истифода шудааст; барои ҷудо кардани ҳуқуқҳои PostgreSQL ба намунаи расмии ҷойгиркунии PostgreSQL дар n8n муроҷиат кунед.

4. Файли Caddyfile барои HTTPS созед

Файли Caddyfile-ро (бо ҳарфи калони C ва бе пасванд) дар паҳлуи compose.yaml эҷод кунед. Дар ҳамаи ҷойҳо номи хости намунавиро бо номи DNS-и худ иваз намоед:

n8n.example.com {
    reverse_proxy n8n:5678
}

Вақте домен дуруст ба сервер ишора мекунад ва трафики беруна ба портҳои 80/443 мерасад, Caddy сертификатҳои оммавии TLS-ро дархост ва тамдид мекунад. DNS-ро ба localhost равона накунед. Агар Caddy-ро бо проксии баръакси дигар иваз кунед, сарлавҳаҳои аслии хост, протокол ва суроғаи муштариро гузаронед ва N8N_PROXY_HOPS-ро мувофиқи шумораи воқеии гузаришҳо аз проксиҳои боэътимод танзим намоед.

5. Контейнерҳоро оғоз кунед ва аз берун бисанҷед

Баъди нигоҳ доштани .env, compose.yaml ва Caddyfile фармонҳои зеринро аз ҷузвдони лоиҳа иҷро кунед:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Фармони охирин нуқтаи санҷиши саломатиро тавассути HTTPS-и оммавӣ месанҷад. Агар гирифтани сертификат ҳанӯз анҷом наёфта бошад, пеш аз он ки n8n-ро вайрон ҳисобед, логҳои Caddy ва DNS/портҳоро санҷед. Суроғаи https://n8n.example.com-ро кушоед, дарҳол ҳисоби соҳиби аввалро созед ва муҳофизати мувофиқи воридшавиро фаъол намоед. Тасдиқ кунед, ки муҳит воқеан ҷараёни кориро иҷро мекунад, на танҳо муҳаррирро мекушояд:

  1. Дар муҳаррир ҷараёни корие бо триггери Webhook эҷод кунед. Параметри HTTP Method-ро ба GET танзим кунед. Барои параметри Path vps-check-ро интихоб кунед ва параметри Respond-ро ба Immediately танзим намоед. Ҷараёни кориро захира кунед.
  2. Тугмаи Listen for Test Event-ро пахш карда, суроғаи пурраи Test URL-ро аз n8n нусхабардорӣ кунед ва аз дастгоҳи дигар фармони curl -i 'PASTE_TEST_URL_HERE'-ро бо URL-и нусхабардоришуда иҷро кунед. Ҷавоби муваффақи HTTP ва пайдо шудани рӯйдоди воридшударо дар муҳаррири n8n интизор шавед. URL-ҳои санҷишӣ танҳо дар вақти интизори рӯйдод будани n8n кор мекунанд.
  3. Publish-ро барои нашри ҷараёни корӣ пахш кунед; сипас гиреҳро ба Production URL гузаронед, URL-ро нусхабардорӣ кунед ва фармони curl -i 'PASTE_PRODUCTION_URL_HERE'-ро дубора иҷро намоед. Иҷроишро дар ҷадвали Executions ҷараёни корӣ санҷед. Дархостҳои вебҳуки истеҳсолӣ танҳо ҳангоми нашр шудани ҷараён кор мекунанд ва додаҳояшон дар намоиши санҷишии муҳаррир нишон дода намешаванд.

Ин танҳо санҷиши одӣ ва бидуни тасдиқи ҳувият аст: ба он ҳеҷ гоҳ маълумоти махфӣ нафиристед. Пас аз санҷиш онро аз нашр бароред ё ҳазф кунед, ё пеш аз истифода барои додаҳои воқеӣ тасдиқи ҳувият ва маҳдудиятҳои IP-и Webhook-ро танзим намоед. Ба ҳуҷҷатҳои расмии Webhook барои URL-ҳои санҷишӣ ва истеҳсолӣ муроҷиат кунед.

6. Пеш аз тағйири версияҳои собитшуда нусхаи эҳтиётӣ гиред

Нусхаи барқароршавандаи PostgreSQL-ро ва volume-и доимии додаҳои n8n, .env, калиди рамзгузорӣ ва файлҳои зарурии берунаро дар захираи берун аз ин сервер нигоҳ доред. Пеш аз навсозии муҳити истеҳсолӣ барқарорсозиро бо дастури нусхабардорӣ ва барқарорсозӣ санҷед. Намунаи фармонҳо:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Версияи собитшудаи N8N_VERSION ро танҳо баъди хондани ёддоштҳои нашр тағйир диҳед; версияи образҳои n8n ва иҷрокунандаи вазифаҳо бояд якҷоя нав карда шавад. Ҳангоми нигоҳдории муқаррарӣ фармони docker compose down -v ро иҷро накунед, зеро он volume-ҳои номдори додаҳоро ҳазф мекунад. Тағйири версияи асосии PostgreSQL нақшаи навсозии пойгоҳи додаҳо ё содирот/барқарорсозиро талаб мекунад; иваз кардани образи Postgres 18 ба версияи асосии дигар интиқоли худкор нест.

Манбаъҳои аслӣ: дастури n8n оид ба Docker Compose, танзими проксии баръакс ва вебҳукҳои n8n ва ёддоштҳои расмии ҷойгиркунии PostgreSQL. Ҳеҷ натиҷаи санҷиши сарбории инфрасохтор ё имкони пешакӣ насбшудаи хоси провайдер иддао намешавад.

Маълумоти махфӣ ва URL-ҳои оммавиро бодиққат танзим кунед

Калиди рамзгузорӣ

Пеш аз захира кардани маълумоти дастрасии истеҳсолӣ калиди қавии рамзгузории n8n-ро таъин ва ҳифз кунед. Барои барқарорсозӣ айнан ҳамон калид лозим мешавад.

Маълумоти дастрасии PostgreSQL

Барои пойгоҳи додаҳо маълумоти дастрасии махсус истифода баред ва рамзҳоро берун аз коди сарчашмаи оммавӣ нигоҳ доред.

Номи хости оммавӣ

Ба ҷойи суроғаи дохилии контейнер номи хости воқеии беруна ва суроғаи HTTPS-ро танзим кунед.

URL-и вебҳук

Арзиши N8N_WEBHOOK_URL-ро ба URL-и асосии HTTPS, ки аз интернет дастрас аст, танзим кунед ва параметри N8N_PROXY_HOPS=1 ро ҳангоми мавҷуд будани як проксии баръакси боэътимод таъин намоед. WEBHOOK_URL дар n8n 2.35.0 ва версияҳои баъдӣ номи кӯҳнашудаи алтернативӣ аст; онро аз дастурҳои кӯҳна нусхабардорӣ накунед.

Нуқтаи санҷиши саломатии n8n-ро тафтиш кунед

Версияҳои барномаро собит кунед

Навсозии образи шинокунандаро бе баррасӣ стратегияи нигоҳдорӣ ҳисоб накунед. Версияи n8n-и истифодашавандаро сабт кунед, ёддоштҳои нашрро хонед ва пеш аз тағйири версия нусхаи эҳтиётӣ гиред.

Версияҳои асосии PostgreSQL-ро дар ҳамон ҷояшон иваз накунед

Танҳо тағйир додани барчаспи версияи асосии образи Postgres метавонад ҷузвдони мавҷудаи додаҳоро номувофиқ созад. Ба ҷойи гумон кардани он ки аз нав сохтани контейнер интиқоли версияи асосиро анҷом медиҳад, аввал нусха гиред ва тартиби навсозии пойгоҳи додаҳоро иҷро намоед.

САВОЛҲОИ МАЪМУЛ

Насби n8n бо Docker: саволҳои маъмул

Оё ҳангоми истифодаи Docker ба n8n PostgreSQL лозим аст?

Docker истифодаи PostgreSQL-ро ҳатмӣ намекунад ва насбҳои хурд метавонанд SQLite-ро истифода баранд. Барои VPS-и ба муҳити истеҳсолӣ нигаронидашуда PostgreSQL асоси устувортари пойгоҳи додаҳоро таъмин мекунад ва миқёспазирии минбаъдаро бо режими навбат дастгирӣ менамояд.

Чаро ҳангоми нигоҳдории додаҳо дар PostgreSQL барои n8n volume-и доимӣ ҳам лозим аст?

Ҷузвдони доимии n8n метавонад ҳолат ва танзимоти муҳими барномаро дар бар гирад. Онро мувофиқи сохтори ҷойгиркунӣ ҳифз кунед, на ин ки пойгоҳи додаҳоро ягона манбаи барқарорсозӣ ҳисобед.

Чаро вебҳуки ман localhost-ро нишон медиҳад?

Суроғаи дохилии контейнер аз суроғаи оммавӣ фарқ дорад. Номи хости беруна, протокол ва URL-и вебҳукро танзим кунед ва мутмаин шавед, ки проксии баръакс сарлавҳаҳои заруриро мегузаронад.

Оё порти 5678 бояд ба интернет кушода бошад?

Барои ҷойгиркунии муқаррарии истеҳсолӣ паси проксии баръакс HTTPS-ро дар прокси кушода, порти барномаи n8n-ро дохилӣ нигоҳ доред, магар он ки сабаби мушаххаси техникӣ дигарро талаб кунад.

Оё Redis лозим аст?

Барои насби маъмулии Docker бо як нусха — не. Redis вақте зарур мешавад, ки шумо қасдан ба режими навбат ва коргарҳо мегузаред.

Оё иҷрокунандагони берунии вазифаҳои n8n бо коргарҳои режими навбат як чизанд?

Не. Иҷрокунандагони берунии вазифаҳо коди дастгиришавандаро ҷудо аз раванди асосии n8n иҷро мекунанд ва токени муштараки тасдиқи ҳувият доранд. Режими навбати Redis иҷроишҳои ҷараёнҳои кориро тақсим мекунад ва талаботи инфрасохтории хоси худро дорад. Ин намуна иҷрокунандаи берунии вазифаҳоро нишон медиҳад, на режими навбати Redis-ро. Версияи образи иҷрокунандаи вазифаҳоро бо версияи n8n мувофиқ нигоҳ доред.
