МИҚЁСПАЗИРӢ

Режими навбати n8n

Режими навбат иҷрои ҷараёнҳои кориро аз раванди асосии n8n ҷудо мекунад. Нусхаи асосӣ триггерҳоро қабул карда, иҷроишҳо месозад; Redis навбатро идора мекунад, коргарҳо вазифаҳоро иҷро мекунанд ва PostgreSQL додаҳои муштараки доимии ҷараёнҳо ва иҷроишҳоро нигоҳ медорад.

ҚАРОРИ ЗУД

Оё воқеан ба режими навбат ниёз доред?

Дар режими муқаррарӣ бимонед, агар

як нусха иҷроишҳои вақти авҷро бе душворӣ анҷом диҳад ва CPU, RAM ва таъхири иҷроишҳо устувор бошанд. Режими навбат ҷузъҳои иловагии ҳоло нолозимро меорад.

Режими навбатро баррасӣ кунед, агар

иҷроишҳои зиёди ҳамзамони доимӣ барои захираҳо рақобат эҷод кунанд, таъхири иҷроишҳо ҳангоми сарборӣ афзояд ё барои зиёд кардани иқтидори иҷроиш коргарҳои бештар лозим шаванд.

Аввал захираҳои серверро зиёд кунед, агар

маҳдудият танҳо аз кам будани CPU ё RAM бошад ва як нусхаи калонтар ҳамоно сарбориро ба осонӣ иҷро карда тавонад.

Пеш аз тағйири меъморӣ чен кунед

Ба авҷи иҷроишҳои ҳамзамон, CPU, RAM, давомнокии иҷроишҳо, шумораи вазифаҳои навбат ва сарбории пойгоҳи додаҳо такя кунед, то гузариш асоснок бошад.

МЕЪМОРӢ

Режими навбати n8n чӣ гуна кор мекунад

1 · Раванди асосӣТаймерҳо, вебҳукҳо ва дархостҳои ҷараёнҳои кориро қабул карда, ба ҷойи иҷрои худи ҷараён иҷроиши нав эҷод мекунад.
2 · RedisҲамчун брокери паёмҳо кор мекунад. Паёмҳои иҷроишҳои интизорро нигоҳ медорад, то коргари навбатии озод вазифаро бигирад.
3 · КоргарID-и иҷроишро қабул мекунад, додаҳои ҷараёнро аз пойгоҳи муштарак мегирад, онро иҷро карда, натиҷаро дубора менависад.
4 · PostgreSQLДодаҳои муштараки доимии ҷараёнҳо ва иҷроишҳоро таъмин мекунад. Режими навбати тақсимшуда бо SQLite дастгирӣ намешавад.

ТАЛАБОТИ АСОСӢ

Ҳар ҷойгиркунии режими навбат ба чӣ ниёз дорад

Redis

Раванди асосӣ ва ҳамаи коргарҳо бояд ба хидмати Redis, ки навбатро идора мекунад, дастрасии боэътимод дошта бошанд.

PostgreSQL

Раванди асосӣ ва коргарҳо бояд аз як пойгоҳи додаҳо истифода баранд. Режими навбат меъмории тақсимшуда аст ва набояд дар асоси SQLite сохта шавад.

Танзимоти якхелаи n8n

Раванди асосӣ ва коргарҳо бояд дар режими навбат кор кунанд ва танзимоти лозим барои дастрасӣ ба Redis, PostgreSQL ва маълумоти дастрасии рамзгузоришударо муштарак истифода баранд.

Иқтидори коргарҳо

Барои ҷараёнҳои иҷрошаванда коргарҳо ба CPU ва RAM-и кофӣ ниёз доранд. Илова кардани равандҳо хароҷоти захираҳои ҳар иҷроишро нест намекунад.

Режими навбатро дар муҳити мавҷудаи худидорашаванда фаъол кунед. Аввал тасдиқ кунед, ки хидмати асосии n8n ва ҳар коргар метавонанд тавассути шабакаи хусусӣ ба як PostgreSQL ва Redis пайваст шаванд. Параметри EXECUTIONS_MODE=queue-ро дар раванди асосӣ ва коргарҳо гузоред ва QUEUE_BULL_REDIS_HOST=redis ва QUEUE_BULL_REDIS_PORT=6379 ро таъмин кунед, агар redis номи воқеии хидмати Compose-и шумо бошад. Аз параметри DB_TYPE=postgresdb, DB_POSTGRESDB_HOST=postgres ва қиматҳои мувофиқи DB_POSTGRESDB_DATABASE, DB_POSTGRESDB_USER ва DB_POSTGRESDB_PASSWORD дар ҳар раванд истифода баред; номҳои намунавии хидматҳоро бо номҳои худ иваз кунед. Ба ҳама айнан ҳамон калиди мавҷудаи N8N_ENCRYPTION_KEY ро диҳед. Танҳо барои пайваст кардани контейнерҳо дар як шабакаи Compose портҳои Redis ё PostgreSQL-ро дар хост нашр накунед.

Иҷрокунандаро оғоз кунед, на муҳаррири дуюмро. Хидмати коргари n8n-ро бо ҳамон версияи собити образи n8n ва танзимоти муштараки раванди асосӣ илова кунед, вале онро бо фармони worker ба кор дароред. Агар ин хидматро n8n-worker номида бошед, бо фармони docker compose up -d n8n-worker оғоз намоед. Пас аз тасдиқи иҷроиши воқеӣ дар як коргар метавонед бо docker compose up -d --scale n8n-worker=2 коргари дуюмро оғоз кунед. Ин қадамҳо ба маҷмӯи мавҷудаи дуруст танзимшудаи Compose илова мешаванд, на файли мустақили насб; ҳаҷмҳои доимӣ, проксии HTTPS, сирҳо ва нусхаҳои эҳтиётии мавҷударо нигоҳ доред.

Порчаи Compose барои режими навбат дар муҳити мавҷуда. Намунаи поёнро ба файли ҷории compose.yaml ҳамроҳ кунед; он нест файли комили ҷойгиркунии мустақил. Пешбинӣ мешавад, ки шумо аллакай хидматҳои доимӣ ва хусусии postgres ва n8n, инчунин версияи собитшудаи N8N_VERSION дар муҳит, гузарвожаи муҳофизатшудаи POSTGRES_PASSWORD ва калиди аслии N8N_ENCRYPTION_KEY доред. Номҳо, ҳаҷмҳо, пойгоҳи додаҳо ва версияи n8n-ро ба лоиҳаи мавҷуда мувофиқ кунед. Танзимоти Redis барои режими навбат ва EXECUTIONS_MODE=queue ро, тавре ки боло шарҳ дода шуд, ба хидмати асосии мавҷуда низ илова кунед.

# Merge with the existing services; do not replace your full Compose file.
services:
  redis:
    image: redis:7-alpine
    command: ["redis-server", "--appendonly", "yes"]
    restart: unless-stopped
    volumes:
      - redis_data:/data
  n8n-worker:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    command: worker --concurrency=5
    restart: unless-stopped
    environment:
      EXECUTIONS_MODE: queue
      QUEUE_BULL_REDIS_HOST: redis
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
    depends_on:
      - redis
      - postgres
volumes:
  redis_data:

Дар ин порча ҳеҷ порти хост барои Redis ё коргар нашр намешавад. Нигоҳдории append-only-и Redis қабати иловагии барқарорсозӣ аст, на ҷойгузини нусхаҳои эҳтиётии берун аз сервер. Танзимоти мавҷудаи HTTPS ва тасдиқи ҳувиятро бетағйир нигоҳ доред. Барои гиреҳҳои Code, ки иҷрокунандагони вазифаҳои берунаро талаб мекунанд, равандҳои иҷрокунандаро дар муҳити коргарҳо алоҳида танзим кунед; худи режими навбат онҳоро иваз намекунад.

Нусхаи мавҷудаи SQLite-ро интиқол медиҳед? Фақат арзиши DB_TYPE ро иваз карда, барномаро бо пойгоҳи холии PostgreSQL оғоз накунед: ин амал ҷараёнҳо ва маълумоти дастрасии кӯҳнаро интиқол намедиҳад. Пеш аз гузариш аз пойгоҳи додаҳои ибтидоӣ, ҷузвдони доимии .n8n ва калиди аслии рамзгузорӣ нусха гиред; аз усули дастгиришавандаи содирот/воридот ё интиқоли n8n истифода баред ва баъд ҷараёнҳо ва маълумоти дастрасии рамзгузоришударо дар муҳити алоҳида санҷед. Файлҳои аслиро барои бозгашт нигоҳ доред ва барои омодагӣ ба барқарорсозӣ ба дастури нусхабардорӣ ва барқарорсозии дар поён пайвастшуда муроҷиат намоед. Ҳеҷ гоҳ файли database.sqlite ро танҳо барои осон кардани кор ҳазф накунед.

ИҶРОИШҲОИ ҲАМЗАМОНИ КОРГАРҲО

Иқтидори коргарҳо ҳам аз шумора ва ҳам аз вазифаҳои ҳамзамони ҳар коргар зиёд мешавад

Ҳар коргар метавонад чанд вазифаро ҳамзамон иҷро кунад. Меъёри пешфарзи ҷории иҷроишҳои ҳамзамони коргар дар n8n баробар ба 10 аст ва ҳуҷҷатҳо арзиши 5 ё бештарро тавсия медиҳанд. Иҷроишҳои хеле ками ҳамзамон бо шумораи зиёди коргарҳо метавонанд пайвастҳои нолозими пойгоҳи додаҳоро эҷод карда, ҳавзи пайвастҳоро пур кунанд.

Иҷроишҳои ҳамзамонро зиёд кунед, агар

коргар CPU ва RAM-и холӣ дошта бошад ва ҷараёнҳо бештар ҷавоби хидматҳои берунаро интизор шаванд, на ин ки CPU ё хотираро пурра банд кунанд.

Коргарҳо илова кунед, агар

як раванди коргар ба маҳдудият расад ва пойгоҳи додаҳо, Redis ва инфрасохтор барои иҷроишҳои бештари ҳамзамон захира дошта бошанд.

Иҷроишҳои ҳамзамонро кам кунед, агар

ҷараёнҳои алоҳида CPU ё хотираи зиёд истифода баранд ва вазифаҳои параллелӣ боиси рақобат барои захираҳо, камбуди хотира (OOM) ё ноустувории вақти иҷроиш шаванд.

PostgreSQL-ро назорат кунед

Коргарҳо ва иҷроишҳои ҳамзамони бештар фаъолияти пойгоҳи додаҳоро зиёд мекунанд. Агар иқтидори иҷроишро бе зиёд кардани иқтидори пойгоҳи додаҳо афзоиш диҳед, маҳдудият танҳо ба ҷои дигар мегузарад.

Муайян кунед, ки кадом маҳдудияти иҷроишҳои ҳамзамон амал мекунад. Коргарро метавонед бо фармони n8n worker --concurrency=5 ё фармони мувофиқи коргар дар хидмати Compose оғоз кунед. Агар N8N_CONCURRENCY_PRODUCTION_LIMIT ба арзише ғайр аз -1 муайян шуда бошад, он параметр дар режими навбат бартарӣ дорад; дар акси ҳол n8n арзиши --concurrency ё меъёри пешфарзи 10-ро истифода мебарад. Шумораи коргарҳоро ба меъёри номии пешфарз зарб зада, онро иқтидори кафолатнок ҳисоб накунед: иқтидори воқеӣ аз давомнокии вазифаҳо, CPU, хотира, API-ҳои беруна ва пайвастҳои PostgreSQL вобаста аст.

ВЕБҲУКҲО

Режими навбат метавонад таъхири интиқоли иҷроишҳоро зиёд кунад

Раванди асосӣ ё раванди вебҳук дархости HTTP-ро қабул мекунад, вале ҷараёнро коргар иҷро мекунад. Гузаронидани вазифа тавассути Redis каме сарбории иловагӣ дорад. Барои вебҳукҳои ба таъхир ҳассос вақти пурраи ҷавобро чен кунед, на ин ки гумон кунед коргарҳои бештар ҳар дархостро худкор тез мекунанд.

ҚабулРаванди асосӣ ё вебҳук дархостро қабул мекунад.
НавбатИҷроиш ба Redis супорида мешавад.
ИҷроКоргари озод ҷараёнро иҷро мекунад.
ҶавобҲангоми зарурат натиҷа тавассути роҳи навбат ба қабулкунанда баргардонда мешавад.

Трафики вебҳукро ба раванди дуруст равона кунед. Агар равандҳои махсуси n8n webhook дар паси проксии баръакс ё тақсимкунандаи сарборӣ бошанд, роҳҳои истеҳсолии /webhook/* ва /webhook-waiting/* ро ба онҳо равона кунед; роҳҳои /webhook-test/*, муҳаррир ва дархостҳои API бояд ба раванди асосӣ раванд. Раванди асосиро ба гурӯҳи тақсими сарбории вебҳукҳои истеҳсолӣ ворид накунед, магар он ки қасдан он сарбории иловагиро қабул намоед. Ҷараёни дорои Respond to Webhook метавонад то анҷоми кори коргар ва бозгаштани ҷавоб муштариро мунтазир гузорад; бинобар ин режими навбат кафолати ҷавоби фаврии HTTP ё набудани timeout нест. Пеш аз интиқоли трафик дархости бозгашти воқеии беруна ва рафтори ҷавобро санҷед.

ДОДАҲОИ БИНАРӢ

Нигоҳдории муштараки додаҳоро фаромӯш накунед

Маҳдудияти системаи файлӣ

Режими навбат нигоҳдории додаҳои бинариро дар системаи файлӣ ҳамчун модели муштараки доимӣ барои коргарҳои тақсимшуда дастгирӣ намекунад.

Захираи берунаи додаҳои бинарӣ

Агар ҷараёнҳо бояд додаҳои бинариро дар байни коргарҳои тақсимшуда нигоҳ доранд, тарҳи захираеро истифода баред, ки ба ҳамаи нусхаҳои зарурӣ дастрас бошад, масалан захираи объектии берунии дастгиришаванда.

Ҷавобҳои калони вебҳук

Ҷавобҳои вебҳук аз коргарҳо ба раванди қабулкунанда бармегарданд. Ҷавобҳои калон метавонанд масрафи хотираи Redis-ро зиёд карда, танзими огоҳонаи нигоҳдории ҷавобро талаб кунанд.

Пеш аз тақсим кардани коргарҳо нақша созед

Сарборие, ки сахт ба файлҳои маҳаллӣ вобаста аст, пеш аз тақсим шудани коргарҳо байни серверҳо бояд барои нигоҳдории муштарак аз нав тарҳрезӣ шавад.

Ҳадди ҷавобҳои калони вебҳук. Ҳуҷҷатҳои ҷории n8n барои N8N_WEBHOOK_RESPONSE_RELAY_SIZE_MAX меъёри пешфарзи 64 MiB муайян мекунанд, ки ба ҷавоби коргар ҳангоми интиқол тавассути навбат дахл дорад. Redis метавонад якчанд нусхаро ҳангоми интиқол нигоҳ дорад; бинобар ин барои ҳар ҷавоби калони ҳамзамон тақрибан 1.5 баробари ҳаҷми ҷавобро дар хотираи Redis пешбинӣ кунед. Бе интиқол ба захираи дигар ҷавоби аз ҳад калон ноком мешавад — илова кардани коргарҳо онро худ аз худ тезтар намекунад.

Маҳдудиятҳои версия ва иҷозатнома. Аз версияи n8n 2.34.0, коргарҳо метавонанд тавассути N8N_WEBHOOK_RESPONSE_RELAY_OFFLOAD_ENABLED=true ҷавобҳои аз ҳад калони вебҳукро ба захираи муштараки бинарии хондашаванда интиқол диҳанд, аммо аввал ҳамаи равандҳои асосӣ ва коркардкунандагони вебҳукро ба версияи 2.34.0 ё навтар нав кунед. Параметри интихобшудаи N8N_DEFAULT_BINARY_DATA_MODE бояд воқеан додаҳоро захира кунад ва ба ҳамаи равандҳои иштироккунанда хондашаванда бошад. Захираи берунии бинарии S3 ва Azure барои хостинги мустақил иҷозатномаи Business ё Enterprise талаб мекунад; гумон накунед, ки Community Edition онҳоро фаъол карда метавонад. Режими бинарии database метавонад ҷавоби аз ҳад калонро бе захираи пулакии беруна интиқол диҳад, аммо раванди асосӣ тамоми ҷавоби захирашударо ба хотира мегирад ва худи пойгоҳи додаҳо низ маҳдудияти ҳаҷми файл дорад. Махсусан барои интиқоли ҷисми ҷавоб ба захираи дигар, n8n инчунин истифодаи filesystem муштаракро, вақте ҳамаи нусхаҳо ҳамон дискро васл мекунанд, тавсиф менамояд, вале ин роҳро возеҳ тавсия намедиҳад. Ин роҳи махсуси интиқоли ҷавобро бо дастгирии нигоҳдории доимии додаҳои бинарӣ дар системаи файлӣ барои режими навбати тақсимшуда омехта накунед. Пеш аз фаъол кардани чунин интиқол нашр, версия ва танзимоти захираи додаҳоро санҷед.

МОНИТОРИНГ

Муайян кунед, ки оё навбат воқеан кумак мекунад

Дарозии навбат

Агар навбат аз суръати коргарҳо тезтар афзоиш ёбад, иқтидори иҷроишҳо намерасад ё дар марҳилаи баъдӣ маҳдудият мавҷуд аст.

CPU ва RAM-и коргар

Серборӣ ва авҷи масрафи хотираи ҳар коргарро чен кунед. Агар коргарҳо бекор бошанду навбат калон шавад, маҳдудият дар ҷои дигар аст.

Таъхири иҷроиш

Вақти байни эҷод шудани иҷроиш ва оғози воқеии онро пайгирӣ кунед, на танҳо давомнокии худи ҷараёнро.

Санҷиши саломатӣ

Нуқтаҳои санҷиши саломатии коргар метавонанд нишон диҳанд, ки коргар фаъол аст ва пайвастҳои пойгоҳи додаҳо ва Redis омодаанд ё не.

Иҷроишро дар коргар тасдиқ кунед, на танҳо кори контейнерро. Дар муҳити дуруст танзимшудаи Compose фармони docker compose ps ва docker compose logs --tail=100 n8n-worker ро санҷед (агар номи хидмат дигар бошад, иваз кунед). Як ҷараёни безарари дар муҳити истеҳсолӣ нашршударо бо триггери нақшавӣ ё вебҳуки санҷишӣ иҷро кунед, сипас иҷроиши онро дар бахши Executions-и n8n бо кори воқеии коргар дар логҳои коргар муқоиса намоед. Танҳо кушода шудани муҳаррир, кори контейнери Redis ё дар навбат истодани иҷроиш ҳанӯз исбот намекунад, ки коргар вазифаро иҷро кардааст.

Вобастагиҳо ва омодагиро санҷед. Бо номҳои пешфарзи хидматҳои ин мисол фармони docker compose exec -T redis redis-cli ping дар сурати иҷозат додани тасдиқи ҳувияти Redis бояд ҷавоби PONG гирад, ва фармони docker compose exec -T postgres pg_isready -U n8n -d n8n омодагии PostgreSQL-ро месанҷад (номи хидматҳо ва маълумоти дастрасиро мутобиқ кунед). Агар ба нуқтаҳои хусусии санҷиши саломатии коргар ниёз дошта бошед, параметри QUEUE_HEALTH_CHECK_ACTIVE=true ро фаъол намоед, то роҳҳои /healthz ва /healthz/readiness дастрас шаванд; нуқтаи readiness пайвастшавӣ ба Redis ва пойгоҳи додаҳоро месанҷад. Танҳо барои мониторинг ин нуқтаҳои коргарро ба интернети оммавӣ накушоед.

Иҷроиши дастӣ санҷиши дигар аст. Ба таври пешфарз OFFLOAD_MANUAL_EXECUTIONS_TO_WORKERS=false муқаррар шудааст, бинобар ин иҷрои дастии ҷараён дар муҳаррир метавонад дар раванди асосӣ анҷом ёбад, ҳатто агар режими навбат дуруст танзим шуда бошад. Арзиши онро ба true танҳо дар сурате гузоред, ки қасдан иҷроишҳои дастиро ба коргарҳо фиристоданӣ бошед ва тағйиротро дар муҳити санҷишӣ тафтиш карда бошед. Коргарҳои режими навбат ҳамчунин аз иҷрокунандагони берунии вазифаҳои n8n фарқ доранд; барои иҷрои коди гиреҳҳои Code онҳо танзимоти алоҳида доранд.

РОҲИ МИҚЁСПАЗИРӢ

Ҳар дафъа як маҳдудиятро бартараф кунед

Марҳилаи 1Як нусхаи n8n бо PostgreSQL; авҷи CPU, RAM ва иҷроишҳои ҳамзамонро чен кунед.
Марҳилаи 2Вақте зиёд кардани захираҳои як сервер ҳанӯз мушкилоти ченшударо осон ҳал мекунад, иқтидори VPS-ро зиёд намоед.
Марҳилаи 3Вақте сарбории доимии иҷроишҳои ҳамзамон меъмории тақсимшударо асоснок мекунад, Redis ва коргарҳо илова кунед.
Марҳилаи 4Ҳангоми назорати PostgreSQL, Redis ва таъхири иҷроишҳо коргарҳои бештар илова кунед ё меъёри иҷроишҳои ҳамзамони ҳар коргарро танзим намоед.
Марҳилаи 5Ҷузъҳоро танҳо вақте байни серверҳо ҷудо кунед, ки иқтидор, дастрасӣ ё талаботи идоракунӣ мураккабии иловагиро асоснок кунад.
Вақте миқёспазирӣ иқтидори бештар талаб мекунад, VPS-и тавонотар интихоб кунед

МАҲДУДИЯТИ ДАСТРАСИИ БАЛАНД

Режими навбат иҷроишҳоро миқёспазир мекунад, аммо худ ба худ дастрасии баланди раванди асосиро таъмин намекунад

Калиди рамзгузориро муштарак нигоҳ доред

Ҳар коргар бояд айнан ҳамон N8N_ENCRYPTION_KEY калиди раванди асосиро истифода барад, то маълумоти дастрасии барои иҷроишҳо заруриро кушода тавонад.

Версияҳоро мувофиқ нигоҳ доред

Равандҳои асосӣ, вебҳук ва коргар бояд як версияи n8n-ро иҷро кунанд. Версияҳои гуногун ҳангоми навсозии марҳилавӣ метавонанд рафтори номувофиқ ба вуҷуд оранд.

Коркардкунандагони вебҳук қабати алоҳидаи миқёспазирӣ мебошанд

Вақте шумораи вебҳукҳои воридшаванда ба маҳдудият табдил ёбад, коркардкунандагони махсуси вебҳук метавонанд дар паси тақсимкунандаи сарборӣ бошанд, дар ҳоле ки коргарҳо иҷроишҳоро анҷом медиҳанд. Ин қабатро танҳо вақте илова кунед, ки ҳаҷми ченшудаи дархостҳо онро асоснок кунад.

Multi-main имконияти дигар аст

Иҷрои якчанд раванди асосӣ барои дастрасии баланд бо режими навбати муқаррарӣ баробар нест. n8n ҳоло multi-main-ро ҳамчун имконияти хостинги мустақили Enterprise бо талаботи иловагии тақсимкунандаи сарборӣ ва сессияҳо тавсиф мекунад.

САВОЛҲОИ МАЪМУЛ

Режими навбати n8n: саволҳои маъмул

Оё режими навбати n8n ба Redis ниёз дорад?

Бале. Redis брокери паёмҳоест, ки иҷроишҳои интизорро байни раванди асосӣ ва коргарҳо ҳамоҳанг мекунад.

Оё режими навбат метавонад SQLite-ро истифода барад?

Барои меъмории тақсимшудаи режими навбат — не. Раванди асосӣ ва коргарҳо бояд ба пойгоҳи додаҳои муштарак дастрас бошанд ва n8n барои чунин ҷойгиркунӣ PostgreSQL-ро тавсиф мекунад.

Чанд коргарро бояд истифода барам?

Шумораи ягонаи мувофиқ ба ҳама вуҷуд надорад. Аз иҷроишҳои ҳамзамон ва масрафи захираҳои воқеан ченшуда оғоз кунед; сипас бо назорати PostgreSQL, Redis, CPU, RAM ва дарозии навбат иқтидорро зиёд намоед.

Иҷроишҳои ҳамзамони коргари n8n чӣ маъно доранд?

Ин шумораи вазифаҳое аст, ки як коргар метавонад ҳамзамон иҷро кунад. Меъёри пешфарзи ҷорӣ 10 аст ва n8n ба ҷойи сохтани коргарҳои зиёди дорои иқтидори ками ҳамзамон арзиши 5 ё бештарро тавсия медиҳад.

Оё дар VPS-и хурд режими навбатро фаъол кунам?

Танҳо вақте сарборӣ инро талаб кунад. Насби хурде, ки бо як нусха бемушкил кор мекунад, одатан бе Redis ва коргарҳои алоҳида соддатар идора мешавад.
