Why workflow count alone is the wrong way to choose a plan

Frequent, short API calls: many executions can pass through a modest server when they process small records and finish before the next batch arrives.

Large imports or bursts: even a small number of workflows can hold substantial data in memory when they process big files or run together. Keep an eye on the busiest period, not just the monthly total.

AI API calls: the model runs at the API provider; your VPS handles the workflow, its data and concurrent requests. Local models and extra databases add a different workload. n8n memory factors · Detailed requirements.

BUY THE RESOURCE YOUR WORKFLOWS USE

What to look for in an n8n VPS

Prioritize RAM for working data, CPU for local processing, and storage for the history and files you retain. Include the database and any other applications sharing the VPS.

Estimate your execution-history storage

Use saved executions per day × average stored size × retention days. For example: 1,000 saved executions × 200 KB × 14 days is about 2.8 GB of stored execution data, using decimal units.

Add space for database indexes and logs, the OS, containers and workflow files. Use your own observed stored size in the calculation. Retention can reduce storage demand without changing CPU or RAM. Execution-data settings.

MemoryLeave room for n8n, the database and data held by overlapping runs. Large files and transformations change the requirement more than the number of saved workflows.
CPUBuy more processing capacity for sustained local computation. Compare CPU allocation as well as core count; shared and dedicated offers are different.
StorageUse SSD or NVMe storage and choose capacity for the data you actually keep. Put recovery copies off-server so they survive loss of the VPS.
EnvironmentChoose Linux with administrative access and Docker support. Use a public HTTPS hostname for webhooks and private networking between application services.
Network & regionIf your provider offers multiple regions, place the VPS near the databases, APIs or users that dominate round trips. File-heavy workflows also make bandwidth and transfer policy part of the resource decision; region can matter for data residency.
Support boundaryBefore checkout, verify what the provider supports. With a self-managed VPS, plan to own n8n updates, configuration and recovery unless application-level management is explicitly included.

A CLEAR GROWTH PATH

Start with one instance. Add workers when needed.

Public HTTPS→Reverse proxy→n8n↔PostgreSQL

A single n8n instance keeps a small deployment straightforward. When jobs accumulate because execution capacity is the constraint, queue mode separates incoming triggers from worker processes that run the workflows.

Plan resources for the main process, PostgreSQL, Redis and each worker. Workers share access to the database and the encryption key. For file-heavy queues, choose supported shared binary storage. Plan queue mode and workers · Official queue architecture.

BUYING QUESTIONS ANSWERED

VPS for n8n: common questions

Which configuration should I choose for a small business?

Choose the 2 vCPU, 4 GB RAM and 80 GB Standard configuration for a modest n8n and PostgreSQL stack handling CRM updates, leads and small JSON-based integrations. Use the larger option for data-heavy work and substantial overlap; use the lighter option for a lean instance with small, mostly sequential jobs.

When is 8 GB RAM a better choice than 4 GB?

When your workflows keep larger files or datasets in memory, perform heavier transformations, or run several demanding jobs together. A high monthly execution count alone is not a reason to double RAM; examine the working data and peak overlap.

Do AI workflows need a GPU VPS?

Calling a hosted model API uses the model provider's inference hardware. Choose your n8n VPS for orchestration, payloads and concurrency. Running a local model or a separate inference service is a different purchase with model-specific RAM and hardware needs.

What happens after I choose a VPS?

Select the Standard server configuration and Linux operating system in the hosting catalog. Deploy n8n with Docker, connect HTTPS, then add your workflow credentials. The deployment path on this page is self-managed. Open the setup checklist.

Can I move my existing workflows to this setup?

Export and import workflows, reconnect credentials where needed, and switch webhooks and scheduled triggers deliberately. For a full-instance move, preserve the database and original encryption key so saved credentials remain usable. Migration and recovery preparation.

Will I need Redis or a paid control panel?

A regular single-instance Docker deployment can run without Redis or a paid hosting panel. Add Redis with queue mode when you need worker-based execution; choose a panel only when its management features are useful to you.

How can I keep n8n VPS costs low without undersizing the server?

Start with the smallest configuration that fits your real payloads and peak overlap, then reduce avoidable demand before upgrading. Prune execution history you do not need, batch large imports, stagger heavy schedules and use hosted AI APIs when local inference is not required. Measure memory, CPU and disk during the busiest period; move up a tier when the optimized workload still reaches sustained limits.
