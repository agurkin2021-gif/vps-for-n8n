उदाहरण वापरून कॉन्फिगरेशन जुळवा

तुमच्या कलम VPS वर कलम Docker सह कलम n8n कलम स्थापित करा

या उदाहरणाचा वापर करून एका कलमावर n8n नेमणुकीची रचना करा. स्वयं-व्यवस्थापित Linux VPSतुम्ही स्वतः n8n स्थापित करता आणि त्याची देखभाल करता; आमच्या जोडीदाराच्या माध्यमातून सर्व्हर निवडण्यात पूर्वस्थापित n8n उदाहरण समाविष्ट नाही. उदाहरणामध्ये n8n, PostgreSQL, एक बाह्य कार्य धावपटू आणि Caddy HTTPS हे खाजगी रचना जाळ्यामध्ये एकत्रित केले आहे. हे एक संरचना टेम्पलेट आहे, थेट चाचणी केलेल्या स्थापनेचा दावा नाही.

त्याऐवजी सर्वात वेगवान नवीन प्रतिष्ठापन हवे आहे का? n8n अधिकृत एक-ओळ Docker सेटअप देखील प्रदान करते. तुम्ही त्याची स्क्रिप्ट डाउनलोड आणि पुनरावलोकन करू शकता curl -fsSL https://get.n8n.io -o get-n8n.sh धावण्यापूर्वी sh get-n8n.shतो पर्याय स्थानिक यू. आर. एल. वर SQLite सह प्रारंभिक उदाहरण सुरू करतो आणि त्यात n8n सहाय्यक सँडबॉक्स सेवा समाविष्ट आहेत; समान नाही हे सार्वजनिक-HTTPS, PostgreSQL-समर्थित VPS उपयोजन म्हणून. अधिकृत पूर्ण सँडबॉक्स स्टॅकला लीन n8n इंस्टॉलेशनपेक्षा RAM आणि CPU अधिक आवश्यक आहे (त्याचे कंपोज मार्गदर्शक किमान 4§GB RAM/2 vCPUs निर्दिष्ट करते). इंटरनेट-फेसिंग उत्पादन VPS साठी, खाली हाताने संरचित केलेला स्टॅक सुरू ठेवा.

1. Docker, DNS तयार करा आणि प्रवेश करा

सुडो प्रवेशासह SSH वर जोडा आणि DNS साठी एक नोंद दर्शवा n8n.example.com तुमच्या कलम VPS आय. पी. व्ही. 4 पत्त्यावर. नवीन Ubuntu 22.04, 24.04 किंवा 26.04 VPS, खालील आदेश Docker इंजिन आणि आधुनिक स्थापित करतात docker compose कलम Docker च्या अधिकृत स्वाक्षरी केलेले प्लगइन apt भांडारः

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

अधिकृत Docker Ubuntu स्थापना मार्गदर्शकातील ही उत्पादन-केंद्रित भांडार पद्धत आहे. आधीच कार्यरत असलेल्या कंटेनर किंवा इतर संकेतस्थळांवर VPS वर Docker आंधळेपणाने पुन्हा स्थापित करू नका किंवा काढू नका.; आधी विद्यमान प्रतिष्ठापन आणि संभाव्य संकुल संघर्षांची तपासणी करा. डेबियन किंवा इतर वितरणासाठी, Ubuntu आदेशांऐवजी संबंधित अधिकृत ओएस-विशिष्ट सूचना वापरा.

आता Docker स्वतःच, कंपोज प्लगइन, DNS आणि कार्यरत निर्देशिकेची पडताळणी कराः

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

जर getent hosts पत्ता किंवा चुकीचा पत्ता परत करत नाही, कलम Caddy सुरू करण्यापूर्वी तुमचा कलम DNS दुरुस्त करा; बदला n8n.example.com या संपूर्ण मार्गदर्शकामध्ये तुमच्या वास्तविक यजमाननामांसह. Docker सामान्यतः मूळ विशेषाधिकारांची आवश्यकता असतेः जर तुमचा SSH वापरकर्ता नंतरचे चालवू शकत नसेल तर docker compose आदेश थेट, त्यांना यासह पूर्वनिर्धारीत करा sudo. त्यात वापरकर्त्याची भर घालणे docker गट मूळ-समतुल्य प्रवेश प्रदान करतो आणि सामायिक सर्व्हरवर आकस्मिकपणे करू नये.

फायरवॉल सक्षम करण्यापूर्वी तुमचे वास्तविक SSH प्रशासन बंदर पोहोचण्याजोगे ठेवा. प्रमाणपत्र जारी करण्यासाठी आणि संपादकासाठी अंतर्गामी HTTP (80) आणि HTTPS (443) ला परवानगी द्या. Docker-प्रकाशित कंटेनर पोर्ट काही यू. एफ. डब्ल्यू. नियम टाळू शकतात, म्हणून Docker च्या फायरवॉल मार्गदर्शनाचे पुनरावलोकन करा आणि फक्त इच्छित Caddy पोर्ट प्रकाशित करा. हे रचना उदाहरण जाणूनबुजून करते नाही. PostgreSQL (5432), n8n (5678) किंवा टास्क-रनर ब्रोकर (5679) सार्वजनिक इंटरनेटवर प्रकाशित करा.

2 पर्यावरण मूल्ये तयार करा आणि किल्ली जतन करा

प्रकल्प निर्देशिकेतून, तीन तयार करा वेगळा. यादृच्छिक हेक्साडेसिमल मूल्ये यासहः

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

नावाची फाइल तयार करा .env खालील नमुना वापरून, प्रत्येक नमुना बदला. REPLACE_WITH_RANDOM_HEX भिन्न व्युत्पन्न मूल्यासह, आणि यजमाननाम आणि वेळक्षेत्र बदला. दर्शविलेले 2.42.5 टॅग आहे 8 ऑक्टोबर 2026 वर सूचीबद्ध स्थिर प्रकाशन, दिनांकित संरचनेचे उदाहरण म्हणून येथे वापरले आहे, थेट चाचणी केलेल्या उपयोजनाची किंवा भविष्यातील सुरक्षेची हमी नाहीप्रतिष्ठापन करण्यापूर्वी, सध्याच्या अधिकृत n8n प्रकाशने तपासा, नंतर n8n आणि त्याची कार्य-धावक प्रतिमा त्याच सत्यापित आवृत्तीवर ठेवा.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

कधीही वचनबद्ध होऊ नका. .env सार्वजनिक भांडारामध्ये. गुप्तलेखन किल्ली आणि पुनर्प्राप्ती सूचना VPS पासून सुरक्षितपणे साठवा. कंटेनर मनोरंजन किंवा स्थलांतरानंतर किल्ली तशीच राहिली पाहिजे.

3. नवीन स्थापनेसाठी compose.yaml लिहा.

त्याच निर्देशिकेत, तयार करा compose.yamlहे उदाहरण अधिकृत n8n पर्यावरण-बदलण्यायोग्य परंपरा आणि PostgreSQL 18 चा वापर करते. PGDATA n8n होस्टिंग प्रकल्पाद्वारे दस्तऐवजीकरण केलेला मार्गः

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

चार सेवांच्या वेगवेगळ्या भूमिका आहेतः PostgreSQL संग्रह डेटाबेस स्थिती, n8n कार्यप्रवाह चालवते, n8n-runner जुळणारी आवृत्ती आणि सामायिक प्रमाणीकरण टोकनसह धावपटू कार्ये अंमलात आणते आणि Caddy सार्वजनिक HTTPS हाताळते. कार्य धावपटू हे Redis क्यू मोड नाही. फक्त Caddy यजमान पोर्ट प्रकाशित करते. हे दुबळे चित्रण मांडणीसाठी एकच डेटाबेस भूमिका वापरते; PostgreSQL विशेषाधिकार अधिक मजबूतपणे वेगळे करण्यासाठी, अधिकृत n8n PostgreSQL उपयोजन उदाहरणाचा सल्ला घ्या.

4. HTTPS कॅडीफाइल तयार करा

फाइल तयार करा Caddyfile (कॅपिटल सी, विस्तार नाही) सोबत compose.yamlउदाहरण यजमाननाम सर्वत्र तुमच्या स्वतःच्या DNS नावाने बदलाः

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy विनंत्या आणि नूतनीकरण TLS जेव्हा डोमेन योग्यरित्या निराकरण करते आणि बाह्य रहदारी बंदरांपर्यंत पोहोचू शकते तेव्हा प्रमाणपत्रे 80/443. लक्ष देऊ नका. DNS करण्यासाठी localhostजर तुम्ही Caddy ची जागा दुसऱ्या उलट प्रॉक्सीने घेतली, तर मूळ यजमान, प्रोटोकॉल आणि ग्राहक-पत्ता हेडर पुढे करा आणि समायोजित करा. N8N_PROXY_HOPS विश्वासार्ह प्रॉक्सी हॉप्सच्या वास्तविक संख्येसाठी.

5. कंटेनर सुरू करा आणि बाहेरून चाचणी करा

संचयित केल्यानंतर प्रकल्प निर्देशिकेतून ह्या आज्ञा चालवा .env, compose.yaml आणि Caddyfile:
