Docker इन्स्टॉलेशन

VPS वर n8n इन्स्टॉल करा

Docker रचना आणि PostgreSQL वापरून VPS वर n8n स्थापित करा. उत्पादन उपयोजनासाठी सतत अनुप्रयोग आणि डेटाबेस डेटा आवश्यक असतो, एक स्थिर N8N_ENCRYPTION_KEY, सार्वजनिक होस्टनाव, HTTPS आणि योग्य वेबहुक कॉन्फिगरेशन. उत्पादन कार्यप्रवाह सक्रिय करण्यापूर्वी हे तुकडे सत्यापित करा.

DNS

TLS प्रमाणपत्रे जारी करण्यापूर्वी आणि वेबहुक URL प्रकाशित करण्यापूर्वी डोमेन किंवा सबडोमेन VPS वर निर्देशित करा.

Docker Compose

ऑपरेटिंग सिस्टमसाठी समर्थित पॅकेजेस वापरून Docker इंजिन आणि कंपोझ प्लगइन स्थापित करा.

फायरवॉल

फक्त आवश्यक प्रशासन आणि वेब पोर्ट उघड करा. PostgreSQL आणि अंतर्गत अनुप्रयोग सेवा खाजगी ठेवा.

आधीच वेबसाइट होस्ट करणाऱ्या VPS वर इंस्टॉल करत आहात? जेव्हा CPU, RAM आणि स्टोरेज परवानगी देतात तेव्हा तुम्ही नियंत्रित केलेल्या सर्व्हरमध्ये n8n जोडू शकता. तथापि, जर Nginx, Apache, Caddy किंवा दुसऱ्या रिव्हर्स प्रॉक्सीकडे आधीपासून 80/443 पोर्ट असतील तर नाही खाली न बदललेले उदाहरण Caddy कंटेनर सुरू करा: पोर्ट विवादित होतील. त्याऐवजी, योग्य खाजगी नेटवर्किंगसह तुमच्या विद्यमान रिव्हर्स प्रॉक्सीद्वारे नवीन n8n सबडोमेन रूट करा किंवा अचूक रचना उदाहरणासाठी स्वच्छ VPS वापरा. इतर साइट्स आणि त्यांचे TLS कॉन्फिगरेशन जतन करा; उदाहरण असे गृहीत धरते की पोर्ट 80/443 उपलब्ध आहेत.

डिप्लॉयमेंटची रचना

कॉन्फिगर करण्यासाठी घटक

उलट प्रॉक्सीसार्वजनिक HTTPS रहदारी प्राप्त करते आणि ते n8n वर अग्रेषित करते.
n8nसतत ऍप्लिकेशन डेटासह संपादक, ट्रिगर आणि वर्कफ्लो चालवते.
PostgreSQLप्रोडक्शन डिप्लॉयमेंटसाठी वर्कफ्लो, क्रेडेंशियल आणि एक्झिक्यूशन स्टेट स्टोअर करते.
सतत खंडडिस्पोजेबल कंटेनरच्या बाहेर अनुप्रयोग आणि डेटाबेस स्थिती ठेवा.
सार्वजनिक DNSसंपादक आणि वेबहुक प्रदात्यांद्वारे वापरलेले होस्टनाव VPS वर मॅप करते.

उदाहरण वापरून कॉन्फिगरेशन जुळवा

तुमच्या VPS वर Docker कंपोझसह n8n इंस्टॉल करा

a वर n8n तैनाती तयार करण्यासाठी हे उदाहरण वापरा स्व-व्यवस्थापित Linux VPS. तुम्ही स्वतः n8n स्थापित आणि राखता; आमच्या भागीदाराद्वारे सर्व्हर निवडण्यामध्ये पूर्व-स्थापित n8n उदाहरण समाविष्ट नाही. उदाहरण खाजगी रचना नेटवर्कमध्ये n8n, PostgreSQL, बाह्य कार्य धावणारा आणि Caddy HTTPS एकत्र करते. हे कॉन्फिगरेशन टेम्पलेट आहे, थेट-चाचणी केलेल्या तैनातीचा दावा नाही.

त्याऐवजी सर्वात वेगवान ताजी स्थापना हवी आहे? n8n अधिकृत वन-लाइन Docker सेटअप देखील प्रदान करते. तुम्ही त्याची स्क्रिप्ट डाउनलोड आणि पुनरावलोकन करू शकता curl -fsSL https://get.n8n.io -o get-n8n.sh धावण्यापूर्वी sh get-n8n.sh. तो पर्याय स्थानिक URL वर SQLite सह प्रारंभिक उदाहरण लाँच करतो आणि n8n सहाय्यक सँडबॉक्स सेवा समाविष्ट करतो; आहे समान नाही हे सार्वजनिक-HTTPS, PostgreSQL-समर्थित VPS तैनाती म्हणून. अधिकृत पूर्ण सँडबॉक्स स्टॅकला लीन n8n इंस्टॉलेशनपेक्षा अधिक RAM आणि CPU आवश्यक आहे (त्याचे कंपोझ मार्गदर्शक किमान 4 GB RAM / 2 vCPUs निर्दिष्ट करते). इंटरनेट-फेसिंग उत्पादनासाठी VPS, खाली मॅन्युअली कॉन्फिगर केलेल्या स्टॅकसह सुरू ठेवा.

1. Docker, DNS आणि प्रवेश तयार करा

sudo ऍक्सेससह SSH वर कनेक्ट करा आणि DNS साठी रेकॉर्ड पॉइंट करा n8n.example.com तुमच्या VPS IPv4 पत्त्यावर. वर ए ताजे Ubuntu 22.04, 24.04 किंवा 26.04 VPS, खालील आदेश Docker इंजिन आणि आधुनिक स्थापित करतात docker compose Docker च्या अधिकृत स्वाक्षरीचे प्लगइन apt भांडार:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

अधिकृत Docker Ubuntu स्थापना मार्गदर्शकामध्ये ही उत्पादन-देणारं भांडार पद्धत आहे. आंधळेपणाने पुन्हा स्थापित किंवा काढू नका Docker a वर VPS आधीच कंटेनर किंवा इतर वेबसाइट्स चालू आहेत; प्रथम विद्यमान प्रतिष्ठापन आणि संभाव्य पॅकेज विरोधाभास तपासा. डेबियन किंवा अन्य वितरणासाठी, Ubuntu आदेशांऐवजी संबंधित अधिकृत OS-विशिष्ट सूचना वापरा.

आता Docker स्वतः, कंपोझ प्लगइन, DNS आणि कार्यरत निर्देशिका सत्यापित करा:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

जर getent hosts कोणताही पत्ता किंवा चुकीचा पत्ता देत नाही, Caddy सुरू करण्यापूर्वी तुमचे DNS दुरुस्त करा; बदला n8n.example.com संपूर्ण या मार्गदर्शकामध्ये तुमच्या वास्तविक होस्टनावासह. Docker ला सामान्यतः रूट विशेषाधिकारांची आवश्यकता असते: जर तुमचा SSH वापरकर्ता नंतर चालवू शकत नाही docker compose थेट आज्ञा, त्यांच्यासह उपसर्ग sudo. मध्ये वापरकर्ता जोडत आहे docker गट रूट-समतुल्य प्रवेश मंजूर करतो आणि सामायिक सर्व्हरवर अनौपचारिकपणे केले जाऊ नये.

फायरवॉल सक्षम करण्यापूर्वी तुमचे वास्तविक SSH प्रशासन पोर्ट पोहोचण्यायोग्य ठेवा. प्रमाणपत्र जारी करण्यासाठी आणि संपादकासाठी इनबाउंड HTTP (80) आणि HTTPS (443) ला अनुमती द्या. Docker-प्रकाशित कंटेनर पोर्ट काही UFW नियमांना बायपास करू शकतात, म्हणून Docker च्या फायरवॉल मार्गदर्शनाचे पुनरावलोकन करा आणि केवळ इच्छित Caddy पोर्ट प्रकाशित करा. हे कंपोज उदाहरण मुद्दाम करतो नाही सार्वजनिक इंटरनेटवर PostgreSQL (5432), n8n (5678) किंवा टास्क-रनर ब्रोकर (5679) प्रकाशित करा.

2. एन्व्हायर्नमेंट व्हेरिएबल्स सेट करा आणि एन्क्रिप्शन की जतन करा

प्रकल्प निर्देशिकेतून, तीन व्युत्पन्न करा वेगळे यादृच्छिक हेक्साडेसिमल मूल्यांसह:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

नावाची फाईल तयार करा .env खालील टेम्पलेट वापरून, प्रत्येक बदला REPLACE_WITH_RANDOM_HEX वेगळ्या व्युत्पन्न मूल्यासह, आणि होस्टनाव आणि टाइमझोन बदला. दाखवले 2.42.5 टॅग आहे स्थिर प्रकाशन 8 ऑक्टोबर 2026 रोजी सूचीबद्ध, येथे दिनांकित कॉन्फिगरेशन उदाहरण म्हणून वापरले, थेट-चाचणी तैनाती किंवा भविष्यातील सुरक्षिततेची हमी नाही. स्थापित करण्यापूर्वी, वर्तमान अधिकृत n8n प्रकाशन तपासा, नंतर n8n आणि त्याची कार्य-रनर प्रतिमा त्याच सत्यापित आवृत्तीवर ठेवा.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

कधीही वचनबद्ध करू नका .env सार्वजनिक भांडारात. एन्क्रिप्शन की आणि रिकव्हरी सूचना VPS मधून सुरक्षितपणे साठवा. कंटेनर मनोरंजन किंवा स्थलांतरानंतर की समान राहणे आवश्यक आहे.

3. नवीन स्थापनेसाठी compose.yaml लिहा

त्याच निर्देशिकेत, तयार करा compose.yaml. उदाहरण अधिकृत n8n पर्यावरण-व्हेरिएबल कन्व्हेन्शन्स आणि PostgreSQL 18 वापरते PGDATA n8n होस्टिंग प्रकल्पाद्वारे दस्तऐवजीकरण केलेला मार्ग:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

चार सेवांच्या वेगळ्या भूमिका आहेत: PostgreSQL डेटाबेस स्थिती संग्रहित करते, n8n कार्यप्रवाह चालवते, n8n-runner जुळणारी आवृत्ती आणि सामायिक प्रमाणीकरण टोकनसह धावपटू कार्ये चालवते आणि Caddy सार्वजनिक HTTPS हाताळते. एक बाह्य कार्य धावपटू Redis रांग मोड नाही. फक्त Caddy होस्ट पोर्ट प्रकाशित करते. हे दुबळे चित्र सेटअपसाठी एकल डेटाबेस भूमिका वापरते; PostgreSQL विशेषाधिकारांच्या मजबूत पृथक्करणासाठी, अधिकृत n8n PostgreSQL तैनात उदाहरण पहा.

4. HTTPS Caddyfile तयार करा

फाइल तयार करा Caddyfile (कॅपिटल C, विस्तार नाही) बाजूने compose.yaml. उदाहरण होस्टनाव सर्वत्र तुमच्या स्वतःच्या DNS नावाने बदला:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy विनंत्या आणि सार्वजनिक TLS प्रमाणपत्रांचे नूतनीकरण करते जेव्हा डोमेनचे निराकरण होते आणि बाह्य रहदारी 80/443 पोर्टपर्यंत पोहोचू शकते. DNS कडे निर्देशित करू नका localhost. तुम्ही Caddy ला दुसऱ्या रिव्हर्स प्रॉक्सीने बदलल्यास, मूळ होस्ट, प्रोटोकॉल आणि क्लायंट-पत्ता शीर्षलेख फॉरवर्ड करा आणि समायोजित करा N8N_PROXY_HOPS विश्वसनीय प्रॉक्सी हॉप्सच्या वास्तविक संख्येसाठी.

5. कंटेनर सुरू करा आणि बाहेरून चाचणी करा

सेव्ह केल्यानंतर प्रोजेक्ट डिरेक्टरीमधून या कमांड्स चालवा .env, compose.yaml आणि Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
