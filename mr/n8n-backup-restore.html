अचूक n8n एन्क्रिप्शन किल्ली स्वतंत्रपणे आणि सुरक्षितपणे जतन करा. पुनर्स्थापित एन्क्रिप्ट केलेली ओळखपत्रे त्याच किल्लीवर अवलंबून असतात.

कायमस्वरूपी n8n डेटा निर्देशिका आणि कोणत्याही आरोहित फायली, द्विसंगी-डेटा संचयन किंवा कार्यप्रवाह मालमत्ता समाविष्ट करा ज्यावर तुम्ही उपयोजन अवलंबून आहात.

कार्यप्रवाह आणि प्रमाणपत्र निर्यात

n8n CLI निर्याती स्थलांतर, आवृत्ती कार्यप्रवाह प्रती आणि निवडक पुनर्संचयित करण्यासाठी उपयुक्त आहेत. ओळखपत्रे एन्क्रिप्टेड स्वरूपात निर्यात केली जाऊ शकतात आणि नंतर जुळणाऱ्या एन्क्रिप्शन कीसह आयात केली जाऊ शकतात. फक्त एक कार्यप्रवाह पुनर्प्राप्त करण्यासाठी, कार्यप्रवाह संपादकाच्या तीन-बिंदू मेनूचा वापर करून त्याचा JSON डाउनलोड करा, नंतर फाइलमधून नवीन पुनरावलोकन कार्यप्रवाह किंवा वेगळ्या उदाहरणात आयात करा. थेट कार्यप्रवाह बदलण्यापूर्वी ओळखपत्रे, कार्यप्रवाह आयडी आणि नोड मापदंड तपासाः कार्यप्रवाह पुनर्संचयित करणे JSON संपूर्ण सर्व्हर पुनर्संचयित करत नाही.

संस्थेची निर्यात

CLI समर्थित डेटाबेस प्रकारांमध्ये डेटा हलवण्यासाठी डेटाबेस घटक निर्यात करू शकते. अंमलबजावणी-इतिहास सारण्या ऐच्छिक आहेत कारण त्या खूप मोठ्या असू शकतात.

पूर्ण उदाहरण पुनर्प्राप्ती

डेड-सर्व्हर परिस्थितीसाठी, वास्तविक डेटाबेस, एन्क्रिप्शन की, सातत्यपूर्ण डेटा आणि उपयोजन अवलंबित्व संरक्षित करा. असे समजू नका की वर्कफ्लो JSON एक्सपोर्ट संपूर्ण उदाहरणाची पुनर्रचना करतो.

स्नॅपशॉट प्रदान करा

एक VPS स्नॅपशॉट अतिरिक्त पुनर्प्राप्ती थर म्हणून उपयुक्त आहे, परंतु ती एकमेव प्रत नसावी आणि स्वतंत्रपणे सत्यापित अनुप्रयोग/डेटाबेस बॅकअपची जागा घेऊ नये.

डेटाबेस

डेटाबेसचा सातत्याने बॅकअप घ्या

PostgreSQL

सुसंगत PostgreSQL बॅकअप पद्धत वापरा आणि परिणामी बॅकअप VPS पासून दूर ठेवा. त्याच अयशस्वी डिस्कवरील डेटाबेस प्रत आपत्ती पुनर्प्राप्ती नाही.

SQLite

उपयोजन SQLite वापरत असल्यास, डेटाबेस फाइलला कायम असलेल्या n8n डेटा निर्देशिकेपासून संरक्षित करा. सक्रियपणे सुधारित केले जात असताना असुरक्षित स्थितीत डेटाबेसची नक्कल करणे टाळा.

अंमलबजावणीचा इतिहास

ऐतिहासिक अंमलबजावणीचा डेटा हा तुमच्या पुनर्प्राप्ती उद्देशाचा भाग आहे की नाही हे ठरवा. यामुळे बॅकअप लक्षणीयरीत्या मोठे होऊ शकतात, त्यामुळे धारणा आणि अनुपालनाच्या आवश्यकतांमुळे निवड केली जाईल.

डेटाबेस आवृत्ती

डेटाबेस इंजिन आणि स्रोत उपयोजनाद्वारे वापरलेली आवृत्ती नोंदवा जेणेकरून पुनर्प्राप्ती वातावरण सुसंगतपणे तयार केले जाऊ शकेल.

Docker वर PostgreSQL कलम VPS तयार करा. जर PostgreSQL सेवेचे नाव असेल तर postgres आणि त्याचा डेटाबेस/वापरकर्ता दोन्ही आहेत n8nखालील आदेश यजमानावर एक सुसंगत PostgreSQL कस्टम-फॉरमॅट डंप तयार करतो. ती चालवण्यापूर्वी तुमची वास्तविक कंपोज फाइल तपासा आणि डेटाबेस क्रेडेन्शियल्स आणि सेवा नावे समायोजित करा. pg_dump PostgreSQL चालू असताना तार्किकदृष्ट्या सुसंगत स्नॅपशॉट तयार करू शकतो; तो करतो नाही. वेगळा बॅकअप घ्या .n8n वापरकर्ता फोल्डर किंवा बाह्य बायनरी डेटा.

# In the Docker Compose project; adapt service, DB and user names

Docker वर SQLite. पूर्वनिर्धारित SQLite नेमणुकीसाठी, database.sqlite आणि तयार केलेली एन्क्रिप्शन-की संरचना कायमस्वरूपी आत राहते .n8n फोल्डर (सामान्यतः येथे बसवले जाते /home/node/.n8n). SQLite ची साधी थेट प्रत कधीही सुसंगत मानू नका. फोल्डरची नक्कल करण्यापूर्वी n8n आणि इतर डेटाबेस लेखकांना थांबवा किंवा व्यत्यय येणे अशक्य असताना SQLite ची समर्थित ऑनलाइन बॅकअप यंत्रणा वापराः

पूर्वनिर्धारित SQLite फोल्डर स्वच्छ लक्ष्यावर पुनर्संचयित करत आहेः प्रथम n8n सेवा आणि सर्व डेटाबेस लेखक थांबवा. एकदा सुसंगत n8n सेवा कंटेनर आणि त्याचे गंतव्य खंड अस्तित्वात आले की, बॅक-अप कॉपी करा. .n8n सामग्री मागे त्याच सातत्यपूर्ण निर्देशिकेवर. हे लक्ष्यित फाइल्स अधिलिखित करते, म्हणून तुम्हाला ठेवण्याची आवश्यकता असलेल्या डेटाच्या उदाहरणावर ते चालवू नकाः
