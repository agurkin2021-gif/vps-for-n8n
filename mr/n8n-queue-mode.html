n8n Queue Mode

Higher concurrency साठी main instance + Redis + workers + PostgreSQL architecture वापरली जाते.

Webhook/Main→Redis→Workers→PostgreSQL

सर्व workers मध्ये समान N8N_ENCRYPTION_KEY आणि consistent config आवश्यक आहे.

Queue mode कधी?

Single-process VPS resource limit गाठत असेल, concurrent executions वाढत असतील किंवा workload workers मध्ये distribute करायचा असेल.

मुख्य technical decisions

Queue Mode पूर्ण नियोजित करा

1

Queue Mode PostgreSQL, Redis, main/webhook processes आणि workers वापरतो; सर्व workers मध्ये तोच N8N_ENCRYPTION_KEY हवा.

2

Main, webhook processors आणि workers समान n8n version वर चालवा.

3

Worker concurrency, queue depth आणि latency मोजा; slow DB किंवा external API फक्त workers वाढवून सुटत नाही.

4

Webhook processors स्वतंत्र scaling layer आहेत; multi-main/HA सामान्य Queue Mode सारखे नाही.

FAQ

Queue Mode पूर्ण नियोजित करा: FAQ

1 GB हा खरा VPS आहे का?

हो. तो हलक्या workload साठी खरा entry VPS आहे; मर्यादा कमी resource headroom आहे.

2 GB light baseline का?

Docker, OS आणि लहान peaks साठी अधिक headroom मिळतो.

Scale आधी measure का?

CPU, RAM, disk आणि latency खरा bottleneck दाखवतात.
