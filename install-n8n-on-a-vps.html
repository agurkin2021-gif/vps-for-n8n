DOCKER INSTALLATION

Install n8n on a VPS

Install n8n on a VPS using Docker Compose and PostgreSQL. A production deployment also needs persistent application and database data, a stable N8N_ENCRYPTION_KEY, a public hostname, HTTPS and correct webhook configuration. Verify these pieces before activating production workflows.

PREREQUISITES

Prepare the VPS before starting n8n

Linux VPS

Use a maintained Linux server sized for n8n, PostgreSQL, Docker and the reverse proxy.

DNS

Point a domain or subdomain at the VPS before issuing TLS certificates and publishing webhook URLs.

Docker Compose

Install Docker Engine and the Compose plugin using supported packages for the operating system.

Firewall

Expose only required administration and web ports. Keep PostgreSQL and internal application services private.

CONFIGURATION

Set secrets and public URLs deliberately

Encryption key

Set and preserve a strong n8n encryption key before storing production credentials. The same key is required after recovery.

PostgreSQL credentials

Use dedicated database credentials and keep passwords outside public source control.

Public hostname

Configure the real external hostname and HTTPS origin rather than an internal container address.

Webhook URL

Set the public webhook base URL when the internal n8n address differs from the URL reachable by third-party services.

PERSISTENCE

Persist n8n and PostgreSQL separately

n8n data

Mount persistent storage for the n8n data directory so critical instance state survives container recreation.

PostgreSQL data

Persist the database directory independently from the PostgreSQL container.

File permissions

Make mounted paths writable by the intended container user without making host storage unnecessarily permissive.

Workflow files

Persist any mounted files or binary-data storage that production workflows depend on.

HTTPS & PROXY

Put the public n8n URL behind HTTPS

Reverse proxy

Use Nginx, Caddy or Traefik as the public entry point and forward traffic to the private n8n service.

TLS

Issue a valid certificate for the public hostname and redirect HTTP traffic to HTTPS.

Forwarded headers

Pass the host, protocol and client information n8n needs and configure the expected proxy hop count.

Webhook verification

Trigger a webhook from outside the VPS and confirm n8n generates the externally reachable HTTPS URL.

COMMON FAILURES

Why an n8n Docker install works locally but fails in production

Wrong webhook URL

Callbacks point to localhost, HTTP or an internal hostname instead of the public HTTPS origin.

Missing persistence

Application or database state disappears when a container is recreated.

Lost encryption key

Saved credentials become unusable after rebuilding because the new instance uses a different key.

Public database port

PostgreSQL is exposed unnecessarily even though only n8n needs to reach it.

POST-DEPLOY VERIFICATION

Verify health before connecting real workflows

Check container state

Run docker compose ps and confirm the application and database services are running as expected before treating the deployment as healthy.

Check the n8n health endpoint

From the server, test curl -sf http://localhost:5678/healthz. Then verify the public HTTPS hostname separately through the reverse proxy.

Pin application versions

Do not treat an unreviewed floating image update as a maintenance strategy. Record the n8n version you run, read release notes and back up before changing it.

Do not bump PostgreSQL major versions in place

Changing only the Postgres major image tag can make an existing data directory incompatible. Back up and follow the database upgrade procedure instead of assuming container recreation performs a major-version migration.

FAQ

Installing n8n with Docker: common questions

Does n8n need PostgreSQL when using Docker?

Docker does not require PostgreSQL, and small deployments can use SQLite. For a production-oriented VPS deployment, PostgreSQL provides a stronger database foundation and supports later queue-mode scaling.

Why keep a persistent n8n volume if PostgreSQL stores data?

The persistent n8n directory can contain important instance state and configuration. Preserve it according to the deployment design instead of assuming the database is the only recovery asset.

Why does my webhook show localhost?

The internal container address differs from the public origin. Configure the external hostname, protocol and webhook URL, and ensure the reverse proxy passes the required headers.

Should port 5678 be public?

For a normal production deployment behind a reverse proxy, expose HTTPS at the proxy and keep the n8n application port internal unless there is a specific operational reason not to.

Do I need Redis?

Not for a standard single-instance Docker deployment. Redis becomes relevant when you deliberately move to queue mode and workers.
