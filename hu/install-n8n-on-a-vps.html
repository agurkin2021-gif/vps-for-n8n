DOCKER TELEPÍTÉS

Az n8n telepítése VPS-re

Telepítse a n8n-t egy VPS-ra a Docker Compose és a PostgreSQL használatával. Az éles telepítéshez állandó alkalmazás- és adatbázisadatokra, egy stabilra is szükség van N8N_ENCRYPTION_KEY, egy nyilvános gazdagépnév, HTTPS és a megfelelő webhook konfiguráció. A termelési munkafolyamatok aktiválása előtt ellenőrizze ezeket a darabokat.

ELŐFELTÉTELEK

Az n8n megkezdése előtt készítse elő a VPS-t

Linux VPS

Használjon karbantartott Linux szervert, amelynek mérete n8n, PostgreSQL, Docker és a fordított proxy.

DNS

Az TLS. bekezdés szerinti tanúsítványok kiadása és a webhook URL-ek közzététele előtt mutasson egy domaint vagy aldomaint a VPS-ra.

Docker Compose

Telepítse a Docker Engine-t és a Compose beépülő modult az operációs rendszer támogatott csomagjaival.

Tűzfal

Csak a szükséges adminisztrációs és webportokat tegye közzé. A PostgreSQL és a belső alkalmazási szolgáltatások titkosak maradnak.

Olyan VPS-ra telepít, amely már tartalmaz webhelyeket? Hozzáadhatja a n8n-t az Ön által felügyelt szerverhez, amikor az CPU, RAM és a tárhely lehetővé teszi. Ha azonban az Nginx, az Apache, a Caddy vagy egy másik fordított proxy már rendelkezik a 80/443 portokkal, tegye nem kezdje el az alábbi Caddy tároló példáját változatlanul: a portok ütközni fognak. Ehelyett irányítson át egy új n8n aldomaint meglévő fordított proxyján keresztül megfelelő magánhálózattal, vagy használjon tiszta VPS-t a pontos Compose példához. Megőrzi a többi oldalt és azok TLS-os konfigurációját; a példa azt feltételezi, hogy a 80/443 portok rendelkezésre állnak.

MÁSOLÁS ÉS ALKALMAZÁS TELEPÍTÉS

Telepítse a n8n-t a VPS-ra a Docker Compose segítségével

Használja ezt a példát egy n8n telepítéshez a saját irányítású Linux VPS. Ön maga telepíti és karbantartja a n8n-t; A partnerünkön keresztüli szerver kiválasztása nem tartalmaz előre telepített n8n-példányt. A példa a n8n, PostgreSQL egy külső feladatfutót és a Caddy HTTPS egy privát Compose hálózatban kombinálja. Ez egy konfigurációs sablon, nem élesben tesztelt telepítésre vonatkozó igény.

A leggyorsabb friss telepítést szeretné helyette? A n8n hivatalos egysoros Docker beállítást is biztosít. Letöltheti és áttekintheti a szkriptjét a segítségével curl -fsSL https://get.n8n.io -o get-n8n.sh futás előtt sh get-n8n.sh. Ez az opció elindít egy kezdeti példányt SQLite-val egy helyi URL-en, és magában foglalja az n8n Assistant sandbox szolgáltatásokat; ez van nem ugyanaz mint ez az állami HTTPS, PostgreSQL által támogatott VPS bevetés. A hivatalos teljes homokozóverem több RAM-t és CPU-t igényel, mint egy egyszerű n8n-os telepítést (a Compose útmutatója legalább 4 GB RAM / 2 vCPU-kat ír elő). Az internetre néző produkcióhoz, VPS, folytassa az alábbi, manuálisan konfigurált köteggel.

1. Készítse elő az Docker, DNS és hozzáférést

Csatlakozzon SSH-on keresztül sudo hozzáféréssel, és mutasson rá a DNS-ra n8n.example.com VPS IPv4-címére. Az a friss Ubuntu 22.04, 24.04 vagy 26.04 VPS, a következő parancsok telepítik Docker Motor és a modern docker compose plugin Docker hivatalos aláírásával apt adattár:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Ez a gyártásorientált adattárolási módszer a hivatalos Docker Ubuntu telepítési útmutatóban. Ne telepítse vakon újra vagy távolítsa el a Docker-t olyan VPS-on, amelyen már fut tárolók vagy más webhelyek; először ellenőrizze a meglévő telepítést és az esetleges csomagütközéseket. Debian vagy más disztribúció esetén használja a megfelelő hivatalos operációs rendszer-specifikus utasításokat a Ubuntu parancsok helyett.

Most ellenőrizze magát a Docker-t, a Compose beépülő modult, az DNS-t és a munkakönyvtárat:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Ha getent hosts nem ad vissza címet, vagy rossz címet ad vissza, javítsa ki a DNS-át, mielőtt elkezdi az Caddy-t; cserélje ki n8n.example.com ebben az útmutatóban az Ön valódi gazdagépnevével. A Docker általában root jogosultságokat igényel: ha a SSH felhasználó nem tudja futtatni a későbbi verziót docker compose parancsokat közvetlenül, előtagozzuk őket sudo. Felhasználó hozzáadása a docker csoport root-egyenértékű hozzáférést biztosít, és ezt nem szabad véletlenül megtenni egy megosztott szerveren.

A tűzfal engedélyezése előtt tartsa elérhetővé a tényleges SSH adminisztrációs portját. Bejövő HTTP (80) és HTTPS (443) engedélyezése a tanúsítvány kiállításához és a szerkesztőhöz. Az Docker-ban közzétett konténerportok megkerülhetnek bizonyos UFW-szabályokat, ezért tekintse át a Docker tűzfalra vonatkozó útmutatásait, és csak a tervezett Caddy-os portokat tegye közzé. Ez a Compose példa szándékosan ezt teszi nem PostgreSQL (5432), n8n (5678) vagy Task-runner broker (5679) közzététele a nyilvános interneten.

2. Hozzon létre környezeti értékeket és őrizze meg a kulcsot

A projektkönyvtárból hozzon létre hármat különböző véletlenszerű hexadecimális értékek a következőkkel:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Hozzon létre egy nevű fájlt .env az alábbi sablon használatával cserélje ki mindegyiket REPLACE_WITH_RANDOM_HEX eltérő generált értékkel, és módosítsa a gazdagépnevet és az időzónát. A bemutatott 2.42.5 címke a stabil kiadás a 8 Október 2026-ban, amelyet itt dátumos konfigurációs példaként használunk, nem garantálja az élőben tesztelt telepítést vagy a jövőbeni biztonságot. Telepítés előtt ellenőrizze az aktuális hivatalos n8n kiadásokat, majd tartsa az n8n-t és a feladat-futóképet ugyanazon az ellenőrzött verzión.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Soha ne kötelezze el magát .env nyilvános adattárba. Tárolja biztonságosan a titkosítási kulcsot és a helyreállítási utasításokat a VPS-on kívül. A kulcsnak változatlannak kell maradnia a tároló újratelepítése vagy áttelepítése után.

3. Új telepítéshez írja be a compose.yaml-t

Ugyanabban a könyvtárban hozza létre compose.yaml. A példa a hivatalos n8n környezeti változókonvenciót és az PostgreSQL 18-t használja. PGDATA n8n hosting projekt által dokumentált útvonal:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

A négy szolgáltatásnak külön szerepe van: PostgreSQL tárolja az adatbázis állapotát, n8n munkafolyamatokat futtat, n8n-runner futó feladatokat hajt végre egy megfelelő verzióval és megosztott hitelesítési tokennel, a Caddy pedig a nyilvános HTTPS-t kezeli. Egy külső feladatfutó nem Redis várólista mód. Csak Caddy teszi közzé a gazdagép portokat. Ez a karcsú illusztráció egyetlen adatbázis-szerepet használ a beállításhoz; a PostgreSQL-os jogosultságok erősebb elkülönítéséhez tekintse meg a hivatalos n8n PostgreSQL-os telepítési példát.

4. Hozza létre az HTTPS Caddyfile-t

Hozd létre a fájlt Caddyfile (C nagybetűvel, kiterjesztés nélkül) mellé compose.yaml. Cserélje le a példa hosztnevet mindenhol a saját DNS nevére:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy nyilvános TLS tanúsítványokat kér és újít meg, ha a tartomány helyesen oldódik fel, és a külső forgalom elérheti a 80/443 portokat. Ne a DNS. -ra hivatkozzon localhost. Ha a Caddy-t egy másik fordított proxyra cseréli, továbbítsa az eredeti gazdagép, protokoll és klienscím fejlécet, és állítsa be N8N_PROXY_HOPS a megbízható proxy ugrások tényleges számához.

5. Indítsa el a tartályokat és tesztelje kívülről

Mentés után futtassa ezeket a parancsokat a projektkönyvtárból .env, compose.yaml és Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Az utolsó parancs ellenőrzi a nyilvános HTTPS egészségügyi végpont. Ha a tanúsítvány kiadása még függőben van, ellenőrizze a Caddy naplókat és DNS/portokat, mielőtt a n8n megszakadt. Nyissa meg https://n8n.example.com, azonnal hozza létre az első tulajdonosi fiókot, és engedélyezze a megfelelő bejelentkezési védelmet. Győződjön meg arról, hogy a példány valóban egy munkafolyamatot hajt végre, nem csupán azt, hogy a szerkesztő betölti:

  1. A szerkesztőben hozzon létre egy munkafolyamatot az a Webhook ravaszt. Állítsa be HTTP Módszer hogy GET, válassza ki a Path vps-check, és állítsa be Válaszolj hogy Azonnal. Mentse el a munkafolyamatot.
  2. Kattintson Hallgassa meg a teszt eseményt, másolja a teljes Teszt URL n8n mutatja, és egy másik eszközről fut curl -i 'PASTE_TEST_URL_HERE' a másolt URL-lel. Várja, hogy a HTTP sikeres válasza és a bejövő esemény megjelenjen a n8n szerkesztőben. A teszt URL-ek csak akkor működnek, amikor a n8n figyeli az eseményt.
  3. Közzététel a munkafolyamatot, kapcsolja át a csomópontot a megfelelőre Gyártási URL, másolja ki és futtassa curl -i 'PASTE_PRODUCTION_URL_HERE' újra. Erősítse meg a végrehajtást a munkafolyamat alatt Kivégzések lapon. Az éles webhook-kérelmeknek közzé kell tenni a munkafolyamatot, és nem jelennek meg a hasznos terhelésük a szerkesztő tesztnézetében.

Ez egy szándékosan egyszerű, nem hitelesített füstteszt: soha ne küldj neki titkokat. Tesztelés után vonja vissza a közzétételt/törölje, vagy konfigurálja a Webhook-hitelesítési/IP-korlátozásokat, mielőtt nyilvános végpontot használna valós adatokhoz. Tekintse meg a Webhook hivatalos teszt/gyártási dokumentációját.

6. A rögzített verziók módosítása előtt készítsen biztonsági másolatot

Mentse el a helyreállítható PostgreSQL kiírást és a tartós n8n adatmennyiség, .env/titkosítókulcsot és a szükséges külső fájlokat a kiszolgálón kívüli tárolásra. Ellenőrizze a visszaállítást a biztonsági mentési és helyreállítási útmutató a gyártás frissítése előtt. Példaparancsok:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Cserélje ki a rögzítettet N8N_VERSION csak a kiadási megjegyzések elolvasása után; a n8n és a futóképeknek együtt kell haladniuk. Ne fuss docker compose down -v rutin karbantartás során, mert ez törli a megnevezett adatköteteket. PostgreSQL A főbb verzióváltásokhoz adatbázis-frissítés vagy kiíratási/visszaállítási terv szükséges; a Postgres 18 képének másik fő címkére való lecserélése nem automatikus migráció.

Hiteles hivatkozások: n8n Docker Összeállítási útmutató, n8n fordított proxy/webhook konfiguráció és hivatalos PostgreSQL beépítési megjegyzések. Nem feltételezhető infrastruktúra-benchmark vagy szolgáltató-specifikus előre telepített szolgáltatás.

Gyakran ismételt kérdések

n8n telepítése Docker-al: gyakori kérdések

A n8n-nak szüksége van az PostgreSQL-ra a Docker használatakor?

A Docker nem követeli meg az PostgreSQL -t, és a kis bevetések használhatják a SQLite-t. A termelés-orientált VPS-os telepítéshez a PostgreSQL erősebb adatbázis-alapot biztosít, és támogatja a későbbi sormódú skálázást.

Miért tartsunk fenn tartós n8n-os kötetet, ha az PostgreSQL adatokat tárol?

Az állandó n8n könyvtár fontos példányállapotot és konfigurációt tartalmazhat. Őrizze meg a telepítési terv szerint, ahelyett, hogy azt feltételezné, hogy az adatbázis az egyetlen helyreállítási eszköz.

Miért jelenik meg a webhookom, hogy localhost?

A belső tároló címe eltér a nyilvános eredettől. Konfigurálja a külső gazdagépnevet, protokollt és webhook URL-t, és győződjön meg arról, hogy a fordított proxy átadja a szükséges fejléceket.

A 5678 port nyilvános legyen?

A fordított proxy mögötti normál éles üzembe helyezés esetén tegye közzé a HTTPS-t a proxynál, és tartsa belső az n8n-os alkalmazásportot, hacsak nincs konkrét működési ok, ami miatt nem.

Szükségem van a Redis-ra?

Nem szabványos egypéldányos Docker-os telepítéshez. Az Redis. -a akkor válik relevánssá, ha szándékosan sorban állásra vált és a dolgozókat.

A külső n8n feladatfutók ugyanazok, mint a sor módban dolgozók?

Nem. A külső feladatfutók a támogatott feladatkódot a n8n főfolyamattól elkülönítve hajtják végre, és megosztott hitelesítési tokent használnak. Az Redis. -a queue mode elosztja a munkafolyamat-végrehajtásokat, és saját infrastrukturális követelményei vannak. Ez a példa egy külső feladatfutót mutat be, nem a Redis várólista módot.
