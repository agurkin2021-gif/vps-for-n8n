REQUISITOS DO SERVIDOR

CPU, RAM e armazenamento

Especificações mínimas não garantem produção. Mantenha folga para Docker, PostgreSQL, reverse proxy e picos de carga.

CPU1–2 vCPU para carga leve; 4+ vCPU para transformações pesadas e concorrência maior.
RAM1–2 GB entrada/light · 4 GB small production · 8 GB+ heavy/AI.
StorageSSD/NVMe para PostgreSQL, histórico, logs, binary data e volumes Docker.
NetworkHTTPS público, saída estável para APIs e largura de banda suficiente.

EXECUTION LIMITS

VPS comum não cobra por quantidade de executions

Limite por recurso

O limite prático vem de RAM, CPU, PostgreSQL, disk I/O e arquitetura.

Concorrência importa mais

Muitos workflows leves podem coexistir se não rodarem ao mesmo tempo; poucos workflows pesados simultâneos podem exigir muito mais servidor.

Histórico custa recurso

Execution history, logs e binary data aumentam banco, storage e I/O.

Licença é outra camada

Community Edition e recursos pagos Business/Enterprise são níveis diferentes; comprar VPS não libera automaticamente recursos pagos do n8n.

BRASIL: O QUE VER ANTES DE COMPRAR

Quatro critérios que aparecem no SERP brasileiro

Latência e região

Se seus usuários e APIs estão no Brasil, rota e região podem reduzir latência. Não escolha só pela bandeira do datacenter.

Preço inicial vs renovação

Ofertas promocionais são comuns. Compare a renovação, backup extra, storage e contrato antes de decidir.

Backup e suporte

Veja se o backup é automático e qual é o escopo do suporte. A VDSina informa suporte técnico 24/7 para a infraestrutura; suporte a workflows, Docker e configuração do n8n continua sendo uma camada separada.

Upgrade path

Confirme como sair de 4 GB para 8/16 GB: resize simples, downtime, troca de IP ou migração.

ARQUITETURA DE PRODUÇÃO

Produção não é só subir o container

HTTPS→Reverse Proxy→n8n→PostgreSQL→Backup

Queue mode adiciona Redis e workers. Mantenha configuração consistente e o mesmo N8N_ENCRYPTION_KEY entre os processos.

ANTES DE ESCALAR

Nem todo gargalo precisa de mais RAM

Retention

Não retenha execuções de sucesso por mais tempo que o necessário.

Schedules

Distribua jobs pesados se eles não precisarem rodar em paralelo.

Payload

Evite trafegar JSON enorme e binary data entre nodes sem necessidade.

Measure

Observe RAM, CPU, crescimento de disco e duração das execuções antes de ampliar recurso.

FAQ

Perguntas comuns sobre VPS para n8n

Quanta RAM o n8n precisa?

1–2 GB podem servir para testes e cargas leves. Para n8n + PostgreSQL em produção pequena, 4 GB é uma base mais prática. Para IA e cargas pesadas, considere 8 GB+.

O n8n vem pré-instalado?

Nesta página, assumimos self-install. Se o provedor não anunciar explicitamente uma imagem/one-click n8n, você deverá instalar com Docker/Compose.

Existe limite mensal de executions no VPS?

Um VPS comum não mede executions como o Cloud. O limite prático vem dos recursos e da arquitetura.

Preciso de domínio?

Para um URL HTTPS estável e webhooks públicos, usar domínio ou subdomínio é recomendado.

Redis é obrigatório?

Não no modo normal. Redis entra no queue mode com workers.

Posso rodar PostgreSQL e n8n no mesmo VPS?

Sim, em produção pequena, com 4 GB de RAM e storage suficiente. Em carga maior, o banco pode ser separado.
