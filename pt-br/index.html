Por que a quantidade de workflows, sozinha, não é a forma correta de escolher um plano

Chamadas de API frequentes e curtas: muitas execuções podem passar por um servidor modesto quando processam registros pequenos e terminam antes da chegada do próximo lote.

Grandes importações ou picos: até poucos workflows podem manter muitos dados na memória quando processam arquivos grandes ou rodam juntos. Observe o período de maior carga, não apenas o total mensal.

Chamadas de API de IA: o modelo roda no provedor da API; seu VPS cuida do workflow, dos dados e das requisições simultâneas. Modelos locais e bancos adicionais criam outra carga de trabalho. Fatores de memória do n8n · Requisitos detalhados.

COMPRE OS RECURSOS QUE SEUS WORKFLOWS USAM

O que procurar em um VPS para n8n

Priorize RAM para dados em processamento, CPU para processamento local e armazenamento para o histórico e os arquivos mantidos. Inclua o banco de dados e qualquer outra aplicação que compartilhe o VPS.

Estime o armazenamento do histórico de execuções

Use execuções salvas por dia × tamanho médio armazenado × dias de retenção. Por exemplo: 1,000 execuções salvas × 200 KB × 14 dias são cerca de 2.8 GB de dados de execução armazenados, usando unidades decimais.

Adicione espaço para índices e logs do banco, sistema operacional, contêineres e arquivos de workflow. Use no cálculo o tamanho armazenado observado no seu ambiente. A retenção pode reduzir a necessidade de armazenamento sem alterar CPU ou RAM. Configurações de dados de execução.

MemóriaDeixe folga para o n8n, o banco de dados e os dados mantidos por execuções sobrepostas. Arquivos grandes e transformações alteram a necessidade mais do que a quantidade de workflows salvos.
CPUCompre mais capacidade de processamento para computação local contínua. Compare a alocação de CPU além da quantidade de núcleos; ofertas compartilhadas e dedicadas são diferentes.
ArmazenamentoUse armazenamento SSD ou NVMe e escolha a capacidade para os dados que você realmente mantém. Guarde cópias de recuperação fora do servidor para que sobrevivam à perda do VPS.
AmbienteEscolha Linux com acesso administrativo e suporte a Docker. Use um hostname HTTPS público para webhooks e rede privada entre os serviços da aplicação.
Rede & regiãoSe o provedor oferece várias regiões, coloque o VPS perto dos bancos, APIs ou usuários que concentram as idas e voltas de rede. Workflows com muitos arquivos também tornam a largura de banda e a política de transferência parte da decisão; a região pode importar para residência de dados.
Limite do suporteAntes do checkout, confirme o que o provedor realmente oferece. Em um VPS autogerenciado, considere que atualizações, configuração e recuperação do n8n são sua responsabilidade, salvo quando o gerenciamento da aplicação estiver explicitamente incluído.

UM CAMINHO CLARO DE CRESCIMENTO

Comece com uma instância. Adicione workers quando necessário.

HTTPS público→Reverse proxy→n8n↔PostgreSQL

Uma única instância do n8n mantém um deploy pequeno simples. Quando as tarefas se acumulam porque a capacidade de execução é o limite, o modo fila separa os triggers recebidos dos processos worker que executam os workflows.

Planeje recursos para o processo main, PostgreSQL, Redis e cada worker. Os workers compartilham acesso ao banco e à chave de criptografia. Para filas com muitos arquivos, escolha armazenamento binário compartilhado compatível. Planejar modo fila e workers · Arquitetura oficial de fila.

INVISTA O ORÇAMENTO ONDE ELE AJUDA

Mais RAM, mais CPU ou mudar o workflow?

01 · MEMÓRIA

Para grandes conjuntos de dados em processamento

Verifique o uso de memória enquanto suas tarefas maiores se sobrepõem. Processe importações em lotes menores e retorne apenas os dados necessários para a próxima etapa.

Compre mais RAM quando a carga continuar ocupando toda a memória após essas mudanças.

02 · PROCESSAMENTO

Para transformações lentas

Compare o tempo de processamento local com o tempo gasto aguardando serviços externos. Uso contínuo de CPU durante processamento local indica necessidade de mais capacidade de computação.

Mantenha o nível atual de CPU quando a resposta de uma API ou o rate limit for o gargalo.

03 · ARMAZENAMENTO

Para histórico de execuções em crescimento

Escolha quais resultados de execução salvar e por quanto tempo. Inclua arquivos de workflows e crescimento do banco no orçamento de armazenamento.

Escolha um disco maior quando o histórico que precisa ser mantido ultrapassar o espaço disponível.

04 · TAREFAS PARALELAS

Para picos sobrepostos

Primeiro, distribua os horários das importações agendadas. Adicione workers quando tarefas pendentes indicarem limite de capacidade de execução e o banco e os recursos dos workers suportarem mais trabalho paralelo.

Escale os workers e seus recursos em conjunto.

Para o setup com Docker, um painel de hospedagem pago é opcional. Para chamadas de APIs de IA hospedadas, GPU local não é necessária. Reserve o orçamento para RAM, processamento, armazenamento e recuperação de que seu workflow realmente precisa.

Use docker stats, uso de disco do host e logs de execução para comparar o período de maior carga antes e depois de uma mudança. Medindo o desempenho do n8n · Controles de concorrência.

DÚVIDAS DE COMPRA RESPONDIDAS

VPS para n8n: perguntas frequentes

Qual configuração devo escolher para uma pequena empresa?

Escolha a configuração Standard com 2 vCPU, 4 GB RAM e 80 GB para um stack moderado de n8n e PostgreSQL que processe atualizações de CRM, leads e pequenas integrações baseadas em JSON. Use a opção maior para trabalhos intensivos em dados e muita sobreposição; use a opção mais leve para uma instância enxuta com tarefas pequenas e principalmente sequenciais.

Quando 8 GB de RAM é uma escolha melhor que 4 GB?

Quando seus workflows mantêm arquivos ou conjuntos de dados maiores na memória, fazem transformações mais pesadas ou executam várias tarefas exigentes juntas. Um alto número mensal de execuções, sozinho, não é motivo para dobrar a RAM; analise os dados em processamento e a sobreposição máxima.

Workflows de IA precisam de um VPS com GPU?

Chamar uma API de modelo hospedado usa o hardware de inferência do provedor do modelo. Escolha o VPS para n8n com base em orquestração, payloads e concorrência. Executar um modelo local ou serviço de inferência separado é outra decisão, com necessidades específicas de RAM e hardware.

O que acontece depois de escolher um VPS?

Selecione a configuração de servidor Standard e o sistema operacional Linux no catálogo de hospedagem. Faça o deploy do n8n com Docker, configure HTTPS e depois adicione as credenciais dos workflows. O caminho de deploy desta página é autogerenciado. Abrir a lista de instalação.

Posso mover meus workflows existentes para esta configuração?

Exporte e importe workflows, reconecte credenciais quando necessário e altere webhooks e triggers agendados de forma controlada. Para mover a instância completa, preserve o banco de dados e a chave de criptografia original para manter as credenciais salvas utilizáveis. Preparação para migração e recuperação.

Vou precisar de Redis ou de um painel de controle pago?

Um deploy Docker comum com uma única instância pode rodar sem Redis nem painel de hospedagem pago. Adicione Redis com modo fila quando precisar de execução baseada em workers; escolha um painel apenas se os recursos de gerenciamento forem úteis.

Como manter o custo do VPS para n8n baixo sem subdimensionar o servidor?

Comece com a menor configuração que acomode seus payloads reais e a sobreposição máxima e reduza a demanda evitável antes de fazer upgrade. Remova histórico de execuções desnecessário, processe grandes importações em lotes, distribua horários pesados e use APIs de IA hospedadas quando não precisar de inferência local. Meça memória, CPU e disco no período mais carregado; suba de nível quando a carga otimizada ainda atingir limites sustentados.
