Queue mode no n8n: quando usar Redis e workers

Queue mode separa o processamento com Redis e workers e deve responder a uma necessidade real de paralelismo.

Quando escalar

Não adote Redis e workers apenas por ter muitos workflows. Meça concorrência e saturação. Queue mode faz sentido quando a demanda paralela é sustentada e uma única instância deixa de atender com margem. Planeje Redis, workers, banco compartilhado e armazenamento binário compatível.

Decisões técnicas restantes

Planejar Queue Mode completo

1

Queue Mode usa PostgreSQL, Redis, processos main/webhook e workers; todos precisam do mesmo N8N_ENCRYPTION_KEY.

2

Main, webhook processors e workers devem rodar a mesma versão do n8n.

3

Meça concurrency, queue depth e latência; mais workers não corrigem banco ou API externa lenta.

4

Webhook processors são uma camada separada de escala; multi-main/HA não é o mesmo que Queue Mode comum.

FAQ

Planejar Queue Mode completo: FAQ

1 GB é um VPS real?

Sim. É um VPS de entrada real para carga leve; a limitação é a pequena margem de recursos.

Por que 2 GB é uma base mais segura?

Docker, sistema e pequenos picos ganham mais folga.

Por que medir antes de escalar?

CPU, RAM, disco e latência mostram o gargalo real.
