ఫైర్‌వాల్

అవసరమైన పరిపాలన మరియు వెబ్ పోర్ట్‌లను మాత్రమే బహిర్గతం చేయండి. PostgreSQL మరియు అంతర్గత అప్లికేషన్ సేవలను ప్రైవేట్‌గా ఉంచండి.

ఇప్పటికే వెబ్‌సైట్‌లను హోస్ట్ చేస్తున్న VPS లో ఇన్‌స్టాల్ చేస్తున్నారా? CPU, RAM మరియు నిల్వ అనుమతించినప్పుడు మీరు నియంత్రించే సర్వర్‌కు n8n ని జోడించవచ్చు. అయితే, Nginx, Apache, Caddy లేదా మరొక రివర్స్ ప్రాక్సీ ఇప్పటికే పోర్ట్‌లను కలిగి ఉంటే 80/443, చేయండి కాదు దిగువ ఉదాహరణ Caddy కంటైనర్‌ను మార్చకుండా ప్రారంభించండి: పోర్ట్‌లు వైరుధ్యంగా ఉంటాయి. బదులుగా, తగిన ప్రైవేట్ నెట్‌వర్కింగ్‌తో మీ ప్రస్తుత రివర్స్ ప్రాక్సీ ద్వారా కొత్త n8n సబ్‌డొమైన్‌ను రూట్ చేయండి లేదా ఖచ్చితమైన కంపోజ్ ఉదాహరణ కోసం క్లీన్ VPS ని ఉపయోగించండి. ఇతర సైట్‌లను మరియు వాటి TLS కాన్ఫిగరేషన్‌ను సంరక్షించండి; పోర్ట్‌లు 80/443 అందుబాటులో ఉన్నాయని ఉదాహరణ ఊహిస్తుంది.

రివర్స్ ప్రాక్సీపబ్లిక్ HTTPS ట్రాఫిక్‌ని అందుకుంటుంది మరియు దానిని n8n కి ఫార్వార్డ్ చేస్తుంది.
n8nనిరంతర అప్లికేషన్ డేటాతో ఎడిటర్, ట్రిగ్గర్‌లు మరియు వర్క్‌ఫ్లోలను అమలు చేస్తుంది.
PostgreSQLఉత్పత్తి విస్తరణ కోసం వర్క్‌ఫ్లో, క్రెడెన్షియల్ మరియు ఎగ్జిక్యూషన్ స్టేట్‌ను స్టోర్ చేస్తుంది.
నిరంతర వాల్యూమ్‌లుడిస్పోజబుల్ కంటైనర్‌ల వెలుపల అప్లికేషన్ మరియు డేటాబేస్ స్థితిని ఉంచండి.
పబ్లిక్ DNSVPS కి ఎడిటర్ మరియు వెబ్‌హుక్ ప్రొవైడర్లు ఉపయోగించిన హోస్ట్ పేరుని మ్యాప్ చేయండి.

ఉదాహరణ ఆధారంగా ఇన్‌స్టాలేషన్

Docker కంపోజ్‌తో మీ VPS లో n8n ని ఇన్‌స్టాల్ చేయండి

a పై n8n విస్తరణను రూపొందించడానికి ఈ ఉదాహరణను ఉపయోగించండి స్వీయ-నిర్వహణ Linux VPS. మీరు n8n ని మీరే ఇన్‌స్టాల్ చేసి నిర్వహించండి; మా భాగస్వామి ద్వారా సర్వర్‌ని ఎంచుకోవడంలో ముందుగా ఇన్‌స్టాల్ చేయబడిన n8n ఉదాహరణ ఉండదు. ఉదాహరణ ప్రైవేట్ కంపోజ్ నెట్‌వర్క్‌లో n8n, PostgreSQL, బాహ్య టాస్క్ రన్నర్ మరియు Caddy HTTPS ని మిళితం చేస్తుంది. ఇది కాన్ఫిగరేషన్ టెంప్లేట్, ప్రత్యక్ష-పరీక్షించిన విస్తరణ యొక్క దావా కాదు.

బదులుగా వేగవంతమైన తాజా ఇన్‌స్టాలేషన్ కావాలా? n8n అధికారిక వన్-లైన్ Docker సెటప్‌ను కూడా అందిస్తుంది. దీనితో మీరు దాని స్క్రిప్ట్‌ని డౌన్‌లోడ్ చేసుకోవచ్చు మరియు సమీక్షించవచ్చు curl -fsSL https://get.n8n.io -o get-n8n.sh నడుస్తున్న ముందు sh get-n8n.sh. ఆ ఎంపిక స్థానిక URL వద్ద SQLite తో ప్రారంభ ఉదాహరణను ప్రారంభిస్తుంది మరియు n8n అసిస్టెంట్ శాండ్‌బాక్స్ సేవలను కలిగి ఉంటుంది; అది అదే కాదు ఈ పబ్లిక్-HTTPS, PostgreSQL-మద్దతు గల VPS విస్తరణ. అధికారిక పూర్తి శాండ్‌బాక్స్ స్టాక్‌కు లీన్ n8n ఇన్‌స్టాలేషన్ కంటే ఎక్కువ RAM మరియు CPU అవసరం (దాని కంపోజ్ గైడ్ కనీసం 4 GB RAM / 2 vCPUలను నిర్దేశిస్తుంది). ఇంటర్నెట్ ఫేసింగ్ ఉత్పత్తి VPS కోసం, దిగువ మాన్యువల్‌గా కాన్ఫిగర్ చేసిన స్టాక్‌తో కొనసాగించండి.

1. Docker, DNS మరియు యాక్సెస్‌ని సిద్ధం చేయండి

సుడో యాక్సెస్‌తో SSH ని కనెక్ట్ చేయండి మరియు దీని కోసం DNS రికార్డ్‌ని సూచించండి n8n.example.com మీ VPS IPv4 చిరునామాకు. ఒక తాజా Ubuntu 22.04, 24.04 లేదా 26.04 VPS, కింది ఆదేశాలు Docker ఇంజిన్‌ను ఇన్‌స్టాల్ చేస్తాయి మరియు ఆధునికమైనవి docker compose Docker యొక్క అధికారిక సంతకం నుండి ప్లగిన్ apt రిపోజిటరీ:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

ఇది అధికారిక Docker Ubuntu ఇన్‌స్టాలేషన్ గైడ్‌లో ఉత్పత్తి-ఆధారిత రిపోజిటరీ పద్ధతి. VPS ఇప్పటికే నడుస్తున్న కంటైనర్‌లు లేదా ఇతర వెబ్‌సైట్‌లలో Docker ని గుడ్డిగా మళ్లీ ఇన్‌స్టాల్ చేయవద్దు లేదా తీసివేయవద్దు; ముందుగా ఇప్పటికే ఉన్న ఇన్‌స్టాలేషన్ మరియు సాధ్యమయ్యే ప్యాకేజీ వైరుధ్యాలను తనిఖీ చేయండి. డెబియన్ లేదా మరొక పంపిణీ కోసం, Ubuntu ఆదేశాలకు బదులుగా సంబంధిత అధికారిక OS-నిర్దిష్ట సూచనలను ఉపయోగించండి.

ఇప్పుడు Docker ని, కంపోజ్ ప్లగ్ఇన్, DNS మరియు వర్కింగ్ డైరెక్టరీని ధృవీకరించండి:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

ఉంటే getent hosts చిరునామా లేదా తప్పు చిరునామాను అందించదు, Caddy ని ప్రారంభించే ముందు మీ DNS ని సరి చేయండి; భర్తీ చేయండి n8n.example.com మీ నిజమైన హోస్ట్ పేరుతో ఈ గైడ్ అంతటా. Docker కి సాధారణంగా రూట్ అధికారాలు అవసరం: మీ SSH వినియోగదారు తర్వాత అమలు చేయలేకపోతే docker compose ఆదేశాలను నేరుగా, వాటితో ఉపసర్గ చేయండి sudo. వినియోగదారుని జోడించడం docker సమూహం రూట్-సమానమైన ప్రాప్యతను మంజూరు చేస్తుంది మరియు భాగస్వామ్య సర్వర్‌లో సాధారణం చేయకూడదు.

ఫైర్‌వాల్‌ని ఎనేబుల్ చేసే ముందు మీ వాస్తవ SSH అడ్మినిస్ట్రేషన్ పోర్ట్‌ను అందుబాటులో ఉంచుకోండి. సర్టిఫికేట్ జారీ మరియు ఎడిటర్ కోసం ఇన్‌బౌండ్ HTTP (80) మరియు HTTPS (443)ని అనుమతించండి. Docker-ప్రచురితమైన కంటైనర్ పోర్ట్‌లు కొన్ని UFW నియమాలను దాటవేయగలవు, కాబట్టి Docker యొక్క ఫైర్‌వాల్ మార్గదర్శకత్వాన్ని సమీక్షించండి మరియు ఉద్దేశించిన Caddy పోర్ట్‌లను మాత్రమే ప్రచురించండి. ఈ కంపోజ్ ఉదాహరణ ఉద్దేశపూర్వకంగా చేస్తుంది కాదు పబ్లిక్ ఇంటర్నెట్‌లో PostgreSQL (5432), n8n (5678) లేదా టాస్క్-రన్నర్ బ్రోకర్ (5679)ని ప్రచురించండి.

2. ఎన్విరాన్‌మెంట్ విలువలను సెట్ చేసి కీని భద్రపరచండి

అనే ఫైల్‌ను సృష్టించండి .env దిగువన ఉన్న టెంప్లేట్‌ని ఉపయోగించి, ప్రతిదాన్ని భర్తీ చేయండి REPLACE_WITH_RANDOM_HEX వేరే ఉత్పత్తి చేయబడిన విలువతో మరియు హోస్ట్ పేరు మరియు సమయ మండలిని మార్చండి. చూపినది 2.42.5 ట్యాగ్ ఉంది స్థిరమైన విడుదల 8 అక్టోబర్ 2026 న జాబితా చేయబడింది, ఇక్కడ డేటెడ్ కాన్ఫిగరేషన్ ఉదాహరణగా ఉపయోగించబడింది, ప్రత్యక్ష-పరీక్షించిన విస్తరణ లేదా భవిష్యత్తు భద్రతకు హామీ కాదు. ఇన్‌స్టాల్ చేసే ముందు, ప్రస్తుత అధికారిక n8n విడుదలలను తనిఖీ చేయండి, ఆపై n8n మరియు దాని టాస్క్-రన్నర్ చిత్రాన్ని అదే ధృవీకరించబడిన సంస్కరణలో ఉంచండి.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

ఎప్పుడూ కట్టుబడి ఉండకండి .env పబ్లిక్ రిపోజిటరీకి. గుప్తీకరణ కీ మరియు పునరుద్ధరణ సూచనలను VPS నుండి సురక్షితంగా నిల్వ చేయండి. కంటైనర్ రిక్రియేషన్ లేదా మైగ్రేషన్ తర్వాత కీ తప్పనిసరిగా అలాగే ఉండాలి.

3. తాజా ఇన్‌స్టాలేషన్ కోసం compose.yaml అని వ్రాయండి

అదే డైరెక్టరీలో, సృష్టించండి compose.yaml. ఉదాహరణ అధికారిక n8n పర్యావరణం-వేరియబుల్ సమావేశాలను మరియు PostgreSQL 18 ని ఉపయోగిస్తుంది PGDATA n8n హోస్టింగ్ ప్రాజెక్ట్ ద్వారా డాక్యుమెంట్ చేయబడిన మార్గం:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

నాలుగు సేవలు విభిన్న పాత్రలను కలిగి ఉన్నాయి: PostgreSQL డేటాబేస్ స్థితిని నిల్వ చేస్తుంది, n8n వర్క్‌ఫ్లోలను అమలు చేస్తుంది, n8n-runner సరిపోలే సంస్కరణ మరియు భాగస్వామ్య ప్రమాణీకరణ టోకెన్‌తో రన్నర్ టాస్క్‌లను అమలు చేస్తుంది మరియు Caddy పబ్లిక్ HTTPS ని నిర్వహిస్తుంది. ఒక బాహ్య టాస్క్ రన్నర్ Redis క్యూ మోడ్ కాదు. Caddy మాత్రమే హోస్ట్ పోర్ట్‌లను ప్రచురిస్తుంది. ఈ లీన్ ఇలస్ట్రేషన్ సెటప్ కోసం ఒకే డేటాబేస్ పాత్రను ఉపయోగిస్తుంది; PostgreSQL అధికారాల యొక్క బలమైన విభజన కోసం, అధికారిక n8n PostgreSQL విస్తరణ ఉదాహరణను సంప్రదించండి.

4. HTTPS Caddyfileని సృష్టించండి

ఫైల్‌ను సృష్టించండి Caddyfile (క్యాపిటల్ సి, పొడిగింపు లేదు) పాటు compose.yaml. ప్రతిచోటా ఉదాహరణ హోస్ట్ పేరును మీ స్వంత DNS పేరుతో భర్తీ చేయండి:

n8n.example.com {
    reverse_proxy n8n:5678
}

డొమైన్ సరిగ్గా పరిష్కరించబడినప్పుడు మరియు బాహ్య ట్రాఫిక్ పోర్ట్‌లను 80/443 కి చేరుకున్నప్పుడు Caddy పబ్లిక్ TLS సర్టిఫికెట్‌లను అభ్యర్థిస్తుంది మరియు పునరుద్ధరిస్తుంది. DNS ని సూచించవద్దు localhost. మీరు Caddy ని మరొక రివర్స్ ప్రాక్సీతో భర్తీ చేస్తే, అసలు హోస్ట్, ప్రోటోకాల్ మరియు క్లయింట్-అడ్రస్ హెడర్‌లను ఫార్వార్డ్ చేయండి మరియు సర్దుబాటు చేయండి N8N_PROXY_HOPS విశ్వసనీయ ప్రాక్సీ హాప్‌ల వాస్తవ సంఖ్య కోసం.

5. కంటైనర్లను ప్రారంభించండి మరియు బయటి నుండి పరీక్షించండి

సేవ్ చేసిన తర్వాత ప్రాజెక్ట్ డైరెక్టరీ నుండి ఈ ఆదేశాలను అమలు చేయండి .env, compose.yaml మరియు Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

చివరి ఆదేశం తనిఖీ చేస్తుంది పబ్లిక్ HTTPS ఆరోగ్య ముగింపు స్థానం. సర్టిఫికేట్ జారీ ఇంకా పెండింగ్‌లో ఉంటే, n8n విచ్ఛిన్నమైందని నిర్ధారించే ముందు Caddy లాగ్‌లు మరియు DNS/పోర్ట్‌లను తనిఖీ చేయండి. తెరవండి https://n8n.example.com, వెంటనే మొదటి యజమాని ఖాతాను సృష్టించండి మరియు తగిన సైన్-ఇన్ రక్షణలను ప్రారంభించండి. ఉదాహరణ వాస్తవానికి వర్క్‌ఫ్లోను అమలు చేస్తుందని నిర్ధారించండి, ఎడిటర్ లోడ్ చేయడమే కాదు:

  1. ఎడిటర్‌లో, aతో వర్క్‌ఫ్లో సృష్టించండి వెబ్‌హుక్ ట్రిగ్గర్. సెట్ HTTP పద్ధతి కు GET, ఎంచుకోండి Path vps-check, మరియు సెట్ ప్రతిస్పందించండి కు వెంటనే. వర్క్‌ఫ్లోను సేవ్ చేయండి.
  2. క్లిక్ చేయండి టెస్ట్ ఈవెంట్ కోసం వినండి, పూర్తి కాపీ చేయండి పరీక్ష URL n8n ద్వారా చూపబడింది మరియు మరొక పరికరం అమలు నుండి curl -i 'PASTE_TEST_URL_HERE' కాపీ చేసిన URLతో. n8n ఎడిటర్‌లో HTTP విజయ ప్రతిస్పందన మరియు ఇన్‌కమింగ్ ఈవెంట్ కనిపించాలని ఆశించండి. n8n ఈవెంట్‌ని వింటున్నప్పుడు మాత్రమే పరీక్ష URLలు పని చేస్తాయి.
  3. ప్రచురించండి వర్క్‌ఫ్లో, నోడ్‌ను దానికి మార్చండి ఉత్పత్తి URL, దాన్ని కాపీ చేసి రన్ చేయండి curl -i 'PASTE_PRODUCTION_URL_HERE' మళ్ళీ. వర్క్‌ఫ్లో కింద అమలును నిర్ధారించండి ఎగ్జిక్యూషన్లు ట్యాబ్. ఉత్పత్తి వెబ్‌హుక్ అభ్యర్థనలకు వర్క్‌ఫ్లో ప్రచురించబడాలి మరియు ఎడిటర్ పరీక్ష వీక్షణలో వాటి పేలోడ్‌ను చూపవద్దు.

ఇది ఉద్దేశపూర్వకంగా సరళమైన, ప్రమాణీకరించని పొగ పరీక్ష: దీనికి రహస్యాలను ఎప్పుడూ పంపవద్దు. నిజమైన డేటా కోసం పబ్లిక్ ఎండ్‌పాయింట్‌ని ఉపయోగించే ముందు దాన్ని పరీక్షించిన తర్వాత ప్రచురించడం/తొలగించడం లేదా Webhook ప్రమాణీకరణ/IP పరిమితులను కాన్ఫిగర్ చేయండి. అధికారిక Webhook పరీక్ష/ఉత్పత్తి డాక్యుమెంటేషన్ చూడండి.

6. పిన్ చేసిన సంస్కరణలను మార్చడానికి ముందు బ్యాకప్ చేయండి

రికవరీ చేయగల PostgreSQL డంప్‌ను సేవ్ చేయండి మరియు నిరంతర n8n డేటా వాల్యూమ్, .env/ఎన్‌క్రిప్షన్ కీ మరియు ఈ సర్వర్ వెలుపల నిల్వ చేయడానికి అవసరమైన బాహ్య ఫైల్‌లు. ఉపయోగించి పునరుద్ధరణను ధృవీకరించండి బ్యాకప్ మరియు రికవరీ గైడ్ ఉత్పత్తిని నవీకరించే ముందు. ఉదాహరణ ఆదేశాలు:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

పిన్ చేసిన వాటిని మార్చండి N8N_VERSION విడుదల గమనికలను చదివిన తర్వాత మాత్రమే; n8n మరియు రన్నర్ చిత్రాలు రెండూ కలిసి ముందుకు సాగాలి. పరిగెత్తవద్దు docker compose down -v సాధారణ నిర్వహణ సమయంలో పేరు పెట్టబడిన డేటా వాల్యూమ్‌లను తొలగిస్తుంది. PostgreSQL ప్రధాన-వెర్షన్ మార్పులకు డేటాబేస్ అప్‌గ్రేడ్ లేదా డంప్/పునరుద్ధరణ ప్రణాళిక అవసరం; Postgres 18 చిత్రాన్ని వేరే ప్రధాన ట్యాగ్‌తో భర్తీ చేయడం ఆటోమేటిక్ మైగ్రేషన్ కాదు.

అధికారిక సూచనలు: n8n Docker కంపోజ్ గైడ్, n8n రివర్స్-ప్రాక్సీ/వెబ్‌హూక్ కాన్ఫిగరేషన్ మరియు అధికారిక PostgreSQL డిప్లాయ్‌మెంట్ నోట్స్. ఇన్‌ఫ్రాస్ట్రక్చర్ బెంచ్‌మార్క్ లేదా ప్రొవైడర్-నిర్దిష్ట ప్రీఇన్‌స్టాల్ చేసిన ఫీచర్ ఏదీ ఊహించబడలేదు.
