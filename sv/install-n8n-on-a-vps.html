DOCKER INSTALLATION

Installera n8n på en VPS

Installera n8n på en VPS med Docker Compose och PostgreSQL. En produktionsdistribution behöver också bestående applikations- och databasdata, en stabil N8N_ENCRYPTION_KEY, ett offentligt värdnamn, HTTPS och korrekt webhook konfiguration. Kontrollera dessa bitar innan du aktiverar produktionsflöden.

Förkunskaper

Förbered VPS innan du börjar n8n

Linux VPS

Använd en bibehållen Linux-server som är dimensionerad för n8n, PostgreSQL, Docker och den omvända proxyn.

DNS

Placera en domän eller underdomain på VPS innan du utfärdar TLS certifikat och publicera webhook-adresser.

Docker Compose

Installera Docker Motor och komponera plugin med hjälp av stödpaket för operativsystemet.

Brandvägg

Exponera endast krävs administration och webbportar. Håll PostgreSQL och interna applikationstjänster privata.

Installera på en VPS som redan är värd för webbplatser? Du kan lägga till n8n till en server som du kontrollerar när CPU, RAM och lagring tillåter det. Men om Nginx, Apache, Caddy eller annan omvänd proxy redan äger hamnar 80/443, gör Inte inte starta exemplet Caddy behållare under oförändrad: hamnarna kommer att strida. Istället dirigerar du en ny n8n underdomän genom din befintliga omvända proxy med lämpliga privata nätverk eller använder en ren VPS för det exakta komponeringsexemplet. Bevara de andra platserna och deras konfiguration av TLS; exemplet förutsätter att hamnarna 80/443 är tillgängliga.

COPY-AND-ADAPT INSTALLATION

Installera n8n på din VPS med Docker Compose

Använd detta exempel för att bygga en n8n driftsättning på en Självhanterad Linux VPSDu installerar och upprätthåller n8n själv; välja en server genom vår partner inkluderar inte en förinstallerad n8n instans. Exemplet kombinerar n8n, PostgreSQL, en extern uppgiftslöpare och Caddy HTTPS i ett privat sammansatt nätverk. Det är en konfigurationsmall, Inte ett krav på en live-testad driftsättning.

Vill du ha den snabbaste färska installationen istället? n8n ger också en officiell en-linje Docker setup. Du kan ladda ner och granska skriptet med curl -fsSL https://get.n8n.io -o get-n8n.sh Innan du kör sh get-n8n.shDet alternativet startar ett första instans med SQLite på en lokal URL och inkluderar n8n Assistant sandbox-tjänster; det är Inte samma som denna offentlig- HTTPS, PostgreSQL-stödda VPS driftsättning. Den officiella fulla sandlåda stack behöver mer RAM och CPU än en lean n8n installation (dess Compose guide anger minst 4 GB RAM / 2 vCPU). För en internetansluten produktion VPS, fortsätt med den manuellt konfigurerade stacken nedan.

1. Förbered Docker, DNS och tillgång

Anslut över SSH med sudo access och peka en DNS A rekord för n8n.example.com till din VPS IPv4-adress. På en färsk Ubuntu 22.04, 24.04 eller 26.04 VPS, följande kommandon installerar Docker Motor och den moderna docker compose plugin från Docker s officiella undertecknade apt Repository:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Detta är den produktionsorienterade förvarsmetoden i den officiella installationsguiden Docker Ubuntu. Ominstallera eller ta bort Docker på en VPS som redan kör behållare eller andra webbplatserförst inspektera den befintliga installationen och eventuella paketkonflikter. För Debian eller annan distribution, använd motsvarande officiella OS-specifika instruktioner istället för Ubuntu kommandon.

Kontrollera själv Docker, Compose plugin, DNS och den arbetande katalogen:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Om getent hosts returnerar ingen adress eller fel adress, korrigera din DNS innan du börjar Caddy; ersätta n8n.example.com genom denna guide med ditt riktiga värdnamn. Docker kräver normalt rotprivilegier: om din SSH-användare inte kan köra den senare docker compose kommandon direkt, prefixa dem med sudoLägga till en användare till användaren docker gruppen ger root-ekvivalent tillgång och bör inte göras tillfälligt på en delad server.

Håll din faktiska SSH-administrationsport tillgänglig innan du aktiverar en brandvägg. Tillåt inkommande HTTP (80) och HTTPS (443) för utfärdande av certifikat och redaktör. Docker-publicerade containerhamnar kan kringgå vissa UFW-regler, så se över Docker s brandväggsvägledning och publicera endast de avsedda Caddy-portarna. Detta komponerar exempel medvetet gör Inte inte offentliggöra PostgreSQL (5432), n8n (5678) eller arbetsförmedlare (5679) till det allmänna internet.

2Skapa miljövärden och bevara nyckeln

Från projektkatalogen genererar tre olika slumpmässiga hexadecimalvärden med:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Skapa en fil som heter .env Använd mallen nedan, ersätt varje REPLACE_WITH_RANDOM_HEX med ett annat genererat värde och ändra värdnamn och tidszon. Den visade 2.42.5 tag är den stabil frisättning som anges på 8 oktober 2026, används här som ett daterat konfigurationsexempel, inte en garanti för en levande testad driftsättning eller framtida säkerhetInnan du installerar, kontrollera de nuvarande officiella n8n-utgåvorna, håll sedan n8n och dess uppgiftsbild på samma verifierade version.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Begå aldrig .env till ett offentligt förvar. Lagra krypteringsnyckeln och återställningsinstruktionerna säkert av VPS. Nyckeln måste vara densamma efter behållare rekreation eller migration.

3. Skriv compose.yaml för en ny installation

I samma katalog, skapa compose.yamlExemplet använder de officiella n8n miljövänliga konventionerna och PostgreSQL 18 PGDATA Väg dokumenterad av värdprojektet n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

De fyra tjänsterna har olika roller: PostgreSQL lagrar databasstat, n8n driver arbetsflöden, n8n-runner utför löparuppgifter med en matchande version och delad autentiseringstoken, och Caddy hanterar offentlig HTTPS. En extern Uppgift Runer är inte Redis köläge. Endast Caddy publicerar värdportar. Denna magra illustration använder en enda databasroll för inställning, för starkare separation av PostgreSQL privilegier, konsultera den officiella n8n PostgreSQL driftsättningsexemplet.

4. Skapa HTTPS Caddyfile

Skapa filen Caddyfile (kapital C, ingen förlängning) tillsammans compose.yamlErsätt exemplet värdnamn överallt med ditt eget DNS namn:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy Förfrågningar och förnyar offentliga TLS certifikat när domänen löser korrekt och extern trafik kan nå hamnarna 80/443. Peka inte DNS till localhostOm du ersätter Caddy med en annan omvänd proxy, vidarebefordra den ursprungliga värden, protokoll och klientadressrubriker och justera N8N_PROXY_HOPS för det faktiska antalet betrodda proxyhopp.

5. Starta behållarna och testa utifrån

Kör dessa kommandon från projektkatalogen efter att ha sparat .env, compose.yaml och Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Det sista kommandot kontrollerar offentlig HTTPS hälso endpoint. Om certifikatutfärdandet fortfarande är pågående, inspekterar Caddy loggar och DNS/port innan n8n bryts. Öppet Öppet Öppet https://n8n.example.comSkapa det första ägarkontot omedelbart och aktivera lämpliga inloggningsskydd. Bekräfta att instansen faktiskt utför ett arbetsflöde, inte bara att redaktören laddar:

  1. I redaktören, skapa ett arbetsflöde med ett Webhook trigger. Set HTTP Metod att GETVälj den Path vps-checkoch set Svara att OmedelbartSpara arbetsflödet.
  2. Klicka Lyssna på Test EventKopiera hela Testa URL visas av n8n och från en annan enhet som körs curl -i 'PASTE_TEST_URL_HERE' med den kopierade URL. Förvänta dig ett HTTP framgångssvar och den inkommande händelsen att visas i n8n redaktör. Testa webbadresser fungerar endast medan n8n lyssnar på händelsen.
  3. Publicera arbetsflödet, växla noden till dess ProduktionsURLKopiera den och spring curl -i 'PASTE_PRODUCTION_URL_HERE' igen. Bekräfta utförandet under arbetsflödet Avrättningar Tab. Produktions webhook-förfrågningar behöver arbetsflödet publiceras och visar inte sin nyttolast i redaktörens testvy.

Detta är ett medvetet enkelt, oautentiserat röktest: skicka aldrig hemligheter till det. Publicera / ta bort det efter testning eller konfigurera Webhook-autentisering / IP-restriktioner innan du använder en offentlig slutpunkt för riktiga data. Se den officiella Webhook test/produktion dokumentation.

6. Back up innan du ändrar stiftade versioner

Spara en återhämtningsbar PostgreSQL dumpa och den ihållande n8n datavolymen, .env/krypteringsnyckel och krävde externa filer för lagring utanför denna server. Verifiera en återställning med hjälp av backup och recovery guide före uppdatering av produktionen. Exempel kommandon:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Ändra pinned N8N_VERSION först efter att ha läst release noter; både n8n och löpare bilder måste gå vidare tillsammans. Kör inte docker compose down -v under rutinunderhåll eftersom det raderar namngivna datavolymer. PostgreSQL Omvandlingsändringar kräver en databasuppgradering eller dumpning/återställningsplan; att ersätta Postgres 18-bilden med en annan stor tagga är inte en automatisk migration.

Auktoritativa referenser: n8n Docker Compose guide, n8n omvänd proxy/webhook konfiguration, och officiella PostgreSQL distribueringsanteckningar. Ingen infrastruktur riktmärke eller leverantörsspecifik förinstallerad funktion antas.

Vanliga frågor

Installera n8n med Docker: gemensamma frågor

Behöver n8n PostgreSQL vid användning av Docker?

Docker kräver inte PostgreSQL, och små driftsättningar kan använda SQLite. För en produktionsorienterad VPS driftsättning ger PostgreSQL en starkare databasstiftelse och stöder senare köskala.

Varför hålla en ihållande n8n volym om PostgreSQL lagrar data?

Den ihållande katalogen n8n kan innehålla viktig instanstillstånd och konfiguration. Bevara den enligt distributionsdesignen istället för att anta databasen är den enda återställningstillgången.

Varför visar min webhook localhost?

Den interna containeradressen skiljer sig från det offentliga ursprunget. Konfigurera det externa värdnamnet, protokollet och webhook URL, och se till att den omvända proxy passerar de nödvändiga rubrikerna.

Ska hamn 5678 vara offentlig?

För en normal produktionsdriftsättning bakom en omvänd proxy, exponera HTTPS vid proxy och hålla n8n ansökningsporten intern om det inte finns en specifik operativ anledning att inte.

Behöver jag Redis?

Inte för en standard engångsinstans Docker driftsättning. Redis blir relevant när du medvetet flyttar till köläge och arbetstagare.

Är externa n8n uppgiftslöpare samma som kölägearbetare?

Nej. Externa aktivitetslöpare utför stödda uppgiftskod separat från n8n huvudprocessen och använder ett delat autentiseringstoken. Redis köläge distribuerar utförande av arbetsflöden och har egna infrastrukturkrav. Detta exempel visar en extern aktivitetslöpare, inte Redis köläge. Matcha runner-bildversionen till n8n-versionen.
