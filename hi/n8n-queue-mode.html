Queue mode कब उपयोग करें

Queue mode में main instance triggers/webhooks लेता है, Redis queue संभालता है और workers executions चलाते हैं। Shared PostgreSQL आवश्यक है।

Production में मुख्य बातें

जब optimized single instance पर backlog, webhook delay या concurrency bottleneck बना रहे। Workers की concurrency और DB connection pool साथ में size करें।

Production में मुख्य बातें

Queue mode में main और सभी workers को एक ही N8N_ENCRYPTION_KEY चाहिए। Redis, shared PostgreSQL, worker concurrency और database connection pool को साथ में plan करें।

मुख्य technical decisions

Queue Mode architecture पूरा करें

1

Queue Mode PostgreSQL, Redis, main/webhook processes और workers का उपयोग करता है; सभी workers में वही N8N_ENCRYPTION_KEY होना चाहिए।

2

Main, webhook processors और workers एक ही n8n version पर चलें।

3

Worker concurrency, queue depth और latency मापें; extra workers slow DB या external API को ठीक नहीं करते।

4

Webhook processors अलग scaling layer हैं; multi-main/HA सामान्य Queue Mode के समान नहीं है।
