EXECUTION LIMITS

Resource-based limit

Practical limit RAM, CPU, PostgreSQL, disk और architecture से तय होती है, न कि VPS provider के execution counter से।

Concurrency ज्यादा महत्वपूर्ण है

History भी resources लेती है

Execution history, logs और binary data disk और database I/O बढ़ाते हैं।

n8n license अलग विषय है

Community Edition और paid Business/Enterprise features अलग product levels हैं; VPS खरीदने से paid n8n features अपने-आप नहीं मिलते।

FAQ

n8n VPS के सामान्य सवाल

n8n के लिए कितनी RAM चाहिए?

हल्के workload के लिए 1–2 GB चल सकती है। n8n + PostgreSQL वाले छोटे production के लिए 4 GB practical baseline है। Heavy data और AI के लिए 8 GB+ रखें।

क्या n8n VPS पर preinstalled होगा?

यह page self-install scenario मानता है। अगर provider explicitly one-click n8n offer नहीं करता, तो Docker/Compose से install करना होगा।

क्या executions पर monthly limit होती है?

Ordinary VPS provider आमतौर पर execution count नहीं करता। Practical limit resources और architecture से तय होती है; n8n के paid editions की licensing अलग हो सकती है।

क्या domain जरूरी है?

Stable HTTPS URL और public webhooks के लिए domain या subdomain उपयोग करना बेहतर है।

क्या Redis जरूरी है?

Regular mode में नहीं। Redis queue mode और workers के लिए है।

क्या PostgreSQL और n8n एक ही VPS पर चल सकते हैं?

हाँ, छोटे production में 4 GB RAM और पर्याप्त disk के साथ यह practical है। Load बढ़ने पर database अलग किया जा सकता है।
