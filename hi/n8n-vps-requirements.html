कब resources बढ़ाने चाहिए

Testing: 1–2 vCPU / 2 GB. छोटा production: 2 vCPU / 4 GB. भारी workflows: 4+ vCPU / 8 GB+. 40–80 GB NVMe एक सामान्य शुरुआती range है, retention के अनुसार बढ़ाएँ।

Production में मुख्य बातें

OOM/restarts, swapping, लगातार high CPU/RAM, बढ़ती execution latency और backlog स्पष्ट संकेत हैं।

Production में मुख्य बातें

Minimum configuration को production guarantee न मानें। Docker + PostgreSQL + reverse proxy के लिए headroom रखें और real execution concurrency, payload तथा binary data देखकर size बढ़ाएँ।

मुख्य technical decisions

Production sizing पूरा करें

1

1 GB बहुत हल्के workload के लिए एक वास्तविक entry VPS है; 2 GB Docker और छोटे peaks के लिए अधिक headroom देता है।

2

Server size workflow count से नहीं, concurrent executions, payload size, duration और CPU-heavy nodes से तय करें।

3

PostgreSQL, reverse proxy, monitoring, logs और OS भी उसी RAM/CPU budget का हिस्सा हैं।

4

हल्के workload के लिए SSD पर्याप्त है; NVMe तब उपयोगी है जब PostgreSQL/history I/O मापा हुआ bottleneck बने।

FAQ

Production sizing पूरा करें: FAQ

क्या 1 GB वास्तविक VPS है?

हाँ। यह हल्के workload के लिए वास्तविक entry VPS है; सीमा केवल कम resource headroom है।

2 GB क्यों बेहतर light baseline है?

Docker, OS और छोटे peaks के लिए अधिक headroom मिलता है।

Scale से पहले measurement क्यों?

CPU, RAM, disk और latency वास्तविक bottleneck दिखाते हैं।
