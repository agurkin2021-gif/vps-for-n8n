COPY-AND-ADAPT इंस्टॉलेशन

अपने VPS पर Docker Compose से n8n install करें

इस example से n8n deployment बनाएँ एक self-managed Linux VPS. You install और maintain n8n yourself; choosing a server through our partner does नहीं include a preinstalled n8n instance. The example combines n8n, PostgreSQL, an external task runner और Caddy HTTPS in a private Compose network. It is a configuration template, नहीं a claim of a live-tested deployment.

इसके बजाय सबसे तेज fresh installation चाहिए? n8n official one-line Docker setup भी देता है। Script को download और review कर सकते हैं curl -fsSL https://get.n8n.io -o get-n8n.sh run करने से पहले sh get-n8n.sh. यह option local URL पर SQLite के साथ initial instance launch करता है और n8n Assistant sandbox services शामिल करता है; यह नहीं the same इस public-HTTPS, PostgreSQL-backed VPS deployment जैसा। Official full sandbox stack को lean n8n installation से अधिक RAM और CPU चाहिए (Compose guide कम से कम 4 GB RAM / 2 vCPUs बताती है)। Internet-facing production VPS के लिए नीचे manually configured stack के साथ आगे बढ़ें।

1. Docker, DNS और access तैयार करें

sudo access के साथ SSH से connect करें और DNS A record को n8n.example.com अपने VPS IPv4 address पर point करें। एक fresh Ubuntu 22.04, 24.04 या 26.04 VPS पर नीचे commands Docker Engine और modern docker compose plugin को Docker के official signed apt repository से install करते हैं:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Docker का signed apt repository register करें
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

यह official Docker Ubuntu installation guide की production-oriented repository method है। Do नहीं blindly reinstall or remove Docker on a VPS already running containers or other websites; first inspect the existing installation और possible package conflicts. For Debian or another distribution, use the corresponding official OS-specific instructions instead of Ubuntu commands.

अब Docker, Compose plugin, DNS और working directory verify करें:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

यदि getent hosts कोई address या गलत address return करे तो Caddy start करने से पहले DNS ठीक करें; n8n.example.com throughout this guide with your real hostname. Docker normally requires root privileges: if your SSH user canनहीं run the later docker compose commands सीधे नहीं चला सकता, उनके आगे sudoलगाएँ। User को docker group grants root-equivalent access और should नहीं be done casually on a shared server.

Firewall enable करने से पहले actual SSH administration port reachable रखें। Certificate issuance और editor के लिए inbound HTTP (80) तथा HTTPS (443) allow करें। Docker-published container ports कुछ UFW rules bypass कर सकते हैं, इसलिए Docker firewall guidance review करें और केवल intended Caddy ports publish करें। यह Compose example जानबूझकर नहीं PostgreSQL (5432), n8n (5678) या task-runner broker (5679) को public internet पर publish नहीं करता।

3. Fresh installation के लिए compose.yaml लिखें

उसी directory में बनाएँ compose.yaml। Example official n8n environment-variable conventions और PostgreSQL 18 PGDATA path उपयोग करता है, जिसे n8n hosting project document करता है:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

चार services की अलग roles हैं: PostgreSQL database state store करता है, n8n workflows चलाता है, n8n-runner matching version और shared authentication कोken के साथ runner tasks execute करता है, और Caddy public HTTPS संभालता है। External task runner is नहीं Redis queue mode. Only Caddy publishes host ports. This lean illustration uses a single database role for setup; for stronger separation of PostgreSQL privileges, consult the official n8n PostgreSQL deployment example.

4. HTTPS Caddyfile बनाएँ

File बनाएँ Caddyfile (capital C, कोई extension नहीं) साथ में compose.yaml. Example hostname को हर जगह अपने DNS name से replace करें:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy requests और renews public TLS certificates when the domain resolves correctly और external traffic can reach ports 80/443. Do नहीं point DNS को localhost. यदि you replace Caddy with another reverse proxy, forward the original host, protocol और client-address headers और adjust N8N_PROXY_HOPS को trusted proxy hops की actual संख्या के अनुसार adjust करें।

5. Containers start करें और बाहर से test करें

Project directory से commands चलाएँ, save करने के बाद .env, compose.yaml और Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

The last commऔर checks the public HTTPS health endpoint. यदि certificate issuance is still pending, inspect Caddy logs और DNS/ports before concluding n8n is broken. Open https://n8n.example.com, create the first owner account immediately और enable appropriate sign-in protections. Confirm that the instance actually executes a workflow, नहीं merely that the editor loads:

  1. Editor में workflow बनाएँ एक Webhook trigger के साथ। Set करें करें HTTP Method को GET, चुनें Path vps-check, और set Respond को Immediately. Workflow save करें।
  2. Click करें Listen for Test Eventऔर full Test URL shown by n8n, और from another device run curl -i 'PASTE_TEST_URL_HERE' with the copied URL. Expect an HTTP success response और the incoming event को appear in the n8n editor. Test URLs work only while n8n is listening for the event.
  3. Publish करें the workflow, switch the node को its Production URL, copy it और run curl -i 'PASTE_PRODUCTION_URL_HERE' फिर से। Workflow की Executions tab. Production webhook requests need the workflow को be published और do नहीं show their payload in the editor's test view.

This is a deliberately simple, unauthenticated smoke test: never send secrets को it. Unpublish/delete it after testing, or configure Webhook authentication/IP restrictions before using a public endpoint for real data. See the official Webhook test/production documentation.

6. Pinned versions बदलने से पहले backup लें

Recoverable PostgreSQL dump save करें और persistent n8n data volume, .env/encryption key और required external files को storage outside this server. Verify a restore using the backup और recovery guide production update करने से पहले। Example commands:

# Database, encryption key और instance data का backup लें,
# Pinned versions बदलने से पहले files का भी backup लें।
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# Backup को इस VPS से बाहर सुरक्षित रखने के बाद:
docker compose pull
docker compose up -d
docker compose ps

Pinned N8N_VERSION only after reading release नहींes; both n8n और runner images must advance कोgether. Do नहीं run docker compose down -v during routine maintenance because that deletes named data volumes. PostgreSQL major-version changes require a database upgrade or dump/restore plan; replacing the Postgres 18 image with a अलग major tag is नहीं an automatic migration.

FAQ

Docker से n8n install करना: आम सवाल

Docker के साथ n8n को PostgreSQL चाहिए?

Docker does नहीं require PostgreSQL, और small deployments can use SQLite. For a production-oriented VPS deployment, PostgreSQL provides a stronger database foundation और supports later queue-mode scaling.

PostgreSQL data store करता है तो persistent n8n volume क्यों रखें?

The persistent n8n directory can contain important instance state और configuration. Preserve it according को the deployment design instead of assuming the database is the only recovery asset.

Webhook localhost क्यों दिखाता है?

The internal container address differs from the public origin. Configure the external hostname, protocol और webhook URL, और ensure the reverse proxy passes the required headers.

क्या port 5678 public होना चाहिए?

For a normal production deployment behind a reverse proxy, expose HTTPS at the proxy और keep the n8n application port internal unless there is a specific operational reason नहीं को.

क्या Redis चाहिए?

Not for a standard single-instance Docker deployment. Redis becomes relevant when you deliberately move को queue mode और workers.

क्या external n8n task runners और queue-mode workers एक ही हैं?

No. External task runners execute supported task code separately from the n8n main process और use a shared authentication कोken. Redis queue mode distributes workflow executions और has its own infrastructure requirements. This example shows an external task runner, नहीं Redis queue mode. Match the runner image version को the n8n version.
