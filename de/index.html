EXECUTION LIMITS

Ressourcenlimit

Praktische Grenzen kommen von RAM, CPU, PostgreSQL, Disk I/O und Architektur.

Concurrency zählt

Viele leichte Workflows sind unproblematisch, solange sie nicht gleichzeitig laufen. Wenige schwere parallele Workflows können deutlich mehr Ressourcen benötigen.

Historie verbraucht Storage

Execution-Historie, Logs und Binärdaten erhöhen DB-Größe und I/O.

Lizenz ist separat

Community Edition und Business/Enterprise sind getrennte Produktstufen. Ein VPS schaltet keine kostenpflichtigen n8n-Funktionen frei.

FAQ

Häufige Fragen zu n8n auf VPS

Wie viel RAM braucht n8n?

1–2 GB können für Tests reichen. Für n8n + PostgreSQL in kleiner Produktion sind 4 GB eine praktischere Basis. Für AI und schwere Last eher 8 GB+.

Ist n8n vorinstalliert?

Auf dieser Seite wird Self-Install angenommen. Nur wenn ein Provider explizit 1-Klick/App-Image anbietet, ist n8n vorbereitet.

Gibt es ein monatliches Execution-Limit auf dem VPS?

Ein normaler VPS zählt n8n-Executions nicht. Das praktische Limit entsteht durch Ressourcen und Architektur.

Brauche ich eine Domain?

Für eine stabile HTTPS-URL und öffentliche Webhooks ist eine Domain oder Subdomain empfehlenswert.

Ist Redis Pflicht?

Nicht im normalen Modus. Redis wird für Queue Mode und Worker eingesetzt.

Können PostgreSQL und n8n auf demselben VPS laufen?

Ja, bei kleiner Produktion mit etwa 4 GB RAM und ausreichend Storage. Bei höherer Last kann die Datenbank getrennt werden.
