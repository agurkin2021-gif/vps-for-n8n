DECISION FACTORS

比較すべきポイント

Executions

Cloudは月間枠があります。Community self-hostedでは実用上の上限はCPU、RAM、DB、disk、architectureで決まります。

Concurrency

Cloudはplan limit。Self-hostedではvertical scaleやqueue modeを自分で設計します。

Data location

公式Cloudのdataは現在Frankfurtに保存。Self-hostedなら日本国内regionなど自分で選べます。

Custom environment

custom nodes、CLI、OS package、network設定はself-hostedの方が自由です。

Updates

Cloudはn8n側。VPSはupdate時期、backup、rollbackを自分で管理します。

Support

n8n product supportとVPS infrastructure supportは別です。workflow logicは通常ユーザー側の責任です。

Backup

Self-hostedはDB、persistent data、N8N_ENCRYPTION_KEYを別系統で保護します。

Security

Firewall、SSH、TLS、secret管理、patchingを誰が担当するかで運用コストが変わります。

SELF-HOSTED TCO

VPS料金だけで比較しない

当サイトのaffiliate optionでは2 CPU / 4 GB RAMが約$0.67/日ですが、実際のTCOにはoff-server backup、monitoring、更新、障害対応時間を加えます。

JAPAN CONTEXT

日本での判断ポイント

国内region

日本ユーザーや国内API中心ならself-hostedの国内VPSがlatency面で有利。

Cloudの保存場所

n8n Cloudは現在Frankfurt保存なので、data location要件がある場合は確認が必要です。

Local support

ConoHa/XServerなど国内VPSは日本語supportやlocal billingを選びやすい一方、n8n内部までsupportするとは限りません。

High execution volume

実行数が増えると固定費VPSが有利になる場合がありますが、運用責任を引き受ける必要があります。

MIGRATION

Cloudとself-hostedの移行で忘れやすいもの

Workflowsexport/import後にactivationとdependenciesを確認。
Credentials単純なworkflow exportだけではinstance全体は復元できません。
Webhookspublic URL変更時は外部service側のendpoint更新が必要な場合があります。
Rollback主要workflowを検証するまで旧環境を止めない。

FAQ

Cloud vs self-hostedのよくある質問

Self-hosted n8nは無料ですか？

Community Editionのsoftwareは無料ですが、VPS、backup、monitoring、管理時間は無料ではありません。

Self-hostedは実行回数無制限ですか？

Community Editionには通常のCloud型月間execution枠はありませんが、実際の上限はserver resourceとarchitectureです。有料self-hosted editionは別のcommercial条件があります。

初心者にはCloudが良いですか？

server管理を避けたい場合はCloudの方が簡単です。

後からVPSへ移行できますか？

可能ですが、workflowsだけでなくcredentials、webhook、domain、secret、rollbackを含めて計画します。
