ホスティング方式の選択

n8n Cloudとセルフホストの比較

マネージド ホスティング、サーバー メンテナンス不要、明確なプランベースの実行許可が必要な場合は、n8n Cloud を選択してください。ルート アクセス、プライベート ネットワーク、または独自のスケーリング アーキテクチャが必要で、サーバーを維持できる場合は、VPS 上のセルフホスト型 n8n を選択してください。どちらも実稼働ワークフローを実行できます。実際の比較は、総コスト、エディションの機能、セキュリティ、バックアップ、リカバリに対する責任です。

どちらも本番環境に対応可能

製品使用はどちらのモデルにも限定されるものではありません。決定するのは、管理されたインフラストラクチャが必要か、それとも自分で運用する準備ができているかです。

セルフホスティングの場合は、VPS、バックアップ、モニタリング、管理者の時間を含めます。クラウドの場合、ワークロードに適用できるプランと実行許容量を比較します。

ワークフローの実行頻度を確認

単純なスケジュールでクラウド実行枠を使用する方法

30 日の月を通して 5 分間のスケジュールで実行される 1 つのワークフローを考えてみましょう。スケジュールされた各実行が完了し、1 回の実行としてカウントされる場合、 12 1 時間あたりの実行 × 24 時間 × 30 日 = 8,640 の実行。これは、たとえ 1 つのワークフローであっても、2,500 実行スターターの許容量を超えています。クラウド上で、プランの現在のクォータと、n8n による実行のカウント方法を確認します。 VPS では、実行数を容量として扱うのではなく、実際のサーバーの負荷とリソースの使用状況を確認します。

計算を説明するためのものであり、パフォーマンスのベンチマークや使用量の予測ではありません。ポーリングではなく Webhook として実行した方がワークロードが安くなる可能性がありますが、実際の統合要件に基づいてトリガーを選択してください。公式の n8n クラウド許容量を確認します。

もう一つの運用方式

ワンクリックの n8n VPS は必ずしもマネージド サービスであるとは限りません

公式の n8n クラウドや独自の VPS の運用に加え、プレインストールまたは管理された n8n ホスティングを販売している会社もあります。これらは、サポート、バックアップ、ソフトウェア更新の責任が異なる個別の商用オファーです。ワンクリックのインストールではセットアップが簡素化されますが、プロバイダーが n8n アプリケーションを管理していることは証明されません。サードパーティのオファーを比較する場合は、正確なサービス契約、バックアップ保持、実行制限、ライセンスを確認してください。公式の n8n クラウドと自動的に同等になるわけではありません。

実際の費用モデル

例: セルフホスト型 n8n の月額料金は実際いくらですか?

たとえば、自己管理型の Standard VPS の価格は次のとおりです。 1日あたり$0.07 費用 30 の請求日数に対して $2.10 アドオンの前に。より大きな 1日あたり$0.67 オプション費用 30 の請求日数に対して $20.10。これらはサーバー料金であり、アプリケーション全体の費用ではありません。この例ではなく、実際のワークロードに応じてサーバー サイズを選択してください。

毎月のセルフホスティング TCO = VPS 料金 + 有料のバックアップ/ストレージ/モニタリング + 外部サービス + 管理者の時間。

イラスト: $20.10 VPS + $5 の選択された定期的な追加料金 + $20/時間相当の管理者の 2 時間 = その月の$65.10.

代替案: $2.10 VPS + 選択された有料追加サービスなし + 別途費用がかかる管理者の時間ゼロ = 直接サーバー料金の$2.10ただし、メンテナンスまたは回復の責任が免除されるわけではありません。

$5 の追加料金、2 時間、および $20/時間は仮説的な入力値であり、プロバイダーの見積もりや実際の作業負荷の予測ではありません。 $20/時間で、追加の管理時間ごとにセルフホスト TCO が$20 ずつ変化します。プロバイダーの請求書がないからといって、1 時間が無料であるとみなすことはできません。損益分岐点を見つけるには、実際に完了した実行、同時実行性、必要な機能をカバーするクラウド層と、VPS + 追加料金 + 時間を独自の料金で比較します。現在の Cloud の請求を確認します。有料の n8n セルフホスト エディションには別のライセンスが必要です。

運営

アップデート、セキュリティ パッチ、TLS、モニタリング、インシデント対応、復元テストには時間がかかります。その労働は比較に属する。

約定量

n8n Cloud では、個々のワークフロー ステップごとではなく、プランおよび月次の完了したワークフロー実行ごとに料金が請求されます。セルフホステッド Community Edition には、同じクラウド プランの実行割り当てが課されません。実効スループットは、コンピューティング、メモリ、データベースのパフォーマンス、および別途購入した n8n ライセンスに依存します。

失敗のコスト

テストされていないバックアップや不適切なアップグレードによってダウンタイムが長引く場合、安価な VPS は安くはありません。信頼性に関する作業はセルフホスティングの一部です。

管理権限とデータ

セルフホスティングによってアーキテクチャが変わる場所

プライベートシステム

セルフホスト型の展開は、プライベート データベース、内部 API、制限されたネットワークに直接アクセスできるインフラストラクチャ内に配置できます。

データの常駐性

セルフホスティングを使用すると、利用可能なサーバー リージョンを選択し、アプリケーション データベースを実行する場所を制御できます。これは、すべてのワークフロー データがそこに保持されることを保証するものではありません。外部 API、モデル プロバイダー、ログ、バックアップ先が他の場所でデータを処理する可能性があります。規制された使用のための完全なデータ フローを確認します。

カスタムサーバー構成

リバース プロキシ ルール、ファイアウォール ポリシー、ストレージ、データベース構成、環境変数、サポート サービスを制御します。

セキュリティの責任

コントロールは責任を移転します。 VPS では、SSH、TLS、ファイアウォール ルール、認証情報、データベースの公開、バックアップと更新を保護する必要があります。

VPS では、インフラストラクチャがオペレーティング モデルに属しているため、柔軟性が得られます。同じ自由とは、ユーザーに代わって黙ってボックスの世話をするマネージド プラットフォーム チームが存在しないことを意味します。

拡張性

クラウドの利便性とセルフホスト型のスケーリング制御

クラウド

マネージド サービスでは、インフラストラクチャのスケーリングに関するほとんどの決定をユーザーが行う必要がなくなります。選択したサービス層の機能と商用制限内で運用します。

単一の VPS

実際の同時実行性とペイロード動作に合わせてサイズを調整したサーバーから始めます。垂直方向のスケーリングは、通常、持続的な CPU または RAM の負荷に対する最も単純な最初の対応です。

キューモード

並列需要が分散実行アーキテクチャを正当化する場合、セルフホスティングにより Redis とワーカーを追加できます。これにより、容量と運用の複雑さが両方とも増加します。

データベースとストレージ

n8n のスケーリングは、アプリケーション CPU だけに焦点を当てるのではなく、PostgreSQL、実行保持、バイナリ データ、バックアップの増加を計画することも意味します。

シンプルだからという理由だけでクラウドを選択しないでください

プライベート ネットワーク アクセス、データの場所の要件、またはインフラストラクチャのカスタマイズが厳しい制約である場合、利便性ではそれらは解決されません。

エディションとライセンスの範囲

ホスティング モデルと n8n エディションは個別に決定します

n8nクラウド

クラウド層には、特定の実行許可、同時実行性、保持およびコラボレーション機能を備えたマネージド ホスティングがバンドルされています。公式の年間請求スターターの例には、月あたり 2,500 の実行と 5 の同時実行が含まれています。 Pro では、より多くの同時実行性とプロジェクト機能を備えた 10,000 実行/月をリストしています。正確なプランと契約期間が重要です。ピーク時の並列実行と毎月の完了した実行の両方をカバーする層を選択してください。公式のクラウド マトリックスを確認してください。

自己ホスト型コミュニティ

独自の VPS で n8n を実行すると、すべての有料機能がロック解除されるわけではありません。 Community Edition はコア ワークフローの自動化を提供しますが、有料のコラボレーション、ガバナンス、サポート、ソース管理、またはエンタープライズ機能を自動的に付与するわけではありません。チームのプランを選択する前に、正式版の機能マトリックスを確認してください。

セルフホスト型のビジネス/エンタープライズ

ライセンス キーにより、有料のセルフホスト機能のロックが解除されます。ソフトウェア エディションが有料の場合でも、インフラストラクチャは引き続き運用できます。

他のユーザーのために n8n をホスティングする

組織外のユーザーが、提供した n8n インスタンス上でワークフローを構築または構成できる場合、無料のセルフホステッド ライセンスがそのサービス モデルをカバーすると想定しないでください。 n8n をホスト型製品として提供する前に、n8n の現在のライセンス ルールを確認してください。

n8n クラウドとセルフホスト: よくある質問

n8n クラウドはセルフホスティングよりも優れていますか?

普遍的ではありません。管理されたインフラストラクチャと低い運用オーバーヘッドが意思決定の基準となる場合、クラウドの方が優れています。インフラストラクチャ制御とカスタム展開要件がスタックを自分で操作することが正当化される場合は、セルフホスティングの方が適しています。

セルフホスト型の n8n は安いですか?

生の VPS 料金はクラウド サブスクリプションよりもはるかに低くなる可能性がありますが、総コストが低いことは証明されません。バックアップ、監視、メンテナンス、管理者の時間、および有料版の機能を追加します。クラウドの現在の実行許容量とプラン制限と比較します。明示的な計算については、上記のコストの例を参照してください。

セルフホスト型 n8n は運用環境で実行できますか?

はい。実稼働の準備は、展開の品質に依存します。データベース、永続性、HTTPS、セキュリティ、監視、バックアップ、およびリカバリ手順がすべて重要です。

セルフホスト型 n8n には Redis が必要ですか?

いいえ、Redis はキュー モードと分散ワーカーに関連付けられています。通常の単一インスタンス VPS では、デフォルトでは Redis は必要ありません。

どのような場合に VPS を選択すればよいですか?

サーバー レベルの制御、プライベート ネットワーク、データの場所の制御、または自己管理のスケーリングが、更新、セキュリティ、監視、リカバリの所有を正当化するほど重要である場合は、VPS を選択してください。 VPS の価格だけでは、セルフホスティングの方が安いかどうかはわかりません。

n8n Cloud は何を実行としてカウントしますか?

n8n Cloud の料金は、1 回の実行内の個々のノードやステップではなく、完了したワークフローの実行に基づいています。必要なクラウド層の公開されている月間実行許容量と同時実行制限を比較します。

n8n クラウドからセルフホストに移行できますか?

長期運用

この展開は何年も信頼性を維持できますか?

公式の n8n クラウドも自己ホスト型 VPS も、特定のワークフローが 10 年間中断されずに実行されることを正確に保証することはできません。ビジネス クリティカルな自動化については、どのサービス条件とサポート コミットメントが適用されるか、インシデントがどのように検出されるか、誰がインスタンスを復元するか、デプロイメントまたはその外部 API が失敗した場合に何が起こるかを尋ねてください。

公式n8nクラウドの場合

サービス層の公開されているサポート条件、データ エクスポート機能、およびインシデント プロセスを確認します。管理されたインフラストラクチャによりサーバー管理が軽減されますが、ビジネスの成果や統合の失敗を監視する必要性がなくなるわけではありません。

セルフホスト型 VPS の場合

セキュリティ パッチ、監視、アップグレードの所有者を割り当てます。独立したバックアップを保持し、新しいホストで復元をテストします。サーバーの月々の低価格を信頼性の保証として扱うのではなく、VPS、ディスク、リージョン、またはサードパーティの統合が失敗した場合に回復する方法を検討してください。

可用性、サポート、および復旧の目標は、未検証の稼働時間の約束ではなく、文書化されたサービス条件と独自にテストされた手順に基づく必要があります。

移行の判断

n8n クラウドから独自の VPS に移行すると何が変わりますか?

ワークフローのエクスポートは完全な移行ではありません。クラウド インスタンスをオフにする前に、宛先を動作可能な状態にしてください。

導入環境のインベントリを作成する

アクティブおよびスケジュールされたワークフロー、資格情報、環境変数、統合シークレット、Webhook、およびデータ ストアを一覧表示します。どの機能が Community Edition ではなく Cloud プランに属しているかを特定します。

宛先を構築してテストする

永続ストレージ、HTTPS、および適切なデータベースを備えた保守済みの n8n リリースをデプロイします。各外部統合と認証情報を個別にテストします。エクスポートされたワークフロー JSON は、資格情報の移植性を保証しません。

カットオーバーを計画する

コールバック URL と外部 Webhook を意図的に再ポイントします。重複して実行すると副作用が生じる可能性がある場合は、スケジュールによってトリガーされる両方のコピーを並行して実行しないようにしてください。バックアップとロールバックを検証する時間を確保してください。

転送されないものを確認する

クラウド ユーザー、プロジェクト権限、実行履歴、インスタンス設定、または有料プランの機能が自動的に転送されると想定しないでください。クラウドをキャンセルする前に、必要なデータセットごとにエクスポートまたはサポートされている移行方法を確認してください。
