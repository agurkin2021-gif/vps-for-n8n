n8n VPS で何を探すべきか

作業データ用の RAM、ローカル処理用の CPU、保持する履歴とファイル用のストレージを優先します。 VPS を共有するデータベースとその他のアプリケーションを含めます。

実行履歴のストレージを見積もる

使用する 1 日あたりの保存された実行数 × 平均保存サイズ × 保存日数。例: 1,000 保存された実行数 × 200 KB × 14 日数は約です。 2.8 保存された実行データの GB、10 進単位を使用します。

データベースのインデックスとログ、OS、コンテナー、ワークフロー ファイル用のスペースを追加します。計算には、実際に観察された保存サイズを使用します。保持により、CPU や RAM を変更せずにストレージ需要を削減できます。実行データの設定。

記憶n8n (重複する実行によって保持されるデータベースとデータ) のための余地を残しておきます。大きなファイルや変換では、保存されたワークフローの数よりも要件が大きく変わります。
CPUローカル計算を継続するために、処理能力を追加購入してください。 CPU 割り当てとコア数を比較します。共有オファーと専用オファーは異なります。
ストレージSSD または NVMe ストレージを使用し、実際に保存するデータの容量を選択します。 VPS の喪失に耐えられるように、リカバリ コピーをサーバー外に置きます。
環境管理アクセスと Docker サポートを備えた Linux を選択してください。 Webhook とアプリケーション サービス間のプライベート ネットワークには、パブリック HTTPS ホスト名を使用します。
ネットワークと地域プロバイダーが複数のリージョンを提供している場合は、ラウンド トリップを支配するデータベース、API、またはユーザーの近くに VPS を配置します。ファイルを大量に使用するワークフローでは、帯域幅と転送ポリシーもリソース決定の一部になります。データの所在地にはリージョンが重要になる場合があります。
サポート境界チェックアウトする前に、プロバイダーが何をサポートしているかを確認してください。自己管理型 VPS では、アプリケーション レベルの管理が明示的に含まれていない限り、n8n の更新、構成、およびリカバリを所有するように計画してください。

n8n 用 VPS: よくある質問

中小企業にはどの構成を選択すべきですか?

CRM アップデート、リード、小規模な JSON ベースの統合を処理する控えめな n8n および PostgreSQL スタックには、2 vCPU、4 GB RAM、80 GB Standard 構成を選択します。データ量の多い作業や大幅な重複の場合は、より大きなオプションを使用してください。小規模でほとんどが順次ジョブを実行する無駄のないインスタンスには、軽量オプションを使用してください。

8 GB RAM が4 GB よりも適切な選択となるのはどのような場合ですか?

ワークフローがメモリ内に大きなファイルやデータセットを保持する場合、より重い変換を実行する場合、またはいくつかの要求の厳しいジョブを一緒に実行する場合。毎月の実行数が多いというだけでは、RAM を 2 倍にする理由にはなりません。作業データとピークの重複を調べます。

AI ワークフローには GPU VPS が必要ですか?

ホストされたモデル API を呼び出すと、モデル プロバイダーの推論ハードウェアが使用されます。オーケストレーション、ペイロード、同時実行のために n8n VPS を選択してください。ローカル モデルまたは別個の推論サービスを実行する場合は、モデル固有の RAM とハードウェアが必要になるため、別の購入が必要になります。

VPS を選択した後はどうなりますか?

ホスティング カタログで [標準サーバー構成] と [Linux オペレーティング システム] を選択します。 Docker を使用して n8n をデプロイし、HTTPS に接続して、ワークフローの資格情報を追加します。このページの展開パスは自己管理されます。 セットアップチェックリストを開く.

既存のワークフローをこの設定に移行できますか?

ワークフローをエクスポートおよびインポートし、必要に応じて認証情報を再接続し、Webhook とスケジュールされたトリガーを意図的に切り替えます。フルインスタンスの移動の場合は、データベースと元の暗号化キーを保存して、保存された資格情報を引き続き使用できるようにします。 移行とリカバリの準備.

Redis または有料のコントロール パネルが必要ですか?

通常の単一インスタンスの Docker デプロイメントは、Redis または有料のホスティング パネルなしで実行できます。ワーカーベースの実行が必要な場合は、キュー モードで Redis を追加します。パネルの管理機能が役立つ場合にのみパネルを選択してください。

サーバーのサイズを小さくせずに、n8n VPS のコストを低く抑えるにはどうすればよいですか?

実際のペイロードとピークのオーバーラップに適合する最小の構成から始めて、アップグレードする前に回避可能な需要を減らします。不要な実行履歴を削除し、大規模なインポートをバッチ処理し、重いスケジュールをずらして、ローカル推論が必要ない場合にはホストされた AI API を使用します。最も忙しい時間帯にメモリ、CPU、ディスクを測定します。最適化されたワークロードがまだ持続的な制限に達している場合は、階層を上げます。
