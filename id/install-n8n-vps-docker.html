INSTALASI DOCKER

Instal n8n di VPS

Instal n8n di VPS menggunakan Docker Compose dan PostgreSQL. Deployment produksi juga memerlukan aplikasi persisten dan data database yang stabil N8N_ENCRYPTION_KEY, hostname publik, HTTPS dan konfigurasi webhook yang benar. Verifikasi bagian-bagian ini sebelum mengaktifkan workflow produksi.

Pilih VPS untuk n8n

Tautan mitra: kami dapat memperoleh komisi dari pembelian.

PRASYARAT

Siapkan VPS sebelum menginstal n8n

Linux VPS

Gunakan server Linux yang dikelola dengan ukuran untuk n8n, PostgreSQL, Docker dan reverse proxy.

DNS

Arahkan domain atau subdomain ke VPS sebelum menerbitkan sertifikat TLS dan menerbitkan URL webhook.

Docker Compose

Instal Docker Engine dan plugin Compose menggunakan paket yang didukung untuk sistem operasi.

Firewall

Ekspos hanya administrasi dan port web yang diperlukan. Jaga kerahasiaan PostgreSQL dan layanan aplikasi internal.

Menginstal pada VPS yang sudah menghosting situs web? Anda dapat menambahkan n8n ke server yang Anda kontrol ketika CPU, RAM dan penyimpanan mengizinkannya. Namun, jika Nginx, Apache, Caddy atau reverse proxy lainnya sudah memiliki port 80/443, lakukan tidak mulai contoh container Caddy di bawah ini tanpa perubahan: port akan konflik. Sebagai gantinya, rutekan subdomain n8n baru melalui reverse proxy yang ada dengan jaringan pribadi yang sesuai, atau gunakan VPS yang bersih untuk contoh Compose yang tepat. Pertahankan situs lain dan konfigurasi TLS; contoh ini mengasumsikan bahwa port 80/443 tersedia.

INSTALASI SALINAN DAN ADAPTASI

Instal n8n di VPS Anda dengan Docker Compose

Gunakan contoh ini untuk membangun deployment n8n di a dikelola sendiri Linux VPS. Anda menginstal dan memelihara n8n sendiri; memilih server melalui mitra kami tidak menyertakan instance n8n yang sudah diinstal sebelumnya. Contoh ini menggabungkan n8n, PostgreSQL, task runner eksternal dan Caddy HTTPS di jaringan Compose pribadi. Ini adalah templat konfigurasi, bukan klaim deployment yang diuji langsung.

Ingin instalasi baru tercepat? n8n juga menyediakan pengaturan satu baris Docker resmi. Anda dapat mengunduh dan meninjau skripnya dengan curl -fsSL https://get.n8n.io -o get-n8n.sh sebelum berlari sh get-n8n.sh. Opsi tersebut meluncurkan instance awal dengan SQLite di URL lokal dan mencakup n8n layanan sandbox Asisten; dia tidak sama seperti deployment VPS dengan HTTPS publik dan PostgreSQL ini. Stack sandbox resmi lengkap memerlukan lebih banyak RAM dan CPU daripada instalasi n8n ringan (panduan Compose menetapkan setidaknya 4 GB RAM / 2 vCPUs). Untuk VPS produksi yang terhubung ke internet, lanjutkan dengan stack yang dikonfigurasi secara manual di bawah.

1. Siapkan Docker, DNS dan akses

Hubungkan melalui SSH dengan akses sudo dan arahkan a DNS Catatan untuk n8n.example.com ke alamat VPS IPv4 Anda. Pada a segar Ubuntu 22.04, 24.04 atau 26.04 VPS, perintah berikut menginstal Docker Engine dan modern docker compose plugin dari resmi Docker ditandatangani apt repositori:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Ini adalah metode repositori berorientasi produksi dalam panduan instalasi resmi Docker Ubuntu. Jangan menginstal ulang atau menghapus Docker secara membabi buta pada VPS container atau situs web lain yang sudah berjalan; pertama-tama periksa instalasi yang ada dan kemungkinan konflik paket. Untuk Debian atau distribusi lainnya, gunakan instruksi resmi khusus OS yang sesuai, bukan perintah Ubuntu.

Sekarang verifikasi Docker itu sendiri, plugin Compose, DNS dan direktori kerja:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Jika getent hosts tidak mengembalikan alamat atau alamat yang salah, perbaiki DNS Anda sebelum memulai Caddy; ganti n8n.example.com sepanjang panduan ini dengan hostname asli Anda. Docker biasanya memerlukan hak akses root: jika pengguna SSH Anda tidak dapat menjalankannya nanti docker compose perintah secara langsung, awali dengan sudo. Menambahkan pengguna ke docker grup memberikan akses yang setara dengan root dan tidak boleh dilakukan dengan santai di server bersama.

Jaga agar port administrasi SSH Anda yang sebenarnya dapat dijangkau sebelum mengaktifkan firewall. Izinkan masuk HTTP (80) dan HTTPS (443) untuk penerbitan sertifikat dan editor. Port container yang diterbitkan Docker dapat melewati beberapa aturan UFW, jadi tinjau panduan firewall Docker dan publikasikan hanya port Caddy yang dimaksud. Contoh Compose ini sengaja melakukannya tidak mempublikasikan PostgreSQL (5432), n8n (5678) atau broker pelaksana tugas (5679) ke internet publik.

2. Buat nilai environment dan simpan kuncinya

Dari direktori proyek, hasilkan tiga berbeda nilai heksadesimal acak dengan:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Buat file bernama .env menggunakan templat di bawah ini, ganti setiap REPLACE_WITH_RANDOM_HEX dengan nilai yang dihasilkan berbeda, dan ubah hostname dan zona waktu. Yang ditampilkan 2.42.5 tag adalah rilis stabil terdaftar pada 8 Oktober 2026, digunakan di sini sebagai contoh konfigurasi bertanggal, bukan jaminan deployment yang teruji langsung atau keamanan di masa depan. Sebelum menginstal, periksa rilis resmi n8n saat ini, lalu pertahankan n8n dan gambar task-runner-nya pada versi terverifikasi yang sama.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Jangan pernah berkomitmen .env ke repositori publik. Simpan kunci enkripsi dan instruksi pemulihan dengan aman di luar VPS. Kuncinya harus tetap sama setelah pembuatan ulang atau migrasi container.

3. Buat compose.yaml untuk instalasi baru

Di direktori yang sama, buat compose.yaml. Contoh ini menggunakan konvensi variabel lingkungan resmi n8n dan PostgreSQL 18 PGDATA jalur yang didokumentasikan oleh proyek hosting n8n:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Keempat layanan tersebut memiliki peran yang berbeda: PostgreSQL menyimpan status database, n8n menjalankan workflow, n8n-runner mengeksekusi tugas pelari dengan versi yang cocok dan token autentikasi bersama, dan Caddy menangani HTTPS publik. Eksternal pelari tugas bukan Queue Mode Redis. Hanya Caddy yang menerbitkan port host. Ilustrasi lean ini menggunakan peran database tunggal untuk pengaturan; untuk pemisahan hak istimewa PostgreSQL yang lebih kuat, lihat contoh deployment resmi n8n PostgreSQL.

4. Buat Caddyfile HTTPS

Buat filenya Caddyfile (huruf kapital C, tidak ada perpanjangan) di samping compose.yaml. Ganti contoh hostname di mana pun dengan nama DNS Anda sendiri:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy meminta dan memperbarui sertifikat TLS publik ketika domain diselesaikan dengan benar dan traffic eksternal dapat mencapai port 80/443. Jangan arahkan DNS ke localhost. Jika Anda mengganti Caddy dengan reverse proxy lainnya, teruskan host asli, protokol, dan header alamat klien, lalu sesuaikan N8N_PROXY_HOPS untuk jumlah sebenarnya dari lompatan proxy tepercaya.

5. Jalankan container dan uji dari luar

Jalankan perintah ini dari direktori proyek setelah menyimpan .env, compose.yaml dan Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Perintah terakhir memeriksa publik HTTPS endpoint kesehatan. Jika penerbitan sertifikat masih tertunda, periksa Caddy log dan DNS/ports sebelum menyimpulkan n8n rusak. Buka https://n8n.example.com, segera buat akun pemilik pertama dan aktifkan perlindungan masuk yang sesuai. Konfirmasikan bahwa instance benar-benar menjalankan workflow, bukan hanya editor yang memuat:

  1. Di editor, buat workflow dengan a webhook pemicu. Tetapkan HTTP Metode untuk GET, pilih Path vps-check, dan atur Tanggapi untuk Segera. Simpan workflow.
  2. Klik Dengarkan Acara Tes, salin selengkapnya URL pengujian ditunjukkan oleh n8n, dan dijalankan dari perangkat lain curl -i 'PASTE_TEST_URL_HERE' dengan URL yang disalin. Harapkan respons sukses HTTP dan acara masuk muncul di editor n8n. URL pengujian hanya berfungsi saat n8n mendengarkan acara tersebut.
  3. Publikasikan workflow, alihkan node ke workflownya URL Produksi, salin dan jalankan curl -i 'PASTE_PRODUCTION_URL_HERE' lagi. Konfirmasikan eksekusi berdasarkan workflow Eksekusi tab. Permintaan webhook produksi memerlukan workflow untuk dipublikasikan dan tidak menampilkan muatannya dalam tampilan pengujian editor.

Ini adalah tes asap yang sengaja dibuat sederhana dan tidak diautentikasi: jangan pernah mengirimkan secret ke dalamnya. Batalkan publikasi/hapus setelah pengujian, atau konfigurasikan autentikasi Webhook/pembatasan IP sebelum menggunakan endpoint publik untuk data nyata. Lihat dokumentasi pengujian/produksi Webhook resmi.

6. Backup sebelum mengubah versi yang dipin

Simpan dump PostgreSQL yang dapat dipulihkan dan volume data n8n yang persisten, .env/ kunci enkripsi dan file eksternal yang diperlukan untuk disimpan di luar server ini. Verifikasi pemulihan menggunakan panduan backup dan pemulihan sebelum memperbarui produksi. Contoh perintah:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Ubah yang disematkan N8N_VERSION hanya setelah membaca catatan rilis; baik gambar n8n maupun gambar pelari harus maju bersama-sama. Jangan lari docker compose down -v selama pemeliharaan rutin karena itu menghapus volume data bernama. PostgreSQL perubahan versi besar memerlukan upgrade basis data atau rencana pembuangan/pemulihan; mengganti gambar Postgres 18 dengan tag mayor yang berbeda bukanlah migrasi otomatis.

KEGAGALAN UMUM

Mengapa instalasi n8n Docker berfungsi secara lokal tetapi gagal dalam produksi

URL webhook salah

Callback menunjuk ke localhost, HTTP atau hostname internal dan bukan asal publik HTTPS.

Persistensi hilang

Kunci enkripsi hilang

VERIFIKASI PASCA PENYEDIAAN

Verifikasi kesehatan sebelum menghubungkan workflow nyata

Periksa status container

Jalankan docker compose ps dan memastikan aplikasi dan layanan database berjalan sesuai harapan sebelum menganggap deployment sebagai hal yang sehat.

Periksa health endpoint n8n

Dengan contoh Compose di atas, port 5678 tidak dipublikasikan pada host. Periksa endpoint publik dengan curl -fsS https://n8n.example.com/healthz setelah mengubah hostname, dan gunakan docker compose ps ditambah log layanan jika HTTPS atau database belum siap.

Pin versi aplikasi

Jangan menganggap pembaruan gambar mengambang yang belum ditinjau sebagai strategi pemeliharaan. Rekam versi n8n yang Anda jalankan, baca catatan rilis, dan buat backup sebelum mengubahnya.

Jangan menaikkan versi mayor PostgreSQL langsung di tempat

Mengubah hanya tag gambar utama Postgres dapat membuat direktori data yang ada menjadi tidak kompatibel. Cadangkan dan ikuti prosedur upgrade basis data alih-alih mengasumsikan pembuatan ulang container melakukan migrasi versi utama.

FAQ

Menginstal n8n dengan Docker: pertanyaan umum

Apakah n8n memerlukan PostgreSQL saat menggunakan Docker?

Docker tidak memerlukan PostgreSQL, dan deployment kecil dapat menggunakan SQLite. Untuk deployment VPS yang berorientasi produksi, PostgreSQL menyediakan fondasi database yang lebih kuat dan mendukung penskalaan Queue Mode selanjutnya.

Mengapa menyimpan volume n8n yang persisten jika PostgreSQL menyimpan data?

Direktori n8n yang persisten dapat berisi status dan konfigurasi instance penting. Pertahankan sesuai dengan desain deployment alih-alih berasumsi bahwa database adalah satu-satunya aset pemulihan.

Mengapa webhook saya menampilkan localhost?

Alamat penampung internal berbeda dengan alamat asal publik. Konfigurasikan hostname eksternal, protokol, dan URL webhook, dan pastikan reverse proxy melewati header yang diperlukan.

Haruskah port 5678 bersifat publik?

Untuk deployment produksi normal di belakang reverse proxy, ekspos HTTPS di proksi dan pertahankan port aplikasi n8n internal kecuali ada alasan operasional khusus untuk tidak melakukannya.

Apakah saya memerlukan Redis?

Bukan untuk deployment Docker instans tunggal standar. Redis menjadi relevan ketika Anda dengan sengaja berpindah ke Queue Mode dan worker.

Apakah pelari tugas n8n eksternal sama dengan worker Queue Mode?

Tidak. Pelari tugas eksternal menjalankan kode tugas yang didukung secara terpisah dari proses utama n8n dan menggunakan token autentikasi bersama. Redis Queue Mode mendistribusikan eksekusi workflow dan memiliki persyaratan infrastrukturnya sendiri. Contoh ini menunjukkan pelari tugas eksternal, bukan Queue Mode Redis. Cocokkan versi gambar pelari dengan versi n8n.
