KAPASITAS MINIMUM VS PRAKTIS

Apakah n8n memiliki satu ukuran minimum resmi VPS?

Tidak untuk setiap beban kerja. Contoh prasyarat resmi n8n menjelaskan penerapan OEM ilustratif dan secara eksplisit memperingatkan bahwa persyaratan bervariasi berdasarkan beban kerja. Dokumentasi tersebut bukan merupakan jaminan universal bahwa CPU, RAM atau alokasi disk tertentu akan mendukung otomatisasi produksi.

n8n mencatat bahwa instance yang menganggur mungkin menggunakan memori yang relatif sedikit, tetapi node Kode, muatan biner yang besar, atau eksekusi simultan dapat meningkatkan permintaan memori secara tajam. Anggaran secara terpisah untuk sistem operasi, Docker, PostgreSQL dan alat pencadangan/pemantauan.

Sumber teknis: prasyarat ilustratif n8n dan panduan memori resmi. Empat baris di atas adalah kumpulan sumber daya nyata yang dapat dibeli, bukan persyaratan resmi n8n yang ditentukan.

RAM & CPU

Yang sebenarnya menghabiskan sumber daya server

Eksekusi serentak

Beberapa alur kerja yang berjalan pada saat yang sama dapat menjadi lebih penting daripada jumlah total alur kerja yang disimpan di n8n. Perhatikan puncak memori dan latensi eksekusi selama tumpang tindih.

Ukuran muatan

Objek JSON besar, file, dan data biner meningkatkan tekanan memori. Beberapa eksekusi dengan banyak data mungkin memerlukan lebih banyak RAM daripada banyak otomatisasi ringan API.

CPU-simpul berat

Kode, transformasi, dan langkah-langkah komputasi berat lainnya dapat menciptakan tekanan CPU yang berkelanjutan. Lebih banyak inti membantu ketika eksekusi nyata bersaing untuk komputasi.

Layanan pendukung

Sistem operasi, PostgreSQL, reverse proxy, pemantauan dan Docker juga membutuhkan sumber daya. Ukur tumpukan lengkap, bukan hanya proses n8n.

UKUR SEBELUM ANDA MENINGKATKAN

Bagaimana cara mengetahui apakah n8n memerlukan lebih banyak RAM, CPU atau disk

Jalankan alur kerja terbesar yang diharapkan dan ledakan tumpang tindih yang realistis, lalu periksa server dan n8n log eksekusi. Jumlah alur kerja yang disimpan di editor bukanlah tolok ukur kapasitas yang berguna.

Memori / OOM

Periksa docker stats --no-stream dan free -h. Jika memori habis, pertama-tama kurangi JSON atau muatan biner, batch impor dalam jumlah besar, dan hindari langkah-langkah Kode yang membebani memori. Kesalahan tumpukan JavaScript belum tentu diperbaiki dengan menambahkan vCPU.

CPU / konkurensi

Ukur apakah CPU tetap sibuk selama transformasi atau pekerjaan hanya menunggu API eksternal. Dalam mode reguler, pertimbangkan batas konkurensi produksi yang didukung sebelum melakukan penskalaan ke pekerja. Meningkatkan CPU tidak mempercepat API yang dibatasi tarif eksternal.

Penyimpanan / basis data

Periksa df -h, ukuran database dan riwayat eksekusi yang disimpan. Perhatikan pertumbuhan disk dan operasi database yang lambat. Atur retensi dengan sengaja sebelum membayar untuk disk yang lebih besar; simpan salinan pemulihan di luar server.

Gunakan panduan konkurensi n8n dan penjelasan benchmarking resmi. Jumlah alur kerja bersamaan yang diiklankan tanpa mengetahui muatan dan latensi API hanyalah perkiraan.

DATABASE & PENYIMPANAN

SQLite, PostgreSQL dan data persisten

SQLite

SQLite dapat memuat penerapan dan pengujian instance tunggal berukuran kecil. Seiring dengan meningkatnya penggunaan produksi dan konkurensi, pilihan database menjadi kendala operasional dibandingkan detail instalasi.

PostgreSQL

Untuk tumpukan VPS yang berorientasi produksi, PostgreSQL menyediakan fondasi database yang lebih kuat. Anggaran RAM, CPU dan disk untuk database itu sendiri dan pantau pertumbuhannya.

Data .n8n yang persisten

Jangan perlakukan PostgreSQL sebagai satu-satunya aset yang persisten. Pertahankan direktori data n8n dan lindungi kunci enkripsi yang diperlukan untuk memulihkan kredensial terenkripsi.

Pertumbuhan disk

Riwayat eksekusi, data biner, file database, dan log dapat berkembang seiring waktu. Pengaturan retensi dan pencadangan di luar server secara langsung memengaruhi kapasitas yang diperlukan.

KAPASITAS DISK

Perkirakan n8n penyimpanan riwayat eksekusi sebelum memesan

Mulailah dengan eksekusi yang disimpan per hari × rata-rata byte yang disimpan per eksekusi × hari retensi. Misalnya, 500 eksekusi yang disimpan per hari × 200 KB setiap × 14 hari = 1.4 GB contoh data eksekusi sebelum overhead database. Asumsi 200 KB tersebut bersifat ilustratif, bukan patokan n8n.

Alokasikan juga disk untuk OS, lapisan gambar Docker, indeks basis data, file biner, log aplikasi, pemutakhiran, dan file sementara. Pencadangan di luar server memerlukan kapasitasnya sendiri. Disk 10 GB dapat berfungsi untuk tumpukan ramping tetapi memiliki lebih sedikit ruang untuk file yang disimpan dibandingkan disk 40 atau 80 GB.

n8n mendokumentasikan pemangkasan eksekusi default berdasarkan usia (336 jam / 14 hari) atau hitungan (10,000 eksekusi), dengan pengecualian. Periksa pengaturan Anda yang sebenarnya dan verifikasi apa yang dipertahankan sebelum mengubahnya. SQLite dapat menggunakan kembali ruang kosong daripada menyusutkan filenya secara otomatis.

Sumber: n8n: mengelola data eksekusi dan pemangkasan. Persyaratan disk bergantung pada ukuran muatan tersimpan yang diamati, bukan jumlah node saja.

Docker dan overhead produksi

Gunakan distribusi Linux yang dikelola dengan sumber daya yang cukup untuk sistem operasi dan pembaruan keamanan selain tumpukan aplikasi.

Docker & Menulis

Penerapan kontainer menyederhanakan pengulangan tetapi tidak menghilangkan overhead sumber daya. Pertahankan n8n dan database data di luar wadah sekali pakai.

KONKURENSI

Ketika VPS yang lebih besar berhenti menjadi jawaban keseluruhan

Penskalaan vertikal sesuai jika satu instance dapat menangani beban kerja dengan baik. Ketika permintaan paralel yang berkelanjutan menimbulkan perselisihan, evaluasi mode antrian dan pekerja. Mode antrian memperkenalkan Redis, PostgreSQL dan satu atau lebih proses pekerja; anggaran RAM dan CPU untuk setiap komponen, bukan hanya n8n. n8n juga mendokumentasikan pembatasan penyimpanan data biner sistem file dalam mode antrian, jadi validasi desain penyimpanan data yang kompatibel sebelum beralih.

TINGKAT MASUK & PENYIMPANAN I/O

Cara menggunakan entri 1 GB VPS

1 GB RAM

Ini adalah tingkat VPS yang benar-benar berfungsi, bukan produk uji coba saja. Ini cocok untuk otomatisasi kecil yang selalu aktif dan sebagian besar pekerjaan berurutan API saat Anda menyimpan memori, penggunaan disk, dan pekerjaan bersamaan dalam batas terukur. Ia menawarkan sedikit ruang kepala untuk PostgreSQL di server yang sama, muatan besar, atau eksekusi paralel yang berat.

2 GB RAM

Gunakan 2 GB sebagai garis dasar instans ringan yang lebih aman bila Anda menginginkan lebih banyak ruang untuk sistem operasi, Docker dan semburan kecil tanpa segera berpindah ke tumpukan berukuran produksi.

SSD vs NVMe

Standard SSD memadai untuk otomatisasi cahaya. NVMe menjadi lebih berguna ketika PostgreSQL dan riwayat eksekusi membuat seringnya membaca dan menulis atau ketika latensi disk muncul dalam performa alur kerja yang diukur.

Ukur sebelum meningkatkan

Gunakan CPU, memori, pertumbuhan disk, dan durasi eksekusi di bawah puncak yang tumpang tindih untuk memutuskan apakah hambatannya adalah komputasi, memori, atau penyimpanan, daripada berasumsi bahwa VPS yang lebih besar akan memperbaiki setiap perlambatan.

FAQ

n8n VPS persyaratan: pertanyaan umum

Berapa banyak RAM yang dibutuhkan n8n?

Tidak ada angka universal. RAM menuntut perubahan dengan konkurensi, ukuran muatan, perilaku eksekusi, dan layanan pendukung di VPS. Server 4 GB adalah kelas awal produksi kecil yang praktis, bukan persyaratan jaminan untuk setiap beban kerja.

Berapa banyak CPU inti yang harus saya gunakan?

Beban kerja ringan dapat dimulai dengan alokasi CPU yang kecil. Tambahkan inti ketika pemantauan menunjukkan tekanan CPU yang berkelanjutan atau eksekusi yang lebih lambat dalam konkurensi, bukan mengukur berdasarkan hitungan alur kerja saja.

Apakah n8n memerlukan PostgreSQL?

Penerapan kecil dapat menggunakan SQLite, tetapi PostgreSQL adalah pilihan berorientasi produksi yang lebih kuat seiring dengan meningkatnya persyaratan operasional dan konkurensi.

Kapan Redis diperlukan?

Redis dikaitkan dengan mode antrian. Penerapan instance tunggal normal tidak memerlukan Redis hanya karena dijalankan pada VPS.

Berapa banyak ruang disk yang harus saya pesan?

Permintaan disk bergantung pada pertumbuhan PostgreSQL, riwayat eksekusi yang dipertahankan, data biner, log, lapisan kontainer, dan cadangan. Pantau pertumbuhan dan tinggalkan ruang kepala daripada mengandalkan nomor universal yang tetap.

Bisakah saya menjalankan n8n terus menerus pada 1 GB VPS?

Ya, bila beban kerja sebenarnya sesuai. 1 GB VPS adalah server yang berfungsi nyata dan dapat mendukung otomatisasi kecil, sebagian besar berurutan, tetapi ruang memori terbatas. Hindari berasumsi bahwa tumpukan PostgreSQL server yang sama, pekerjaan biner-berat, atau beberapa eksekusi besar secara bersamaan akan cocok. Pantau konsumsi dan peningkatan berdasarkan tekanan sumber daya yang diamati.

Apakah 2 GB atau 4 GB RAM lebih baik untuk produksi n8n VPS?

Dua gigabyte memberikan lebih banyak ruang daripada contoh lean 1 GB, sedangkan 4 GB adalah kelas awal yang praktis untuk menilai n8n bersama dengan PostgreSQL dan HTTPS. Tidak ada jaminan minimum produksi yang universal: kompleksitas beban kerja, puncak yang tumpang tindih, konfigurasi kontainer, dan data yang disimpan menentukan permintaan sebenarnya.

Apakah alur kerja AI n8n memerlukan GPU?

Tidak jika n8n hanya memanggil model eksternal API: penyedia model menangani inferensi, sedangkan VPS menangani orkestrasi, muatan, dan konkurensi. Menjalankan model inferensi secara lokal merupakan keputusan perangkat keras terpisah yang mungkin memerlukan lebih banyak sumber daya RAM dan GPU yang sesuai.

Apa yang menyebabkan kesalahan kehabisan memori n8n?

Muatan JSON atau biner yang besar, operasi Kode yang memakan banyak memori, dan eksekusi yang tumpang tindih adalah penyebab umum. Periksa log runtime dan penggunaan memori puncak, lalu kurangi data yang disimpan dalam satu eksekusi atau alokasikan lebih banyak RAM berdasarkan masalah yang diukur.
