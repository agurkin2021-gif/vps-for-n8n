KOPIOI JA SOVITA ASENNUS

Asenna n8n VPS:lle Docker Composella

Rakenna tällä esimerkillä n8n-käyttöönotto itse ylläpidettävälle Linux-VPS:lle. Asennat ja ylläpidät n8n:n itse; palvelimen valinta kumppanimme kautta ei sisällä esiasennettua n8n-instanssia. Esimerkissä yhdistyvät n8n, PostgreSQL, ulkoinen tehtäväsuoritin ja Caddyn HTTPS yksityisessä Compose-verkossa. Kyseessä on määritysmalli, ei väite käytännössä testatusta käyttöönotosta.

Haluatko mahdollisimman nopean uuden asennuksen? n8n tarjoaa myös virallisen yhden komennon Docker-asennuksen. Voit ladata ja tarkistaa sen skriptin komennolla curl -fsSL https://get.n8n.io -o get-n8n.sh ennen komennon sh get-n8n.shsuorittamista. Tämä vaihtoehto käynnistää alkuinstanssin SQLite-tietokannalla paikalliseen URL-osoitteeseen ja sisältää n8n Assistantin eristetyn ympäristön palveluita. Se ei ole sama kuin tässä kuvattu julkista HTTPS:ää ja PostgreSQL:ää käyttävä VPS-asennus. Virallinen täysi eristetty ympäristö tarvitsee enemmän RAM-muistia ja CPU-tehoa kuin kevyt n8n-asennus (sen Compose-opas määrittää vähintään 4 GB RAM / 2 vCPU). Internetiin avattavaa tuotanto-VPS:ää varten jatka alla olevalla käsin määritettävällä kokonaisuudella.

1. Valmistele Docker, DNS ja käyttöoikeudet

Yhdistä SSH:lla sudo-oikeuksin ja osoita DNS:n A-tietue n8n.example.com VPS:si IPv4-osoitteeseen. Uudelle Ubuntu 22.04-, 24.04- tai 26.04- VPS:lle seuraavat komennot asentavat Docker Enginen ja nykyisen docker compose lisäosan Dockerin virallisesta allekirjoitetusta apt pakettivarastosta:

# Uusi Ubuntu 22.04 / 24.04 / 26.04 -asennus virallisista lähteistä
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Rekisteröi Dockerin allekirjoitettu apt-pakettivarasto
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Tämä on virallisen Dockerin Ubuntu-asennusoppaan tuotantokäyttöön tarkoitettu pakettivarastomenetelmä. Älä asenna Dockeria uudelleen tai poista sitä harkitsematta VPS:llä, jossa suoritetaan jo kontteja tai muita verkkosivustoja; tarkista ensin nykyinen asennus ja mahdolliset pakettiristiriidat. Käytä Debianissa tai muussa jakelussa vastaavia virallisia käyttöjärjestelmäkohtaisia ohjeita Ubuntu-komentojen sijaan.

Tarkista seuraavaksi Docker, Compose-lisäosa, DNS ja työhakemisto:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Jos getent hosts ei palauta osoitetta tai palauttaa väärän osoitteen, korjaa DNS ennen Caddyn käynnistämistä. Korvaa n8n.example.com kaikkialla oppaassa oikealla palvelinnimelläsi. Docker edellyttää tavallisesti pääkäyttäjän oikeuksia: jos SSH-käyttäjäsi ei voi suorittaa myöhempiä docker compose komentoja suoraan, lisää niiden eteen sudo. Käyttäjän lisääminen docker ryhmään myöntää käytännössä pääkäyttäjän oikeudet, joten sitä ei pidä tehdä kevyin perustein jaetulla palvelimella.

Pidä SSH-ylläpidon todellinen portti saavutettavissa ennen palomuurin käyttöönottoa. Salli sisääntuleva HTTP (80) ja HTTPS (443) varmenteiden myöntämistä ja editoria varten. Dockerin julkaisemat konttiportit voivat ohittaa joitakin UFW-sääntöjä, joten tarkista Dockerin palomuuriohjeet ja julkaise vain tarkoitetut Caddy-portit. Tässä Compose-esimerkissä ei julkaista PostgreSQL:ää (5432), n8n:ää (5678) eikä tehtäväsuorittimen välityspalvelua (5679) julkiseen internetiin.

2. Luo ympäristöarvot ja säilytä avain

Luo projektihakemistossa kolme erilaista satunnaista heksadesimaaliarvoa komennolla:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Luo tiedosto nimeltä .env käyttäen alla olevaa mallia. Korvaa jokainen REPLACE_WITH_RANDOM_HEX eri satunnaisarvolla ja muuta palvelinnimi sekä aikavyöhyke. Tässä esitetty 2.42.5-versiotunniste on 8. lokakuuta 2026 ilmoitettu vakaa julkaisu, jota käytetään tässä päivätyn kokoonpanoesimerkin pohjana, ei takeena käytännössä testatusta asennuksesta tai tulevasta tietoturvasta. Tarkista viralliset ajantasaiset n8n-julkaisut ennen asennusta ja pidä n8n:n sekä sen tehtäväsuorittimen levykuvat samassa varmennetussa versiossa.

# .env — korvaa kolme esimerkkisalaisuutta
# Kiinnitä ylläpidetty n8n-versio; käytä samaa versiota myös tehtäväsuorittimessa.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Älä koskaan tallenna .env julkiseen repositorioon. Säilytä salausavain ja palautusohjeet turvallisesti VPS:n ulkopuolella. Avaimen on pysyttävä samana kontin uudelleenluonnin tai siirron jälkeen.

3. Kirjoita compose.yaml uutta asennusta varten

Luo samaan hakemistoon tiedosto compose.yaml. Esimerkissä käytetään virallisia n8n-ympäristömuuttujakäytäntöjä ja PostgreSQL 18:n PGDATA polkua, joka on dokumentoitu n8n:n hosting-projektissa:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Neljällä palvelulla on eri tehtävät: PostgreSQL tallentaa tietokannan tilan, n8n suorittaa työnkulut, n8n-runner suorittaa tehtäviä vastaavalla versiolla ja jaetulla todennustunnuksella, ja Caddy hoitaa julkisen HTTPS-yhteyden. Ulkoinen tehtäväsuoritin ei ole sama kuin Redis-jonotila. Vain Caddy julkaisee palvelinkoneen portteja. Tässä kevyessä esimerkissä käytetään asennuksen yksinkertaistamiseksi yhtä tietokantaroolia; PostgreSQL-oikeuksien tarkempaa eriyttämistä varten katso n8n:n virallinen PostgreSQL-käyttöönottoesimerkki.

4. Luo HTTPS:n Caddyfile

Luo tiedosto Caddyfile (iso C-kirjain, ei tiedostopäätettä) tiedoston compose.yamlviereen. Korvaa esimerkin palvelinnimi kaikkialla omalla DNS-nimelläsi:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy pyytää ja uusii julkiset TLS-varmenteet, kun verkkotunnuksen DNS toimii ja ulkoinen liikenne pääsee portteihin 80/443. Älä osoita DNS:ää osoitteeseen localhost. Jos korvaat Caddyn toisella käänteisellä välityspalvelimella, välitä alkuperäisen palvelinnimen, protokollan ja asiakasosoitteen otsakkeet ja säädä N8N_PROXY_HOPS todellisten luotettujen välityspalvelinhyppyjen määrän mukaan.

5. Käynnistä kontit ja testaa ulkopuolelta

Suorita nämä komennot projektihakemistossa tallennettuasi tiedostot .env, compose.yaml ja Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Viimeinen komento tarkistaa julkisen HTTPS-palvelun terveystarkistuspisteen. Jos varmenteen myöntäminen on kesken, tarkista Caddyn lokit sekä DNS ja portit ennen kuin päättelet n8n:n olevan rikki. Avaa https://n8n.example.com, luo ensimmäinen omistajatili heti ja ota käyttöön asianmukainen kirjautumissuojaus. Varmista, että instanssi todella suorittaa työnkulun eikä pelkästään näytä editoria:

  1. Luo editorissa työnkulku, jonka käynnistimenä on Webhook . Aseta HTTP Method arvoksi GET, valitse Path vps-checkja aseta Respond arvoksi Immediately. Tallenna työnkulku.
  2. Napsauta Listen for Test Event, kopioi n8n:n näyttämä täydellinen Test URL ja suorita toiselta laitteelta komento curl -i 'PASTE_TEST_URL_HERE' kopioidulla URL-osoitteella. Odota onnistunutta HTTP-vastausta ja tarkista, että saapuva tapahtuma näkyy n8n-editorissa. Testi-URL toimii vain, kun n8n kuuntelee tapahtumaa.
  3. Julkaise työnkulku, vaihda solmun osoitteeksi Production URL, kopioi se ja suorita curl -i 'PASTE_PRODUCTION_URL_HERE' uudelleen. Varmista suoritus työnkulun Executions välilehdeltä. Tuotannon webhook-pyynnöt edellyttävät julkaistua työnkulkua, eivätkä ne näytä sisältöään editorin testinäkymässä.

Tämä on tarkoituksella yksinkertainen, todentamaton toimintatesti: älä koskaan lähetä siihen salaisuuksia. Peru sen julkaisu tai poista se testauksen jälkeen, tai määritä webhookin todennus/IP-rajoitukset ennen julkisen päätepisteen käyttöä oikeilla tiedoilla. Katso virallinen webhookien testi- ja tuotantodokumentaatio.

6. Varmuuskopioi ennen kiinnitettyjen versioiden muuttamista

Tallenna palautettavissa oleva PostgreSQL-varmuuskopio ja pysyvän n8n-datataltion sisältö, .env-tiedosto ja salausavain sekä tarvittavat ulkoiset tiedostot palvelimen ulkopuolelle. Testaa palautus varmuuskopiointi- ja palautusoppaan avulla ennen tuotannon päivittämistä. Esimerkkikomennot:

# Varmuuskopioi tietokanta, salausavain ja instanssin tiedot,
# sekä tiedostot ennen kiinnitettyjen versioiden muuttamista.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# Kun varmuuskopio on suojattu tämän VPS:n ulkopuolella:
docker compose pull
docker compose up -d
docker compose ps

Muuta kiinnitettyä N8N_VERSION versiota vasta julkaisutietoihin tutustumisen jälkeen. n8n:n ja tehtäväsuorittimen levykuvat on päivitettävä samaan aikaan. Älä suorita komentoa docker compose down -v rutiiniylläpidossa, sillä se poistaa nimetyt datataltiot. PostgreSQL:n pääversion muuttaminen edellyttää tietokannan päivitys- tai vienti- ja palautussuunnitelmaa; Postgres 18 -levykuvan korvaaminen toisen pääversion tunnisteella ei tee siirtoa automaattisesti.

Luotettavat lähteet: n8n:n Docker Compose -opas, käänteisen välityspalvelimen ja webhookien asetukset sekä PostgreSQL:n viralliset käyttöönotto-ohjeet. Infrastruktuurin suorituskykytestiä tai palveluntarjoajakohtaista esiasennettua ominaisuutta ei oleteta.

Tarkista konttien tila

Tarkista n8n:n terveyden tarkistuspiste

Yllä olevassa Compose-esimerkissä porttia 5678 ei julkaista palvelinkoneella. Tarkista julkinen päätepiste komennolla curl -fsS https://n8n.example.com/healthz palvelinnimen vaihtamisen jälkeen ja käytä docker compose ps sekä palvelulokeja, jos HTTPS tai tietokanta ei ole valmis.

Kiinnitä sovellusversiot

Älä vaihda PostgreSQL:n pääversiota suoraan

Pelkkä Postgresin pääversion levykuvatunnisteen muuttaminen voi tehdä nykyisestä datahakemistosta yhteensopimattoman. Varmuuskopioi ja noudata tietokannan päivitysohjeita sen sijaan, että olettaisit kontin uudelleenluonnin hoitavan pääversion siirron.

n8n:n asennus Dockerilla: usein kysytyt kysymykset

Tarvitseeko n8n PostgreSQL:n Dockeria käytettäessä?

Docker ei edellytä PostgreSQL:ää, ja pienet asennukset voivat käyttää SQLitea. Tuotantokäyttöön suunnitellussa VPS-asennuksessa PostgreSQL tarjoaa vahvemman tietokantapohjan ja tukee myöhempää jonotilan skaalausta.

Miksi n8n:lle tarvitaan pysyvä taltio, jos PostgreSQL tallentaa tiedot?

Pysyvässä n8n-kansiossa voi olla tärkeää instanssitilaa ja määrityksiä. Säilytä se käyttöönottomallin mukaisesti sen sijaan, että olettaisit tietokannan olevan ainoa palautettava osa.

Miksi webhookissani näkyy localhost?

Sisäinen konttiosoite eroaa julkisesta osoitteesta. Määritä ulkoinen palvelinnimi, protokolla ja webhook-osoite ja varmista, että käänteinen välityspalvelin välittää tarvittavat otsakkeet.

Pitääkö portin 5678 olla julkinen?

Tavallisessa tuotantokäyttöönotossa käänteisen välityspalvelimen takana julkaise HTTPS välityspalvelimessa ja pidä n8n:n sovellusportti sisäisenä, ellei poikkeamiseen ole erityistä toiminnallista syytä.

Tarvitsenko Redisin?

Et tavalliseen yhden instanssin Docker-käyttöönottoon. Redis tulee tarpeelliseksi, kun siirryt tarkoituksella jonotilaan ja työntekijäprosesseihin.

Ovatko ulkoiset n8n-tehtäväsuorittimet sama asia kuin jonotilan työntekijät?

Eivät. Ulkoiset tehtäväsuorittimet suorittavat tuettua tehtäväkoodia erillään n8n:n pääprosessista ja käyttävät yhteistä todennustunnusta. Redis-jonotila hajauttaa työnkulkujen suorituksia ja sillä on omat infrastruktuurivaatimuksensa. Tämä esimerkki näyttää ulkoisen tehtäväsuorittimen, ei Redis-jonotilaa. Pidä tehtäväsuorittimen levykuva samassa versiossa n8n:n kanssa.

Vertailetko palveluntarjoajia?

Palveluntarjoajan valintaan, yhden napsautuksen asennukseen, tuen rajauksiin, varmuuskopioihin, siirtoihin, alueisiin ja skaalaukseen löydät tietoa n8n:n parhaiden VPS-vaihtoehtojen vertailusta. Resurssien mitoitusta varten palaa n8n:n VPS-pääoppaaseen.
