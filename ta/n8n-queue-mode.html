n8n Queue Mode

Queue Mode என்பது ஒரு switch அல்ல; Redis, PostgreSQL, main process, workers, shared encryption key மற்றும் monitoring சேரும் distributed architecture.

SCALING INTENT

Queue Mode என்ன மாற்றுகிறது?

MainTriggers/timers மற்றும் execution coordination; heavy execution வேலை workers-க்கு அனுப்பப்படுகிறது.
RedisPending execution queue/message broker; workers மற்றும் main இதை share செய்கின்றன.
PostgreSQLExecution/workflow state persistence. Distributed queue architecture-ல் SQLite practical choice அல்ல.
WorkersActual executions process செய்கின்றன; workers எண்ணிக்கை/concurrency workload-க்கு ஏற்றபடி scale செய்யலாம்.
Encryption keyMain, workers மற்றும் webhook processors ஒரே N8N_ENCRYPTION_KEY பயன்படுத்த வேண்டும்.
Version parityMain/worker/webhook processes ஒரே n8n version-ல் இருக்க வேண்டும்.

“More workers” எல்லா bottleneck-ஐவும் தீர்க்காது

Database bottleneck

Slow PostgreSQL அல்லது disk I/O இருந்தால் workers அதிகரிப்பதால் contention கூடலாம்.

External API latency

Rate limits/slow APIs worker count அதிகரித்தாலும் upstream limit-ஐ மாற்றாது.

Webhook processors

Incoming webhook layer-ஐ தனியாக scale செய்யலாம்; main process-ஐ heavy webhook pool-ல் சேர்ப்பது அவசியமில்லை.

Queue depth

Pending executions, worker utilization மற்றும் execution latency ஒன்றாக measure செய்ய வேண்டும்.

Binary data

Current n8n queue-mode docs filesystem binary storage-க்கு வரம்பு காட்டுகின்றன; external/object storage architecture தேவைப்படலாம்.

HA boundary

Queue workers சேர்ப்பது மற்றும் full multi-main/high-availability architecture ஒன்றல்ல; edition/license feature boundaries-ஐ current n8n plan-ல் verify செய்யுங்கள்.

n8n Queue Mode — FAQ

Queue Mode-க்கு Redis வேண்டுமா?

ஆம், current n8n queue architecture Redis message broker-ஐ பயன்படுத்துகிறது.

Workers எல்லாம் same encryption key பயன்படுத்த வேண்டுமா?

ஆம். இல்லையெனில் stored credentials-ஐ workers decrypt செய்ய முடியாது.

SQLite-ஐ வைத்துக்கொண்டு queue mode ஓட்டலாமா?

Distributed queue deployment-க்கு PostgreSQL பயன்படுத்துவது current n8n guidance.

Webhook processors workers மாதிரியா?

இல்லை. Webhook processors incoming requests layer-ஐ scale செய்கின்றன; workers executions-ஐ process செய்கின்றன.
