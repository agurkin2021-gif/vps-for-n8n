Linux VPS

n8n, PostgreSQL, Docker மற்றும் ரிவர்ஸ் ப்ராக்ஸிக்கு பராமரிக்கப்படும் Linux சேவையகத்தைப் பயன்படுத்தவும்.

DNS

TLS சான்றிதழ்களை வழங்குவதற்கும் வெப்ஹூக் URLகளை வெளியிடுவதற்கும் முன் VPS இல் டொமைன் அல்லது துணை டொமைனைக் குறிக்கவும்.

Docker எழுது

Docker இன்ஜின் மற்றும் கம்போஸ் செருகுநிரலை இயக்க முறைமைக்கான ஆதரிக்கப்படும் தொகுப்புகளைப் பயன்படுத்தி நிறுவவும்.

ஃபயர்வால்

தேவையான நிர்வாகம் மற்றும் வலை துறைமுகங்களை மட்டும் வெளிப்படுத்தவும். PostgreSQL மற்றும் உள் பயன்பாட்டு சேவைகளை தனிப்பட்டதாக வைத்திருங்கள்.

ஏற்கனவே இணையதளங்களை ஹோஸ்ட் செய்யும் VPS இல் நிறுவுகிறீர்களா? CPU, RAM மற்றும் சேமிப்பகம் அனுமதிக்கும் போது நீங்கள் கட்டுப்படுத்தும் சர்வரில் n8n ஐச் சேர்க்கலாம். இருப்பினும், Nginx, Apache, Caddy அல்லது மற்றொரு தலைகீழ் ப்ராக்ஸி ஏற்கனவே போர்ட்களை 80/443 வைத்திருந்தால், செய்யுங்கள் இல்லை கீழே உள்ள உதாரண Caddy கொள்கலனை மாற்றாமல் தொடங்கவும்: துறைமுகங்கள் முரண்படும். அதற்கு பதிலாக, பொருத்தமான தனிப்பட்ட நெட்வொர்க்கிங் மூலம் உங்கள் தற்போதைய தலைகீழ் ப்ராக்ஸி மூலம் புதிய n8n துணை டொமைனை வழிநடத்தவும் அல்லது சரியான எழுது உதாரணத்திற்கு சுத்தமான VPS ஐப் பயன்படுத்தவும். மற்ற தளங்களையும் அவற்றின் TLS உள்ளமைவையும் பாதுகாத்தல்; எடுத்துக்காட்டு போர்ட்கள் 80/443 கிடைக்கின்றன என்று கருதுகிறது.

n8n க்கு Linux VPS ஐத் தேர்ந்தெடுக்கவும்

கூட்டாளர் இணைப்பு: வாங்குதல்களிலிருந்து நாங்கள் கமிஷனைப் பெறலாம்.

வரிசைப்படுத்தல் அடுக்கு

கட்டமைக்க வேண்டிய கூறுகள்

ரிவர்ஸ் ப்ராக்ஸிபொது HTTPS போக்குவரத்தைப் பெற்று அதை n8n க்கு அனுப்புகிறது.
n8nநிலையான பயன்பாட்டுத் தரவுகளுடன் எடிட்டரை இயக்குகிறது, தூண்டுகிறது மற்றும் பணிப்பாய்வுகள்.
PostgreSQLஉற்பத்தி வரிசைப்படுத்தலுக்கான பணிப்பாய்வு, நற்சான்றிதழ் மற்றும் செயல்படுத்தல் நிலை ஆகியவற்றை சேமிக்கிறது.
நிலையான தொகுதிகள்பயன்பாடு மற்றும் தரவுத்தள நிலையை செலவழிக்கக்கூடிய கொள்கலன்களுக்கு வெளியே வைத்திருங்கள்.
பொது DNSஎடிட்டர் மற்றும் வெப்ஹூக் வழங்குநர்கள் பயன்படுத்தும் ஹோஸ்ட்பெயரை VPS க்கு வரைபடமாக்குகிறது.

நகலெடு-மற்றும்-அடாப்ட் நிறுவல்

உங்கள் VPS இல் Docker கம்போஸ் உடன் n8n ஐ நிறுவவும்

ஒரு n8n வரிசைப்படுத்தலை உருவாக்க இந்த உதாரணத்தைப் பயன்படுத்தவும் சுய மேலாண்மை Linux VPS. நீங்களே n8n ஐ நிறுவி பராமரிக்கிறீர்கள்; எங்கள் கூட்டாளர் மூலம் ஒரு சேவையகத்தைத் தேர்ந்தெடுப்பதில் முன்பே நிறுவப்பட்ட n8n உதாரணம் இல்லை. உதாரணம் n8n, PostgreSQL, ஒரு வெளிப்புற டாஸ்க் ரன்னர் மற்றும் Caddy HTTPS ஆகியவற்றை ஒரு தனியார் கம்போஸ் நெட்வொர்க்கில் இணைக்கிறது. இது ஒரு கட்டமைப்பு டெம்ப்ளேட், நேரடி-சோதனை செய்யப்பட்ட வரிசைப்படுத்தலின் உரிமைகோரல் அல்ல.

அதற்கு பதிலாக வேகமான புதிய நிறுவல் வேண்டுமா? n8n அதிகாரப்பூர்வ ஒரு வரி Docker அமைப்பையும் வழங்குகிறது. நீங்கள் அதன் ஸ்கிரிப்டை பதிவிறக்கம் செய்து மதிப்பாய்வு செய்யலாம் curl -fsSL https://get.n8n.io -o get-n8n.sh ஓடுவதற்கு முன் sh get-n8n.sh. அந்த விருப்பம் உள்ளூர் URL இல் SQLite உடன் ஆரம்ப நிகழ்வைத் தொடங்குகிறது மற்றும் n8n உதவி சாண்ட்பாக்ஸ் சேவைகளை உள்ளடக்கியது; அது அதே அல்ல இந்த பொது-HTTPS, PostgreSQL-ஆதரவு VPS வரிசைப்படுத்தல். அதிகாரப்பூர்வ முழு சாண்ட்பாக்ஸ் அடுக்கிற்கு லீன் n8n நிறுவலை விட RAM மற்றும் CPU தேவை (அதன் கம்போஸ் வழிகாட்டி குறைந்தபட்சம் 4 GB RAM / 2 vCPUகளைக் குறிப்பிடுகிறது). இணையத்தை எதிர்கொள்ளும் தயாரிப்பு VPS க்கு, கீழே கைமுறையாக உள்ளமைக்கப்பட்ட அடுக்கைத் தொடரவும்.

1. Docker, DNS மற்றும் அணுகலை தயார் செய்யவும்

சூடோ அணுகலுடன் SSH க்கு மேல் இணைத்து, DNS ஒரு பதிவைக் குறிக்கவும் n8n.example.com உங்கள் VPS IPv4 முகவரிக்கு. அன்று ஒரு புதிய Ubuntu 22.04, 24.04 அல்லது 26.04 VPS, பின்வரும் கட்டளைகள் Docker இன்ஜின் மற்றும் நவீனத்தை நிறுவுகின்றன docker compose Docker இன் அதிகாரப்பூர்வ கையொப்பமிடப்பட்ட சொருகி apt களஞ்சியம்:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

இது அதிகாரப்பூர்வ Docker Ubuntu நிறுவல் வழிகாட்டியில் உள்ள உற்பத்தி சார்ந்த களஞ்சிய முறையாகும். VPS ஏற்கனவே இயங்கும் கொள்கலன்கள் அல்லது பிற இணையதளங்களில் Docker ஐ கண்மூடித்தனமாக மீண்டும் நிறுவவோ அல்லது அகற்றவோ வேண்டாம்; முதலில் இருக்கும் நிறுவல் மற்றும் சாத்தியமான தொகுப்பு முரண்பாடுகளை ஆய்வு செய்யவும். Debian அல்லது வேறு விநியோகத்திற்கு, Ubuntu கட்டளைகளுக்குப் பதிலாக தொடர்புடைய அதிகாரப்பூர்வ OS-சார்ந்த வழிமுறைகளைப் பயன்படுத்தவும்.

இப்போது Docker தானே, கம்போஸ் சொருகி, DNS மற்றும் வேலை செய்யும் கோப்பகத்தை சரிபார்க்கவும்:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

என்றால் getent hosts முகவரி இல்லை அல்லது தவறான முகவரியைத் தரவில்லை, Caddy ஐத் தொடங்குவதற்கு முன் உங்கள் DNS ஐத் திருத்தவும்; பதிலாக n8n.example.com உங்கள் உண்மையான ஹோஸ்ட்பெயருடன் இந்த வழிகாட்டி முழுவதும். Docker க்கு பொதுவாக ரூட் சிறப்புரிமைகள் தேவை: உங்கள் SSH பயனரால் பின்னர் இயக்க முடியவில்லை என்றால் docker compose கட்டளைகளை நேரடியாக, அவற்றை முன்னொட்டு sudo. ஒரு பயனரைச் சேர்க்கிறது docker குழு ரூட்-சமமான அணுகலை வழங்குகிறது மற்றும் பகிரப்பட்ட சேவையகத்தில் சாதாரணமாக செய்யக்கூடாது.

ஃபயர்வாலை இயக்கும் முன் உங்கள் உண்மையான SSH நிர்வாக போர்ட்டை அணுகக்கூடியதாக வைத்திருங்கள். சான்றிதழ் வழங்குதல் மற்றும் எடிட்டருக்கு உள்வரும் HTTP (80) மற்றும் HTTPS (443) ஆகியவற்றை அனுமதிக்கவும். Docker-வெளியிடப்பட்ட கொள்கலன் போர்ட்கள் சில UFW விதிகளைத் தவிர்க்கலாம், எனவே Docker இன் ஃபயர்வால் வழிகாட்டுதலை மதிப்பாய்வு செய்து, Caddy போர்ட்களை மட்டும் வெளியிடவும். இந்த கம்போஸ் உதாரணம் வேண்டுமென்றே செய்கிறது இல்லை பொது இணையத்தில் PostgreSQL (5432), n8n (5678) அல்லது டாஸ்க்-ரன்னர் தரகர் (5679) வெளியிடவும்.

2. சுற்றுச்சூழல் மதிப்புகளை உருவாக்கி, திறவுகோலைப் பாதுகாக்கவும்

திட்ட கோப்பகத்திலிருந்து, மூன்றை உருவாக்கவும் வேறுபட்டது இதனுடன் சீரற்ற ஹெக்ஸாடெசிமல் மதிப்புகள்:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

என்ற பெயரில் ஒரு கோப்பை உருவாக்கவும் .env கீழே உள்ள டெம்ப்ளேட்டைப் பயன்படுத்தி, ஒவ்வொன்றையும் மாற்றவும் REPLACE_WITH_RANDOM_HEX வேறு உருவாக்கப்பட்ட மதிப்புடன், ஹோஸ்ட்பெயர் மற்றும் நேர மண்டலத்தை மாற்றவும். காட்டப்பட்டது 2.42.5 குறிச்சொல் என்பது 8 அக்டோபர் 2026 இல் பட்டியலிடப்பட்ட நிலையான வெளியீடு, தேதியிடப்பட்ட உள்ளமைவு உதாரணமாக இங்கே பயன்படுத்தப்படுகிறது, நேரடி-சோதனை செய்யப்பட்ட வரிசைப்படுத்தல் அல்லது எதிர்கால பாதுகாப்பிற்கான உத்தரவாதம் அல்ல. நிறுவும் முன், தற்போதைய அதிகாரப்பூர்வ n8n வெளியீடுகளைச் சரிபார்த்து, n8n மற்றும் அதன் டாஸ்க்-ரன்னர் படத்தை அதே சரிபார்க்கப்பட்ட பதிப்பில் வைத்திருங்கள்.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

ஒருபோதும் உறுதியளிக்காதீர்கள் .env ஒரு பொது களஞ்சியத்திற்கு. குறியாக்க விசை மற்றும் மீட்பு வழிமுறைகளை VPS இல் பாதுகாப்பாக சேமிக்கவும். கொள்கலன் பொழுதுபோக்கு அல்லது இடம்பெயர்வுக்குப் பிறகு சாவி அப்படியே இருக்க வேண்டும்.

3. புதிய நிறுவலுக்கு compose.yaml என்று எழுதவும்

அதே கோப்பகத்தில், உருவாக்கவும் compose.yaml. எடுத்துக்காட்டு உத்தியோகபூர்வ n8n சூழல்-மாறி மரபுகள் மற்றும் PostgreSQL 18 ஆகியவற்றைப் பயன்படுத்துகிறது PGDATA n8n ஹோஸ்டிங் திட்டத்தால் ஆவணப்படுத்தப்பட்ட பாதை:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

நான்கு சேவைகளும் தனித்துவமான பாத்திரங்களைக் கொண்டுள்ளன: PostgreSQL தரவுத்தள நிலையைச் சேமிக்கிறது, n8n பணிப்பாய்வுகளை இயக்குகிறது, n8n-runner பொருந்தக்கூடிய பதிப்பு மற்றும் பகிரப்பட்ட அங்கீகார டோக்கனுடன் ரன்னர் பணிகளைச் செயல்படுத்துகிறது, மேலும் Caddy பொது HTTPS ஐக் கையாளுகிறது. ஒரு வெளி பணி ரன்னர் Redis வரிசை முறை அல்ல. Caddy மட்டுமே ஹோஸ்ட் போர்ட்களை வெளியிடுகிறது. இந்த ஒல்லியான விளக்கப்படம் அமைப்பதற்கு ஒரு தரவுத்தளப் பாத்திரத்தைப் பயன்படுத்துகிறது; PostgreSQL சிறப்புரிமைகளை வலுவாகப் பிரிக்க, அதிகாரப்பூர்வ n8n PostgreSQL வரிசைப்படுத்தல் உதாரணத்தைப் பார்க்கவும்.

4. HTTPS Caddyfile ஐ உருவாக்கவும்

கோப்பை உருவாக்கவும் Caddyfile (மூலதனம் சி, நீட்டிப்பு இல்லை) உடன் compose.yaml. எல்லா இடங்களிலும் எடுத்துக்காட்டு ஹோஸ்ட்பெயரை உங்கள் சொந்த DNS பெயருடன் மாற்றவும்:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy பொது TLS சான்றிதழைக் கோருகிறது மற்றும் டொமைன் சரியாகத் தீர்க்கப்படும் மற்றும் வெளிப்புற போக்குவரத்து போர்ட்களை 80/443 அடையும் போது புதுப்பிக்கிறது. DNS ஐ சுட்டிக்காட்ட வேண்டாம் localhost. நீங்கள் Caddy ஐ வேறொரு தலைகீழ் ப்ராக்ஸியுடன் மாற்றினால், அசல் ஹோஸ்ட், நெறிமுறை மற்றும் கிளையன்ட்-முகவரி தலைப்புகளை முன்னோக்கிச் சென்று சரிசெய்யவும் N8N_PROXY_HOPS நம்பகமான ப்ராக்ஸி ஹாப்களின் உண்மையான எண்ணிக்கைக்கு.

5. கொள்கலன்களைத் தொடங்கி வெளியில் இருந்து சோதிக்கவும்

சேமித்த பிறகு இந்த கட்டளைகளை திட்ட கோப்பகத்திலிருந்து இயக்கவும் .env, compose.yaml மற்றும் Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

கடைசி கட்டளை சரிபார்க்கிறது பொது HTTPS சுகாதார இறுதிப்புள்ளி. சான்றிதழ் வழங்கல் இன்னும் நிலுவையில் இருந்தால், Caddy பதிவுகள் மற்றும் DNS/போர்ட்களை பரிசோதிக்கவும், n8n உடைந்துவிட்டதாக முடிவடையும் முன். திற https://n8n.example.com, முதல் உரிமையாளர் கணக்கை உடனடியாக உருவாக்கி, பொருத்தமான உள்நுழைவு பாதுகாப்பை இயக்கவும். நிகழ்வு உண்மையில் ஒரு பணிப்பாய்வு செயல்படுத்துகிறது என்பதை உறுதிப்படுத்தவும், எடிட்டர் ஏற்றுவது மட்டுமல்ல:

  1. எடிட்டரில், ஒரு பணிப்பாய்வு ஒன்றை உருவாக்கவும் வெப்ஹூக் தூண்டுதல். அமைக்கவும் HTTP முறை செய்ய GET, தேர்வு செய்யவும் Path vps-check, மற்றும் அமைக்கவும் பதிலளிக்கவும் செய்ய உடனே. பணிப்பாய்வுகளைச் சேமிக்கவும்.
  2. கிளிக் செய்யவும் சோதனை நிகழ்வைக் கேளுங்கள், முழுவதையும் நகலெடுக்கவும் சோதனை URL n8n ஆல் காட்டப்பட்டது, மற்றும் மற்றொரு சாதனத்திலிருந்து இயக்கப்பட்டது curl -i 'PASTE_TEST_URL_HERE' நகலெடுக்கப்பட்ட URL உடன். n8n எடிட்டரில் HTTP வெற்றிப் பதிலையும் உள்வரும் நிகழ்வையும் எதிர்பார்க்கலாம். n8n நிகழ்வைக் கேட்கும் போது மட்டுமே சோதனை URLகள் செயல்படும்.
  3. வெளியிடு பணிப்பாய்வு, முனையை அதற்கு மாற்றவும் தயாரிப்பு URL, அதை நகலெடுத்து இயக்கவும் curl -i 'PASTE_PRODUCTION_URL_HERE' மீண்டும். பணிப்பாய்வுகளின் கீழ் செயல்படுத்துவதை உறுதிப்படுத்தவும் மரணதண்டனைகள் தாவல். தயாரிப்பு வெப்ஹூக் கோரிக்கைகளுக்கு பணிப்பாய்வு வெளியிடப்பட வேண்டும் மற்றும் எடிட்டரின் சோதனைக் காட்சியில் அவற்றின் பேலோடைக் காட்ட வேண்டாம்.

இது வேண்டுமென்றே எளிமையான, அங்கீகரிக்கப்படாத புகைப் பரிசோதனை: இதற்கு ஒருபோதும் ரகசியங்களை அனுப்ப வேண்டாம். சோதனைக்குப் பிறகு அதை வெளியிடுவதை நீக்கவும்/நீக்கவும் அதிகாரப்பூர்வ Webhook சோதனை/தயாரிப்பு ஆவணத்தைப் பார்க்கவும்.

6. பின் செய்யப்பட்ட பதிப்புகளை மாற்றும் முன் காப்புப் பிரதி எடுக்கவும்

மீட்டெடுக்கக்கூடிய PostgreSQL டம்பைச் சேமிக்கவும் மற்றும் நிலையான n8n தரவு அளவு, .env/குறியாக்க விசை மற்றும் இந்த சேவையகத்திற்கு வெளியே சேமிப்பகத்திற்கு தேவையான வெளிப்புற கோப்புகள். பயன்படுத்தி மீட்டமைப்பைச் சரிபார்க்கவும் காப்பு மற்றும் மீட்பு வழிகாட்டி உற்பத்தியைப் புதுப்பிக்கும் முன். எடுத்துக்காட்டு கட்டளைகள்:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

பின் செய்யப்பட்டதை மாற்றவும் N8N_VERSION வெளியீட்டு குறிப்புகளைப் படித்த பிறகு மட்டுமே; n8n மற்றும் ரன்னர் படங்கள் இரண்டும் ஒன்றாக முன்னேற வேண்டும். ஓடாதே docker compose down -v வழக்கமான பராமரிப்பின் போது அது பெயரிடப்பட்ட தரவு தொகுதிகளை நீக்குகிறது. PostgreSQL முக்கிய-பதிப்பு மாற்றங்களுக்கு தரவுத்தள மேம்படுத்தல் அல்லது டம்ப்/ரீஸ்டோர் திட்டம் தேவை; Postgres 18 படத்தை வேறு முக்கிய குறிச்சொல்லுடன் மாற்றுவது ஒரு தானியங்கி இடம்பெயர்வு அல்ல.

அதிகாரப்பூர்வ குறிப்புகள்: n8n Docker எழுதுதல் வழிகாட்டி, n8n தலைகீழ்-ப்ராக்ஸி/வெப்ஹூக் உள்ளமைவு மற்றும் அதிகாரப்பூர்வ PostgreSQL வரிசைப்படுத்தல் குறிப்புகள். உள்கட்டமைப்பு அளவுகோல் அல்லது வழங்குநர்-குறிப்பிட்ட முன் நிறுவப்பட்ட அம்சம் எதுவும் கருதப்படவில்லை.

கட்டமைப்பு

இரகசியங்கள் மற்றும் பொது URLகளை வேண்டுமென்றே அமைக்கவும்

குறியாக்க விசை

உற்பத்திச் சான்றுகளைச் சேமிப்பதற்கு முன் வலுவான n8n குறியாக்க விசையை அமைத்துப் பாதுகாக்கவும். மீட்புக்குப் பிறகு அதே விசை தேவைப்படுகிறது.
