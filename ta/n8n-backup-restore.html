n8n Backup & Restore

Backup என்பது file உருவானது என்று log காட்டுவது அல்ல. New server-ல் credentials decrypt ஆகி workflows சரியாக restore ஆகும் வரை recovery நிரூபிக்கப்படவில்லை.

RECOVERY INTENT

Workflow export மட்டும் முழு backup அல்ல

DatabaseWorkflows, executions, users/projects மற்றும் instance state-ன் பெரிய பகுதி database-ல் இருக்கலாம்.
N8N_ENCRYPTION_KEYCredentials-ஐ புதிய server-ல் decrypt செய்ய matching key recovery set-ல் இருக்க வேண்டும்.
.n8n / persistent dataInstance configuration மற்றும் local persistent files deployment-ஐ சார்ந்து தேவைப்படலாம்.
Binary dataFilesystem/object storage-ல் binary payloads இருந்தால் அவற்றின் recovery path தனியாக வேண்டும்.
Off-server copyஅதே VPS disk/snapshot மட்டும் வைத்தால் host-level failure-ல் backup-வும் இழக்கலாம்.
Restore drillBackup success log அல்ல, isolated environment-ல் உண்மையான restore தான் recovery confidence.

Restore போது மறக்கப்படும் operational details

Credentials

Encrypted credential export matching key இல்லாமல் புதிய instance-ல் usable ஆகாமல் போகலாம்.

Owner / projects

Import மட்டும் செய்து access ownership சரியாக வந்ததாக assume செய்யாதீர்கள்.

IDs / duplicates

Existing target instance-க்கு import செய்தால் IDs அல்லது records overwrite/duplicate risk இருக்கலாம்.

Activation state

Restored workflows automatically desired active/inactive state-ல் உள்ளனவா என்று சரிபார்க்கவும்.

RPO

எவ்வளவு data loss ஏற்றுக்கொள்ளலாம் என்பதை backup frequency தீர்மானிக்க வேண்டும்.

RTO

எவ்வளவு நேரத்தில் service மீள வேண்டும் என்பதை restore procedure மற்றும் automation தீர்மானிக்கும்.

1Database backup / supported export path
2N8N_ENCRYPTION_KEY secure copy

4Binary/object storage copy

6DNS/TLS cutover notes + restore test result

n8n Backup & Restore — FAQ

Workflow JSON export மட்டும் போதுமா?

இல்லை. Credentials, database state, encryption key, binary data மற்றும் instance settings separately தேவைப்படலாம்.

Snapshot போதுமா?

Fast rollback-க்கு உதவும்; ஆனால் off-server copy மற்றும் application-consistent restore test இல்லாமல் முழு recovery strategy அல்ல.

Backup எவ்வளவு அடிக்கடி?

உங்கள் RPO-ஐப் பொறுத்தது. ஒரு நாள் data loss ஏற்க முடியாவிட்டால் daily மட்டும் போதாது.

Restore test எப்போது?

Backup policy மாற்றும் போது, major upgrade முன் மற்றும் periodic disaster-recovery drill-ல் செய்ய வேண்டும்.
