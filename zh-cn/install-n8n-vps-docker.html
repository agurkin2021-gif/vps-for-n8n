复制并调整安装

使用 Docker Compose 在 VPS 上安装 n8n

使用此示例构建一个 n8n 部署在 自我管理 Linux VPS。您自行安装和维护 n8n；通过我们的合作伙伴选择的服务器不包括预安装的 n8n 实例。该示例在专用 Compose 网络中结合了 n8n、PostgreSQL、外部task runner和 Caddy HTTPS。它是一个配置模板， 并非现场测试部署的声明.

想要最快的全新安装吗？ n8n 还提供官方单行 Docker 设置。您可以下载并查看其脚本 curl -fsSL https://get.n8n.io -o get-n8n.sh 跑步前 sh get-n8n.sh。该选项在本地 URL 处启动带有 SQLite 的初始实例，并包括 n8n 助理沙箱服务；这是 不一样 作为此公共 HTTPS、PostgreSQL 支持的 VPS 部署。官方完整沙盒堆栈比精简的 n8n 安装需要更多的 RAM 和 CPU（其 Compose 指南指定至少 4 GB RAM / 2 vCPU）。对于面向互联网的生产 VPS，请继续使用下面的手动配置堆栈。

1.准备 Docker、DNS 并访问

通过 sudo 访问连接 SSH 并指向 DNS A 记录 n8n.example.com 到您的 VPS IPv4 地址。上一个 新鲜的 Ubuntu 22.04、24.04 或 26.04 VPS，以下命令安装 Docker 引擎和现代 docker compose 来自 Docker 官方签名的插件 apt 存储库：

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

这是官方 Docker Ubuntu 安装指南中面向生产的存储库方法。 不要在已运行的容器或其他网站上盲目地重新安装或删除 VPS Docker;首先检查现有的安装和可能的包冲突。对于 Debian 或其他发行版，请使用相应的官方操作系统特定指令而不是 Ubuntu 命令。

现在验证 Docker 本身、Compose 插件、DNS 和工作目录：

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

如果 getent hosts 未返回地址或地址错误，请在开始 Caddy 之前更正您的 DNS；替换 n8n.example.com 在本指南中使用您的真实主机名。 Docker 通常需要 root 权限：如果您的 SSH 用户无法运行后者 docker compose 直接命令，前缀为 sudo。将用户添加到 docker 组授予 root 等效访问权限，不应在共享服务器上随意执行。

在启用防火墙之前，请确保您的实际 SSH 管理端口可访问。允许入站 HTTP (80) 和 HTTPS (443) 进行证书颁发和编辑。 Docker-发布的容器端口可以绕过某些 UFW 规则，因此请查看 Docker 的防火墙指南并仅发布预期的 Caddy 端口。这个 Compose 示例故意这样做 不 将 PostgreSQL (5432)、n8n (5678) 或任务运行代理 (5679) 发布到公网。

2.创建环境值并保存密钥

从项目目录中，生成三个 不同的 随机十六进制值：

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

创建一个名为 .env 使用下面的模板，替换每个 REPLACE_WITH_RANDOM_HEX 使用不同的生成值，并更改主机名和时区。所示的 2.42.5 标签是 稳定版本于 10 月 8 2026 上市，此处用作过时的配置示例， 不能保证实时测试的部署或未来的安全性。安装之前，请检查当前的官方 n8n 版本，然后将 n8n 及其task runner 镜像保留在同一经过验证的版本上。

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

从不承诺 .env 到公共存储库。将加密密钥和恢复指令安全地存储在 VPS 之外。在容器重新创建或迁移后，密钥必须保持不变。

3.为全新安装编写 compose.yaml

在同一目录下创建 compose.yaml。该示例使用官方的 n8n 环境变量约定和 PostgreSQL 18 PGDATA n8n 托管项目记录的路径：

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

这四个服务具有不同的角色：PostgreSQL 存储数据库状态，n8n 运行工作流程， n8n-runner 使用匹配版本和共享身份验证令牌执行运行器任务，Caddy 处理公共 HTTPS。一个外部 任务运行者 不是 Redis 队列模式。仅 Caddy 发布主机端口。此精益插图使用单个数据库角色进行设置；要加强 PostgreSQL 权限的分离，请参阅官方 n8n PostgreSQL 部署示例。

4.创建 HTTPS Caddyfile

创建文件 Caddyfile （大写 C，无扩展名）旁边 compose.yaml。将示例主机名替换为您自己的 DNS 名称：

n8n.example.com {
    reverse_proxy n8n:5678
}

当域正确解析并且外部流量可以到达端口 80/443 时，Caddy 请求并续订公共 TLS 证书。不要将 DNS 指向 localhost。如果将 Caddy 替换为另一个反向代理，则转发原始主机、协议和客户端地址标头并调整 N8N_PROXY_HOPS 为可信代理跃点的实际数量。

5.启动容器并从外部进行测试

保存后从项目目录运行这些命令 .env, compose.yaml 和 Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

最后一个命令检查 公共 HTTPS 健康检查端点。如果证书颁发仍在等待中，请在得出 n8n 已损坏的结论之前检查 Caddy 日志和 DNS/端口。打开 https://n8n.example.com，立即创建第一个所有者帐户并启用适当的登录保护。确认实例实际执行工作流，而不仅仅是编辑器加载：

  1. 在编辑器中，创建一个工作流程 Webhook 触发。套装 HTTP 方法 到 GET，选择 Path vps-check，并设置 回应 到 立即。保存工作流程。
  2. 点击 监听测试事件，复制完整的 测试网址 由 n8n 显示，并从另一台设备运行 curl -i 'PASTE_TEST_URL_HERE' 与复制的 URL。预计 HTTP 成功响应和传入事件将出现在 n8n 编辑器中。测试 URL 仅在 n8n 侦听事件时有效。
  3. 发布 工作流程，将节点切换到其 生产网址，复制并运行 curl -i 'PASTE_PRODUCTION_URL_HERE' 再次。确认工作流程下的执行 处决 选项卡。生产 Webhook 请求需要发布工作流程，并且不会在编辑器的测试视图中显示其负载。

这是一个故意简单的、未经身份验证的冒烟测试：永远不要向它发送秘密。测试后取消发布/删除它，或者在使用公共端点获取真实数据之前配置 Webhook 身份验证/IP 限制。请参阅官方 Webhook 测试/生产文档。

6.更改固定版本之前进行备份

保存可恢复的 PostgreSQL 转储 和 持久的 n8n 数据量， .env/加密密钥和需要存储在该服务器外部的外部文件。使用以下命令验证恢复 备份和恢复指南 在更新生产之前。命令示例：

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

更改固定的 N8N_VERSION 仅在阅读发行说明后； n8n 和跑步者图像必须一起前进。 不要跑 docker compose down -v 在日常维护期间，因为这会删除命名数据卷。 PostgreSQL 主要版本更改需要数据库升级或转储/恢复计划；用不同的主要标签替换 Postgres 18 映像并不是自动迁移。

权威参考：n8n Docker Compose 指南、n8n 反向代理/Webhook 配置以及官方 PostgreSQL 部署说明。不假定任何基础设施基准或特定于提供商的预安装功能。

常见问题

将 n8n 与 Docker 一起安装：常见问题

使用 Docker 时 n8n 是否需要 PostgreSQL？

Docker 不需要 PostgreSQL，小型部署可以使用 SQLite。对于面向生产的 VPS 部署，PostgreSQL 提供了更强大的数据库基础并支持以后的队列模式扩展。

如果 PostgreSQL 存储数据，为什么还要保留持久的 n8n 卷？

持久性 n8n 目录可以包含重要的实例状态和配置。根据部署设计保留它，而不是假设数据库是唯一的恢复资产。

为什么我的 webhook 显示 localhost？

内部容器地址与公共来源不同。配置外部主机名、协议和 Webhook URL，并确保反向代理传递所需的标头。

端口 5678 应该是公共的吗？

对于反向代理后面的正常生产部署，请在代理处公开 HTTPS，并将 n8n 应用程序端口保留在内部，除非有特定的操作原因不这样做。

我需要 Redis 吗？

不适用于标准单实例 Docker 部署。当您有意转向队列模式和工作人员时，Redis 变得相关。

外部 n8n task runner 与队列模式工作程序相同吗？

不会。外部task runner独立于 n8n 主进程执行支持的任务代码，并使用共享身份验证令牌。 Redis 队列模式分布工作流执行并有其自己的基础设施要求。此示例显示外部task runner，而不是 Redis 队列模式。将跑步者图像版本与 n8n 版本进行匹配。
