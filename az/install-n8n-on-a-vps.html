KÖÇÜRÜB UYĞUNLAŞDIRILAN QURAŞDIRMA

Docker Compose ilə n8n-i VPS-də quraşdırın

Bu nümunədən özünüz idarə etdiyiniz Linux VPS. n8n-i özünüz quraşdırıb idarə edirsiniz; tərəfdaşımız vasitəsilə server seçmək əvvəlcədən quraşdırılmış n8n instansiyasını əhatə etmir. Nümunə n8n, PostgreSQL, xarici tapşırıq icraçısı və Caddy HTTPS xidmətlərini özəl Compose şəbəkəsində birləşdirir. Bu, konfiqurasiya şablonudur, işlək yerləşdirmənin real sınaqdan keçirildiyi iddiası deyil.

Ən sürətli təmiz quraşdırma yolunu axtarırsınız? n8n həmçinin birsətirlik rəsmi Docker quraşdırması təqdim edir. Onun skriptini aşağıdakı vasitə ilə endirib yoxlaya bilərsiniz: curl -fsSL https://get.n8n.io -o get-n8n.sh işə salmazdan əvvəl: sh get-n8n.sh. Bu seçim lokal URL-də SQLite ilə ilkin instansiya və n8n Assistant qum qutusu xidmətləri başladır; o, eyni deyil bu, açıq HTTPS və PostgreSQL istifadə edən VPS yerləşdirməsi ilə eyni deyil. Rəsmi tam qum qutusu dəsti sadə n8n quraşdırmasından daha çox RAM və CPU tələb edir (Compose təlimatında ən azı 4 GB RAM / 2 vCPU göstərilir). İnternetdən əlçatan istehsal VPS-i üçün aşağıdakı əl ilə qurulan dəstə davam edin.

1. Docker, DNS və giriş imkanlarını hazırlayın

SSH vasitəsilə sudo icazəsi ilə qoşulun və n8n.example.com VPS-inizin IPv4 ünvanına. Əgər təzə Ubuntu 22.04, 24.04 və ya 26.04 VPS-də aşağıdakı əmrlər Docker Engine və müasir docker compose plaginini Docker-in rəsmi imzalanmış apt repozitoriyasını:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Bu, rəsmi Docker Ubuntu quraşdırma təlimatında göstərilən, repozitoriyadan istifadə edən istehsala yönəlmiş üsuldur. Artıq konteynerlər və ya başqa saytlar işlədən VPS-də Docker-i düşünmədən yenidən quraşdırmayın və ya silməyin; əvvəlcə mövcud quraşdırmanı və mümkün paket ziddiyyətlərini yoxlayın. Debian və ya başqa distributiv üçün Ubuntu əmrləri əvəzinə həmin əməliyyat sisteminə uyğun rəsmi təlimatdan istifadə edin.

İndi Docker-in özünü, Compose plaginini, DNS-i və iş kataloqunu yoxlayın:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Əgər getent hosts ünvan qaytarmırsa və ya yanlış ünvan göstərirsə, Caddy-ni başlatmazdan əvvəl DNS-i düzəldin; əvəz edin: n8n.example.com bu bələdçi boyunca faktiki host adınızla əvəz edin. Docker adətən root icazəsi tələb edir: SSH istifadəçiniz sonrakı docker compose əmrlərini birbaşa işlətməzdən əvvəl onların əvvəlinə sudo. İstifadəçini docker qrupuna üzvlük root səviyyəsinə bərabər giriş verir və paylaşılan serverdə düşünülmədən edilməməlidir.

Təhlükəsizlik divarını aktivləşdirməzdən əvvəl faktiki SSH idarəetmə portunuzun əlçatan olduğuna əmin olun. Sertifikat almaq və redaktora giriş üçün daxil olan HTTP (80) və HTTPS (443) trafikini açın. Docker vasitəsilə yayımlanan konteyner portları bəzi UFW qaydalarını keçə bilər, buna görə Docker-in təhlükəsizlik divarı təlimatını yoxlayın və yalnız nəzərdə tutulan Caddy portlarını yayımlayın. Bu Compose nümunəsi qəsdən deyil PostgreSQL (5432), n8n (5678) və ya tapşırıq icraçısının brokerini (5679) açıq internetə yayımlamayın.

2. Mühit dəyişənlərini yaradın və açarı qoruyun

Layihə kataloqundan üç fərqli aşağıdakı vasitə ilə təsadüfi onaltılıq dəyərlər yaradın:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Aşağıdakı adlı fayl yaradın: .env aşağıdakı şablona uyğun yaradın, hər bir REPLACE_WITH_RANDOM_HEX başqa təsadüfi yaradılmış dəyərlə əvəz edin, host adını və vaxt qurşağını dəyişin. Göstərilmiş 2.42.5 teqi 8 oktyabr 2026 tarixində göstərilən stabil buraxılış, burada tarixlə göstərilən konfiqurasiya nümunəsi kimi istifadə olunur, işlək yerləşdirmənin yoxlandığına və ya gələcək təhlükəsizliyinə zəmanət deyil. Quraşdırmadan əvvəl n8n-in rəsmi aktual buraxılışlarını yoxlayın, sonra n8n və onun tapşırıq icraçısı təsvirini eyni təsdiqlənmiş versiyada saxlayın.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Heç vaxt repozitoriyaya göndərməyin: .env açıq repozitoriyaya. Şifrələmə açarını və bərpa təlimatlarını VPS-dən kənarda təhlükəsiz saxlayın. Konteyner yenidən yaradıldıqdan və ya miqrasiyadan sonra açar dəyişməməlidir.

3. Yeni quraşdırma üçün compose.yaml faylını hazırlayın

Eyni kataloqda yaradın: compose.yaml. Nümunə n8n-in rəsmi mühit dəyişəni qaydalarından və PostgreSQL 18 PGDATA n8n hostinq layihəsində sənədləşdirilmiş yol:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Dörd xidmətin fərqli rolu var: PostgreSQL verilənlər bazasının vəziyyətini saxlayır, n8n iş axınlarını icra edir, n8n-runner ortaq autentifikasiya tokeni və uyğun versiya ilə icraçı tapşırıqlarını yerinə yetirir, Caddy isə açıq HTTPS trafikini idarə edir. Xarici tapşırıq icraçısı Redis növbə rejimi deyil. Host portlarını yalnız Caddy yayımlayır. Bu sadə nümunə ilkin qurma üçün bir verilənlər bazası rolundan istifadə edir; PostgreSQL icazələrini daha sərt ayırmaq üçün n8n-in rəsmi PostgreSQL yerləşdirmə nümunəsinə baxın.

4. HTTPS üçün Caddyfile yaradın

Faylı yaradın: Caddyfile (böyük C hərfi ilə, uzantısız) faylı ilə yanaşı compose.yaml. Nümunə host adını hər yerdə öz DNS adınızla əvəz edin:

n8n.example.com {
    reverse_proxy n8n:5678
}

Domen düzgün həll olunduqda və xarici trafik 80/443 portlarına çata bildikdə Caddy açıq TLS sertifikatlarını tələb edir və yeniləyir. DNS-i localhost. Caddy-ni başqa əks proksi ilə əvəz etsəniz, ilkin host, protokol və müştəri ünvanı başlıqlarını ötürün və N8N_PROXY_HOPS etibarlı proksi keçidlərinin faktiki sayı üçün.

5. Konteynerləri başladın və kənardan sınaqdan keçirin

Yadda saxladıqdan sonra layihə kataloqundan aşağıdakı əmrləri işlədin: .env, compose.yaml və Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Son əmr açıq HTTPS sağlamlıq son nöqtəsini yoxlayır. Sertifikatın alınması hələ davam edirsə, n8n-in sıradan çıxdığı qənaətinə gəlməzdən əvvəl Caddy jurnallarını, DNS-i və portları yoxlayın. Açın: https://n8n.example.com, dərhal ilk sahib hesabını yaradın və uyğun giriş qorunmasını aktivləşdirin. Təkcə redaktorun açıldığını deyil, instansiyanın iş axınını həqiqətən icra etdiyini təsdiqləyin:

  1. Redaktorda Vebhuk tetikləyicisi. Təyin edin: HTTP metodu üçün GET, seçin: Path vps-check, və təyin edin: Cavab üçün Dərhal. İş axınını yadda saxlayın.
  2. Klikləyin: «Test Event-i gözlə», tam Sınaq URL-i n8n-in göstərdiyi ünvanla və başqa cihazdan işlədin: curl -i 'PASTE_TEST_URL_HERE' köçürülmüş URL ilə. HTTP sorğusunun uğurlu cavab qaytarmasını və gələn hadisənin n8n redaktorunda görünməsini gözləyin. Sınaq URL-ləri yalnız n8n hadisəni gözlədiyi müddətdə işləyir.
  3. Dərc edin iş axınını, qovşağı onun İstehsal URL-i, onu köçürüb işlədin: curl -i 'PASTE_PRODUCTION_URL_HERE' yenidən. İcranın iş axınının İcralar vərəqində təsdiqləyin. İstehsal vebhuk sorğuları üçün iş axını dərc olunmalıdır; onların məlumatları redaktorun sınaq görünüşündə göstərilmir.

Bu, qəsdən sadə və autentifikasiyasız ilkin sınaqdır: ona heç vaxt məxfi məlumat göndərməyin. Sınaqdan sonra onu dərcdən çıxarın/silin və ya açıq son nöqtədən real məlumatlar üçün istifadə etməzdən əvvəl Webhook autentifikasiyası/IP məhdudiyyətləri tətbiq edin. Rəsmi Webhook sınaq və istehsal sənədlərinə baxın.

6. Sabitlənmiş versiyaları dəyişməzdən əvvəl ehtiyat nüsxə yaradın

Bərpa edilə bilən PostgreSQL ehtiyat surəti yaradın və n8n-in daimi məlumat disk sahəsini, .env/şifrələmə açarını və lazım olan xarici faylları bu serverdən kənardakı yaddaşa köçürün. Bərpanı ehtiyat nüsxələmə və bərpa bələdçisi istehsal mühitini yeniləməzdən əvvəl. Əmr nümunələri:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Sabitlənmiş N8N_VERSION yalnız buraxılış qeydlərini oxuduqdan sonra; n8n və icraçı təsvirləri birlikdə yenilənməlidir. İşə salmayın: docker compose down -v adi texniki xidmət zamanı, çünki bu, adlandırılmış məlumat disk sahələrini silir. PostgreSQL əsas versiyasının dəyişməsi verilənlər bazası yeniləməsi və ya ixrac/bərpa planı tələb edir; Postgres 18 təsvirini başqa əsas versiya teqi ilə əvəz etmək avtomatik miqrasiya deyil.

Etibarlı mənbələr: n8n-in Docker Compose təlimatı, əks proksi/vebhuk konfiqurasiyası və PostgreSQL-in rəsmi yerləşdirmə qeydləri. Heç bir infrastruktur performans testi və ya provayderə xas əvvəlcədən quraşdırılmış imkan fərz edilmir.

n8n-in açıq URL-ni HTTPS ilə qoruyun

Tərs proksi

Açıq giriş nöqtəsi kimi Nginx, Caddy və ya Traefik istifadə edin və trafiki özəl n8n xidmətinə ötürün.

TLS
