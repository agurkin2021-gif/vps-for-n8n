İSTEHSAL TƏHLÜKƏSİZLİYİ

VPS-də n8n-in təhlükəsizliyini təmin etmək

VPS-də n8n-in təhlükəsizliyi üçün n8n (5678), PostgreSQL (5432) və istəyə bağlı Redis (6379) portlarını açıq internetdən gizlədin; HTTPS əks proksisindən, SSH açarlarından və MFA-dan istifadə edin, şifrələmə açarını qoruyun, vebhukları autentifikasiya edin, riskli iş axını imkanlarını məhdudlaşdırın və yerləşdirilmiş instansiyanı audit edin. Redaktoru açıq vebhuk yollarından ayrıca qoruyun. Təkcə HTTPS bağlı xidmətləri təhlükəsiz etmir.

SÜRƏTLİ YOXLAMA SİYAHISI

İctimai girişə açmazdan əvvəl minimum təhlükəsizlik tələbləri

Əvvəlcə əlçatan portları, HTTPS-i, təsdiqlənmiş inzibatçı girişini, MFA-nı və saxlanmış giriş məlumatlarının qorunmasını təmin edin. Həssas işi işə salmazdan əvvəl hər gələn vebhuku autentifikasiya edin. Giriş nəzarətini dəyişdikdən sonra nəzərdə tutulan redaktor istifadəçilərinin və xarici inteqrasiyaların hələ də işlədiyini yoxlayın, sonra n8n təhlükəsizlik auditini işə salın.

Yalnız HTTPS

n8n-i düzgün qurulmuş TLS əks proksisinin arxasına yerləşdirin və redaktorla vebhuklar üçün açıq HTTPS URL-ni ardıcıl istifadə edin.

Minimum açıq port

Yalnız açıq trafik üçün vacib portları yayımlayın. PostgreSQL, Redis və daxili tətbiq portlarını internetdən gizli saxlayın.

SSH təhlükəsizliyini gücləndirin

Açar əsasında idarəetmə girişi tətbiq edin, kimin daxil ola biləcəyini məhdudlaşdırın və əməliyyat sistemini yeniləyin.

Giriş məlumatlarını qoruyun

n8n şifrələmə açarını dəyişməz və gizli saxlayın. Mühit fayllarını, verilənlər bazasına girişi və ehtiyat nüsxələri həssas resurslar hesab edin.

ŞƏBƏKƏNİN XARİCİ SƏRHƏDİ

Tərs proksi, HTTPS və etibarlı HTTP başlıqları

TLS bağlantısının sonlandırılması

HTTPS bağlantısını sonlandırmaq üçün Nginx, Caddy və ya Traefik kimi əks proksidən istifadə edin. Adi HTTP-ni HTTPS-ə yönləndirin və proksi nəzərdə tutulan giriş nöqtəsidirsə n8n tətbiq portunu birbaşa açmayın.

Proksi konfiqurasiyası

n8n əks proksi arxasında işləyəndə proksi keçidlərinin sayını düzgün qurun və n8n-in ilkin müştəri sorğusunu bərpa etmək üçün tələb etdiyi ötürülən başlıqları göndərin.

Təhlükəsiz cookie-lər

Redaktoru HTTPS üzərindən təqdim edin ki, autentifikasiya kukiləri təhlükəsiz qalsın. TLS quruluşundakı problemi kuki təhlükəsizliyini zəiflətməklə həll etməyə çalışmayın.

Webhook URL-si

Açıq vebhuk URL-ni internetdən əlçatan HTTPS host adına təyin edin ki, yaradılan vebhuk ünvanları daxili konteynerə və ya HTTP ünvanına yönəlməsin.

Vebhukları pozmadan redaktoru özəl saxlayın. Mümkün olduqda idarəetmə girişini VPN, etibarlı IP siyasəti və ya autentifikasiyalı proksi ilə məhdudlaşdırın. Açıq vebhuk qəbul nöqtələri və OAuth geri çağırış yolları əlçatan qalmalı ola bilər; proksi qaydasını tətbiq etməzdən əvvəl etibarlı redaktor girişini və real xarici geri çağırışı sınaqdan keçirin. Müştəri ünvanı başlıqlarını istənilən sorğu başlığından deyil, yalnız etibarlı proksilərdən qəbul edin.

Vebhuk çağıranlarını autentifikasiya edin: Webhook qovşağında göndərən dəstəkləyirsə None əvəzinə Basic, Header və ya JWT autentifikasiyası seçin. Onun IP(s) Allowlist uyğun olduqda seçimini tətbiq edin və inteqrasiya imzalı sorğuları dəstəkləyirsə provayder imzalarını yoxlayın. Təxmin edilməsi çətin URL kifayət qədər autentifikasiya deyil. Lazım gəldikdə proksidə sorğu tezliyi hədləri tətbiq edin və qanuni sorğu sıçrayışlarının bloklanmadığına əmin olun. Rəsmi Webhook autentifikasiyası seçimləri.

VPS SƏRTLƏŞDİRMƏSİ

Serverin hücum səthini azaldın

Firewall

İstənilməyən daxil olan trafiki standart olaraq bloklayın və yalnız əlçatan olması vacib xidmətlərə icazə verin. Verilənlər bazası və Redis portları adətən özəl/lokal şəbəkədə qalmalıdır.

SSH

Parollar əvəzinə SSH açarlarına üstünlük verin, lazımsız giriş yollarını bağlayın və inzibatçı girişini məhdudlaşdırın. Root səviyyəsinə bərabər giriş ciddi nəzarətdə olmalıdır.

Əməliyyat sisteminin yeniləmələri

Linux hostunu və konteyner icra mühitini yeniləyin. Tətbiqin sərtləşdirilməsi açıq və ya köhnəlmiş əməliyyat sistemini kompensasiya edə bilməz.

Konteynerlərin şəbəkəyə açılması

Yalnız hosta giriş tələb edən portları yayımlayın. Daxili xidmətlər açıq interfeyslər əvəzinə özəl Docker şəbəkələrində əlaqə saxlamalıdır.

Təhlükəsizlik divarı və ya SSH parametrlərini dəyişməzdən əvvəl vəziyyəti yoxlayın: dinləyən portları aşağıdakı vasitə ilə yoxlayın: sudo ss -lntp, Docker-də docker compose ps layihə kataloqundan və host təhlükəsizlik divarı qaydasını sudo ufw status verbose UFW istifadə olunursa. Parolla girişi söndürməzdən əvvəl ayrıca seansda faktiki SSH portunu və uğurlu açar girişini yoxlayın. Docker tərəfindən yayımlanan portlar UFW qaydalarını keçə bilər; təhlükəsizlik divarının status səhifəsi təkbaşına 5678 portunun özəl olduğunu sübut etmir. Kənardan real əlçatanlığı yoxlayın. Docker/UFW məhdudiyyəti.

Ubuntu təhlükəsizlik yeniləmələrinin avtomatik işlədiyini fərz etmək əvəzinə yoxlayın: yoxlayın: apt-config dump APT::Periodic::Unattended-Upgrade və jurnalı /var/log/unattended-upgrades/unattended-upgrades.log. Avtomatik təhlükəsizlik yeniləmələri söndürülübsə, sudo dpkg-reconfigure unattended-upgrades dəstəklənən konfiqurasiya dialoqunu təqdim edir. İşlək VPS-də aktivləşdirməzdən əvvəl yenidən başlatma və xidmətin təkrar başladılması davranışını yoxlayın. Ubuntu APT yeniləmələri deyil n8n Docker təsvirini və ya hər üçüncü tərəf proqram repozitoriyasını avtomatik yeniləmir. Ubuntu avtomatik yeniləmə sənədləri.

İstəyə bağlı SSH parol-təxmin etmə hücumlarının monitorinqi: Fail2Ban təkrarlanan uğursuz SSH girişlərini aşkarlaya bilər. SSH üçün quraşdırılıbsa, sudo fail2ban-client status sshd və bunun faktiki SSH autentifikasiya jurnalını oxuduğunu və qurulmuş porta uyğun olduğunu təsdiqləyin. Bu, SSH açarlarını və şəbəkə məhdudiyyətlərini tamamlayır, onları əvəz etmir. Mövcud girişi yoxlamadan sabit SSH portu və ya bloklama qaydasını köçürməyin. Ubuntu SSH sərtləşdirmə təlimatı.

VERİLƏNLƏR BAZASI VƏ REDIS

Arxa plan xidmətlərini ictimai girişdən qoruyun

Tipik Docker Compose quruluşunda PostgreSQL və növbə rejimindəki Redis hostda yayımlanmış portlarla deyil, özəl şəbəkə üzərindən müvafiq konteynerlər üçün əlçatan olmalıdır. Yoxlayın: docker compose ps 5432 və 6379 portlarının açıq yayımlanmadığını təsdiqləyin; VPS/bulud təhlükəsizlik divarının açıq girişlərini ayrıca yoxlayın. Şəbəkə qaydaları verilənlər bazasına minimum tələb olunan səlahiyyətlərin verilməsini əvəz etmir.

PostgreSQLUzaqdan giriş açıq şəkildə tələb olunub ayrıca qorunmayıbsa, xidməti özəl interfeysə və ya konteyner şəbəkəsinə bağlayın.
RedisNövbə rejimindəki Redis infrastruktur xidmətidir, açıq internet son nöqtəsi deyil. Şəbəkə girişini yalnız ona ehtiyacı olan n8n komponentləri ilə məhdudlaşdırın.
Giriş məlumatlarıTətbiqin ehtiyacı olan icazələrlə məhdudlaşdırılmış ayrıca verilənlər bazası giriş məlumatları istifadə edin və onları mənbə kodu idarəetməsindən kənarda qoruyun.
Məlumat ötürülməsiVerilənlər bazası trafiki etibarsız şəbəkələrdən keçirsə, təkcə tətbiq səviyyəsində giriş məlumatlarının şifrələnməsinə güvənməyin; uyğun şifrələnmiş ötürmədən istifadə edin.

N8N SİRLƏRİ

Şifrələmə açarını və giriş məlumatlarını qoruyun

Şifrələmə açarı

n8n saxlanmış giriş məlumatlarını öz şifrələmə açarı ilə şifrələyir. Açarı yenidən başlatmalar və işçi proseslər arasında dəyişməz saxlayın, onu adi tətbiq məzmunundan ayrıca qoruyun.

Mühitin məxfi dəyişənləri

Parolları, tokenləri və şifrələmə açarını açıq repozitoriyaya göndərməyin. Mühit fayllarına və yerləşdirmə sirlərinə girişi məhdudlaşdırın.

İstifadəçi girişləri

Redaktora girişi yalnız etibarlı istifadəçilərə verin. İş axınları həssas sistemlərə qoşula, sirləri emal edə və güclü qovşaqları işlədə bilər.

Giriş məlumatlarının səlahiyyət dairəsi

Mümkün olduqda dar səlahiyyətli xidmət hesabları və API tokenləri istifadə edin. Ələ keçirilmiş iş axını avtomatik olaraq əlaqəsiz sistemlərə geniş giriş almamalıdır.

Yoxlanmalı n8n konfiqurasiyası: N8N_BLOCK_ENV_ACCESS_IN_NODE=true Code qovşaqları və ifadələrin mühit dəyərlərinə girişini bloklayır; N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true parametrlər faylı üçün yalnız sahibin giriş icazələrini tələb edir. Saxlayın: N8N_ENCRYPTION_KEY daimi və təhlükəsiz ehtiyat nüsxəyə daxil edin: n8n ilk başladıqda təsadüfi açar yarada bilər, lakin onun itməsi mövcud şifrələnmiş giriş məlumatlarını istifadəsiz edə bilər. İstehsal şifrələmə açarını düşünmədən dəyişməyin; rəsmi dəstəklənən açar dəyişmə prosedurundan istifadə edin. Mühitə girişi bloklamaq mövcud inteqrasiyaları poza bilər, ona görə istehsal dəyişikliklərindən əvvəl sınaqdan keçirin. n8n təhlükəsizlik dəyişənlərinin izahı.

İŞ AXINI RİSKLƏRİ

Node-lar təhlükəsizlik sərhədini genişləndirə bilər

Öz serverində hostinq iş axınlarına geniş imkanlar verir. Kod icrası, shell girişi, istənilən HTTP sorğusu və üçüncü tərəf icma qovşaqları riski artıra bilər. Lazımsız funksiyaları söndürün və etibarsız iş axını idxallarını işlətməzdən əvvəl nəzərdən keçirin.

Dəstəklənən dəqiq nəzarət vasitələrindən istifadə edin: qurun: NODES_EXCLUDE söndürüləcək qovşaqların JSON massivi ilə, məsələn: n8n-nodes-base.executeCommand və n8n-nodes-base.readWriteFile, istifadə olunmursa. Bəzi yüksək riskli qovşaqlar yeni versiyalarda artıq standart olaraq bloklanır; dəyişməzdən əvvəl faktiki siyahını yoxlayın. Rəsmi qovşaq istisnaları.

n8n-dən 2.12.0, N8N_SSRF_PROTECTION_ENABLED=true daxili, loopback və metadata ünvan aralıqlarına gedən HTTP sorğularını yoxlamağı aktivləşdirir. Qanuni daxili API iş axınları işləməyə bilər; zərurət varsa yalnız nəzarət etdiyiniz təyinatları dar şəkildə icazəli siyahıya salın. Şəbəkə seqmentasiyasını əsas müdafiə kimi saxlayın. Code qovşaqlarının təcridi üçün xarici tapşırıq icraçılarını nəzərdən keçirin. SSRF qorunması · Tapşırıq icraçısının təcridi.

İcma tərəfindən hazırlanmış node-larYalnız etibar etdiyiniz paketləri quraşdırın; onlar n8n mühitinizdə icra olunur.
Riskli qovşaqlarİmkanları nəzərdə tutulan iş axını sərhədlərindən kənara çıxan və yerləşdirmədə lazım olmayan qovşaqları söndürün.
SSRFİş axınları daxili və ya metadata ünvanlarına çıxmamalı olduqda n8n-in SSRF və şəbəkə nəzarətlərindən istifadə edin.
İş axını idxallarıAktivləşdirməzdən əvvəl idxal edilmiş iş axınlarını, giriş məlumatlarını, ifadələri və icra olunan addımları yoxlayın.

AUDİT VƏ YENİLƏMƏLƏR

Təhlükəsizlik davamlı istismar prosesidir

n8n təhlükəsizlik auditini işə salın

Rəsmi CLI əmri: n8n audit. Docker Compose xidmətinizin adı n8n, işlədin: docker compose exec -T n8n n8n audit həmin yerləşdirmə kataloqunda. Beş kateqoriyanı yoxlayın: istifadə olunmayan giriş məlumatları, riskli SQL sorğu nümunələri, fayl sisteminə giriş, riskli/icma qovşaqları və qorunmayan vebhuklar, köhnəlmiş versiyalar daxil olmaqla instansiya riskləri. Uyğun tapıntıları düzəldin və yenidən yoxlayın. Bu, penetrasiya testi deyil. Rəsmi audit təlimatı.

Yeniləmələri planlı şəkildə aparın

n8n-i təhlükəsizlik düzəlişlərini alacaq qədər aktual saxlayın. İnternetdən əlçatan instansiyanı daimi köhnəlmiş vəziyyətdə buraxmaq əvəzinə buraxılış qeydlərini yoxlayın və vacib yeniləmələri sınaqdan keçirin.

Giriş cəhdlərini izləyin

Gözlənilməz giriş davranışını, iş axını dəyişikliklərini və xətaları izləyin. İş modeliniz geniş ictimai giriş tələb etmirsə, redaktor interfeysini daha da məhdudlaşdırın.

Əvvəlki vəziyyətə qayıtma və bərpa planını hazırlayın

Böyük yeniləmələrdən əvvəl bərpa edilə bilən ehtiyat nüsxələr yaradın. Ehtiyat nüsxənin tam əhatəsi və bərpa qaydaları ayrıca bərpa bələdçisindədir.

Həssas icra tarixçəsini minimuma endirin: uğurlu icralarda müştəri məlumatları və tokenlər saxlanıla bilər. Uyğundursa, təyin edin: EXECUTIONS_DATA_SAVE_ON_SUCCESS=none, saxlayın: EXECUTIONS_DATA_PRUNE=true, və seçin: EXECUTIONS_DATA_MAX_AGE saatla, məsələn: 168 (yeddi gün). Bunlar dəyişdirilə bilən nümunələrdir, hüquqi saxlama qaydaları deyil. Daha az tarixçə xəta axtarışı və insident araşdırması üçün daha az məlumat deməkdir; davam edən, gözləmədə olan və ya qeydlə işarələnmiş icralar eyni qaydada silinməyə bilər. Rəsmi icra tarixçəsinin saxlanması təlimatı.

Ehtimal olunan müdaxilə: izləri məhv etmədən zərərli girişi məhdudlaşdırın, proksi, host və n8n fəaliyyətini, eləcə də dəyişdirilmiş iş axınlarını araşdırın; ifşa olunmuş ola biləcək xarici giriş məlumatlarını ləğv edin və ya yeniləyin, səbəbi aradan qaldırın və lazım olduqda yalnız sınaqdan keçirilmiş bərpa edilə bilən ehtiyat nüsxələrdən bərpa edin. Təsirlənmiş vebhuk URL-lərini, redaktor hesablarını və bağlı xidmətləri yoxlayın; HTTPS, anlıq görüntülər və ya VPS alışının insidentə cavab xidməti verdiyini fərz etməyin.

HESABLAR VƏ PLATFORMA NƏZARƏTİ

VPS-lə yanaşı n8n redaktorunu da qoruyun

Daha güclü giriş mühafizəsi tətbiq edin

Redaktor hesabları üçün iki faktorlu autentifikasiyanı aktivləşdirin; versiyanız mərkəzləşdirilmiş siyasət tətbiqini dəstəkləyirsə, n8n təhlükəsizlik qaydaları vasitəsilə MFA tələb edin.

İş axınlarını redaktə edə bilənləri məhdudlaşdırın

Redaktora giriş yüksək səlahiyyətli girişdir: iş axınları giriş məlumatlarını oxuya, daxili sistemlərə sorğu göndərə və güclü qovşaqları icra edə bilər. İstifadəçi girişini dar çərçivədə saxlayın, artıq ehtiyacı olmayan hesabları silin.

İstifadə etmədiyiniz imkanları deaktiv edin

Lazım olmayan açıq API-ni söndürərək və iş modelinizin tələb etmədiyi yüksək riskli qovşaq və funksiyaları bloklayaraq tətbiqin hücum səthini azaldın.

SSRF və məxfi məlumatların qorunmasını məqsədli şəkildə tənzimləyin
