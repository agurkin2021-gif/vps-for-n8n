Kaip įdiegti n8n VPS serveryje

Įdiekite n8n VPS serveryje naudodami „Docker Compose“ ir „PostgreSQL“. Darbinei aplinkai taip pat būtini nuolat išsaugomi programos bei duomenų bazės duomenys, pastovus N8N_ENCRYPTION_KEY, viešas serverio vardas, HTTPS ir tinkama webhook konfigūracija. Prieš aktyvindami darbines darbo eigas patikrinkite visus šiuos komponentus.

Diegiate VPS serveryje, kuriame jau veikia svetainės? Galite pridėti n8n prie valdomo serverio, jei pakanka CPU, RAM ir saugyklos. Tačiau jei „Nginx“, „Apache“, „Caddy“ ar kitas atvirkštinis tarpinis serveris jau naudoja 80/443 prievadus, toliau pateikto pavyzdinio „Caddy“ konteinerio nepaleiskite nepakeitę: prievadai konfliktuos. Vietoj to nukreipkite naują n8n padomenį per esamą atvirkštinį tarpinį serverį tinkamai sukonfigūravę privatų tinklą arba tiksliam „Compose“ pavyzdžiui naudokite švarų VPS. Išsaugokite kitų svetainių ir jų TLS konfigūraciją; šiame pavyzdyje laikoma, kad 80/443 prievadai laisvi.

DIEGIMO PAVYZDYS, KURĮ REIKIA PRITAIKYTI

Įdiekite n8n VPS serveryje naudodami „Docker Compose“

Pagal šį pavyzdį galite įdiegti n8n savarankiškai administruojamame „Linux“ VPS. n8n diegiate ir prižiūrite patys; pasirinkę serverį per mūsų partnerį negaunate iš anksto įdiegtos n8n. Pavyzdyje viename privačiame „Compose“ tinkle sujungti n8n, „PostgreSQL“, išorinis užduočių vykdytojas ir „Caddy“ su HTTPS. Tai konfigūracijos šablonas, o ne teiginys, kad ši sistema buvo išbandyta veikiančiame serveryje.

Norite dar greičiau įdiegti naują egzempliorių? n8n taip pat pateikia oficialų vienos komandos „Docker“ diegimą. Galite atsisiųsti scenarijų ir jį peržiūrėti naudodami curl -fsSL https://get.n8n.io -o get-n8n.sh prieš vykdydami sh get-n8n.sh. Taip paleidžiamas pradinis egzempliorius su „SQLite“ vietiniu adresu ir n8n „Assistant“ smėliadėžės paslaugomis; tai nėra tas pats , kas ši VPS sistema su viešu HTTPS ir „PostgreSQL“. Visai oficialiai smėliadėžės aplinkai reikia daugiau RAM ir CPU nei nesudėtingai n8n sistemai (jos „Compose“ vadove nurodyta bent 4 GB RAM / 2 vCPU). Jei VPS bus naudojamas internete pasiekiamai darbinei sistemai, tęskite toliau pateiktos rankiniu būdu konfigūruojamos aplinkos diegimą.

1. Paruoškite „Docker“, DNS ir prieigą

Prisijunkite per SSH su „sudo“ teisėmis ir nukreipkite DNS A įrašą, skirtą n8n.example.com į jūsų VPS IPv4 adresą. Naujame „Ubuntu 22.04“, „24.04“ arba „26.04“ VPS toliau pateiktos komandos įdiegia „Docker Engine“ ir šiuolaikinį docker compose papildinį iš oficialios „Docker“ pasirašytos apt paketų saugyklos:

# Naujas oficialus „Ubuntu 22.04“ / „24.04“ / „26.04“ diegimas
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Pridėkite pasirašytą „Docker“ apt paketų saugyklą
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Tai darbinei aplinkai skirtas oficialiame „Docker“ diegimo „Ubuntu“ vadove aprašytas paketų saugyklos būdas. Neperdiekite ir nešalinkite „Docker“ nepatikrinę jo būsenos VPS serveryje, kuriame jau veikia konteineriai ar kitos svetainės; pirmiausia patikrinkite esamą diegimą ir galimus paketų konfliktus. Jei naudojate „Debian“ ar kitą distribuciją, vietoj „Ubuntu“ komandų laikykitės tai operacinei sistemai skirtų oficialių instrukcijų.

Tada patikrinkite patį „Docker“, „Compose“ papildinį, DNS ir darbo katalogą:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Jei getent hosts negrąžina adreso arba pateikia neteisingą, prieš paleisdami „Caddy“ sutvarkykite DNS; visame vadove vietoj n8n.example.com naudokite tikrąjį savo serverio vardą. „Docker“ paprastai reikia root teisių: jei SSH naudotojas vėliau nurodytų docker compose komandų negali vykdyti tiesiogiai, prieš jas rašykite sudo. Pridėjus naudotoją prie docker grupės, suteikiamos root lygio teisės, todėl bendrame serveryje to nedarykite neapgalvotai.

Prieš įjungdami užkardą įsitikinkite, kad jūsų SSH administravimo prievadas lieka pasiekiamas. Įeinantį HTTP (80) ir HTTPS (443) srautą leiskite sertifikatams išduoti ir redaktoriui pasiekti. „Docker“ publikuojami konteinerių prievadai gali apeiti kai kurias UFW taisykles, todėl peržiūrėkite „Docker“ užkardos instrukcijas ir viešai skelbkite tik numatytus „Caddy“ prievadus. Šiame „Compose“ pavyzdyje sąmoningai nepaleiskite neatveriami viešajame internete „PostgreSQL“ (5432), n8n (5678) ir užduočių vykdytojo tarpininko (5679) prievadai.

2. Sukurkite aplinkos reikšmes ir išsaugokite raktą

Projekto kataloge sugeneruokite tris skirtingas atsitiktines šešioliktaines reikšmes naudodami:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Sukurkite failą pavadinimu .env pagal toliau pateiktą šabloną, kiekvieną REPLACE_WITH_RANDOM_HEX pakeiskite skirtinga sugeneruota reikšme ir pakeiskite serverio vardą bei laiko juostą. Nurodyta 2.42.5 žyma atitinka stabilią 2026 m. spalio 8 d. nurodytą versiją, kuri čia naudojama kaip konkrečios datos konfigūracijos pavyzdys, o ne garantija, kad diegimas buvo išbandytas veikiančiame serveryje ar kad jis ateityje išliks saugus. Prieš diegdami patikrinkite naujausias oficialias n8n laidas ir naudokite tą pačią patikrintą n8n bei užduočių vykdytojo atvaizdų versiją.

# .env — pakeiskite tris pavyzdines slaptas reikšmes
# Nurodykite palaikomą n8n versiją; n8n ir vykdytojo versijos turi sutapti.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Niekada nekelkite .env į viešą repozitoriją. Šifravimo raktą ir atkūrimo instrukcijas saugiai laikykite už VPS ribų. Sukūrus konteinerį iš naujo arba perkeliant sistemą raktas privalo likti tas pats.

3. Sukurkite compose.yaml naujai sistemai

Tame pačiame kataloge sukurkite compose.yaml. Pavyzdyje naudojami oficialūs n8n aplinkos kintamųjų pavadinimai ir n8n prieglobos projekte dokumentuotas „PostgreSQL 18“ PGDATA kelias:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Keturios paslaugos atlieka skirtingas užduotis: „PostgreSQL“ saugo duomenų bazės būseną, n8n vykdo darbo eigas, n8n-runner vykdo atskiras užduotis, naudodamas tą pačią versiją ir bendrą autentifikavimo žetoną, o „Caddy“ apdoroja viešą HTTPS. Išorinis užduočių vykdytojas nėra „Redis“ eilių režimas. Tik „Caddy“ publikuoja pagrindinio serverio prievadus. Šiame paprastame pavyzdyje naudojamas vienas duomenų bazės vaidmuo, kad diegimas būtų lengvesnis; norėdami geriau atskirti „PostgreSQL“ teises, peržiūrėkite oficialų n8n diegimo su „PostgreSQL“ pavyzdį.

4. Sukurkite HTTPS Caddyfile

Greta Caddyfile sukurkite failą pavadinimu „Caddyfile“ (didžiąja C, be plėtinio). Visur pavyzdinį serverio vardą pakeiskite savo DNS vardu: compose.yaml. Visur pavyzdinį serverio vardą pakeiskite savo DNS vardu:

n8n.example.com {
    reverse_proxy n8n:5678
}

„Caddy“ prašo ir atnaujina viešus TLS sertifikatus, kai domenas teisingai nukreiptas ir išorinis srautas gali pasiekti 80/443 prievadus. Nenukreipkite DNS į localhost. Jei vietoje „Caddy“ naudojate kitą atvirkštinį tarpinį serverį, persiųskite pradinio serverio vardo, protokolo ir kliento adreso antraštes bei pritaikykite N8N_PROXY_HOPS prie tikrojo patikimų tarpinių serverių skaičiaus.

5. Paleiskite konteinerius ir išbandykite iš išorės

Išsaugoję .env, compose.yaml ir Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Paskutinė komanda patikrina viešąjį HTTPS būsenos tikrinimo adresą. Jei sertifikatas dar neišduotas, peržiūrėkite „Caddy“ žurnalus, DNS ir prievadus, prieš nuspręsdami, kad n8n neveikia. Atverkite https://n8n.example.com, nedelsdami sukurkite pirmąją savininko paskyrą ir įjunkite tinkamas prisijungimo apsaugas. Patikrinkite, ar egzempliorius iš tikrųjų vykdo darbo eigą, o ne tik įkelia redaktorių:

  1. Redaktoriuje sukurkite darbo eigą su Webhook paleidimo mazgu. Nustatykite HTTP Method reikšmę GET, pasirinkite Path vps-checkir nustatykite Respond reikšmę Immediately. Išsaugokite darbo eigą.
  2. Spustelėkite Listen for Test Event, nukopijuokite visą Test URL , kurį rodo n8n, ir kitame įrenginyje vykdykite curl -i 'PASTE_TEST_URL_HERE' su nukopijuotu URL. Tikėkitės sėkmingo HTTP atsakymo ir n8n redaktoriuje pasirodžiusio gaunamo įvykio. Bandomieji URL veikia tik tada, kai n8n laukia įvykio.
  3. Paskelbkite darbo eigą, perjunkite mazgą į Production URL, nukopijuokite jį ir dar kartą vykdykite curl -i 'PASTE_PRODUCTION_URL_HERE' . Įsitikinkite, kad vykdymas matomas darbo eigos skirtuke Executions . Darbinėms webhook užklausoms darbo eiga turi būti paskelbta, o jų duomenys nerodomi redaktoriaus bandomajame rodinyje.

Tai tyčia paprastas neautentifikuotas veikimo bandymas: niekada nesiųskite jam slaptų duomenų. Po bandymo atšaukite jo paskelbimą arba ištrinkite; prieš naudodami viešą adresą tikriems duomenims įjunkite „Webhook“ autentifikavimą ar IP apribojimus. Žr. oficialią bandomųjų ir darbinių webhook dokumentaciją.

6. Prieš keisdami fiksuotas versijas sukurkite atsarginę kopiją

Išsaugokite atkuriamą „PostgreSQL“ duomenų bazės išrašą, ir nuolatinį n8n duomenų tomą, .env/šifravimo raktą ir reikalingus išorinius failus saugykloje už šio serverio ribų. Prieš atnaujindami darbinę sistemą išbandykite atkūrimą pagal atsarginių kopijų ir atkūrimo vadovą . Komandų pavyzdys:

# Sukurkite duomenų bazės, šifravimo rakto, egzemplioriaus duomenų
# ir failų atsargines kopijas prieš keisdami fiksuotas versijas.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# Kai atsarginė kopija jau saugiai išsaugota už VPS ribų:
docker compose pull
docker compose up -d
docker compose ps

Fiksuotą N8N_VERSION versiją keiskite tik perskaitę laidos pastabas; n8n ir užduočių vykdytojo atvaizdus būtina atnaujinti kartu. Nenaudokite docker compose down -v įprastai priežiūrai, nes ši komanda ištrina vardinius duomenų tomus. Pereinant tarp pagrindinių „PostgreSQL“ versijų reikia duomenų bazės atnaujinimo arba išrašo ir atkūrimo plano; „Postgres 18“ atvaizdo pakeitimas kitos pagrindinės versijos žyma nėra automatinis perkėlimas.

Autoritetingi šaltiniai: n8n „Docker Compose“ vadovas, n8n atvirkštinio tarpinio serverio ir webhook konfigūracija bei oficialios diegimo su „PostgreSQL“ pastabos. Netvirtiname, kad atlikti infrastruktūros našumo testai ar kad teikėjas siūlo iš anksto įdiegtą n8n.

Ar naudojant „Docker“ n8n reikia „PostgreSQL“?

„Docker“ nereikalauja „PostgreSQL“, o mažos sistemos gali naudoti „SQLite“. Darbinei VPS aplinkai „PostgreSQL“ suteikia tvirtesnį duomenų bazės pagrindą ir vėliau leidžia plėstis naudojant eilių režimą.

Kam reikalingas nuolatinis n8n duomenų tomas, jei duomenis saugo „PostgreSQL“?

Nuolatiniame n8n kataloge gali būti svarbi egzemplioriaus būsena ir konfigūracija. Išsaugokite jį pagal diegimo architektūrą, o ne manykite, kad duomenų bazė yra vienintelis atkūrimui reikalingas komponentas.

Kodėl mano webhook rodo „localhost“?

Vidinis konteinerio adresas skiriasi nuo viešojo. Nustatykite išorinį serverio vardą, protokolą ir webhook URL, o atvirkštiniame tarpiniame serveryje įjunkite būtinų antraščių persiuntimą.

Ar 5678 prievadas turi būti viešas?

Įprastoje darbinėje aplinkoje su atvirkštiniu tarpiniu serveriu viešai atverkite HTTPS per tarpinį serverį, o n8n programos prievadą palikite vidinį, nebent yra konkreti techninė priežastis elgtis kitaip.

Ar reikia „Redis“?

Ne įprastam „Docker“ diegimui su vienu egzemplioriumi. „Redis“ tampa aktuali sąmoningai pereinant prie eilių režimo ir vykdytojų.

Ar išoriniai n8n užduočių vykdytojai yra tas pats, kas eilių režimo vykdytojai?

Ne. Išoriniai užduočių vykdytojai vykdo palaikomą užduočių kodą atskirai nuo pagrindinio n8n proceso ir naudoja bendrą autentifikavimo žetoną. „Redis“ eilių režimas paskirsto darbo eigų vykdymus ir turi atskirus infrastruktūros reikalavimus. Šiame pavyzdyje pateiktas išorinis užduočių vykdytojas, o ne „Redis“ eilių režimas. Užduočių vykdytojo atvaizdo versija turi sutapti su n8n versija.
