DOCKER АРҚЫЛЫ ОРНАТУ

n8n-ді VPS-ке орнату

n8n-ді VPS-ке Docker Compose және PostgreSQL арқылы орнатыңыз. Өндірістік орта үшін қолданба мен дерекқор деректерін тұрақты сақтау, өзгермейтін N8N_ENCRYPTION_KEY, ашық хост атауы, HTTPS және вебхуктардың дұрыс конфигурациясы қажет. Өндірістік жұмыс процестерін қоспас бұрын осы компоненттердің барлығын тексеріңіз.

АЛДЫН АЛА ТАЛАПТАР

n8n-ді іске қоспас бұрын VPS-ті дайындаңыз

Linux VPS

n8n, PostgreSQL, Docker және кері прокси үшін ресурсы жеткілікті, қолдауы жалғасып жатқан Linux серверін пайдаланыңыз.

DNS

TLS сертификатын шығармай және webhook URL-дерін жарияламай тұрып доменді немесе субдоменді VPS IP-мекенжайына бағыттаңыз.

Docker Compose

Docker Engine мен Compose плагинін операциялық жүйеге арналған ресми қолдау көрсетілетін пакеттер арқылы орнатыңыз.

Желілік экран

Тек әкімшілендіру мен вебке қажет порттарды ашыңыз. PostgreSQL мен ішкі қолданба сервистерін сыртқы желіге шығармаңыз.

VPS-те басқа сайттар жұмыс істеп тұр ма? CPU, RAM және диск ресурстары жеткілікті болса, n8n-ді өзіңіз басқаратын бар серверге қосуға болады. Бірақ Nginx, Apache, Caddy немесе басқа кері прокси 80/443 порттарын пайдаланып тұрса, төмендегі Caddy контейнерін өзгеріссіз іске қоспаңыз: порттар қақтығысады. Оның орнына жаңа n8n субдоменін қолданыстағы кері прокси арқылы жеке желіге бағыттаңыз немесе дәл осы Compose мысалы үшін таза VPS пайдаланыңыз. Басқа сайттар мен олардың TLS конфигурациясын сақтаңыз; бұл мысалда 80/443 порттары бос деп есептеледі.

КӨШІРІП, ӨЗ ОРТАҢЫЗҒА БЕЙІМДЕП ОРНАТУ

n8n-ді VPS-ке Docker Compose арқылы орнатыңыз

Бұл мысалды n8n deployment-ын өзіңіз басқаратын Linux VPS-теқұру үшін пайдаланыңыз. n8n-ді өзіңіз орнатып, әрі қарай өзіңіз басқарасыз; серіктестік сілтеме арқылы сервер таңдау алдын ала орнатылған n8n инстансын қамтымайды. Мысал n8n, PostgreSQL, сыртқы task runner және Caddy HTTPS-ті жеке Compose желісінде біріктіреді. Бұл — конфигурация шаблоны, нақты production deployment толық тексерілді деген мәлімдеме емес.

Жаңа инстансты ең жылдам тәсілмен орнатқыңыз келе ме? n8n бір жолдық ресми Docker орнатуын да ұсынады. Скриптті іске қоспас бұрын мына командамен жүктеп алып, мазмұнын тексеруге болады: curl -fsSL https://get.n8n.io -o get-n8n.sh содан кейін ғана мына команданы орындаңыз: sh get-n8n.sh. Бұл нұсқа SQLite пайдаланатын бастапқы инстансты жергілікті URL-де іске қосады және n8n Assistant sandbox сервистерін қамтиды; ол бірдей емес осы ашық HTTPS және PostgreSQL негізіндегі VPS deployment-ымен. Ресми толық sandbox стек жеңіл n8n орнатуына қарағанда көбірек RAM және CPU қажет етеді (Compose нұсқаулығында кемінде 4 GB RAM / 2 vCPU көрсетілген). Интернетке ашық production VPS үшін төмендегі қолмен бапталатын стекті пайдаланыңыз.

1. Docker, DNS және қолжетімділікті дайындаңыз

sudo құқығы бар SSH арқылы серверге қосылып, n8n.example.com үшін DNS A жазбасын VPS-тің IPv4 мекенжайына бағыттаңыз. Жаңа Ubuntu 22.04, 24.04 немесе 26.04 VPS-те төмендегі командалар Docker Engine мен қазіргі docker compose плагинін Docker-дың ресми қолтаңбаланған apt репозиторийінен орнатады:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Бұл — Docker-дың Ubuntu үшін ресми орнату нұсқаулығындағы өндірістік ортаға арналған репозиторий тәсілі. Контейнерлер немесе басқа сайттар жұмыс істеп тұрған VPS-те Docker-ды тексермей қайта орнатпаңыз немесе өшірмеңіз; алдымен бар орнатуды және ықтимал пакет қайшылықтарын тексеріңіз. Debian немесе басқа дистрибутивте Ubuntu командаларының орнына сол операциялық жүйеге арналған ресми нұсқаулықты пайдаланыңыз.

Енді Docker-дың өзін, Compose плагинін, DNS-ті және жұмыс бумасын тексеріңіз:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

Егер getent hosts мекенжай қайтармаса немесе қате мекенжай көрсетсе, Caddy-ді іске қоспас бұрын DNS-ті түзетіңіз; осы нұсқаулықтағы n8n.example.com мәнін өзіңіздің нақты хост атауыңызбен ауыстырыңыз. Docker әдетте root құқығын қажет етеді: SSH пайдаланушысы кейінгі docker compose командаларын тікелей орындай алмаса, алдына sudoқосыңыз. Пайдаланушыны docker тобына қосу root деңгейіне тең құқық береді, сондықтан ортақ серверде мұны ойланбай жасамаңыз.

Желілік экранды қоспас бұрын нақты SSH әкімшілік портына қолжетімділік сақталғанын тексеріңіз. Сертификат шығару мен редактор үшін кіріс HTTP (80) және HTTPS (443) трафигіне рұқсат беріңіз. Docker жариялаған контейнер порттары кейбір UFW ережелерін айналып өтуі мүмкін, сондықтан Docker-дың firewall нұсқаулығын тексеріп, тек Caddy үшін қажет порттарды жариялаңыз. Бұл Compose мысалында PostgreSQL (5432), n8n (5678) және task-runner broker (5679) порттары әдейі ашық интернетке шығарылмайды.

2. Environment мәндерін жасап, кілтті сақтаңыз

Жоба бумасында үш әртүрлі кездейсоқ hexadecimal мән жасаңыз:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Төмендегі шаблон бойынша .env файлын жасаңыз. Әрбір REPLACE_WITH_RANDOM_HEX мәнін бөлек жасалған кездейсоқ мәнмен ауыстырып, хост атауы мен уақыт белдеуін өзгертіңіз. Көрсетілген 2.42.5 тегі — 2026 жылғы 8 қазанда тұрақты релиз ретінде көрсетілген нұсқа; ол тек күні белгіленген конфигурация мысалы ретінде берілген және нақты production ортада толық тексерілді немесе болашақта қауіпсіз болады деген кепілдік емес. Орнатпас бұрын n8n-нің қазіргі ресми релизін тексеріп, n8n мен task-runner image-ін бір тексерілген нұсқада ұстаңыз.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Ешқашан .env файлын ашық репозиторийге commit жасамаңыз. Шифрлау кілті мен қалпына келтіру нұсқаулығын VPS-тен бөлек қауіпсіз сақтаңыз. Контейнер қайта жасалғанда немесе миграция кезінде кілт өзгермеуі тиіс.

3. Жаңа орнату үшін compose.yaml жасаңыз

Сол бумада compose.yaml файлын жасаңыз. Мысалда n8n-нің ресми environment variable атаулары және PostgreSQL 18 үшін n8n hosting жобасы құжаттаған PGDATA жолы пайдаланылады:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Төрт сервистің міндеті бөлек: PostgreSQL дерекқор күйін сақтайды, n8n жұмыс процестерін орындайды, n8n-runner сәйкес нұсқамен және ортақ authentication token арқылы runner тапсырмаларын орындайды, ал Caddy ашық HTTPS-ті өңдейді. Сыртқы task runner Redis queue mode емес. Хост порттарын тек Caddy жариялайды. Бұл жеңіл мысалда орнатуды қарапайым ету үшін бір database role пайдаланылады; PostgreSQL құқықтарын қатаңырақ бөлу үшін n8n-нің ресми PostgreSQL орнату мысалын қараңыз.

4. HTTPS үшін Caddyfile жасаңыз

Мына файлды жасаңыз: Caddyfile (C әрпі бас әріппен, кеңейтімсіз), ол compose.yaml файлының жанында тұруы керек. Мысалдағы хост атауын барлық жерде өз DNS атауыңызбен ауыстырыңыз:

n8n.example.com {
    reverse_proxy n8n:5678
}

Домен дұрыс resolve болып, сыртқы трафик 80/443 порттарына жете алса, Caddy ашық TLS сертификаттарын өзі сұратады және жаңартады. DNS-ті localhost мәніне бағыттамаңыз. Caddy орнына басқа кері прокси қолдансаңыз, бастапқы host, protocol және client address header-лерін өткізіп, нақты сенімді proxy hop санына қарай N8N_PROXY_HOPS мәнін баптаңыз.

5. Контейнерлерді іске қосып, сырттан тексеріңіз

Жоба бумасында төмендегі файлдарды сақтағаннан кейін командаларды орындаңыз: .env, compose.yaml және Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Соңғы команда ашық HTTPS жүйе күйін тексеру endpoint-ын тексереді. Сертификат әлі шығарылып жатса, n8n істемей тұр деп қорытынды жасамас бұрын Caddy логтарын, DNS пен порттарды тексеріңіз. Мына мекенжайды ашыңыз: https://n8n.example.com, алғашқы owner аккаунтын бірден жасап, кіруді тиісті деңгейде қорғаңыз. Инстанс тек редакторды ашып қана қоймай, жұмыс процесін шынымен орындайтынын тексеріңіз:

  1. Редакторда Webhook триггері бар жұмыс процесін жасаңыз. HTTP Method параметрін GET етіп қойыңыз, Path ретінде vps-check енгізіңіз, ал Respond параметрін Immediately етіп орнатыңыз. Жұмыс процесін сақтаңыз.
  2. Listen for Test Event батырмасын басыңыз, n8n көрсеткен толық Test URL мәнін көшіріңіз және басқа құрылғыдан көшірілген URL-мен curl -i 'PASTE_TEST_URL_HERE' командасын орындаңыз. Сәтті HTTP жауабы келіп, кіріс оқиға n8n редакторында көрінуі тиіс. Test URL тек n8n тест оқиғасын күтіп тұрған кезде жұмыс істейді.
  3. Жұмыс процесін Publish етіңіз, node-ты Production URL режиміне ауыстырыңыз, URL-ді көшіріп, curl -i 'PASTE_PRODUCTION_URL_HERE' командасын қайта орындаңыз. Орындалуды жұмыс процесінің Executions қойындысынан тексеріңіз. Production вебхук сұраулары жұмыс процесінің published күйде болуын талап етеді және олардың payload-ы редактордың тест көрінісінде көрсетілмейді.

Бұл әдейі қарапайым, аутентификациясыз smoke test: оған ешқашан құпия дерек жібермеңіз. Тексеруден кейін workflow-ды unpublish етіңіз немесе өшіріңіз; нақты деректер үшін ашық endpoint қолданбас бұрын вебхук аутентификациясын және IP restriction баптаңыз. Ресми Webhook test/production құжаттамасын қараңыз.

6. Бекітілген нұсқаларды өзгертпес бұрын резервтік көшірме жасаңыз

Қалпына келтіруге жарамды PostgreSQL dump-ын және тұрақты n8n data volume-ін, .env/шифрлау кілтін және қажет сыртқы файлдарды осы серверден бөлек сақтау орнына көшіріңіз. Өндірістік ортаны жаңартпас бұрын резервтік көшіру және қалпына келтіру нұсқаулығы бойынша restore тексеріңіз. Мысал командалар:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Бекітілген N8N_VERSION мәнін тек релиз ескертпелерін оқығаннан кейін өзгертіңіз; n8n және runner image бір нұсқаға бірге жаңартылуы тиіс. Күнделікті техникалық қызмет кезінде docker compose down -v командасын орындамаңыз, себебі ол атаулы деректер томдарын өшіреді. PostgreSQL негізгі нұсқасын өзгерту дерекқорды жаңарту немесе dump/restore жоспарын қажет етеді; Postgres 18 image-ін басқа негізгі tag-пен ауыстыру автоматты миграция болып саналмайды.

Негізгі дереккөздер: n8n Docker Compose нұсқаулығы, n8n reverse-proxy/webhook конфигурациясы және PostgreSQL-дің ресми орнату ескертпелері. Мұнда инфрақұрылым benchmark-і немесе провайдерге тән алдын ала орнатылған функциялар бар деп болжанбайды.

КОНФИГУРАЦИЯ

Құпия мәндер мен ашық URL-дерді саналы түрде баптаңыз

Шифрлау кілті

Өндірістік орта тіркелгі деректерін сақтамас бұрын сенімді n8n шифрлау кілтін орнатып, оны сақтаңыз. Қалпына келтіруден кейін де дәл сол кілт қажет.

PostgreSQL тіркелгі деректері

Дерекқор үшін жеке тіркелгі деректерін пайдаланыңыз және құпиясөздерді ашық нұсқаларды басқару жүйесінде сақтамаңыз.

Ашық хост атауы

Ішкі контейнер мекенжайының орнына нақты сыртқы хост атауы мен HTTPS origin мәнін баптаңыз.

Webhook URL

Орнатыңыз: N8N_WEBHOOK_URL мәнін сырттан қолжетімді HTTPS негізгі URL-іне, ал N8N_PROXY_HOPS=1 мәнін бір сенімді кері прокси болса 1 етіп қойыңыз. WEBHOOK_URL n8n 2.35.0 және кейінгі нұсқаларда ескірген alias болып саналады; оны ескі нұсқаулықтардан көшірмеңіз.

ТҰРАҚТЫ САҚТАУ

n8n мен PostgreSQL деректерін бөлек тұрақты сақтаңыз

n8n деректері

Контейнер қайта жасалғанда маңызды инстанс күйі жоғалмауы үшін n8n деректер бумасына тұрақты сақтау орнын қосыңыз.

PostgreSQL деректері

Дерекқор бумасын PostgreSQL контейнерінен тәуелсіз тұрақты сақтаңыз.

Файл рұқсаттары

Mounted жолдарға қажетті контейнер пайдаланушысы жаза алатындай етіңіз, бірақ хосттағы сақтау орнына артық құқық бермеңіз.

Жұмыс процесі файлдары

Өндірістік жұмыс процестері тәуелді mounted файлдар мен бинарлық деректер қоймасын тұрақты сақтаңыз.

POSTGRESQL

n8n-ді жеке дерекқор сервисіне қосыңыз

Дерекқор түріn8n-ді PostgreSQL пайдаланатындай нақты баптаңыз, әйтпесе ол байқамай SQLite-қа ауысуы мүмкін.
ХостЖеке Docker желісінде PostgreSQL сервисінің атауын пайдаланыңыз.
Тіркелгі деректеріҚажетті дерекқор, қолданба пайдаланушысы және құпиясөздің сәйкестігін тексеріңіз.
Дайындық күйіn8n сәтті инициализацияланады деп күтпес бұрын PostgreSQL толық дайын болғанын күтіңіз.
ЖеліКонтейнерлер арасындағы дерекқор байланысы үшін PostgreSQL портын интернетке ашу қажет емес.

HTTPS ЖӘНЕ PROXY

n8n-нің ашық URL-ін HTTPS артында орналастырыңыз

Кері прокси

Nginx, Caddy немесе Traefik-ті ашық кіру нүктесі ретінде пайдаланып, трафикті жеке n8n сервисіне бағыттаңыз.

TLS

Ашық хост атауы үшін жарамды сертификат шығарып, HTTP трафигін HTTPS-ке бағыттаңыз.

Прокси арқылы берілетін header-лер

n8n қажет ететін host, protocol және client ақпаратын өткізіп, күтілетін proxy hop санын баптаңыз.

Webhook тексеруі

VPS-тен тыс жерден webhook шақырып, n8n сырттан қолжетімді HTTPS URL жасайтынын тексеріңіз.

АЛҒАШҚЫ ІСКЕ ҚОСУ

Өндірістік қолдануға дейін тұрақты сақтауды тексеріңіз

КонтейнерлерІске қосқаннан және қайта іске қосқаннан кейін n8n, PostgreSQL және proxy сервистері қалыпты күйде қалатынын тексеріңіз.
РедакторАшық HTTPS hostname-ды ашып, аутентификация дұрыс жұмыс істейтінін тексеріңіз.
ДерекқорТест күйін жасап, контейнерлерді қайта құрыңыз және күй сақталғанын тексеріңіз.
WebhookDNS, TLS, проксилеуді және ашық callback URL-ді тексеру үшін сыртқы webhook тестін орындаңыз.

ЖАҢАРТУЛАР

Контейнерлерді резервтік көшірме деп есептемей, Docker орнатуын жаңартыңыз

Release notes оқыңыз

Жаңарту алдында n8n-дегі маңызды өзгерістерді, әсіресе бірнеше нұсқаны өткізіп жаңартсаңыз, қарап шығыңыз.

Алдымен резервтік көшірме жасаңыз

Өндірістік image-ті өзгертпес бұрын қалпына келтіруге болатын дерекқор мен инстанстың резервтік көшірмесін жасаңыз.

Қауіпсіз қайта құрыңыз

Таңдалған image-ті pull жасап, тұрақты томдарды сақтай отырып қолданба контейнерлерін қайта құрыңыз.

Жаңартудан кейін тексеріңіз

Орнату қалыпты жұмыс істейді деп есептемес бұрын логтарды, редакторға қолжетімділікті, тіркелгі деректері мен негізгі жұмыс процестерін тексеріңіз.

Резервтік көшіру және қалпына келтіру нұсқаулығы

ЖИІ КЕЗДЕСЕТІН ҚАТЕЛЕР

Неге n8n Docker орнатуы локалды жұмыс істейді, бірақ өндірістік ортада істемейді

Қате webhook URL

Callback URL-дері ашық HTTPS origin-нің орнына localhost, HTTP немесе ішкі хост атауына бағытталған.

Тұрақты сақтау жоқ

Контейнер қайта жасалғанда қолданба немесе дерекқор күйі жоғалады.

Шифрлау кілті жоғалған

Жаңа инстанс басқа кілт пайдаланғандықтан, сервер қайта құрылғаннан кейін сақталған credentials жарамсыз болады.

PostgreSQL қажетсіз интернетке ашылған, ал оған тек n8n қол жеткізуі керек.

DEPLOYMENT-ТАН КЕЙІНГІ ТЕКСЕРУ

Нақты жұмыс процестерін қоспас бұрын жүйе күйін тексеріңіз

Контейнерлер күйін тексеріңіз

Орындаңыз: docker compose ps және deployment қалыпты деп есептемес бұрын қолданба мен дерекқор сервистері күткендей жұмыс істеп тұрғанын тексеріңіз.

n8n жүйе күйін тексеру endpoint-ын тексеріңіз

Жоғарыдағы Compose мысалында 5678 порты хостта жарияланбайды. Хост атауын ауыстырғаннан кейін ашық endpoint-ты мына командамен тексеріңіз: curl -fsS https://n8n.example.com/healthz HTTPS немесе дерекқор дайын болмаса, docker compose ps және сервис логтарын пайдаланыңыз.

Қолданба нұсқаларын бекітіңіз

Тексерілмеген, бекітілмеген image жаңартуын техникалық қызмет стратегиясы деп қабылдамаңыз. Қолданылып тұрған n8n нұсқасын жазып қойыңыз, релиз ескертпелерін оқыңыз және нұсқаны өзгертпес бұрын резервтік көшірме жасаңыз.

PostgreSQL major version-ын орнында бірден көтермеңіз

Тек Postgres негізгі image tag-ын өзгерту бар деректер бумасын үйлесімсіз етуі мүмкін. Контейнерді қайта құру негізгі нұсқа миграциясын жасайды деп есептемей, backup жасап, дерекқор upgrade процедурасын қолданыңыз.

FAQ

n8n-ді Docker арқылы орнату: жиі қойылатын сұрақтар

Docker қолданғанда n8n үшін PostgreSQL қажет пе?

Docker міндетті түрде PostgreSQL талап етпейді, шағын орнату SQLite пайдалана алады. Өндірістік VPS үшін PostgreSQL сенімдірек дерекқор негізін береді және кейін queue mode арқылы масштабтауға мүмкіндік береді.

PostgreSQL деректерді сақтаса, неге тұрақты n8n томы қажет?

Тұрақты n8n бумасында маңызды инстанс күйі мен конфигурация болуы мүмкін. Дерекқорды жалғыз қалпына келтірудің жалғыз көзі деп есептемей, оны орнату архитектурасына сай сақтаңыз.

Неге webhook localhost көрсетеді?

Контейнердің ішкі мекенжайы ашық origin-нен өзгеше. Сыртқы хост атауын, protocol және webhook URL-ді баптап, кері прокси қажетті header-лерді өткізетініне көз жеткізіңіз.

5678 порты интернетке ашық болуы керек пе?

Кері прокси артындағы қалыпты өндірістік орнатуда HTTPS-ті proxy арқылы ашып, арнайы операциялық себеп болмаса n8n қолданба портын ішкі желіде қалдырыңыз.

Redis қажет пе?

Кәдімгі бір инстансты Docker орнатуы үшін қажет емес. Redis queue mode пен worker-лерге саналы түрде көшкен кезде қажет болады.

Сыртқы n8n task runner-лері queue mode worker-лерімен бірдей ме?

Жоқ. Сыртқы task runner-лер қолдау көрсетілетін task code-ты n8n негізгі процесінен бөлек орындайды және ортақ authentication token пайдаланады. Redis queue mode жұмыс процестерінің орындалуын таратады және өзінің инфрақұрылым талаптары бар. Бұл мысалда Redis queue mode емес, сыртқы task runner көрсетілген. Runner image нұсқасын n8n нұсқасына сәйкестендіріңіз.
