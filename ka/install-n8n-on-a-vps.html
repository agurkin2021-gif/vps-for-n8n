დააკოპირეთ და მოარგეთ

დააყენეთ n8n თქვენს VPS-ზე Docker Compose-ით

Use this example to build an n8n deployment on a თვითმართვად Linux VPS-ზე. You install and maintain n8n yourself; choosing a server through our partner does not include a preinstalled n8n instance. The example combines n8n, PostgreSQL, an external task runner and Caddy HTTPS in a private Compose network. It is a configuration template, და არა განცხადება ცოცხალ გარემოში სრულად გამოცდილი განთავსების შესახებ.

გსურთ ახალი ინსტალაციის ყველაზე სწრაფი გზა? n8n also provides an official one-line Docker setup. You can download and review its script with curl -fsSL https://get.n8n.io -o get-n8n.sh before running sh get-n8n.sh. That option launches an initial instance with SQLite at a local URL and includes n8n Assistant sandbox services; it is იგივე არ არის as this public-HTTPS, PostgreSQL-backed VPS deployment. The official full sandbox stack needs more RAM and CPU than a lean n8n installation (its Compose guide specifies at least 4 GB RAM / 2 vCPUs). For an internet-facing production VPS, continue with the manually configured stack below.

1. მოამზადეთ Docker, DNS და წვდომა

Connect over SSH with sudo access and point a DNS A record for n8n.example.com to your VPS IPv4 address. On a Ubuntu 22.04, 24.04 ან 26.04 VPS, the following commands install Docker Engine and the modern docker compose plugin from Docker's official signed apt repository:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

This is the production-oriented repository method in the official Docker Ubuntu installation guide. არ გადააყენოთ ან წაშალოთ Docker დაუფიქრებლად VPS-ზე, სადაც უკვე მუშაობს კონტეინერები ან სხვა ვებსაიტები; ჯერ შეამოწმეთ არსებული ინსტალაცია და შესაძლო package conflict-ები. Debian-ის ან სხვა დისტრიბუტივისთვის Ubuntu ბრძანებების ნაცვლად შესაბამისი ოფიციალური OS-სპეციფიკური ინსტრუქციები გამოიყენეთ.

ახლა გადაამოწმეთ Docker, Compose plugin, DNS და სამუშაო დირექტორია:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

If getent hosts returns no address or the wrong address, correct your DNS before starting Caddy; replace n8n.example.com throughout this guide with your real hostname. Docker normally requires root privileges: if your SSH user cannot run the later docker compose commands directly, prefix them with sudo. Adding a user to the docker group grants root-equivalent access and should not be done casually on a shared server.

Keep your actual SSH administration port reachable before enabling a firewall. Allow inbound HTTP (80) and HTTPS (443) for certificate issuance and the editor. Docker-published container ports can bypass some UFW rules, so review Docker's firewall guidance and publish only the intended Caddy ports. This Compose example deliberately does არ publish PostgreSQL (5432), n8n (5678) or task-runner broker (5679) to the public internet.

2. შექმენით გარემოს მნიშვნელობები და შეინახეთ გასაღები

From the project directory, generate three განსხვავებული random hexadecimal values with:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Create a file named .env using the template below, replace every REPLACE_WITH_RANDOM_HEX with a different generated value, and change the hostname and timezone. The shown 2.42.5 tag is the სტაბილური რელიზი, რომელიც 2026 წლის 8 ოქტომბერს იყო მითითებული, used here as a dated configuration example, და არა ცოცხალ გარემოში გამოცდილი განთავსების ან მომავალი უსაფრთხოების გარანტია. დაყენებამდე გადაამოწმეთ n8n-ის მიმდინარე ოფიციალური რელიზი და n8n-ისა და task-runner image-ის ერთი და იგივე შემოწმებული ვერსია გამოიყენეთ.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Never commit .env to a public repository. Store the encryption key and recovery instructions securely off the VPS. The key must stay the same after container recreation or migration.

3. დაწერეთ compose.yaml ახალი ინსტალაციისთვის

In the same directory, create compose.yaml. The example uses the official n8n environment-variable conventions and the PostgreSQL 18 PGDATA path documented by the n8n hosting project:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

The four services have distinct roles: PostgreSQL stores database state, n8n runs workflows, n8n-runner executes runner tasks with a matching version and shared authentication token, and Caddy handles public HTTPS. An external task runner is not Redis queue mode. Only Caddy publishes host ports. This lean illustration uses a single database role for setup; for stronger separation of PostgreSQL privileges, consult the official n8n PostgreSQL deployment example.

4. შექმენით HTTPS Caddyfile

Create the file Caddyfile (capital C, no extension) alongside compose.yaml. მაგალითში hostname ყველგან თქვენი DNS სახელით ჩაანაცვლეთ:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy requests and renews public TLS certificates when the domain resolves correctly and external traffic can reach ports 80/443. Do not point DNS to localhost. If you replace Caddy with another reverse proxy, forward the original host, protocol and client-address headers and adjust N8N_PROXY_HOPS for the actual number of trusted proxy hops.

5. გაუშვით კონტეინერები და გარედან შეამოწმეთ

Run these commands from the project directory after saving .env, compose.yaml and Caddyfile:

docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

The last command checks the საჯარო HTTPS health endpoint. If certificate issuance is still pending, inspect Caddy logs and DNS/ports before concluding n8n is broken. Open https://n8n.example.com, დაუყოვნებლივ შექმენით პირველი owner ანგარიში და ჩართეთ შესაბამისი sign-in დაცვა. დაადასტურეთ, რომ ინსტანცია რეალურად ასრულებს სამუშაო პროცესს და არა მხოლოდ რედაქტორს ხსნის:

  1. In the editor, create a workflow with a Webhook trigger. Set HTTP Method to GET, choose the Path vps-check, and set Respond to Immediately. შეინახეთ სამუშაო პროცესი.
  2. Click Listen for Test Event, copy the full Test URL shown by n8n, and from another device run curl -i 'PASTE_TEST_URL_HERE' with the copied URL. Expect an HTTP success response and the incoming event to appear in the n8n editor. Test URLs work only while n8n is listening for the event.
  3. გამოაქვეყნეთ the workflow, switch the node to its Production URL, copy it and run curl -i 'PASTE_PRODUCTION_URL_HERE' again. Confirm the execution under the workflow's Executions tab. Production webhook requests need the workflow to be published and do not show their payload in the editor's test view.

6. pinned ვერსიების შეცვლამდე შექმენით სარეზერვო ასლი

Save a recoverable PostgreSQL dump და the persistent n8n data volume, .env/encryption key and required external files to storage outside this server. Verify a restore using the სარეზერვო და აღდგენის გზამკვლევით before updating production. Example commands:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Change the pinned N8N_VERSION only after reading release notes; both n8n and runner images must advance together. Do not run docker compose down -v during routine maintenance because that deletes named data volumes. PostgreSQL major-version changes require a database upgrade or dump/restore plan; replacing the Postgres 18 image with a different major tag is not an automatic migration.

FAQ

n8n-ის Docker-ით დაყენება: გავრცელებული კითხვები

სჭირდება n8n-ს PostgreSQL Docker-ის გამოყენებისას?

Docker PostgreSQL-ს არ მოითხოვს და მცირე deployment-ებს SQLite-ის გამოყენება შეუძლია. პროდუქტიულ VPS deployment-ში PostgreSQL უფრო ძლიერი მონაცემთა ბაზის საფუძველია და შემდგომ queue-mode scaling-ს უჭერს მხარს.

რატომ შევინარჩუნოთ persistent n8n volume, თუ მონაცემებს PostgreSQL ინახავს?

persistent n8n დირექტორია შეიძლება შეიცავდეს ინსტანციის მნიშვნელოვან მდგომარეობასა და კონფიგურაციას. შეინარჩუნეთ იგი deployment design-ის მიხედვით და ნუ ჩათვლით, რომ აღდგენის ერთადერთი რესურსი მონაცემთა ბაზაა.

რატომ აჩვენებს ჩემი webhook localhost-ს?

შიდა container address საჯარო origin-ისგან განსხვავდება. დააკონფიგურირეთ გარე hostname, protocol და webhook URL და დარწმუნდით, რომ reverse proxy საჭირო headers-ს გადასცემს.

უნდა იყოს 5678 პორტი საჯარო?

ჩვეულებრივ პროდუქტიულ deployment-ში reverse proxy-ის უკან HTTPS proxy-ზე გამოაქვეყნეთ, ხოლო n8n application port შიდა დატოვეთ, თუ მისი საჯაროდ გახსნის კონკრეტული საოპერაციო მიზეზი არ არსებობს.

მჭირდება Redis?

სტანდარტული ერთინსტანციანი Docker deployment-ისთვის არა. Redis საჭირო ხდება, როდესაც განზრახ გადადიხართ queue mode-სა და worker-ებზე.

External n8n task runner-ები იგივეა, რაც queue mode worker-ები?

არა. External task runner-ები მხარდაჭერილ task code-ს n8n main process-ისგან ცალკე ასრულებს და shared authentication token-ს იყენებს. Redis queue mode სამუშაო პროცესების შესრულებებს ანაწილებს და საკუთარი ინფრასტრუქტურული მოთხოვნები აქვს. ეს მაგალითი external task runner-ს აჩვენებს და არა Redis queue mode-ს. runner image-ის ვერსია n8n-ის ვერსიას შეუსაბამეთ.
