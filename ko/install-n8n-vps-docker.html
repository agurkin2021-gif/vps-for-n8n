1. Docker, DNS 준비 및 접속

sudo 액세스로 SSH 을 통해 연결하고 DNS A 레코드를 지정합니다. n8n.example.com 귀하의 VPS IPv4 주소로. 에 신선한 Ubuntu 22.04, 24.04 또는 26.04 VPS, 다음 명령은 Docker 엔진과 최신 버전을 설치합니다. docker compose Docker 공식 서명 플러그인 apt 저장소:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

이는 공식 Docker Ubuntu 설치 가이드에 있는 프로덕션 중심 저장소 방법입니다. 이미 실행 중인 VPS 컨테이너 또는 기타 웹사이트에서 Docker 을 무작정 재설치하거나 제거하지 마세요.; 먼저 기존 설치와 가능한 패키지 충돌을 검사하십시오. Debian 또는 다른 배포판의 경우 Ubuntu 명령 대신 해당 공식 OS별 지침을 사용하세요.

이제 Docker 자체, Compose 플러그인, DNS 및 작업 디렉터리를 확인하세요.

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com

만약에 getent hosts 주소가 없거나 잘못된 주소가 반환되는 경우 Caddy 을 시작하기 전에 DNS 을 수정하세요. 교체하다 n8n.example.com 이 가이드 전반에 걸쳐 실제 호스트 이름을 사용하세요. Docker 에는 일반적으로 루트 권한이 필요합니다. SSH 사용자가 나중에 실행할 수 없는 경우 docker compose 명령을 직접 접두어로 사용하세요. sudo. 사용자 추가 docker 그룹은 루트와 동등한 액세스 권한을 부여하므로 공유 서버에서 임의로 수행해서는 안 됩니다.

방화벽을 활성화하기 전에 실제 SSH 관리 포트에 접근할 수 있도록 유지하십시오. 인증서 발급 및 편집자에 대해 인바운드 HTTP(80) 및 HTTPS(443)을 허용합니다. Docker 게시된 컨테이너 포트는 일부 UFW 규칙을 우회할 수 있으므로 Docker 의 방화벽 지침을 검토하고 의도된 Caddy 포트만 게시하세요. 이 Compose 예시는 의도적으로 다음을 수행합니다. 아니 PostgreSQL(5432), n8n(5678) 또는 작업 실행자 브로커(5679)를 공용 인터넷에 게시합니다.

2. 환경 값 생성 및 키 보존

프로젝트 디렉터리에서 세 가지를 생성합니다. 다른 다음을 포함하는 임의의 16진수 값:

openssl rand -hex 32
openssl rand -hex 32

라는 이름의 파일을 생성합니다. .env 아래 템플릿을 사용하여 REPLACE_WITH_RANDOM_HEX 다른 생성된 값을 사용하고 호스트 이름과 시간대를 변경합니다. 표시된 2.42.5 태그는 8 10월 2026 에 나열된 안정적인 릴리스, 여기서는 날짜가 지정된 구성 예시로 사용되었습니다. 실시간 테스트된 배포 또는 향후 보안을 보장하지 않습니다.. 설치하기 전에 현재 공식 n8n 릴리스를 확인한 다음 n8n 및 해당 작업 실행기 이미지를 동일한 검증 버전에 유지하십시오.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

커밋하지 않음 .env 공개 저장소에. 암호화 키와 복구 지침을 VPS 에 안전하게 저장하세요. 키는 컨테이너 재생성 또는 마이그레이션 후에도 동일하게 유지되어야 합니다.

3. 새로 설치하려면 compose.yaml을 작성하세요.

동일한 디렉터리에 다음을 만듭니다. compose.yaml. 이 예에서는 공식 n8n 환경 변수 규칙과 PostgreSQL 18 를 사용합니다. PGDATA n8n 호스팅 프로젝트에 문서화된 경로:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

네 가지 서비스에는 고유한 역할이 있습니다. PostgreSQL 는 데이터베이스 상태를 저장하고, n8n 은 워크플로를 실행하고, n8n-runner 일치하는 버전과 공유 인증 토큰을 사용하여 실행기 작업을 실행하고 Caddy 는 공개 HTTPS 을 처리합니다. 외부 작업 실행자 Redis 대기열 모드가 아닙니다. Caddy 만 호스트 포트를 게시합니다. 이 간결한 그림에서는 설정을 위해 단일 데이터베이스 역할을 사용합니다. PostgreSQL 권한을 더욱 강력하게 분리하려면 공식 n8n PostgreSQL 배포 예를 참조하세요.

4. HTTPS 캐디파일 생성

파일 만들기 Caddyfile (대문자 C, 확장자 없음) compose.yaml. 모든 곳의 예시 호스트 이름을 자신의 DNS 이름으로 바꿉니다.

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy 은 도메인이 올바르게 확인되고 외부 트래픽이 포트 80/443 에 도달할 수 있을 때 공개 TLS 인증서를 요청하고 갱신합니다. DNS 를 가리키지 마십시오. localhost. Caddy 을 다른 역방향 프록시로 바꾸는 경우 원래 호스트, 프로토콜 및 클라이언트 주소 헤더를 전달하고 조정하십시오. N8N_PROXY_HOPS 신뢰할 수 있는 프록시 홉의 실제 수입니다.

5. 컨테이너를 시작하고 외부에서 테스트

저장 후 프로젝트 디렉터리에서 다음 명령을 실행하세요. .env, compose.yaml 그리고 Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

마지막 명령은 공개 HTTPS 건강 끝점. 인증서 발급이 아직 보류 중인 경우 n8n 가 손상되었다고 결론을 내리기 전에 Caddy 로그 및 DNS/포트를 검사하세요. 열기 https://n8n.example.com, 첫 번째 소유자 계정을 즉시 생성하고 적절한 로그인 보호 기능을 활성화하십시오. 단순히 편집기가 로드되는 것이 아니라 인스턴스가 실제로 워크플로를 실행하는지 확인합니다.

  1. 편집기에서 웹훅 방아쇠. 세트 HTTP 방법 에 GET, 다음을 선택하세요. Path vps-check, 그리고 설정 응답하다 에 즉시. 워크플로를 저장합니다.
  2. 클릭 테스트 이벤트 듣기, 전체 복사 테스트 URL n8n 으로 표시되고 다른 장치에서 실행됩니다. curl -i 'PASTE_TEST_URL_HERE' 복사한 URL로 HTTP 성공 응답과 수신 이벤트가 n8n 편집기에 나타날 것으로 예상합니다. 테스트 URL은 n8n 가 이벤트를 수신하는 동안에만 작동합니다.
  3. 게시 워크플로에서 노드를 해당 노드로 전환합니다. 생산 URL, 복사하고 실행 curl -i 'PASTE_PRODUCTION_URL_HERE' 다시. 워크플로에서 실행을 확인합니다. 처형 탭. 프로덕션 웹훅 요청에는 워크플로를 게시해야 하며 편집기의 테스트 보기에 페이로드를 표시하지 않습니다.

이것은 의도적으로 간단하고 인증되지 않은 스모크 테스트입니다. 절대로 비밀 정보를 보내지 마십시오. 테스트 후 게시를 취소/삭제하거나 실제 데이터에 퍼블릭 엔드포인트를 사용하기 전에 웹훅 인증/IP 제한을 구성하세요. 공식 Webhook 테스트/프로덕션 문서를 참조하세요.

6. 고정된 버전을 변경하기 전에 백업하세요

복구 가능한 PostgreSQL 덤프 저장 그리고 지속적인 n8n 데이터 볼륨, .env/encryption 키와 이 서버 외부 저장소에 필요한 외부 파일입니다. 다음을 사용하여 복원을 확인합니다. 백업 및 복구 가이드 생산을 업데이트하기 전에. 예제 명령:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull

자주 묻는 질문

Docker 과 함께 n8n 설치: 일반적인 질문

Docker 를 사용할 때 n8n 에 PostgreSQL 이 필요합니까?

Docker 에는 PostgreSQL 이 필요하지 않으며 소규모 배포에서는 SQLite 를 사용할 수 있습니다. 프로덕션 지향 VPS 배포의 경우 PostgreSQL 는 더 강력한 데이터베이스 기반을 제공하고 이후 대기열 모드 확장을 지원합니다.

PostgreSQL 이 데이터를 저장하는 경우 영구 n8n 볼륨을 유지하는 이유는 무엇입니까?

영구 n8n 디렉터리에는 중요한 인스턴스 상태 및 구성이 포함될 수 있습니다. 데이터베이스가 유일한 복구 자산이라고 가정하는 대신 배포 설계에 따라 이를 보존하세요.

내 웹훅에 localhost가 표시되는 이유는 무엇입니까?

내부 컨테이너 주소가 공개 원본과 다릅니다. 외부 호스트 이름, 프로토콜 및 웹훅 URL을 구성하고 역방향 프록시가 필수 헤더를 전달하는지 확인하세요.

포트 5678 을 공개해야 합니까?

역방향 프록시 뒤의 일반적인 프로덕션 배포의 경우, 특별한 운영상의 이유가 없는 한 프록시에서 HTTPS 을 노출하고 n8n 애플리케이션 포트를 내부에 유지합니다.

Redis 가 필요합니까?

표준 단일 인스턴스 Docker 배포에는 적합하지 않습니다. Redis 은 의도적으로 대기열 모드와 작업자로 전환할 때 관련됩니다.

외부 n8n 작업 실행자는 대기열 모드 작업자와 동일합니까?

아니요. 외부 작업 실행자는 n8n 기본 프로세스와 별도로 지원되는 작업 코드를 실행하고 공유 인증 토큰을 사용합니다. Redis 대기열 모드는 워크플로 실행을 분산하며 자체 인프라 요구 사항이 있습니다. 이 예에서는 Redis 대기열 모드가 아닌 외부 작업 실행기를 보여줍니다. 실행기 이미지 버전을 n8n 버전과 일치시킵니다.
