n8n VPS에서 먼저 봐야 할 것은 RAM보다 workload입니다

간단한 API sync 수백 회와 큰 파일을 읽는 execution 몇 회는 같은 부하가 아닙니다. 먼저 peak concurrency, payload 크기, Code node/파일 처리, 함께 돌릴 PostgreSQL과 다른 컨테이너를 계산하고 그다음 CPU와 RAM을 고릅니다.

Hosted AI API

OpenAI·Claude 같은 외부 API가 추론을 처리하면 VPS는 orchestration, payload와 동시 요청을 담당합니다. GPU VPS가 자동으로 필요한 것은 아닙니다.

Local AI / heavy processing

로컬 모델, embeddings, 대형 문서 파싱이나 CPU-heavy Code node는 별도의 RAM·CPU·GPU 예산이 필요합니다.

One-click ≠ managed

빠른 설치는 배포 방법일 뿐입니다. 업데이트, 백업, 복구, 보안, workflow 문제까지 관리해 준다는 뜻은 아닙니다.

월 실행 수 ≠ 서버 크기

서버 크기는 월간 workflow 개수보다 가장 바쁜 시간대의 겹치는 실행과 각 실행의 메모리 사용량에 더 직접적으로 영향을 받습니다.

실제 비용과 지원 범위

월 서버 가격만 보면 중요한 비용을 놓칩니다

비교할 때는 서버 요금 하나가 아니라 서버 + 선택 옵션 + 운영 시간을 같이 보세요. 특히 “설치가 쉽다”와 “운영까지 관리해 준다”는 다른 의미입니다.

1 · 서버와 옵션

기본 서버 요금에 추가 storage, backup, IP, 관리 옵션이 필요한지 확인합니다. 프로모션이 있다면 갱신 후 가격도 따로 봅니다.

2 · 내가 맡는 일

self-hosted에서는 n8n 업데이트, OS 보안, backup 확인, restore, 장애 대응을 누가 할지 정해야 합니다.

3 · 지원이 맡는 일

서버 접속·네트워크 같은 인프라 지원과 workflow 작성·Docker·PostgreSQL 운영 지원은 별개일 수 있습니다. 구매 전에 범위를 확인하세요.

4 · 위치는 API까지 보고 선택

한국 사용자에게 가까운 서버만 고르지 말고, n8n이 자주 호출하는 API, database, webhook 상대와의 지연도 함께 봅니다.

30일 비용을 간단히 계산하는 방법

일일 서버 요금 × 30 + 선택한 유료 옵션으로 시작합니다. 여기에 직접 관리한다면 업데이트·백업·장애 복구에 쓰는 운영 시간을 별도 비용으로 잡으면 Cloud와 self-hosted를 더 공정하게 비교할 수 있습니다.

PRODUCTION PATH

한 인스턴스에서 queue mode까지 언제 넘어갈까

1 · 단일 인스턴스

가벼운 workload는 n8n + HTTPS로 시작하고 실제 CPU, RAM, disk growth를 측정합니다.

2 · PostgreSQL 추가

production에서 execution history와 운영 안정성을 관리하려면 DB 리소스도 서버 sizing에 포함합니다.

3 · Queue mode

동시 실행과 burst가 커지면 Redis와 worker를 추가해 execution을 분리합니다. queue mode에서는 PostgreSQL 기반 구성이 적합합니다.

4 · Worker 확장

worker 수와 concurrency는 함께 설계합니다. 단순히 worker를 많이 늘리면 DB connection pool이 새로운 병목이 될 수 있습니다.

FAQ

n8n VPS 호스팅 자주 묻는 질문

n8n에는 몇 GB RAM이 필요한가요?

가벼운 테스트는 1–2 GB에서도 가능하지만, n8n과 PostgreSQL을 함께 쓰는 소규모 production은 4 GB를 실용적인 출발점으로 볼 수 있습니다. 실제 필요량은 payload와 동시 실행에 따라 달라집니다.

AI workflow에는 GPU VPS가 필요한가요?

외부 AI API를 호출한다면 보통 필요하지 않습니다. 로컬 모델이나 로컬 inference를 실행할 때 GPU와 추가 RAM 요구가 생깁니다.

Redis는 처음부터 필요한가요?

일반적인 단일 인스턴스에는 필수 조건이 아닙니다. Redis는 queue mode에서 main과 worker 사이의 실행 queue를 운영할 때 사용합니다.

One-click 설치면 관리형 호스팅인가요?

아닙니다. 설치 자동화와 운영 관리 범위는 별개입니다. 업데이트, backup, 보안, 장애 대응이 포함되는지 따로 확인해야 합니다.

한국 리전이 무조건 더 빠른가요?

항상 그렇지는 않습니다. workflow가 호출하는 API와 DB의 위치가 중요하므로 실제 네트워크 경로와 latency를 기준으로 선택해야 합니다.
