INSTALACIJA POMOĆU DOCKERA

Instalirajte n8n na VPS

Instalirajte n8n na VPS pomoću Docker Compose i PostgreSQL-a. Za produkciono okruženje potrebni su i trajno skladište za aplikaciju i bazu, nepromenljiv N8N_ENCRYPTION_KEY, javno ime hosta, HTTPS i ispravno podešeni veb-hukovi. Proverite sve ove stavke pre aktiviranja produkcionih radnih tokova.

PREDUSLOVI

Pripremite VPS pre pokretanja n8n

Linux VPS

Koristite Linux server koji dobija bezbednosna ažuriranja i ima dovoljno resursa za n8n, PostgreSQL, Docker i obrnuti proksi.

DNS

Usmerite domen ili poddomen na VPS pre izdavanja TLS sertifikata i objavljivanja adresa veb-hukova.

Docker Compose

Instalirajte Docker Engine i Compose dodatak pomoću paketa koje vaš operativni sistem podržava.

Zaštitni zid

Otvorite samo portove potrebne za administraciju i veb-saobraćaj. PostgreSQL i interne aplikacione servise držite na privatnoj mreži.

Instalirate n8n na VPS-u na kojem već postoje veb-sajtovi? Možete dodati n8n na server kojim upravljate ako CPU, RAM i prostor to dozvoljavaju. Međutim, ako Nginx, Apache, Caddy ili drugi obrnuti proksi već koristi portove 80/443, nemojte pokretati donji Caddy kontejner bez izmena jer će se portovi sukobiti. Umesto toga, preusmerite novi poddomen za n8n preko postojećeg obrnutog proksija i odgovarajuće privatne mreže ili koristite čist VPS za tačno prikazani Compose primer. Sačuvajte ostale sajtove i njihove TLS postavke; primer podrazumeva slobodne portove 80/443.

INSTALACIJA KOJU PRILAGOĐAVATE

Instalirajte n8n na svoj VPS pomoću Docker Compose

Pomoću ovog primera postavite n8n na Linux VPS kojim sami upravljate. Vi instalirate i održavate n8n; kupovina servera preko našeg partnera ne uključuje unapred instaliranu n8n instancu. Primer povezuje n8n, PostgreSQL, spoljnog task runner-a i Caddy HTTPS unutar privatne Compose mreže. To je šablon konfiguracije, a ne tvrdnja da je prikazana instalacija testirana u stvarnom radu.

Želite najbrži način da pokrenete novu instalaciju? n8n nudi i zvaničnu Docker instalaciju jednom komandom. Skriptu možete preuzeti i pregledati pomoću curl -fsSL https://get.n8n.io -o get-n8n.sh pre izvršavanja sh get-n8n.sh. Ta opcija pokreće početnu instancu sa SQLite bazom na lokalnoj adresi i uključuje sandbox servise n8n Assistant-a. To nije isto što i ova VPS instalacija sa javnim HTTPS-om i PostgreSQL bazom. Puna zvanična sandbox instalacija zahteva više RAM-a i CPU-a nego jednostavan n8n (Compose vodič navodi najmanje 4 GB RAM / 2 vCPU). Za produkcioni VPS dostupan preko interneta nastavite sa ručno podešenim okruženjem u nastavku.

1. Pripremite Docker, DNS i pristup

Povežite se preko SSH-a sa sudo ovlašćenjima i usmerite DNS A zapis za n8n.example.com na IPv4 adresu VPS-a. Na novom VPS-u sa Ubuntu 22.04, 24.04 ili 26.04 sledeće komande instaliraju Docker Engine i savremeni docker compose dodatak iz zvaničnog, digitalno potpisanog Docker apt repozitorijuma:

# Fresh official Ubuntu 22.04 / 24.04 / 26.04 installation
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Register Docker's signed apt repository
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Ovo je metod instalacije iz repozitorijuma namenjen produkcionom okruženju, opisan u zvaničnom Docker uputstvu za Ubuntu. Nemojte bez provere ponovo instalirati ili uklanjati Docker sa VPS-a na kojem već rade kontejneri ili drugi sajtovi; prvo pregledajte postojeću instalaciju i moguće sukobe paketa. Za Debian ili drugu distribuciju koristite odgovarajuće zvanično uputstvo, umesto Ubuntu komandi.

Sada proverite Docker, Compose dodatak, DNS i radni direktorijum:

sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
getent hosts n8n.example.com
mkdir -p ~/n8n && cd ~/n8n

If getent hosts ne vraća adresu ili vraća pogrešnu, ispravite DNS pre pokretanja Caddy-ja; zamenite n8n.example.com svojim stvarnim imenom hosta svuda u vodiču. Za Docker su obično potrebna root ovlašćenja: ako SSH korisnik ne može direktno da izvrši naredne docker compose komande, ispred njih dodajte sudo. Dodavanje korisnika u docker grupu daje ovlašćenja praktično jednaka root-u i ne treba ga olako raditi na deljenom serveru.

Pre uključivanja zaštitnog zida sačuvajte pristup stvarnom SSH administrativnom portu. Dozvolite ulazni HTTP (80) i HTTPS (443) radi izdavanja sertifikata i pristupa editoru. Portovi koje Docker objavi mogu zaobići pojedina UFW pravila. Proverite Docker uputstva za zaštitni zid i objavite samo potrebne Caddy portove. Ovaj Compose primer namerno ne otvara PostgreSQL (5432), n8n (5678) ili task runner broker (5679) prema javnom internetu.

2. Napravite vrednosti okruženja i sačuvajte ključ

U direktorijumu projekta napravite tri različite nasumične heksadecimalne vrednosti komandom:

openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32

Napravite datoteku pod nazivom .env prema sledećem šablonu, svaku vrednost REPLACE_WITH_RANDOM_HEX zamenite drugom generisanom vrednošću i prilagodite ime hosta i vremensku zonu. Prikazana oznaka 2.42.5 odgovara stabilnom izdanju navedenom 8. oktobra 2026.i ovde služi kao datirani primer konfiguracije, a ne kao garancija da je instalacija uživo testirana ili da će biti bezbedna u budućnosti. Pre instalacije proverite aktuelna zvanična izdanja n8n, pa za aplikaciju i njen task runner koristite istu proverenu verziju slike.

# .env — replace the three example secrets
# Pin a maintained n8n release; keep n8n and runner equal.
N8N_VERSION=2.42.5
N8N_HOST=n8n.example.com
GENERIC_TIMEZONE=Etc/UTC
POSTGRES_PASSWORD=REPLACE_WITH_RANDOM_HEX
N8N_ENCRYPTION_KEY=REPLACE_WITH_RANDOM_HEX
RUNNERS_AUTH_TOKEN=REPLACE_WITH_RANDOM_HEX

Nikada ne postavljajte .env u javni repozitorijum. Ključ za šifrovanje i uputstva za oporavak čuvajte bezbedno van VPS-a. Ključ mora ostati isti nakon ponovnog kreiranja kontejnera ili migracije.

3. Napravite compose.yaml za novu instalaciju

U istom direktorijumu napravite compose.yaml. Primer koristi zvanična pravila n8n za promenljive okruženja i putanju za PostgreSQL 18 PGDATA opisanu u dokumentaciji n8n projekta za hosting:

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: n8n
      PGDATA: /var/lib/postgresql/data
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_EDITOR_BASE_URL: https://${N8N_HOST}/
      N8N_WEBHOOK_URL: https://${N8N_HOST}/
      N8N_PROXY_HOPS: "1"
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
      GENERIC_TIMEZONE: ${GENERIC_TIMEZONE}
      TZ: ${GENERIC_TIMEZONE}
      N8N_RUNNERS_MODE: external
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_BROKER_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      postgres:
        condition: service_healthy

  n8n-runner:
    image: n8nio/runners:${N8N_VERSION}
    restart: unless-stopped
    environment:
      N8N_RUNNERS_AUTH_TOKEN: ${RUNNERS_AUTH_TOKEN}
      N8N_RUNNERS_TASK_BROKER_URI: http://n8n:5679
    depends_on:
      - n8n

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - n8n

volumes:
  postgres_data:
  n8n_data:
  caddy_data:
  caddy_config:

Četiri servisa imaju zasebne uloge: PostgreSQL čuva podatke baze, n8n izvršava radne tokove, n8n-runner izvršava zadatke pomoću podudarne verzije i zajedničkog autentifikacionog tokena, dok Caddy obezbeđuje javni HTTPS. Spoljni task runner nije isto što i režim reda sa Redisom. Samo Caddy objavljuje portove hosta. Ovaj jednostavan primer koristi jednu ulogu baze tokom podešavanja; za strože razdvajanje PostgreSQL ovlašćenja pogledajte zvanični n8n primer za PostgreSQL instalaciju.

4. Napravite Caddyfile za HTTPS

Napravite datoteku Caddyfile (veliko C, bez ekstenzije) uz compose.yaml. Svuda zamenite primer imena hosta svojim DNS nazivom:

n8n.example.com {
    reverse_proxy n8n:5678
}

Caddy traži i obnavlja javne TLS sertifikate kada domen ispravno pokazuje na server i spoljni saobraćaj može da stigne do portova 80/443. Nemojte usmeravati DNS na localhost. Ako umesto Caddy-ja koristite drugi obrnuti proksi, prosleđujte izvorno ime hosta, protokol i zaglavlja sa IP adresom klijenta i prilagodite N8N_PROXY_HOPS stvarnom broju pouzdanih proksi koraka.

5. Pokrenite kontejnere i testirajte pristup spolja

Pokrenite komande iz direktorijuma projekta nakon što sačuvate .env, compose.yaml i Caddyfile:

chmod 600 .env
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=100 n8n n8n-runner postgres caddy
curl -fsS https://n8n.example.com/healthz

Poslednja komanda proverava javni HTTPS endpoint za proveru rada. Ako izdavanje sertifikata još traje, proverite Caddy logove, DNS i portove pre zaključka da n8n ne radi. Otvorite https://n8n.example.com, odmah napravite prvi vlasnički nalog i uključite odgovarajuću zaštitu prijavljivanja. Potvrdite da instanca zaista izvršava radni tok, a ne samo da se editor otvara:

  1. U editoru napravite radni tok sa Webhook okidačem. Postavite HTTP Method na GET, izaberite Path vps-check, pa postavite Respond na Immediately. Sačuvajte radni tok.
  2. Kliknite na Listen for Test Event, kopirajte punu Test URL koju n8n prikazuje, pa sa drugog uređaja pokrenite curl -i 'PASTE_TEST_URL_HERE' sa tom adresom. Očekujte uspešan HTTP odgovor i prikaz dolaznog događaja u n8n editoru. Test URL radi samo dok n8n čeka događaj.
  3. Objavite radni tok, u čvoru pređite na Production URL, kopirajte ga i ponovo pokrenite curl -i 'PASTE_PRODUCTION_URL_HERE' . Proverite izvršavanje na kartici Executions u okviru radnog toka. Produkcioni veb-huk zahtevi traže objavljen radni tok i njihov sadržaj se ne prikazuje u testnom prikazu editora.

Ovo je namerno jednostavan funkcionalni test bez autentifikacije: nikada ne šaljite tajne podatke. Nakon testa povucite radni tok iz objave ili ga obrišite, odnosno podesite autentifikaciju veb-huka i IP ograničenja pre korišćenja javne adrese sa stvarnim podacima. Pogledajte zvaničnu dokumentaciju o testnim i produkcionim veb-hukovima.

6. Napravite rezervnu kopiju pre promene fiksiranih verzija

Sačuvajte PostgreSQL dump koji može da se vrati i trajni n8n volumen sa podacima, .envi ključ za šifrovanje, kao i potrebne spoljne datoteke, u skladište van ovog servera. Proverite oporavak prema vodiču za rezervne kopije i oporavak pre ažuriranja produkcije. Primeri komandi:

# Back up the database, encryption key, instance data,
# and files before changing the pinned versions.
docker compose exec -T postgres \
  pg_dump -U n8n -d n8n > n8n-db.sql
# After securing the backup outside this VPS:
docker compose pull
docker compose up -d
docker compose ps

Menjajte fiksiranu N8N_VERSION tek pošto pročitate napomene o izdanju. n8n i task runner slike moraju preći na istu verziju. Nemojte pokretati docker compose down -v tokom redovnog održavanja, jer ova komanda briše imenovane volumene sa podacima. Prelazak na drugu glavnu verziju PostgreSQL-a zahteva nadogradnju baze ili plan dump/vraćanja; prosta zamena Postgres 18 slike drugom glavnom verzijom nije automatska migracija.

Merodavni izvori: n8n vodič za Docker Compose, dokumentacija o obrnutom proksiju i veb-hukovima i zvanična PostgreSQL uputstva za instalaciju. Ne podrazumevamo testove performansi infrastrukture niti unapred instalirane mogućnosti određenog provajdera.

Aktuelni zvanični vodič za Docker Compose

ČESTA PITANJA

Instalacija n8n pomoću Dockera: česta pitanja

Da li je n8n potreban PostgreSQL uz Docker?

Docker ne zahteva PostgreSQL, a male instalacije mogu koristiti SQLite. Za VPS u produkciji PostgreSQL je robusniji izbor baze i podržava kasnije skaliranje u režimu reda.

Zašto čuvati n8n volumen ako su podaci u PostgreSQL-u?

Trajni n8n direktorijum može sadržati važno stanje i konfiguraciju instance. Sačuvajte ga prema svojoj arhitekturi umesto pretpostavke da je baza jedino što treba za oporavak.

Zašto moj veb-huk pokazuje localhost?

Interna adresa kontejnera razlikuje se od javne adrese. Podesite spoljašnje ime hosta, protokol i URL veb-huka i proverite da obrnuti proksi prosleđuje potrebna zaglavlja.

Da li port 5678 treba da bude javan?

U uobičajenoj produkcionoj instalaciji iza obrnutog proksija izložite HTTPS na proksiju, a aplikacioni port n8n ostavite internim osim ako postoji konkretan razlog za drugačije.

Da li mi treba Redis?

Ne za običnu Docker instalaciju sa jednom instancom. Redis postaje potreban ako namerno pređete na režim reda sa workerima.

Da li su spoljni task runners isto što i workeri režima reda?

Ne. Spoljni task runners izvršavaju podržani kod zasebno od glavnog n8n procesa uz zajednički autentifikacioni token. Režim reda sa Redisom raspodeljuje izvršavanja radnih tokova i ima sopstvene infrastrukturne zahteve. Ovaj primer koristi spoljni task runner, a ne Redis režim reda. Verzija runner slike mora odgovarati verziji n8n.
